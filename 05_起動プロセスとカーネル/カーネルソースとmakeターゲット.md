## カーネルを作り直すとはどういうことか

### そもそもカーネルとは

**カーネル**は、OS の一番中心にある「本体のプログラム」です。
メモリの割り当て、CPU の割り振り、ディスクやネットワーク機器とのやり取りを、すべてここが担当します。

アプリケーション（`ls` や `nginx`）は、自分でディスクを触ることはできません。
**必ずカーネルにお願いして、カーネルが代わりにハードウェアを操作します。**

```text
  あなたが打つコマンド（ls, nginx, python …）
            │  「このファイル読んで」とお願いする
            ▼
  ┌─────────────────────────────┐
  │        カーネル              │  ← これが /boot/vmlinuz-… の中身
  │  メモリ管理 / CPU / ドライバ │
  └─────────────────────────────┘
            │  実際に電気信号を送る
            ▼
     ハードウェア（ディスク・NIC・メモリ）
```

---

### 「ビルド」と「インストール」は別のこと

ここが一番まちがえやすいところなので、先に分けておきます。

| 言葉 | 何をするか | 終わった時点でどうなっているか |
|:--|:--|:--|
| **ビルド（コンパイル）** | ソースコード（人間が読む文字）を、機械が実行できる形に**翻訳する** | ソースのディレクトリの中に**成果物ができただけ**。システムはまだ何も変わっていない |
| **インストール** | ビルドでできた成果物を、**システムの決まった場所に配置する** | `/boot` にカーネルが置かれ、**起動メニューに新しいカーネルが出る** |

> **「ビルドは成功したのに、起動時に新しいカーネルが選べない」**
> これは、ビルドだけして**インストール（`make install`）を忘れている**状態です。

---

### モジュールとは

カーネルのすべての機能を 1 つの巨大なファイルに詰め込むと、使わない機能の分までメモリを食います。
そこで Linux は、機能を**後から付け外しできる部品**に分けられるようになっています。これが**カーネルモジュール**（拡張子 `.ko`）です。

| 組み込み方 | どこに入るか | 特徴 |
|:--|:--|:--|
| **カーネル本体に組み込む**（設定で `y`） | `/boot/vmlinuz-…` の中 | 常にメモリに載る。起動に必須のものはこちら |
| **モジュールにする**（設定で `m`） | `/lib/modules/(バージョン)/` | 必要なときだけ読み込む。ドライバの多くはこちら |

だから、インストールも **「モジュールのインストール」** と **「カーネル本体のインストール」** の 2 回に分かれます。

> できあがったモジュールを**読み込む・外す・依存を調べる**側の話（`lsmod` / `modprobe` / `modules.dep` / DKMS）は
> [カーネルモジュールの管理](./カーネルモジュールの管理.md) にまとめています。

## カーネルのソースはどこに置くか

### 慣例の置き場所

**`/usr/src/linux`** が、カーネルソースの慣例的な置き場所です。
FHS（Filesystem Hierarchy Standard＝ディレクトリ構成の標準規格）では `/usr/src` を「参照目的のソースコードを置く場所」と定めています。

実際には、こうなっています。

```text
/usr/src/
 ├── linux -> linux-2.6.35.10/     ← シンボリックリンク（ただの「近道」）
 └── linux-2.6.35.10/              ← 実体。バージョン名つきのディレクトリ
      ├── .config
      ├── Makefile
      ├── kernel/
      └── …
```

**なぜシンボリックリンクなのか**

複数バージョンのソースを並べて置いても、`/usr/src/linux` の向き先を張り替えるだけで
「今さわっているソース」を切り替えられるからです。
手順書やスクリプトの中で `/usr/src/linux` と書いておけば、バージョンが変わっても書き換えずに済みます。

**例文**

```bash
$ ls -l /usr/src/                                    # シンボリックリンクかどうかを確認する
合計 4
lrwxrwxrwx  1 root root   16  9月  1 10:00 linux -> linux-2.6.35.10
drwxr-xr-x 23 root root 4096  9月  1 10:00 linux-2.6.35.10

$ sudo ln -sfn /usr/src/linux-2.6.35.10 /usr/src/linux   # 向き先を張り替える
```

**補足**

- `ln -s` … シンボリックリンクを作る。`-f` は既存のリンクを上書き、`-n` はリンク先ディレクトリの中に潜らせないための指定
- Debian 系でカーネルヘッダを入れると `/usr/src/linux-headers-…` ができますが、これは**ヘッダだけ**でソース一式ではありません

---

### 現在の kernel.org の推奨は違う

Ping-t（LPIC）で問われるのは上の「`/usr/src/linux` が慣例」という知識ですが、
**現在の kernel.org 公式 README は `/usr/src/linux` を使わないよう明記しています。**

> "Do NOT use the /usr/src/linux area!"
> （`/usr/src/linux` は使わないこと。この領域には、ライブラリのヘッダが使う不完全なカーネルヘッダ一式が置かれている）

| どちらの話か | 置き場所 | 理由 |
|:--|:--|:--|
| **試験（LPIC / Ping-t）** | `/usr/src/linux` | FHS と、古くからの慣例にもとづく |
| **現在の実作業** | **自分のホームディレクトリ**（`~/linux-6.x/` など） | `root` 権限なしでビルドでき、システムのヘッダと混ざらない |

**試験では `/usr/src/linux`、手を動かすときはホームディレクトリ** と覚えておけば、どちらでも困りません。

## カーネルソースの中身

ソースを展開すると、直下にはこれらが並びます。**Ping-t で問われるのはこの表です。**

| ファイル / ディレクトリ | 説明 | もう少しくわしく |
|:--|:--|:--|
| **`.config`** | カーネルの**ビルド設定ファイル** | 「どの機能を組み込むか／モジュールにするか／外すか」が数千行ならんだファイル。`make menuconfig` などが書き換える |
| **`Makefile`** | **`make` の設定**や**カーネルバージョン**が書いてある | `make` は「何をどの順で作るか」をこのファイルから読む。先頭の数行にバージョン番号がある |
| **`kernel/`** | **カーネル本体** | プロセススケジューラ、シグナル処理など、OS の中核そのもの |
| **`Documentation/`** | **ドキュメントの類** | ビルド方法・各機能の説明・カーネルパラメータの一覧。**困ったらまずここ** |
| **`arch/`** | **アーキテクチャ固有のコード** | `i386`、`x86_64`、`arm64` など、CPU の種類ごとに違う部分 |
| **`drivers/`** | **デバイスドライバ** | NIC、ディスク、USB など、機器を動かすコード。ソース全体で一番容量が大きい |
| **`fs/`** | **ファイルシステム** | ext4、XFS、Btrfs、NFS などの実装 |
| **`include/`** | **インクルードファイル** | 各所から共通で読み込むヘッダ（`.h`）。関数や構造体の「宣言」が置かれる |
| **`mm/`** | **メモリ管理** | memory management の略。ページング、スワップ、メモリ割り当て |
| **`net/`** | **ネットワーク** | TCP/IP、ソケット、ルーティングの実装 |

**名前と中身が結びつきにくいものだけ、もう一度**

| ディレクトリ | 名前の由来 | 覚え方 |
|:--|:--|:--|
| **`fs/`** | **f**ile **s**ystem | **「ファイルシステム」**。「同期（sync）」ではない |
| **`mm/`** | **m**emory **m**anagement | **「メモリ管理」**。「モジュール管理」ではない |
| **`include/`** | include | **「インクルードファイル」**＝ほかのファイルから呼び出すコードのまとまり |
| **`arch/`** | **arch**itecture | **「アーキテクチャ固有のコード」**（i386、x86_64 など） |
| **`net/`** | network | **「ネットワーク」** |

---

### 実際に展開すると、もっと多くのものが並ぶ

上の表は**試験で問われるもの**に絞っています。
実物はもっと多くのファイルとディレクトリが並びます。

```bash
$ pwd                                                # 今いるディレクトリを確認する
/usr/src/kernels/3.10.0-1127.el7.x86_64

$ ls -aF                                             # 隠しファイルも含め、種類を記号付きで一覧する
./            Makefile.qlock  crypto/    init/     net/       tools/
../           Module.symvers  drivers/   ipc/      samples/   usr/
.config       System.map      firmware/  kernel/   scripts/   virt/
Kconfig       arch/           fs/        lib/      security/  vmlinux.id
Makefile      block/          include/   mm/       sound/
```

| よく見かける追加のもの | 中身 |
|:--|:--|
| **`System.map`** | **カーネルのアドレスマップ**。ビルド時に作られ、`/boot/System.map-(バージョン)` として配置される |
| **`Module.symvers`** | モジュールが公開するシンボルとその版の一覧。外部モジュールのビルドに必要 |
| **`Kconfig`** | 設定項目の定義ファイル。`make menuconfig` のメニューはここから作られる |
| `block/` | ブロックデバイス（ディスク）の共通処理 |
| `crypto/` | 暗号アルゴリズムの実装 |
| `init/` | カーネル起動直後の初期化処理 |
| `ipc/` | プロセス間通信 |
| `lib/` | 共通で使う汎用ルーチン |
| `scripts/` | ビルドに使う補助スクリプト（`patch-kernel` もここ） |
| `security/` | SELinux / AppArmor などのセキュリティ機構 |
| `sound/` | サウンドドライバ |
| `tools/` | `perf` などの付属ツール |
| `virt/` | 仮想化（KVM）関連 |

**補足**

- `ls -aF` の `-a` … 隠しファイルも表示する ／ `-F` … ディレクトリに `/`、実行ファイルに `*` を付けて種類を見分けやすくする

### ディストリによって置き場所が違う

| 系統 | ソースの置き場所 |
|:--|:--|
| **試験（LPIC / Ping-t）の標準** | **`/usr/src/linux/`** |
| **Debian 系** | `/usr/src/linux-source-(バージョン)/`（`linux-source` パッケージ） |
| **Red Hat 系** | **`/usr/src/kernels/(バージョン)/`** |

いずれの場合も、**バージョン付きのディレクトリが実体**で、`/usr/src/linux` はそこへのシンボリックリンクにしておくのが推奨されています。

---

### 存在しないパスにだまされない

試験では、**それらしいが実在しないパス**が選択肢に混ざります。

| パス | 実在するか | 中身 |
|:--|:--:|:--|
| **`/usr/src/linux/kernel/`** | **する** | **カーネル本体のソース**（プロセススケジューラなど） |
| **`/usr/src/linux/Documentation/`** | **する** | ビルドやインストールに関する**ドキュメント・資料** |
| **`/usr/src/linux/.config`** | **する** | **ビルド設定ファイル**（ソース直下にある） |
| `/etc/src/linux/` | **しない** | — |
| `/bin/src/kernel/` | **しない** | — |
| `/etc/src/linux/config` | **しない** | ディレクトリもファイルも存在しない |
| `/usr/src/linux/kernel/.config` | **しない** | `kernel/` の中にはソースファイルがあるだけ。`.config` は**ソース直下にしかない** |

**ディレクトリ名にも、実在しないものが混ざります。**

| 名前 | 実在するか | ひとこと |
|:--|:--:|:--|
| **`net/`** | **する** | ネットワーク。**`network/` ではない** |
| `network/` | **しない** | 正しくは `net/`。**3 文字**と覚える |
| **`arch/`** | **する** | **アーキテクチャ**（architecture）の略。**Arch Linux とは無関係** |
| **`mm/`** | **する** | メモリ管理。`memory/` ではない |
| **`fs/`** | **する** | ファイルシステム。`filesystem/` ではない |

> **ディレクトリ名は、どれも短く省略されています。**
> `net` / `mm` / `fs` / `arch` のように、**略された形が正**だと覚えてください。

> **`.config` も `Makefile` も、置かれているのは「ソースの直下」だけ**です。
> `kernel/` のような下の階層には、`.config` はありません。

### ビルド設定をバックアップする

設定をやり直したくないときは、**`/usr/src/linux/.config` をコピー**しておきます。

| 候補 | バックアップすべきか | 理由 |
|:--|:--:|:--|
| **`/usr/src/linux/.config`** | **これ** | `make menuconfig` などで作った**ユーザの設定そのもの** |
| `/usr/src/linux/Makefile` | 不要 | `make` の動作とバージョンが書いてあるだけ。**ユーザ設定ではない** |
| `/usr/src/linux/kernel/Makefile` | 不要 | 同じく `make` の動作を決めるファイル |
| `/usr/src/linux/kernel/.config` | — | **存在しない** |

**例文**

```bash
$ cp /usr/src/linux/.config ~/config-$(date +%Y%m%d)   # 日付つきの名前で設定を退避する
$ cp /usr/src/linux/.config /boot/config-2.6.35.10     # /boot に控えとして置く（make install と同じ形）
$ diff /usr/src/linux/.config /boot/config-$(uname -r) # 今動いているカーネルとの設定差分を見る
```

**補足**

- `$(date +%Y%m%d)` … 実行した日の日付（`20260912` のような文字列）に置き換わる書き方
- **`make mrproper` は `.config` を消します。**実行する前に必ず退避してください

---

### 設定ファイルは config、バージョンは Makefile

この 2 つは役割が混同されやすいので、並べて覚えます。

| | `.config` | `Makefile` |
|:--|:--|:--|
| **何が書いてある** | **ビルド設定**（どの機能を入れるか） | **`make` の動作** と **カーネルバージョン** |
| **誰が書き換える** | `make config` / `menuconfig` / `xconfig` / `oldconfig` | 基本さわらない（バージョン表記を変えるときだけ） |
| **隠しファイルか** | **隠しファイル**（`ls -a` でないと見えない） | 見える |
| **バックアップ先** | ビルド後 **`/boot/config-(バージョン)`** にコピーされる | されない |

**例文**

```bash
$ head -5 /usr/src/linux/Makefile                    # 先頭5行にバージョンが書いてある
# SPDX-License-Identifier: GPL-2.0
VERSION = 2
PATCHLEVEL = 6
SUBLEVEL = 35
EXTRAVERSION = .10

$ ls -a /usr/src/linux/ | grep config                # .config は隠しファイルなので -a が要る
.config
.config.old
```

**補足**

- `.config.old` … 設定をやり直したときに、**1 つ前の設定**が自動で残されたもの
- `EXTRAVERSION` を書き換えると、できあがるカーネルの名前（`uname -r` の表示）を変えられます

### Documentation は「ビルドと導入の手引き」

`Documentation/` には、**ビルドとインストールのやり方そのもの**が入っています。
はじめてカーネルを作るときに、最初に開くべき場所です。

| よく見るもの | 中身 |
|:--|:--|
| `Documentation/admin-guide/README.rst` | **ビルドとインストールの全手順**。kernel.org の README と同じもの |
| `Documentation/admin-guide/kernel-parameters.txt` | **起動時に渡せるカーネルパラメータの一覧**（`quiet`、`nomodeset` など） |
| `Documentation/process/` | パッチの投稿方法、コーディング規約 |
| `Documentation/filesystems/` | 各ファイルシステムの仕様 |

**例文**

```bash
$ less /usr/src/linux/Documentation/admin-guide/README.rst   # ビルド手順の公式ドキュメント
$ grep -n "nomodeset" /usr/src/linux/Documentation/admin-guide/kernel-parameters.txt   # 起動オプションを引く
```

## カーネルの設定のしかた

`.config` を作る方法は何通りかあります。**どれを使っても、できあがるのは同じ `.config` です。**

---

### 設定の 4 つのやり方

| ターゲット | 見た目 | 何が要るか | 使いどころ |
|:--|:--|:--|:--|
| **`make config`** | **1 項目ずつ順番に質問される**（テキスト） | 何も要らない | 項目が数千あるので、実質使わない。**「対話的に 1 つずつ」＝ `config`** と覚える |
| **`make menuconfig`** | **コンソール画面の中に出るメニュー** | ncurses ライブラリ | **実務で一番使う**。矢印キーで項目を選べる |
| **`make nconfig`** | menuconfig の新しい版のメニュー | ncurses ライブラリ | menuconfig の代わり。検索が強い |
| **`make xconfig`** | **X（GUI）のウィンドウ** | Qt ライブラリと X 環境 | デスクトップ環境があるとき |
| **`make gconfig`** | X（GUI）のウィンドウ | GTK ライブラリと X 環境 | xconfig の GTK 版 |
| **`make oldconfig`** | **今の `.config` を引き継ぎ**、新項目だけ質問される | 何も要らない | **カーネルを新しくするとき**に使う。設定をやり直さずに済む |

> **`menuconfig` と `xconfig` の区別が問われます。**
> - `menuconfig` … **コンソール画面の中**に表示されるメニュー。**X は不要**
> - `xconfig` … **X 上の GUI**。名前の `x` が X Window System の `x`

**例文**

```bash
$ make menuconfig                                    # コンソール内のメニューで設定する
$ make xconfig                                       # X 上の GUI で設定する
$ make oldconfig                                     # 現在のカーネルの設定を引き継ぐ
```

---

### oldconfig は「引き継ぐ」ターゲット

`make oldconfig` は、**すでにある `.config` を読み込み、そのバージョンで新しく増えた項目だけを質問します。**

```text
  古い .config（前のカーネルの設定）
         │
         ▼  make oldconfig
  新しいバージョンで増えた項目だけ y/n/m を聞かれる
         │
         ▼
  新しい .config （古い設定はそのまま引き継がれている）
```

**今動いているカーネルの設定を引き継ぎたいとき**は、`/boot/config-$(uname -r)` を `.config` としてコピーしてから実行します。

```bash
$ cp /boot/config-$(uname -r) /usr/src/linux/.config  # 今動いているカーネルの設定を持ってくる
$ cd /usr/src/linux                                  # ソースの直下へ移動する
$ make oldconfig                                     # 増えた項目だけ質問される
```

**補足**

- `$(uname -r)` … 今動いているカーネルのバージョン文字列に置き換わる書き方。`uname -r` の実行結果をその場に埋め込みます
- 質問に全部デフォルトで答えてよいなら **`make olddefconfig`**（一切質問されない）

---

### 設定項目の 3 つの答え方

設定画面では、各項目に 3 つのうちどれかを指定します。

| 記号 | 意味 | どうなるか |
|:--|:--|:--|
| **`y`**（`*`） | カーネル本体に**組み込む** | `vmlinuz` の中に入る。常に使える |
| **`m`**（`M`） | **モジュールにする** | `/lib/modules/…` に `.ko` として置かれ、必要時に読み込む |
| **`n`**（空白） | **入れない** | 機能そのものが使えない |

> 起動に必須のドライバ（ルートファイルシステムのドライバなど）を `m` にすると、
> **初期RAMディスクがないと起動できなくなります。** → [初期RAMディスク initrdとinitramfs](./初期RAMディスク_initrdとinitramfs.md)

## make ターゲット一覧

`make` は「ターゲット」という名前を付けて呼ぶと、`Makefile` にあらかじめ書かれた処理を実行してくれます。
カーネルのビルドで使うものを、まとめて置きます。

### 設定系

| ターゲット | 動作 |
|:--|:--|
| **`make config`** | **項目ごとに対話的に**設定する（テキストで 1 問ずつ） |
| **`make menuconfig`** | **コンソール画面内の GUI メニュー**で設定する（ncurses） |
| **`make nconfig`** | menuconfig の新版。検索機能が強い |
| **`make xconfig`** | **X 上の GUI** で設定する（Qt） |
| **`make gconfig`** | X 上の GUI で設定する（GTK） |
| **`make oldconfig`** | **現在のカーネルの設定を引き継ぐ**。新規項目だけ質問される |
| **`make olddefconfig`** | oldconfig と同じだが、新規項目は**すべて既定値**で無言に決める |
| **`make defconfig`** | **デフォルト状態の設定ファイルを作る**（そのアーキテクチャの既定値） |
| **`make cloneconfig`** | **現在動いているカーネルの設定を引き継いだ設定ファイルを作る**。**SUSE 系のソースだけに用意された独自ターゲット**で、kernel.org の `make help` には出てこない |
| **`make savedefconfig`** | 今の `.config` から、**既定値と違う項目だけ**を書き出す（最小の設定） |
| **`make localmodconfig`** | **今読み込まれているモジュールだけ**を有効にした設定を作る（ビルドが速くなる） |
| **`make allyesconfig`** | 全項目を `y` にする（検証用） |
| **`make allnoconfig`** | 全項目を `n` にする（最小構成の出発点） |
| **`make tinyconfig`** | 作れる**最小のカーネル**の設定を作る |
| **`make listnewconfig`** | 増えた設定項目を**一覧で表示するだけ**（設定は変えない） |

> **`oldconfig` と `cloneconfig` は、どちらも「現在動いているカーネルの設定を引き継いだ設定ファイルを作る」**ものです。
> 内部の細かい違いはありますが、**同じものとして覚えて差し支えありません。**
> ただし `cloneconfig` は SUSE 系のカーネルソースにしか無いため、**手を動かすときは `oldconfig` を使ってください。**

> **設定ターゲットの名前には、ひっかけが多く出ます。**
>
> | 紛らわしい名前 | 実際は |
> |:--|:--|
> | 「設定ファイルの**バックアップ**を作る」ターゲット | **存在しない**。バックアップは `cp .config ~/…` と自分で取る |
> | 「**古い形式の互換**設定ファイルを作る」ターゲット | **存在しない**。`oldconfig` の `old` は「古い形式」ではなく「**既にある `.config`**」の意味 |
> | `make pkg` | **存在しない**。パッケージ化は `rpm-pkg` / `deb-pkg` のように形式まで含めた名前 |

### ビルド系

| ターゲット | 動作 |
|:--|:--|
| **`make`** / **`make all`** | **ターゲットを何も指定しないと `make all` と同じ動作になる**。依存関係のチェック・**カーネル本体（`bzImage`）とモジュールのビルド**・不要になった一時ファイルの削除を、まとめて自動で行う |
| **`make modules`** | **モジュールだけをビルドする**。**カーネル本体（`bzImage`）は含まれない**。配置もしない |
| **`make bzImage`** | **カーネル本体のイメージだけ**をビルドする（モジュールは含まれない） |
| **`make vmlinux`** | 圧縮前のカーネル（デバッグ用）だけをビルドする |

> **「`bzImage` を含めてビルドしたい」なら、答えは `make`（＝ `make all`）です。**
> `make modules` はモジュール専用なので、カーネル本体はできあがりません。

### インストール系

| ターゲット | 動作 |
|:--|:--|
| **`make modules_install`** | ビルド済みモジュールを **`/lib/modules/(バージョン)/`** へ配置する |
| **`make install`** | カーネル本体を **`/boot`** へ配置し、**ブートローダに登録する** |
| **`make headers_install`** | ユーザ空間向けのヘッダを配置する |

### 掃除系

| ターゲット | 何を消すか | `.config` を消すか |
|:--|:--|:--|
| **`make clean`** | ビルドでできた**一時ファイル・オブジェクトファイル**を消す | **消さない**（設定は残る） |
| **`make mrproper`** | `clean` の内容に加えて、**`.config` などの設定ファイルも**消す | **消す** |
| **`make distclean`** | `mrproper` の内容に加えて、**エディタのバックアップやパッチの残骸**まで消す | **消す** |

> **`clean` と `mrproper` の違いは頻出です。**
>
> ```text
>   clean      ← 一時ファイルを消す。設定ファイルは残す
>   mrproper   ← clean ＋ 設定ファイル（.config）も消す
>   distclean  ← mrproper ＋ バックアップ・パッチの残骸も消す
>              （右にいくほど消える範囲が広い）
> ```

**例文**

```bash
$ make clean                                         # 一時ファイルだけ消す（設定は残る）
$ make mrproper                                      # 設定ファイルも含めて初期化する
$ make distclean                                     # バックアップやパッチの残骸まで消す
```

**補足**

- `make clean` は「**設定ファイル `.config` は残したまま**、ソースディレクトリ内の不要ファイルを消す」ターゲットです。前回のビルドの残骸だけを掃除したいときに使います
- `make mrproper` は「**既に設定された内容を初期化する**」ターゲットです。ソースを取ってきた直後は、まずこれを実行するのが推奨されています

## パッケージにして配る

ビルドしたカーネルを**そのままシステムに入れず、`rpm` や `deb` のパッケージにまとめる**ターゲットも用意されています。
同じカーネルを何台ものサーバへ配りたいときに使います。

### 覚え方

名前は **「形式」＋`-pkg`** でできています。

```text
      src   rpm   -pkg      →  ソースだけの rpm
      bin   rpm   -pkg      →  バイナリだけの rpm
    （なし） rpm   -pkg      →  ソースとバイナリの両方の rpm
             ↑
        rpm / deb / snap / pacman / tar …  ＝ パッケージの形式
```

| 接頭辞 | 意味 |
|:--|:--|
| **なし** | **ソースとバイナリの両方**を作る |
| **`src`** | **ソースだけ**を作る |
| **`bin`** | **バイナリだけ**を作る（**ソースは含まれない**） |

---

### パッケージ化ターゲット一覧

| ターゲット | 作られるもの |
|:--|:--|
| **`make rpm-pkg`** | **ソースとバイナリの両方**を含む rpm パッケージ |
| **`make srcrpm-pkg`** | **ソースだけ**の rpm パッケージ |
| **`make binrpm-pkg`** | **バイナリだけ**の rpm パッケージ（**元になったソースは含まれない**） |
| **`make deb-pkg`** | **ソースとバイナリの両方**を含む deb パッケージ |
| **`make srcdeb-pkg`** | ソースだけの deb パッケージ |
| **`make bindeb-pkg`** | バイナリだけの deb パッケージ |
| **`make snap-pkg`** | バイナリの snap パッケージ（外部ホストへの通信が発生する） |
| **`make pacman-pkg`** | バイナリの pacman パッケージ（Arch Linux 系） |
| **`make dir-pkg`** | パッケージにせず、**素のディレクトリ構造**として出力する |
| **`make tar-pkg`** | 無圧縮の tar 書庫 |
| **`make targz-pkg`** | gzip 圧縮の tar 書庫 |
| **`make tarbz2-pkg`** | bzip2 圧縮の tar 書庫 |
| **`make tarxz-pkg`** | xz 圧縮の tar 書庫 |
| **`make tarzst-pkg`** | zstd 圧縮の tar 書庫 |
| **`make modules-cpio-pkg`** | **モジュールだけ**を cpio 書庫にまとめる |
| **`make perf-tar-src-pkg`** | 付属ツール `perf` のソース書庫（`perf-targz-src-pkg` などの圧縮版もある） |

**例文**

```bash
$ make rpm-pkg                                       # ソース入りの rpm を作る
$ make binrpm-pkg                                    # バイナリだけの rpm を作る
$ make deb-pkg                                       # ソース入りの deb を作る
$ make -j$(nproc) bindeb-pkg                         # バイナリだけの deb を並列ビルドで作る
$ make help                                          # 使えるターゲットの一覧を表示する
```

**補足**

- **`rpm`** … Red Hat 系（RHEL / CentOS / Rocky / Fedora / SUSE）で標準的に使われる、ソフトウェア配布用のパッケージ形式
- **`deb`** … Debian 系（Debian / Ubuntu）のパッケージ形式
- できあがったパッケージは、`rpm -ivh` や `dpkg -i` でほかのサーバへ入れられます
- **`make help`** を打つと、そのソースで使えるターゲットが全部出ます。名前をうろ覚えのときはこれが一番確実です

## 設定画面の見方

```text
 ┌──────────── Linux/x86 6.1.0 Kernel Configuration ────────────┐
 │  Arrow keys navigate the menu.  <Enter> selects submenus ---> │
 │  Highlighted letters are hotkeys.  Pressing <Y> includes,     │
 │  <N> excludes, <M> modularizes features.                      │
 │                                                               │
 │      [*] 64-bit kernel                                        │
 │          General setup  --->                                  │
 │      [ ] Enable loadable module support                       │
 │      <M> XFS filesystem support                               │
 │                                                               │
 └────────<Select>  < Exit >  < Help >  < Save >  < Load >───────┘
```

| 表示 | 意味 |
|:--|:--|
| **`[*]`** | **カーネル本体に組み込む**（`y`） |
| **`[ ]`** | **入れない**（`n`） |
| **`<M>`** | **モジュールにする**（`m`） |
| **`--->`** | サブメニューがある。Enter で入る |
| **`(値)`** | 数値や文字列を入力する項目 |

| キー | 動作 |
|:--|:--|
| `↑` `↓` | 項目を移動する |
| `Enter` | サブメニューに入る |
| `Y` / `N` / `M` | その項目を 組み込み／無効／モジュール にする |
| `/` | **検索**する（設定名の一部でよい） |
| `?` | その項目のヘルプを読む |
| `Esc` `Esc` | 1 つ上に戻る／終了する |
