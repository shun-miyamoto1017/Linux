## SYSLINUX ファミリの4つ

### SYSLINUX

**FAT ファイルシステムから Linux を起動する、軽量なブートローダ**です。

**FAT** は MS-DOS や Windows で使われるファイルシステムで、
**USB メモリやフロッピーディスクが最初から FAT でフォーマットされている**ことから、
**「USB メモリから起動する」用途で主に使われます。**

| | |
|:--|:--|
| **読み出し元** | FAT（FAT12 / FAT16 / FAT32） |
| **設定ファイル** | `syslinux.cfg` |
| **インストール** | `syslinux --install デバイス名` |

```bash
$ sudo syslinux --install /dev/sdb1          # USBメモリのパーティションにインストールする
```

**補足** … 機能が少なく軽いのが特長です。**GRUB のようなシェルやスクリプトの仕組みは持ちません。**

---

### ISOLINUX

**CD-ROM で使われる ISO 9660 ファイルシステムから Linux を起動する**ブートローダです。

**ISO 9660** は光学メディア用の標準ファイルシステムで、
**Linux のインストール ISO は、ほぼこれで起動します。**

| | |
|:--|:--|
| **読み出し元** | ISO 9660（CD-ROM / DVD） |
| **本体のファイル** | **`isolinux.bin`** |
| **設定ファイル** | **`isolinux.cfg`** |
| **置き場所** | **通常は本体と同じディレクトリ**に置く |

```bash
$ ls /mnt/iso/isolinux/                      # インストールISOをマウントして中を見る
boot.cat  isolinux.bin  isolinux.cfg  vmlinuz  initrd.img
```

**補足** … **`isolinux.cfg` は「設定ファイルの名前」であって、ディレクトリの名前ではありません。**
`isolinux.cfg/` というディレクトリに入れる必要はありません。
**ディレクトリに入れるのは、あとで出てくる PXELINUX のほう**です。ここは入れ替えて問われます。

---

### EXTLINUX

**ext2 / ext3 / ext4 / btrfs から Linux を起動する**ブートローダです。
**Linux で標準的に使われるファイルシステム**が読めるので、**GRUB の代わりに使われることがあります。**

| | |
|:--|:--|
| **読み出し元** | ext2 / ext3 / ext4 / btrfs |
| **設定ファイル** | `extlinux.conf` |
| **インストール** | **`extlinux --install ディレクトリ`** |

```bash
$ sudo extlinux --install /boot               # /boot ディレクトリにインストールする
```

**補足** … **指定するのがデバイスではなく「ディレクトリ」**なのが SYSLINUX との大きな違いです。
すでにマウントされているファイルシステムの、**そのディレクトリに対して**書き込みます。

---

### PXELINUX

**PXE（Preboot Execution Environment）を使って、ネットワークサーバから Linux を起動する**ブートローダです。

**PXE** は**ネットワーク経由で OS を起動するための規格**で、**DHCP サーバと TFTP サーバ**を使います。

| | |
|:--|:--|
| **読み出し元** | ネットワーク（TFTP サーバ） |
| **本体のファイル** | **`pxelinux.0`** |
| **設定ファイル** | **`pxelinux.cfg/` ディレクトリの中**に置く |
| **必要なもの** | PXE 対応のネットワークデバイス／**DHCP サーバ**／**TFTP サーバ** |

**補足** … **本体の拡張子が `.0` である**ことと、
**設定ファイルが「ディレクトリの中」に入る**ことが、ほかの 3 つと違います。

## インストールコマンドの違い

**ここは確実に落としたくないところ**です。**指定するものが違います。**

| コマンド | 書式 | 指定するもの | 例 |
|:--|:--|:--|:--|
| **`syslinux`** | `syslinux -i\|--install デバイス名` | **デバイス** | `syslinux --install /dev/sdb1` |
| **`extlinux`** | `extlinux -i\|--install ディレクトリ` | **ディレクトリ** | `extlinux --install /boot` |

```bash
$ sudo syslinux --install /dev/sdb1          # SYSLINUX … デバイスを指定する
$ sudo extlinux --install /boot              # EXTLINUX … ディレクトリを指定する
```

**覚え方**

```text
 SYSLINUX  … FAT の USB メモリに入れる   → まだマウントしていない「デバイス」を渡す
 EXTLINUX  … 動いている Linux の /boot に入れる → もうマウント済みの「ディレクトリ」を渡す
```

**`-i` は `--install` の短い書き方**です。どちらで書いても同じです。

**ISOLINUX と PXELINUX には、専用のインストールコマンドがありません。**

| | どうやって使うか |
|:--|:--|
| **ISOLINUX** | `isolinux.bin` と `isolinux.cfg` を**ISO イメージの中に入れて焼く**（`xorriso` / `genisoimage` などを使う） |
| **PXELINUX** | `pxelinux.0` と `pxelinux.cfg/` を**TFTP サーバの公開ディレクトリに置くだけ** |

## PXE でネットワークから起動する

### PXE に必要なもの

| 必要か | もの | 役割 |
|:--:|:--|:--|
| **要る** | **PXE 対応のネットワークデバイス** | **ネットワークインタフェースを介して起動する**ため |
| **要る** | **DHCP サーバ** | 自ホストの IP、TFTP サーバの IP、**ブートローダのパス**を教える |
| **要る** | **TFTP サーバ** | `pxelinux.0` と設定ファイル、カーネルを**配る** |
| 要らない | NFS サーバ | **PXE の起動そのものには不要** |

**DHCP**（Dynamic Host Configuration Protocol）は、**ネットワークに接続したホストに IP アドレスなどを自動で割り当てるプロトコル**です。
**TFTP**（Trivial File Transfer Protocol）は、**UDP 上でファイルを送受信するための、簡素なプロトコル**です。

**押さえておく 2 点**

| 論点 | 答え |
|:--|:--|
| **HDD にインストールするのか** | **しない。** だから**ディスクレスマシンでも起動できる** |
| **ネットワークがダウンしていたら** | **起動できない。** 読み出し元がネットワークの向こうにあるため |

---

### 起動の3ステップ

```text
  ① DHCP サーバへ問い合わせ
       ├─ 自ホストの IP アドレス
       ├─ TFTP サーバの IP アドレス
       └─ TFTP サーバ上の pxelinux.0 のパス
                    │
                    ▼
  ② TFTP サーバから取得
       ├─ pxelinux.0         （ブートローダ本体）
       └─ pxelinux.cfg/... （設定ファイル）
                    │
                    ▼
  ③ 設定ファイルにしたがって起動
       └─ カーネルと初期RAMディスクを TFTP から読み込んで実行
```

**DHCP は「どこに何があるか」を教えるだけ**で、**ファイルそのものを配るのは TFTP** です。
この役割分担がそのまま問われます。

### 設定ファイルの探しかた

**PXELINUX は、1 台ごとに違う設定を配れます。**
そのために、**`pxelinux.cfg/` ディレクトリの中を、決まった順番で探します。**

| 順番 | ファイル名 | 例 |
|:-:|:--|:--|
| 1 | 接続ホストの **MAC アドレス**をハイフンで区切ったもの | `01-88-99-aa-bb-cc-dd` |
| 2 | 接続ホストの **IP アドレスを16進数に変換**したもの（**1 文字ずつ短くしながら**探す） | `192.168.1.10` → `C0A8010A` |
| 3 | **`default`** | `default` |

**上から順に探し、最初に見つかったものを使います。**
**どれも無ければ `default` が使われる**ので、**共通設定は `default` に置きます。**

```bash
$ ls /var/lib/tftpboot/pxelinux.cfg/          # TFTPサーバ側の設定ディレクトリを見る
01-88-99-aa-bb-cc-dd  C0A8010A  default
```

**補足1** … MAC アドレスのファイル名の**先頭の `01` は MAC アドレスの一部ではありません。**
**ARP のハードウェア種別（`01` = Ethernet）**を表す番号が付きます。

**補足2** … IP アドレスの 16 進数は**大文字**で書き、
`C0A8010A` → `C0A8010` → `C0A801` … と**1 文字ずつ削りながら**探します。
**`C0A801` のような短いファイル名を置けば、そのネットワーク全体に同じ設定を配れる**という仕組みです。

**補足3** … 公式ドキュメント（`pxelinux.txt`）では、**この 3 つの前に「クライアント UUID」による検索**があります。
**DHCP がオプション 97 で UUID を渡してきた場合だけ**使われるため、**試験では MAC → IP → `default` の 3 段階**を押さえれば足ります。

## UEFI で動くブートローダ

**UEFI では、ブートローダは「ESP の中に置かれた `.efi` ファイル」**です。
ESP そのものの説明は [BIOSとUEFI](./BIOSとUEFI.md) にあります。

### ファイルの役割一覧

| ファイル | 何をするか |
|:--|:--|
| **`/EFI/BOOT/bootx64.efi`** | **UEFI のブートマネージャ**。**標準では UEFI 起動時に読み込まれる**。起動順の設定が無い USB メモリなどから起動できるのはこれのおかげ |
| **`grubx64.efi`** | **grub を起動する** UEFI アプリケーション |
| **`shim.efi`** | **セキュアブート時に最初に読み込まれる** UEFI アプリケーション。**UEFI CA（マイクロソフト）の署名**を受けており、**他のブートローダ等の署名検証**を行う |
| **`systemd-boot`** | **systemd 独自**の UEFI ブートマネージャ |
| **`efiboot.img`** | UEFI で **ISOLINUX** を使ってブートする際に使われるイメージ。**FAT16 で作成されている** |

```bash
$ sudo ls -R /boot/efi/EFI/                   # ESP の中にある .efi ファイルを見る
/boot/efi/EFI/:
BOOT  ubuntu

/boot/efi/EFI/BOOT:
BOOTX64.EFI  fbx64.efi

/boot/efi/EFI/ubuntu:
grub.cfg  grubx64.efi  mmx64.efi  shimx64.efi
```

**補足** … **ディストリビューションごとのディレクトリ**（上の例では `ubuntu`）に本体が置かれ、
**`/EFI/BOOT/BOOTX64.EFI` は「どの OS か分からないときの既定の入口」**として使われます。

---

### セキュアブートと shim

**セキュアブート（Secure Boot）は、UEFI が持つ「起動を制限する機能」**です。

| | |
|:--|:--|
| **何をするか** | システム起動にあたって**署名の確認を行い、起動を制限する** |
| **何で識別するか** | **X.509 証明書**を使って署名を識別する |
| **実務での注意** | **Windows 8 以降を搭載した PC は初期状態で有効になっているものもあり、Linux のインストールにはセキュアブートの無効化が必要になる場合がある** |

**ここで `shim.efi` が効いてきます。**

```text
  UEFI ファームウェア
        │  マイクロソフトの署名しか信用しない
        ▼
  shim.efi           ← UEFI CA（マイクロソフト）の署名を受けている
        │  ここから先は、ディストリビューションの鍵で検証する
        ▼
  grubx64.efi        ← shim が署名を検証して起動する
        │
        ▼
  vmlinuz（カーネル）
```

**`shim.efi` は「橋渡し役」**です。
**マイクロソフトの署名を受けた小さなプログラムを 1 つだけ挟むことで、
その先は各ディストリビューションが自分の鍵で署名したものを起動できる**ようになります。

**これにより、セキュアブートを有効にしたまま Linux を起動できます。**

```bash
$ mokutil --sb-state                          # セキュアブートが有効かどうかを確認する
SecureBoot enabled
```

**補足** … `mokutil` は **MOK（Machine Owner Key）**を管理するコマンドで、
**自分でビルドしたカーネルモジュールに署名して登録する**ときにも使います。
（`mokutil` は `shim` パッケージに付属します。**入っていない環境もあります。**）

### systemd-boot

**systemd が持つ、独自の UEFI ブートマネージャ**です。**UEFI で動く EFI アプリケーションの 1 つ**です。

**使うための条件**

| 条件 | 内容 |
|:--|:--|
| 1 | **システムが UEFI モードで起動している**こと |
| 2 | **ESP パーティションにアクセスできる**こと |
| 3 | **ESP に systemd-boot のバイナリがある**こと |

```bash
$ bootctl status                              # systemd-boot の状態と ESP の場所を確認する
$ sudo bootctl install                        # ESP に systemd-boot をインストールする
```

**補足** … GRUB に比べて**設定が非常に単純**で、**UEFI 専用**です。
**BIOS（レガシー）環境では使えません。**

## U-boot

**U-boot（Universal Boot Loader）は、オープンソースの組み込み用ブートローダ**です。
**ラズベリーパイのような組み込み機器**で広く使われています。

| 特徴 | 内容 |
|:--|:--|
| **ステージ分割** | **サイズの制約に対応するため、複数のステージに分割される仕様**になっている |
| **メモリアドレス** | 他の多くのブートローダが起動時に**メモリ上の配置を自動的に決める**のに対し、**U-boot では明示的に指定することが必要** |
| **コマンド** | **低レベルのコマンド**で、**カーネルをブートするにも複数のステップが必要** |
| **その裏返し** | **手順は増えるが、自由度は高い** |

```text
 一般的なブートローダ          U-boot
 ───────────────          ──────
 起動 → 自動でメモリ配置       起動 → どのアドレスに何を置くかを自分で指定
      → カーネル起動               → 複数のコマンドを順に実行してカーネル起動
```

**補足** … **「自由度が高い＝面倒」ではなく、「ハードウェアが千差万別だから自動化できない」**のが実情です。
組み込み機器はメモリの配置が機種ごとに違うため、**明示指定が前提**になっています。

## Isohybrid と isohdpfx.bin

**ISOLINUX は、CD-ROM や DVD-ROM などの光学メディアからの起動だけに対応したブートローダ**です。
ところが実際には、**ISO ファイルを USB メモリに書き込んで起動したい**場面が多くあります。

**そこで使われるのが Isohybrid** です。

| | |
|:--|:--|
| **何をするか** | **USB スティックなどで、ISOLINUX イメージの MBR コードを使ったブートを可能にし、ブロックデバイスとしても扱えるようにする** |
| **使う MBR コード** | **SYSLINUX の MBR コードである `isohdpfx.bin`** |

```text
 もとの ISO           Isohybrid 適用後
 ───────           ───────────────
 ISO 9660 だけ        先頭に MBR（isohdpfx.bin）を埋め込む
 → 光学メディア専用     → 光学メディアからも USB からも起動できる
```

```bash
$ ls /usr/lib/ISOLINUX/                       # isohdpfx.bin の置き場所を確認する
isohdpfx.bin  isohdppx.bin  isolinux.bin
$ isohybrid ./linux.iso                       # ISO に MBR を埋め込んでUSB起動可能にする
```

**補足** … `dd` で USB メモリに書き込むだけで起動できる ISO は、**ほぼこの処理がされています。**
[ddコマンド](../06_ストレージとファイルシステム/ddコマンド.md) も合わせて参照してください。

## よく使うオプション

**`syslinux`**（`syslinux [オプション] デバイス`）

| オプション | 意味 |
|:--|:--|
| **`-i` / `--install`** | **現在のブートセクタに上書きしてインストールする** |
| `-U` / `--update` | 以前のインストールを更新する |
| `-d` / `--directory` | **インストール先のディレクトリ**を指定する（デバイスの中のパス） |
| `-f` / `--force` | 安全確認を無視して実行する |
| `-s` / `--stupid` | 遅いが安全で確実なモード |
| `-r` / `--raid` | 起動に失敗したら次のデバイスにフォールバックする |
| `-O` / `--clear-once` | 一度だけ実行する起動コマンドを消す |

**`extlinux`**（`extlinux [オプション] ディレクトリ`）

| オプション | 意味 |
|:--|:--|
| **`-i` / `--install`** | **現在のブートセクタに上書きしてインストールする** |
| `-U` / `--update` | 以前のインストールを更新する |
| `--device` | ブロックデバイスを明示指定する（**上級者向け**。通常は不要） |
| `-s` / `--stupid` | 遅いが安全で確実なモード |
| `-r` / `--raid` | 起動に失敗したら次のデバイスにフォールバックする |
| `-M` / `--menu-save=` | 次回の起動で既定にするラベルを設定する |

**`isohybrid`**

| オプション | 意味 |
|:--|:--|
| `-u` / `--uefi` | **UEFI でも起動できるイメージ**にする |
| `-b` / `--mbr <PATH>` | 使う MBR を指定する（既定は `isohdpfx.bin`） |
| `-t` / `--type` | パーティションタイプを指定する（既定 `0x17`） |
| `--partok` | パーティションの内側からの起動を許可する |

> **上の一覧は、`syslinux 6.04` の `--help` の出力をもとにしています。**
> **バージョンによって増減する可能性があるため、実機では `--help` で確認してください。**

## 結果画面の見方

**PXE サーバのディレクトリ**

```bash
$ ls -l /var/lib/tftpboot/                    # TFTPサーバが公開しているディレクトリ
-rw-r--r-- 1 root root  26443 Sep 14 10:00 pxelinux.0
drwxr-xr-x 2 root root   4096 Sep 14 10:02 pxelinux.cfg
-rw-r--r-- 1 root root  85261 Sep 14 10:01 ldlinux.c32
-rw-r--r-- 1 root root 8912345 Sep 14 10:01 vmlinuz
-rw-r--r-- 1 root root 41234567 Sep 14 10:01 initrd.img
```

| 見るもの | 何が分かるか | 異常と判断する目安 |
|:--|:--|:--|
| **`pxelinux.0` があるか** | ブートローダ本体が配れるか | **無ければ TFTP が「ファイルが無い」で止まる** |
| **`pxelinux.cfg/` があるか** | 設定を配れるか | **ディレクトリでなくファイルになっていたら誤り** |
| **`ldlinux.c32` があるか** | **SYSLINUX 6.x は補助モジュールが必須** | **`pxelinux.0` だけ置くと起動途中で止まる** |
| **パーミッション** | TFTP が読めるか | **`root` 以外が読めないと配れない** |

**UEFI の起動エントリ**

```bash
$ sudo efibootmgr -v                          # UEFI に登録された起動エントリを見る
BootCurrent: 0000
BootOrder: 0000,0001,0002
Boot0000* ubuntu    HD(1,GPT,...)/File(\EFI\ubuntu\shimx64.efi)
Boot0001* UEFI OS   HD(1,GPT,...)/File(\EFI\BOOT\BOOTX64.EFI)
Boot0002* UEFI: USB
```

| 欄 | 意味 |
|:--|:--|
| **`BootCurrent`** | **いま起動に使われたエントリ** |
| **`BootOrder`** | **試す順番**。先頭から順に起動を試みる |
| **`Boot0000*`** | エントリ番号。**`*` は有効** |
| **`File(\EFI\...)`** | **ESP の中のどのファイルを読むか**。`shimx64.efi` ならセキュアブート経由 |

**`File()` に何が書いてあるかで、どの経路で起動しているかが分かります。**

| 書いてあるファイル | 起動経路 |
|:--|:--|
| `\EFI\<ディストリ名>\shimx64.efi` | **shim → grub** の順（セキュアブート対応） |
| `\EFI\<ディストリ名>\grubx64.efi` | **grub を直接**（セキュアブート無効） |
| `\EFI\BOOT\BOOTX64.EFI` | **既定の入口**から（USB メモリなど） |

## 名前がまぎらわしいものの整理

**存在するもの**

| 分類 | 名前 |
|:--|:--|
| ブートローダ | **SYSLINUX** / **ISOLINUX** / **PXELINUX** / **EXTLINUX** / **U-boot** / **systemd-boot** / GRUB |
| UEFI アプリ | **`bootx64.efi`** / **`grubx64.efi`** / **`shim.efi`** / **`efiboot.img`** |
| MBR コード | **`isohdpfx.bin`** |

**存在しないもの**（選択肢に混ざります）

| 見かける名前 | 実際は |
|:--|:--|
| **BOOTLINUX** | **存在しない** |
| **NETBOOTLINUX** | **存在しない**（ネットワーク起動は **PXELINUX**） |
| **ISO9660LINUX** | **存在しない**（ISO 9660 からの起動は **ISOLINUX**） |
| **STDLINUX** | **存在しない** |
| **`secure-boot.efi`** | **存在しない**（セキュアブートで最初に読まれるのは **`shim.efi`**） |
| `bootsyslinux` / `installsyslinux` | **存在しないコマンド**（正しくは `syslinux`） |
| `extboot` / `installextlinux` | **存在しないコマンド**（正しくは `extlinux`） |
| `syslinux --device` | **存在しないオプション**（`--device` があるのは `extlinux` のほう） |
| `extlinux -d` | **存在しないオプション**（`-d` があるのは `syslinux` のほう） |

**覚え方** … **「〇〇LINUX」は SYSLINUX パッケージの 4 つだけ**です。
**FAT / ISO / ext / PXE の 4 つの入口**にそれぞれ 1 つ、と覚えると迷いません。
