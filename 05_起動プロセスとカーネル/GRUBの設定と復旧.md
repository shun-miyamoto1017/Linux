## GRUB Legacy と GRUB2

### 2つの世代

**GRUB**（GRand Unified Bootloader）には、**大きく異なる 2 つの世代**があります。

| | **GRUB Legacy**（GRUB 0.9x） | **GRUB2**（現在の主流） |
|:--|:--|:--|
| **バージョン番号** | **`0.9x` 系まで** | **`1.9` 以降** |
| **設定ファイル** | **`/boot/grub/menu.lst`**<br>（環境により **`/boot/grub/grub.conf`**） | **`/boot/grub/grub.cfg`**<br>（下の「設定ファイルはどこにあるか」参照） |
| **設定ファイルの扱い** | **直接編集する** | **自動生成される。直接編集してはいけない** |
| **管理者が編集する場所** | 設定ファイルそのもの | **`/etc/default/grub`** と **`/etc/grub.d/`** |
| **反映のしかた** | **不要**（保存すれば効く） | **`update-grub`** / **`grub2-mkconfig`** で生成し直す |
| **ディスクの数え方** | `(hd0,0)` … **0 から** | `(hd0,msdos1)` … **ディスクは 0 から、パーティションは 1 から** |
| **エントリの書き方** | `title` | `menuentry` |
| **カーネルを指定する命令** | **`kernel`** | **`linux`** |

> **世代を見分けるには、設定ファイルの名前を見ます。**
>
> ```text
>   menu.lst / grub.conf  →  GRUB Legacy   → 直接編集する
>   grub.cfg              →  GRUB2         → 直接編集しない
> ```
>
> **バージョン番号でいうと `1.9` が境目**です。「0.9x が Legacy、1.9 以降が GRUB2」と覚えます。

**どちらの世代にも共通していること**

| 共通点 | 内容 |
|:--|:--|
| **メニューから起動設定を選べる** | どちらも複数のエントリを並べて選択できる。**GRUB Legacy にもこの機能はある** |
| **起動オプションを実行時に指定できる** | **どちらもメニューで `e` キーを押すと、その場で編集できる** |
| **MBR には第1段階だけが入る** | **どちらも MBR（446 バイト）に収まらない**ので、第1段階と第2段階に分かれている |

> **「GRUB2 だけができること」と思い込みやすい 3 つ**です。**どちらも同じようにできます。**
> 第1段階・第2段階の話は [ブートプロセスの全体像](./ブートプロセスの全体像.md) にまとめています。

### 設定ファイルはどこにあるか

**GRUB2 の `grub.cfg` は、環境によって 3 か所に分かれます。**

| 環境 | パス |
|:--|:--|
| **BIOS（一般的な構成）** | **`/boot/grub/grub.cfg`** |
| **BIOS（CentOS 7 など RHEL 系）** | **`/boot/grub2/grub.cfg`** |
| **UEFI** | **`/boot/efi/EFI/<ディストリ名>/grub.cfg`** |

**UEFI のときの `<ディストリ名>` は、ディストリごとに違います。**

| ディストリ | `<ディストリ名>` の部分 | 実際のパス |
|:--|:--|:--|
| **CentOS** | `centos` | `/boot/efi/EFI/centos/grub.cfg` |
| **RHEL** | `redhat` | `/boot/efi/EFI/redhat/grub.cfg` |
| **Ubuntu** | `ubuntu` | `/boot/efi/EFI/ubuntu/grub.cfg` |

```text
   BIOS  一般     /boot/grub/grub.cfg
   BIOS  RHEL系   /boot/grub2/grub.cfg
   UEFI           /boot/efi/EFI/***/grub.cfg
                                 ▲
                        ディストリによって変わる
```

**自分の環境がどれかを調べる**

```bash
$ ls /sys/firmware/efi >/dev/null 2>&1 && echo UEFI || echo BIOS   # BIOS か UEFI かを判定する
BIOS
$ ls -l /boot/grub/grub.cfg /boot/grub2/grub.cfg 2>/dev/null       # BIOS 環境の候補を探す
$ sudo find /boot/efi -name grub.cfg 2>/dev/null                   # UEFI 環境の grub.cfg を探す
```

**補足**

- **`>/dev/null 2>&1`** … 標準出力と標準エラー出力をどちらも捨てる書き方です。**「あるかどうか」だけを知りたいので、表示は要りません**
- **どの環境でも「`grub.cfg` を直接編集しない」は変わりません。** 直すのは `/etc/default/grub` と `/etc/grub.d/` です
- **`update-grub` は `grub-mkconfig -o /boot/grub/grub.cfg` の短縮形**です。出力先が決め打ちなので、**BIOS の一般的な構成でだけ使えます。** RHEL 系や UEFI では **`grub2-mkconfig -o <パス>`** のように出力先を明示します

### GRUB2 の設定の流れ

**GRUB2 でいちばん大事なのは、「どこを直して、どう反映するか」です。**

```text
 ┌────────────────────┐   ┌────────────────────┐
 │ /etc/default/grub  │   │ /etc/grub.d/       │
 │ （変数で設定する）   │   │ （スクリプト群）     │
 └────────────────────┘   └────────────────────┘
            │                        │
            └───────────┬────────────┘
                        │
                        ▼
         update-grub  /  grub2-mkconfig -o …
                        │  読み込んで生成する
                        ▼
            ┌────────────────────────┐
            │ /boot/grub/grub.cfg     │ ← 自動生成。手で編集しない
            └────────────────────────┘
                        │  起動時に GRUB が読む
                        ▼
                    起動メニュー
```

> **`grub.cfg` を直接編集してはいけません。**
> 自動生成されるファイルなので、**次にカーネルが更新されたときなどに生成コマンドが走り、書いた内容は消えます。**
> ファイルの先頭にも「DO NOT EDIT THIS FILE」と書かれています。

**例文**

```bash
$ head -5 /boot/grub/grub.cfg                        # 先頭に編集禁止の注意書きがある
#
# DO NOT EDIT THIS FILE
#
# It is automatically generated by grub-mkconfig using templates
# from /etc/grub.d and settings from /etc/default/grub

$ sudo vi /etc/default/grub                          # 設定を変えるのはこちら
$ sudo update-grub                                   # Debian系：grub.cfg を作り直す
$ sudo grub2-mkconfig -o /boot/grub2/grub.cfg        # RHEL系：grub.cfg を作り直す
```

**補足**

- **`update-grub` は `grub-mkconfig -o /boot/grub/grub.cfg` の短縮形**です。Debian 系にだけあります
- RHEL 系では `grub2-` の接頭辞が付き、出力先も `/boot/grub2/grub.cfg` です

## デバイスの指定のしかた

### GRUB独自の表記

**GRUB は、Linux とは違う独自の表記でディスクを指します。**ここは必ず問われます。

```text
   (hd0,msdos1)
    ─── ─ ──────
     │   │    └─ パーティション番号（GRUB2 は 1 から）
     │   └────── ディスク番号（0 から）
     └────────── デバイスの種類（hd = ハードディスク、fd = フロッピー）
```

| | **GRUB Legacy** | **GRUB2** |
|:--|:--|:--|
| **1 台目のディスクの 1 番目の区画** | **`(hd0,0)`** | **`(hd0,msdos1)`** または `(hd0,1)` |
| **1 台目のディスクの 2 番目の区画** | `(hd0,1)` | `(hd0,msdos2)` |
| **2 台目のディスクの 1 番目の区画** | `(hd1,0)` | `(hd1,msdos1)` |
| **ディスクの数え方** | **0 から** | **0 から**（変わらない） |
| **パーティションの数え方** | **0 から** | **1 から**（**ここが変わった**） |

> **GRUB2 で変わったのは「パーティション番号が 1 から」という点だけ**です。
> ディスク番号はどちらも 0 からです。
>
> ```text
>   Legacy : (hd0,0)       ← 1台目の1番目
>   GRUB2  : (hd0,msdos1)  ← 同じ場所
>              ▲       ▲
>            0 のまま  1 に変わった
> ```

**パーティション形式の接頭辞**

| 書き方 | 意味 |
|:--|:--|
| **`(hd0,msdos1)`** | **MBR 形式**のディスクの 1 番目のパーティション |
| **`(hd0,gpt1)`** | **GPT 形式**のディスクの 1 番目のパーティション |
| `(hd0,1)` | 接頭辞を省略した書き方。GRUB2 でも通る |
| `(hd1,msdos5)` | **論理パーティション**（拡張の中）。**5 から始まる** |
| `(fd0)` | フロッピーディスク |

**Linux の表記との対応**

```text
   Linux           GRUB Legacy      GRUB2
   /dev/sda1  →    (hd0,0)     →    (hd0,msdos1)
   /dev/sda2  →    (hd0,1)     →    (hd0,msdos2)
   /dev/sdb1  →    (hd1,0)     →    (hd1,msdos1)
```

**例文**

```bash
$ lsblk                                              # Linux側のデバイス名を確認する
$ sudo fdisk -l /dev/sda                             # パーティションの並びを見る
$ grep -n "set root" /boot/grub/grub.cfg | head      # grub.cfg でどう指定されているか見る
```

## 設定ファイルの中身

### etc default grub の主な変数

**GRUB2 で管理者が触るのは、基本的にこのファイルです。**

| 変数 | 意味 | よく使う値 |
|:--|:--|:--|
| **`GRUB_DEFAULT`** | **既定で起動するエントリ**。番号（0 から）、タイトル、`saved` | `0` ／ `saved` |
| **`GRUB_TIMEOUT`** | **メニューを表示して待つ秒数**。`0` で即起動、`-1` で無期限 | `5` |
| **`GRUB_CMDLINE_LINUX`** | **すべてのエントリに渡すカーネルパラメータ** | `console=ttyS0` |
| **`GRUB_CMDLINE_LINUX_DEFAULT`** | **通常のエントリにだけ渡すパラメータ**（復旧用には渡さない） | `quiet splash` |
| **`GRUB_DISTRIBUTOR`** | メニューに出すディストリ名 | — |
| **`GRUB_TERMINAL`** | 入出力の装置（`console` / `serial` / `gfxterm`） | `console` |
| **`GRUB_DISABLE_RECOVERY`** | 復旧用エントリを出さない | `true` |
| **`GRUB_TIMEOUT_STYLE`** | メニューの出し方（`menu` / `hidden` / `countdown`） | `menu` |
| **`GRUB_HIDDEN_TIMEOUT`** | **メニューを表示せずに待つ秒数**（古い書き方。`GRUB_TIMEOUT_STYLE=hidden` に相当） | `0` |
| **`GRUB_HIDDEN_TIMEOUT_QUIET`** | **待ち時間のカウントダウンを表示するか**（`true` で非表示） | `true` |
| `GRUB_DISABLE_SUBMENU` | 世代違いのカーネルをサブメニューにまとめない | `true` |
| `GRUB_GFXMODE` | グラフィカルメニューの解像度 | `1024x768` |

**例文**

```bash
$ cat /etc/default/grub                              # 現在の設定を確認する
GRUB_DEFAULT=0
GRUB_TIMEOUT=5
GRUB_DISTRIBUTOR=`lsb_release -i -s 2> /dev/null || echo Debian`
GRUB_CMDLINE_LINUX_DEFAULT="quiet"
GRUB_CMDLINE_LINUX=""

$ sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=10/' /etc/default/grub   # 待ち時間を10秒にする
$ sudo update-grub                                   # 変更を grub.cfg に反映する
$ grep -c menuentry /boot/grub/grub.cfg              # 生成されたエントリの数を数える
```

**補足**

- `sed -i 's/古い/新しい/' ファイル` … ファイルの中身を直接置き換える書き方。`^` は行頭、`.*` は残り全部を表します
- **`GRUB_CMDLINE_LINUX` と `GRUB_CMDLINE_LINUX_DEFAULT` の違い**：前者は**復旧用も含めた全エントリ**に、後者は**通常のエントリだけ**に渡されます

### etc grub.d のスクリプト

`/etc/grub.d/` には、**メニューを組み立てるシェルスクリプト**が番号順に並んでいます。

| ファイル | 役割 |
|:--|:--|
| `00_header` | `/etc/default/grub` を読み込み、メニューの共通部分を出力する |
| `10_linux` | **インストール済みの Linux カーネルのエントリ**を自動で作る |
| `20_linux_xen` | Xen 用のエントリ |
| `30_os-prober` | **他の OS を検出して**エントリを作る |
| **`40_custom`** | **自由に書き足すためのファイル**。**ここに手書きする** |
| `41_custom` | `/boot/grub/custom.cfg` を読み込む |

> **独自のメニュー項目を足したいときは、`40_custom` に書きます。**
> `grub.cfg` を直接編集する代わりの、正しいやり方です。

**例文**

```bash
$ ls /etc/grub.d/                                    # スクリプトを番号順に確認する
$ sudo vi /etc/grub.d/40_custom                      # 独自エントリを書き足す
$ sudo chmod +x /etc/grub.d/40_custom                # 実行権限が無いと読まれない
$ sudo update-grub                                   # 反映する
```

**補足**

- **実行権限が無いスクリプトは読まれません。**足したのに反映されないときは `ls -l /etc/grub.d/` で確認してください

### menuentry の書き方

**`grub.cfg` の中身**（自動生成される部分）は、こう書かれています。

```text
menuentry 'Debian GNU/Linux' {
        set root='hd0,msdos1'
        linux   /vmlinuz-6.1.0-18-amd64 root=UUID=52abae61-… ro quiet
        initrd  /initrd.img-6.1.0-18-amd64
}
```

| 行 | 意味 |
|:--|:--|
| **`menuentry '名前' { … }`** | **メニューに出す 1 項目**。`{ }` の中が、選ばれたときに実行される |
| **`set root='hd0,msdos1'`** | **カーネルを読みに行くパーティション**を指定する |
| **`linux パス オプション`** | **カーネルを読み込む**。後ろに続くのが**カーネルパラメータ** |
| **`initrd パス`** | **初期RAMディスクを読み込む**。**`linux` より後に書く** |

**GRUB Legacy との対応**

| GRUB Legacy（`menu.lst`） | GRUB2（`grub.cfg`） |
|:--|:--|
| `title Debian` | `menuentry 'Debian' {` |
| `root (hd0,0)` | `set root='hd0,msdos1'` |
| **`kernel /vmlinuz-… root=/dev/sda1 ro`** | **`linux /vmlinuz-… root=UUID=… ro`** |
| `initrd /initrd.img-…` | `initrd /initrd.img-…` |
| `default 0` | `GRUB_DEFAULT=0`（`/etc/default/grub`） |
| `timeout 5` | `GRUB_TIMEOUT=5`（同上） |

> **命令名が `kernel` から `linux` に変わった**のが、世代を見分ける目印のひとつです。

## GRUB をディスクに入れる

### grub-install

**意味**

**ブートローダ本体を、ディスクの MBR（または ESP）に書き込む**コマンドです。
GRUB が壊れて起動しなくなったときの、復旧の要になります。

**例文**

```bash
$ sudo grub-install /dev/sda                         # BIOS環境：1台目のディスクのMBRに入れる
$ sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi   # UEFI環境：ESPに入れる
$ sudo grub-install --boot-directory=/mnt/boot /dev/sda             # 別の場所を /boot として扱う
$ sudo grub2-install /dev/sda                        # RHEL系のコマンド名
```

**よく使うオプション**

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`--target=形式`** | **対象のプラットフォーム**（`i386-pc` / `x86_64-efi`） | BIOS か UEFI かを明示する |
| **`--efi-directory=パス`** | **ESP のマウント先**を指定する | UEFI 環境で必須 |
| **`--boot-directory=パス`** | **`/boot` として扱うディレクトリ**（既定は `/boot`） | **復旧作業で `chroot` せずに使う** |
| **`--recheck`** | デバイスの対応表を作り直す | ディスク構成を変えたあと |
| **`--force`** | 警告を無視して実行する | 最終手段 |

**補足**

- **引数はパーティションではなくディスク全体**です。`/dev/sda1` ではなく **`/dev/sda`** を指定します
- **`grub-install` は MBR を書き換えます。**間違ったディスクを指定すると、そのディスクが起動しなくなります

### grub コマンドとGRUBシェル

**意味**

**`grub` は、GRUB Legacy に付属する「GRUB シェル」を Linux 上から呼び出すコマンド**です。
**GRUB シェル**とは、**GRUB に関する操作を対話的に行えるプログラム**のことです。

**GRUB シェルには、入り口が 2 つあります。**

```text
   ■ システム起動時に入る
        GRUB のメニューで  c  キーを押す   →  grub>  プロンプト

   ■ Linux が動いている状態から入る（GRUB Legacy のみ）
        # grub                             →  grub>  プロンプト
```

**`grub` コマンドと `grub-install` は、どちらも MBR へのインストールに使えます。**

| コマンド | どこから使うか | 何ができるか |
|:--|:--|:--|
| **`grub-install /dev/sda`** | **Linux 上から** | **MBR へインストールする**（GRUB Legacy / GRUB2 の両方。RHEL 系は `grub2-install`） |
| **`grub`** | **Linux 上から**（GRUB Legacy のみ） | **GRUB シェルに入る。** そこから `setup` などでインストールできる |

**例文**

```bash
$ sudo grub                                          # GRUB シェルに入る（GRUB Legacy）
grub> find /boot/grub/stage1                         # stage1 のあるパーティションを探す
 (hd0,0)
grub> root (hd0,0)                                   # そのパーティションをルートに設定する
grub> setup (hd0)                                    # 1台目のディスクの MBR にインストールする
grub> quit                                           # GRUB シェルを抜ける
```

**補足**

- **`grub` コマンドは GRUB Legacy のものです。** GRUB2 には同名のコマンドはなく、**`grub-install`（または `grub2-install`）を使います**
- **ブートローダを壊してしまったときは、CD/DVD などのメディアから臨時に起動し、これらのコマンドで入れ直します**（次の「起動できなくなったときの復旧手順」）
- **GRUB シェルでは、現在動いているカーネルの起動オプションは分かりません。** それを知りたいときは **`/proc/cmdline`** か **`dmesg`** を見ます（[カーネルの実行時管理 dmesgとsysctl](./カーネルの実行時管理_dmesgとsysctl.md)）

---

### device.map でGRUBとLinuxの対応を見る

**意味**

**GRUB は `hd0` / `hd1` という独自の名前でディスクを指します。**
**この名前と、Linux 側の `/dev/sda` などの対応を記録しているのが `device.map`** です。

**置き場所**

| 環境 | パス |
|:--|:--|
| **一般的な構成** | **`/boot/grub/device.map`** |
| **RHEL 系（CentOS 7 など）** | **`/boot/grub2/device.map`** |

**例文**

```bash
$ cat /boot/grub2/device.map                         # GRUB と Linux のデバイス名の対応を見る
# this device map was generated by anaconda
(hd0)      /dev/sda                                  # hd0 は /dev/sda のこと

$ sudo grub2-install --recheck /dev/sda              # 対応表を作り直す（ディスク構成を変えたあと）
```

**補足**

- **`hd0` がどのディスクかを確かめたいときは、まずここを見ます。** ディスクを増設・交換したあと、**GRUB から見た順番が入れ替わっている**ことがあるためです
- **ファイルが無い環境もあります。** GRUB2 は UUID でディスクを識別できるので、`device.map` に頼らない構成が増えています
- **作り直すには `--recheck`** を付けて `grub-install` / `grub2-install` を実行します

---

### 起動できなくなったときの復旧手順

**インストールメディアやレスキューモードから起動して、次の順で作業します。**

| 手順 | やること | コマンド例 |
|:--|:--|:--|
| **①** | ルートになるパーティションをマウントする | `mount /dev/sda2 /mnt` |
| **②** | `/boot` が別パーティションならマウントする | `mount /dev/sda1 /mnt/boot` |
| **③** | 仮想ファイルシステムを引き継ぐ | `mount --bind /dev /mnt/dev` など |
| **④** | そこをルートとして入り込む | `chroot /mnt` |
| **⑤** | GRUB を入れ直す | `grub-install /dev/sda` |
| **⑥** | 設定を作り直す | `update-grub` |
| **⑦** | 抜けて再起動する | `exit` → `reboot` |

**例文**

```bash
$ sudo mount /dev/sda2 /mnt                          # ルートになるパーティションをマウントする
$ sudo mount /dev/sda1 /mnt/boot                     # /boot が別なら一緒にマウントする
$ for d in dev proc sys; do sudo mount --bind /$d /mnt/$d; done   # 仮想FSを引き継ぐ
$ sudo chroot /mnt                                   # そこをルートとして入り込む
# grub-install /dev/sda                              # GRUB を MBR に入れ直す
# update-grub                                        # grub.cfg を作り直す
# exit                                               # chroot から抜ける
$ sudo reboot                                        # 再起動する
```

**補足**

- **`chroot`** … 指定したディレクトリを「/」とみなして、その中でコマンドを実行する仕組み。**壊れたシステムを、外から正常なカーネルで操作する**ために使います
- `mount --bind` … 既にマウントされているものを、別の場所にも見せる。`/dev` や `/proc` を引き継がないと、`grub-install` が失敗します
- `for d in … ; do … ; done` … 3 つの値を順に処理する繰り返し。1 つずつ 3 回打っても同じです

## 起動時にその場で直す

### メニューでのキー操作

**GRUB のメニューが出ている間に、その場で設定を変えられます。**再起動すれば元に戻るので、**試すだけなら安全**です。

| キー | できること |
|:--|:--|
| **`e`** | **選んでいるエントリを編集する**（その場かぎり） |
| **`c`** | **GRUB のコマンドラインに入る** |
| **`↑` `↓`** | エントリを選ぶ |
| **`Enter`** | 選んだエントリで起動する |
| **`Esc`** | 編集をやめてメニューに戻る |
| **`Ctrl + x`** または **`F10`** | **編集した内容で起動する** |

> **メニューが一瞬で消えてしまうときは、起動中に `Shift` キー（BIOS）または `Esc` キー（UEFI）を押し続ける**と出せます。

---

### カーネルパラメータを足して起動する

**`e` で編集画面に入り、`linux` で始まる行の末尾にパラメータを足して `Ctrl + x`** で起動します。

```text
   linux /vmlinuz-6.1.0-18-amd64 root=UUID=52ab… ro quiet
                                                        ▲
                                             ここにパラメータを足す
```

**復旧でよく使うパラメータ**

| パラメータ | 効果 | 使いどころ |
|:--|:--|:--|
| **`single`** / **`1`** / **`s`** | **シングルユーザモード**で起動する。**この 3 つはすべて同じ意味** | 最小構成で調査する |
| **`systemd.unit=rescue.target`** | **レスキューモード**で起動する | systemd 環境での `single` 相当 |
| **`systemd.unit=emergency.target`** | **緊急モード**で起動する | レスキューでも起動しないとき |
| **`rd.break`** | **initramfs の段階で止める**（ルート切り替えの前） | **root パスワードの再設定**（RHEL 系の定番） |
| **`init=/bin/bash`** | **`systemd` の代わりにシェルを起動する** | 同上（汎用） |
| **`ro`** / **`rw`** | ルートを読み取り専用／読み書き可でマウントする | `rw` にすると編集しやすい |
| **`quiet`** | 起動メッセージを抑える | **外すと詳細が見える**（調査時は外す） |
| **`nomodeset`** | グラフィックのドライバを使わない | 画面が真っ暗なとき |
| **`console=ttyS0`** | **シリアルコンソールに出力する** | クラウドのコンソールログに出したいとき |
| **`0` 〜 `6`（数字だけ）** | **その番号のランレベルで起動する** | **`3` で CUI、`5` で GUI、`1` でシングルユーザ** |
| **`init=<PATH>`** | **`init` の代わりに、指定したコマンドを実行する** | `init=/bin/bash` でシェルに落ちる |
| **`nosmp`** / **`maxcpus=0`** | **マルチプロセッサ機を、シングルプロセッサとして動かす** | CPU まわりの不具合を切り分けるとき |
| **`maxcpus=<N>`**（1 以上） | **使う CPU の最大数を指定する**（`maxcpus=1` なら 1 個だけ使う） | 使用 CPU 数を絞って挙動を見たいとき |
| **`root=UUID=…`** | ルートファイルシステムを指定する | `root=` が間違っているとき |

**例文（root パスワードを忘れたとき）**

```bash
# 1) GRUB メニューで e キー → linux 行の末尾に init=/bin/bash を足す → Ctrl+x
# 2) シェルが起動したら、ルートを読み書き可で再マウントする
mount -o remount,rw /                                # ルートを書き込み可にする
passwd root                                          # root のパスワードを設定し直す
touch /.autorelabel                                  # SELinux を使っているならラベルを付け直す
exec /sbin/init                                      # 通常の起動に戻す（または強制再起動）
```

**補足**

- **`exec /sbin/init`** … 今のシェルを systemd に置き換えて、通常の起動を続けます。うまくいかないときは `reboot -f` で強制再起動します
- **`touch /.autorelabel`** … RHEL 系で SELinux が有効なとき、次回起動時にラベルを付け直させるための目印です。これを忘れるとログインできなくなることがあります
- **この操作は物理コンソールがあれば誰でもできます。**だからこそ、**サーバの物理的な保護と、GRUB のパスワード設定**が意味を持ちます

---

### ランレベルを指定して起動する

**起動するランレベルは、カーネルを指定する行の末尾に「数字だけ」を足して指定します。**
`runlevel=3` のような書き方ではありません。**`3` と数字を置くだけ**です。

**どの行に足すかが、GRUB の世代で違います。**

| 世代 | 足す行 | 書き方 |
|:--|:--|:--|
| **GRUB2** | **`linux` で始まる行** | `linux /boot/vmlinuz-… root=/dev/sda1 ro **1**` |
| **GRUB Legacy** | **`kernel` で始まる行** | `kernel /boot/vmlinuz-… root=/dev/sda1 ro **1**` |

> **`linux` 行（GRUB2）と `kernel` 行（GRUB Legacy）は、同じ役割の項目**です。
> どちらも「**このカーネルイメージを、このオプションで起動する**」という指定で、名前が世代で変わっただけです。

**GRUB2 の設定ファイル（`/etc/grub.d/40_custom` などのカスタム設定）での例**

```text
   menuentry 'Ubuntu, with Linux 3.2.0-29-generic-pae' …(略){
       ...(略)
       set root='(hd0,3)'
       linux  /boot/vmlinuz-3.2.0-29-generic-pae root=/dev/sda1 ro 1
       initrd /boot/initrd.img-3.2.0-29-generic-pae            ▲
   }                                                           │
                                                  末尾に 1 を足すと
                                             ランレベル1（シングルユーザ）で起動する
```

**`linux` 行に書ける起動オプション**

| 起動オプション | 説明 |
|:--|:--|
| **`init=<PATH>`** | **`init` の代わりに、指定したコマンドを実行する** |
| **`root=<DEVICE>`** | **ルートファイルシステムを設定する** |
| **数字（`0`〜`6`）** | **指定したランレベルで起動する** |
| **`single`** | **シングルユーザモードで起動する**（`1` と同じ意味） |
| **`nosmp`** ／ **`maxcpus=0`** | **マルチプロセッサマシンを、シングルプロセッサマシンとして動作させる** |

> **`run level 3` のような書き方はありません。** `run level` というオプションは存在しないので、**数字だけを置く**と覚えてください。

**`/etc/inittab` との関係**

```text
   /etc/inittab の initdefault  … 何も指定しなかったときの既定のランレベル
            ↑ 上書きされる
   GRUB の linux 行に足した数字 … その回かぎり、こちらが優先される
```

> **SysVinit の環境では `/etc/inittab` でも起動時のランレベルを決められますが、GRUB での指定が優先されます。**
> 「`inittab` を直したのに、意図した状態で上がらない」ときは、**ブートローダ側に数字が残っていないか**を確認してください。
> `/etc/inittab` の書き方は [SysVinit の起動スクリプトとランレベル](./SysVinitの起動スクリプトとランレベル.md) にまとめています。

**例文**

```bash
$ cat /proc/cmdline                                  # 今回の起動で渡された内容を確認する
BOOT_IMAGE=/vmlinuz-6.1.0-18-amd64 root=UUID=52ab… ro quiet 3
$ runlevel                                           # 実際にどのランレベルで上がったか見る
N 3
```

**補足**

- **systemd の環境では、数字のランレベル指定も受け付けられ、対応するターゲットに読み替えられます**（`3` → `multi-user.target`、`5` → `graphical.target`）。ただし**`systemd.unit=multi-user.target` と明示するほうが意図が伝わります**
- **恒久的に変えたいときは、GRUB ではなく `systemctl set-default` を使います。** GRUB メニューでの指定は、その回かぎりです

---

### GRUB のコマンドライン

**`c` キーで入ると、GRUB 自身のコマンドを打てます。**`grub.cfg` が壊れているときの最後の手段です。

| コマンド | 意味 |
|:--|:--|
| **`ls`** | **認識しているディスクとパーティションを一覧する** |
| **`ls (hd0,msdos1)/`** | そのパーティションの中身を見る |
| **`set root=(hd0,msdos1)`** | ルートにするパーティションを指定する |
| **`linux /vmlinuz-… root=/dev/sda2 ro`** | カーネルを読み込む |
| **`initrd /initrd.img-…`** | 初期RAMディスクを読み込む |
| **`boot`** | **読み込んだ内容で起動する** |
| `set` | 現在の変数を一覧する |

**手動で起動する流れ**

```text
   grub> ls                          ← どのパーティションがあるか調べる
   grub> ls (hd0,msdos1)/            ← /boot の中身が見えるか確かめる
   grub> set root=(hd0,msdos1)
   grub> linux /vmlinuz-6.1.0-18-amd64 root=/dev/sda2 ro
   grub> initrd /initrd.img-6.1.0-18-amd64
   grub> boot                        ← 起動する
```

> **これで起動できたら、ログイン後に `grub-install` と `update-grub` で恒久的に直します。**
> コマンドラインでの操作は、その場かぎりです。

## 結果画面の見方

### grub.cfg の読み方

```bash
$ sudo grep -n "menuentry\|linux\|initrd" /boot/grub/grub.cfg | head -12   # 主要な行だけ抜き出す
110:menuentry 'Debian GNU/Linux' --class debian --class gnu-linux {
120:	linux	/vmlinuz-6.1.0-18-amd64 root=UUID=52abae61-… ro quiet
121:	initrd	/initrd.img-6.1.0-18-amd64
```

| 見る場所 | 何が分かるか | 異常と判断する目安 |
|:--|:--|:--|
| **`menuentry` の数** | **起動メニューに出る項目の数** | **古いカーネルが 1 つも無い**と、失敗時に戻れない |
| **`linux` のパス** | **読み込むカーネルのファイル** | `ls /boot/` に**実在しない**なら起動しない |
| **`linux` の `root=`** | **ルートファイルシステムの指定** | UUID が `blkid` の結果と違えば起動しない |
| **`initrd` のパス** | **初期RAMディスクのファイル** | 同じく実在しなければ panic |
| **`set root=`** | **カーネルを読みに行く場所** | `/boot` が別パーティションのとき要注意 |

**整合性の確認**

```bash
$ ls /boot/vmlinuz-* /boot/initrd.img-*               # 実在するファイルを確認する
$ sudo blkid                                          # 各パーティションのUUIDを確認する
$ grep -o "root=UUID=[^ ]*" /boot/grub/grub.cfg | sort -u   # grub.cfg が指しているUUIDを抜き出す
$ cat /proc/cmdline                                   # 今回の起動で実際に渡された内容を見る
```

**補足**

- `grep -o` … **一致した部分だけ**を取り出す。`[^ ]*` は「空白以外が続くかぎり」という意味です
- **`/proc/cmdline` と `grub.cfg` を見比べる**と、「設定は直したが反映されていない」状態がすぐ分かります
