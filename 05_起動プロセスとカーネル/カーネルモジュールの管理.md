## モジュールとは

### 意味

**カーネルモジュール**は、**カーネルに後から付け外しできる部品**です。拡張子は **`.ko`**（kernel object）。

**拡張子を取り違えない**

似た拡張子が並ぶので、まとめて整理します。

| 拡張子 | 何のファイルか |
|:--|:--|
| **`.ko`** | **カーネルモジュール**（kernel object）。**これが正解** |
| `.o` | C/C++ などのソースをコンパイルした**オブジェクトファイル** |
| `.so` | **動的にロードできるライブラリ**（共有ライブラリ／動的ライブラリ） |
| `.a` | **コンパイル時にリンクして使うライブラリ**（静的ライブラリ） |

ドライバの多くはモジュールになっています。
必要なときだけ読み込めば済むので、**カーネル本体を小さく保てる**のが利点です。

```text
  ┌──────────────────────────────────┐
  │        カーネル本体（vmlinuz）     │
  │                                  │
  │   ┌────┐  ┌────┐  ┌────┐          │  ← 必要なときに差し込む
  │   │xfs │  │e1000│ │nvme│  …       │     これがモジュール（.ko）
  │   └────┘  └────┘  └────┘          │
  └──────────────────────────────────┘
```

---

### 置き場所

モジュールは、**カーネルのバージョンごとに分かれたディレクトリ**に置かれます。

```text
/lib/modules/(uname -r の文字列)/
 ├── kernel/                  ← モジュール本体（.ko）が用途別に並ぶ
 │    ├── drivers/
 │    ├── fs/
 │    └── net/
 ├── modules.dep              ← 依存関係（テキスト）
 ├── modules.dep.bin          ← 依存関係（プログラムが読む形式）
 ├── modules.alias            ← 別名の対応表
 ├── modules.symbols          ← どのモジュールがどのシンボルを提供するか
 └── modules.builtin          ← カーネル本体に組み込み済みの機能の一覧
```

**例文**

```bash
$ uname -r                                           # 動いているカーネルのバージョンを見る
6.1.0-18-amd64

$ ls /lib/modules/$(uname -r)/                       # そのバージョンのモジュール一式を確認する
kernel  modules.alias  modules.builtin  modules.dep  modules.dep.bin  modules.symbols

$ find /lib/modules/$(uname -r) -name "xfs.ko*"      # 特定のモジュールの実体を探す
/lib/modules/6.1.0-18-amd64/kernel/fs/xfs/xfs.ko
```

**補足**

- **バージョンごとにディレクトリが分かれている**ので、カーネルを更新しても古いモジュールは残ります
- **`uname -r` の文字列とディレクトリ名が食い違うと、モジュールは一切読み込めません。**ここは障害調査の定番の確認ポイントです

## モジュールを操作するコマンド

まず**役割の違い**を表で押さえます。**ここを混同すると調査が進みません。**

| コマンド | 何をするか | 依存関係を見るか |
|:--|:--|:--|
| **`lsmod`** | **読み込まれているモジュールの一覧**を表示する | — |
| **`modinfo`** | モジュールの**情報**（パス・説明・パラメータ）を表示する | — |
| **`insmod`** | **ファイルを直接指定して**モジュールを読み込む | **見ない**（依存は自分で解決する） |
| **`rmmod`** | モジュールを**外す** | **見ない** |
| **`modprobe`** | **名前で**モジュールを読み込む／外す | **見る**（依存も自動で処理する） |
| **`depmod`** | 依存関係の一覧ファイルを**作り直す** | 作る側 |

> **実務で使うのは `modprobe` です。**
> `insmod` / `rmmod` は依存関係を見てくれないため、**手順が増えて事故りやすい**からです。

---

### lsmod

**意味**

**今カーネルに読み込まれているモジュールの一覧**を表示します。
中身は `/proc/modules` を読みやすく整形したものです。

**例文**

```bash
$ lsmod                                              # 読み込まれているモジュールを一覧する
Module                  Size  Used by
xfs                  2138112  1
libcrc32c              16384  1 xfs
e1000e                299008  0

$ lsmod | grep xfs                                   # 特定のモジュールが入っているか確認する
$ lsmod | wc -l                                      # 読み込まれている数をかぞえる
$ cat /proc/modules                                  # lsmod の元データを直接見る
```

**よく使うオプション**

`lsmod` に**オプションはありません**（`--help` と `--version` のみ）。
絞り込みは `grep` と組み合わせます。

**補足**

- **`lsmod` に出てこない＝使えない、ではありません。**カーネル本体に組み込まれた機能（`=y`）は出てきません

```bash
$ grep xfs /lib/modules/$(uname -r)/modules.builtin   # 組み込み済みかどうかを確認する
$ grep CONFIG_XFS_FS /boot/config-$(uname -r)         # =y なら組み込み、=m ならモジュール
```

### modinfo

**意味**

モジュールの**素性**を調べます。実体のパス、説明、対応カーネル、指定できるパラメータが分かります。

**例文**

```bash
$ modinfo xfs                                        # モジュールの情報をすべて表示する
filename:       /lib/modules/6.1.0-18-amd64/kernel/fs/xfs/xfs.ko
license:        GPL
description:    SGI XFS with ACLs, security attributes, no debug enabled
depends:        libcrc32c
vermagic:       6.1.0-18-amd64 SMP preempt mod_unload modversions

$ modinfo -p e1000e                                  # 指定できるパラメータだけ表示する
$ modinfo -F filename xfs                            # 実体のパスだけ取り出す
$ modinfo -k 6.1.0-17-amd64 xfs                      # 別バージョン向けの情報を見る
```

**よく使うオプション**

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-F 欄名`** / `--field` | **指定した欄だけ**を表示する | スクリプトで値を取り出すとき |
| **`-p`** / `--parameters` | **指定できるパラメータ**の一覧を表示する | 挙動を変えたいとき |
| **`-a`** / `--author` | 作者だけ表示する | — |
| **`-d`** / `--description` | 説明だけ表示する | 何のモジュールか手早く知りたいとき |
| **`-l`** / `--license` | ライセンスだけ表示する | — |
| **`-n`** / `--filename` | **実体のファイル名だけ**表示する（`-F filename` と同じ） | パスを知りたいとき |
| **`-k バージョン`** | **別のカーネルバージョン**のモジュールを調べる | 更新前後の比較 |
| **`-0`** | 区切りを改行ではなく `\0` にする | スクリプト用 |

### modprobe

**意味**

**モジュールを名前で読み込み・取り外し**します。
**`modules.dep` を見て、必要なモジュールを自動で先に読み込む**のが最大の利点です。

**書式**

```text
   modprobe [オプション] モジュール名
```

**`modprobe` の性質を 4 つで押さえる**

| 性質 | 正しいか | 補足 |
|:--|:--:|:--|
| **カーネルモジュールの依存関係を自動的に解決する** | **正しい** | `modules.dep` を読んで、足りないものを先に読み込む |
| **ロード・アンロードのどちらも行える** | **正しい** | オプション無しでロード、**`-r`** でアンロード |
| **オプションで依存関係を調べることができる** | **正しい** | **`--show-depends`** で、指定したモジュールの依存を表示する |
| **モジュール名だけでよい（フルパス不要）** | **正しい** | フルパスが要るのは **`insmod`** のほう |

**間違いやすい説明**

| 説明 | 正しくは |
|:--|:--|
| 「`modprobe` は依存関係を**更新**する」 | 更新するのは **`depmod`**。`modprobe` は**使う側** |
| 「`modprobe` はロードされているモジュールの**一覧を表示**する」 | 一覧は **`lsmod`** |
| 「`modprobe` は**フルパスを指定する必要がある**」 | フルパスが必要なのは **`insmod`** |
| 「`--show-depends` は**全モジュール**の依存を表示する」 | **モジュール名を必ず指定する。**全件の一覧はできない |
| 「`--show-depends` は依存を考慮して**アンロード**する」 | **表示するだけ。**アンロードは `-r` |
| 「`-r` は指定したモジュールを**再読込**する」 | `-r` は **remove（アンロード）**。再読込ではない |

**例文**

```bash
$ sudo modprobe xfs                                  # 依存も含めて読み込む
$ sudo modprobe -r xfs                               # 取り外す（依存していたものも外れる）
$ sudo modprobe -n -v xfs                            # 実行せずに、何が起きるか表示する
$ modprobe --show-depends xfs                        # 読み込まれる順番を確認する
$ sudo modprobe e1000e InterruptThrottleRate=3000    # パラメータを指定して読み込む
$ modprobe -c | head                                 # 有効な設定をすべて表示する
```

**よく使うオプション**

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-r`** / `--remove` | **モジュールを外す**（依存していて不要になったものも外す） | 後片付け |
| **`-n`** / `--dry-run` | **実際には読み込み・取り外しをせず**、動作だけ確認する | **本番前に必ず** |
| **`-v`** / `--verbose` | 実行している内容を表示する | `-n` とセットで使う |
| **`--show-depends`** | **読み込まれるモジュールの順番**を表示する | 依存の確認 |
| **`-c`** / `--show-config` | **有効になっている設定**をすべて表示する | `modprobe.d` の反映確認 |
| **`-q`** / `--quiet` | エラーを表示しない | スクリプトの中で |
| **`-f`** / `--force` | **強制的に操作を行う。**`modprobe` は通常、モジュールのバージョンをチェックして問題があれば読み込みませんが、**そのチェックを省いて**読み込む | **最終手段**。カーネルが不安定になりうる |
| **`-i`** / `--ignore-install` | 設定ファイルの `install` 行を無視する | 設定の切り分け |
| **`-b`** / `--use-blacklist` | `blacklist` 設定を適用する | 自動読み込みの検証 |
| **`-S バージョン`** | 対象のカーネルバージョンを指定する | 別カーネル向けの確認 |
| **`--first-time`** | **既に読み込み済みならエラーにする** | 冪等性を確かめたいとき |

**補足**

- `modprobe` は **`/lib/modules/(バージョン)/modules.dep.bin`** を読みます。手でコピーした `.ko` が見つからないときは、**先に `depmod`** を実行してください
- **`-r` で外せないのは「使用中」だから**です。`lsmod` の `Used by` を見て、先に上に載っているモジュールを外します

### insmod と rmmod

**意味**

| コマンド | 動作 | 依存関係 |
|:--|:--|:--|
| **`insmod`** | **ファイルのパスを直接指定して**読み込む | **見ない**。足りないと `Unknown symbol` で失敗する |
| **`rmmod`** | **指定したモジュールだけ**を外す | **見ない**。ほかのモジュールから使われている場合は失敗する |

> **`rmmod` が依存関係で失敗したら、`modprobe -r` に切り替えます。**
> `modprobe -r` なら、**指定したモジュールと、それに依存しているモジュールの両方**を自動で外してくれます。
>
> ```text
>   rmmod xfs        → 「使用中」で失敗することがある（依存を見ない）
>   modprobe -r xfs  → 依存しているモジュールも含めて外す
> ```
>
> Red Hat 系のドキュメントでも、**`rmmod` ではなく `modprobe -r` を使うことが推奨**されています。

**例文**

```bash
$ sudo insmod /lib/modules/$(uname -r)/kernel/lib/libcrc32c.ko   # 先に土台を読み込む
$ sudo insmod /lib/modules/$(uname -r)/kernel/fs/xfs/xfs.ko      # そのうえで本体を読み込む
$ sudo rmmod xfs                                     # 外す（先に上に載っているものを外しておく）
$ sudo rmmod -v xfs                                  # 何をしているか表示しながら外す
```

**よく使うオプション**

| コマンド | オプション | 意味 |
|:--|:--|:--|
| `insmod` | **`-f`** | バージョン不一致でも**強制的に**読み込む |
| `insmod` | `-v` | **現在の `kmod` 版には無い**（`insmod: invalid option -- 'v'` になる。あったのは旧 module-init-tools 版。実測） |
| `rmmod` | **`-f`** / `--force` | **強制的に**外す（カーネルが `CONFIG_MODULE_FORCE_UNLOAD` で作られている場合のみ） |
| `rmmod` | **`-v`** / `--verbose` | 詳しく表示する |
| `rmmod` | **`-s`** / `--syslog` | メッセージを syslog へ出す |

**補足**

- **`insmod` は名前ではなくパスを取ります。**`insmod xfs` は動きません
- **同じことは `modprobe` なら 1 行で済みます。**試験では両者の違い（依存を見るかどうか）が問われます

## modprobe の設定ファイル

読み込むときの**別名・パラメータ・禁止**を、設定ファイルで決められます。

| 場所 | 誰のものか |
|:--|:--|
| **`/etc/modprobe.conf`** | **古い形式**。1 つのファイルにまとめて書く。現在も読まれる環境がある |
| **`/etc/modprobe.d/*.conf`** | **現在の形式。**目的ごとにファイルを分けて置くと、**そのすべてが読み込まれる** |
| `/lib/modprobe.d/*.conf` | パッケージが置く（触らない） |
| `/run/modprobe.d/*.conf` | 実行時に生成されるもの |

> **「`modprobe` の設定ファイルはどれか」と問われたら、`/etc/modprobe.conf` と `/etc/modprobe.d/*.conf` の両方**が答えです。
> 古くは `modprobe.conf` の 1 ファイルでしたが、現在は `modprobe.d` の中に分けて置く方式になっています。

**よく似た名前のファイルとの区別**

| ファイル | 何の設定か |
|:--|:--|
| **`modprobe.conf` / `modprobe.d/*.conf`** | **カーネルモジュール**の設定 |
| `sysctl.conf` | **カーネルパラメータ**の設定 → [カーネルの実行時管理 dmesgとsysctl](./カーネルの実行時管理_dmesgとsysctl.md) |
| `grub.conf` | **ブートローダ GRUB Legacy** の設定 |
| `aliases` | **メールアドレス**のエイリアス設定 |

### 書ける行

**書式は「1 行に 1 つの設定、各項目は空白で区切る」です。**

| 書き方 | 意味 |
|:--|:--|
| **`alias 別名 モジュール名`** | モジュールに**別名**を付ける |
| **`options モジュール名 パラメータ=値`** | 読み込むときの**パラメータ**を決めておく（複数書ける） |
| **`blacklist モジュール名`** | **自動での読み込みを禁止する**（手動の `modprobe` は通る） |
| **`install モジュール名 コマンド`** | 読み込む代わりに**指定したコマンドを実行する** |
| **`remove モジュール名 コマンド`** | 外すときに指定したコマンドを実行する |
| **`softdep モジュール名 pre: 別モジュール`** | 依存には出ないが**先に読み込みたい**モジュールを指定する |

### alias は書く順番が決まっている

**`alias` は 2 つの語の順番を取り違えやすい**ので、図で固定します。

```text
   alias   X      Y
           ─      ─
         別名   モジュール名

   → 「X が Y の別名になる」
```

**例**：`modprobe eth1` と打ったときに **`tg3`** が読み込まれるようにしたい。

```text
   呼びたい名前（別名）  =  eth1
   実際のモジュール      =  tg3

   → alias eth1 tg3
```

| 書き方 | 結果 |
|:--|:--|
| **`alias eth1 tg3`** | **正しい。**`modprobe eth1` で `tg3` が読み込まれる |
| `alias tg3 eth1` | **逆。**`modprobe tg3` で `eth1` を探してしまう |
| `options eth1 eth1=tg3` | `options` は**パラメータ**を渡す行。別名の設定ではない |
| `install tg3=eth1` | `install` は**実行するコマンド**を書く行。`=` の書き方も違う |

**実際の設定ファイルの例**

```text
1:  alias uhci uhci-hcd
2:  install snd-emu10k1 /sbin/modprobe --ignore-install snd-emu10k1 && /sbin/modprobe snd-emu10k1-synth
3:  remove ov518_decomp /sbin/modprobe -r --first-time --ignore-remove ov518_decomp && { /sbin/modprobe -r ov511; /bin/true; }
4:  options b43 nohwcrypt=1 qos=0
```

| 行 | 読み方 |
|:--|:--|
| **1 行目** | `uhci` は `uhci-hcd` の別名 |
| **2 行目** | `snd-emu10k1` を読み込むとき、**3 番目以降はシェルコマンド**。空白を含んでいても行末までがコマンドとして扱われる |
| **3 行目** | 外すときに実行するコマンド。同じく行末まで |
| **4 行目** | `b43` に `nohwcrypt=1` と `qos=0` の**2 つのパラメータ**を渡す |

**例文**

```bash
$ cat /etc/modprobe.d/my-alias.conf                  # 自分で作った別名の設定を確認する
alias eth1 tg3

$ sudo modprobe -c | grep eth1                       # 設定が効いているか確認する
$ sudo modprobe eth1                                 # 別名で読み込んでみる
$ lsmod | grep tg3                                   # 実体の tg3 が読み込まれたか確認する
```

**例文**

```bash
$ cat /etc/modprobe.d/blacklist-nouveau.conf         # 自動読み込みを止める設定の例
blacklist nouveau
options nouveau modeset=0

$ sudo modprobe -c | grep nouveau                    # 設定が効いているか確認する
$ sudo update-initramfs -u                           # Debian系：設定を initramfs にも反映する
$ sudo dracut -f                                     # RHEL系：設定を initramfs にも反映する
```

**補足**

- **`blacklist` は「手動でも読み込めない」設定ではありません。**自動読み込みを止めるだけです。完全に止めるなら `install モジュール名 /bin/false` を使います
- 起動の初期に読み込まれるモジュールを止めたい場合は、**初期RAMディスクの作り直しが必要**です → [初期RAMディスク initrdとinitramfs](./初期RAMディスク_initrdとinitramfs.md)

## 結果画面の見方

### lsmod の見方

```bash
$ lsmod                                              # 読み込まれているモジュールを一覧する
Module                  Size  Used by
xfs                  2138112  1
libcrc32c              16384  1 xfs
e1000e                299008  0
```

| 列 | 意味 | どこを見るか | 異常と判断する目安 |
|:--|:--|:--|:--|
| **`Module`** | **モジュール名** | 目的のドライバが載っているか | 期待するドライバが**一覧に無い**なら、読み込まれていない |
| **`Size`** | そのモジュールが使っている**メモリのバイト数** | 参考値 | 極端な値は通常起こらない |
| **`Used by`**（数値） | **使用カウント**。いくつの相手から使われているか | **`0` なら外せる** | `0` 以外なのに外そうとすると失敗する |
| **`Used by`**（名前） | **どのモジュールから使われているか** | 外す順番を決めるのに使う | ここに名前があるものを**先に外す** |

**読み方の例**

```text
  libcrc32c   16384   1 xfs
                      │ └─ xfs から使われている
                      └─ 使用カウントは 1

  → libcrc32c を外したいなら、先に xfs を外す必要がある
```

### modinfo の見方

```bash
$ modinfo xfs                                        # モジュールの情報をすべて表示する
filename:       /lib/modules/6.1.0-18-amd64/kernel/fs/xfs/xfs.ko
alias:          fs-xfs
license:        GPL
description:    SGI XFS with ACLs, security attributes, no debug enabled
author:         Silicon Graphics, Inc.
depends:        libcrc32c
retpoline:      Y
intree:         Y
name:           xfs
vermagic:       6.1.0-18-amd64 SMP preempt mod_unload modversions
parm:           bug_on_assert:Bug on assert failed (int)
```

| 欄 | 意味 | どこを見るか |
|:--|:--|:--|
| **`filename`** | **実体のパス** | どのカーネルバージョン向けかが**パスから分かる** |
| **`alias`** | このモジュールを指す**別名** | 自動読み込みの仕組みが使う |
| **`license`** | ライセンス | GPL 以外だとカーネルが「汚染」扱いにする |
| **`description`** | **何のモジュールか** | 素性を知る最短ルート |
| **`author`** | 作者 | サードパーティ製かの判断材料 |
| **`depends`** | **依存しているモジュール** | `modules.dep` のコロンの右と同じ内容 |
| **`intree`** | **`Y` ならカーネル本体に同梱**のモジュール | `N` なら外部から入れたもの。**DKMS の対象になりやすい** |
| **`vermagic`** | **対応するカーネルのバージョンと構成** | **ここが `uname -r` と食い違うと読み込めない**（最重要） |
| **`parm`** | **指定できるパラメータ**（名前・説明・型） | 挙動を変えたいときに読む |
| **`signature`** / `sig_id` | 署名情報 | セキュアブート環境で必要 |

> **`vermagic` の不一致が、モジュールが読み込めない原因のほとんどです。**
>
> ```text
>   modinfo の vermagic : 6.1.0-17-amd64 …
>   uname -r            : 6.1.0-18-amd64
>                              ↑ ここが違う → 読み込めない
> ```
