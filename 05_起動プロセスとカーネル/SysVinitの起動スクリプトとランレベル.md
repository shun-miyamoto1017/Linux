## SysVinitとはなにか

**SysVinit**（System V init）は、**systemd より前に広く使われていた、最初のプロセス（PID 1）のしくみ**です。
名前の由来は、商用 UNIX の **System V** が採用していた起動方式を Linux に持ち込んだところにあります。

> **PID 1** … システムで最初に起動するプロセスで、すべてのプロセスの先祖にあたります。
> カーネルがルートファイルシステムをマウントし終えると、**`/sbin/init` を実行**します。これが PID 1 になります。

**systemd との一番大きな違いは「並列に起動するかどうか」です。**

| | **SysVinit** | **systemd** |
|:--|:--|:--|
| **状態の呼び方** | **ランレベル**（`0`〜`6` の数字） | **ターゲット**（`multi-user.target` などの名前） |
| **設定ファイル** | **`/etc/inittab`** | ユニットファイル（`/etc/systemd/system/` など） |
| **サービスの定義** | **シェルスクリプト**（`/etc/init.d/`） | **ユニットファイル**（INI 形式のテキスト） |
| **起動のしかた** | **番号の順に 1 つずつ**実行する | **依存関係を見て並列に**起動する |
| **起動の速さ** | **遅い**（前のスクリプトが終わるまで次に進めない） | **速い** |
| **プロセスの監視** | **しない**（起動したら放置） | **する**（落ちたら `Restart=` で再起動できる） |
| **主に見かける環境** | RHEL6 以前、一部の組み込み機器、古いアプライアンス | 現在のほぼすべての主要ディストリ |

**いまどちらで動いているか調べる**

```bash
$ ps -p 1 -o pid,comm                                # PID 1 が何かを確認する
  PID COMMAND
    1 systemd                                        # systemd なら現在の方式
$ ls -l /sbin/init                                   # init の実体を確認する
lrwxrwxrwx 1 root root 20 Jan  1 00:00 /sbin/init -> /lib/systemd/systemd
$ ls /etc/inittab                                    # SysVinit の設定ファイルがあるか見る
```

**補足**

- **`/sbin/init` は、現在のディストリでは systemd へのシンボリックリンク**になっています。ファイル名が同じなので、実体を `ls -l` で確かめるのが確実です
- **systemd の環境にも `/etc/inittab` が残っていることがあります**が、中身は「このファイルはもう使われない」という注意書きだけです

### initがやること・やらないこと

**起動処理は BIOS・ブートローダ・カーネル・init の 4 者で分担しています。**
**どれが何をするかを取り違えると、障害の切り分け先を間違えます。**

```text
 ① BIOS / UEFI      ハードウェアの初期化と自己診断
        │           （低レベルなメモリ初期化もここ）
        ▼
 ② ブートローダ      起動パーティションを選ぶ
        │           カーネルイメージを見つけてメモリへ読み込む
        │           起動オプション（ランレベル含む）をカーネルに渡す
        ▼
 ③ カーネル          メモリ・CPU の初期化（ソフトウェア的な初期化）
        │           ルートファイルシステムをマウントする
        │           /sbin/init を実行する
        ▼
 ④ init（PID 1）     /etc/inittab を読む
                    ランレベルに応じて起動スクリプトを実行する
                    サービスを自動的に起動・終了させる
```

**init の性質**

| 性質 | 内容 |
|:--|:--|
| **PID は必ず 1 で固定** | **カーネルが最初に起動するプロセス**なので、番号は常に 1。変わることはない |
| **すべてのプロセスの親** | 仮想コンソールも各種デーモンも init が起動する。**プロセスツリーの頂点**になる |
| **`/etc/inittab` を読む** | **SysVinit 環境での設定の入口**。ここに書かれた内容に従って動く |
| **ランレベルに応じた処理を行う** | `/etc/rc[0-6].d/` のスクリプトを K → S の順に実行する |

**init がやらないこと**

| よく誤解される内容 | 実際にやっているのは |
|:--|:--|
| **メモリを初期化する** | **ハードウェア的な初期化は BIOS / UEFI、ソフトウェア的な初期化はカーネル** |
| **ルートパーティションをマウントする** | **カーネル**（init が動き始める時点では、すでにマウント済み） |
| **起動パーティションを選択できる** | **ブートローダ**（GRUB のメニューで選ぶ） |
| **カーネルイメージをロードする** | **ブートローダ** |

```bash
$ ps -p 1 -o pid,ppid,comm                           # PID 1 の素性を確認する
  PID  PPID COMMAND
    1     0 init                                     # 親プロセス(PPID)が 0 = 先祖がいない
$ pstree -p | head -3                                # プロセスツリーの頂点を見る
init(1)─┬─crond(1234)
        ├─sshd(1567)
        └─mingetty(1890)
```

**補足**

- **`PPID` が `0`** なのは、**親プロセスが存在しない**という意味です。init はカーネルから直接生み出されるため、通常のプロセスのような親を持ちません
- **ブートローダで指定したランレベルは、`/etc/inittab` の `initdefault` より優先されます。** 「起動しなくなったのでシングルユーザで上げたい」ときに、この優先順位が効きます（[GRUB の設定と復旧](./GRUBの設定と復旧.md)）

## 起動スクリプトの置き場所

### 起動スクリプトとは何か

**起動スクリプト**（init スクリプト）は、**1 つのサービスを起動・停止するためのシェルスクリプト**です。
`init` が、**システムの起動時とランレベルの変更時**にこれを実行することで、サービスが自動的に上がったり下りたりします。

**ディレクトリの役割は 2 つに分かれています。**

| ディレクトリ | 何が入っているか |
|:--|:--|
| **`/etc/init.d/`** | **起動スクリプトの実体**（本物のファイル）。サービス 1 つにつき 1 ファイル |
| **`/etc/rc0.d/` 〜 `/etc/rc6.d/`** | **ランレベルごとの「何を起動し、何を止めるか」の一覧**。中身は**すべて `/etc/init.d/` へのシンボリックリンク** |

> **シンボリックリンク** … ファイルの「別名」を作るしくみです。Windows のショートカットに近く、**開くと実体のファイルが読まれます**。
> `ls -l` で表示すると `名前 -> 実体のパス` の形で出ます。

```text
  /etc/init.d/                    ← ここが実体（本物のスクリプト）
   ├─ sshd      ●─────────────┐
   ├─ httpd     ●──────────┐  │
   └─ crond     ●───────┐  │  │
                        │  │  │
  /etc/rc3.d/           │  │  │   ← ランレベル3で何をするかの一覧（全部リンク）
   ├─ S55sshd   ○───────┼──┼──┘    起動する
   ├─ S85httpd  ○───────┼──┘       起動する
   ├─ S90crond  ○───────┘          起動する
   └─ K15httpd  ○──────────┐       止める（別のランレベルにある例）
                           └─ /etc/init.d/httpd

     ● = 実体のファイル      ○ = シンボリックリンク
```

### ディストリによる違い

| ディストリ | 実体の場所 | ランレベル別ディレクトリ |
|:--|:--|:--|
| **RHEL 系**（CentOS / Oracle Linux など） | **`/etc/rc.d/init.d/`** | **`/etc/rc.d/rc0.d/` 〜 `/etc/rc.d/rc6.d/`** |
| **Debian 系**（Ubuntu など） | **`/etc/init.d/`** | **`/etc/rc0.d/` 〜 `/etc/rc6.d/`** |

> **RHEL 系でも `/etc/init.d` と `/etc/rc3.d` で届きます。**
> `/etc/init.d` が `/etc/rc.d/init.d` への、`/etc/rc3.d` が `/etc/rc.d/rc3.d` への**シンボリックリンクになっている**ためです。
> **どちらの書き方も同じ場所を指す**ので、試験でも実務でも `/etc/init.d/` の表記で通じます。

**例文**

```bash
$ ls -l /etc/init.d | head -5                        # 起動スクリプトの実体を一覧する
total 68
-rwxr-xr-x 1 root root  2989 Jun 10  2024 crond      # 実行権があるふつうのファイル
-rwxr-xr-x 1 root root  3434 Jun 10  2024 httpd
-rwxr-xr-x 1 root root  4621 Jun 10  2024 sshd

$ ls -l /etc/rc3.d | head -5                         # ランレベル3で動くものを一覧する
total 0
lrwxrwxrwx 1 root root 15 Jun 10  2024 K15httpd -> ../init.d/httpd   # すべてリンク
lrwxrwxrwx 1 root root 14 Jun 10  2024 S55sshd  -> ../init.d/sshd
lrwxrwxrwx 1 root root 15 Jun 10  2024 S90crond -> ../init.d/crond

$ readlink -f /etc/rc3.d/S55sshd                     # リンクをたどって実体のパスを表示する
/etc/rc.d/init.d/sshd
```

**補足**

- **`readlink -f`** … シンボリックリンクを最後までたどって、**実体の絶対パス**を表示します。「このリンクの正体は何か」を一発で確かめられます
- `/etc/rc3.d/` の中身が **`lrwxrwxrwx`** で始まっていることに注目してください。先頭の **`l`** が「これはシンボリックリンクです」という印です

## リンク名の読み方

**`/etc/rc3.d/` に並ぶファイル名には、3 つの情報が詰まっています。**

```text
       S 5 5 s s h d
       │ └┬┘ └──┬──┘
       │  │     └──── ③ サービス名（/etc/init.d/ の中のファイル名と同じ）
       │  └────────── ② 実行順序（2桁の数字。小さい方が先）
       └───────────── ① S = 起動する ／ K = 終了する
```

| 位置 | 意味 | 取りうる値 |
|:--|:--|:--|
| **1 文字目** | **何をするか** | **`S`** = Start（**起動**） ／ **`K`** = Kill（**終了**） |
| **2〜3 文字目** | **実行する順番** | **`00`〜`99` の 2 桁**。**数字が小さいものから順に**実行される |
| **4 文字目以降** | **サービス名** | `/etc/init.d/` にある**実体のファイル名と同じ** |

### 順序の数字が要る理由

**依存するサービスを、先に上げておかなければならないから**です。

```text
  ネットワークが上がっていないのに、Web サーバを起動しようとすると失敗する
        ↓
  だから、ネットワークに小さい番号、Web サーバに大きい番号を振る

     S10network   ← 先に起動（番号が小さい）
     S55sshd
     S85httpd     ← あとで起動（番号が大きい）
```

**止めるときは、起動と逆の順番にしたい**ので、`K` の番号は `S` の番号と裏返しになるように振るのが慣例です
（たとえば `S85httpd` に対して `K15httpd`。**`85 + 15 = 100`** になっています）。

### ランレベル変更時に何が起きるか

**`init` は、切り替え先のランレベルのディレクトリを見て、K → S の順に処理します。**

```text
  ① /etc/rc3.d/ の中の  K で始まるリンクを、番号の小さい順に
       → それぞれ「stop」という引数を付けて実行する

  ② /etc/rc3.d/ の中の  S で始まるリンクを、番号の小さい順に
       → それぞれ「start」という引数を付けて実行する
```

**例文**

```bash
$ ls /etc/rc3.d/                                     # ランレベル3の設定を一覧する
K15httpd  S10network  S55sshd  S90crond

$ ls /etc/rc3.d/ | sort                              # 実行される順番どおりに並べ替える
K15httpd                                             # 先に httpd を止める
S10network                                           # 次にネットワークを起動
S55sshd                                              # sshd を起動
S90crond                                             # 最後に crond を起動

$ ls -l /etc/rc*.d/*sshd                             # sshd が各ランレベルでどう扱われるか見る
lrwxrwxrwx 1 root root 14 /etc/rc0.d/K30sshd -> ../init.d/sshd   # 停止時は止める
lrwxrwxrwx 1 root root 14 /etc/rc3.d/S55sshd -> ../init.d/sshd   # CUIでは起動する
lrwxrwxrwx 1 root root 14 /etc/rc5.d/S55sshd -> ../init.d/sshd   # GUIでも起動する
lrwxrwxrwx 1 root root 14 /etc/rc6.d/K30sshd -> ../init.d/sshd   # 再起動時は止める
```

**補足**

- **`sort`** … 行を並べ替えるコマンドです。ファイル名の文字順は、そのまま実行順になります（`K` が `S` より前、数字は小さい順）
- `/etc/rc*.d/*sshd` の **`*`** は、あてはまるパスをすべて展開するシェルの機能です。**「sshd が全ランレベルでどう設定されているか」を一覧するのに便利**です

## inittabによるランレベルの設定

### ランレベルの一覧

| ランレベル | 意味 | 備考 |
|:-:|:--|:--|
| **0** | **システム停止（電源OFF）** | **既定にしてはいけない**（起動直後に落ちる） |
| **1**／**`s`**／**`S`** | **シングルユーザモード** | **この 3 つはすべて同じ意味**。管理者だけ。ネットワークなし。復旧作業用 |
| **2** | **マルチユーザ（NFS なし）** | ネットワークは使えるが、**NFS でのファイル共有は動かない** |
| **3** | **マルチユーザ（CUI）** | **サーバの標準** |
| **4** | **未定義** | **使われていない枠**。管理者が自由に定義してよい |
| **5** | **マルチユーザ（GUI）** | X Window System が起動する |
| **6** | **再起動** | **既定にしてはいけない**（無限に再起動する） |
| **`Q`**／**`q`** | **（状態ではない）`/etc/inittab` を読み直す** | ランレベルは変わらない。`init q` のように使う |

**取り違えやすいところ**

| 混同しやすい組 | 違い |
|:--|:--|
| **1 と s と S** | **すべてシングルユーザモード**。`init 1` でも `init s` でも `init S` でも同じところへ行く |
| **2 と 3** | **2 は NFS が動かない**。ネットワーク自体は使える |
| **4** | **「未使用」ではなく「未定義」**。枠は用意されているが、標準では何も割り当てられていない |
| **`Q` と 0〜6** | **`Q` はランレベルではない**。設定ファイルの再読込を指示する特別な引数 |

### inittab の書式

**`/etc/inittab`** は、**SysVinit がどのランレベルで何を実行するかを書いたファイル**です。
1 行 1 設定で、**コロン `:` で 4 つの項目に区切ります**。

```text
   id : runlevels : action : process
   │     │           │        └── 実行するコマンド
   │     │           └─────────── いつ・どう実行するか
   │     └─────────────────────── 対象のランレベル（複数可、区切り文字なしで並べる）
   └───────────────────────────── この行を識別する名前（英数字2〜4文字）
```

| 項目 | 意味 | 書き方の決まり |
|:--|:--|:--|
| **`id`** | **その行を識別するための名札** | **1〜4 文字**。ファイル内で重複させない。**空にはできない** |
| **`runlevels`** | **この行を適用するランレベル** | **数字を区切らずに並べる**。`35` で「3 と 5」 |
| **`action`** | **実行のしかた**（下の表） | 決められた語のどれか。勝手な語は使えない |
| **`process`** | **実行するコマンド** | 絶対パスで書く。引数も付けられる |

> **コロンは必ず 3 つ**です。項目が空でも**コロンは省略しません**。
> `id:3:initdefault:` の末尾のコロンも、**省略すると書式エラー**になります。

### 書式でつまずくところ

**Ping-t でも実務でも、ここで落とし穴にはまります。**

```text
   正しい     id:3:initdefault:
                └┬┘│    └───┬──┘│
                 │ │        │   └── コマンド部は空でよいが、コロンは書く
                 │ │        └────── アクション
                 │ └─────────────── ランレベル
                 └───────────────── ID（1〜4文字）
```

| 書き方 | 正しいか | 理由 |
|:--|:-:|:--|
| **`id:3:initdefault:`** | **○** | 既定のランレベルを 3 に設定する正しい形 |
| `id::initdefault:3` | **×** | **コマンド部にランレベルを書いている。** ランレベルは 2 番目の項目 |
| `si::sysinit:/etc/rc.d/rc.sysinit` | **○** | `sysinit` はランレベルを見ないので、2 番目は空でよい。**コロンは 3 つある** |
| `si:sysinit:/etc/rc.d/rc.sysinit` | **×** | **コロンが 2 つしかない。** これでは「ランレベル＝`sysinit`」と読まれてしまう |
| `:12345:respawn:/sbin/mingetty tty1` | **×** | **ID が空**。ID は 1〜4 文字で必ず書く |
| **`my:345:once:/etc/rc.d/myrc`** | **○** | ランレベル 3・4・5 が対象。**数字を並べて書く** |
| `my:3-5:once:/etc/rc.d/myrc` | **×** | **ハイフンでつなぐ書き方はない** |
| `my:3~5:once:/etc/rc.d/myrc` | **×** | **チルダでつなぐ書き方もない** |
| `3:L3:wait:/etc/rc.d/rc 3` | **×** | **ランレベル部に `L3`。** `L` はランレベルとして解釈できない |
| `L3:3:rc:/etc/rc.d/rc 3` | **×** | **アクションに `rc` という指定子は存在しない** |
| `1:12345:auto:/sbin/mingetty tty1` | **×** | **アクションに `auto` は存在しない**。再起動させたいなら `respawn` |

> **`sysinit` / `boot` / `bootwait` はランレベルを見ません。**
> この 3 つを使うときは、**ランレベル部は空**にしておくのが決まりです（書いても無視されます）。

### action に書ける主なもの

| action | 意味 |
|:--|:--|
| **`initdefault`** | **起動時の既定のランレベルを決める**。`process` は書かない |
| **`sysinit`** | **システム起動時に、ランレベルに関係なく最初に 1 度だけ実行する** |
| **`wait`** | **そのランレベルに入るときに実行し、終わるまで次へ進まない** |
| `once` | そのランレベルに入るときに 1 度だけ実行する（終了を待たない） |
| **`respawn`** | **プロセスが終了したら、自動的に起動し直す**（ログインプロンプトなど） |
| `boot` | 起動時に実行する（ランレベルは無視） |
| `bootwait` | 起動時に実行し、終わるまで待つ |
| **`ctrlaltdel`** | **`Ctrl` + `Alt` + `Del` が押されたときに実行する** |
| `powerfail` / `powerokwait` | UPS からの電源異常・復帰の通知を受けたときに実行する |

**例文**

```bash
$ cat /etc/inittab                                   # 設定ファイルの中身を見る
id:3:initdefault:                                    # 既定のランレベルは 3（CUI）
si::sysinit:/etc/rc.d/rc.sysinit                     # 起動時に必ず1度だけ実行する初期化
l3:3:wait:/etc/rc.d/rc 3                             # ランレベル3に入るとき rc スクリプトを実行
ca::ctrlaltdel:/sbin/shutdown -t3 -r now             # Ctrl+Alt+Del で再起動させる
1:2345:respawn:/sbin/mingetty tty1                   # ログインプロンプトを出し、落ちたら出し直す

$ grep initdefault /etc/inittab                      # 既定のランレベルだけを取り出す
id:3:initdefault:
```

**補足**

- **`/etc/rc.d/rc 3` が、先ほどの `/etc/rc3.d/` を読んで K → S の順に実行する本体**です。`inittab` の 1 行が、あの一連の処理の入口になっています
- **`respawn` は「落ちたら上げ直す」**という意味です。`mingetty` が `respawn` なのは、ログアウトするたびにログインプロンプトを出し直すためです
- **`initdefault` を `0` や `6` にすると、起動できなくなります**。`0` は電源断、`6` は再起動を延々と繰り返すためです

### 変更を反映する

**`/etc/inittab` を書き換えても、すぐには効きません。** `init` に読み直させます。

```bash
$ sudo vi /etc/inittab                               # 設定を書き換える
$ sudo init q                                        # init に inittab を読み直させる
$ sudo telinit q                                     # 上とまったく同じ意味
```

**補足**

- **`q`**（または `Q`）は「**再読込**」を意味する引数です。ランレベルは変わりません
- **`initdefault` の変更は次回の起動から**効きます。今すぐ変えたいときは、後述の `init 3` でランレベルそのものを切り替えます

## ランレベルの確認と変更

### いまのランレベルを見る

```bash
$ runlevel                                           # 直前と現在のランレベルを表示する
N 3                                                  # N = 直前なし（起動してから変えていない）

$ who -r                                             # 同じ内容を、時刻つきで表示する
         run-level 3  2026-09-13 09:12
```

| 出力 | 読み方 |
|:--|:--|
| **左側** | **直前のランレベル**。**`N`** は **None**（起動してから一度も変えていない） |
| **右側** | **現在のランレベル** |

### ランレベルを切り替える

| コマンド | 意味 |
|:--|:--|
| **`init 3`** | **ランレベル 3 へ切り替える** |
| **`telinit 3`** | **同上**（`telinit` は `init` へのシンボリックリンク） |
| **`init 1`** / **`telinit 1`** | **シングルユーザモードへ落とす**（復旧作業） |
| **`init 6`** / **`telinit 6`** | **再起動する** |
| **`init 0`** / **`telinit 0`** | **システムを停止する** |
| **`init q`** / **`telinit q`** | **`/etc/inittab` を読み直す**（ランレベルは変えない） |

```bash
$ sudo telinit 1                                     # シングルユーザモードへ落とす（復旧作業）
$ sudo telinit 3                                     # 作業が終わったら通常のCUIへ戻す
$ sudo telinit 6                                     # 再起動する
```

**補足**

- **`init` と `telinit` は同じものです。** `telinit` は `init` へのシンボリックリンクで、「**PID 1 の init に指示を送る**」という役割をはっきりさせるための別名です
- **`telinit` には必ずランレベルの引数が要ります。** 引数なしでは「どの状態に移るか」が決まらないためです
- **リモート接続中に `telinit 1` を実行すると、その場で接続が切れます。** ネットワークが止まるためです。**物理コンソールまたは仮想コンソールが使える状態で実行してください**

**`init` / `telinit` の制約**

| 制約 | 内容 |
|:--|:--|
| **root でしか使えない** | **一般ユーザが実行しても拒否されます。** ランレベルの変更はシステム全体に影響するためです |
| **複数のランレベルは指定できない** | **`telinit 35` のような書き方はできません。** `inittab` の RunLevel 欄とは違い、**移行先はひとつだけ**です |
| **OS の再起動は伴わない** | **プロセスレベルで状態を切り替えるだけ**です。ハードウェアの初期化からやり直すわけではありません |

---

### ランレベルを変えられるコマンド・変えられないコマンド

**名前が似ていて混同しやすいので、「何ができるか」で並べます。**

| コマンド | ランレベルを**変えられるか** | 何をするコマンドか |
|:--|:-:|:--|
| **`init <0-6>`** | **○** | **init プロセスに、指定したランレベルへの移行を指示する** |
| **`telinit <0-6>`** | **○** | **同上**（`init` へのリンク） |
| **`shutdown`** | **○（間接的に）** | **内部で init にランレベル変更を要求する。** `-h` なら 0、`-r` なら 6 |
| **`runlevel`** | **×** | **直前と現在のランレベルを表示するだけ**。変更する機能はない |
| **`sysctl`** | **×** | **カーネルパラメータを参照・設定する**コマンド。ランレベルとは無関係 |

> **`runlevel` は「見る」だけ、`init` / `telinit` は「変える」。**
> この対比がそのまま問われます。

---

### shutdown コマンド

**意味**

**`shutdown` は、システムを安全に停止または再起動させるコマンド**です。
**内部でやっていることは、init にランレベルの変更を要求すること**です。

```text
   shutdown -h now   →  init に「ランレベル 0 へ」と要求  →  システム停止
   shutdown -r now   →  init に「ランレベル 6 へ」と要求  →  再起動

   つまり  shutdown -r now  と  init 6  は、結果として同じところへ行く
```

**書式**

```text
   shutdown [オプション] 実行タイミング [警告メッセージ]
```

| 部分 | 意味 |
|:--|:--|
| **オプション** | `-h`（停止） ／ `-r`（再起動） ／ `-c`（予約の取り消し）など |
| **実行タイミング** | **`now`**（すぐ） ／ **`+分`**（何分後） ／ **`hh:mm`**（時刻）。**省略できない** |
| **警告メッセージ** | ログイン中のユーザの端末に表示される文字列（省略可） |

**よく使うオプション**

| オプション | 意味 |
|:--|:--|
| **`-h`** | **システムを停止する**（halt）。`-h now` で即時停止 |
| **`-r`** | **再起動する**（reboot）。`-r now` で即時再起動 |
| **`-c`** | **予約したシャットダウンを取り消す**（時刻指定したものを止める） |
| **`-k`** | **実際には実行せず、警告メッセージだけ流す**（予行演習） |
| `-H` | 停止するが電源は切らない |
| `-P` | 停止して電源も切る |
| `-f` | 次回起動時のファイルシステム検査を省略する |
| `-F` | 次回起動時にファイルシステム検査を強制する |

**例文**

```bash
$ sudo shutdown -r now                               # すぐに再起動する
$ sudo shutdown -h now                               # すぐに停止する
$ sudo shutdown -r +10 "10分後に再起動します"          # 10分後に再起動し、全員に通知する
$ sudo shutdown -h 23:00                             # 23時に停止する予約を入れる
$ sudo shutdown -c                                   # 入れた予約を取り消す
$ sudo shutdown -k +5 "これはテストです"               # 実行せず、警告だけ流す
```

**補足**

- **実行タイミングは省略できません。** `shutdown -r` だけでは動かないので、**`now` を付ける**のを忘れないでください
- **`reboot` と `halt` は `shutdown` の短縮形**にあたります。`reboot` は `shutdown -r now`、`halt` は `shutdown -h now` とほぼ同じ動きです
- **`-h` と `-r` を取り違えると、再起動のつもりでサーバが落ちます。** リモートから実行すると**そのまま戻ってきません**。クラウドのコンソールから起動し直すことになるので、**実行前に必ず読み返してください**

### シングルユーザモードから通常の運用へ戻す

**メンテナンスが終わったあと、通常のモードへ戻す方法は 3 つあります。**

| やり方 | コマンド | どういうときに選ぶか |
|:--|:--|:--|
| **既定のランレベルへ切り替える** | **`init 3`**（既定が 3 の場合） | **再起動したくない**とき。いちばん速い |
| **再起動する** | **`shutdown -r now`** | **確実にきれいな状態から**上げ直したいとき |
| **再起動する（短縮形）** | **`reboot`** | 上と同じ。打ち慣れているほう |

> **どのランレベルへ戻すかは、`/etc/inittab` の `initdefault` 行で決まっている値**です。
> **「GUI を起動しないマルチユーザモード」が既定なら、戻り先は 3** になります。

```bash
$ grep initdefault /etc/inittab                      # 戻り先のランレベルを確認する
id:3:initdefault:
$ sudo init 3                                        # 再起動せずに通常のCUIへ戻す
$ runlevel                                           # 戻れたことを確認する
1 3                                                  # 1 から 3 へ移ったという意味
```

**間違えやすい選択肢**

| 書き方 | なぜ違うか |
|:--|:--|
| **`telinit 5`** | **5 は GUI 付き**。既定が 3 の環境では「通常の運用」に戻ったことにならない |
| **`halt`** | **システムを停止する**コマンド。通常運用には戻らない |
| **`shutdown -h now`** | 同上。**`-h` は停止**。再起動したいなら **`-r`** |

## 起動スクリプトを手で動かす

### 2つの呼び方

起動スクリプトは**ただのシェルスクリプト**なので、**引数を付けて直接実行**できます。
これを包んで、パスを気にせず使えるようにしたのが **`service`** コマンドです。

| やり方 | 書式 |
|:--|:--|
| **直接実行** | **`/etc/init.d/サービス名 引数`** |
| **`service` 経由** | **`service サービス名 引数`** |

### 渡せる引数

| 引数 | 意味 |
|:--|:--|
| **`start`** | **サービスを起動する** |
| **`stop`** | **サービスを停止する** |
| **`restart`** | **停止してから起動する** |
| **`reload`** | **プロセスを止めずに設定だけ読み直させる**（対応していないスクリプトもある） |
| **`status`** | **稼働しているかどうかを表示する** |
| `condrestart` / `try-restart` | **動いているときだけ**再起動する |
| `force-reload` | reload に対応していれば reload、していなければ restart |

**例文**

```bash
$ sudo /etc/init.d/sshd status                       # 実体を直接たたいて状態を見る
openssh-daemon (pid 1234) is running...

$ sudo service sshd restart                          # service 経由で再起動する
Stopping sshd:                       [  OK  ]
Starting sshd:                       [  OK  ]

$ sudo service --status-all                          # すべてのサービスの状態をまとめて見る
```

**補足**

- **`service` は、環境変数をそろえてからスクリプトを呼びます。** 直接実行すると、**そのときのシェルの環境変数を引き継いでしまう**ため、**手作業では `service` を使うほうが安全**です
- **`[  OK  ]` / `[FAILED]`** が、SysVinit 時代の見慣れた成否表示です

## 自動起動の設定は別ノートにある

**「次に起動したときに、このサービスを自動で上げるか」の設定**は、
[サービスの自動起動設定](./サービスの自動起動設定.md) に移しました。

| やりたいこと | コマンド | 系統 |
|:--|:--|:--|
| **自動起動を有効／無効にする** | **`chkconfig サービス on` / `off`** | RHEL 系 |
| 同上 | **`update-rc.d サービス defaults`** / **`-f サービス remove`** | Debian 系（6.0 より前） |
| 同上 | **`insserv サービス`** / **`insserv -r サービス`** | SUSE 系・Debian 6.0 以降 |
| **設定状態を確認する** | **`chkconfig --list サービス`** | RHEL 系 |
| **手でリンクを作る** | **`ln -s ../init.d/名前 S50名前`** | どの系統でも |

> **`service` だけは役割が違います。** これは「その場で起動・停止する」コマンドで、
> 自動起動の設定はしません（下の「起動スクリプトを手で動かす」を参照）。
>
> **4 コマンドの対応表・書式・止め方の比較**も、すべて
> [サービスの自動起動設定](./サービスの自動起動設定.md) にまとめてあります。

## 結果画面の見方

### ls -l で rc ディレクトリを見る

```bash
$ ls -l /etc/rc3.d/                                  # ランレベル3の設定をリンクごと確認する
total 0
lrwxrwxrwx 1 root root 15 Jun 10  2024 K15httpd -> ../init.d/httpd
lrwxrwxrwx 1 root root 17 Jun 10  2024 S10network -> ../init.d/network
lrwxrwxrwx 1 root root 14 Jun 10  2024 S55sshd -> ../init.d/sshd
```

| 欄 | 内容 | どこを見れば何が分かるか | 異常と判断する目安 |
|:--|:--|:--|:--|
| **1 欄目の 1 文字目**（`l`） | **ファイルの種類** | **`l` = シンボリックリンク** | **`-`（通常ファイル）なら要注意**。`rc3.d` に実体を置くと、パッケージ更新で置き去りになる |
| **1 欄目の残り**（`rwxrwxrwx`） | パーミッション | リンク自体の権限は常に `rwxrwxrwx` | リンクでは意味を持たないので気にしない |
| **2 欄目**（`1`） | ハードリンク数 | リンクなので常に `1` | — |
| **3・4 欄目**（`root root`） | 所有者とグループ | **`root root`** であること | 一般ユーザ所有なら、**不正に差し替えられた可能性がある** |
| **5 欄目**（`15`） | **リンク文字列の長さ**（バイト数） | 実体のサイズではない | — |
| **6〜8 欄目** | 最終更新日時 | **リンクが作られた日時** | 直近に増えている＝誰かが設定を変えた |
| **ファイル名の 1 文字目** | **`S` = 起動 ／ `K` = 終了** | **このランレベルでどう扱われるか** | 同じサービスの `S` と `K` が**同じランレベルに両方ある**のは設定ミス |
| **ファイル名の 2〜3 文字目** | **実行順序** | **小さい番号から実行される** | 依存先より小さい番号なら**起動失敗の原因** |
| **`->` の右側** | **リンク先（実体）** | **`../init.d/サービス名`** | **リンク切れ**（`ls` で赤く表示される）なら、実体が消えている |

**リンク切れを探す**

```bash
$ find /etc/rc3.d/ -xtype l                          # リンク先が存在しないリンクだけを探す
```

**補足**

- **`find -xtype l`** … 「たどった先がリンクとして壊れているもの」を探す指定です。**パッケージを消したのにリンクが残っている**ケースを一発で見つけられます

### runlevel の出力

```bash
$ runlevel                                           # 直前と現在のランレベルを表示する
N 3
```

| 位置 | 内容 | 読み方 |
|:--|:--|:--|
| **左側** | **直前のランレベル** | **`N`** = 起動してから一度も変えていない ／ 数字 = その値から移ってきた |
| **右側** | **現在のランレベル** | ここが**いまの状態** |

```text
   N 3   ← 起動してからずっと 3（通常の状態）
   3 1   ← 3 から 1 へ落とした（復旧作業中）
   1 3   ← 1 から 3 へ戻した（復旧が終わった）
```

**補足**

- **`unknown` と出ることがあります。** systemd 環境で、ランレベルの概念にうまく対応づけられないときの表示です。その場合は **`systemctl get-default`** で確認してください

## systemdとの対応

**systemd の環境でも、`/etc/init.d/` のスクリプトはそのまま動きます。**
systemd が、**起動スクリプトを読み取って、内部的にユニットとして扱う**しくみ（SysV 互換ジェネレータ）を持っているためです。

| SysVinit での操作 | systemd での操作 |
|:--|:--|
| `service sshd start` | **`systemctl start sshd`** |
| `service sshd status` | **`systemctl status sshd`** |
| `chkconfig sshd on` | **`systemctl enable sshd`** |
| `chkconfig sshd off` | **`systemctl disable sshd`** |
| `chkconfig --list` | **`systemctl list-unit-files --type=service`** |
| `runlevel` | **`systemctl get-default`**（既定） ／ `systemctl list-units --type=target`（現在） |
| `telinit 3` | **`systemctl isolate multi-user.target`** |
| `/etc/inittab` の `initdefault` | **`systemctl set-default multi-user.target`** |

> **`service` や `chkconfig` を打っても動くのは、systemd 側に転送されているから**です。
> 実行すると「`Redirecting to /bin/systemctl …`」という注意書きが出ます。
> **新しく設定を書くときは、素直に `systemctl` を使ってください。**

```bash
$ sudo service sshd status                           # 古い書き方でも受け付けられる
Redirecting to /bin/systemctl status sshd.service    # systemctl へ転送された、という表示
```

**ランレベルとターゲットの対応表**は [ブートプロセスの全体像](./ブートプロセスの全体像.md) にまとめています。

## 公式ドキュメントで確認した補足

- **`init` と `telinit` は同一のプログラム**です。`telinit` は `init` へのリンクとして提供され、**すでに動いている init にランレベルの変更を伝える**ために使われます（`man 8 init`）
- **`init q` は `/etc/inittab` を再読込します。** ランレベルの変更は伴いません（`man 8 init`）
- **`runlevel` は、`/var/run/utmp` に記録された直前と現在のランレベルを表示します。** 直前の記録が無い場合は `N` と表示されます（`man 8 runlevel`）
- **`chkconfig` は、起動スクリプト内のコメント行（`# chkconfig:` ヘッダ）を読んで、既定のランレベルと順序番号を決めます**（`man 8 chkconfig`）
- **`update-rc.d` は、LSB のヘッダ（`### BEGIN INIT INFO` 〜 `### END INIT INFO`）に書かれた依存関係をもとに順序を決めます**（`man 8 update-rc.d`）
- **systemd 環境では、`systemd-sysv-generator` が `/etc/init.d/` のスクリプトを実行時にユニットへ変換します**（`man 8 systemd-sysv-generator`）
