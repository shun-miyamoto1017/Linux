## 4つのコマンドの使い分け

### ディストリごとの対応表

**「このディストリでは何を使うか」を 1 枚で押さえます。**

| | **自動起動の設定** | **その場で起動・停止** |
|:--|:--|:--|
| **RHEL 系**（RHEL 6.x まで / CentOS / Fedora） | **`chkconfig`** | **`service`** |
| **Debian 系** | **`update-rc.d`** | `/etc/init.d/サービス名 引数` |
| **SUSE 系**（openSUSE / SLES） | **`insserv`** | `/etc/init.d/サービス名 引数` |
| **どの系統でも使える** | **`ln`** でリンクを直接操作 | **`/etc/init.d/サービス名 引数`** |

> **Ping-t では「`service` は RHEL 系」として出題されます**が、
> **実機の Debian / Ubuntu にも `service` はあります**（`init-system-helpers` パッケージが `/usr/sbin/service` を提供）。
> 試験では上の表のとおりに答え、実務では `service` が使えると覚えておいてください。
> スクリプトを直接たたく方法は
> [SysVinit の起動スクリプトとランレベル](./SysVinitの起動スクリプトとランレベル.md) の「起動スクリプトを手で動かす」にあります。

### 誤答になりやすい組み合わせ

**「コマンドと引数の組」で問われることが多いので、正しい組み合わせを先に並べます。**

| 組み合わせ | 正しいか | 理由 |
|:--|:-:|:--|
| **`update-rc.d サービス defaults`** | **○** | 自動起動を設定する正しい指示 |
| **`update-rc.d サービス start 優先度 ランレベル .`** | **○** | ランレベルを明示して起動リンクを作る |
| `update-rc.d サービス stop` | **×** | **停止リンク（`K`）を作る指示**。自動起動にはならない |
| **`chkconfig サービス on`** | **○** | 自動起動を有効にする正しい指示 |
| `chkconfig サービス reset` | **△** | `reset` は**既定の設定に戻す**指示。「有効にする」とは限らない |
| `chkconfig サービス start` | **×** | **`chkconfig` に `start` は無い**（`start` は `update-rc.d` 側） |
| `update-rc.d サービス on` | **×** | **`update-rc.d` に `on` は無い**（`on` は `chkconfig` 側） |

> **覚え方**
>
> ```text
>   chkconfig   … on / off / reset      （スイッチを入れる・切るイメージ）
>   update-rc.d … start / stop / defaults / remove  （リンクを作る・消すイメージ）
> ```

## RHEL系のchkconfig

### 意味

**`chkconfig` は、RHEL 系で自動起動の設定を代行してくれるコマンド**です。
`/etc/rc[0-6].d/` の中のシンボリックリンクを、**命名規則を間違えずに**作ったり消したりしてくれます。

**書式**

```text
   chkconfig [--level ランレベル] サービス名 (on | off | reset)
   chkconfig --list [サービス名]
```

| 部分 | 意味 |
|:--|:--|
| **`--level ランレベル`** | **対象のランレベル**。**省略できる** |
| **`サービス名`** | `/etc/init.d/` にあるスクリプトの名前 |
| **`on` / `off` / `reset`** | **有効にする / 無効にする / 既定の設定に戻す** |
| **`--list`** | **現在の設定状態を表示する**（設定は変更しない） |

### ランレベルは省略できる

**`--level` を省略すると、`on` / `off` は「ランレベル 2, 3, 4, 5」が対象**になります。
サーバの通常運用（3）とデスクトップ（5）が両方含まれるので、**普段は省略で困りません。**

```text
   chkconfig crond on            → ランレベル 2,3,4,5 が対象
   chkconfig --level 35 crond on → ランレベル 3 と 5 だけが対象
```

**複数のランレベルは、数字を並べて書きます。** `--level 235` で「2 と 3 と 5」です。
**カンマやハイフンでつなぐ書き方はありません。**

### 例文

```bash
$ sudo chkconfig crond on                        # ランレベル2,3,4,5で自動起動にする
$ sudo chkconfig crond off                       # 自動起動をやめる
$ sudo chkconfig --level 35 httpd on             # ランレベル3と5でだけ自動起動にする
$ sudo chkconfig --level 235 httpd off           # ランレベル2,3,5での自動起動をやめる
$ sudo chkconfig crond reset                     # スクリプトのヘッダに書かれた既定値に戻す
$ chkconfig --list crond                         # crond の設定状態だけを見る
crond   0:off  1:off  2:on   3:on   4:on   5:on   6:off
$ chkconfig --list                               # すべてのサービスの設定状態を見る
$ sudo chkconfig --add myapp                     # 新しいスクリプトを管理対象に加える
$ sudo chkconfig --del myapp                     # 管理対象から外す（リンクをすべて削除）
```

### 補足

- **`chkconfig --list` は設定を変えません。** 「いまどうなっているか」を見るだけの安全な操作なので、**変更する前に必ず実行して控えておく**のが実務の作法です
- **`--list` にサービス名を付けないと全サービスが出ます。** 行数が多いので `grep` と組み合わせます
- **`reset` は「既定に戻す」であって「有効にする」ではありません。** 既定が `off` のサービスなら、`reset` しても `off` のままです
- **`chkconfig` の第二引数に `start` や `stop` は指定できません。** それらは `update-rc.d` の指示です。**ここが試験で繰り返し問われます**
- **`--add` が必要なのは、新しく作ったスクリプトのときだけ**です。パッケージで入れたサービスは、インストール時に登録済みです

## Debian系のupdate-rc.d

### 意味

**`update-rc.d` は、Debian 系で自動起動の設定を行うコマンド**です。
現行の Debian / Ubuntu でもこれが標準の入口です。
名前のとおり、**`/etc/rc[0-6].d` を更新する（update）ことだけ**を行います。

> **`update-rc.d` にサービスを起動・停止する機能はありません。**
> その場で動かしたいときは `/etc/init.d/サービス名 start` のようにスクリプトを直接実行します。

**書式**

```text
   update-rc.d [オプション] サービス名 操作 [優先度] [ランレベル...] .
```

### 操作は4種類

| 操作 | 何をするか |
|:--|:--|
| **`defaults`** | **ランレベルに応じて、`S` か `K` で始まるリンクを作る**（2,3,4,5 に `S`／0,1,6 に `K`） |
| **`start`** | **`S` で始まるリンクを作る**（起動する） |
| **`stop`** | **`K` で始まるリンクを作る**（終了する） |
| **`remove`** | **リンクを削除する**（`-f` で強制） |

### 優先順位とランレベルを指定できる

**`start` と `stop` を使うときは、優先度とランレベルを続けて書きます。**
**少し変わった書き方をするので、形で覚えてください。**

```text
   update-rc.d  sshd  stop  25  1 2 4  .
                 │     │    │   └─┬─┘  │
                 │     │    │     │    └── ランレベル指定の終わりを表すドット（必須）
                 │     │    │     └─────── 対象のランレベル（スペース区切りで並べる）
                 │     │    └───────────── 優先度（S や K に続く2桁の数字）
                 │     └────────────────── 操作
                 └──────────────────────── サービス名

   → /etc/rc1.d/K25sshd
     /etc/rc2.d/K25sshd
     /etc/rc4.d/K25sshd   が作られる
```

| 部分 | 書き方 | 間違えやすい点 |
|:--|:--|:--|
| **優先度** | **操作の直後**に 2 桁の数字 | **ランレベルより先**。順番を逆にしない |
| **ランレベル** | **スペース区切りで並べる** | `1,2,4` のようにカンマでつながない |
| **最後のドット** | **`.` を必ず置く** | **これが無いと、ランレベル指定の終わりが伝わらない** |

### defaults と start の使い分け

**`defaults` は便利ですが、「ランレベル 6 で起動したい」のような特殊な要求には使えません。**

```text
   defaults を指定すると……
     ランレベル 2,3,4,5 → S で始まるリンク（起動）
     ランレベル 0,1,6   → K で始まるリンク（終了）
   を自動的に作る

   つまり「ランレベル 6 に S リンクを作りたい」ときは
   defaults では K リンクになってしまうので、start を明示する必要がある
```

**例文**

```bash
$ sudo update-rc.d ssh defaults                  # 標準の順序でリンクを作る（自動起動にする）
$ sudo update-rc.d myreboot start 99 6 .         # ランレベル6で優先度99の起動リンクを作る
$ sudo update-rc.d sshd stop 25 1 2 4 .          # ランレベル1,2,4に優先度25の終了リンクを作る
$ sudo update-rc.d ssh enable                    # 自動起動を有効にする
$ sudo update-rc.d ssh disable                   # 自動起動を無効にする（SリンクをKリンクに変える）
$ sudo update-rc.d -f ssh remove                 # リンクをすべて削除する
$ ls /etc/rc6.d/ | grep myreboot                 # 結果をリンクで確かめる
S99myreboot
```

### 補足

- **`update-rc.d myreboot start 99 6 .` の結果は `/etc/rc6.d/S99myreboot`** です。`/etc/init.d/myreboot` へのシンボリックリンクが作られます
- **`update-rc.d myreboot defaults 99` では目的を達成できません。** `defaults` はランレベル 6 を「終了」とみなすので、`K99myreboot` が作られてしまいます
- **`update-rc.d myreboot start 6 99` は書式が誤り**です。**優先度が先、ランレベルが後**。順番が逆になっています
- **`-f`**（force）… `/etc/init.d/` に実体が残っていても、**リンクだけを消す**ための指定です。これが無いと「実体がまだある」と言われて中断します

## SUSE系のinsserv

### 意味

**`insserv` は、SUSE 系で自動起動の設定を行うコマンド**です。
（Debian でも 6.0 の頃に依存関係順の起動へ使われていましたが、現行の Debian / Ubuntu には入っていません。）
役割は `chkconfig` / `update-rc.d` と同じで、**`/etc/rc[0-6].d/` のリンクを操作**します。

**`insserv` の特徴は、スクリプトに書かれた依存関係を読んで、順序番号を自動で決めるところ**です。

> **LSB ヘッダ** … 起動スクリプトの先頭に書かれた、`### BEGIN INIT INFO` から
> `### END INIT INFO` までのコメント行です。**そのサービスが何に依存するか**が書かれています。
> `insserv` はこれを読んで、「ネットワークの後に起動する」といった順序を自動的に組み立てます。

**書式**

```text
   insserv [オプション] [サービス名]
```

| 書き方 | 意味 |
|:--|:--|
| **`insserv サービス名`** | **自動起動を有効にする**（リンクを作る） |
| **`insserv -r サービス名`** | **自動起動を無効にする**（リンクを削除する） |
| `insserv -d サービス名` | スクリプトの既定の設定でリンクを作り直す |
| `insserv -n` | 実際には変更せず、何が起きるかだけ表示する（ドライラン） |
| `insserv -v` | 処理の内容を詳しく表示する |

### 例文

```bash
$ sudo insserv crond                             # crond の自動起動を有効にする
$ sudo insserv -r crond                          # crond の自動起動を無効にする
$ sudo insserv -n -v crond                       # 何が起きるかだけ確認する（変更しない）
$ ls -l /etc/rc3.d/ | grep crond                 # 結果をリンクで確かめる
lrwxrwxrwx 1 root root 15 Jun 10  2024 S15crond -> ../init.d/crond
```

### 補足

- **`-r`**（remove）が「無効にする」指定です。**`chkconfig` の `off`、`update-rc.d` の `remove` に相当**します
- **`insserv` は順序番号を自分で決めます。** `chkconfig` や `update-rc.d` のように優先度を手で指定する必要がありません。そのぶん、**スクリプトの LSB ヘッダが正しく書かれていることが前提**になります
- **`insserv` は SUSE 系の標準**です。Debian でも 6.0（squeeze）の頃は依存関係順の起動に `insserv` を使っていましたが、**利用者が触る入口は一貫して `update-rc.d`** で、現行の Debian / Ubuntu には `insserv` 自体が入っていません

## RHEL系のservice

### 意味

**`service` は、サービスを「その場で」起動・停止するコマンド**です。
**自動起動の設定はしません。** 4 つのコマンドの中で、**ここだけ役割が違います。**

**書式**

```text
   service サービス名 引数
   service --status-all
```

`/etc/init.d/` 以下から対応するスクリプトを見つけて、**引数を付けて実行してくれます。**

### 例文

```bash
$ sudo service crond start                       # その場で crond を起動する
$ sudo service crond stop                        # その場で crond を停止する
$ sudo service crond restart                     # 停止してから起動する
$ sudo service crond status                      # 稼働しているかを表示する
$ sudo service --status-all                      # すべてのサービスの状態をまとめて見る
```

### 補足

- **Ping-t では「`service` は RHEL 系」として扱われます**。ただし実機の Debian / Ubuntu にも `service` はあるため、**試験の答えと実機の挙動が食い違う点**として覚えておいてください
- **`service` は環境変数をそろえてからスクリプトを呼びます。** スクリプトを直接実行すると、**そのときのシェルの環境変数を引き継いでしまう**ため、**手作業では `service` を使うほうが安全**です
- 詳しい引数（`start` / `stop` / `restart` / `reload` / `status` など）は
  [SysVinit の起動スクリプトとランレベル](./SysVinitの起動スクリプトとランレベル.md) の「起動スクリプトを手で動かす」にまとめています

## 手でリンクを作る

### コマンドを使わなくても設定できる

**自動起動の設定は、結局 `/etc/rc[0-6].d/` にシンボリックリンクを作ることです。**
だから **`ln` コマンドで直接作っても、まったく同じように動きます。**

> **`ln -s 実体 リンク名`** … シンボリックリンクを作るコマンドです。
> **`-s`**（symbolic）を付けないと**ハードリンク**になってしまい、`/etc/rc[0-6].d/` の作法から外れます。

**`/etc/rc[0-6].d/` には、決められた形のシンボリックリンクを置く決まり**なので、
**`cp`（コピー）や `mv`（移動）で実体を置いてはいけません。**

| コマンド | 使えるか | 理由 |
|:--|:-:|:--|
| **`ln -s`** | **○** | **決まりどおりシンボリックリンクを作る** |
| `cp` | **×** | **実体のコピーが置かれる**。元を直しても反映されず、二重管理になる |
| `mv` | **×** | **実体が移動してしまう**。`/etc/init.d/` から消える |
| `touch` | **×** | 空のファイルができるだけ |
| `make` | **×** | ソースからプログラムを作るコマンド。用途が違う |

### 例文

```bash
$ cd /etc/rc5.d                                  # ランレベル5のディレクトリへ移動する
$ pwd                                            # いまどこにいるかを確認する
/etc/rc5.d
$ ls ../init.d/mydaemon                          # 実体があることを確かめる
../init.d/mydaemon
$ sudo ln -s ../init.d/mydaemon S50mydaemon      # 起動リンクを作る（ランレベル5で自動起動になる）
$ ls -l S50mydaemon                              # 作られたリンクを確認する
lrwxrwxrwx 1 root root 18 Sep 13 23:40 S50mydaemon -> ../init.d/mydaemon
```

### 補足

- **リンク名は `S` または `K` ＋ 2 桁の数字 ＋ サービス名**です。この形から外れると `init` に無視されます（[リンク名の読み方](./SysVinitの起動スクリプトとランレベル.md)）
- **リンク先は相対パス（`../init.d/mydaemon`）で書くのが慣例**です。絶対パスでも動きますが、ディストリの流儀に合わせておくと、他の人が見たときに違和感がありません
- **`ln -s` の第 2 引数を省略すると、カレントディレクトリに「実体と同じ名前」でリンクが作られます。** `S50mydaemon` という名前にしたいので、**第 2 引数は必ず書きます**

## 自動起動を止める

### 正しい方法は2つ

**「次回の起動でサービスを上げない」ようにする方法は、次の 2 つです。**

| 方法 | コマンド | 何が起きるか |
|:--|:--|:--|
| **コマンドで無効にする** | `chkconfig サービス off` ／ **`update-rc.d -f サービス remove`** ／ `insserv -r サービス` | **`S` リンクが消える（または `K` リンクに変わる）** |
| **リンクを直接消す** | **`rm /etc/rc3.d/S55sshd`** | **そのランレベルの起動リンクだけが消える** |

### やってはいけない方法と、その理由

**「止めたつもりで止まっていない」「別のものまで壊した」になりやすい操作です。**

| やりがちな操作 | なぜだめか |
|:--|:--|
| **`update-rc.d サービス stop`** | **`K` リンクを作る指示**であって、**`S` リンクは残ったまま**です。起動も終了も設定された、ちぐはぐな状態になります |
| **`/etc/init.d/サービス stop`** | **その場で止めるだけ**です。**次に起動すればまた上がってきます** |
| **`/etc/inittab` を編集する** | `inittab` は**ランレベルそのものの設定**で、**個別サービスの自動起動とは関係ありません** |
| **`/etc/init.d/` の実体を消す** | **リンク切れが大量に残ります。** 再び使いたくなったときに復旧が面倒です |
| **`chkconfig サービス reset`** | **既定の設定に戻すだけ**です。**既定が `on` のサービスなら `on` のまま**です |

### 手順の例

```bash
$ chkconfig --list sshd                          # ① 変更前の状態を控えておく
sshd   0:off  1:off  2:on   3:on   4:on   5:on   6:off

$ sudo chkconfig sshd off                        # ② 自動起動を無効にする
$ chkconfig --list sshd                          # ③ 変わったことを確かめる
sshd   0:off  1:off  2:off  3:off  4:off  5:off  6:off

$ ls /etc/rc3.d/ | grep sshd                     # ④ リンク側でも確かめる
K30sshd                                          # S ではなく K になっている
```

**補足**

- **`update-rc.d ... remove` には `-f` が要ります。** `/etc/init.d/` に実体が残っていると、**「まだ実体がある」と言われて中断する**ためです
- **無効にしても、いま動いているプロセスは止まりません。** 止めたいなら `service サービス stop` を別に実行します。**「自動起動の設定」と「いまの稼働状態」は別**です

## よく使うオプション

### chkconfig

| オプション | 意味 |
|:--|:--|
| **`--list [サービス名]`** | **設定状態を表示する**。サービス名を省くと全サービス |
| **`--level <数字>`** | **対象のランレベルを指定する**（`--level 35` で 3 と 5。**数字を並べて書く**） |
| **`--add <名前>`** | **管理対象に追加する**（スクリプトの `# chkconfig:` ヘッダを読んでリンクを作る） |
| **`--del <名前>`** | **管理対象から外す**（すべてのランレベルのリンクを削除する） |
| `--override <名前>` | 既定の設定を上書きする |
| `--type <xinetd\|sysv>` | 対象の種類を絞る |
| `-v` | **`chkconfig` 自体のバージョンを表示する**（サービスの状態は出ない） |

> **`-v` を「詳しく表示する」と読み違えないでください。** `chkconfig` の `-v` は**バージョン表示**です。
> サービスの設定を見たいなら **`--list`** です。

### update-rc.d

| 書き方 | 意味 |
|:--|:--|
| **`update-rc.d <名前> defaults [優先度]`** | **標準の順序でリンクを作る** |
| **`update-rc.d <名前> start <優先度> <ランレベル…> .`** | **起動リンク（`S`）を作る**。最後のドットを忘れない |
| **`update-rc.d <名前> stop <優先度> <ランレベル…> .`** | **終了リンク（`K`）を作る**。同上 |
| **`update-rc.d <名前> enable [ランレベル]`** | **自動起動を有効にする** |
| **`update-rc.d <名前> disable [ランレベル]`** | **自動起動を無効にする** |
| **`update-rc.d -f <名前> remove`** | **リンクをすべて削除する**（`-f` が必要） |
| `-n` | 実際には変更せず、何が起きるかだけ表示する |

### insserv

| オプション | 意味 |
|:--|:--|
| **`insserv <名前>`** | **自動起動を有効にする** |
| **`-r`** | **自動起動を無効にする**（リンクを削除する） |
| `-d` | スクリプトの既定の設定でリンクを作り直す |
| `-n` | 実際には変更せず、何が起きるかだけ表示する |
| `-v` | 処理の内容を詳しく表示する |
| `-f` | 依存関係の警告を無視して強制的に処理する |

### service

| 書き方 | 意味 |
|:--|:--|
| **`service <名前> <引数>`** | **起動スクリプトに引数を渡して実行する** |
| **`service --status-all`** | **すべてのサービスの状態をまとめて表示する** |

## 結果画面の見方

### chkconfig --list の出力

```bash
$ chkconfig --list                               # 全サービスのランレベル別設定を一覧する
crond   0:off  1:off  2:on   3:on   4:on   5:on   6:off
httpd   0:off  1:off  2:off  3:off  4:off  5:off  6:off
sshd    0:off  1:off  2:on   3:on   4:on   5:on   6:off
```

| 欄 | 内容 | どこを見れば何が分かるか | 異常と判断する目安 |
|:--|:--|:--|:--|
| **1 列目** | **サービス名** | `/etc/init.d/` のファイル名と同じ | 見覚えのない名前は、誰かが追加したスクリプト |
| **`0:`** | ランレベル 0（システム停止）での設定 | **`off` が正しい** | `on` は通常ありえない |
| **`1:`** | ランレベル 1（シングルユーザ）での設定 | **`off` が普通** | `on` なら、復旧作業中にも動いてしまう |
| **`2:`** | ランレベル 2（NFS なしのマルチユーザ）での設定 | 3 と揃っているのが普通 | 2 と 3 で食い違うのは意図的か確認する |
| **`3:`** | **ランレベル 3（CUI）での設定** | **サーバはここを見る。`on` なら起動時に自動で上がる** | **上げたいサービスが `3:off`** なら、再起動後に落ちたままになる |
| **`4:`** | ランレベル 4（未定義）での設定 | 使われないので、どちらでもよい | — |
| **`5:`** | **ランレベル 5（GUI）での設定** | **デスクトップはここを見る** | 3 と食い違うのは意図的か確認する |
| **`6:`** | ランレベル 6（再起動）での設定 | **`off` が正しい** | `on` は通常ありえない |
| **`on` / `off`** | **`S` リンクがあるか無いか** | `on` = `S` リンクあり ／ `off` = `K` リンクあり、または何もない | — |

> **見るべきは、ほぼ `3:` と `5:` の 2 つだけ**です。
> サーバは 3（CUI）、デスクトップは 5（GUI）で動くためです。

**1 つのサービスだけを見る**

```bash
$ chkconfig --list sshd                          # sshd の設定だけを表示する
sshd   0:off  1:off  2:on   3:on   4:on   5:on   6:off

$ chkconfig --list | grep -E "3:on"              # ランレベル3で自動起動するものを絞り込む
```

---

### update-rc.d の出力

```bash
$ sudo update-rc.d ssh defaults                  # 標準の順序でリンクを作る
Adding system startup for /etc/init.d/ssh ...
   /etc/rc0.d/K20ssh -> ../init.d/ssh
   /etc/rc1.d/K20ssh -> ../init.d/ssh
   /etc/rc6.d/K20ssh -> ../init.d/ssh
   /etc/rc2.d/S20ssh -> ../init.d/ssh
   /etc/rc3.d/S20ssh -> ../init.d/ssh
   /etc/rc4.d/S20ssh -> ../init.d/ssh
   /etc/rc5.d/S20ssh -> ../init.d/ssh
```

| 行 | 内容 | どこを見れば何が分かるか | 異常と判断する目安 |
|:--|:--|:--|:--|
| **`Adding system startup for …`** | **どのスクリプトを対象にしたか** | パスが意図したものか | 打ち間違えた名前なら、ここで気づける |
| **`/etc/rc0.d/K20ssh`** の `K` | **終了リンクが作られた** | **ランレベル 0, 1, 6 は `K`** | `S` になっていたら指定を誤っている |
| **`/etc/rc2.d/S20ssh`** の `S` | **起動リンクが作られた** | **ランレベル 2〜5 は `S`** | 上げたいランレベルに `S` が無ければ設定漏れ |
| **`20`** | **優先度**（実行順序） | 小さいほど先に実行される | 依存先より小さいと起動に失敗する |
| **`-> ../init.d/ssh`** | **リンク先（実体）** | 相対パスで実体を指している | ここが空なら実体が無い |

**補足**

- **`defaults` の結果は「0,1,6 が `K`、2,3,4,5 が `S`」**です。この並びを覚えておくと、出力を一目で検算できます
- **表示が出ないディストリもあります。** その場合は `ls -l /etc/rc*.d/ | grep サービス名` で確かめます

---

### 設定後にリンクで確かめる

**コマンドの出力を信じきらず、リンクを直接見るのがいちばん確実です。**

```bash
$ ls -l /etc/rc*.d/*crond                        # crond が各ランレベルでどう扱われるか見る
lrwxrwxrwx 1 root root 15 /etc/rc0.d/K60crond -> ../init.d/crond   # 停止時は止める
lrwxrwxrwx 1 root root 15 /etc/rc2.d/S90crond -> ../init.d/crond   # 起動する
lrwxrwxrwx 1 root root 15 /etc/rc3.d/S90crond -> ../init.d/crond   # 起動する
lrwxrwxrwx 1 root root 15 /etc/rc5.d/S90crond -> ../init.d/crond   # 起動する
lrwxrwxrwx 1 root root 15 /etc/rc6.d/K60crond -> ../init.d/crond   # 再起動時は止める
```

| 見るところ | 何が分かるか |
|:--|:--|
| **先頭の `l`** | シンボリックリンクであること（`-` なら実体が置かれていて、作法から外れている） |
| **`S` / `K`** | そのランレベルで起動するか終了するか |
| **2 桁の数字** | 実行順序 |
| **`->` の右側** | 実体のパス。**`ls` で赤く表示されるならリンク切れ** |

```bash
$ find /etc/rc3.d/ -xtype l                      # リンク切れだけを探す
```

## systemdとの対応

**systemd の環境では、4 つのコマンドは `systemctl` に置き換わります。**

| SysVinit | systemd |
|:--|:--|
| `chkconfig サービス on` ／ `update-rc.d サービス defaults` ／ `insserv サービス` | **`systemctl enable サービス`** |
| `chkconfig サービス off` ／ `update-rc.d -f サービス remove` ／ `insserv -r サービス` | **`systemctl disable サービス`** |
| `chkconfig --list` | **`systemctl list-unit-files --type=service`** |
| `chkconfig --list サービス` | **`systemctl is-enabled サービス`** |
| `service サービス start` | **`systemctl start サービス`** |
| `service --status-all` | **`systemctl list-units --type=service`** |

> **systemd では「ディストリごとにコマンドが違う」問題が無くなりました。**
> `systemctl` ひとつで、RHEL 系でも Debian 系でも SUSE 系でも同じように操作できます。
> **4 コマンドを覚える必要があるのは、古い環境を触るときだけ**です。

```bash
$ sudo chkconfig sshd on                         # 古い書き方でも受け付けられる
Note: Forwarding request to 'systemctl enable sshd.service'.   # systemctl へ転送された
```

**`systemctl enable` が実際にしていること**も、リンクを作ることです。

```bash
$ sudo systemctl enable httpd                    # 自動起動を有効にする
Created symlink /etc/systemd/system/multi-user.target.wants/httpd.service
 → /usr/lib/systemd/system/httpd.service
```

```text
   SysVinit :  /etc/rc3.d/S90crond        →  /etc/init.d/crond
   systemd  :  …/multi-user.target.wants/httpd.service  →  /usr/lib/systemd/system/httpd.service

   置き場所と名前が違うだけで、「リンクを作って自動起動にする」考え方は同じ
```

詳しくは [systemctl サービスの操作と確認](./systemctl_サービスの操作と確認.md) と
[systemd 基本とユニットファイル](./systemd_基本とユニットファイル.md) にまとめています。

## 公式ドキュメントで確認した補足

- **`chkconfig` は、`--level` を省略すると、`on` / `off` の対象がランレベル 2, 3, 4, 5 になります**（`man 8 chkconfig`）
- **`chkconfig` は、起動スクリプト内の `# chkconfig:` ヘッダを読んで既定のランレベルと順序番号を決めます。** このヘッダが無いスクリプトは `--add` できません（`man 8 chkconfig`）
- **`update-rc.d` の `start` / `stop` は、優先度に続けてランレベルを並べ、最後にドット（`.`）で終端します**（`man 8 update-rc.d`）
- **`update-rc.d` は、LSB ヘッダ（`### BEGIN INIT INFO` 〜 `### END INIT INFO`）に書かれた依存関係をもとに順序を決めます**（`man 8 update-rc.d`）
- **`insserv` は、LSB ヘッダの `Required-Start` / `Should-Start` などを読んで、起動順序を自動的に決定します**（`man 8 insserv`）
- **`service` は、環境変数を最小限に整えたうえで `/etc/init.d/` のスクリプトを実行します**（`man 8 service`）
