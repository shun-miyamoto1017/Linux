## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| **カーネルのメッセージを見る** | **`dmesg -T`**（時刻を読める形で表示） |
| **エラーだけ見る** | **`dmesg -l err,crit,alert,emerg`** |
| **流れてくるのを見続ける** | **`dmesg -w`** |
| **カーネルの設定値を見る** | **`sysctl -a`** ／ 個別なら **`sysctl 項目名`** |
| **設定値を一時的に変える** | **`sudo sysctl -w 項目名=値`** |
| **設定を再起動後も残す** | **`/etc/sysctl.d/99-mysetting.conf`** に書いて **`sudo sysctl --system`** |
| **設定の実体はどこ？** | **`/proc/sys/`** 以下のファイル |
| **起動時のオプションを見る** | **`cat /proc/cmdline`** |

## カーネルとのやりとりの3つの窓口

カーネルは「動いているプログラム」なので、直接のぞくことはできません。
代わりに、**カーネルが用意した 3 つの窓口**を通して状態を見たり設定を変えたりします。

```text
           あなた
             │
  ┌──────────┼──────────────────┐
  │          │                  │
  ▼          ▼                  ▼
 dmesg     /proc/sys           /sys
（メッセージ）（設定値）      （デバイス情報）
  │          │                  │
  └──────────┴──────────────────┘
             │
             ▼
        カーネル本体
```

| 窓口 | 何が見えるか | 主に使うコマンド |
|:--|:--|:--|
| **カーネルリングバッファ** | **カーネルが出したメッセージ**（起動ログ、エラー、警告） | **`dmesg`** |
| **`/proc`**（procfs） | **カーネルとプロセスの状態**。`/proc/sys` の下は**設定値** | **`sysctl`**、`cat` |
| **`/sys`**（sysfs） | **デバイスとドライバの情報**（機器の階層構造） | `cat`、`udevadm` |

> **`/proc` も `/sys` も、ディスク上に実体があるファイルではありません。**
> カーネルがその場で作って見せている「仮想的なファイル」です。`ls -l` してもサイズは `0` と表示されます。

---

### proc は擬似的なファイルシステム

**`/proc`** は、**プロセス・ハードウェア・システムリソースなどの情報を扱うための擬似的なファイルシステム**です。

| 性質 | 意味すること |
|:--|:--|
| **ハードディスク上には存在しない** | 実体のあるファイルではない |
| **システムが起動するときにメモリ上に作成される** | 再起動のたびに作り直される |
| **中身はカーネルがその場で生成する** | `cat` した瞬間の値が返る |

**`/` の直下にある主なディレクトリと区別する**

| ディレクトリ | 中身 |
|:--|:--|
| **`/proc`** | **プロセス・ハードウェア・システムリソースの情報**（擬似ファイルシステム） |
| `/boot` | **起動に必要な設定ファイルやカーネルイメージ** → [カーネルのビルドとインストール](./カーネルのビルドとインストール.md) |
| `/dev` | **デバイスファイル** → [ハードウェアの確認とudev](./ハードウェアの確認とudev.md) |
| `/etc` | **システムの設定ファイル** |
| `/sbin` | **管理用コマンド** |

**カーネル関係でよく見る `/proc` のファイル**

| パス | 中身 |
|:--|:--|
| **`/proc/sys/`** | **カーネルパラメータ**（`sysctl` が読み書きする先） |
| **`/proc/modules`** | **現在ロードされているカーネルモジュールの一覧**（`lsmod` の元データ） |
| **`/proc/version`** | **カーネルバージョンを含むシステム情報** |
| **`/proc/cmdline`** | 起動時にカーネルへ渡されたオプション |
| **`/proc/dma`** / **`/proc/interrupts`** / **`/proc/ioports`** | **ハードウェアの割り当て情報**（`lsdev` の元データ） |
| `/proc/cpuinfo` / `/proc/meminfo` | CPU とメモリの情報 |
| `/proc/<数字>/` | **そのプロセス ID の情報** |

## dmesg カーネルのメッセージを見る

### カーネルリングバッファとは

カーネルは、起きたことをメッセージとして書き出します。
その置き場所が **カーネルリングバッファ**（kernel ring buffer）です。

**リング（輪）という名前のとおり、大きさが決まっていて、いっぱいになると古いものから消えます。**

```text
  ┌─────────────────────────────────┐
  │  新しいメッセージが書き込まれる   │
  │            ↓                    │
  │  [ 5 ][ 6 ][ 7 ][ 8 ][ 1 ][ 2 ] │  ← 一周すると古いものを上書き
  │                      ↑          │
  │            ここが一番古い         │
  └─────────────────────────────────┘
```

| 性質 | 意味すること |
|:--|:--|
| **大きさが有限** | 忙しいサーバでは、**起動時のメッセージがもう消えている**ことがある |
| **メモリ上にある** | **再起動すると消える**。過去の障害を追うには `journalctl` を使う |
| **カーネルが書く** | アプリケーションのログ（`/var/log/`）とは**別物** |

**過去にさかのぼりたいときは `journalctl` を使います。**

```bash
$ dmesg -T                                           # 今のリングバッファの中身を見る
$ journalctl -k                                      # journald が保存したカーネルメッセージを見る
$ journalctl -k -b -1                                # 1つ前の起動時のカーネルメッセージを見る
```

| コマンド | 見えるもの | 再起動をまたげるか |
|:--|:--|:--|
| **`dmesg`** | **今のリングバッファ**の中身 | **またげない** |
| **`journalctl -k`** | journald が保存したカーネルメッセージ | **またげる**（`-b -1` で前回の起動） |

---

### 起動時のメッセージを見る3つの入口

**「起動時のカーネルメッセージを確認したい」**という場面では、入口が 3 つあります。
**`/var/log/dmesg` というファイルがある**ことを知らないと、選択肢として出てきません。

| 入口 | 実体 | 残るか |
|:--|:--|:--|
| **`dmesg`** | **今のリングバッファ**を読む | 再起動で消える。忙しいサーバでは**起動時の分がすでに押し出されている**ことがある |
| **`cat /var/log/dmesg`** | **起動が終わった時点のリングバッファを書き出したファイル** | **ファイルなので残る**。ただし**中身は起動直後で止まったまま**で、その後のメッセージは入らない |
| **`journalctl -k`** | journald が保存したカーネルメッセージ | **残る**。`-b -1` で前回の起動もたどれる |

```bash
$ cat /var/log/dmesg                                 # 起動完了時点のカーネルメッセージをファイルから読む
$ ls -l /var/log/dmesg                               # あるかどうかを確かめる（無いディストリもある）
$ journalctl -k -b                                   # 今回の起動のカーネルメッセージ（systemd 系ではこちらが確実）
```

> **`/var/log/dmesg` は、あるディストリと無いディストリがあります。**
> RHEL 6 系のように起動スクリプト（`rc.sysinit`）が書き出す構成では作られますが、
> **systemd が中心の新しいディストリでは作られないことが多い**です。
> **無ければ `journalctl -k` に切り替える**、と覚えておくと現場で困りません。

**起動まわりで見る場所をもう 1 つ**

```bash
$ cat /proc/cmdline                                  # 起動時にブートローダからカーネルへ渡されたパラメータを見る
BOOT_IMAGE=/vmlinuz-6.1.0-18-amd64 root=/dev/sda2 ro quiet
```

| 知りたいこと | 見る場所 |
|:--|:--|
| **起動時に何のメッセージが出たか** | **`dmesg` / `/var/log/dmesg` / `journalctl -k`** |
| **起動時にどんなオプションが渡されたか** | **`/proc/cmdline`**（`dmesg` の先頭の `Command line:` 行にも出る） |

---

### 基本の使い方

**例文**

```bash
$ dmesg                                              # そのまま表示する（時刻は起動からの秒数）
[    0.000000] Linux version 6.1.0-18-amd64 …
[    1.234567] e1000e 0000:00:1f.6 eth0: NIC Link is Up 1000 Mbps

$ dmesg -T                                           # 時刻を人が読める形で表示する
[Thu Sep 11 09:12:03 2026] e1000e 0000:00:1f.6 eth0: NIC Link is Up 1000 Mbps

$ dmesg -T | tail -30                                # 直近30行だけ見る
$ dmesg -T | grep -i error                           # エラーらしき行を拾う
$ sudo dmesg -w                                       # 新しいメッセージを流れるまま見続ける
```

**補足**

- **`-T` を付けないと、時刻が「起動してから何秒後か」で表示されます。**いつ起きたかを知りたいなら必ず付けてください
- ディストリによっては **`dmesg` に `root` 権限が必要**です（`kernel.dmesg_restrict` が `1` のとき）
- `grep -i` の `-i` … 大文字小文字を区別しない

---

### よく使うオプション

**表示を整える**

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-T`** / `--ctime` | **人が読める日時**で表示する | **まずこれ**。いつ起きたかが分かる |
| **`-H`** / `--human` | 読みやすい形式（色・相対時刻・ページャ付き） | 対話的に眺めるとき |
| **`-e`** / `--reltime` | ローカル時刻と**前の行からの経過**を表示する | 処理の間隔を見たいとき |
| **`-d`** / `--show-delta` | **前の行からの経過秒**を表示する | 時間のかかっている処理を探す |
| **`-t`** / `--notime` | **時刻を表示しない** | 差分を取るとき、ノイズを減らす |
| **`-x`** / `--decode` | **ファシリティと優先度を文字で**表示する | どの重さのメッセージか見たいとき |
| **`-L`** / `--color` | 色を付ける | 目視で追うとき |
| **`-P`** / `--nopager` | ページャを使わない | パイプに流すとき |
| **`--time-format 形式`** | 時刻の形式を指定（`ctime` / `reltime` / `delta` / `iso` / `raw`） | ログ収集の形式に合わせる |

**絞り込む**

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-l レベル`** / `--level` | **優先度で絞る**（カンマ区切りで複数可） | **`-l err,crit,alert,emerg`** で異常だけ拾う |
| **`-f ファシリティ`** / `--facility` | **発生元で絞る**（`kern` / `daemon` など） | 種類を分けたいとき |
| **`-k`** / `--kernel` | **カーネルからのメッセージだけ** | ノイズを除く |
| **`-u`** / `--userspace` | ユーザ空間からのメッセージだけ | アプリ側の書き込みを見る |

**動作を変える**

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-w`** / `--follow` | **新しいメッセージを待ち続ける**（`tail -f` と同じ感覚） | 操作しながら反応を見る |
| **`-C`** / **`--clear`** | **リングバッファを空にする**（表示しない） | **システムを動かしたまま**、たまった内容を消せる。検証前にきれいにする |
| **`-c`** / `--read-clear` | **表示してから**空にする | 内容を残しつつ初期化 |
| **`-F ファイル`** / `--file` | ファイルから読む | 採取済みのログを解析する |
| **`-S`** / `--syslog` | 古い syslog インタフェースを使う | 互換用 |
| **`-n レベル`** / `--console-level` | **コンソールに出す優先度のしきい値**を変える | 画面がメッセージで埋まるとき |
| **`-D`** / `--console-off` | コンソールへの表示を止める | 作業中に邪魔なとき |
| **`-E`** / `--console-on` | コンソールへの表示を再開する | `-D` を戻す |

---

### 優先度（レベル）

メッセージには、**8 段階の重さ**が付いています。**数字が小さいほど重大**です。

| 番号 | 名前 | 意味 | 対応の目安 |
|:-:|:--|:--|:--|
| **0** | **`emerg`** | システムが**使用不能** | 即時対応 |
| **1** | **`alert`** | **直ちに対処が必要** | 即時対応 |
| **2** | **`crit`** | **重大な状態**（ハードウェア障害など） | 即時対応 |
| **3** | **`err`** | **エラー** | **まずここを見る** |
| **4** | **`warn`** | 警告 | 傾向を見る |
| **5** | **`notice`** | 正常だが注意すべき事象 | 参考 |
| **6** | **`info`** | 情報 | 参考 |
| **7** | **`debug`** | デバッグ用 | 通常は不要 |

**例文**

```bash
$ dmesg -T -l err,crit,alert,emerg                   # 異常だけを時刻付きで拾う
$ dmesg -T -l warn                                   # 警告だけ見る
$ dmesg -x | head                                    # ファシリティと優先度を文字で表示する
kern  :info  : [    0.000000] Linux version 6.1.0-18-amd64 …
kern  :err   : [   12.345678] EXT4-fs error (device sda1): …
```

**補足**

- **障害調査の第一手は `dmesg -T -l err,crit,alert,emerg`** です。これで何も出なければ、カーネルは異常を検知していません

---

### 現場でよく見るメッセージ

| 出てくる文字列 | 何が起きているか | 次に見るもの |
|:--|:--|:--|
| **`Out of memory: Killed process …`** | **OOM Killer** がメモリ不足でプロセスを強制終了した | `free -h`、該当プロセスのメモリ使用量 |
| **`I/O error, dev sda, sector …`** | **ディスクの読み書きに失敗** | `smartctl`、ストレージの状態 |
| **`EXT4-fs error (device …)`** | **ファイルシステムの異常** | `fsck`（アンマウントしてから） |
| **`NIC Link is Down` / `Link is Up`** | **NIC のリンク断・復帰** | 物理配線、スイッチ側 |
| **`Firmware … failed to load`** | ドライバが**ファームウェアを読めない** | `linux-firmware` パッケージの有無 |
| **`Unknown symbol in module`** | モジュールの**依存が解決できていない** | [カーネルモジュールの管理](./カーネルモジュールの管理.md) |
| **`segfault at … ip … sp …`** | アプリケーションが異常終了した | コアダンプ、アプリのログ |
| **`TCP: out of memory -- consider tuning tcp_mem`** | ネットワークのバッファ不足 | `sysctl net.ipv4.tcp_mem` |
| **`blocked for more than 120 seconds`** | I/O 待ちでプロセスが固まっている | ストレージの性能、NFS の状態 |

**例文**

```bash
$ dmesg -T | grep -i "out of memory"                 # OOM Killer が動いたか調べる
$ dmesg -T | grep -iE "i/o error|ext4-fs error"      # ディスクとFSの異常を探す
$ dmesg -T | grep -i "link is"                       # NICのリンク状態の変化を追う
```

**補足**

- `grep -E` … 拡張正規表現を使う指定。`|` で「または」を書けます

## dmesg の結果画面の見方

```bash
$ dmesg -x -T | head -3                              # 時刻とレベルを付けて先頭3行を見る
kern  :info  : [Thu Sep 11 09:12:01 2026] Linux version 6.1.0-18-amd64 (debian-kernel@lists.debian.org)
kern  :err   : [Thu Sep 11 09:12:45 2026] EXT4-fs error (device sda1): ext4_find_entry:1663: inode #2
kern  :info  : [Thu Sep 11 09:12:46 2026] e1000e 0000:00:1f.6 eth0: NIC Link is Up 1000 Mbps Full Duplex
```

| 位置 | 内容 | どこを見るか | 異常と判断する目安 |
|:--|:--|:--|:--|
| **1 番目**（`kern`） | **ファシリティ**＝メッセージの発生元 | ほぼ `kern`（カーネル） | `daemon` などが混ざるのは `-u` を付けたとき |
| **2 番目**（`err`） | **優先度**（`-x` で文字表示） | **`err` 以上**を最優先で見る | `err` / `crit` / `alert` / `emerg` は要対応 |
| **`[ … ]`** | **時刻**。`-T` なしなら**起動からの秒数** | いつ起きたか | 起動直後（数秒以内）ならハードウェア認識まわり |
| **本文の先頭** | **どのサブシステムか**（`EXT4-fs`、`e1000e`、`TCP` など） | 原因の切り分けの起点 | ドライバ名なら機器、`EXT4-fs` ならFS |
| **本文の残り** | 具体的な内容 | デバイス名・セクタ番号・プロセス名 | 同じ内容の**繰り返し**は進行中の障害 |

**時刻の読み方の注意**

```text
  -T なし : [   12.345678]  ← 起動してから 12.34 秒後
  -T あり : [Thu Sep 11 09:12:45 2026]  ← 実際の日時
```

> **`-T` の時刻は、サスペンド（一時停止）をはさむとずれることがあります。**
> 厳密な時刻が必要なら `journalctl -k` のタイムスタンプを使ってください。

## procとsysという2つの仮想ファイルシステム

### それぞれの役割

| | **`/proc`**（procfs） | **`/sys`**（sysfs） |
|:--|:--|:--|
| **何が見えるか** | **プロセスとカーネルの状態**。`/proc/sys` の下は**設定値** | **デバイスとドライバ**の情報を、階層構造で |
| **代表的な中身** | `/proc/cpuinfo`、`/proc/meminfo`、`/proc/cmdline`、`/proc/modules` | `/sys/class/net/`、`/sys/block/`、`/sys/devices/` |
| **主に使うコマンド** | **`sysctl`**、`cat` | `cat`、`udevadm`、`lsblk` |
| **設定を変えられるか** | **`/proc/sys` の下は変えられる** | 一部変えられる |

**例文**

```bash
$ cat /proc/cmdline                                  # 起動時にカーネルへ渡されたオプションを見る
BOOT_IMAGE=/boot/vmlinuz-6.1.0-18-amd64 root=UUID=… ro quiet

$ cat /proc/cpuinfo | grep "model name" | head -1    # CPUの種類を確認する
$ cat /proc/meminfo | head -3                        # メモリの状況を見る
$ cat /proc/uptime                                   # 起動からの経過秒と、アイドルの合計秒
$ cat /sys/class/net/eth0/operstate                  # NICが up か down かを見る
$ cat /sys/block/sda/queue/scheduler                 # ディスクのI/Oスケジューラを見る
```

**補足**

- **`/proc/cmdline`** は「このカーネルがどんなオプションで起動したか」の記録です。GRUB の設定が効いているかの確認に使えます
- `/proc/<数字>/` は**プロセスごとの情報**です（`/proc/1234/status` など）

---

## sysctl カーネルの設定を変える

### 意味

**`sysctl`** は、**`/proc/sys/` の下にあるカーネルの設定値を、読み書きするコマンド**です。

**設定名とファイルパスは、そのまま対応しています。**

```text
   sysctl の項目名 :  net.ipv4.ip_forward
                       │    │    │
                       ▼    ▼    ▼
   ファイルのパス   : /proc/sys/net/ipv4/ip_forward
                                ↑
                     ドット（.）がスラッシュ（/）になるだけ
```

| 書き方 | 同じ意味になる |
|:--|:--|
| `sysctl net.ipv4.ip_forward` | `cat /proc/sys/net/ipv4/ip_forward` |
| `sudo sysctl -w net.ipv4.ip_forward=1` | `echo 1 \| sudo tee /proc/sys/net/ipv4/ip_forward` |

> **`sysctl` を使うほうが安全です。**
> 項目名の誤りをその場でエラーにしてくれますし、設定ファイルからの読み込みにも同じコマンドを使えます。

---

### 3つの書き方を固定する

**`sysctl` は、やりたいことによって書き方が 3 通りに分かれます。**ここを混ぜると動きません。

| やりたいこと | 書き方 |
|:--|:--|
| **表示** | **`sysctl カーネルパラメータ`** |
| **変更** | **`sysctl -w カーネルパラメータ=値`** |
| **一覧** | **`sysctl -a`** |

```text
   表示   sysctl     kernel.shmmax
   変更   sysctl -w  kernel.shmmax=68719476736
                                  ▲
                            スペースではなくイコール
   一覧   sysctl -a
```

**間違いやすい書き方**

| 書き方 | 何が起きるか |
|:--|:--|
| **`sysctl -w kernel.shmmax`** | **エラー。**`-w` は変更用なので、**値が必要**<br>`error: "kernel.shmmax" must be of the form name=value` |
| **`sysctl -w kernel.shmmax 68719476736`** | **エラー。**区切りは**スペースではなくイコール（`=`）** |
| **`sysctl kernel.shmmax 68719476736`** | 変更にならない。変更には **`-w`** が要る |
| `sysctl -l` | **存在しないオプション** |

**補足**

- 環境によっては **`-w` を付けなくても変更できる**ことがありますが、**試験でも実務でも `-w` を付けるのが確実**です

---

### 仮想ファイルで操作するときの書き方

`/proc/sys` 以下のファイルを直接使う場合も、**表示と変更で書き方が違います。**

| やりたいこと | 書き方 |
|:--|:--|
| **表示** | **`cat /proc/sys/kernel/shmall`** |
| **変更** | **`echo '2097152' > /proc/sys/kernel/shmall`** |

**2 つの落とし穴**

| 間違い | 何が起きるか |
|:--|:--|
| **`cat /proc/sys/kernel.shmmax`** | **エラー。**パスにするときは**ドットをスラッシュに置き換える** |
| **`echo /proc/sys/kernel/shmmax`** | **「`/proc/sys/kernel/shmmax`」という文字列が画面に出るだけ。**`echo` は引数をそのまま表示するコマンドで、ファイルの中身は読まない |
| **`echo 20000 \| /proc/sys/kernel/keys/maxbytes`** | **エラー。**`\|`（パイプ）は**右側にコマンドを書いて、その標準入力へ流す**記号。ファイルへの書き込みにはならない |
| **`echo 20000 > /proc/sys/kernel/keys/maxbytes`** | **正しい。**`>`（リダイレクト）が**ファイルへの書き込み** |

```text
   >  … ファイルへ書き込む（リダイレクト）      ← 設定を変えるのはこちら
   |  … 右のコマンドの標準入力へ流す（パイプ）  ← ファイルには書けない
```

**パス変換の練習**

```text
   kernel.shmmax             →  /proc/sys/kernel/shmmax
   kernel.keys.maxbytes      →  /proc/sys/kernel/keys/maxbytes
   net.ipv4.ip_forward       →  /proc/sys/net/ipv4/ip_forward
   kernel.pty.max            →  /proc/sys/kernel/pty/max
              ▲                            ▲
          ドット区切り                 スラッシュ区切り
```

**例文**

```bash
$ sysctl kernel.shmmax                               # sysctl で表示する
kernel.shmmax = 68719476736

$ cat /proc/sys/kernel/shmmax                        # 仮想ファイルで表示する（同じ値）
68719476736

$ sudo sysctl -w kernel.keys.maxbytes=20000          # sysctl で変更する
$ echo 20000 | sudo tee /proc/sys/kernel/keys/maxbytes   # 仮想ファイルで変更する（同じ結果）

$ cd /proc/sys                                       # /proc/sys へ移動してから
$ cat kernel/pty/max                                 # 相対パスで読むこともできる
4096
```

**補足**

- `echo 値 > ファイル` は `root` でないと権限エラーになります。`sudo echo … > …` は**リダイレクトがsudoの外で行われるため効きません。**`sudo tee` を使ってください

### カーネルパラメータの性質

| 性質 | 正しいか | 補足 |
|:--|:--:|:--|
| **設定内容は即座に反映させることができる** | **正しい** | 多くの項目は**実行中に値を変えられ、すぐ有効**になる |
| **仮想ファイルに対する読み書きを通じて操作できる** | **正しい** | `/proc/sys` 以下のファイルがそれ |
| カーネルのビルド時に設定しなければならない | **誤り** | ビルド時に決めるのは **`.config`（カーネルコンフィギュレーション）**。**カーネルパラメータとは別物** |
| `sysctl` で変更した設定は恒久的に有効になる | **誤り** | **再起動で元に戻る。**恒久化には設定ファイルが要る |
| 新しいカーネルを入れたら手動で設定する必要がある | **誤り** | **適切な既定値が自動で入る。**チューニング目的以外では触らなくてよい |

> **「カーネルパラメータ」と「カーネルコンフィギュレーション」は別物です。**
>
> | | カーネルパラメータ | カーネルコンフィギュレーション |
> |:--|:--|:--|
> | **いつ決めるか** | **動いている最中に**変えられる | **ビルドする前に**決める |
> | **どこにあるか** | `/proc/sys` 以下 ／ `sysctl` | **`/usr/src/linux/.config`** |
> | **何を決めるか** | メモリやネットワークの**動作の値** | **どの機能を組み込むか**（`y` / `m` / `n`） |
> | 参照先 | このノート | [カーネルソースとmakeターゲット](./カーネルソースとmakeターゲット.md) |

---

### 基本の使い方

**例文**

```bash
$ sysctl -a | head                                   # 設定値をすべて表示する
$ sysctl -a | wc -l                                  # 設定項目の数をかぞえる
$ sysctl net.ipv4.ip_forward                         # 1項目だけ表示する
net.ipv4.ip_forward = 0

$ sysctl -n net.ipv4.ip_forward                      # 値だけ取り出す（項目名を出さない）
0

$ sudo sysctl -w net.ipv4.ip_forward=1               # 値を書き換える（再起動で消える）
net.ipv4.ip_forward = 1

$ sysctl -a --pattern "net.ipv4.tcp_.*mem"           # 正規表現で項目を絞って表示する
```

**補足**

- **`-w` で変えた値は、再起動すると元に戻ります。**恒久化したいときは、次の節の設定ファイルに書きます
- **値を変える操作には `root` 権限が必要**です

---

### よく使うオプション

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-a`** / `--all` | **設定値をすべて表示する**（`-A` / `-X` も同じ） | 全体を眺める。`grep` と組み合わせる |
| **`-w`** / `--write` | **値を書き込む** | 一時的に設定を変える |
| **`-n`** / `--values` | **値だけ**を表示する（項目名を出さない） | スクリプトで値を取り出すとき |
| **`-N`** / `--names` | **項目名だけ**を表示する | 項目を探すとき |
| **`-p ファイル`** / `--load` | **設定ファイルを読み込んで適用する**（省略時は `/etc/sysctl.conf`） | 編集した設定を反映する |
| **`--system`** | **すべての設定ファイル**を決まった順序で読み込む | **恒久化した設定の反映はこれ** |
| **`-r パターン`** / `--pattern` | **正規表現に一致する項目だけ**を対象にする | 大量の項目から絞る |
| **`-e`** / `--ignore` | **存在しない項目のエラーを無視する** | 環境差のある設定ファイルを流すとき |
| **`-q`** / `--quiet` | 設定した値を表示しない | 自動化の中で |
| **`-b`** / `--binary` | 改行を付けずに値を出力する | スクリプトで扱うとき |

---

### 設定を再起動後も残す

`-w` で変えた値は再起動で消えます。**恒久化するには設定ファイルに書きます。**

| 置き場所 | 使い方 |
|:--|:--|
| **`/etc/sysctl.d/99-名前.conf`** | **こちらを推奨**。目的ごとにファイルを分けられ、パッケージの設定とぶつからない |
| **`/etc/sysctl.conf`** | 昔からある単一のファイル。**最後に読まれるので、いちばん強い** |

> **恒久化できるのは、この 2 か所だけ**です。
>
> | やり方 | 再起動後も残るか |
> |:--|:--:|
> | **`/etc/sysctl.conf` に書く** | **残る** |
> | **`/etc/sysctl.d/*.conf` に書く** | **残る** |
> | `sysctl -w` で変更する | **残らない**（その場かぎり） |
> | `/proc/sys` の仮想ファイルに書き込む | **残らない**（その場かぎり） |
> | `/etc/kernel.d/` に書く | **そのディレクトリは存在しない** |
> | `/usr/src/linux/.config` に書く | **別物。**ビルド時の設定ファイルで、動いているカーネルには効かない |

**OS 起動時に自動実行されるスクリプトの中で `sysctl` がこのファイルを読み込み、設定が反映されます。**

**`--system` が読む順序**（上から順に読み、**あとに読んだほうが勝つ**）

```text
  1. /etc/sysctl.d/*.conf
  2. /run/sysctl.d/*.conf
  3. /usr/local/lib/sysctl.d/*.conf
  4. /usr/lib/sysctl.d/*.conf
  5. /lib/sysctl.d/*.conf
  6. /etc/sysctl.conf          ← 最後。ここに書くと他をすべて上書きする
```

> **ファイル名の先頭の数字は、読む順番を決めるためのものです。**
> `99-` のように大きい数字にしておくと、ほかの設定より**あとに読まれる＝勝つ**ので、意図した値になります。

**例文**

```bash
$ sudo tee /etc/sysctl.d/99-ipforward.conf <<'EOF'   # 恒久化する設定ファイルを作る
net.ipv4.ip_forward = 1
EOF

$ sudo sysctl --system                               # すべての設定ファイルを読み込んで反映する
$ sysctl net.ipv4.ip_forward                         # 反映されたか確認する
net.ipv4.ip_forward = 1

$ sudo sysctl -p /etc/sysctl.d/99-ipforward.conf     # そのファイルだけを読み込む
```

**補足**

- `tee ファイル <<'EOF' … EOF` … ヒアドキュメント。`EOF` までの複数行を、そのままファイルに書き込む書き方です
- **設定ファイルに書いただけでは反映されません。**`sysctl --system` を実行するか、再起動が必要です
- 設定ファイルの書式は **`項目名 = 値`**。`#` から行末はコメントです

---

### よく触る設定項目

| 項目 | 意味 | よく使う場面 |
|:--|:--|:--|
| **`net.ipv4.ip_forward`** | **パケットの転送を許可するか**（`1` で許可） | ルータ化、NAT、**Kubernetes のノード** |
| **`vm.swappiness`** | **スワップの使いやすさ**（0〜100。小さいほど使わない） | DB サーバでスワップを抑える |
| **`vm.overcommit_memory`** | メモリの過剰割り当てを許すか | Redis などの推奨設定 |
| **`fs.file-max`** | **システム全体で開けるファイル数の上限** | 同時接続の多いサーバ |
| **`net.core.somaxconn`** | **接続待ちキューの長さ** | Web サーバの高負荷対策 |
| **`net.ipv4.tcp_tw_reuse`** | TIME_WAIT のソケットを再利用するか | 短い接続が大量に発生する環境 |
| **`kernel.pid_max`** | プロセス ID の上限 | コンテナを大量に動かすホスト |
| **`kernel.dmesg_restrict`** | **一般ユーザに `dmesg` を許すか**（`1` で禁止） | セキュリティ要件 |
| **`net.bridge.bridge-nf-call-iptables`** | ブリッジを通る通信に iptables を適用するか | **Kubernetes の必須設定** |

**例文**

```bash
$ sysctl vm.swappiness                               # スワップの使いやすさを確認する
vm.swappiness = 60

$ sudo sysctl -w vm.swappiness=10                    # スワップを控えめにする（一時的）
$ sysctl -a | grep -E "^net\.ipv4\.(ip_forward|tcp_syncookies)"   # 特定の項目だけ抜き出す
```

**補足**

- **値の意味は項目ごとに違います。**変更する前に、必ずカーネルドキュメント（`Documentation/admin-guide/sysctl/`）で確認してください
- `net.bridge.*` は **`br_netfilter` モジュールが読み込まれていないと項目自体が存在しません**

## sysctl の結果画面の見方

```bash
$ sysctl -a | grep -A0 "^vm\.swappiness"             # 1行の出力を確かめる
vm.swappiness = 60
```

| 位置 | 内容 | どこを見るか |
|:--|:--|:--|
| **`=` の左** | **項目名**。ドット区切り | 先頭の単語が分類（`net` / `vm` / `fs` / `kernel`） |
| **`=` の右** | **現在の値** | 数値・複数の数値・文字列のいずれか |

**項目名の先頭でわかる分類**

| 先頭 | 扱う対象 |
|:--|:--|
| **`kernel.`** | カーネル全体（ホスト名、PID 上限、パニック時の挙動） |
| **`vm.`** | **メモリ管理**（スワップ、キャッシュ、OOM） |
| **`fs.`** | **ファイルシステム**（開けるファイル数、inotify） |
| **`net.`** | **ネットワーク**（`net.ipv4.` / `net.core.` / `net.bridge.`） |
| **`dev.`** | デバイス固有の設定 |

**値が複数並ぶ場合**

```text
  net.ipv4.tcp_mem = 190584  254112  381168
                       │       │        │
                    low で   pressure  high で
                  余裕あり    圧迫      上限
```

> 複数の数値が並ぶ項目は、**しきい値が並んでいる**ことがほとんどです。
> 意味は項目ごとに違うので、カーネルドキュメントで確認してください。

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| **`dmesg` が `Operation not permitted` で動かない** | **`kernel.dmesg_restrict = 1`** で一般ユーザに禁止されている | `sudo dmesg`、または `sudo sysctl -w kernel.dmesg_restrict=0` |
| **起動時のメッセージが `dmesg` に出てこない** | **リングバッファが一周して上書きされた** | **`journalctl -k -b`** を使う。`-b -1` で前回の起動 |
| **`dmesg` の時刻が実際とずれる** | `-T` の時刻は起動時刻からの計算。サスペンドをはさむとずれる | `journalctl -k` のタイムスタンプを見る |
| **`sysctl -w` で変えたのに再起動で戻る** | `-w` は**一時的な変更** | `/etc/sysctl.d/99-….conf` に書いて `sysctl --system` |
| **設定ファイルに書いたのに反映されない** | **書いただけでは適用されない** | `sudo sysctl --system` を実行する。書式は `項目名 = 値` |
| **`/etc/sysctl.conf` に書いたのに別の値になる** | **ほかの `sysctl.d` の設定が勝っている**…ことは通常ない（`sysctl.conf` が最後） | `sysctl --system` の出力で、どのファイルが何を設定したか確認する |
| **`sysctl: cannot stat /proc/sys/… : No such file`** | **その項目が存在しない**（機能が無効、モジュール未読込） | 関係するモジュールを `modprobe` する（例 `br_netfilter`） |
| **`sysctl -a` が一部エラーを出す** | 読み取り権限の無い項目がある | `sudo sysctl -a`、または `-e` でエラーを無視する |
| **`/proc` のファイルをエディタで編集できない** | 仮想ファイルなので**通常の編集はできない** | `echo 値 \| sudo tee /proc/sys/…`、または `sysctl -w` |
| **`ls -l /proc/…` のサイズが 0** | 実体を持たない仮想ファイル。**異常ではない** | `cat` で読めば中身は出る |
| **設定を変えたら不安定になった** | 意味を確認せずに値を変えた | 元の値に戻す。変更前に必ず `sysctl 項目名` で控えを取る |

## クラウド実務メモ

| 場面 | 何に効くか |
|:--|:--|
| **EC2 が突然遅くなった／プロセスが消えた** | **`dmesg -T \| grep -i "out of memory"`**。OOM Killer が動いたかを最初に確認する |
| **EBS の I/O エラー** | `dmesg -T -l err` に `I/O error, dev nvme0n1` が出る。ボリュームかインスタンスの問題かを切り分けられる |
| **インスタンス起動直後の障害** | コンソールのシステムログ（EC2 の Get System Log）は、**実質 `dmesg` の内容**。読み方は同じ |
| **Kubernetes ノードの前提設定** | `net.ipv4.ip_forward=1` と `net.bridge.bridge-nf-call-iptables=1` が必須。`/etc/sysctl.d/` に置き、`br_netfilter` も読み込む |
| **ファイルディスクリプタ不足** | `fs.file-max` と、プロセス単位の `ulimit -n` の**両方**を確認する |
| **DB インスタンスのチューニング** | `vm.swappiness` を小さくする、`vm.dirty_ratio` を調整する、などが定番 |
| **Ansible での設定管理** | `ansible.posix.sysctl` モジュールで、値の書き込みと `sysctl.d` への永続化を冪等に扱える |
| **コンテナ内から見た `/proc`** | **ホストのカーネルを共有している**ので、`sysctl` の多くはコンテナ内から変更できない。ホスト側か、`securityContext` での許可が必要 |
| **AMI の作り込み** | `sysctl.d` の設定を AMI に焼き込んでおくと、起動ごとの設定漏れを防げる |

**補足**

- クラウドのインスタンスは**再起動でメモリ上の情報が消える**ため、`dmesg` だけに頼らず、**CloudWatch Logs などへ `journald` の内容を転送しておく**のが安全です

```bash
$ journalctl -k -b -1 --no-pager > /tmp/prev-boot-kernel.log   # 前回起動時のカーネルログを保存する
```
