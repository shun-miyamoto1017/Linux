## 内側から見るか外側から見るか

**同じ「ポートが開いているか」でも、見る位置で分かることが違います。**

```text
   [サーバの中から]  netstat -l / ss -l
        → プロセスが待ち受けているか             （アプリの問題かが分かる）

   [ネットワーク越しに]  nmap / nc
        → 実際に外から届くか                     （経路とファイアウォールが分かる）
```

**この2つが食い違うとき、答えははっきりしています。**

| 中から見ると | 外から見ると | 原因 |
|:--|:--|:--|
| LISTEN している | 届かない | **ファイアウォール / セキュリティグループ / 経路** |
| LISTEN していない | 届かない | **アプリが起動していない、または別のポートで待っている** |
| `127.0.0.1:80` で LISTEN | 届かない | **ループバックにしかバインドしていない** |

3つ目は実務で非常によくあります。**`netstat -ln` の `Local Address` が `127.0.0.1` なのか `0.0.0.0` なのかを必ず見てください。**

## nmap とは

**`nmap` は、対象のポートへ順にパケットを送り、どれが待ち受けているかを一覧するコマンド**です。
構成が分からないネットワークの調査や、セキュリティ検査に使います。

---

## 書式と対象の指定

```text
nmap [スキャンタイプ] [オプション] 対象
```

**対象はホスト1台だけでなく、範囲でも指定できます。**

| 書き方 | 意味 |
|:--|:--|
| `192.168.1.10` | ホスト1台 |
| `example.com` | ホスト名でも指定できる |
| `192.168.1.0/24` | **CIDR 表記でネットワーク全体** |
| `192.168.1.1-254` | **ハイフンで範囲** |
| `192.168.0-255.1-254` | オクテットごとに範囲を書ける |

実測で確かめます。

```bash
$ nmap -sn 127.0.0.1-3 | grep -c "Nmap scan report"   # 3台ぶんスキャンされるか数える
```

```text
3
```

**3 台として解釈されました。**

## 結果画面の見方

```bash
$ nmap 127.0.0.1                            # 既定のスキャンを実行する
```

```text
Starting Nmap 7.94SVN ( https://nmap.org ) at 2026-09-23 15:44 UTC
Nmap scan report for localhost (127.0.0.1)
Host is up (0.0000020s latency).
Not shown: 997 closed tcp ports (reset)
PORT    STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https

Nmap done: 1 IP address (1 host up) scanned in 0.07 seconds
```

| 行 | 意味 |
|:--|:--|
| `Host is up` | **対象が応答した**（latency は往復時間） |
| **`Not shown: 997 closed tcp ports`** | **表示を省いたポートの数と、その状態** |
| `PORT` | **ポート番号 / プロトコル** |
| `STATE` | **`open` / `closed` / `filtered`** |
| `SERVICE` | ポート番号から推定したサービス名（`/etc/services` 由来） |

**`STATE` の3つの違いが最も重要**です。

```text
   open      … 応答があり、待ち受けている          （SYN に SYN+ACK が返った）
   closed    … 応答はあるが、待ち受けていない      （SYN に RST が返った）
   filtered  … 応答そのものが無い                  （途中で落とされている）
```

**`closed` と `filtered` を区別できるのが nmap の価値**です。

```text
   closed   → 相手のホストまでは届いている。アプリが起動していない
   filtered → 途中のファイアウォール / セキュリティグループで落ちている
```

**既定では上位 1000 ポートだけを調べます。** 実測で確かめます。

```bash
$ nmap 127.0.0.1 | grep "Not shown"         # 既定で何ポート調べるか
$ nmap -F 127.0.0.1 | grep "Not shown"      # -F では何ポートか
```

```text
Not shown: 997 closed tcp ports (reset)
Not shown: 97 closed tcp ports (reset)
```

開いていた 3 ポート（22 / 80 / 443）を足すと、**既定は 1000 ポート、`-F` は 100 ポート**です。

## スキャンタイプ

### 既定は実行ユーザで変わる

**スキャンタイプを省略したときの既定は、root かどうかで変わります。** これは見落としやすい点です。

```bash
$ nmap -d 127.0.0.1 -p 80 | grep -i "Initiating.*Scan"   # root で実行した場合
```

```text
Initiating SYN Stealth Scan at 15:44
```

```bash
$ su tu -c 'nmap -d 127.0.0.1 -p 80' | grep -i "Initiating.*Scan"   # 一般ユーザで実行した場合
```

```text
Initiating Ping Scan at 15:44
Initiating Connect Scan at 15:44
```

```text
   root で実行      → SYN スキャン（-sS 相当）。生パケットを作るので root が要る
   一般ユーザで実行 → Connect スキャン（-sT 相当）に自動で落ちる
```

**「既定は SYN スキャン」は root 前提の話**です。
一般ユーザで実行して結果が違うときは、まずここを疑ってください。

### 主なスキャンタイプ

| 指定 | 名前 | 内容 |
|:--|:--|:--|
| **`-sS`** | SYN スキャン | SYN だけ送って応答を見る。**接続を完了させないので速く、ログに残りにくい**。root が必要 |
| **`-sT`** | TCP 接続スキャン | **実際に接続を確立する**。一般ユーザでも使えるが遅く、相手のログに残る |
| **`-sU`** | UDP スキャン | UDP ポートを調べる。**非常に遅い** |
| **`-sn`** | Ping スキャン | **ポートは調べず、ホストが生きているかだけ**を見る（旧 `-sP`） |
| `-sA` | ACK スキャン | ファイアウォールのルールを推定する |

**`-sP` は古い書き方**で、現在は `-sn` です。nmap 7.x では `-sP` も互換のため受け付けます。

```bash
$ nmap -h | grep -- '-sn'                   # ヘルプでの表記を確認する
```

```text
  -sn: Ping Scan - disable port scan
  nmap -v -sn 192.168.0.0/16 10.0.0.0/8
```

（2 行目は EXAMPLES の行が引っかかったものです）

## ポートを絞る

| オプション | 意味 |
|:--|:--|
| **`-p ポート`** | **調べるポートを指定する**（`-p 80`、`-p 20-25`、`-p 22,80,443`） |
| `-p-` | **全 65535 ポート**を調べる（時間がかかる） |
| **`-F`** | **有名ポート 100 個だけ**を調べる（高速スキャン） |
| `--open` | 開いているポートだけを表示する |

```bash
$ nmap -p 80 127.0.0.1 | sed -n '4,6p'      # 1つのポートだけ調べる
```

```text
PORT   STATE SERVICE
80/tcp open  http
```

```bash
$ nmap -p 20-25 127.0.0.1 | sed -n '4,11p'  # ポートの範囲を調べる
```

```text
PORT   STATE  SERVICE
20/tcp closed ftp-data
21/tcp closed ftp
22/tcp open   ssh
23/tcp closed telnet
24/tcp closed priv-mail
25/tcp closed smtp
```

**書式の注意**

```text
   ○ nmap -p 80 192.168.1.10
   ✗ nmap 192.168.1.10:80      …  Failed to resolve "192.168.1.10:80". で失敗する
   ✗ nmap 192.168.1.10 80      …  80 が 別のホスト として追加スキャンされる
```

**2 つ目は「効かない」だけでは済みません。** 実測します。

```bash
$ nmap -sL 127.0.0.1 80                     # 実際には送信せず対象だけ一覧する
```

```text
Nmap scan report for localhost (127.0.0.1)
Nmap scan report for 80 (0.0.0.80)
Nmap done: 2 IP addresses (0 hosts up) scanned in 0.00 seconds
```

**`80` が `0.0.0.80` というホストとして解釈されました。**
意図しない相手をスキャンしてしまうので、**`-p` は必ず付けてください。**

**TCP ポートを調べるだけなら、スキャンタイプの指定は要りません。**
既定が TCP を使うスキャンだからです。

## OS を推定する

**`-O` は、応答パケットの癖から OS の種類を推定**します。

```bash
$ nmap -O 127.0.0.1 | sed -n '3,10p'        # OS の推定を試みる
```

```text
Host is up (0.000062s latency).
Not shown: 997 closed tcp ports (reset)
PORT    STATE SERVICE
22/tcp  open  ssh
80/tcp  open  http
443/tcp open  https
No exact OS matches for host (If you know what OS is running on it, see https://nmap.org/submit/ ).
TCP/IP fingerprint:
OS:SCAN(V=7.94SVN%E=4%D=9/23%OT=22%CT=1%CU=43596%PV=N%DS=0%DC=L%G=Y%TM=6AB3
```

**`No exact OS matches for host` — 必ず特定できるとは限りません。**
開いているポートが少ない、ファイアウォールが挟まっている、といった条件では推定が外れます。
**`-O` の結果は「参考値」として扱ってください。**

`-O` も生パケットを作るため **root 権限が必要**です。

| オプション | 意味 |
|:--|:--|
| `-O` | OS を推定する |
| `-sV` | **サービスのバージョン**を推定する（バナーを読む） |
| `-A` | `-O` と `-sV` などをまとめて有効にする |
| `-n` | 名前解決をしない |
| `-v` / `-vv` | 詳細に表示する |
| `-oN ファイル` | 結果をテキストで保存する |

## nc とは

**`nc`（netcat）は、TCP / UDP で「とりあえず繋いでみる」ためのコマンド**です。
「ネットワークの十徳ナイフ」と呼ばれます。

```text
nc [オプション] ホスト ポート
```

### ポートが開いているか調べる

**`-z`（接続だけ試してデータを送らない）と `-v`（結果を表示）**の組み合わせが定番です。

```bash
$ nc -zv 127.0.0.1 20-25                    # ポート範囲への接続を試す
```

```text
nc: connect to 127.0.0.1 port 20 (tcp) failed: Connection refused
nc: connect to 127.0.0.1 port 21 (tcp) failed: Connection refused
Connection to 127.0.0.1 22 port [tcp/ssh] succeeded!
nc: connect to 127.0.0.1 port 23 (tcp) failed: Connection refused
nc: connect to 127.0.0.1 port 24 (tcp) failed: Connection refused
nc: connect to 127.0.0.1 port 25 (tcp) failed: Connection refused
```

**`succeeded!` が開いているポート**です。**ポートはハイフンで範囲指定できます。**

```text
   Connection refused   … 相手まで届いたが待ち受けていない  （nmap の closed に相当）
   （何も返らず固まる）  … 途中で落とされている              （nmap の filtered に相当）
```

**固まる場合は `-w` でタイムアウトを付けてください。**

```bash
$ nc -zv -w 3 10.0.0.5 3306                 # 3秒で諦める
```

### データを送る

**`-z` を付けなければ、標準入力の内容がそのまま相手へ流れます。**

```bash
$ (nc -l 127.0.0.1 7777 > recv.txt &)       # 受信側を用意する
$ echo "hello from client" | nc -q1 127.0.0.1 7777   # パイプで送る
$ cat recv.txt                              # 受信内容を確認する
```

```text
hello from client
```

**HTTP を手で話すこともできます。**

```bash
$ printf 'GET / HTTP/1.0\r\n\r\n' | nc example.com 80   # HTTP リクエストを直接送る
```

**telnet の代わりに使えます。** telnet が入っていない環境でも `nc` はたいてい使えます。

### 待ち受け側になる

**`-l` を付けると、`nc` 自身が待ち受けになります。**

```bash
$ nc -l 8080                                # 8080 番で待ち受ける
```

**疎通確認の相手役として非常に便利**です。

```text
  [サーバ側]  nc -l 8080            … とりあえず 8080 を開けておく
  [手元から]  nc -zv サーバ 8080    … 経路とファイアウォールだけを試験する
```

**アプリを起動しなくても、経路とファイアウォールだけを切り分けられます。**
セキュリティグループを直したときの確認に、この組み合わせをよく使います。

| オプション | 意味 |
|:--|:--|
| **`-l`** | **待ち受けモード**になる |
| **`-z`** | 接続を試すだけでデータを送らない |
| **`-v`** | 結果を表示する |
| `-w 秒` | 接続のタイムアウト |
| `-u` | **UDP** を使う（既定は TCP） |
| `-p ポート` | 送信元ポートを指定する |
| `-4` / `-6` | IPv4 / IPv6 を明示する |

> **実装差に注意** … `nc` には OpenBSD 版、GNU 版、Nmap 付属の `ncat` があり、
> **オプションが微妙に違います。** 検証環境は OpenBSD 版でした。
> ```text
> $ nc -h
> OpenBSD netcat (Debian patchlevel 1.226-1ubuntu2)
> ```
> `-q` や `-e` は版によって有無が変わるので、**手元で `nc -h` を確認**してください。

## ネットワーク調査コマンドの整理

**どれも「ネットワークを調べる」ですが、見ているものが違います。**

| コマンド | 何を見るか | 位置 |
|:--|:--|:--|
| **`ping`** | 相手に届くか（ICMP） | 外から |
| **`traceroute`** | どの経路を通るか | 外から |
| **`mtr`** | 経路＋各ホップのロス率と遅延を継続測定 | 外から |
| **`nmap`** | どのポートが開いているか | 外から |
| **`nc`** | 特定のポートに繋がるか、データが流れるか | 外から |
| **`tcpdump`** | 実際に流れているパケット | インタフェース上 |
| **`netstat` / `ss`** | 自ホストの接続・待ち受け・統計 | 中から |
| **`arp`** | IP と MAC の対応（ARP キャッシュ） | 中から |
| **`dig` / `nslookup`** | 名前解決の結果 | DNS へ |

**切り分けの順番**

```text
  1. ping          … そもそも相手に届くか
  2. traceroute    … 届かないなら、どこまで行っているか
  3. nc / nmap     … 届くなら、そのポートが開いているか
  4. tcpdump       … 開いているはずなのに繋がらないなら、パケットを直接見る
  5. netstat / ss  … 相手側にログインできるなら、待ち受けているか確認する
```

## 使ってよい相手とよくない相手

**ポートスキャンは強力なので、扱いには注意が必要です。**

```text
  ○ 自分が管理しているホスト
  ○ 検証環境
  ○ 依頼を受けて実施するセキュリティ検査（書面で合意があるもの）

  ✗ 他人が管理しているホスト
  ✗ クラウド事業者の許可を取っていない大規模スキャン
  ✗ 「気になったから」で外部サイトを試すこと
```

**無断のポートスキャンは攻撃の準備行為とみなされます。**
IDS / IPS に検知され、通報や接続遮断につながることもあります。

**`tcpdump` も同様**です。他人の通信が見えてしまうため、
本番環境で取ったキャプチャの扱い（保存先・共有範囲・保持期間）は事前に決めておいてください。

**実務での安全な進め方**

```text
  1. 対象と範囲を書面で確認する（IP、ポート、実施時間帯）
  2. 関係者へ事前に予告する（監視チームが誤検知で騒がない）
  3. -F や -p で範囲を絞り、-p- のフルスキャンは必要なときだけ
  4. 結果を -oN で保存し、いつ何を実施したか記録に残す
```
