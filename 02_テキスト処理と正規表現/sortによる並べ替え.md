## sortとは

**`sort` は行単位でファイルの内容をソートするコマンド**です。

```text
sort [オプション] [ファイル名]
```

**ファイル名を省略すると標準入力から読みます。** パイプの途中に置けます。

**「行単位」がポイント**です。行の中身を並べ替えるのではなく、**行そのものの順番**を変えます。

```text
   入力            sort の結果
   20              1
   100             100        ← 数値順ではない（後述）
   1               11
   11              20
```

---

## よく使うオプション

**`sort` コマンドの書式と主なオプションは以下のとおり**です。

| オプション | 説明 |
|:--|:--|
| **`-t 区切り文字`** | **指定した文字を区切り文字としてフィールドを認識** |
| **`-n`** | **数字を文字でなく数値としてソート** |
| **`-k フィールド`** | **ソート対象とするフィールドを指定**（デフォルトは1つ目のフィールド） |

**この 3 つが試験の中心**です。実務では次も合わせて使います。

| そのほかのオプション | 説明 |
|:--|:--|
| **`-r`** | **逆順**にする（reverse） |
| **`-u`** | **重複を取り除く**（unique） |
| **`-f`** | **大文字と小文字を区別しない**（fold） |
| **`-o ファイル`** | **結果をファイルに書き出す**（入力と同じファイルを指定できる） |
| **`-h`** | **`1K` `2M` のような人間向け表記**を数値として扱う |
| **`-M`** | **月名**（`Jan` `Feb` …）として並べ替える |
| **`-b`** | 先頭の空白を無視する |
| **`-c`** | **ソート済みかどうかを検査する**（並べ替えはしない） |
| `-V` | バージョン番号として並べ替える（`1.10` が `1.9` の後になる） |
| `-z` | 行の区切りを NUL にする（ファイル名に改行が含まれる場合） |

## 文字としてのソートと数値としてのソート

**ここが最初のつまずきどころ**です。

**`sort` の既定は「文字としてのソート」**です。数字も 1 文字ずつ比較します。

```bash
$ cat FileA                           # 確認用のファイル
20
100
1
11

$ sort FileA                          # 既定は、数字も文字としてソート
1
100                                   ← 左端の文字が1、次の文字が0のためこの位置になる
11
20

$ sort -n FileA                       # -n で数値としてソートする
1
11
20
100
```

**なぜ `100` が `11` より前に来るのか。** 文字として 1 文字ずつ比べているためです。

```text
   1     1
   100   1 → 0        ← 2文字目で「0 < 1」なので 11 より前
   11    1 → 1
   20    2
```

**数値を扱うときは必ず `-n`** を付けてください。
ファイルサイズ、行数、PID、ポート番号——業務で並べ替えたいものはほぼ数値です。

**逆順は `-r`** です。`-n` と組み合わせるのが定番になります。

```bash
$ sort -rn FileA                      # 数値として大きい順に並べる
100
20
11
1
```

**`-rn`（または `-nr`）は「多い順」の定番**です。集計結果を上位から見るときに使います。

## フィールドを指定して並べ替える

**既定では行の先頭から比較します。** 特定の列で並べたいときは `-k` を使います。

```bash
$ cat f.txt                           # 確認用のファイル（空白区切り）
3 banana
1 apple
2 cherry

$ sort f.txt                          # 既定は1つ目のフィールド（数字）で並ぶ
1 apple
2 cherry
3 banana

$ sort -k2 f.txt                      # 2つ目のフィールド（果物名）で並べる
1 apple
3 banana
2 cherry
```

**フィールド番号は 1 から数えます。** 0 ではありません。

**`-k` には範囲も指定できます。**

| 書き方 | 意味 |
|:--|:--|
| **`-k2`** | **2 番目のフィールドから行末まで**を比較する |
| **`-k2,2`** | **2 番目のフィールドだけ**を比較する |
| `-k2,3` | 2 番目から 3 番目のフィールドを比較する |
| `-k2 -k1` | 2 番目で並べ、同点なら 1 番目で並べる |
| `-k2,2n` | 2 番目のフィールドだけを**数値として**比較する |

**`-k2` と `-k2,2` は違います。**
`-k2` は「2 番目以降すべて」なので、意図しない列まで比較に入ることがあります。
**確実にやるなら `-k2,2` と終わりを明示**してください。

### 区切り文字を指定する

**既定の区切りは「空白の並び」**です。
CSV のようにカンマ区切りなら `-t` で指定します。

```bash
$ cat FileB                           # 「,」で区切られたファイル
aaa,200 ,AAA
bbb,1000,ddd
ccc,30  ,bbb
ddd,4   ,CCC

$ LC_ALL=C sort -k 3 -t , FileB       # 3番目のフィールドを基準にソートする
aaa,200 ,AAA
ddd,4   ,CCC
ccc,30  ,bbb
bbb,1000,ddd
```

**3 列目が `AAA` `CCC` `bbb` `ddd` の順**になっています。
大文字が小文字より先に来るのは、**文字コード順（ASCII 順）**だからです。

```text
   A(65) … Z(90)  <  a(97) … z(122)
```

**重要 … この並びは `LC_ALL=C` を付けたからこそ得られます。**

**`LC_ALL=C` を外すと結果が変わります。**

```bash
$ LC_ALL=en_US.UTF-8 sort -k 3 -t , FileB   # 英語ロケールで同じことをする
aaa,200 ,AAA
ccc,30  ,bbb
ddd,4   ,CCC
bbb,1000,ddd
```

**`AAA` `bbb` `CCC` `ddd` の順**、つまり **大文字小文字を区別せず、
アルファベット順に並びました**（実測）。

**「大文字が先」は ASCII 順（C ロケール）のときの話**であって、
`sort` の普遍的な動きではありません。
この章の例はすべて **`LC_ALL=C` を前提**にしています。
詳しくはこのノート末尾の「並び順はロケールで変わります」を見てください。

**区切り文字（`-t`）・列番号（`-k`）・数値扱い（`-n`）は組み合わせて使えます。**

```bash
$ sort -t: -k3 -n /etc/passwd | head -3    # UID 順にユーザを並べる
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
```

**`/etc/passwd` を UID 順に見る**のは、アカウント棚卸しの定番です。

## そのほかの並べ替え方

**`-h` は `1K` `2M` のような単位付きの数値**を正しく並べます。

```bash
$ printf '1K\n1M\n500\n2G\n' | sort -h     # 人間向け表記を数値として扱う
500
1K
1M
2G
```

**`du -h` の結果を並べるとき**に必須です。`-n` では `1K` と `1M` を区別できません。

```bash
$ du -h /var/log/* | sort -h | tail -5     # 大きいものを5つ表示する
```

**`-M` は月名**として並べます。

```bash
$ printf 'Mar\nJan\nFeb\n' | sort -M       # 月名の順に並べる
Jan
Feb
Mar
```

**`-o` は結果を書き出すファイルを指定**します。

```bash
$ sort -o out.txt f.txt               # 結果を out.txt に書き出す
$ sort -o f.txt f.txt                 # 入力と同じファイルを指定してもよい
```

**`sort file > file` は動きません。**
リダイレクトが先にファイルを空にしてしまうためです
（[標準入出力とリダイレクト](../01_シェルとコマンドライン/標準入出力とリダイレクト.md)）。
**同じファイルに書き戻すときは `-o` を使ってください。**

**`-c` はソート済みかどうかを検査**します。並べ替えはしません。

```bash
$ sort -c f.txt                       # ソート済みかどうかを検査する
sort: f.txt:2: disorder: 1 apple      # 2行目で順序が崩れている
```

**終了ステータスは、ソート済みなら 0、崩れていたら 1** です。

## uniqと組み合わせる

**`uniq` は連続した重複行をまとめるコマンド**です。
**`sort` とセットで使う**のが前提になっています。

```text
uniq [オプション] [入力ファイル [出力ファイル]]
```

```bash
$ cat u.txt                           # 確認用のファイル
a
a
b
b
b
c

$ uniq u.txt                          # 連続した重複をまとめる
a
b
c
```

**補足 … 出力先をファイルで指定できます**

**引数を 2 つ取れる**のが `uniq` の特徴です。
**2 つ目を書くと、結果は画面ではなくそのファイルへ出力**されます。

```bash
$ uniq u.txt newfile                  # 結果を newfile へ書き出す
$ echo $?                             # 画面には何も出ない
0
$ cat newfile                         # 中身を確かめる
a
b
c
```

**`uniq u.txt > newfile` とリダイレクトするのと同じ結果**になりますが、
**試験では「第2引数に出力ファイルを書く」形が正解として問われます。**
`grep` や `sed` にこの書き方は無いので、**`uniq` だけの例外**として覚えてください。

**注意 … `sort` は同じ書き方をしません。**

```bash
$ sort u.txt newfile                  # 2つ目も「入力」として読まれる
sort: cannot read: newfile: No such file or directory
$ echo $?                             # 終了ステータスは 2
2
```

**`sort` で出力先を指定するのは `-o`** です（前述）。
**`sort ファイルA ファイルB` は「2 つをまとめて並べ替える」**という意味になります。

**注意 … 入力と出力に同じファイルを書かないでください。**

```bash
$ printf 'a\na\nb\n' > z.txt          # 確認用のファイル
$ uniq z.txt z.txt                    # 入力と出力を同じにしてしまう
$ echo $?                             # エラーにならない
0
$ cat z.txt                           # 中身が消えている
$ wc -c z.txt                         # 0バイトになっている
0 z.txt
```

**`uniq` は読む前に出力ファイルを空にする**ので、**中身が全部消えます**（実測）。
`sort` は `-o` で同じファイルを指定しても壊れませんが、**`uniq` は壊れます。**

### uniq のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-c`** | **各行が何回出てきたかを数える**（count） |
| **`-d`** | **重複した行だけ**を表示する（duplicate） |
| **`-u`** | **重複していない行だけ**を表示する（unique） |
| `-i` | 大文字小文字を区別しない |
| `-f n` | 先頭 n 個のフィールドを無視して比較する |
| `-s n` | 先頭 n 文字を無視して比較する |

```bash
$ uniq -c u.txt                       # 出現回数を数える
      2 a
      3 b
      1 c

$ uniq -d u.txt                       # 2回以上出てきた行だけ
a
b

$ uniq -u u.txt                       # 1回しか出てこない行だけ
c
```

### なぜ sort が先に必要なのか

**`uniq` が見るのは「隣り合った行」だけ**です。離れていると重複と判定しません。

```bash
$ printf 'a\nb\na\n' | uniq           # a が離れているのでまとめられない
a
b
a
```

```text
   uniq が見ているのは、この「隣同士」だけ
     a  ┐
     b  ┘ 違う → 残す
     b  ┐
     a  ┘ 違う → 残す
```

**そのため `sort` で同じ値を隣に集めてから `uniq` に渡します。**

```bash
$ printf 'a\nb\na\n' | sort | uniq -c      # 並べ替えてから数える
      2 a
      1 b
```

**`sort -u` と `sort | uniq` の違い**

| 書き方 | できること |
|:--|:--|
| **`sort -u`** | **重複を消す**だけ（速い） |
| **`sort \| uniq`** | 重複を消す（`sort -u` と同じ結果） |
| **`sort \| uniq -c`** | **回数を数えられる**（`sort -u` ではできない） |
| **`sort \| uniq -d`** | **重複したものだけ**を取り出せる |

**単に重複を消すだけなら `sort -u`**、
**数えたり絞ったりするなら `sort | uniq -c`** と使い分けます。

## 似ているコマンドとの違い

**Ping-t では「行単位でソートするコマンドはどれか」という形で、
似た名前のコマンドと並べて問われます。**

| コマンド | 何をするか |
|:--|:--|
| **`sort`** | **行単位でファイルの内容をソートする** |
| **`head`** | **ファイルの先頭数行を表示する** |
| **`tail`** | ファイルの末尾数行を表示する |
| **`nl`** | **ファイルの内容に行番号をつけて表示する** |
| **`cut`** | **テキストファイルの各行から指定したフィールドを取り出して表示する** |
| **`fmt`** | **1行あたりの最大文字数を指定してテキストを整形する** |
| `tr` | 文字を置き換える・削除する |
| `wc` | 行数・単語数・バイト数を数える |
| `uniq` | 連続した重複行をまとめる |
| `paste` | 複数ファイルを列方向に連結する |
| `join` | 共通のフィールドで2つのファイルを結合する |

**`cut` と `sort -k` は対になります。**
`cut` が「列を取り出す」、`sort -k` が「列で並べる」です。

```bash
$ cut -d: -f1 /etc/passwd | sort      # ユーザ名だけ取り出して並べる
```

これらの詳細は [パイプとフィルタ](../01_シェルとコマンドライン/パイプとフィルタ.md) と
[ファイルの内容を見るコマンド](../01_シェルとコマンドライン/ファイルの内容を見るコマンド.md) にまとめています。

## 実務での組み合わせ

| やりたいこと | コマンド |
|:--|:--|
| **アクセス元IPを多い順に** | `awk '{print $1}' access.log \| sort \| uniq -c \| sort -rn \| head` |
| **ログの時間帯別件数** | `cut -c1-13 app.log \| sort \| uniq -c` |
| **大きいディレクトリを探す** | `du -h --max-depth=1 /var \| sort -h \| tail` |
| **UID順にユーザを見る** | `sort -t: -k3 -n /etc/passwd` |
| **2つのファイルの差を見る** | `sort a.txt > a.s; sort b.txt > b.s; comm -3 a.s b.s` |
| **重複したファイル名を探す** | `find . -type f -printf '%f\n' \| sort \| uniq -d` |

**1つ目の組み合わせは頻出**なので、部品ごとに分解します。

| 部品 | やっていること |
|:--|:--|
| `awk '{print $1}'` | 各行の**1列目（IPアドレス）だけ**を取り出す |
| `sort` | **同じIPを隣り合わせる**（`uniq` の前提） |
| `uniq -c` | **同じIPが何回出たか**を数える |
| `sort -rn` | **件数の多い順**に並べ替える |
| `head` | **上位だけ**を表示する |

**`sort` が 2 回出てくる**のがポイントです。
**1 回目は `uniq` のための整列、2 回目は件数での並べ替え**で、役割がまったく違います。

**補足 … 巨大なファイルではメモリと一時領域に注意してください**

`sort` は**全行をメモリに読み込んでから**並べ替えます。
入りきらない場合は `/tmp` に一時ファイルを作るため、
**`/tmp` が小さいサーバでは失敗**することがあります。

```bash
$ sort -T /var/tmp huge.log           # 一時ファイルの置き場所を変える
$ sort -S 1G huge.log                 # 使うメモリの上限を指定する
```

**補足 … 並び順はロケールで変わります**

`sort` の比較順は `LC_COLLATE` に従います。
**スクリプトで安定した結果が欲しいときは `LC_ALL=C` を設定してください。**

```bash
$ LC_ALL=C sort file.txt              # 文字コード順で安定して並べる
```

**違いは実際に確認できます。**

```bash
$ cat case.txt                        # 確認用のファイル
AAA
bbb
CCC
ddd
$ LC_ALL=C sort case.txt              # ASCII 順 … 大文字が先にまとまる
AAA
CCC
bbb
ddd
$ LC_ALL=en_US.UTF-8 sort case.txt    # 英語ロケール … 大文字小文字を区別しない
AAA
bbb
CCC
ddd
```

**同じコマンド・同じファイルでも、ロケールが違えば結果が違います。**
**手順書に `sort` の出力例を載せるときは、`LC_ALL=C` を明示**してください。

これはコマンド前置でも効きます（`sort` 自身が環境変数を読むため）。
シェルのパス名展開とは事情が違う点に注意してください
（[パス名展開とワイルドカード](../01_シェルとコマンドライン/パス名展開とワイルドカード.md)）。
