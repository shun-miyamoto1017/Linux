## 正規表現とは何か

**正規表現とは、文字列の特定のパターンを認識するために使用する表現方法**です。
**文字列の検索や置換などを行う際に利用します。**

```text
   「エラーを含む行」        → error
   「行頭が # の行」          → ^#
   「.log で終わるファイル名」 → \.log$
   「数字が3つ続く箇所」       → [0-9][0-9][0-9]
```

**「ある1文字」ではなく「こういう形の文字列」を指定できる**のが正規表現です。

## 基本正規表現と拡張正規表現

**正規表現には 2 つの種類があります。** ここを混同すると「書いたのにマッチしない」が起きます。

| 種類 | 略称 | 正式名称 |
|:--|:--|:--|
| **基本正規表現** | **BRE** | Basic Regular Expression |
| **拡張正規表現** | **ERE** | Extended Regular Expression |

**違いは「どの記号が特別扱いされるか」だけ**です。

| 記号 | BRE での扱い | ERE での扱い |
|:-:|:--|:--|
| **`+`** | **ただの文字** | **繰り返しの指定** |
| **`?`** | **ただの文字** | **繰り返しの指定** |
| **`\|`**（縦棒） | **ただの文字** | **「または」** |
| `( )` | ただの文字 | グループ化 |
| `{ }` | ただの文字 | 回数の指定 |

**BRE でこれらを使いたいときは、バックスラッシュでエスケープします。**

```text
   ERE:   a+          BRE:   a\+
   ERE:   windows?    BRE:   windows\?
   ERE:   abc|xyz     BRE:   abc\|xyz
   ERE:   a{2}        BRE:   a\{2\}
```

**BRE と ERE で `\` の意味が逆**になる、と覚えると分かりやすいです。

| | 特別な意味にしたいとき | ただの文字にしたいとき |
|:--|:--|:--|
| **BRE** | **`\` を付ける**（`a\+`） | そのまま書く（`a+`） |
| **ERE** | そのまま書く（`a+`） | **`\` を付ける**（`a\+`） |

**どちらが使われるかはコマンドで決まります。**

| コマンド | 既定 | 拡張正規表現にするには |
|:--|:--|:--|
| **`grep`** | **BRE** | **`-E`**（または `egrep`） |
| `sed` | BRE | `-E` または `-r` |
| `awk` | **ERE** | — |
| `pgrep` / `pkill` | **ERE** | — |
| `find -regex` | **Emacs 正規表現**（BRE ではない） | `-regextype` で変更 |

**補足 … `find -regex` だけは仲間外れです**

GNU find の `-regex` は **既定が Emacs 正規表現**で、BRE でも ERE でもありません。
**見た目は ERE に近く、`+` や `?` や `|` がバックスラッシュなしで使えます。**

```bash
$ ls ft                               # 確認用のディレクトリ
aaa  b
$ find ft -regex '.*a+'               # 既定（Emacs）… + がそのまま効く
ft/aaa
$ find ft -regextype posix-basic -regex '.*a+'   # BRE にすると + は「文字の +」
$ echo $?                             # 0 だが、1件も出ていない
0
```

**`-regex` は「パスの一部」ではなく「パス全体」に一致させる**点にも注意してください。
そのため先頭に `.*` を付けています。

## 記号の一覧

**以下は主な正規表現とその使用例をまとめたもの**です。

| 記号 | 説明 | 使用例（一致する文字） |
|:-:|:--|:--|
| **`.`** | **任意の1文字** | `a..` … a から始まる3文字（`aaa` `abc` など） |
| **`*`** | **直前の文字の0回以上の繰り返し** | `.*` … 任意の文字列 |
| **`[ ]`** | **`[ ]` 内のいずれか1文字**<br>`[ ]` 内では、以下の表現と併用可能<br>　`-` 範囲指定<br>　`^` 先頭にある場合は後続の文字以外 | `[abc]` … a,b,c のどれか1文字<br>`[a-z]` … 小文字のアルファベット1文字<br>`[^abc]` … a,b,c 以外のどれか1文字 |
| **`^`** | **行頭** | `^a` … a から始まる行 |
| **`$`** | **行末** | `a$` … a で終わる行 |
| **`\`** | **次の1文字をエスケープ**（通常の文字として処理） | `\*` … `*` という文字 |
| **`+`** | **直前の文字の1回以上の繰り返し**【拡張正規表現】 | `a+` … a を1回以上繰り返す文字列（`a` `aa` `aaa` など） |
| **`?`** | **直前の文字の0回もしくは1回の繰り返し**【拡張正規表現】 | `windows?` … windows の s が0または1文字（`window` `windows`） |
| **`\|`**（縦棒） | **左右いずれかの文字列**【拡張正規表現】 | `abc\|xyz` … abc または xyz |

## 一文字ずつ確認する

確認に使うファイルはこれです。

```bash
$ cat re.txt                          # 確認用のファイルを見る
aaa
abc
bbb
Abc
a-z
```

### 任意の1文字

**`.`（ピリオド）は「何でもいい1文字」**です。

```bash
$ grep 'a..' re.txt                   # a のあとに任意の2文字が続く行を探す
aaa
abc
a-z
```

**`bbb` と `Abc` が出ていない**点に注目してください。
`bbb` には `a` がなく、`Abc` の `A` は大文字なので `a` と一致しません。

**`.` は「1文字」であって「0文字以上」ではありません。** `a.` は `a` 単独にはマッチしません。

### 直前の文字の繰り返し

```bash
$ cat rep.txt                         # 確認用のファイル
a
aa
aaa
b
```

**`*` は「直前の文字の 0 回以上」**です。**0 回でもよい**のがポイントです。

```bash
$ grep 'a*b' rep.txt                  # a が0回以上続いたあとに b がある行
b
```

**`b` だけの行がマッチしています。** `a` が 0 回でも条件を満たすためです。
**「`*` は、直前の文字が無くても成立する」**——ここが最もよく誤解される点です。

**`+` は「1 回以上」**なので、0 回は許しません。**拡張正規表現なので `-E` が要ります。**

```bash
$ grep -E '^a+$' rep.txt              # a だけが1回以上続く行（-E で拡張正規表現）
a
aa
aaa
```

**`-E` を付けないと `+` はただの文字になります。**

```bash
$ cat words.txt                       # 確認用のファイル（hair air car wear beer の5行）
hair
air
car
wear
beer

$ grep '^.+[ie]r$' words.txt          # BRE なので + が「+ という文字」になる
                                      # 1件もマッチせず、終了ステータスは 1
$ grep -E '^.+[ie]r$' words.txt       # -E で拡張正規表現として扱う
hair
air
beer
$ grep '^.\+[ie]r$' words.txt         # BRE のまま \+ とエスケープしても同じ結果になる
hair
air
beer
```

**回数を数字で指定する書き方**もあります。

| 書き方（ERE） | 書き方（BRE） | 意味 |
|:--|:--|:--|
| `a{2}` | `a\{2\}` | **ちょうど2回** |
| `a{2,}` | `a\{2,\}` | **2回以上** |
| `a{2,4}` | `a\{2,4\}` | **2回以上4回以下** |

```bash
$ grep -E '^a{2}$' rep.txt            # a がちょうど2個の行（拡張正規表現）
aa
$ grep '^a\{2\}$' rep.txt             # 同じ内容を基本正規表現で書く
aa
```

### 文字クラス

**`[ ]` は「この中のどれか1文字」**です。

```bash
$ grep '[^abc]' re.txt                # a,b,c 以外の文字を含む行を探す
Abc
a-z
```

**`[^abc]` は「a,b,c 以外の文字が1文字でもある行」**です。
`Abc` は大文字の `A` が該当し、`a-z` は `-` と `z` が該当します。

**`[ ]` の中と外で `^` の意味が変わります。**

| 位置 | 意味 |
|:--|:--|
| **`[ ]` の外の `^`** | **行頭** |
| **`[ ]` の先頭の `^`** | **否定**（後続の文字以外） |
| `[ ]` の先頭以外の `^` | ただの `^` という文字 |

**`-` も同じく、位置で意味が変わります。**

```bash
$ grep 'a-z' re.txt                   # [ ] の外なので、a-z という3文字を探す
a-z
```

```text
   [a-z]   →  [ ] の中の -   … 「a から z のどれか1文字」という範囲指定
    a-z    →  [ ] の外の -   … 「a」「-」「z」という3文字そのもの
```

### アンカー

**`^` と `$` は「位置」を表します。** 文字にはマッチしません。

```bash
$ grep '^a' re.txt                    # 行頭が a の行
aaa
abc
a-z

$ grep 'c$' re.txt                    # 行末が c の行
abc
Abc
```

**`^` と `$` を両方書くと「行全体が一致」**という意味になります。

```text
   grep 'abc'      →  abc を「含む」行（xxabcyy もマッチ）
   grep '^abc$'    →  abc 「だけ」の行
```

**設定ファイルで「有効な行だけ見たい」ときの定番**がこれです。

```bash
$ grep -v '^#' httpd.conf | grep -v '^$'   # コメント行と空行を除く
```

`^$` は「行頭のすぐ後ろが行末」＝**空行**を表します。

### エスケープ

**記号そのものを探したいときは `\` を前に付けます。**

```bash
$ cat star.txt                        # 確認用のファイル
a*b
ab

$ grep '\*' star.txt                  # 「*」という文字を含む行を探す
a*b
```

**`\` を付けないと `*` は「繰り返し」として解釈**されます。

| 書きたいもの | 正規表現 |
|:--|:--|
| `.` という文字 | **`\.`** |
| `*` という文字 | **`\*`** |
| `$` という文字 | **`\$`** |
| `[` という文字 | **`\[`** |
| `\` という文字 | **`\\`** |

**`\.` を忘れるのがいちばん多い間違い**です。

```text
   grep 'file.txt'    →  file と txt の間が「何か1文字」なら何でもマッチ
                         file.txt / fileXtxt / file1txt すべて拾う
   grep 'file\.txt'   →  file.txt だけにマッチする
```

## 拡張正規表現だけの記号

**`|`（縦棒）は「左右いずれかの文字列」**です。**拡張正規表現でのみ使えます。**

```bash
$ printf 'abc\nxyz\npqr\n' | grep -E 'abc|xyz'   # abc または xyz を含む行
abc
xyz
```

**`-E` を付けないと、`|` はただの文字**になります。

```bash
$ printf 'abc\nxyz\nabc|xyz\n' | grep 'abc|xyz'  # BRE なので「abc|xyz」という文字列を探す
abc|xyz
```

**`?` は「0回または1回」**です。**あってもなくてもよい、という意味**になります。

```bash
$ cat w.txt                           # 確認用のファイル
windows
window
windo

$ grep -E '^windows?$' w.txt          # windows の s があってもなくてもマッチする
windows
window
```

`windo` は `w` が足りないのでマッチしません。

**`( )` でグループ化すると、繰り返しや `|` の適用範囲を決められます。**

```text
   abc|xyz      →  「abc」または「xyz」
   a(bc|xy)z    →  「abcz」または「axyz」
   (ab)+        →  ab が1回以上（ab / abab / ababab）
```

## POSIX文字クラス

**`[a-z]` はロケール（言語設定）によって範囲が変わることがあります。**
確実に指定するには**POSIX 文字クラス**を使います。

| 書き方 | 意味 |
|:--|:--|
| **`[[:alpha:]]`** | アルファベット 1 文字 |
| **`[[:digit:]]`** | 数字 1 文字 |
| **`[[:alnum:]]`** | 英数字 1 文字 |
| **`[[:lower:]]`** | 小文字 1 文字 |
| **`[[:upper:]]`** | 大文字 1 文字 |
| `[[:space:]]` | 空白文字 1 文字（スペース、タブ、改行） |
| `[[:punct:]]` | 記号 1 文字 |
| `[[:blank:]]` | スペースかタブ |

```bash
$ grep '[[:upper:]]' re.txt           # 大文字を含む行を探す
Abc
```

**外側の `[ ]` が必要**です。`[:upper:]` ではなく `[[:upper:]]` と書きます。

```text
   [[:digit:]]
   │└───┬──┘│
   │  クラス │
   └────────┘  ← 外側の [ ] が「このうちの1文字」を表す
```

## 組み合わせて読む練習

**記号を 1 つずつ覚えても、組み合わさると読めなくなります。**
**「12345 という行だけを取り出す」**という課題で、実際に手を動かして確かめます。

```bash
$ cat n5.txt                          # 確認用のファイル
1
12
123
1234
12345
```

**正解は 2 つ**あります。

```bash
$ grep '^1.*5$' n5.txt                # 1で始まり、途中は何でもよく、5で終わる
12345
$ grep '1...5' n5.txt                 # 1 のあと任意の3文字、そのあと 5
12345
```

**`^1.*5$` の読み方**

```text
   ^     1     .*      5     $
   │     │     │       │     │
   │     │     │       │     └─ 行末で終わる
   │     │     │       └─────── 文字の 5
   │     │     └─────────────── 任意の文字が0回以上（＝何でもよい）
   │     └───────────────────── 文字の 1
   └─────────────────────────── 行頭から始まる
```

**`^` と `$` で両端を固定しているので、「行全体が 1 で始まり 5 で終わる」**という意味になります。
`1` と `12345` は行頭が `1` ですが、**行末が `5` なのは `12345` だけ**です。

**`1...5` の読み方**

```text
   1     .  .  .     5
   │     └──┬──┘     │
   │        │        └─ 文字の 5
   │        └────────── 任意の文字がちょうど3つ
   └─────────────────── 文字の 1
```

**`.` は「任意の 1 文字」で、3 つ並べれば「ちょうど 3 文字」**です。
**`1` ＋ 3 文字 ＋ `5` ＝ 5 文字**なので、`12345` だけが一致します。

**アンカーが無くても一致するのは、この行しか 5 文字にならないから**です。
**長い行の途中に `1abc5` があれば、それも拾ってしまう**点は覚えておいてください。

**一致しない書き方**

| 正規表現 | 結果 | なぜそうなるか |
|:--|:--|:--|
| **`[1-5]`** | **全部一致**（5行） | **「1〜5 のいずれか 1 文字を含む行」**。全部の行が `1` を含む |
| **`1[2-5]`** | **`12` 以降の4行** | 「`1` の次が 2〜5」。`1` だけの行は次の文字が無いので外れる |
| **`^15$`** | **一致なし** | 「行全体が `15`」。そんな行は無い |
| **`[^1-5]`** | **一致なし** | **`[^ ]` は否定**。「1〜5 以外の文字を含む行」は無い |

**`[1-5]` と `[^1-5]` の違いが最大の落とし穴**です。

```text
   [1-5]    …  1 から 5 の「いずれか1文字」
   [^1-5]   …  1 から 5 「以外の1文字」   ← [ ] の中の ^ は否定
   ^[1-5]   …  行頭が 1 から 5            ← [ ] の外の ^ は行頭
```

**`^` は場所によって意味が変わります。**
**`[` のすぐ後ろなら否定、それ以外なら行頭**、と覚えてください。

## 用語の整理

**正規表現には次のような基本の概念があります。**
Ping-t の解説でも用語として出てくるので、対応を押さえておきます。

| 用語 | 意味 | 該当する記号 |
|:--|:--|:--|
| **特殊文字** | **特殊な意味を持つ文字** | 縦棒 `\|` や `\`（エスケープ文字）など |
| **文字クラス** | **`[ ]` 内の文字集合** | `[abc]` `[a-z]` `[[:digit:]]` |
| **数量詞** | **直前の文字の繰り返し回数を示す文字** | `*` `+` `?` `{n,m}` |
| **アンカー** | **文字列内での位置を示す文字** | `^` `$` |

**「アンカー（錨）」は位置に固定する、というイメージ**です。
文字を消費せず、「ここが行頭である」という条件だけを表します。

## シェルのメタキャラクタとの違い

**ここが最も事故が起きるところ**です。

**正規表現の `*` と、シェルによって解釈されるメタキャラクタの `*` では意味が異なります。**

| | **シェルの `*`**（パス名展開） | **正規表現の `*`** |
|:--|:--|:--|
| 意味 | **0文字以上の任意の文字列** | **直前の文字の0回以上の繰り返し** |
| `*.txt` の解釈 | **`.txt` で終わるファイル名** | 「直前の文字の繰り返し」＋`.txt` |
| 解釈するのは | **シェル**（コマンドが動く前） | **コマンド自身** |

```text
   シェル:      a*      →  a で始まるファイル名（abc, a1, a）
   正規表現:    a*      →  a が0回以上（空文字, a, aa, aaa）
```

**同じ記号で意味が違うため、クォートを忘れるとシェルに食べられます。**

**正規表現は明示的に `'`（シングルクォーテーション）や `"`（ダブルクォーテーション）の
引用符で囲うことができます。これらの引用符で囲まれた正規表現の記号は、
シェルにメタキャラクタとして扱われなくなります。**

**実際に食べられる例**を見てください。
カレントディレクトリに `a.txt` と `aa.txt` があるとします。

```bash
$ ls                                  # 手前の状況を確認する
a.txt  aa.txt  data.txt
$ cat data.txt                        # 中身は3行
abc
aaa
xyz
$ grep a* data.txt                    # 危険。クォートがないので a* が展開される
$ echo $?                             # 1 … 1行も一致しなかった
1
$ echo grep a* data.txt               # 何に化けたのかを echo で確かめる
grep a.txt aa.txt data.txt
$ grep 'a*' data.txt                  # 正しい。シングルクォートで守る
abc
aaa
xyz
```

**`grep a* data.txt` は `grep a.txt aa.txt data.txt` に化けています。**
検索パターンが `a.txt`、検索対象が `aa.txt` と `data.txt` にずれてしまい、
一致なし（終了ステータス 1）で終わりました。
**エラーにならず、黙って別のコマンドとして成立してしまう**のが怖いところです。

**正規表現は必ずシングルクォートで囲む**、と機械的に覚えてください。
[クォートとエスケープ](../01_シェルとコマンドライン/クォートとエスケープ.md) の考え方がそのまま効きます。

**補足 … ダブルクォートでは足りないことがあります**

ダブルクォートの中でも **`$` と `` ` `` と `\` は特別な意味を保ちます**。
ただし **`$` が特別になるのは、直後に変数名・`{`・`(` が続くときだけ**です。
そのため `grep "a$" f.txt` のように **`$` が閉じ引用符の直前にある場合は、
そのまま行末アンカーとして働きます**（実測：`banana` が一致します）。

**壊れるのは `$` の直後に文字が続くとき**です。

```bash
$ cat prof.txt                        # $HOME という文字列を含むファイル
export PATH=$HOME/bin
export PATH=/usr/bin
$ grep "$HOME" prof.txt               # 危険。$HOME がシェルに展開される
$ echo $?                             # 1 … 一致なし
1
$ echo grep "$HOME" prof.txt          # 何に化けたのかを確かめる
grep /root prof.txt
$ grep '$HOME' prof.txt               # 正しい。シングルクォートなら文字のまま
export PATH=$HOME/bin
```

**判断に迷う余地をなくすため、シングルクォートを既定にする**のが安全です。

## 正規表現を使う主なコマンド

**正規表現を利用する主なコマンドには `sed` と `grep` があります。**

| コマンド | 役割 | 既定の正規表現 |
|:--|:--|:--|
| **`grep`** | **ファイルや標準入力から、検索パターンにマッチする文字列を含む行を抽出する** | **BRE** |
| **`sed`** | **ファイルや標準入力の内容を編集して表示する** | **BRE** |
| `awk` | 行をフィールドに分けて処理する | ERE |
| `vi` の `/` と `:s` | 検索と置換 | vim 独自（BRE に近い） |
| `find -regex` | パス名を正規表現で照合する | **Emacs 正規表現** |

```bash
$ grep '[1-5]' test.txt               # 1から5までのいずれかの文字がある行を抽出する
$ sed '/^#/d' test.txt                # 「#」から始まる行を削除して出力する
```

詳細はそれぞれ [grepによる検索](./grepによる検索.md) と
[sedによる置換](./sedによる置換.md) にまとめています。
