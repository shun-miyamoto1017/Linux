## 改行コードとは

**コンピュータ上でテキストファイルを扱う際には、改行コードという制御コードについて
意識する必要があります。**

**「改行」は目に見えませんが、ファイルの中では 1〜2 バイトの文字として記録されています。**

```text
   画面で見える姿          ファイルの中の実際のバイト列
   ┌──────────┐
   │ line1    │            l i n e 1 \n l i n e 2 \n
   │ line2    │                     ↑            ↑
   └──────────┘                   改行コード   改行コード
```

**多くのシステムでは、キャリッジリターン（Carriage Return: CR、`\r`、16進数で 0D）と
ラインフィード（Line feed: LF、`\n`、16進数で 0A）を使って改行を表します。**

| 記号 | 名前 | 16進数 | 由来 |
|:--|:--|:--|:--|
| **`\r`** | **CR（キャリッジリターン）** | **0D** | タイプライタで**印字ヘッドを左端に戻す**動作 |
| **`\n`** | **LF（ラインフィード）** | **0A** | タイプライタで**紙を1行送る**動作 |

**もともとは別々の動作**でした。タイプライタでは「左端に戻す」と「1 行送る」の
2 つの操作が必要だったため、その名残が改行コードの違いとして残っています。

## OSごとの改行コード

**改行コードと代表的な OS の組み合わせは以下のとおり**です。

| 改行コード | 使う OS |
|:--|:--|
| **`CRLF`（`\r\n`）** | **Windows** |
| **`LF`（`\n`）** | **Unix OS（Linux, Mac OS X など）** |
| **`CR`（`\r`）** | **古い MacOS（バージョン9まで）** |

**Linux は LF のみ**、**Windows は CR と LF の 2 バイト**、と覚えてください。

```text
   Linux    line1 \n         line2 \n          … 1バイト
   Windows  line1 \r \n      line2 \r \n       … 2バイト
   旧Mac    line1 \r         line2 \r          … 1バイト
```

**OS の改行コードと異なる改行コードのテキストファイルを読み込むと、
正しく改行されなかったり、不正な制御コードの付いたファイルだと認識されたりします。**

**補足 … 現在の macOS は Linux と同じ LF です**

`CR` を使っていたのは **Mac OS 9 まで**です。
Mac OS X（現在の macOS）は Unix 系なので LF を使います。
**「Mac は CR」は古い知識**なので、実務では気にしなくて構いません。

## どの改行コードかを調べる

### fileコマンドで調べる

**いちばん手軽なのが `file` コマンド**です。

```bash
$ file unix.txt dos.txt mac.txt       # 3つのファイルの種類を調べる
unix.txt: ASCII text
dos.txt:  ASCII text, with CRLF line terminators
mac.txt:  ASCII text, with CR line terminators
```

| 表示 | 改行コード |
|:--|:--|
| **`ASCII text`** | **LF**（Linux 標準。何も付かない） |
| **`ASCII text, with CRLF line terminators`** | **CRLF**（Windows） |
| **`ASCII text, with CR line terminators`** | **CR**（旧 Mac） |

**LF のときは何も書かれない**のが分かりにくい点です。
「何も出ていない＝正常」と読んでください。

### cat -A で目で見る

**`cat -A` は制御文字を記号で表示します。**

```bash
$ cat -A unix.txt                     # LF のファイルを制御文字付きで表示する
line1$
line2$

$ cat -A dos.txt                      # CRLF のファイルを制御文字付きで表示する
line1^M$
line2^M$
```

| 記号 | 意味 |
|:--|:--|
| **`$`** | **行末（LF）** |
| **`^M`** | **CR**（Ctrl+M の意味） |
| `^I` | タブ |

**`^M$` で終わっていたら CRLF**です。`$` だけなら LF です。

**補足 … `^M` は「^」と「M」の2文字ではありません**

**`^M` は CR（0x0D）という 1 文字の制御コード**を、画面に出せる形にした表記です。
**キーボードから打ち込むには `Ctrl+V` に続けて `Ctrl+M` を押します。**

```text
   Ctrl+V  …  「次に押すキーを、そのまま文字として入れる」という合図
   Ctrl+M  …  CR そのもの
```

| 打ちたいもの | キー操作 |
|:--|:--|
| **`^M`（CR）** | **`Ctrl+V` → `Ctrl+M`** |
| `^I`（タブ） | `Ctrl+V` → `Ctrl+I` |
| `^[`（Esc） | `Ctrl+V` → `Esc` |

**`Ctrl+V` は vi の入力モードでも、bash のコマンドラインでも同じように使えます。**

**ただし、打ち間違えても見た目では気づけません。**
スクリプトに書くときは **`'\r'`** というエスケープのほうが安全です。

```bash
$ tr -d '\r' < dos.txt > unix.txt     # 推奨。エスケープで書く
$ tr -d '^M' < dos.txt | cat -A       # このページからコピペした「^」「M」の2文字だと
line1^M$                              # CR は1つも消えない（エラーも出ない）
line2^M$
```

詳しくは [trによる文字の変換と削除](./trによる文字の変換と削除.md) にまとめています。

**`cat -A` は `cat -vET` と同じ**です。個別に指定することもできます。

| オプション | 表示するもの |
|:--|:--|
| `-E` | 行末に `$` を付ける |
| `-T` | タブを `^I` で表示する |
| `-v` | そのほかの制御文字を `^X` 形式で表示する |
| **`-A`** | **上の3つすべて** |

### od -c でバイト列を見る

**いちばん確実なのが `od`（octal dump）**です。バイト単位で中身を見せます。

```bash
$ od -c unix.txt                      # LF のファイルをバイト列で見る
0000000   l   i   n   e   1  \n   l   i   n   e   2  \n
0000014

$ od -c dos.txt                       # CRLF のファイル
0000000   l   i   n   e   1  \r  \n   l   i   n   e   2  \r  \n
0000016

$ od -c mac.txt                       # CR のファイル
0000000   l   i   n   e   1  \r   l   i   n   e   2  \r
0000014
```

**`\r` と `\n` がそのまま見える**ので、疑わしいときはこれが決定打になります。

**補足 … 最後の行の数字はデータではありません**

`od` は **各行の先頭に「そこまで何バイト目か」を 8 進数で表示**します。
最後にもう 1 行だけ出る `0000014` のような数字は、
**ファイル全体のバイト数（の 8 進表記）を表す終端の目印**です。

8 進の `0000014` は 10 進の **12 バイト**、`0000016` は 10 進の **14 バイト**です。
**10 進で見たいときは `od -Ad -c` を使います**（`-A` はアドレスの表示形式の指定）。

```bash
$ od -Ad -c unix.txt                  # アドレスを10進で表示する
0000000   l   i   n   e   1  \n   l   i   n   e   2  \n
0000012
$ od -Ad -c dos.txt                   # CRLF のファイル
0000000   l   i   n   e   1  \r  \n   l   i   n   e   2  \r  \n
0000014
```

**`0000014`（8進）が `0000012`（10進）に、`0000016` が `0000014` に変わりました**（実測）。

**補足 … `od` は8進数・16進数でも表示できます**

**`od`（octal dump）は、もともと「8進ダンプ」のコマンド**です。
**オプションを付けないと、2 バイトずつの 8 進数**で出ます。

```bash
$ printf 'AB\n' > ab.txt             # 3バイトのファイル
$ od ab.txt                           # 既定は2バイトずつの8進数
0000000 041101 000012
0000003
$ od -c ab.txt                        # -c なら文字として見える
0000000   A   B  \n
0000003
$ od -x ab.txt                        # -x は2バイトずつの16進数
0000000 4241 000a
0000003
$ od -t x1 ab.txt                     # -t x1 なら1バイトずつの16進数（読みやすい）
0000000 41 42 0a
0000003
```

| オプション | 表示形式 |
|:--|:--|
| **（なし）** | **2 バイトずつの 8 進数** |
| **`-c`** | **文字として表示**（制御文字は `\n` `\r` などで出る） |
| `-x` | 2 バイトずつの 16 進数 |
| **`-t x1`** | **1 バイトずつの 16 進数**（バイト単位で見たいときはこれ） |
| `-A d` / `-A x` / `-A n` | アドレスを 10 進 / 16 進 / 表示しない |

**`-x` は 2 バイトずつまとめる**ので、**リトルエンディアンで順序が入れ替わって見えます**。
上の例では `A`(41) `B`(42) が **`4241`** と出ています。
**バイト単位で確かめたいときは `-t x1`** を使ってください。

**16進と文字を並べて見る**のが、実務でいちばん使う形です。

```bash
$ od -An -tx1c ab.txt                 # アドレスなし・16進と文字を並べる
  41  42  0a
   A   B  \n
```

**サイズの差でも分かります。**

```bash
$ wc -c unix.txt dos.txt              # バイト数を比べる
12 unix.txt
14 dos.txt
26 total
```

**複数のファイルを渡すと、最後に `total` の行が付きます。**

**2 行のファイルで 2 バイトの差**があります。1 行につき 1 バイト（CR）多いためです。

## 改行コードが違うと何が起きるか

**症状が分かりにくいのが厄介なところ**です。代表的な 4 つを挙げます。

| 症状 | 原因 |
|:--|:--|
| **シェルスクリプトが `bad interpreter` で動かない** | `#!/bin/bash\r` の `\r` までパスの一部と見なされる |
| **`grep` がマッチしない** | 行末が `\r` なので `$`（行末）の位置がずれる |
| **設定ファイルの値が効かない** | 値の末尾に見えない `\r` が付いている |
| **画面表示が崩れる** | CR で行頭に戻り、上書きされる |

**1 つ目が最も多く、かつ分かりにくい**です。

```text
$ ./deploy.sh
-bash: ./deploy.sh: /bin/bash^M: bad interpreter: No such file or directory
                              ↑
                    この ^M が犯人。「/bin/bash\r」というパスを探しに行っている
```

**エラーメッセージに `^M` が出たら改行コードを疑ってください。**

**2 つ目も静かに失敗します。**

```bash
$ grep -c 'line1$' dos.txt            # 行末が \r なので $ の位置がずれ、マッチしない
0
```

**`line1` のあとに `\r` があるため、`line1$` という条件を満たしません。**
エラーにならず「0 件」と返るので、**気づかないまま間違った結論を出す**ことになります。

## 変換する

### dos2unix と unix2dos

**いちばん素直なのが専用コマンド**です。

```bash
$ dos2unix d2.txt                     # CRLF を LF に変換する
dos2unix: converting file d2.txt to Unix format...
$ file d2.txt                         # 変換されたか確認する
d2.txt: ASCII text

$ unix2dos u2.txt                     # LF を CRLF に変換する
unix2dos: converting file u2.txt to DOS format...
$ file u2.txt                         # 変換されたか確認する
u2.txt: ASCII text, with CRLF line terminators
```

| コマンド | 変換 |
|:--|:--|
| **`dos2unix`** | **CRLF → LF** |
| **`unix2dos`** | **LF → CRLF** |
| `mac2unix` | CR → LF |
| `unix2mac` | LF → CR |

**ファイルを直接書き換えます。** 元の内容は残らないので、必要ならバックアップを取ってください。

| オプション | 意味 |
|:--|:--|
| `-n 入力 出力` | 元を残し、別ファイルに出力する |
| `-k` | タイムスタンプを保持する |
| `-i` | 変換せず、改行コードの種類だけ表示する |

**補足 … 標準では入っていないことが多いです**

```bash
$ sudo dnf install -y dos2unix        # RHEL 系
$ sudo apt install -y dos2unix        # Debian 系
```

**インストールできない環境も多い**ので、次の `sed` の方法も覚えておいてください。

### sed で変換する

**どこにでもある `sed` で同じことができます。**

```bash
$ sed 's/\r$//' dos.txt | od -c       # 行末の CR を削除して結果をバイト列で確認する
0000000   l   i   n   e   1  \n   l   i   n   e   2  \n
0000014
```

**`\r$` は「行末の CR」**という意味です。これを空文字に置換して削除しています。

**ファイルを直接書き換えるなら `-i`** を付けます。

```bash
$ sed -i.bak 's/\r$//' script.sh      # バックアップを残して変換する
```

**逆方向（LF → CRLF）も書けます。**

```bash
$ sed -i 's/$/\r/' script.sh          # 各行の末尾に CR を足す
```

**`sed` が最も可搬性が高い方法**です。追加インストールが要りません。

### tr で変換する

**`tr -d` で CR をすべて削除する方法**もあります。

```bash
$ tr -d '\r' < dos.txt | od -c        # CR をすべて削除して結果をバイト列で確認する
0000000   l   i   n   e   1  \n   l   i   n   e   2  \n
0000014
```

**`sed` との違いは「行末に限らず、すべての CR を消す」**点です。

| | **`sed 's/\r$//'`** | **`tr -d '\r'`** |
|:--|:--|:--|
| 消す対象 | **行末の CR だけ** | **すべての CR** |
| 行の途中の CR | **残る** | **消える** |
| どちらが安全か | **こちら**（意図しない削除が起きない） | 乱暴だが確実 |

**`tr` はファイルを直接書き換えられません。** リダイレクトで別ファイルに出します。

```bash
$ tr -d '\r' < dos.txt > unix.txt     # 別ファイルに書き出す
```

**同じファイル名にリダイレクトすると中身が消える**ので注意してください。

### nkf で変換する

**`nkf` は文字コードと改行コードを同時に変換できるコマンド**です。

```bash
$ nkf -Lu -w --overwrite file.txt     # 改行を LF に、文字コードを UTF-8 にする
```

| オプション | 意味 |
|:--|:--|
| **`-Lu`** | 改行コードを **LF**（Unix）にする |
| **`-Lw`** | 改行コードを **CRLF**（Windows）にする |
| `-Lm` | 改行コードを CR（Mac）にする |
| **`-w`** | 文字コードを **UTF-8** にする |
| `-s` | 文字コードを Shift_JIS にする |
| `-e` | 文字コードを EUC-JP にする |
| `--overwrite` | ファイルを直接書き換える |
| `-g` | 判定結果だけを表示する |

**日本語の Windows ファイルを受け取ったときは、
改行コードと文字コードの両方が違う**ことが多いので、`nkf` が一度で済みます。

**`nkf` も標準では入っていません**（`epel-release` や `apt install nkf` が必要です）。

## 文字コードとの違い

**改行コードと文字コード（キャラクタセット）は別の話**です。混同しやすいので整理します。

| | **改行コード** | **文字コード** |
|:--|:--|:--|
| 何を決めるか | **「行の終わり」をどのバイトで表すか** | **文字をどのバイト列で表すか** |
| 種類 | CR / LF / CRLF | UTF-8 / Shift_JIS / EUC-JP など |
| 調べるコマンド | **`file`** / `od -c` | **`file`** / `nkf -g` |
| 変換コマンド | `dos2unix` / `sed` / `tr` | **`iconv`** / `nkf` |

```bash
$ file -i doc.txt                     # 文字コードまで含めて表示する
doc.txt: text/plain; charset=utf-8

$ iconv -f SHIFT_JIS -t UTF-8 sjis.txt > utf8.txt   # 文字コードを変換する
```

**「文字化けしている」と「改行がおかしい」は別の症状**です。
`file` はどちらも教えてくれるので、**まず `file` を打つ**のが正解です。

## そもそも混入させない

**変換で対処するより、入り口で止めるほうが確実**です。

| 対策 | 方法 |
|:--|:--|
| **エディタの設定** | VS Code は右下の `CRLF` / `LF` をクリックして切り替え。既定を `files.eol: "\n"` にする |
| **`.editorconfig` を置く** | `end_of_line = lf` をリポジトリに置くと、対応エディタ全体に効く |
| **Git の設定** | `core.autocrlf=input`（Windows でコミット時に LF へ変換） |
| **`.gitattributes` を置く** | `*.sh text eol=lf` のようにファイル種別ごとに固定する |

```text
# .editorconfig の例
root = true

[*]
end_of_line = lf
insert_final_newline = true

[*.{bat,cmd}]
end_of_line = crlf
```

**`.gitattributes` がいちばん強力**です。
リポジトリの設定なので、**チーム全員の環境に効きます**。

```text
# .gitattributes の例
* text=auto
*.sh text eol=lf
*.bat text eol=crlf
```

**補足 … 疑わしいファイルを一括で調べる**

```bash
$ file $(find . -name '*.sh') | grep CRLF       # CRLF のシェルスクリプトを探す
$ grep -rlP '\r$' --include='*.sh' .            # 行末に CR があるファイルを探す
```

**デプロイ前のチェックに入れておく**と、`bad interpreter` で悩む時間が消えます。
