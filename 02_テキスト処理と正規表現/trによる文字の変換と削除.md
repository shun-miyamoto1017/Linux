## trとは

**`tr` は文字を別の文字に変換したり、削除したりするコマンド**です。
**translate（変換）の略**です。

```text
tr [オプション] 文字列1 [文字列2]
```

**`tr` が見ているのは「行」ではなく「1文字ずつ」**です。
ここが `sed` との最大の違いになります。

```text
   sed  … 行を見て、パターンに一致した「文字列」を置き換える
   tr   … 流れてくる「1文字」を、対応表に従って置き換える
```

---

## ファイル名を引数に取れない

**ここが最初のつまずきどころ**です。

**`tr` は標準入力からしか読みません。** `grep` や `sed` のように
ファイル名を引数に書くことができません。

```bash
$ cat f.txt                           # これから使う確認用のファイル
apple
banana
cherry
$ tr a-z A-Z f.txt                    # ファイル名を書くとエラーになる
tr: extra operand 'f.txt'
Try 'tr --help' for more information.
$ echo $?                             # 終了ステータスは 1
1
```

**`extra operand`（引数が多すぎる）というエラー**になりました。
`tr` にとって引数は「文字列1」と「文字列2」の最大 2 つで、
`f.txt` は 3 つ目の余分な引数と解釈されています。

**渡し方は 2 通り**です。

```bash
$ tr a-z A-Z < f.txt                  # ① 入力リダイレクトで渡す
APPLE
BANANA
CHERRY
$ cat f.txt | tr a-z A-Z              # ② パイプで渡す
APPLE
BANANA
CHERRY
```

| 書き方 | 動くか | 備考 |
|:--|:-:|:--|
| **`tr a-z A-Z < f.txt`** | **○** | **リダイレクト。プロセスが1つで済むので軽い** |
| **`cat f.txt \| tr a-z A-Z`** | **○** | パイプ。前段に別の処理を挟みやすい |
| `tr a-z A-Z f.txt` | **✕** | **ファイル名は書けない**（`extra operand`） |
| `tr a-z A-Z \| f.txt` | **✕** | パイプの右はコマンド。ファイル名は置けない |

**試験では「ファイル名を引数に書いた選択肢」が誤答として必ず混ざります。**

## 文字を変換する

**オプションを付けない場合、「文字列1」を「文字列2」に変換**します。

```bash
$ tr a-z A-Z < f.txt                  # 小文字を大文字に変換する（f.txt は apple / banana / cherry）
APPLE
BANANA
CHERRY
```

**対応は「位置」で決まります。** 1 文字目どうし、2 文字目どうし、と順に対応します。

```text
   文字列1:  a  b  c  d  …  z
             │  │  │  │     │
   文字列2:  A  B  C  D  …  Z
```

**`a-z` は範囲指定**です。`abcdefghijklmnopqrstuvwxyz` と書くのと同じです。

**順番を逆にすれば、大文字→小文字**になります。

```bash
$ cat case.txt                        # 確認用のファイル
PINGT
PINGT
PINGT
$ tr A-Z a-z < case.txt               # 大文字を小文字に変換する
pingt
pingt
pingt
```

**補足 … 文字列2 が短いとどうなるか**

**足りない分は、文字列2 の最後の 1 文字が繰り返して使われます。**

```bash
$ echo 'abcde' | tr 'abcde' 'XY'      # 文字列2 が2文字しかない
XYYYY
```

`a`→`X`、`b`→`Y` のあと、`c` `d` `e` はすべて `Y` になりました。
**意図しない変換になりやすいので、長さはそろえてください。**

## よく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-d`** | **文字列1 で指定した文字を削除する**（delete） |
| **`-s`** | **連続した同じ文字を 1 文字にまとめる**（squeeze）。**対象は「最後に書いた集合」** |
| `-c` | 文字列1 を「指定した文字以外」の意味にする（complement） |
| `-t` | 文字列1 を文字列2 の長さに切り詰めてから変換する（truncate） |

### -d で削除する

**`-d` は文字列2 を取りません。** 文字列1 に書いた文字を消すだけです。

```bash
$ tr -d ac < f.txt                    # a と c を削除する
pple
bnn
herry
```

`apple` から `a` が、`banana` から `a` が 3 つ、`cherry` から `c` が消えました。
**「ac」という並びを消すのではなく、「a」と「c」をそれぞれ消す**点に注意してください。

### -s で連続をまとめる

**`-s` は同じ文字が続いたときだけ 1 文字にします。**

```bash
$ printf '112233\n' | tr -s '[:digit:]'    # 連続した同じ数字を1文字にする
123
$ printf 'aaabbbccc\n' | tr -s abc         # 連続した a b c を1文字にする
abc
```

**削除ではありません。** 1 文字は残ります。

```text
   -d  …  1 1 2 2 3 3  →  （数字は全部消える。改行は残るので空行になる）
   -s  …  1 1 2 2 3 3  →  1 2 3
```

**注意 … 文字列2 も書いたときは、圧縮の対象が変わります**

**`tr -s 文字列1` なら文字列1 が対象**ですが、
**`tr -s 文字列1 文字列2` と 2 つ書くと、対象は「変換後の文字列2」**になります。
`man tr` の表現では **「最後に指定した集合（the last specified ARRAY）」**です。

```bash
$ echo 'XXX' | tr -s 'a' 'X'          # 入力に a は無いのに XXX が潰れる
X
$ echo 'aaabbb' | tr -s 'ab' 'xy'     # a→x b→y に変換したあと、xy の連続を潰す
xy
```

**「`-s` は変換のあとに効く」**と覚えてください。

**空白の詰め直しが代表的な使い道**です。

```bash
$ printf 'a    b     c\n' | tr -s ' '      # 連続した空白を1つにそろえる
a b c
```

## POSIX文字クラス

**`a-z` のような範囲指定の代わりに、意味で指定する書き方**があります。

| 文字クラス | 意味 |
|:--|:--|
| **`[:lower:]`** | **英小文字**（`a-z`） |
| **`[:upper:]`** | **英大文字**（`A-Z`） |
| **`[:digit:]`** | **数字**（`0-9`） |
| **`[:alpha:]`** | **英字**（大文字と小文字） |
| **`[:alnum:]`** | **英数字** |
| **`[:space:]`** | **空白類**（スペース・タブ・改行など） |
| `[:punct:]` | 記号 |
| `[:cntrl:]` | 制御文字 |

```bash
$ cat f.txt | tr '[:lower:]' '[:upper:]'   # 文字クラスで小文字を大文字にする
APPLE
BANANA
CHERRY
$ cat mix.txt                              # 英数字が混ざったファイル
a1b2c3
xyz
$ tr -d '[:digit:]' < mix.txt              # 数字だけを消す
abc
xyz
```

**`[:num:]` というクラスはありません。** 数字は **`[:digit:]`** です。
試験ではここが誤答として出ます。

**補足 … クォートは付けてください**

`[:digit:]` はシェルから見ると **`[` `]` を含むパス名展開のパターン**です。
カレントディレクトリに `:` `d` `i` `g` `t` のいずれかの名前のファイルがあると、
**シェルに食べられて別の文字列に化けます**
（[パス名展開とワイルドカード](../01_シェルとコマンドライン/パス名展開とワイルドカード.md)）。

```bash
$ tr -d '[:digit:]' < mix.txt         # 必ずシングルクォートで囲む
abc
xyz
```

## 改行コードを落とす

**Windows で作られたファイルは行末が `CRLF`（`\r\n`）**です。
Linux では `\r` が余分なので、**`tr -d` で落とす**のが定番です。

```bash
$ cat -A dos.txt                      # 確認用のファイル（行末が CRLF、2行目は行の途中にも CR がある）
line1^M$
li^Mne2^M$
$ tr -d '\r' < dos.txt > unix.txt     # CR をすべて削除する
$ cat -A unix.txt                     # 行末も行中も CR が消えた
line1$
line2$
```

**`\r` は「復帰（Carriage Return）」**で、
**画面上では `^M` という制御コードとして見える**ことがあります。

**ここで最大の落とし穴**があります。
**画面に見えている `^M` を、そのまま `^` と `M` の 2 文字として打ってはいけません。**

```bash
$ cat -A caret.txt                    # 「^」「M」の2文字と、行末の本物の CR が混ざったファイル
CoMMand^M output^M$
$ tr -d '^M' < caret.txt | cat -A     # 2文字として打つと、^ と M が消えるだけ
Coand output^M$
```

**`CoMMand` が `Coand` に壊れ、行末の CR は 1 つも消えていません。**
**エラーも出ません。** 次の節の入力方法が必要になります。

### 制御コードの入力方法

**`^M` は「^」と「M」の 2 文字ではありません。** 1 文字の制御コードです。
**キーボードから入力するには、`Ctrl+V` に続けて `Ctrl+M` を押します。**

```text
   Ctrl+V  …  「次に押すキーを、そのまま文字として入れる」という合図
   Ctrl+M  …  CR（復帰）そのもの
```

**`Ctrl+V` は「クォートされた挿入」**と呼ばれ、
**vi の入力モードでも、bash のコマンドラインでも同じように使えます**。

| 打ちたいもの | キー操作 |
|:--|:--|
| **`^M`（CR）** | **`Ctrl+V` → `Ctrl+M`** |
| `^I`（タブ） | `Ctrl+V` → `Ctrl+I` |
| `^[`（Esc） | `Ctrl+V` → `Esc` |

**入力ミスが怖いので、スクリプトでは `'\r'` と書くほうが安全**です。
`tr` は `\r` `\n` `\t` といったエスケープを解釈します。

詳しくは [テキストファイルの改行コード](./テキストファイルの改行コード.md) を見てください。

## sed との使い分け

**同じことができる場面もありますが、得意分野が違います。**

| | **`tr`** | **`sed`** |
|:--|:--|:--|
| 単位 | **1 文字** | **行（と正規表現にマッチした文字列）** |
| 正規表現 | **使えない** | **使える** |
| ファイル名の引数 | **取れない**（標準入力のみ） | **取れる** |
| 直接書き換え | **できない** | **`-i` でできる** |
| 速さ | **速い**（単純な対応表） | 正規表現の解析ぶん遅い |
| 向いている仕事 | **大文字小文字の統一・文字の削除・空白の詰め直し** | **文字列の置換・行の削除・行の挿入** |

**「1 文字ずつ機械的に」なら `tr`、「パターンで」なら `sed`** と覚えてください。

```bash
$ tr -d '\r' < dos.txt | cat -A       # tr … CR という「文字」を全部消す
line1$
line2$
$ sed 's/\r$//' dos.txt | cat -A      # sed … 「行末の」CR だけを消す
line1$
li^Mne2$
```

**この 2 つは結果が違います。**
**行の途中に `\r` があるとき、`tr` は消しますが `sed` は残します**（実測）。
**行末だけを直したいなら `sed`、CR を根こそぎ消したいなら `tr`** と使い分けます。

## 実務での組み合わせ

| やりたいこと | 書き方 |
|:--|:--|
| **改行コードを LF にそろえる** | `tr -d '\r' < win.csv > lin.csv` |
| **大文字小文字を無視して集計する** | `tr '[:upper:]' '[:lower:]' < access.log \| sort \| uniq -c` |
| **連続した空白を 1 つに詰める** | `tr -s ' ' < messy.txt` |
| **改行を空白に変えて 1 行にする** | `tr '\n' ' ' < list.txt` |
| **空白区切りを改行区切りにする** | `tr ' ' '\n' < line.txt` |
| **英数字以外を消す** | `tr -cd '[:alnum:]\n' < dirty.txt` |

**最後の `-c`（complement）は「指定した文字以外」**という意味です。
`-cd '[:alnum:]\n'` で「英数字と改行以外を全部消す」になります。

```bash
$ echo 'a-b_c!1' | tr -cd '[:alnum:]\n'    # 英数字と改行以外を消す
abc1
```
