## grepとは

**`grep` は、ファイルや標準入力から、検索パターンにマッチする文字列を含む行を抽出するコマンド**です。

```text
grep [オプション] 検索パターン [ファイル名]
```

**ファイル名を省略すると標準入力から読みます。** パイプでつなげるのはこのためです。

```bash
$ grep error /var/log/messages        # ファイルから検索する
$ ps aux | grep nginx                 # 他のコマンドの出力から検索する
```

**名前の由来** … `g/re/p`（**g**lobally search for a **r**egular **e**xpression and **p**rint）という
`ed` エディタのコマンドから来ています。「正規表現で探して表示する」がそのまま名前になっています。

## よく使うオプション

**`grep` コマンドの書式と主なオプションは以下のとおり**です。

| オプション | 説明 |
|:--|:--|
| **`-c`** | **マッチした行の行数のみ表示** |
| **`-f`** | **検索パターンをファイルから読み込む** |
| **`-i`** | **大文字と小文字を区別しない** |
| **`-n`** | **先頭に行番号をつけて、マッチした行を表示** |
| **`-v`** | **マッチしなかった行を表示** |
| **`-E`** | **拡張正規表現を使用**（`egrep` コマンドと同様） |
| **`-F`** | **検索パターンを正規表現ではなく、固定文字列とする**（`fgrep` コマンドと同様） |

**試験でも実務でもこの 7 つ**です。まずこれを押さえてから、次の表に進んでください。

| そのほかのオプション | 説明 |
|:--|:--|
| **`-r`** / `-R` | **ディレクトリを再帰的にたどる** |
| **`-l`** | **マッチしたファイル名だけ**を表示する |
| `-L` | マッチ**しなかった**ファイル名を表示する |
| **`-w`** | **単語単位で一致**したものだけ（`cat` が `concat` に当たらない） |
| `-x` | **行全体が一致**したものだけ |
| **`-o`** | **マッチした部分だけ**を表示する（行全体ではない） |
| **`-A n`** | マッチした行の**後ろ n 行**も表示する（After） |
| **`-B n`** | マッチした行の**前 n 行**も表示する（Before） |
| **`-C n`** | マッチした行の**前後 n 行**も表示する（Context） |
| `-q` | **何も表示しない**。終了ステータスだけ返す（スクリプト用） |
| `-s` | ファイルが読めないときのエラーを抑制する |
| `-m n` | n 件見つかった時点で打ち切る |
| `--color=auto` | マッチした部分に色を付ける |

## 一つずつ例文で確認する

### 件数だけ数える

**`-c` はマッチした行の行数のみ表示します。**

```bash
$ cat h.conf                          # 確認用のファイル
#a
#b
c
#d

$ grep -c '^#' h.conf                 # 行頭が # の行が何行あるか数える
3
```

**数えているのは「行数」であって「出現回数」ではありません。**
1 行に 3 回出てきても 1 と数えます。

```text
   grep -c 'a' → a を含む「行」の数
   grep -o 'a' | wc -l → a の「出現回数」
```

### 行番号を付ける

**`-n` は先頭に行番号をつけて、マッチした行を表示します。**

```bash
$ cat test.txt                        # 確認用のファイル
Pingt1
pingT2
pingt3

$ grep -n 'ping' test.txt             # 行番号付きで表示する
2:pingT2
3:pingt3
```

**1 行目の `Pingt1` が出ていません。** 大文字の `P` で始まっているためです。

**ファイルが 1 つのときは `行番号:内容` の形式**です。
エディタで `vi +2 test.txt` と開き直すのにそのまま使えます。

**ファイルが 2 つ以上のときは、先頭にファイル名が付きます。**

```bash
$ grep -n 'ping' test.txt other.txt   # 複数ファイルを指定する
test.txt:2:pingT2
test.txt:3:pingt3
other.txt:1:ping4
```

**`ファイル名:行番号:内容` になるのは複数ファイルのとき**、と覚えてください。
1 ファイルでも必ずファイル名を出したいときは **`-H`**、
逆に複数でも出したくないときは **`-h`** を使います。

### マッチしなかった行を出す

**`-v` はマッチしなかった行を表示します。**

```bash
$ grep -v 'ping' test.txt             # ping を含まない行を表示する
Pingt1
```

**設定ファイルから「実際に効いている行」だけを見る定番**がこれです。

```bash
$ grep -v '^#' httpd.conf | grep -v '^$'   # コメント行と空行を除く
```

### 大文字と小文字を区別しない

**`-i` は大文字と小文字を区別しません。**

```bash
$ grep -i 'PINGT' test.txt            # 大文字小文字を無視して探す
Pingt1
pingT2
pingt3
```

**ログ調査では `-i` を常に付ける**くらいでちょうどいいです。
`Error` `ERROR` `error` はアプリによってばらばらだからです。

### 検索パターンをファイルから読み込む

**`-f` は検索パターンをファイルから読み込みます。**

```bash
$ cat f.txt                           # 検索対象のファイル
#PINGT
PingT
#pingt
.*

$ cat pattern                         # 検索パターンを書いたファイル
^[^#]

$ grep -f pattern f.txt               # pattern に書いたパターンで f.txt を検索する
PingT
.*
```

**`^[^#]` は「行頭が `#` ではない行」**という意味です。
`#` で始まる 2 行が除かれ、残りの 2 行が出力されました。

**パターンファイルには 1 行 1 パターンを書きます。** 複数書けば **OR 条件**になります。

```bash
$ cat keywords                        # 探したいキーワードを並べたファイル
error
warning
critical

$ grep -f keywords /var/log/messages  # 3つのいずれかを含む行を抽出する
```

**「監視で拾いたいキーワード一覧」をファイルで管理できる**のが実務上の利点です。

### 拡張正規表現を使う

**`grep` コマンドは、`-E` オプションを付けない場合は検索パターンを基本正規表現と判断します。**
**検索パターンで拡張正規表現を使うには、`-E` オプションを指定します**（`egrep` コマンドと同様）。

```bash
$ cat words.txt                       # 確認用のファイル
hair
air
car
wear
beer

$ grep '^.+[ie]r$' words.txt          # + が使えないため、1件もマッチしない
                                      # 終了ステータスは 1
$ grep -E '^.+[ie]r$' words.txt       # -E を付けると拡張正規表現になる
hair
air
beer
```

**基本正規表現のままでも、`\+` とエスケープすれば同じ指定ができます。**

```bash
$ grep '^.\+[ie]r$' words.txt         # BRE で + を使うには \ を付ける
hair
air
beer
```

**拡張正規表現の `?` `+` は、基本正規表現では `\?` `\+` で同様の指定ができます。**

### 正規表現ではなく固定文字列として扱う

**`-F` は検索パターンを正規表現ではなく、固定文字列とします**（`fgrep` コマンドと同様）。

```bash
$ cat dot.txt                         # 確認用のファイル
a.c
abc

$ grep 'a.c' dot.txt                  # . が「任意の1文字」として解釈される
a.c
abc

$ grep -F 'a.c' dot.txt               # -F なら「a.c」という文字そのものを探す
a.c
```

**IP アドレスやバージョン番号を探すときに効きます。**

```bash
$ grep -F '192.168.1.1' access.log    # ドットをエスケープせずに済む
```

**`-F` は高速でもあります。** 正規表現の解析をしないためで、
**大量のキーワードを `-f` で渡すとき**は `-F` と組み合わせるのが定石です。

## 前後の行も出す

**マッチした行だけでは、前後の文脈が分からないことがあります。**

| オプション | 意味 | 覚え方 |
|:--|:--|:--|
| **`-A n`** | **後ろ n 行**も出す | **A**fter |
| **`-B n`** | **前 n 行**も出す | **B**efore |
| **`-C n`** | **前後 n 行**も出す | **C**ontext |

```bash
$ grep -A 5 'ERROR' app.log           # エラー行と、その後ろ5行を表示する
$ grep -B 3 'Segmentation' app.log    # 落ちる直前の3行を見る
$ grep -C 2 'timeout' app.log         # 前後2行を見る
```

**スタックトレースを追うときは `-A`**、
**落ちる原因を探すときは `-B`** と使い分けます。

**区切りとして `--` が挿入される**のが出力の特徴です。

```text
2026-09-18 10:00:01 ERROR connection refused
2026-09-18 10:00:01   at Connector.connect
2026-09-18 10:00:01   at Pool.acquire
--
2026-09-18 10:05:33 ERROR timeout
2026-09-18 10:05:33   at Reader.read
```

## ディレクトリをまとめて検索する

**`-r` でディレクトリを再帰的にたどります。**

```bash
$ grep -r 'ServerName' /etc/httpd/    # 設定ディレクトリ全体から探す
$ grep -rn 'TODO' ./src               # 行番号付きでソースツリーを探す
$ grep -rl 'password' /etc            # 見つかったファイル名だけを出す
```

| 組み合わせ | 用途 |
|:--|:--|
| **`-rn`** | **どのファイルの何行目か**を知りたい |
| **`-rl`** | **どのファイルにあるか**だけ知りたい（一覧を作る） |
| `-ri` | 大文字小文字を無視して全体から探す |
| `--include='*.conf'` | 対象を拡張子で絞る |
| `--exclude-dir=.git` | 特定のディレクトリを除く |

```bash
$ grep -rn --include='*.conf' 'Listen' /etc   # .conf だけを対象にする
```

**設定が「どこに書かれているか」を探す作業は `grep -rn` が最短**です。

## 結果画面の見方

**出力の形は、対象ファイルが 1 つか複数かで変わります。**

**ファイル1つのとき**

```text
2:pingT2
│ │
│ └─ マッチした行の内容
└─── 行番号（-n のときだけ）
```

**ファイルが複数のとき（`-r` を含む）**

```text
/etc/httpd/conf/httpd.conf:44:Listen 80
        │                   │      │
        │                   │      └─ 行の内容
        │                   └──────── 行番号（-n のときだけ）
        └──────────────────────────── ファイル名
```

**区切りは `:` です。** ただし `-l`（ファイル名だけ）や `-c`（件数）では形が変わります。

| オプション | 出力の形 |
|:--|:--|
| （なし） | 行の内容だけ |
| **`-n`** | **`行番号:内容`** |
| 複数ファイル | **`ファイル名:内容`** |
| **`-rn`** | **`ファイル名:行番号:内容`** |
| **`-c`** | **`ファイル名:件数`**（複数ファイルのとき） |
| **`-l`** | **ファイル名だけ** |
| **`-o`** | **マッチした部分だけ** |

**終了ステータスも重要です。**

| 終了ステータス | 意味 |
|:-:|:--|
| **`0`** | **1 行以上マッチした** |
| **`1`** | **1 行もマッチしなかった** |
| **`2`** | **エラー**（ファイルが無い、など） |

```bash
$ grep -q 'ERROR' app.log && echo "エラーあり"   # -q で結果を表示せず判定だけする
```

**`-q` は見つかった時点で打ち切る**ので、大きなファイルでも速く終わります。

## egrepとfgrepの関係

**`egrep` と `fgrep` は、`grep` のオプション付きと同じもの**です。

| コマンド | 同等の書き方 | 意味 |
|:--|:--|:--|
| **`egrep`** | **`grep -E`** | 拡張正規表現を使う |
| **`fgrep`** | **`grep -F`** | 固定文字列として扱う |

**POSIX はかなり前から `egrep` と `fgrep` を規格から外して**おり、
**GNU grep は 3.8（2022年9月）から、実行時に警告を出すようになりました。**

```text
egrep: warning: egrep is obsolescent; using grep -E
```

**補足 … 警告が出ない環境もあります**

`egrep` / `fgrep` の実体は **`grep -E` / `grep -F` を呼ぶだけの小さなシェルスクリプト**です。
ディストリビューションによっては、この警告を出さないように手を入れている場合があります。
**手元で確かめるなら中身を見るのが早い**です。

```bash
$ grep --version | head -1            # まず grep の版を確認する
grep (GNU grep) 3.11
$ file $(which egrep)                 # egrep の正体を調べる
/usr/bin/egrep: POSIX shell script, ASCII text executable
$ cat $(which egrep)                  # 中身はこれだけ
#!/bin/sh
cmd=${0##*/}
exec grep -E "$@"
```

**この例（Ubuntu 24.04）では警告を出す行が取り除かれています**（実測）。
**警告の有無にかかわらず非推奨であることは変わりません。**

**新しく書くスクリプトでは `grep -E` / `grep -F` を使ってください。**
ただし**試験では `egrep` / `fgrep` も出題される**ので、対応は覚えておきます。

## 実務での組み合わせ

| やりたいこと | コマンド |
|:--|:--|
| **ログからエラーを抜く** | `grep -i error /var/log/messages` |
| **設定の有効行だけ見る** | `grep -v '^#' nginx.conf \| grep -v '^$'` |
| **設定がどこに書かれているか探す** | `grep -rn 'ServerName' /etc/httpd/` |
| **エラーの前後を見る** | `grep -C 5 'ERROR' app.log` |
| **特定のIPのアクセスを数える** | `grep -cF '203.0.113.1' access.log` |
| **アクセス元IPを集計する** | `grep -oE '^[0-9.]+' access.log \| sort \| uniq -c \| sort -rn` |
| **スクリプトで存在確認する** | `grep -q 'pattern' file && 処理` |

**最後から2番目の組み合わせは頻出**なので、部品ごとに分解しておきます。

| 部品 | やっていること |
|:--|:--|
| `grep -oE '^[0-9.]+'` | 行頭の**IPアドレス部分だけ**を抜き出す |
| `sort` | 同じIPを**隣り合わせる**（`uniq` の前提） |
| `uniq -c` | **重複を数える** |
| `sort -rn` | **件数の多い順**に並べ替える |

集計側の詳細は [sortによる並べ替え](./sortによる並べ替え.md) にまとめています。

**補足 … 巨大なログには `grep` を先に置いてください**

```bash
$ cat huge.log | grep error           # cat が全体を読んでから渡す（無駄が多い）
$ grep error huge.log                 # grep が直接読む（こちらが速い）
```

**パイプの段数を減らすほど速くなります。**
`cat file | grep` は「無駄な `cat`」と呼ばれる典型的な書き方です。
