# _tools — 目次の生成と品質チェック

このフォルダには、リポジトリを管理するための **Python スクリプト 4 本とデータ** が入っています。
**目次と README は `gen_index.py` が作る生成物**なので、手で編集しません。
**ノートそのものではないので、読み物としては読まなくて大丈夫**です。

| ファイル | 役割 |
|:--|:--|
| **`gen_index.py`** | **`README.md` と各フォルダの `00_このフォルダにあるもの.md` を生成する** |
| **`check.py`** | **リンク切れ・目次アンカー・コマンドのコメント漏れ・行数・証跡の記録漏れを検査する** |
| **`index_notes.py`** | **既存ノートの索引を作る。「この論点はもう書いてあるか」を 3 段階で調べるため** |
| **`add_shouseki.py`** | **処理した証跡を、TSV から `gen_index.py` の対応表へまとめて書き足す** |
| `roadmap.json` | Ping-t の学習ロードマップ（全 133 項目）のデータ |
| `notes_index.json` | `index_notes.py` が生成。機械用の索引（`by_command` / `by_term` / **`by_headline`**） |
| `notes_outline.md` | `index_notes.py` が生成。人間用の一覧（全ノートの見出しとコマンド） |

---

## 前提

**Python 3 が入っていれば動きます。** 追加のライブラリは要りません。

```bash
$ python3 --version                  # バージョンを確認する（3.8 以上なら動く）
Python 3.11.2
```

Windows では `python3` ではなく `python` の場合があります。

```powershell
> python --version                   # Windows の場合
```

## 使い方

**どのディレクトリから実行しても構いません。** スクリプトが自分の位置からリポジトリのルートを判断します。

### 目次を作り直す

```bash
$ python3 _tools/gen_index.py        # README.md と各フォルダの目次を再生成する
ok: 41 files
```

**上書きされるのは目次だけ**です。ノート本体（`メタキャラクタとクォート.md` など）は触りません。

| 生成されるもの | 内容 |
|:--|:--|
| `README.md` | テーマ一覧、全 133 項目のチェックリスト、ノートの書き方ルール、証跡の対応表 |
| `各フォルダ/00_このフォルダにあるもの.md` | そのフォルダのノート一覧と、学習項目の進捗（✅ / 🔶 / ⬜） |

### 品質をチェックする

```bash
$ python3 _tools/check.py            # 検査を実行する
リンク切れ: なし
目次アンカー不整合: なし

コマンドの連結と制御演算子.md   457行  コマンド  47  コメント無し  0
コマンド履歴.md                616行  コマンド  64  コメント無し  0
（略）
```

**5 つを検査します。**

| 検査項目 | 何を見るか | 終了コード |
|:--|:--|:--|
| **リンク切れ** | ノート間のリンク先ファイルが**実在するか** | **`1`（失敗）** |
| **目次アンカー不整合** | 目次のリンク（`#見出し名`）が、**実際の見出しと一致するか** | **`1`（失敗）** |
| **コメント漏れ** | ` ```bash ` ブロック内のコマンド行に `#` コメントが付いているか | `0`（警告のみ） |
| **行数** | **900 行**で予告、**1,000 行**（ルールの目安）で分割の合図 | `0`（警告のみ） |
| **証跡の記録漏れ** | `SHOUSEKI` に**記録されていない番号**が無いか | `0`（警告のみ） |

#### 行数は 2 段階で知らせます

行末に **`← そろそろ`**（900 行超）と **`← 分割を検討`**（1,000 行超）が付き、最後にまとめて出ます。

```text
=== 1000 行を超えたノート（ルールの目安。トピック単位で分割する） ===
  マウントとアンマウント.md  1119行  （目安 +119 行）

=== 900 行を超えたノート（次の追記で目安に届く。切れ目を決めておく） ===
  ブートプロセスの全体像.md  927行  （目安まであと 73 行）
```

**900 行の予告があるのは、超えてから割ると手戻りが大きいから**です。
リンクの張り直しと索引の作り直しが発生するので、**超える前に切れ目を決めておきます**。

しきい値は `check.py` の先頭の **`LINE_WARN`** と **`LINE_LIMIT`** で変えられます。
自動生成される `00_このフォルダにあるもの.md` は、行数の検査から除外しています。

#### 証跡の記録漏れ

`SHOUSEKI` に載っている番号の**最小〜最大の範囲**を見て、**抜けている番号**を知らせます。

```text
=== 証跡の対応表に記録が無い番号（処理漏れか、書き戻し漏れの疑い） ===
  PC  18 件  95〜112
  ※ 空フォルダなど、処理しなくてよい番号は check.py の SHOUSEKI_SKIP に足す
```

| 出る理由 | どうするか |
|:--|:--|
| **まだ処理していない証跡がある** | そのフォルダを処理する |
| **処理したのに `SHOUSEKI` へ足し忘れた** | `add_shouseki.py` で足す |
| **空フォルダ・存在しない番号** | `check.py` の **`SHOUSEKI_SKIP`** に足して、以後は黙らせる |

> **まだ着手していない先の番号は対象外**です（記録の最大値より先は見ません）。
> 除外の設定を書き足すときは、**なぜ除外するのかをコメントで残す**こと。

問題があれば、**該当ファイルと行番号つき**で表示されます。

```text
=== コメントの無いコマンド行 ===
  圧縮とアーカイブ.md:565  $ tar czvf app.tar.gz --exclude='*.log' app/
```

**終了コード** … リンク切れか目次アンカー不整合があれば `1`、なければ `0` を返します。

```bash
$ python3 _tools/check.py > /dev/null && echo "OK" || echo "NG"   # 成否だけ知りたいとき
```

## ノートを追加したとき

新しいノートを作ったら、**`gen_index.py` の `NOTES` に 1 行足してから再生成**します。
これをしないと、目次に出てきません。

`gen_index.py` を開いて `NOTES = {` を探し、該当テーマのリストに追記します。

```python
 "01_シェルとコマンドライン": [
  ("メタキャラクタとクォート.md",
   "`*` `?` `[ ]` によるパス名展開、クォート、エスケープ、コマンド置換、展開の順番", [1]),
  # ↑ (ファイル名, 目次に出す一言説明, そのノートが「一通り扱った」学習項目の番号)

  ("新しいノート.md",
   "ここに一言説明を書く", [3]),                        # ← こういう形で足す
 ],
```

**4 つ目の要素で「一部だけ扱った」を表せます。**

```python
  ("ファイルシステムの種類と作成.md",
   "ext4 / XFS / Btrfs / tmpfs の違い、`mkfs`", [], [32]),
   #                                            │    └─ 🔶 一部だけ扱った項目
   #                                            └─ ✅ 一通り扱った項目（今回は無し）
```

| 状態 | 意味 | 書き方 |
|:--|:--|:--|
| ✅ | 一通り扱った | 3 つ目のリストに項目番号を入れる |
| 🔶 | 一部だけ扱った | **4 つ目**のリストに項目番号を入れる |
| ⬜ | まだ書いていない | どちらにも入れない |

**学習項目の番号**は `README.md` の「全 133 項目チェックリスト」で確認できます。

## 書く前に「もう書いてあるか」を調べる

**Ping-t には同じ論点を角度を変えて問う問題が多くあります。**
新しいノートを作る前に、**必ず既存ノートを探す**のがこのリポジトリのルールです。
リポジトリ全体を毎回 `grep` すると取りこぼすので、**索引を引きます**。

```bash
$ python3 _tools/index_notes.py                          # ① 索引を作り直す（ノートを足したら毎回）
ノート 44 本を索引しました（2026-09-14 01:20 JST）
  コマンド 218 種 / 用語 1825 種 / 見出しに出る語 412 種

$ python3 _tools/index_notes.py --find blkid nice dig    # ② 語を渡して、収録されているかを調べる
  blkid                ◎ 本体   → fstabの書き方
  nice                 ○ 言及あり（解説とは限らない。開いて確かめる） → 圧縮とアーカイブ / …
  dig                  ★ 未収録（新規ノートの候補）
```

**判定は 3 段階です。**

| 出た結果 | 意味 | どうするか |
|:--|:--|:--|
| **◎ 本体** | **見出し・小見出し・ファイル名にその語がある** | そのノートが解説の本体。**観点が足りなければその節にだけ追記**する |
| **○ 言及あり** | **本文や例文に出てくるだけ**。解説してあるとは限らない | **必ず開いて確かめる。** 解説が無ければ**未収録と同じ扱い**にする |
| **完全一致なし。近い語を含むノート** | 表記ゆれの可能性がある | 挙がったノートを開いて確かめる |
| **★ 未収録** | どこにも無い | **新しいノートを作る候補**。テーマフォルダの `00_このフォルダにあるもの.md` も見て決める |

> **「○ 言及あり」を「既出」と読み違えないこと。**
> 例えば `nice` は `圧縮とアーカイブ` の例文にたまたま出てくるだけで、解説はされていません。
> **この区別があるのは、実際にこの取りこぼしが起きたから**です。

**「本体」をどう判定しているか**

| 拾う場所 | 例 |
|:--|:--|
| 見出し（`#` 〜 `####`） | `### mpstat のよく使うオプション` → `mpstat` |
| **太字で始まり、先頭がインラインコードの行**（小見出しとして使っている） | ``**`blkid` … ブロックデバイスの情報を表示する**`` → `blkid` |
| ファイル名 | `systemctl_結果画面の見方.md` → `systemctl` |

地の文の強調（``**これらは `kill` してはいけません。**``）は**拾いません**。
**先頭がインラインコードかどうか**で、小見出しと強調を区別しています。

**人が読む一覧は `notes_outline.md`** です。全ノートの見出しと扱うコマンドが並んでいるので、
「このテーマはどこまで書いたか」を眺めるときはこちらが早いです。

```bash
$ grep -n "lvcreate" _tools/notes_index.json     # 索引を直接引くこともできる
$ grep -n "^### " _tools/notes_outline.md        # ノートの題名だけ並べる
```

> **索引は生成物です。** ノートを足したり分割したりしたら、**`index_notes.py` を実行し直す**まで古いままになります。

## 証跡を処理したとき

`gen_index.py` の `SHOUSEKI` に 1 行足すと、`README.md` の「取り込み済みの証跡」表に反映されます。

```python
 ("PC", 80, "問われた内容をここに書く", "新規作成",
  "01_シェルとコマンドライン/ノート名.md"),
 #  │    │                              │       └─ 取り込み先のパス
 #  │    │                              └─ 「新規作成」「既存ノートへ追記」「**既出**（追加なし）」
 #  │    └─ 証跡の番号
 #  └─ 取得元（"PC" または "Drive"）
```

**ここが「どこまで処理したか」の記録**になります。次に作業するときの起点になるので、必ず更新します。

### まとめて処理したときは TSV から流し込む

10 件 20 件とまとめて処理したときに手で編集すると、取りこぼします。
**タブ区切りのファイルを用意して `add_shouseki.py` に渡す**と、番号順に並べて書き足してくれます。

```bash
$ cat 追加分.tsv                     # 5列（取得元 / 番号 / 内容 / 扱い / 取り込み先）
PC	269	`mount` の主なオプション	既存ノートへ追記	06_ストレージとファイルシステム/マウントとアンマウント.md
PC	270	`lvcreate` で論理ボリュームを作る	新規作成	06_ストレージとファイルシステム/LVM.md

$ python3 _tools/add_shouseki.py 追加分.tsv --dry-run   # 何が起きるか先に見る
$ python3 _tools/add_shouseki.py 追加分.tsv             # 実際に書き足す
```

| 守ってくれること | 内容 |
|:--|:--|
| **番号の重複** | すでに登録済みの番号は**飛ばす**。TSV の中の重複は**エラーで止める** |
| **取り込み先の実在** | パスが無ければ**エラーで止める**（打ち間違いでリンク切れを作らない） |
| **並び順** | 取得元ごとに**番号順へ並べ直す**ので、どこに挿しても崩れない |
| **壊れた書き換えの防止** | 書き換え後に Python として読めるか・件数が合うかを確かめ、**駄目なら保存しない** |

> **「扱い」は `新規作成` / `既存ノートへ追記` / `既出` の 3 つ**で書きます。
> `既出` と書けば、表では `**既出**（追加なし）` に置き換わります。

## いつもの流れ

```bash
$ python3 _tools/index_notes.py --find <語>   # ① 書く前に、既出かどうかを調べる
                                              #    （ここでノートを書く）
$ python3 _tools/add_shouseki.py 追加分.tsv   # ② 処理した証跡を対応表に足す
$ python3 _tools/index_notes.py               # ③ 索引を作り直す
$ python3 _tools/gen_index.py                 # ④ 目次と README を作り直す
$ python3 _tools/check.py                     # ⑤ 検査する
$ git add -A                                  # ⑥ 変更をすべてステージする
$ git commit -m "docs: 証跡 269〜280 を反映"   # ⑦ コミットする
$ git push                                    # ⑧ GitHub へ push する
```

## 注意

| 項目 | 内容 |
|:--|:--|
| **`gen_index.py` は目次を上書きします** | ノート本体は触りませんが、`README.md` と `00_このフォルダにあるもの.md` を**手で編集しても次回の実行で消えます**。直したいときは**スクリプト側**を直します |
| **`roadmap.json` は編集しない** | Ping-t のロードマップ Excel から起こしたデータです。書き換えると項目数の検証（133 件）でエラーになります |
| **`_tools` は検査対象外** | `check.py` は `_tools` / `_deploy` / `_to_delete` を検査しません |
