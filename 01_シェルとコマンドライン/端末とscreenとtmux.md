## 端末とは何か

**Linux はマルチユーザ・マルチタスクの OS** です。
**複数の人が同時にログインして、それぞれ別の作業ができます。**

**その入出力の窓口が「端末（ターミナル）」**です。

```text
   人 ──[キーボード  ]──▶ 端末 ──▶ シェル ──▶ カーネル
      ◀──[ディスプレイ]── 端末 ◀── シェル ◀── カーネル
```

**もともとは物理的な機械でした。** キーボードと画面だけを持ち、
本体（メインフレーム）にケーブルでつながっている装置です。
**いまは同じ役割をソフトウェアが担っています。**

### 端末の種類

| 種類 | 実体 | デバイスファイル |
|:--|:--|:--|
| **コンソール** | **実機のキーボードとディスプレイ** | `/dev/tty1` 〜 `/dev/tty6` |
| **擬似端末（pty）** | **SSH 接続や端末エミュレータ** | `/dev/pts/0` `/dev/pts/1` … |

**端末を持たないプロセス（デーモン）**は、`ps` の `TTY` 欄が **`?`** になります。

**実機で操作するときは `getty`（`agetty` / `mingetty`）が入出力を制御**し、
ログイン画面を出しています。

**リモートから接続するときは、手元の端末プログラムが窓口**になります。

| 端末プログラム | 備考 |
|:--|:--|
| **Tera Term** | Windows の定番。SSH に対応 |
| **PuTTY** | Windows / Linux。軽量 |
| `telnet` | **暗号化されないので、いまは使わない** |
| Windows Terminal / macOS Terminal | OS 付属 |

**これらは「手元の窓口」**であって、**サーバ側の仮想端末とは別のもの**です。
混同しやすいので、次の節で切り分けます。

### 自分の端末を確かめる

```bash
$ tty                                 # いまの端末のデバイスファイルを表示する
/dev/pts/0
$ who                                 # ログイン中のユーザと端末を一覧する
shun     pts/0        2026-09-19 15:30 (192.168.1.10)
$ w                                   # 端末ごとに「何をしているか」まで見る
```

**この出力は SSH でログインしたときの例**です。
**端末を持たない環境（コンテナや `cron` の中）では `tty` が `not a tty` になり、
`who` は何も出しません。**

**`ps` の `TTY` 列も同じもの**です。
**`?` はデーモン（端末を持たないプロセス）**を表します
（[プロセスの確認 ps](../04_プロセスとリソース管理/プロセスの確認_ps.md)）。

## 端末が切れると何が起きるか

**端末が切れると、その端末につながっていたプロセスに `SIGHUP`（1）が送られます。**
**HUP は hang up（電話を切る）の略**です。

```text
   回線が切れる
        │
        ▼
   端末が消える
        │
        ▼
   SIGHUP が送られる  ──▶  シェルが終了  ──▶  子プロセスも道連れ
```

**踏み台越しに 1 時間かかる作業を流している最中に回線が切れると、
作業が途中で死にます。** これが実務でいちばん痛いパターンです。

**対策は 2 系統**あります。

| 方法 | 考え方 |
|:--|:--|
| **`nohup` / `disown`** | **プロセスを SIGHUP から守る**（画面は戻ってこない） |
| **`screen` / `tmux`** | **端末そのものをサーバ側に作り置きする**（**画面ごと戻ってくる**） |

**途中経過を見たい作業では、`screen` / `tmux` が圧倒的に有利**です。

## 仮想端末制御プログラム

**`screen` と `tmux` は、1 つの端末の上に複数の仮想端末を作るプログラム**です。
**端末マルチプレクサ（terminal multiplexer）**とも呼びます。

**できることは 3 つ**です。

| 機能 | 何が嬉しいか |
|:--|:--|
| **デタッチ / アタッチ** | **接続が切れても作業が生き残り、あとから画面ごと戻れる** |
| **画面分割** | 1 つの接続で、ログ監視と作業を並べて見られる |
| **複数ウィンドウ** | タブのように切り替えられる |

```text
      手元の端末（Tera Term など）
                │  SSH
                ▼
   ┌────────────────────────────┐
   │  サーバ上の screen / tmux  │ ← ここが生き残る
   │  ┌──────────┐┌──────────┐  │
   │  │仮想端末0 ││仮想端末1 │  │
   │  │ 作業中   ││ tail -f  │  │
   │  └──────────┘└──────────┘  │
   └────────────────────────────┘
```

### デタッチとアタッチ

**この 2 語が試験でも実務でも要**です。

| 用語 | 意味 |
|:--|:--|
| **デタッチ（detach）** | **仮想端末を動かしたまま切り離す**。プロセスは動き続ける |
| **アタッチ（attach）** | **切り離した仮想端末に、あとからつなぎ直す** |

**別のマシンからアタッチすることもできます。**
会社で流した処理に、帰宅後に自宅からつなぎ直す、といった使い方ができます。

```text
   ① 作業を始める        screen / tmux を起動 → 中で作業
   ② 切り離す            デタッチ（作業は動き続ける）
   ③ 回線が切れる        ← 影響なし
   ④ つなぎ直す          SSH し直して アタッチ → 画面がそのまま戻る
```

## screen

**GNU screen は古くからある端末マルチプレクサ**です。
**RHEL 7 までは標準で入っていました**（RHEL 8 以降は別リポジトリになっています）。

```text
screen [オプション] [コマンド]
```

### screen の基本操作

| やりたいこと | コマンド |
|:--|:--|
| **新しいセッションを始める** | **`screen`** |
| **名前を付けて始める** | **`screen -S 名前`** |
| **一覧を見る** | **`screen -ls`** |
| **アタッチする** | **`screen -r 名前`** |
| **強制的に奪ってアタッチする** | `screen -dr 名前` |
| 起動だけしてデタッチしたままにする | `screen -dmS 名前 コマンド` |
| 外から終了させる | `screen -S 名前 -X quit` |

```bash
$ screen -dmS work bash -c 'sleep 300'   # デタッチした状態で起動する
$ screen -ls                             # 一覧を見る
There is a screen on:
	702.work	(09/19/26 16:31:36)	(Detached)
1 Socket in /run/screen/S-shun.
```

**`702.work` の `702` は PID**、**`work` が付けた名前**です。
**`(Detached)` は切り離し済み**、**`(Attached)` は誰かがつないでいる**状態を表します。

**セッションの中での操作は、すべて `Ctrl+a` から始まります。**

| キー操作 | 意味 |
|:--|:--|
| **`Ctrl+a` → `d`** | **デタッチする**（detach） |
| **`Ctrl+a` → `c`** | **新しいウィンドウを作る**（create） |
| **`Ctrl+a` → `n`** | **次のウィンドウへ**（next） |
| **`Ctrl+a` → `p`** | **前のウィンドウへ**（previous） |
| `Ctrl+a` → `"` | ウィンドウ一覧から選ぶ |
| `Ctrl+a` → `S` | 画面を上下に分割 |
| `Ctrl+a` → `\|` | 画面を左右に分割 |
| `Ctrl+a` → `?` | ヘルプ |

**`Ctrl+a` は「これから screen への指示です」という合図**です。
**bash の「行頭へ移動」も `Ctrl+a`** なので、**screen の中では 2 回押す**（`Ctrl+a` → `a`）必要があります。

## tmux

**tmux は screen とは別系統の、独立した実装の端末マルチプレクサ**です。
**screen の fork ではなく、キー操作にも互換性はありません。**

ただし **Red Hat は RHEL 8 で `screen` を非推奨とし、置き換えとして `tmux` を挙げています。**
「後継」と呼ばれるのはこの経緯によるものです。
**設定が素直で、画面分割が扱いやすい**のが利点です。

```text
tmux [サブコマンド] [オプション]
```

### tmux の基本操作

| やりたいこと | コマンド |
|:--|:--|
| **新しいセッションを始める** | **`tmux`** |
| **名前を付けて始める** | **`tmux new -s 名前`** |
| **一覧を見る** | **`tmux ls`**（`tmux list-sessions`） |
| **アタッチする** | **`tmux a -t 名前`**（`tmux attach -t 名前`） |
| 起動だけしてデタッチしたままにする | `tmux new -d -s 名前 'コマンド'` |
| 外から終了させる | `tmux kill-session -t 名前` |
| 全部終了させる | `tmux kill-server` |

```bash
$ tmux new -d -s work 'sleep 300'     # デタッチした状態で起動する
$ tmux new -d -s db 'sleep 300'       # もう1つ起動する
$ tmux ls                             # 一覧を見る
db: 1 windows (created Sat Sep 19 16:31:42 2026)
work: 1 windows (created Sat Sep 19 16:31:42 2026)
```

**セッションの中での操作は、すべて `Ctrl+b` から始まります。**

| キー操作 | 意味 |
|:--|:--|
| **`Ctrl+b` → `d`** | **デタッチする** |
| **`Ctrl+b` → `c`** | **新しいウィンドウを作る** |
| **`Ctrl+b` → `n`** / **`p`** | **次 / 前のウィンドウへ** |
| **`Ctrl+b` → `数字`** | その番号のウィンドウへ |
| **`Ctrl+b` → `"`** | **画面を上下に分割**（ペイン） |
| **`Ctrl+b` → `%`** | **画面を左右に分割**（ペイン） |
| `Ctrl+b` → `矢印` | ペインを移動 |
| `Ctrl+b` → `w` | ウィンドウ一覧から選ぶ |
| `Ctrl+b` → `?` | ヘルプ |

**screen の `Ctrl+a` に対して、tmux は `Ctrl+b`** です。
**ここを取り違えると何も反応しない**ので、まずこの 1 文字を覚えてください。

## 結果画面の見方

**セッション一覧の読み方**が、この 2 つを使ううえでいちばん大事です。

**screen -ls**

```text
There is a screen on:
	702.work	(09/19/26 16:31:36)	(Detached)
1 Socket in /run/screen/S-shun.
```

```text
   702  .  work     (09/19/26 16:31:36)    (Detached)
    │       │                │                  │
    │       │                │                  └─ 状態
    │       │                └──────────────────── 作成日時
    │       └───────────────────────────────────── セッション名（-S で付けた名前）
    └───────────────────────────────────────────── screen プロセスの PID
```

| 表示 | 意味 |
|:--|:--|
| **`(Detached)`** | **切り離されている**。`screen -r` でそのままアタッチできる |
| **`(Attached)`** | **誰かがつないでいる**。奪うには `screen -dr` |
| `(Multi)` | マルチユーザモードで動いている |
| `(Dead ???)` | 異常終了して残骸になっている。`screen -wipe` で掃除する |

**最終行の `1 Socket in …` は、ソケットの置き場と個数**です。
既定は `/run/screen/S-ユーザ名`（古い環境では `/var/run/screen/S-ユーザ名`）で、
**環境変数 `SCREENDIR` で変えられます。**

**tmux ls**

```text
db: 1 windows (created Sat Sep 19 16:31:42 2026)
work: 1 windows (created Sat Sep 19 16:31:42 2026)
```

```text
   work  :  1 windows  (created Sat Sep 19 16:31:42 2026)
     │          │                     │
     │          │                     └─ 作成日時
     │          └─────────────────────── そのセッションのウィンドウ数
     └────────────────────────────────── セッション名
```

**`tmux ls` は PID を出しません。** 名前で指定するのが基本です。
**アタッチ中のセッションには末尾に `(attached)` が付きます。**

| | **`screen -ls`** | **`tmux ls`** |
|:--|:--|:--|
| PID | **出る**（`702.work`） | **出ない** |
| 状態 | **`(Detached)` / `(Attached)`** | **`(attached)` が付くかどうか** |
| ウィンドウ数 | 出ない | **出る**（`1 windows`） |
| ソケットの置き場 | **最終行に出る** | 出ない（`/tmp/tmux-UID/`） |

## screen と tmux の比較

| | **`screen`** | **`tmux`** |
|:--|:--|:--|
| 操作の起点 | **`Ctrl+a`** | **`Ctrl+b`** |
| 登場 | **1987 年、ベルリン工科大学**（のちに GNU プロジェクトへ移管） | **2007 年**、Nicholas Marriott（OpenBSD 由来） |
| 画面分割 | できる（やや扱いにくい） | **できる（扱いやすい）** |
| 設定ファイル | `~/.screenrc` | `~/.tmux.conf` |
| セッション一覧 | `screen -ls` | `tmux ls` |
| 古い環境での可用性 | **高い**（RHEL 7 まで標準） | 環境による |
| 今後 | 保守中心 | **活発に開発中** |

**新しく覚えるなら tmux**、
**古い環境に入るなら screen も知っておく**、というのが実務的な落としどころです。

**試験では「1 つの端末上で複数の仮想端末を扱えるプログラムはどれか」という形で、
`screen` と `tmux` の 2 つを選ばせる問題**が出ます。

**紛らわしい名前**

| 名前 | 正体 |
|:--|:--|
| `monit` | **プロセスやサービスの監視ツール**。端末マルチプレクサではない |
| `tux` | Linux のマスコット（コマンドではない） |
| `multiterm` | 該当するコマンドは無い |

## nohup との使い分け

**どちらも「切れても死なない」を実現しますが、狙いが違います。**

| | **`nohup` / `disown`** | **`screen` / `tmux`** |
|:--|:--|:--|
| 守るもの | **プロセス** | **端末そのもの** |
| 画面に戻れるか | **戻れない**（ログを見るだけ） | **戻れる**（続きから操作できる） |
| 対話的な作業 | **できない** | **できる** |
| 事前の準備 | 不要 | **先に起動しておく必要がある** |
| 向いている仕事 | **出力をファイルに落として流しっぱなしにする処理** | **途中で判断が要る作業・復旧対応** |

```bash
$ nohup ./batch.sh > batch.log 2>&1 &      # 流しっぱなしでよいとき
$ tmux new -s maint                        # 途中で判断が要るとき
```

**`yum update` や `fsck` のように、途中で確認を求められる作業は `tmux` 一択**です。

## 実務での使い方

**踏み台サーバにログインしたら、作業の前にまず仮想端末を立てる**のが基本動作です。

```bash
$ ssh bastion                         # ① 踏み台に入る
$ tmux new -s maint-20260919          # ② 日付入りの名前で起動する
                                      # ③ ここで作業する。回線が切れても生き残る
                                      # ④ 席を立つときは Ctrl+b → d でデタッチ（キー操作）
$ exit                                # ⑤ SSH を切る

# 後日、別のマシンから
$ ssh bastion                         # ⑥ 別のマシンから踏み台に入り直す
$ tmux ls                             # ⑦ 残っているセッションを確認する
maint-20260919: 2 windows (created Sat Sep 19 16:31:42 2026)
$ tmux a -t maint-20260919            # ⑧ 続きから再開する
```

**セッション名に日付や作業名を入れておく**と、
**`tmux ls` を見ただけで「何の作業が残っているか」が分かります**。

**画面分割の定番の使い方**

```text
   ┌──────────────────┬──────────────────┐
   │                  │                  │
   │   作業する側     │  tail -f でログ  │
   │                  │  を流しっぱなし  │
   │                  │                  │
   └──────────────────┴──────────────────┘
        Ctrl+b → %  で左右に分ける
```

**設定変更とログ確認を同時に見られる**ので、
**「変更した瞬間に何が起きたか」が分かる**のが最大の利点です。

**注意 … 放置しないでください**

デタッチしたセッションは **ログアウトしても残り続けます**。
**作業が終わったら `exit` でちゃんと閉じてください。**
残ったセッションには、**同じアカウントを共有している人**（踏み台の共有運用アカウントなど）や
**root が `screen -dr` / `tmux a` で入れてしまいます**。

**別のユーザからは、既定では入れません。**
ソケットの置き場は `0700`、ソケット自体は所有者のみのパーミッションになっています。

```bash
$ ls -ld /run/screen/S-shun           # ディレクトリは 0700
drwx------ 2 shun shun 60 Sep 19 16:31 /run/screen/S-shun
```

```bash
$ tmux ls                             # 残っていないか確認する
$ tmux kill-session -t 名前           # 不要なセッションを閉じる
```
