## まずこれだけ

| 記号 | 打ち消す範囲 | 中で生きるもの |
|:--|:--|:--|
| **`'` シングルクォート** | **囲んだ全部**を文字列にする | **何も生きない**（`$` も `` ` `` もただの文字） |
| **`"` ダブルクォート** | **一部だけ**打ち消す | **`$` `` ` `` `\` `!`** は生きる（変数やコマンド置換が働く） |
| **`\` バックスラッシュ** | **直後の 1 文字だけ** | — |
| **`` ` `` / `$( )`** | 打ち消さない。**コマンドの実行結果を貼る** | — |
| **`$VAR` / `${VAR}`** | 打ち消さない。**変数の中身を貼る** | — |

**外しやすい 3 点**

| 論点 | 結論 |
|:--|:--|
| **変数は必ず `"$VAR"` と書く** | クォートしないと、**スペースで単語が割れる**／中身のワイルドカードが展開される |
| **`\` は自分自身も消える** | `\` そのものを出したいなら **`\\`** と 2 つ重ねる |
| **`'` の中では `\` も効かない** | シングルクォートの中に `'` は書けない。いったん閉じて `\'` を足す |

## 変数の展開

`$変数名` と書くと、変数に格納されている値に置き換わります。

```bash
$ NAME=shun                         # シェル変数 NAME に値を入れる
$ echo $NAME                        # $ を付けると中身が取り出される
shun

$ echo $HOME                        # 最初から用意されている変数（ホームディレクトリ）
/home/shun
```

**補足** … 変数名の直後に文字を続けるときは `${ }` で区切りを明示します。

```bash
$ echo $NAMEsan                     # 「NAMEsan」という別の変数を探すので空になる

$ echo ${NAME}san                   # { } でどこまでが変数名かを示す
shunsan
```

> 変数そのものの詳しい話（シェル変数と環境変数の違い、`export` など）は
> [シェル変数と環境変数](./シェル変数と環境変数.md) を参照してください。

## クォートでメタキャラクタを打ち消す

---

### シングルクォート

**意味** … `'` で囲まれた部分を文字列と見なす（メタキャラクタの意味を打ち消す）

**例文**

```bash
$ echo '$HOME is my home'           # $ が打ち消されて展開されない
$HOME is my home

$ echo '*'                          # ワイルドカードも打ち消される
*

$ echo 'today is `date`'            # バッククォートも実行されない
today is `date`

$ echo '~'                          # チルダも展開されない
~
```

**補足** … 打ち消しに**例外はありません**。`$` も `` ` `` も `\` も `~` もすべて文字になります。

ただし、**中にシングルクォートは書けません**。
バックスラッシュでエスケープしても無効なので、いったん閉じて連結します。

```bash
$ echo 'it'\''s ok'                 # 「it」+ エスケープした' + 「s ok」を連結
it's ok
```

---

### ダブルクォート

**意味** … `"` で囲まれた部分を文字列と見なす。
ただし `$` `` ` `` `\` `"` は特別な意味を保つ

| 文字 | ダブルクォート内での扱い |
|:--|:--|
| `$` | 変数展開・コマンド置換 `$( )` が**行われる** |
| `` ` `` | コマンド置換が**行われる** |
| `\` | 直後が `$` `` ` `` `"` `\` **改行** のときだけエスケープとして働く |
| `!` | ヒストリ展開が有効な場合（対話シェルの既定）に**展開される** |
| `*` `?` `[ ]` `~` | 打ち消される（展開されない） |

**例文**

```bash
$ NAME=shun                         # 確認用に変数を用意

$ echo "$NAME"                      # $ は生きているので展開される
shun

$ echo '$NAME'                      # シングルクォートなら展開されない
$NAME

$ echo "today is `date +%F`"        # バッククォートも生きているので実行される
today is 2026-08-27

$ echo "*"                          # ワイルドカードは打ち消される
*

$ echo "~"                          # チルダも打ち消される（展開されない）
~

$ echo "price is \$100"             # \ でエスケープすれば $ も打ち消せる
price is $100

$ echo "path is C:\temp"            # \t は特別扱いされないのでそのまま残る
path is C:\temp
```

**補足 … 変数参照は原則 `"$VAR"` と書く**

変数の値にスペースが入る場合、クォートしないと**単語分割**されて別々の引数になります。
シェルスクリプトのバグの大半はこれが原因です。

```bash
$ FILE="my report.txt"              # スペースを含むファイル名を変数に入れる

$ rm $FILE                          # → rm my report.txt （2ファイル扱いになり失敗）
$ rm "$FILE"                        # → rm 'my report.txt' （1ファイルとして正しく渡る）
```

### 三つのクォートの比較

同じ文字列を 3 通りで囲むと、何が展開されるかがはっきり分かります。

```bash
$ NAME=shun                         # 変数に値を入れる
$ echo ~/$NAME/*.txt                # クォートなし → すべて展開される
/home/shun/shun/a.txt /home/shun/shun/b.txt

$ echo "~/$NAME/*.txt"              # ダブルクォート → $ だけ生きる
~/shun/*.txt

$ echo '~/$NAME/*.txt'              # シングルクォート → 何も展開されない
~/$NAME/*.txt
```

| 展開の種類 | クォートなし | `"..."` | `'...'` |
|:--|:-:|:-:|:-:|
| チルダ展開 `~` | ○ | × | × |
| 変数展開 `$VAR` | ○ | **○** | × |
| コマンド置換 `` ` `` `$( )` | ○ | **○** | × |
| パス名展開 `*` `?` `[ ]` | ○ | × | × |
| エスケープ `\` | ○ | **一部○** | × |

**使い分けの目安**

| やりたいこと | 書き方 |
|:--|:--|
| 変数の値を渡したい | `"$VAR"` |
| 文字をそのまま渡したい（正規表現やパターン） | `'...'` |
| ファイル名を展開させたい | クォートなし |

## コマンド置換

`` `コマンド` `` は、コマンドを実行してその**標準出力を文字列として埋め込みます**。

```bash
$ echo "今日は `date +%F` です"      # date の実行結果が文中に埋め込まれる
今日は 2026-08-27 です

$ FILE_COUNT=`ls | wc -l`           # ls の行数を数えて変数に入れる
$ echo $FILE_COUNT                  # 数えた結果を確認
5
```

### 変数に入れたコマンドも実行される

「`` ` ``」で囲まれた文字列が**変数の場合は、変数に格納されている値**がコマンドと見なされます。
`$` と `` ` `` の**両方**が効くため、次の 2 段階で評価されます。

```bash
$ DATE=date                         # 変数に「date」という文字列を入れる

$ echo $DATE                        # 変数展開だけ → 中身の文字列がそのまま出る
date

$ echo `$DATE`                      # 変数展開 → コマンド置換の2段階で実行される
2026年  8月 27日 木曜日 23:24:40 JST
```

| 順番 | 処理 | 結果 |
|:-:|:--|:--|
| 1 | 変数展開 … `$DATE` を中身に置き換える | `` `date` `` |
| 2 | コマンド置換 … `` ` `` の中身をコマンドとして実行する | `2026年 8月 27日 …` |
| 3 | `echo` がその文字列を表示する | `2026年 8月 27日 …` |

書き方による違いを並べると、どこで何が起きているかが見えます。

```bash
$ echo DATE                         # $ が無いのでただの文字列
DATE

$ echo '$DATE'                      # ' が $ を打ち消す
$DATE

$ echo $DATE                        # 変数展開だけが起きる
date

$ echo `$DATE`                      # 変数展開 → コマンド置換
2026年  8月 27日 木曜日 23:24:40 JST
```

**補足** … 変数名は大文字小文字を区別します。`$date`（小文字）は `$DATE` とは**別の変数**です。
未定義なので参照しても空文字になります。

```bash
$ echo "[$date]"                    # 小文字の date という変数は定義していない
[]

$ echo "[$DATE]"                    # 大文字なら値が入っている
[date]
```

### 実務では `$( )` を使う

同じ動作を `$( )` でも書けます。**実務では `$( )` が推奨**です。

```bash
$ echo "今日は $(date +%F) です"     # バッククォートと同じ結果になる
今日は 2026-08-27 です
```

**理由1 … 入れ子にできる**

```bash
$ echo "$(dirname "$(readlink -f "$0")")"    # スクリプト自身が置かれた場所を求める
/home/shun/bin

$ echo "`dirname \"\`readlink -f $0\`\"`"     # 同じことをバッククォートで書いた場合
```

上の例は内側から順に、次のように処理されています。

| 順番 | 部分 | やっていること |
|:-:|:--|:--|
| 1 | `$0` | 実行中のスクリプト自身のパス（例 `./bin/run.sh`） |
| 2 | `readlink -f "$0"` | シンボリックリンクを解決して絶対パスにする |
| 3 | `dirname "..."` | パスからファイル名を除いてディレクトリ部分だけ取り出す |

**理由2 … 見分けやすい**

`` ` ``（バッククォート）と `'`（シングルクォート）は、フォントによってはほぼ同じに見えます。
`$( )` なら誤読の余地がありません。

## バックスラッシュによるエスケープ

**意味** … 次の文字（メタキャラクタ）の意味を打ち消して通常の文字として扱う

```bash
$ echo \$HOME                       # $ を打ち消すので変数展開されない
$HOME

$ echo \*                           # * を打ち消すのでファイル名に展開されない
*

$ touch "my file.txt"               # スペース入りのファイルを用意
$ ls my\ file.txt                   # スペースをエスケープして1つの名前として渡す
my file.txt
```

### 打ち消したあと `\` 自身は消える

`\` は「直後の 1 文字を打ち消す」記号なので、役目を終えると消えます。
`\w` は単なる `w` になります。

```bash
$ echo \w                           # \ が消えて w だけが残る
w
```

### `\` そのものを書くには 2 つ重ねる

**`\` 自身をエスケープするには `\\` と 2 つ重ねます。**

```bash
$ echo \\                           # \ を2つ書くと \ が1つ出力される
\

$ echo \\w                          # \\ が \ になり、そこに w が続く
\w

$ touch back\\slash                 # 「back\slash」という名前のファイルを作る
$ ls                                # 作成されたファイル名を確認
back\slash
```

名前に `\` が入るディレクトリを作る場合も同じです。

```bash
$ pwd                               # いまいる場所を確認
/home/staff

$ echo mkdir ~/\\work               # 実行せず、展開後の内容だけ表示して確かめる
mkdir /home/staff/\work

$ mkdir ~/\\work                    # 実行する
$ ls                                # 「\work」ができたことを確認
\work
```

引数がどう組み立てられているかを 1 段ずつ追うと、次のようになります。

| 段階 | 状態 |
|:--|:--|
| 入力 | `~/\\work` |
| `\\` のエスケープ処理 | `\\` → `\` になる |
| チルダ展開（`~` の直後が `/`） | `~` → `/home/staff` |
| **`mkdir` が受け取る引数** | `/home/staff/\work` |

**書き方を変えると結果が変わります。**

| 書き方 | `~` の展開 | `\\` → `\` | `mkdir` に渡る引数 |
|:--|:-:|:-:|:--|
| `~/\\work` | ○ | ○ | `/home/staff/\work` |
| `~/\work` | ○ | — （`\w` → `w`） | `/home/staff/work` |
| `"~/\\work"` | × | ○ | `~/\work` |
| `'~/\\work'` | × | × | `~/\\work` |
| `~\\work` | ×（`/` が続かない） | ○ | `~\work` |

```bash
$ echo mkdir ~/\work                # \ が消えて「work」になる
mkdir /home/staff/work

$ echo mkdir "~/\\work"             # \\ は \ になるが、~ は展開されない
mkdir ~/\work

$ echo mkdir '~/\\work'             # 何ひとつ変換されない
mkdir ~/\\work

$ echo mkdir ~\\work                # ~ が展開されない（後述）
mkdir ~\work
```

**確認のしかた** … `echo` を頭に付けると、シェルが何を渡すのか**実行前に**確認できます。
危険なコマンドを打つ前の定番の安全確認です。

### 行末の `\` は改行をエスケープする

行末に置くと**改行そのもの**をエスケープでき、長いコマンドを複数行に分けられます。
手順書に長いコマンドを載せるときの定番です。

```bash
$ aws ec2 describe-instances \
    --filters "Name=instance-state-name,Values=running" \
    --query 'Reservations[].Instances[].InstanceId' \
    --output text
```
（各行末の `\` が「まだコマンドは続く」という意味になる）

**注意** … `\` の後ろにスペースがあると行継続になりません。見えないバグの温床です。
`cat -A` で行末を確認すると `\$` と見えるはずが `\ $` になっていたら原因はこれです。

## 記法の早見表

| 記法 | 意味 | よく使う場面 |
|:--|:--|:--|
| `$VAR` `${VAR}` | 変数展開 | `echo "$HOME"` |
| `$( )` `` ` ` `` | コマンド置換 | `DATE=$(date +%F)` |
| `'...'` | すべて文字列化 | `grep 'ERROR.*$'` |
| `"..."` | `$` `` ` `` `\` `!` 以外を文字列化 | `echo "$MSG"` |
| `\` | 直後 1 文字をエスケープ／行継続 | `my\ file.txt` |

**どれを使うかの決め方**

```text
中身をそのまま出したい            → '  シングルクォート
変数やコマンドの結果を入れたい    → "  ダブルクォート
1 文字だけ打ち消したい            → \  バックスラッシュ
```

**展開が起きる順番**（`$` と `*` のどちらが先か）は
[パス名展開とワイルドカード](./パス名展開とワイルドカード.md) の「展開が起きる順番」にまとめています。

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| スペース入りファイル名で失敗 | 変数をクォートしていない | 必ず `"$VAR"` と書く |
| `echo $VAR` の結果が空 | 変数名の区切りが曖昧 | `${VAR}` と書く |
| `\` が消えてしまう | `\` は直後を打ち消して自身は消える | `\\` と 2 つ重ねる |
| 行継続の `\` が効かない | `\` の後ろにスペースがある | `cat -A` で行末を確認 |
| `'` の中の変数が展開されない | シングルクォートは `$` も打ち消す | ダブルクォートにする |
| `"` の中で `$` を文字として出したい | ダブルクォートは `$` を生かす | `\$` とエスケープするか `'` にする |
| 変数の中身のワイルドカードが展開される | クォートせずに書いた | `"$PAT"` と囲む |

## クラウド実務メモ

**`aws` コマンドの `--query` はシングルクォートで囲む**

JMESPath 式には `[` `]` `*` `?` が頻出するため、クォートしないとシェルのパス名展開に食われます。

```bash
$ aws ec2 describe-instances --query Reservations[].Instances[].InstanceId   # クォートなし
                                    # NG: [] をシェルが解釈してしまう可能性がある

$ aws ec2 describe-instances --query 'Reservations[].Instances[].InstanceId'   # クォートあり
                                    # OK: クォートで囲んで aws にそのまま渡す
```

**Windows から持ち込んだパスに注意**

Windows のパス区切り `\` は、Linux では**エスケープ記号**です。
`C:\Users\systemi` をそのまま貼ると `\U` `\s` が消えて別物になります。

```bash
$ echo C:\Users\systemi             # \U と \s がエスケープ扱いされて消える
C:Userssystemi

$ echo 'C:\Users\systemi'           # シングルクォートで囲めばそのまま扱われる
C:\Users\systemi
```

**Ansible の `{{ }}` や Terraform の `${}` と混同しない**

それぞれのツールが解釈するもので、シェルの展開とはタイミングが違います。
`ansible -m shell` などシェルを経由する場合は、どちらが先に展開されるかを意識します。

**環境変数を渡すときは `"$VAR"`**

CI やコンテナの起動スクリプトでは、値にスペースや記号が入ることがあります。

```bash
$ docker run -e MSG="$MSG" myimage   # 値にスペースがあっても 1 つの値として渡る
$ docker run -e MSG=$MSG myimage     # NG: スペースで割れて別の引数になる
```
