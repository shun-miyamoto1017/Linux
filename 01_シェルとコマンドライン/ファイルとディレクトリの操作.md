## 一覧を表示する

```bash
$ ls                                # ファイル名だけを表示する
dir1  dir2

$ ls -l                             # 詳細情報つきで表示する
total 8
drwxrwxr-x. 3 test test 4096 Jun  1 14:05 dir1
drwxrwxr-x. 3 test test 4096 Jun  1 14:06 dir2
```

### 主なオプション

| オプション | 意味 |
|:--|:--|
| `-l` | 詳細情報（権限・所有者・サイズ・更新日時）を表示 |
| `-a` | 隠しファイル（`.` で始まるもの）も表示 |
| `-A` | `-a` から `.` と `..` を除く |
| **`-R`** | **ディレクトリ内のファイルやディレクトリを再帰的に表示** |
| `-h` | サイズを人が読みやすい単位（K, M, G）で表示 |
| `-t` | 更新日時順に並べる |
| `-r` | 並び順を逆にする |
| `-S` | サイズ順に並べる |
| **`-d`** | **指定したディレクトリ自身の情報を表示**（中身を展開しない） |
| `-i` | inode 番号を付けて表示 |
| `-F` | 名前の後ろにファイルタイプを示す記号を付ける |

### ディレクトリ自身の情報を見る

**意味** … `-d` を付けると、**ディレクトリの「中身」ではなく「そのディレクトリ自体」**を対象にする

ここは `ls` で最も間違えやすい箇所です。
`ls` にディレクトリ名を渡すと、既定では**その中身が一覧されます**。

**`-d` なし … 中身が出る**

```bash
$ ls -l home                        # home の「中にあるもの」の詳細が出る
total 8
drwxr-xr-x 2 root root 4096 Sep  1 02:37 alice
drwxr-xr-x 2 root root 4096 Sep  1 02:37 bob
```

**`-d` あり … ディレクトリ自身が出る**

```bash
$ ls -dl home                       # home そのものの詳細が1行だけ出る
drwxr-xr-x 4 root root 4096 Sep  1 02:37 home
```

**`/home` ディレクトリの詳細情報「のみ」を見たいなら `ls -dl /home`** になります。

```text
ls -l  /home  … /home の中にある alice, bob … の詳細   （中身が対象）
ls -dl /home  … /home そのものの権限・所有者・日時      （自分が対象）
```

**なぜ `-l` と併用するのか**

- `-d` は「**対象をディレクトリ自身にする**」オプション
- `-l` は「**詳細情報を出す**」オプション

役割が別なので、**両方必要**です。`-d` だけでは名前しか出ません。

```bash
$ ls -d home                        # -l が無いので名前だけ
home
```

`ls -dl` は `ls -d -l` と書いても同じです。短いオプションはまとめて書けます。

**補足 … 実務では「複数ディレクトリの権限を並べて見る」ときに効きます**

```bash
$ ls -dl /var/log /etc/nginx /srv/shared   # 各ディレクトリ自身の権限を並べて確認する
drwxr-xr-x  12 root root   4096 Sep  1 02:37 /etc/nginx
drwxr-xr-x  15 root root   4096 Sep  1 02:37 /var/log
drwxrwsr-x   2 root devteam 4096 Sep  1 02:37 /srv/shared
```

`-d` が無いと 3 つのディレクトリの**中身がずらずらと出てしまい**、
肝心の権限が見えません。権限調査ではほぼ必ず `-d` を付けます。

**補足 … ワイルドカードと組み合わせる**

```bash
$ ls -dl */                         # カレント直下のディレクトリだけを一覧する
drwxr-xr-x 4 root root 4096 Sep  1 02:37 home/
```

`*/` は「末尾がスラッシュのもの」＝ディレクトリだけにマッチするパターンです。
`-d` を付けないと、それぞれの中身が展開されてしまいます。

### ファイルの種類を記号で見分ける

**意味** … `-F` は名前の後ろに**種類を示す 1 文字**を付ける

| 記号 | 意味 |
|:--|:--|
| （なし） | 通常のファイル |
| `*` | 実行可能ファイル |
| `/` | ディレクトリ |
| `@` | シンボリックリンク |
| `\|` | 名前付きパイプ（FIFO） |

```bash
$ ls -F                             # 種類の記号つきで一覧する
exe.sh*  home/  link.txt@  normal.txt  pipe1|
```

**読み方**

| 表示 | 実体 |
|:--|:--|
| `normal.txt` | 記号なし → 通常のファイル |
| `exe.sh*` | `*` → 実行権のあるファイル |
| `home/` | `/` → ディレクトリ |
| `link.txt@` | `@` → シンボリックリンク |
| `pipe1\|` | `\|` → 名前付きパイプ |

**補足** … 記号は**表示のためだけに付いています**。実際のファイル名には含まれません。
`exe.sh*` というファイルがあるのではなく、ファイル名は `exe.sh` です。

**補足 … `ls -l` の先頭 1 文字でも同じことがわかります**

```bash
$ ls -l                             # 行頭の1文字が種類を表す
-rwxr-xr-x 1 root root    0 Sep  1 02:37 exe.sh      # - は通常ファイル
drwxr-xr-x 4 root root 4096 Sep  1 02:37 home        # d はディレクトリ
lrwxrwxrwx 1 root root   10 Sep  1 02:37 link.txt -> normal.txt   # l はシンボリックリンク
prw-r--r-- 1 root root    0 Sep  1 02:37 pipe1       # p は名前付きパイプ
```

| 先頭の文字 | 意味 |
|:--|:--|
| `-` | 通常のファイル |
| `d` | ディレクトリ |
| `l` | シンボリックリンク |
| `p` | 名前付きパイプ |
| `b` / `c` | ブロック／キャラクタデバイス |
| `s` | ソケット |

`-F` は名前だけを短く見たいとき、`-l` は権限も一緒に見たいときに使い分けます。

### 隠しファイルを表示する

**意味** … `-a` はドット `.` で始まるファイルも含めてすべて表示する

```bash
$ ls                                # 既定では隠しファイルは出ない
exe.sh  home  link.txt  normal.txt  pipe1

$ ls -a                             # -a なら隠しファイルも出る
.  ..  .hidden  exe.sh  home  link.txt  normal.txt  pipe1

$ ls -A                             # -A は . と .. を除く
.hidden  exe.sh  home  link.txt  normal.txt  pipe1
```

| オプション | `.hidden` | `.`（カレント） | `..`（親） |
|:--|:-:|:-:|:-:|
| `ls` | ✕ | ✕ | ✕ |
| `-a` | ○ | **○** | **○** |
| `-A` | ○ | ✕ | ✕ |

**補足** … スクリプトでファイルを数えるときは `-A` が便利です。
`-a` だと `.` と `..` の 2 つが必ず混ざり、件数がずれます。

```bash
$ ls -A ~/.ssh | wc -l              # 隠しファイルを数える（. と .. は除く）
```

### inode 番号を表示する

**意味** … `-i` はファイルの管理番号（inode 番号）を先頭に付ける

```bash
$ ls -i normal.txt                  # inode 番号つきで表示する
950371 normal.txt
```

**補足** … **inode 番号が同じファイルは、同じ実体を指すハードリンク**です。
「コピーしたつもりが同じファイルだった」といった調査で使います。

```bash
$ ls -li file1 file2                # 2つの inode 番号を比べる
950371 -rw-r--r-- 2 root root 0 Sep  1 02:37 file1
950371 -rw-r--r-- 2 root root 0 Sep  1 02:37 file2
                └ リンク数が 2 = 同じ実体を指す名前が2つある
```

### 再帰表示で構造を確認する

`-R` オプションはディレクトリ内のファイルやディレクトリを**再帰的に**表示します。

```bash
$ ls                                # まず直下だけ見る
dir1  dir2

$ ls -lR                            # 詳細つきで再帰的に表示する
.:
total 8
drwxrwxr-x. 3 test test 4096 Jun  1 14:05 dir1
drwxrwxr-x. 3 test test 4096 Jun  1 14:06 dir2

./dir1:
total 12
-rw-rw-r--. 1 test test    4 Jun  1 13:40 file1.txt
-rw-rw-r--. 1 test test    4 Jun  1 13:40 file2.txt
drwxrwxr-x. 2 test test 4096 Jun  1 14:05 subdir1

./dir1/subdir1:
total 0

./dir2:
total 4
drwxrwxr-x. 2 test test 4096 Jun  1 13:52 subdir2

./dir2/subdir2:
total 0
```

この出力から、**`dir1` の配下には `file1.txt`・`file2.txt`・`subdir1` があり、
`dir2` の配下には `subdir2` がある**ことがわかります。

**補足 … 出力の読み方**

`./dir1:` のように**パスとコロン**が見出しになり、その下にそのディレクトリの中身が並びます。
`total` はブロック数の合計で、ファイルサイズの合計とは一致しません。

**補足 … `tree` のほうが見やすい**

構造を把握したいだけなら `tree` コマンドが読みやすいです。
ただし**既定ではインストールされていない**ことが多く、試験では `ls -R` が問われます。

```bash
$ tree                              # 木構造で表示する（要インストール）
.
├── dir1
│   ├── file1.txt
│   ├── file2.txt
│   └── subdir1
└── dir2
    └── subdir2

$ sudo dnf install -y tree          # RHEL系でインストールする場合
```

`find` でも同じことができます。こちらはどの環境にも入っています。

```bash
$ find . -type d                    # ディレクトリだけを再帰的に一覧する
.
./dir1
./dir1/subdir1
./dir2
./dir2/subdir2
```

## 作成する

### ファイルを作る

```bash
$ touch file1.txt                   # 中身が空のファイルを作る
$ ls -l file1.txt                   # 作られたことを確認
-rw-rw-r--. 1 test test 0 Aug 31 23:30 file1.txt
```

**補足** … `touch` は本来「タイムスタンプを更新する」コマンドで、
ファイルが無い場合に新規作成する、という位置づけです。
（[ファイルの種類とタイムスタンプ](./ファイルの種類とタイムスタンプ.md) を参照）

### ディレクトリを作る

```bash
$ mkdir dir1                        # ディレクトリを1つ作る
$ mkdir dir2 dir3                   # 複数まとめて作る
```

| オプション | 意味 |
|:--|:--|
| `-p` | **親ディレクトリも含めて**作る。既に存在してもエラーにしない |
| `-m` | 作成時のパーミッションを指定する |
| `-v` | 作成したものを表示する |

```bash
$ mkdir a/b/c                       # 親の a が無いので失敗する
mkdir: cannot create directory 'a/b/c': No such file or directory

$ mkdir -p a/b/c                    # -p なら親ごと作られる
$ find a                            # 作られた構造を確認
a
a/b
a/b/c

$ mkdir -p a/b/c                    # 既に存在してもエラーにならない
```

**補足** … スクリプトの中では `mkdir -p` が定番です。
「既にあってもエラーで止まらない」ため、何度実行しても同じ結果になります。

**`-m` … 作成と同時にパーミッションを指定する**

**意味** … 作ったあとに `chmod` するのではなく、**作る瞬間から指定した権限にする**

```bash
$ mkdir -m 700 dir                  # アクセス権 700 のディレクトリを作る
$ ls -ld dir                        # 権限を確認する
drwx------ 2 root root 4096 Sep  1 02:29 dir
```

**補足 … `-m` を付けないと `umask` が効きます**

`-m` を付けずに作ると、パーミッションは
**`777` から `umask` の値を引いた**ものになります。

```bash
$ umask                             # 現在の umask を確認する
0022

$ mkdir plain                       # -m なしで作る
$ ls -ld plain                      # 777 - 022 = 755 になっている
drwxr-xr-x 2 root root 4096 Sep  1 02:29 plain
```

**`-m` を使うと `umask` を無視して、指定した値そのものになります。**

**なぜ「作ってから chmod」ではダメなのか**

```bash
$ mkdir secret                      # まず 755 で作られる（この瞬間は誰でも読める）
$ chmod 700 secret                  # そのあとで 700 に絞る
```

この 2 行の**あいだのほんの一瞬だけ、他のユーザから中が見える状態**になります。
鍵や証明書を置くディレクトリではこれが問題になるため、`-m` で一発で作ります。

```bash
$ mkdir -m 700 ~/.ssh               # 最初から 700。隙間がない
```

**補足 … `-p` と `-m` を一緒に使うときの注意**

`-m` が効くのは**一番深い（最後の）ディレクトリだけ**です。
`-p` で作られた途中の親ディレクトリには `umask` が適用されます。

```bash
$ mkdir -p -m 700 x/y/z             # z は 700 だが、x と y は 755 になる
```

親も絞りたいなら、階層ごとに `mkdir -m` するか、あとで `chmod` します。

## 削除する

### 空のディレクトリを消す

**`rmdir` は空のディレクトリのみを削除することができるコマンド**です。

```bash
$ mkdir empty_dir                   # 空のディレクトリを作る
$ rmdir empty_dir                   # 削除できる

$ rmdir dir1                        # 中身があるディレクトリを消そうとする
rmdir: failed to remove 'dir1': Directory not empty
```

| オプション | 意味 |
|:--|:--|
| `-p` | ディレクトリ名に階層を指定した場合、**全ての階層のディレクトリを同時に削除**する |
| `-v` | 削除したものを表示する |

**`-p` も「空のディレクトリしか削除できない」制約は同じです。**

```bash
$ mkdir -p x/y/z                    # 3階層のディレクトリを作る
$ rmdir -p x/y/z                    # z → y → x の順に、空なら消していく
$ ls x                              # すべて消えている
ls: cannot access 'x': No such file or directory
```

中身があると、そこで止まります。

```bash
$ rmdir -p dir1/subdir1             # 空の subdir1 は消えるが…
rmdir: failed to remove directory 'dir1': Directory not empty
                                    # ファイルがある dir1 は消せない
```

**`rmdir` に `-r` オプションはありません。**

```bash
$ rmdir -r dir1                     # -r は存在しないオプション
rmdir: invalid option -- 'r'
Try 'rmdir --help' for more information.
```

### 中身ごと消す

**ファイルやディレクトリを削除することができるコマンドは `rm`** です。
**ディレクトリを削除するには「`-r`」オプションが必要**ですが、
**`rm -r` は空ではないディレクトリも削除することができます。**

```bash
$ rm dir1                           # -r なしではディレクトリを消せない
rm: cannot remove 'dir1': Is a directory

$ rm -r dir1                        # -r を付けると中身ごと消える
$ ls -lR                            # dir1 と配下がすべて消え、dir2 だけが残る
.:
total 4
drwxrwxr-x. 3 test test 4096 Jun  1 14:06 dir2

./dir2:
total 4
drwxrwxr-x. 2 test test 4096 Jun  1 13:52 subdir2

./dir2/subdir2:
total 0
```

| オプション | 意味 |
|:--|:--|
| **`-r`** / `-R` | **ディレクトリを再帰的に削除する** |
| `-f` | 確認せず強制的に削除する。存在しなくてもエラーにしない |
| `-i` | 削除前に 1 つずつ確認する |
| `-I` | 3 個以上まとめて消すときだけ確認する |
| `-v` | 削除したものを表示する |
| `-d` | 空のディレクトリを削除する（`rmdir` 相当） |

```bash
$ rm -i file1.txt                   # 確認しながら削除する
rm: remove regular file 'file1.txt'? y

$ rm -rf /tmp/work                  # 確認なしで中身ごと削除する（強力・危険）
```

**補足 … `-f` は「エラーを出さない」効果もあります**

ファイルが無くてもエラーにならないため、スクリプトの後始末で使われます。

```bash
$ rm /tmp/nothing                    # 存在しないとエラーになる
rm: cannot remove '/tmp/nothing': No such file or directory

$ rm -f /tmp/nothing                 # -f なら黙って成功する
$ echo $?                            # 終了ステータスも 0 になる
0
```

**補足 … 一般ユーザでも削除できます**

削除に必要なのは、**そのファイル自身の権限ではなく、置かれているディレクトリの書き込み権限**です。
root でなければ消せない、ということはありません。

```bash
$ ls -ld .                          # カレントディレクトリの権限を確認
drwxrwxr-x. 4 test test 4096 Jun  1 14:06 .
                                    # 所有者 test に w があるので削除できる
```

### 二つの削除コマンドの使い分け

| | `rmdir` | `rm` |
|:--|:--|:--|
| ファイルを消す | ✗ | ○ |
| **空の**ディレクトリを消す | ○ | `-r` または `-d` |
| **中身がある**ディレクトリを消す | ✗ | **`-r`** |
| `-r` オプション | **存在しない** | ある |
| `-p` オプション | ある（空の階層をまとめて削除） | ない |

```bash
$ rmdir dir1                        # 中身があるので失敗
rmdir: failed to remove 'dir1': Directory not empty

$ rm dir1                           # -r が無いので失敗
rm: cannot remove 'dir1': Is a directory

$ rm -r dir1                        # これが正解
```

**補足** … `rmdir` は「うっかり中身ごと消さない」という安全側のコマンドです。
**空だと確信しているときは、あえて `rmdir` を使う**のが事故を減らすコツになります。

## コピーする

```bash
$ cp file1.txt file2.txt            # ファイルをコピーする
$ cp file1.txt /tmp/                # ディレクトリの中へコピーする
```

```text
cp [オプション] コピー元のファイル(ディレクトリ) コピー先ファイル(ディレクトリ)
```

| オプション | 意味 |
|:--|:--|
| `-r` / `-R` | **ディレクトリを再帰的にコピーする**（指定したディレクトリ配下を全てコピー） |
| `-p` | **ファイルの属性（パーミッション、所有者、更新時間など）を保持したままコピー**する<br>※**所有者（ユーザ）を変更できるのは root だけ**。グループは自分が所属していれば一般ユーザでも保持できる |
| `-a` | `-dR --preserve=all` と同じ（**まるごと保持してコピー**） |
| `-i` | 同名のファイルやディレクトリがある場合、上書きするかどうか問い合わせる |
| `-f` | コピー先の既存のファイルやディレクトリが**上書きできない場合、削除してからコピー**する |
| `-n` | 既存ファイルを上書きしない |
| `-u` | コピー元が新しいときだけ上書きする |
| `-v` | コピーしたものを表示する |

```bash
$ cp dir1 dir1_backup               # -r が無いとディレクトリはコピーできない
cp: -r not specified; omitting directory 'dir1'

$ cp -r dir1 dir1_backup            # -r を付ける
$ cp -a /etc/nginx /backup/nginx    # 権限や日時を保ったままバックアップする
```

### 属性を保持してコピーする

**意味** … `-p` を付けると、**パーミッション・所有者・タイムスタンプがコピー元のまま**になる

**`-p` を付けないとどうなるか**

`-p` を指定しない場合、**コピー先の属性は「`cp` を実行したユーザ」のもの**になります。
以下は `test` ユーザが作った `file1` を、**root ユーザが** `file2` という名前でコピーした例です。

```bash
# cp file1 file2                    # -p を付けずにコピーする
# ls -l                             # 属性を比べる
-rw-rw-r-- 1 test claude 6 Feb  1  2026 file1
-rw-r--r-- 1 root root   6 Sep  1 02:29 file2
```

`file2` は `file1` と違い、**所有者が root、権限も日時も変わっています**。

| | 所有者 | パーミッション | 更新時刻 |
|:--|:--|:--|:--|
| `file1`（元） | `test` | `rw-rw-r--` | 2026-02-01 |
| `file2`（`-p` なし） | **root** | **`rw-r--r--`** | **コピーした時刻** |

新しく作られたファイルなので、当然といえば当然です。
所有者は実行ユーザ、パーミッションは `umask`、日時は「いま」になります。

**`-p` を付けた場合**

```bash
# cp -p file1 file3                 # 属性を保持してコピーする
# ls -l                             # 属性を比べる
-rw-rw-r-- 1 test claude 6 Feb  1  2026 file1
-rw-rw-r-- 1 test claude 6 Feb  1  2026 file3
```

所有者・グループ・パーミッション・更新時刻の**すべてが `file1` と同じ**になりました。

**補足 … 所有者を保持できるのは root だけです**

これは `cp` の制限ではなく、**Linux の仕組み上の制約**です。
「ファイルの所有者を他人に変更する」操作（`chown`）は root にしか許されていません。
そのため一般ユーザが `-p` を付けても、**所有者は自分になります**。

```bash
$ cp -p file1 file4                 # test ユーザが自分でコピーした場合
$ ls -l                             # グループが自分のものに変わっている
-rw-rw-r-- 1 test claude 6 Feb  1  2026 file1
-rw-rw-r-- 1 test test   6 Feb  1  2026 file4
```

**パーミッションとタイムスタンプは保持されますが、所有者は引き継げません。**
一般ユーザが作ったファイルの所有者は必ず自分になるためで、これを変えられるのは root だけです。
グループについては、**自分がそのグループに所属していれば保持できます**。
上の例で `claude` から `test` に変わったのは、`test` ユーザが `claude` グループに入っていないからです。
バックアップを取るときに `sudo` を付けるのは、この所有者情報をそのまま残すためです。

**補足 … `-a` は「`-p` の上位版」です**

| | 保持されるもの |
|:--|:--|
| `-p` | パーミッション・所有者・タイムスタンプ |
| `-a` | 上記に加えて、**シンボリックリンク・ACL・SELinux コンテキスト**、さらに `-R` 相当の再帰コピー |

設定ファイルのディレクトリを丸ごと退避するなら `-a` が安全です。

```bash
$ sudo cp -a /etc/nginx /backup/nginx_$(date +%F)    # 属性ごと日付つきで退避する
```

### -f は「上書き」ではなく「消してから作り直す」

**意味** … コピー先が**書き込めない状態のときに、いったん削除してからコピー**する

`-f` は force の `f` ですが、`mv -f` とは動きが違います。
`cp -f` は「コピー先のファイルを開けなかったら、**そのファイルを削除して新規作成する**」という動作です。

**`-f` を付けないと失敗する例**

```bash
$ ls -l                             # dst は読み取り専用（444）
-r--r--r-- 1 test test 2 Sep  1 02:29 dst
-rw-r--r-- 1 test test 2 Sep  1 02:29 src

$ cp src dst                        # 書き込めないので失敗する
cp: cannot create regular file 'dst': Permission denied
```

**`-f` を付けた場合**

```bash
$ cp -f src dst                     # dst を削除してから作り直す
$ cat dst                           # src の内容に置き換わっている
A
$ ls -l dst                         # 権限が 444 から 644 に変わっている
-rw-r--r-- 1 test test 2 Sep  1 02:29 dst
```

**注意 … `-f` はコピー先の属性を作り直します**

上の例で**パーミッションが `444` から `644` に変わっている**点に注目してください。
「削除して新しく作った」ため、元のファイルの権限は失われ、`umask` に従った権限になります。

| | 動き | 元ファイルの属性 |
|:--|:--|:--|
| `cp`（`-f` なし） | 中身だけ上書きする | **残る** |
| `cp -f` | 削除して作り直す | **失われる** |

権限を維持したまま中身を差し替えたいなら、`-f` ではなく
**先に書き込めるようにする**（`chmod u+w`）ほうが安全です。

**注意 … ディレクトリへの書き込み権も必要です**

`-f` は「削除してから作る」ので、コピー先の**ファイル**ではなく
**そのファイルがあるディレクトリ**への書き込み権が必要になります。
ここが分かっていないと「`-f` を付けたのに Permission denied」で悩みます。

**補足 … 末尾のスラッシュで意味が変わります**

```bash
$ cp -r dir1 dir2                   # dir2 が存在する → dir2/dir1 が作られる
$ cp -r dir1/. dir2/                # dir1 の「中身」を dir2 にコピーする
```

**補足 … バックアップを取るときは `-a` を使います**

`cp -r` だけだと所有者やタイムスタンプが変わってしまい、
設定ファイルを戻したときに挙動が変わることがあります。

## 移動と名前の変更

`mv` は「移動」と「名前の変更」の両方を担います。**同じ動作の別の見え方**です。

```bash
$ mv file1.txt /tmp/                # 移動する
$ mv file1.txt file_old.txt         # 名前を変える（同じディレクトリ内での移動）
$ mv dir1 dir_new                   # ディレクトリでも -r は不要
```

| オプション | 意味 |
|:--|:--|
| `-i` | 移動先に同名のファイルやディレクトリがある場合、**上書きしてよいかどうか問い合わせる** |
| `-f` | 移動先に同名のファイルやディレクトリがある場合、**確認せず強制的に上書きする** |
| `-n` | 既存ファイルを上書きしない（確認もしない） |
| `-u` | 移動元が新しいときだけ上書きする |
| `-v` | 移動したものを表示する |
| `-b` | 上書き前にバックアップを作る |

### 上書きの扱いを決める3つのオプション

移動先に**同じ名前のものがすでにある**とき、どう振る舞うかを選びます。

| オプション | 動き | 使いどころ |
|:--|:--|:--|
| `-i` | **聞いてくる**（interactive の `i`） | 手作業で、消したくないものがあるとき |
| `-f` | **黙って上書きする**（force の `f`） | スクリプトで、上書きが前提のとき |
| `-n` | **黙って何もしない**（no-clobber の `n`） | スクリプトで、既存を守りたいとき |

**`-i` … 上書きしてよいか確認する**

**例文** … `tmp` ディレクトリの中身を `doc` ディレクトリへ移動する場合

```bash
$ mv -i tmp/* doc                   # 上書きになるものがあれば確認してくる
mv: 'doc/newfile' を上書きしてもよろしいですか(yes/no)?
```

`doc` に `newfile` がすでにあるため、確認メッセージが出ています。
ここで **`n`（または `no`）を入力すると、そのファイルは上書きされません**。
`y`（または `yes`）を入力すると上書きされます。

```bash
$ mv -i tmp/newfile doc/            # 確認に対して n と答える
mv: overwrite 'doc/newfile'? n
$ cat doc/newfile                   # 元の中身がそのまま残っている
b
```

**`-f` … 確認せずに上書きする**

```bash
$ mv -f tmp/newfile doc/            # 何も聞かれず上書きされる
$ cat doc/newfile                   # tmp 側の中身に置き換わっている
a
```

**補足 … 応答は環境の言語設定で変わります**

日本語環境では「上書きしてもよろしいですか(yes/no)?」、
英語環境では「overwrite 'doc/newfile'?」と表示されます。
**どちらでも `y` / `n` で答えられます。**

**補足 … `-i` と `-f` を両方書いたら**

**後に書いたほうが勝ちます。** GNU の `mv` は
`-i` / `-f` / `-n` を「最後に指定されたものだけ有効」として扱います。

```bash
$ mv -i -f a b                      # -f が後 → 確認せず上書きする
$ mv -f -i a b                      # -i が後 → 確認してくる
```

**注意 … `-r` や `-R` は `mv` には存在しません**

```bash
$ mv -r dir1 dir2                   # -r というオプションは無い
mv: invalid option -- 'r'
Try 'mv --help' for more information.
```

`cp` には再帰コピーの `-r` がありますが、`mv` はディレクトリを
そのまま移動できるため**再帰オプションが要りません**（次の補足を参照）。
`-p`（`cp` の属性保持）も `mv` にはありません。移動は属性をそのまま持ち運ぶためです。

**関連** … ディスクやデバイスを**ブロック単位で**コピーする `dd` は、
[06_ストレージとファイルシステム / dd コマンド](../06_ストレージとファイルシステム/ddコマンド.md) にあります。
`cp` はファイル単位、`dd` はバイト列単位という違いです。

**補足 … `mv` に `-r` は不要です**

`cp` と違い、`mv` はディレクトリをそのまま移動できます。
同じファイルシステム内なら**名前の付け替えだけ**なので、中身の量に関係なく一瞬で終わります。

```bash
$ mv -v large_dir /tmp/             # 同一ファイルシステム内なら一瞬で終わる
renamed 'large_dir' -> '/tmp/large_dir'
```

別のファイルシステムへ移すときは、実体のコピーが発生するため時間がかかります。

**補足 … 上書きの警告は既定では出ません**

多くのディストリでは `alias mv='mv -i'` が設定されていますが、
**スクリプト内ではエイリアスが効きません**。上書きしたくない場合は `-n` を明示します。

```bash
$ mv -n src.txt dst.txt             # dst.txt があれば何もしない
```

## 誤削除を防ぐ

`rm -rf` は**取り消せません**。ゴミ箱にも入りません。

### 実行前に対象を確認する

```bash
$ ls /var/log/*.gz                  # まず何が対象になるか目で見る
/var/log/app.log.1.gz  /var/log/app.log.2.gz

$ echo rm -rf /var/log/*.gz         # 展開結果だけ表示して確認する
rm -rf /var/log/app.log.1.gz /var/log/app.log.2.gz
                                    # 意図どおりなら echo を外して実行する
```

### 移動してから消す

いきなり消さず、いったん退避しておくと戻せます。

```bash
$ mkdir -p /tmp/_to_delete          # 退避先を用意する
$ mv /var/log/old_dir /tmp/_to_delete/    # 消さずに移動する
                                    # 問題が無いことを確認してから rm -r する
```

### 変数を使うときは必ずクォートする

`$DIR` が空になると `rm -rf /` になります。**実際に起きている事故です。**

```bash
$ DIR=""                            # 変数が空になってしまった状況
$ echo rm -rf "$DIR/"               # 展開結果を確認すると…
rm -rf /                            # ルートを消しにいく形になっている
```

スクリプトでは `set -u` を有効にして、未定義変数をエラーにします。
（[シェルのオプション設定](./シェルのオプション設定.md) を参照）

### `cd` と `&&` をセットにする

```bash
$ cd /var/log/myapp && rm -rf ./*   # cd が成功したときだけ削除する

$ cd /var/log/myapp ; rm -rf ./*    # cd が失敗しても削除が走る（危険）
```

（[コマンドの連結と制御演算子](./コマンドの連結と制御演算子.md) を参照）
