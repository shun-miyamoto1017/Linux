## 履歴のしくみ

`bash` シェルには、過去に入力したコマンドの履歴を記録する機能があります。
**コマンドの履歴はログアウト時にコマンド履歴保存ファイルに保存され、
次回ログイン時に参照できるようになっています。**

**保存場所が 2 段構えになっている点が重要です。**

```
コマンド入力
   ↓
メモリ上の履歴リスト   ← HISTSIZE が上限
   ↓ ログアウト時に書き出し
~/.bash_history        ← HISTFILESIZE が上限
```

| 変数 | どこの話か | 効く範囲 |
|:--|:--|:--|
| `HISTSIZE` | **メモリ上**の履歴リスト | 現在のシェルで `history` に何件表示されるか |
| `HISTFILESIZE` | **ファイル**（`$HISTFILE`）の履歴 | ログアウト時に何件書き出されるか |
| `HISTFILE` | 保存先ファイルのパス | 既定は `~/.bash_history` |

```bash
$ echo $HISTFILE                    # 履歴の保存先ファイルを確認する
/home/shun/.bash_history

$ ls -l $HISTFILE                   # ファイルのサイズと権限を確認する
-rw------- 1 shun shun 12043 Aug 27 23:20 /home/shun/.bash_history
```

**補足** … 履歴ファイルの権限は `600`（本人だけ読み書き可）です。
過去に打ったコマンドには、うっかり平文で書いたパスワードが含まれることがあるためです。

## history コマンド

**`history` コマンドは、コマンドの履歴を表示します。**

```bash
$ history                           # 履歴を番号つきで表示する
    1  ls
    2  pwd
    3  cat hoge.txt
    4  cp hoge.txt hoge2.txt
    5  history

$ history 3                         # 直近3件だけ表示する
    3  cat hoge.txt
    4  cp hoge.txt hoge2.txt
    5  history

$ history | grep ssh                # 履歴の中から ssh を含む行を探す
   12  ssh -i key.pem ec2-user@10.0.1.20
```

### 主なオプション

| オプション | 動作 |
|:--|:--|
| `-c` | メモリ上の履歴を**すべて消す** |
| `-d 番号` | 指定した 1 件を消す |
| `-a` | メモリ上の**新しい履歴をファイルへ追記**する |
| `-r` | ファイルの履歴を**メモリへ読み込む** |
| `-w` | メモリ上の履歴で**ファイルを上書き**する |
| `-n` | ファイルのうち**まだ読んでいない行**をメモリへ読み込む |

```bash
$ history -d 12                     # 12番の履歴を消す（パスワードを打ってしまったとき）
$ history -a                        # いまの履歴をファイルへ即時追記する
$ history -c                        # メモリ上の履歴をすべて消す
```

**補足 … `history -c` だけではファイルは消えません**

`-c` はメモリ上の履歴を消すだけです。ファイルに残っている過去の履歴はそのままです。

```bash
$ history -c                        # メモリの履歴を消す
$ history                           # 空になったことを確認
    1  history

$ cat $HISTFILE | wc -l             # ファイル側はまだ残っている
482
```

## ヒストリ展開で呼び出す

履歴の番号や文字列を使って、過去のコマンドを打ち直さずに再実行できます。
この仕組みを **ヒストリ展開** と呼びます。

**「`!番号`」と入力すると、指定した履歴番号のコマンドを再実行します。**
**「`!文字列`」と入力すると、指定した文字列から始まる直近のコマンドを再実行します。**

| 書き方 | 意味 |
|:--|:--|
| `!番号` | 指定した履歴番号のコマンドを再実行する |
| `!文字列` | 指定した文字列から始まる**直近**のコマンドを再実行する |
| `!!` | 直前のコマンドを再実行する |
| `!-2` | 2 つ前のコマンドを再実行する |
| `!$` | 直前のコマンドの**最後の引数**を再利用する |
| `!^` | 直前のコマンドの**最初の引数**を再利用する |
| `!*` | 直前のコマンドの**すべての引数**を再利用する |
| `^旧^新` | 直前のコマンドの文字列を置換して実行する |
| `Ctrl+R` | 履歴をインクリメンタル検索する |

**例文**

先ほどの履歴（`3 cat hoge.txt`）を使います。

```bash
$ !3                                # 履歴番号3番のコマンドを再実行する
cat hoge.txt                        # 何が実行されるかが表示されてから走る
hello

$ !ca                               # 「ca」で始まる直近のコマンドを再実行する
cat hoge.txt
hello

$ !!                                # 直前のコマンドをもう一度実行する
cat hoge.txt
hello
```

### 実務で効く書き方

**`!$` … 直前の最後の引数を再利用する**

長いパスを 2 度打たずに済みます。

```bash
$ mkdir -p /opt/app/config          # 長いパスのディレクトリを作る
$ cd !$                             # 直前の最後の引数（＝そのパス）を再利用する
cd /opt/app/config
```

**`sudo !!` … sudo を付け忘れたとき**

```bash
$ systemctl restart nginx           # 権限が足りず失敗する
Failed to restart nginx.service: Access denied

$ sudo !!                           # 直前のコマンドに sudo を付けて再実行する
sudo systemctl restart nginx
```

**`^旧^新` … 打ち間違いを直して再実行する**

```bash
$ systemctl status ngnix            # nginx を打ち間違えた
Unit ngnix.service could not be found.

$ ^ngnix^nginx                      # 直前のコマンドの ngnix を nginx に置換して実行
systemctl status nginx
● nginx.service - The nginx HTTP and reverse proxy server
```

**矢印キー … 1 つずつ遡る**

いちばん手軽な呼び出し方です。**`↑` を押すごとに、直近から過去の方向へ順に**表示されます。
`↓` を押すと逆に、過去から直近の方向へ戻ります。
コマンドが表示された状態で `Enter` を押せば、そのコマンドを再実行できます。

```bash
$ history                           # 履歴が5件ある状態
    1  ls
    2  pwd
    3  cat hoge.txt
    4  cp hoge.txt hoge2.txt
    5  history

$                                   # ここで ↑ を1回押すと 5番が出る
$ history                           # ↑ 1回目
$ cp hoge.txt hoge2.txt             # ↑ 2回目（4番）
$ cat hoge.txt                      # ↑ 3回目（3番）→ Enter で実行できる
```

**補足** … 表示された状態で **`←` `→` を押せば、そのまま編集**できます。
「前回のコマンドの引数だけ変えたい」ときは、`↑` で呼び出して直すのが最速です。

**`Ctrl+R` … 検索しながら探す**

番号を覚えていなくても、文字列の一部から探せます。**実務ではこれが最もよく使われます。**

```bash
（Ctrl+R を押す）
(reverse-i-search)`ssh': ssh -i ~/.ssh/prod.pem ec2-user@10.0.1.20
                                    # 打つほどに候補が絞られる
                                    # Enter で実行、→ キーで編集してから実行
                                    # Ctrl+R をもう一度押すと次の候補へ
                                    # Ctrl+G で検索を中止
```

### 注意点

**`!文字列` は「直近」を拾うので、狙いが外れることがあります。**

```bash
$ cal                               # cat のあとに cal を実行したとする
$ !ca                               # 「ca」で始まる直近は cal になってしまう
cal
```

確実に狙ったものを実行したいなら **`!番号`** を使うか、
`Ctrl+R` で中身を目視してから実行します。

**`!` はコメントの `#` とは別物です。**

`#` から行末まではコメントとして無視され、**何も実行されません**。
「実行したつもりなのに何も起きない」という気づきにくいミスにつながります。

```bash
$ #3                                # コメント扱いなので何も起きない
$                                   # プロンプトが返るだけ

$ !3                                # こちらが履歴の再実行
cat hoge.txt
```

| 記号 | 意味 |
|:--|:--|
| `!番号` / `!文字列` | 履歴からの再実行（ヒストリ展開） |
| `#` | コメント。以降は実行されない |

**`!!` に文字を続けると、単純に連結されます。**

```bash
$ history                           # 直前のコマンドが history だったとする
$ !!3                               # 「直前のコマンド + 3」として展開される
history3
bash: history3: command not found
```

### ヒストリ展開が効く場所

ヒストリ展開は `histexpand`（`set -H`）オプションで制御されています。
**対話シェルでは既定で有効、スクリプト内では既定で無効**です。

```bash
$ set -o | grep histexpand          # 現在の設定を確認する
histexpand     on
```

そのため、対話シェルで `!` を含む文字列を書くと意図せず展開されることがあります。
**シングルクォートで囲めば安全**です。

```bash
$ echo "Hello World!"               # ! の直後が引用符の終わりなら展開されず、そのまま出る
Hello World!

$ echo "Hello!World"                # ! の直後に文字が続くと履歴として解釈される
bash: !World: event not found

$ echo 'Hello!World'                # シングルクォートなら確実に文字として扱われる
Hello!World
```

## 履歴を制御する変数

| 変数 | 意味 | 既定値の例 |
|:--|:--|:--|
| `HISTFILE` | コマンド履歴保存ファイルのパス | `~/.bash_history` |
| `HISTSIZE` | 現在のシェルでのコマンド履歴の保存数 | `1000` |
| `HISTFILESIZE` | コマンド履歴保存ファイルへの履歴保存数 | `2000` |
| `HISTCONTROL` | 記録しない条件を指定する | （未設定） |
| `HISTIGNORE` | 記録しないコマンドのパターンを指定する | （未設定） |
| `HISTTIMEFORMAT` | 履歴に付ける日時のフォーマット | （未設定） |

```bash
$ set | grep '^HIST'                # HIST で始まる変数をまとめて確認する
HISTCONTROL=ignoredups
HISTFILE=/home/shun/.bash_history
HISTFILESIZE=2000
HISTSIZE=1000
```

**補足 … これらは厳密には「環境変数」ではありません**

`HISTFILE` `HISTSIZE` `HISTFILESIZE` は bash が用意する**シェル変数**で、
既定では `export` されていません。試験では「環境変数」としてまとめて出題されますが、
実際に確認すると `env` には出てきません。

```bash
$ set | grep '^HISTSIZE'            # set はシェル変数も表示するので見つかる
HISTSIZE=1000

$ env | grep '^HISTSIZE'            # env は環境変数だけなので見つからない
                                    # （何も出力されない）
```

### HISTCONTROL

記録**しない**条件を指定します。

| 値 | 動作 |
|:--|:--|
| `ignoredups` | 直前と同じコマンドを記録しない |
| `ignorespace` | **先頭がスペース**のコマンドを記録しない |
| `ignoreboth` | 上の両方 |
| `erasedups` | 同じコマンドの過去の記録をすべて消す |

```bash
$ HISTCONTROL=ignorespace           # 先頭スペースのコマンドを記録しない設定にする
$  mysql -u root -pSecret123        # ← 先頭にスペースを入れると履歴に残らない
$ history | tail -2                 # 確認すると「 mysql …」だけが抜けている
   58  HISTCONTROL=ignorespace
   59  history | tail -2
```

**補足** … `ignorespace` は「パスワードを含むコマンドを履歴に残さない」定番の手段です。
ただし**恒久的な対策にはなりません**。パスワードはコマンドラインではなく、
環境変数や設定ファイル、Secrets Manager から渡すのが本筋です。

### HISTIGNORE

記録しないコマンドを**パターン**で指定します。`:` 区切りで複数書けます。

```bash
$ HISTIGNORE='ls:ll:pwd:history:exit:cd'    # よく打つが記録する価値のないものを除外
$ ls                                        # 実行しても履歴に残らない
$ history | tail -2                         # 確認する
   59  HISTIGNORE='ls:ll:pwd:history:exit:cd'
   60  history | tail -2
```

### HISTTIMEFORMAT

履歴に日時を付けます。`date` コマンドと同じ書式指定子が使えます。

```bash
$ HISTTIMEFORMAT='%F %T '           # 「年-月-日 時:分:秒 」を付ける
$ history | tail -2                 # 直近2件を表示して確認
   61  2026-08-27 23:20:12 ls -l
   62  2026-08-27 23:20:20 history | tail -2
```

| 書式 | 意味 |
|:--|:--|
| `%F` | 年-月-日（`2026-08-27`） |
| `%T` | 時:分:秒（`23:20:12`） |
| `%Y-%m-%d %H:%M:%S` | 上と同じ内容を個別に指定した書き方 |

**補足** … `HISTTIMEFORMAT` を設定すると、履歴ファイルにも
`#エポック秒` という行が各コマンドの直前に書き込まれるようになります。
**設定する前に打ったコマンドには日時が付きません**（記録が無いため）。

```bash
$ head -4 $HISTFILE                 # ファイルの中身を確認する
#1787840412
ls -l
#1787840420
history
```

## 履歴を残さない設定

**シェル変数 `HISTFILESIZE` を `0` にすると、
コマンド履歴保存ファイルにコマンド履歴が保存されなくなります。**

```bash
$ HISTFILESIZE=0                    # ファイルへの保存件数を0にする
$ ls -l $HISTFILE                   # 履歴ファイルのサイズを確認する
-rw------- 1 shun shun 0 Aug 27 23:20 /home/shun/.bash_history
                                    # ↑ 設定した時点で 0 バイトに切り詰められる
```

**メモリ上の履歴は消えません。**
`HISTFILESIZE=0` を設定した直後でも `history` には従来どおり表示されます。
**ログアウト時にファイルへ書き出す件数が 0 になる**だけです。

```bash
$ HISTFILESIZE=0                    # 設定する
$ history | tail -3                 # メモリ上の履歴はそのまま残っている
   60  cat hoge.txt
   61  HISTFILESIZE=0
   62  history | tail -3

$ exit                              # ログアウト
（再ログイン）
$ history                           # 前回の履歴は残っていない
    1  history
```

### HISTSIZE との違い

名前が似ているので、**「FILE が付くほうがファイル」**と覚えます。

| 変数 | 制御する対象 | `=0` にすると |
|:--|:--|:--|
| `HISTSIZE` | メモリ上の履歴リスト | `history` に何も表示されなくなる |
| `HISTFILESIZE` | 履歴保存ファイル | ファイルが 0 バイトに切り詰められる |

```bash
$ HISTSIZE=3                        # メモリ上の履歴を3件に制限してみる
$ history                           # 直近の数件しか残らない
   64  HISTSIZE=3
   65  history

$ cat $HISTFILE | wc -l             # ファイル側は制限されていない
482
```

「作業中も履歴を見たくない」なら `HISTSIZE=0`、
「ファイルに残したくない」なら `HISTFILESIZE=0` です。

### そのほかの消し方

| やりたいこと | 書き方 |
|:--|:--|
| メモリ上の履歴を全消し | `history -c` |
| 特定の 1 件だけ消す | `history -d 番号` |
| ファイルも空にする | `history -c && > $HISTFILE` |
| 今回のセッションだけ記録しない | `unset HISTFILE` |

```bash
$ unset HISTFILE                    # 保存先を未設定にすると、そのセッションは保存されない
```

**補足 … 消すことが正しいとは限りません**

金融案件などの監査要件では、**「いつ誰が何を打ったか」の証跡を残すこと**が求められます。
履歴を消す設定は、あくまで「パスワードを誤って打ってしまった」といった
例外的な場面のための手段だと理解しておくのが安全です。

## 複数端末での履歴の扱い

同じユーザで複数のターミナルを開くと、**後から閉じたほうの履歴でファイルが上書き**されます。
片方で打ったコマンドが消えるのはこれが原因です。

対策は 2 つあります。

```bash
$ shopt -s histappend               # 上書きせず追記する設定にする
$ PROMPT_COMMAND='history -a'       # コマンドを打つたびにファイルへ即時追記する
```

| 設定 | 効果 |
|:--|:--|
| `shopt -s histappend` | ログアウト時に**上書きではなく追記**する |
| `PROMPT_COMMAND='history -a'` | ログアウトを待たず、**1 コマンドごとに**追記する |

**`PROMPT_COMMAND` とは** … 「プロンプトを表示する直前に実行されるコマンド」を入れる変数です。
ここに `history -a`（メモリ上の履歴をファイルへ追記）を入れておくと、
**異常終了やセッション切断でも履歴が失われません**。

```bash
$ echo $PROMPT_COMMAND              # 現在の設定を確認する
history -a
```

さらに、他の端末で打った履歴も取り込みたい場合は `history -n` を足します。

```bash
$ PROMPT_COMMAND='history -a; history -n'    # 追記してから未読を読み込む
                                    # 追記してから、未読の行を読み込む
```

| 部分 | やっていること |
|:--|:--|
| `history -a` | 自分の新しい履歴をファイルへ追記する |
| `;` | 続けて次のコマンドを実行する区切り記号 |
| `history -n` | ファイルのうち、まだ読んでいない行をメモリへ読み込む |

## おすすめの設定

`~/.bashrc` に書いておくと、以降ずっと有効になります。

```bash
# ~/.bashrc に追記する例
HISTSIZE=10000                      # メモリ上の履歴を1万件まで保持
HISTFILESIZE=20000                  # ファイルには2万件まで残す
HISTTIMEFORMAT='%F %T '             # 履歴に日時を付ける（調査で効く）
HISTCONTROL=ignoreboth              # 重複と、先頭スペースのコマンドを記録しない
HISTIGNORE='ls:ll:pwd:history:exit' # よく打つだけのコマンドは記録しない
shopt -s histappend                 # 履歴を上書きせず追記する
PROMPT_COMMAND='history -a'         # コマンドごとにファイルへ即時追記
```

> 設定ファイルの使い分け（`~/.bashrc` と `~/.bash_profile` の違い）は
> [シェルの設定ファイル](./シェルの設定ファイル.md) を参照してください。
