## まずこれだけ

| 書きたいもの | 書く場所 |
|:--|:--|
| **環境変数**（`PATH` `JAVA_HOME` など） | `~/.bash_profile` |
| **エイリアス・シェルオプション・プロンプト** | `~/.bashrc` |
| システム全体の環境変数 | `/etc/profile.d/xxx.sh` |
| システム全体のエイリアス | `/etc/bashrc`（RHEL 系）／`/etc/bash.bashrc`（Debian 系） |

**理由はシンプルです。**

- 環境変数は一度 `export` すれば**子プロセスに継承される**ので、ログイン時に 1 回で十分
- エイリアスやシェルオプションは**継承されない**ので、新しい対話シェルが立つたびに読み込む必要がある

## シェルの三つの種類

どの設定ファイルが読まれるかは、**シェルの起動のしかた**で決まります。

| 種類 | どういうとき | 読まれる設定ファイル |
|:--|:--|:--|
| **ログインシェル** | SSH でログイン、コンソールでログイン、`su -` | `/etc/profile` → `~/.bash_profile` |
| **対話シェル**（非ログイン） | 端末で `bash` と打つ、端末エミュレータの新規タブ | `~/.bashrc` |
| **非対話シェル** | シェルスクリプトの実行、`ssh host 'cmd'`、cron | **どちらも読まれない** |

### 自分がどれか確かめる

```bash
$ echo $0                           # ログインシェルなら先頭に「-」が付く
-bash                               # ← ログインシェル

$ echo $0                           # 非ログインの対話シェル
bash                                # ← 先頭に「-」が無い

$ shopt login_shell                 # bash なら shopt でも確認できる
login_shell     on                  # on ならログインシェル

$ echo $-                           # 有効なオプションの一覧
himBHs                              # 「i」が含まれていれば対話シェル
```

| 確認方法 | ログインシェル | 対話シェル | 非対話シェル |
|:--|:--|:--|:--|
| `echo $0` | `-bash` | `bash` | `bash` |
| `shopt login_shell` | `on` | `off` | `off` |
| `echo $-` に `i` が含まれる | ○ | ○ | ✗ |

**補足 … `ssh host 'command'` は非対話シェルです**

これが「手元では動くのに ssh 経由だと動かない」の最大の原因です。

```bash
$ ssh web01 'echo $PATH'            # 非対話シェルなので .bashrc が読まれない
/usr/local/bin:/usr/bin:/bin        # ← 手元とは違う PATH になることがある

$ ssh web01                         # ログインすると .bash_profile が読まれる
$ echo $PATH                        # PATH に追記が反映されているか確認する
/usr/local/bin:/usr/bin:/bin:/opt/app/bin
```

## 設定ファイルの一覧

| ファイル | 読まれるタイミング | 対象 | 主な用途 |
|:--|:--|:--|:--|
| `/etc/profile` | ログインシェル起動時 | 全ユーザ | システム全体の環境変数 |
| `/etc/profile.d/*.sh` | ログインシェル起動時 | 全ユーザ | パッケージごとの設定を分割して置く |
| `/etc/bashrc`（RHEL 系）<br>`/etc/bash.bashrc`（Debian 系） | 対話シェル起動時 | 全ユーザ | システム全体のエイリアス・関数 |
| `~/.bash_profile` | ログインシェル起動時 | 個人 | `PATH` などの環境変数 |
| `~/.bash_login` | 同上（`.bash_profile` が無い場合） | 個人 | 同上 |
| `~/.profile` | 同上（上の 2 つが無い場合） | 個人 | 同上。`sh` 互換 |
| `~/.bashrc` | 対話シェル起動時 | 個人 | エイリアス、`set -o`、プロンプト |
| `~/.bash_logout` | ログアウト時 | 個人 | 後始末（画面クリアなど） |

```bash
$ ls -la ~ | grep bash              # 自分のホームにある bash 関連ファイルを確認
-rw-r--r--. 1 shun shun   18 Aug 20 10:00 .bash_logout
-rw-r--r--. 1 shun shun  141 Aug 20 10:00 .bash_profile
-rw-r--r--. 1 shun shun  492 Aug 27 22:10 .bashrc

$ ls /etc/profile.d/ | head -5      # システム全体の設定ファイル群を確認
colorls.sh
lang.sh
less.sh
which2.sh
```

**補足 … 個人用ログイン設定は 3 つのうち先に見つかった 1 つだけ**

`~/.bash_profile` → `~/.bash_login` → `~/.profile` の順に探し、
**最初に見つかったものだけ**を読み込みます。3 つとも置くと後の 2 つは無視されます。

## 読み込まれる順番

### ログインシェルの場合

```
/etc/profile
   ↓ （この中から呼ばれる）
/etc/profile.d/*.sh
   ↓
~/.bash_profile      ← 無ければ ~/.bash_login、それも無ければ ~/.profile
   ↓ （この中から呼ばれることが多い）
~/.bashrc
   ↓ （この中から呼ばれることが多い）
/etc/bashrc
```

**多くのディストリの `~/.bash_profile` は、中で `~/.bashrc` を読み込む作りになっています。**

```bash
$ cat ~/.bash_profile               # 既定の中身を確認する
# .bash_profile

# Get the aliases and functions
if [ -f ~/.bashrc ]; then           # ~/.bashrc が存在すれば
    . ~/.bashrc                     # それを読み込む（. は source と同じ）
fi

PATH=$PATH:$HOME/.local/bin:$HOME/bin
export PATH
```

このため「とりあえず `~/.bashrc` に書けば両方で効く」ことが多いのですが、
**理屈を知らないと非対話シェルでハマります**。

### 対話シェル（非ログイン）の場合

```
~/.bashrc
   ↓ （この中から呼ばれることが多い）
/etc/bashrc
```

`/etc/profile` も `~/.bash_profile` も読まれません。

### 非対話シェルの場合

**どの設定ファイルも読まれません。**

ただし `BASH_ENV` 変数にファイルパスが設定されていれば、それだけは読み込まれます。

```bash
$ BASH_ENV=~/.bashenv bash script.sh     # 非対話シェルでも指定ファイルを読ませる
```

**補足 … 読み込み順を実際に見る**

各ファイルに `echo` を仕込むと、順番が目で確認できます。

```bash
$ echo 'echo "読み込み: ~/.bash_profile"' >> ~/.bash_profile   # 目印を仕込む
$ echo 'echo "読み込み: ~/.bashrc"' >> ~/.bashrc               # こちらにも仕込む

$ bash -l                           # -l を付けるとログインシェルとして起動する
読み込み: ~/.bashrc
読み込み: ~/.bash_profile           # bash_profile の中で bashrc が先に呼ばれている

$ exit                              # 確認が終わったら追記した行を消しておく
```

## 使い分けの原則

**環境変数は `~/.bash_profile`、エイリアスやシェルオプションは `~/.bashrc`** に書きます。

| 書くもの | 場所 | 理由 |
|:--|:--|:--|
| `export PATH=...` | `~/.bash_profile` | 子プロセスに継承されるので 1 回で足りる |
| `export JAVA_HOME=...` | `~/.bash_profile` | 同上 |
| `alias ll='ls -alF'` | `~/.bashrc` | エイリアスは継承されない |
| `set -o noclobber` | `~/.bashrc` | シェルオプションは継承されない |
| `PS1='...'` | `~/.bashrc` | プロンプトは対話シェルでのみ意味がある |
| `HISTSIZE=10000` | `~/.bashrc` | 対話シェルでのみ意味がある |
| シェル関数の定義 | `~/.bashrc` | 関数は継承されない（`export -f` しない限り） |

**継承されるかどうかを確かめる**

```bash
$ export MYVAR=hello                # 環境変数を定義する
$ alias ll='ls -alF'                # エイリアスを定義する

$ bash -c 'echo "[$MYVAR]"'         # 子シェルで環境変数を確認
[hello]                             # 継承されている

$ bash -c 'll'                      # 子シェルでエイリアスを確認
bash: ll: command not found         # 継承されていない
```

## 設定ファイルの中身の例

### ~/.bash_profile

```bash
# ~/.bash_profile

if [ -f ~/.bashrc ]; then           # 対話シェル用の設定も読み込む
    . ~/.bashrc                     # . は source と同じ意味
fi

export PATH="$PATH:$HOME/bin"       # 個人用のコマンド置き場を PATH に追加
export EDITOR=vi                    # crontab -e などで起動するエディタ
export LANG=ja_JP.UTF-8             # ロケール
```

**`PATH` は既存の値を含めて書く**のが鉄則です。`export PATH="$HOME/bin"` と書くと
`ls` も `cat` も使えなくなります。

### ~/.bashrc

```bash
# ~/.bashrc

# ---- シェルの挙動 ----
set -o noclobber                    # > による上書き事故を防ぐ
set -o ignoreeof                    # Ctrl+D での誤ログアウトを防ぐ
shopt -s histappend                 # 履歴を上書きせず追記する
shopt -s checkwinsize               # ウィンドウサイズの変更を検知する

# ---- コマンド履歴 ----
HISTSIZE=10000                      # メモリ上の履歴を1万件まで保持
HISTFILESIZE=20000                  # ファイルには2万件まで残す
HISTTIMEFORMAT='%F %T '             # 履歴に日時を付ける（調査で効く）
HISTCONTROL=ignoreboth              # 重複と、先頭スペースのコマンドを記録しない
PROMPT_COMMAND='history -a'         # コマンドごとにファイルへ即時追記

# ---- エイリアス ----
alias ll='ls -alF'                  # 詳細表示の短縮形
alias grep='grep --color=auto'      # 検索結果に色を付ける
alias df='df -h'                    # 容量を人が読める形式で表示
alias ..='cd ..'                    # 1つ上へ移動する短縮形

# ---- プロンプト ----
PS1='[\u@\h \W]\$ '                 # ユーザ@ホスト カレントディレクトリ
```

**プロンプト（`PS1`）でよく使う記号**

| 記号 | 意味 |
|:--|:--|
| `\u` | ユーザ名 |
| `\h` | ホスト名（最初のドットまで） |
| `\H` | ホスト名（完全） |
| `\w` | カレントディレクトリ（フルパス） |
| `\W` | カレントディレクトリ（末尾だけ） |
| `\$` | root なら `#`、一般ユーザなら `$` |
| `\t` | 時刻（`HH:MM:SS`） |
| `\d` | 日付 |

```bash
$ PS1='[\t \u@\h \w]\$ '            # 時刻とフルパスを表示するプロンプトにする
[23:24:40 shun@web01 /home/shun/work]$
```

**補足 … 本番と検証でプロンプトの色を変える**

取り違え事故の防止に効きます。

```bash
# 本番サーバの ~/.bashrc（赤くする）
PS1='\[\e[41;37m\][PROD]\[\e[0m\] [\u@\h \W]\$ '

# 検証サーバの ~/.bashrc（緑にする）
PS1='\[\e[42;30m\][DEV]\[\e[0m\] [\u@\h \W]\$ '
```

### ~/.bash_logout

```bash
# ~/.bash_logout

clear                               # ログアウト時に画面をクリアする
```

**補足** … 共用端末で「前の人の作業内容が画面に残る」のを防ぐための仕組みです。

## システム全体に配る

全ユーザに設定を配るときは、`/etc/profile` を直接編集せず
**`/etc/profile.d/` に `.sh` ファイルを置く**のが定石です。

理由は、`/etc/profile` を書き換えると**OS のアップデートで上書きされる可能性がある**ためです。

```bash
$ sudo vi /etc/profile.d/company.sh  # 新しい設定ファイルを作る
$ cat /etc/profile.d/company.sh      # 中身を確認する
# 全社共通の設定
export TZ='Asia/Tokyo'               # タイムゾーンを日本時間にする
export LANG=ja_JP.UTF-8              # ロケール

$ sudo chmod 644 /etc/profile.d/company.sh    # 読み取り権限を付ける
```

**補足** … `/etc/profile.d/*.sh` は `/etc/profile` の中からループで読み込まれています。

```bash
$ grep -A5 'profile.d' /etc/profile  # 読み込んでいる箇所を確認する
for i in /etc/profile.d/*.sh /etc/profile.d/sh.local ; do
    if [ -r "$i" ]; then
        ...
```

**RHEL 系と Debian 系の違い**

| 用途 | RHEL 系 | Debian 系 |
|:--|:--|:--|
| システム全体のログイン設定 | `/etc/profile` | `/etc/profile` |
| 分割配置用ディレクトリ | `/etc/profile.d/` | `/etc/profile.d/` |
| システム全体の対話シェル設定 | **`/etc/bashrc`** | **`/etc/bash.bashrc`** |
| 新規ユーザに配られる雛形 | `/etc/skel/` | `/etc/skel/` |

```bash
$ ls -a /etc/skel/                  # 新規ユーザ作成時にコピーされる雛形を確認
.  ..  .bash_logout  .bash_profile  .bashrc
```

**補足** … `/etc/skel/` に置いたファイルは、`useradd` で作られた新規ユーザのホームにコピーされます。
**既存ユーザには反映されません**。

## 変更を反映する

設定ファイルを編集しても、**すでに開いているシェルには自動では反映されません**。

```bash
$ vi ~/.bashrc                      # 編集する
$ source ~/.bashrc                  # 現在のシェルに読み込ませる
```

| 方法 | 動作 |
|:--|:--|
| `source ~/.bashrc` | 現在のシェルで読み込む（**推奨**） |
| `. ~/.bashrc` | 同じ意味（POSIX 準拠の書き方） |
| 端末を開き直す | 新しいシェルとして読み込まれる |
| `exec bash` | 現在のシェルを置き換えて起動し直す |
| `bash ~/.bashrc` | **効果がない**（子シェルで実行されて終わる） |

**`bash ~/.bashrc` では反映されません。**
別のシェルが起動してそこで実行され、終了と同時に消えるためです。

```bash
$ bash ~/.bashrc                    # 子シェルで実行されて終わる
$ alias ll                          # 定義されていない
bash: alias: ll: not found

$ source ~/.bashrc                  # いまのシェルで読み込む
$ alias ll                          # 定義されている
alias ll='ls -alF'
```

**補足 … 編集後は必ず構文チェックする**

`~/.bashrc` に構文エラーがあると、**新しい端末が開けなくなる**ことがあります。
編集したら反映前にチェックします。

```bash
$ bash -n ~/.bashrc                 # 実行せず文法だけチェックする
                                    # 問題なければ何も出力されない
```

## キーバインドの設定ファイル

コマンドライン入力時のキー操作は、`readline` というライブラリが担当しています。
その設定は `~/.inputrc`（個人）と `/etc/inputrc`（全体）に書きます。

```bash
$ cat ~/.inputrc                    # 設定を確認する
set editing-mode vi                 # vi キーバインドにする
set completion-ignore-case on       # 補完で大文字小文字を区別しない
set show-all-if-ambiguous on        # 候補が複数でも1回のTabで一覧表示する
"\e[A": history-search-backward     # ↑ キーで、入力中の文字列に一致する履歴を検索
"\e[B": history-search-forward      # ↓ キーで同様に前方検索
```

**補足 … `history-search-backward` は覚える価値があります**

`ssh` と打ってから `↑` を押すと、**`ssh` で始まる履歴だけ**が遡れます。
`Ctrl+R` より速い場面が多く、実務での時短効果が大きい設定です。

反映するには端末を開き直すか、`Ctrl+X Ctrl+R` を押します。

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| `~/.bashrc` の設定が `ssh host 'cmd'` で効かない | 非対話シェルでは読まれない | `~/.bash_profile` に書くか `env` で明示 |
| 環境変数がスクリプトで見えない | `export` していない | `export VAR=値` と書く |
| エイリアスがスクリプトで使えない | エイリアスは非対話シェルで無効 | 関数にするか、フルパスで書く |
| 編集したのに反映されない | 開いているシェルには自動反映されない | `source ~/.bashrc` |
| `bash ~/.bashrc` で反映されない | 子シェルで実行されて終わる | `source` を使う |
| 新しい端末が開けなくなった | `~/.bashrc` に構文エラーがある | 別の方法でログインし `bash -n` で確認 |
| `PATH` を書き換えたらコマンドが使えない | 既存の値を含めずに上書きした | `export PATH="$PATH:/new"` |
| `~/.profile` を書いても効かない | `~/.bash_profile` が優先される | 存在するファイルを確認する |
| cron で環境変数が効かない | cron は非対話・非ログインシェル | crontab 内で明示的に設定する |

## クラウド実務メモ

**EC2 のユーザーデータは非対話・非ログインシェルで動く**

`~/.bashrc` も `~/.bash_profile` も読まれません。`PATH` は明示的に設定します。

```bash
#!/bin/bash
export PATH=/usr/local/bin:/usr/bin:/bin       # 明示的に設定する
export AWS_DEFAULT_REGION=ap-northeast-1
```

**cron も設定ファイルを読まない**

cron の実行環境は最小限です。手元で動くスクリプトが cron で動かない典型例です。

```bash
$ crontab -e                        # cron の設定を編集する
PATH=/usr/local/bin:/usr/bin:/bin   # crontab の先頭で明示的に設定する
0 3 * * * /opt/app/backup.sh
```

**Ansible の `shell` モジュールも非対話シェル**

`.bashrc` に書いた設定は効きません。必要なら `environment:` で明示します。

```yaml
- name: バックアップを実行する
  shell: /opt/app/backup.sh
  environment:
    PATH: "/usr/local/bin:/usr/bin:/bin"
    AWS_PROFILE: "prod"
```

**コンテナには設定ファイルがほぼ無い**

`docker exec -it container bash` で入っても、`~/.bashrc` は最小限か存在しません。
設定は `Dockerfile` の `ENV` で渡すのが基本です。

```dockerfile
ENV PATH="/opt/app/bin:${PATH}"
ENV TZ="Asia/Tokyo"
```

**Session Manager はログインシェルで入る**

`aws ssm start-session` で接続すると、通常はログインシェルとして起動します。
そのため `/etc/profile.d/` に置いた全社設定（履歴記録など）が有効になります。

```bash
$ aws ssm start-session --target i-0123456789abcdef0    # 対象インスタンスに接続する
$ echo $0                                               # ログインシェルか確認する
-bash
```

**全ユーザ共通の設定は `/etc/profile.d/` に置く**

Ansible や cloud-init で配布しやすく、OS アップデートで上書きされません。

```yaml
- name: 全社共通のシェル設定を配布する
  copy:
    src: company.sh
    dest: /etc/profile.d/company.sh
    mode: '0644'
```
