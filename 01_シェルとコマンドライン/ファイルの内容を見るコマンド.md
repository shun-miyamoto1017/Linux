## まずこれだけ

| コマンド | 何をするか | 1 画面ずつ | 編集できる |
|:--|:--|:-:|:-:|
| `cat` | ファイルの中身を**すべて**一気に表示する | ✗ | ✗ |
| `less` | ファイルの中身を**1 画面ずつ**表示する（前にも戻れる） | ○ | ✗ |
| `more` | ファイルの中身を**1 画面ずつ**表示する（`less` の古い版） | ○ | ✗ |
| `head` | ファイルの**先頭**だけ表示する（既定 10 行） | ✗ | ✗ |
| `tail` | ファイルの**末尾**だけ表示する（既定 10 行） | ✗ | ✗ |
| `vi` | テキストエディタを起動する | ○ | **○** |
| `emacs` | テキストエディタを起動する | ○ | **○** |

**「1 画面ずつ表示する」と「編集できる」は別の軸です。**
この 2 つを分けて考えられるかが、ここの理解の分かれ目になります。

## ページャとエディタのちがい

`less` や `more` のように「中身を見るためだけ」のコマンドを **ページャ（pager）** と呼びます。
`vi` や `emacs` は **エディタ（editor）** で、見るだけでなく**書き換えられます**。

| | ページャ（`less` / `more`） | エディタ（`vi` / `emacs`） |
|:--|:--|:--|
| 中身を見る | ○ | ○ |
| 1 画面ずつ表示する | ○ | ○ |
| **中身を書き換える** | **✗** | **○** |
| 起動の速さ | 速い（全部読まない） | ファイルを読み込む |
| 誤操作のリスク | 低い（壊せない） | 高い（保存すると変わる） |

**本番環境で「見るだけ」のときは、あえてページャを使う**のが安全側の作法です。
`vi` で開いてしまうと、うっかり文字を入力して `:wq` で保存する事故が起こりえます。

```bash
$ less /etc/nginx/nginx.conf        # 見るだけなら壊しようがない
$ vi /etc/nginx/nginx.conf          # 編集する意図があるときだけ開く
```

### エディタについて

`vi` は **Linux で標準的に使用されるテキストエディタ**です。
`emacs` も `vi` と並んで愛用者の多いテキストエディタです。

```bash
$ vi sample.log                     # エディタが起動する
                                    # i を押すと入力モードになり、中身を書き換えられる
                                    # ESC で戻り、:q! で保存せず終了、:wq で保存して終了

$ emacs sample.log                  # emacs が起動する（環境によっては未インストール）
                                    # Ctrl+X Ctrl+S で保存、Ctrl+X Ctrl+C で終了
```

**補足** … `emacs` は多くのディストリで**既定ではインストールされていません**。
一方 `vi`（`vim-minimal`）はほぼ確実に入っています。
この差が、実務で `vi` を覚える理由になっています。

```bash
$ which vi emacs                    # インストール状況を確認する
/usr/bin/vi
/usr/bin/which: no emacs in (/usr/local/bin:/usr/bin:/bin)
```

### 読み取り専用でエディタを開く

どうしても `vi` の操作感で読みたい場合は、**読み取り専用**で開けます。

```bash
$ view /etc/nginx/nginx.conf        # vi と同じ操作だが書き込みできない
$ vi -R /etc/nginx/nginx.conf       # -R でも同じ（read-only モード）
```

**補足** … `set -o emacs` / `set -o vi` というシェルオプションもありますが、
これは**コマンドライン入力時のキーバインドの話**であり、
`emacs` / `vi` コマンドとは別物です
（[シェルのオプション設定](./シェルのオプション設定.md) を参照）。

## cat

**意味** … ファイルの内容を**すべて**表示する

以下の例では、100 行のファイルを使います。

```bash
$ seq 1 100 > sample.log            # 1〜100 の数字を1行ずつ書いたファイルを作る
$ wc -l sample.log                  # 行数を数えて確認する
100 sample.log
```

**例文**

```bash
$ cat sample.log                    # 100行が一気に流れる（画面に収まらない）
1
2
...
100
$                                   # 止まらずにプロンプトへ戻る
```

### 主なオプション

| オプション | 意味 |
|:--|:--|
| `-n` | すべての行に行番号を付ける |
| `-b` | **空行以外**に行番号を付ける |
| `-A` | 制御文字を可視化する（`-vET` と同じ） |
| `-E` | 行末に `$` を表示する |
| `-T` | タブを `^I` として表示する |
| `-s` | 連続する空行を 1 行にまとめる |

```bash
$ cat -n sample.log | head -3       # -n で行番号を付ける（先頭3行だけ表示）
     1  1
     2  2
     3  3

$ cat -A script.sh | head -3        # 制御文字を可視化する
#!/bin/bash$                        # 行末の $ が改行を表す
echo hello$
^Iindent$                           # ^I がタブを表す
```

**補足 … `-A` は「見えないバグ」を見つける道具です**

Windows で作ったファイルには改行コードに `\r`（CR）が含まれ、
`^M$` と表示されます。これが原因でスクリプトが動かないことがあります。

```bash
$ cat -A deploy.sh | head -2        # 改行コードを確認する
#!/bin/bash^M$                      # ^M があると Windows 改行（CRLF）
                                    # → bash: /bin/bash^M: bad interpreter になる

$ dos2unix deploy.sh                # 改行コードを LF に変換して直す
```

### ファイルを連結する

`cat` は **conCATenate（連結する）** の略です。
本来は「複数ファイルをつなげる」コマンドで、
1 ファイルだけ指定したときに「中身を表示する」ように見えているだけです。

```bash
$ cat file1.txt file2.txt > all.txt # 2つのファイルを連結して1つにまとめる
$ cat header.txt body.txt footer.txt > report.txt   # 3つを順に連結して1ファイルにする
```

### 大きなファイルに使ってはいけない

**`cat` は全部を画面に流します。** 数十万行のログだと端末が固まったようになり、
先頭は流れ去って読めません。

```bash
$ cat /var/log/messages             # 巨大なログだと画面が流れ続けて読めない
                                    # Ctrl+C で中断するしかない

$ less /var/log/messages            # こちらを使う
```

## less

**意味** … ファイルの内容を**ページ（1 画面）ごとに**表示する

**例文**

```bash
$ less sample.log                   # 1画面ずつ表示する（q で終了）
1
2
...
（画面の高さぶんだけ表示されて止まる）
```

### 画面内のキー操作

| キー | 動作 |
|:--|:--|
| `スペース` / `f` | 次のページへ |
| `b` | **前のページへ戻る** |
| `↓` / `↑` | 1 行ずつ移動 |
| `g` | 先頭へ |
| `G` | 末尾へ |
| `/文字列` | 下方向へ検索 |
| `?文字列` | 上方向へ検索 |
| `n` / `N` | 次の / 前の検索結果へ |
| `F` | 追従モード（`tail -f` と同じ。`Ctrl+C` で解除） |
| `&文字列` | その文字列を含む行**だけ**を表示する |
| `h` | ヘルプ |
| `q` | 終了 |

### 主なオプション

| オプション | 意味 |
|:--|:--|
| `-N` | 行番号を表示する |
| `-i` | 検索時に大文字小文字を区別しない |
| `-S` | 長い行を折り返さない（横スクロールする） |
| `-R` | 色（ANSI エスケープ）をそのまま表示する |
| `-X` | 終了時に画面をクリアしない |
| `+G` | **末尾から**開く |
| `+F` | 追従モードで開く（`tail -f` 相当） |
| `+/文字列` | その文字列を検索した状態で開く |

```bash
$ less -N sample.log                # 行番号を表示して開く
$ less +G /var/log/messages         # 末尾から開く（最新のログをすぐ見る）
$ less +F /var/log/messages         # tail -f と同じ追従モードで開く
$ less -S wide.csv                  # 折り返さずに横スクロールで読む
$ less +/ERROR app.log              # ERROR を検索した状態で開く
```

**補足 … `less` はファイル全体を読み込まずに表示を始めます**

数 GB のログでも一瞬で開きます。実務ではこれが決定的な差になります。

**補足 … `&` による絞り込みが便利です**

`grep` してから `less` に渡さなくても、開いたまま絞り込めます。

```bash
$ less /var/log/messages            # 開く
&ERROR                              # ERROR を含む行だけが表示される
&                                   # （空で Enter）絞り込みを解除する
```

### パイプでつないで使う

長い出力を読むときの定番です。

```bash
$ ps aux | less                     # プロセス一覧をページ送りで読む
$ journalctl -u nginx | less        # systemd のログをページ送りで読む
$ aws ec2 describe-instances | less # JSON 出力をページ送りで読む
```

### 既定オプションを固定する

毎回オプションを打たずに済ませたい場合は、`LESS` 環境変数に入れます。

```bash
$ export LESS='-R -N -i'            # -R:色を表示 -N:行番号 -i:検索で大小無視
$ less sample.log                   # 上のオプションが自動で適用される
```

`man` コマンドの表示にも `less` が使われているため、この設定は man ページにも効きます。

## more

**意味** … ファイルの内容を**ページ（1 画面）ごとに**表示する（`less` より古いコマンド）

**例文**

```bash
$ more sample.log                   # 1画面ずつ表示する
1
2
...
--More--(23%)                       # 画面下に進捗率が出る
```

| キー | 動作 |
|:--|:--|
| `スペース` | 次のページへ |
| `Enter` | 1 行だけ進む |
| `b` | 前のページへ（util-linux 版） |
| `/文字列` | 検索 |
| `v` | エディタを起動する |
| `q` | 終了 |

**補足 … `more` は末尾まで表示すると自動的に終了します**

`less` は `q` を押すまで終わりません。この違いは実際に触るとすぐ分かります。

もともと `more` には「戻れない」という制約があり、それを改良したのが `less` です。
**「less is more」（less のほうが more より高機能）** という言葉遊びが名前の由来として知られています。

現在の Linux（util-linux 版）の `more` は `b` で 1 画面戻れますが、
検索や移動の機能は `less` に及びません。**実務では `less` を使えば十分**です。

| 項目 | `more` | `less` |
|:--|:--|:--|
| 前のページへ戻る | 限定的 | ○（`b` / `↑` / `g`） |
| 末尾まで表示したとき | **自動的に終了する** | `q` を押すまで終わらない |
| ファイルの読み込み | 先に読む | **必要なぶんだけ読む**（巨大ファイルでも速い） |
| 検索の機能 | 単純 | 前方・後方検索、ハイライト、絞り込み |
| 標準搭載 | POSIX で規定 | ほぼすべてのディストリに同梱 |

## head

**意味** … ファイルの**先頭**を表示する（既定は 10 行）

**例文**

```bash
$ head sample.log                   # 先頭10行を表示する（既定）
1
2
...
10

$ head -3 sample.log                # 行数を指定して先頭3行だけ表示する
1
2
3
```

### 主なオプション

| オプション | 意味 |
|:--|:--|
| `-n 行数` / `-行数` | 表示する行数を指定する |
| `-c バイト数` | 行ではなくバイト数で指定する |
| `-n -行数` | **末尾から数えた行数を除いて**表示する |
| `-q` | 複数ファイル指定時にファイル名の見出しを出さない |

```bash
$ head -n 3 sample.log              # -n を明示した書き方（-3 と同じ）
$ head -c 20 sample.log             # 先頭20バイトだけ表示する
$ head -n -95 sample.log            # 末尾95行を除いて表示する（＝先頭5行）
1
2
3
4
5
```

**補足 … ログの形式や CSV のヘッダを確認するのに使います**

```bash
$ head -1 data.csv                  # CSV のヘッダ行だけ確認する
id,name,created_at

$ head -3 /var/log/messages         # ログの書式を確認する
```

## tail

**意味** … ファイルの**末尾**を表示する（既定は 10 行）

**例文**

```bash
$ tail sample.log                   # 末尾10行を表示する（既定）
91
...
100

$ tail -3 sample.log                # 末尾3行だけ表示する
98
99
100
```

### 主なオプション

| オプション | 意味 |
|:--|:--|
| `-n 行数` / `-行数` | 表示する行数を指定する |
| `-n +行数` | **その行から最後まで**表示する（`+` に注意） |
| `-c バイト数` | 行ではなくバイト数で指定する |
| `-f` | 追記された内容を**リアルタイムで表示し続ける** |
| `-F` | `-f` に加え、**ローテートされても追従し続ける** |

```bash
$ tail -n +95 sample.log            # 95行目から最後まで表示する（+ に注意）
95
96
97
98
99
100
```

### `-f` はログ調査の必需品

ファイルに追記された内容をリアルタイムで表示し続けます。

```bash
$ tail -f /var/log/messages         # 追記されるログを流し続ける（Ctrl+C で終了）

$ tail -F /var/log/messages         # ローテートされても追従し続ける

$ tail -f /var/log/nginx/access.log | grep 500   # 追記を監視しつつ 500 だけ拾う
                                    # 500エラーだけを絞り込んで監視する
```

**`-f` と `-F` の違い**

`logrotate` でログが切り替わると、`-f` は**古いファイルを見続けてしまい、何も出なくなります**。
`-F` は同じ名前のファイルを開き直すため、追従を続けられます。

| オプション | ローテート後 |
|:--|:--|
| `-f` | 古いファイルを見続ける（**止まったように見える**） |
| `-F` | 新しいファイルを開き直して追従する |

**長時間の監視には `-F` を使う**のが実務での定石です。

## そのほかの表示コマンド

| コマンド | 用途 |
|:--|:--|
| `tac` | `cat` の逆。**末尾の行から**表示する |
| `nl` | 行番号を付けて表示する（`cat -n` より書式が細かい） |
| `wc` | 行数・単語数・バイト数を数える |
| `zcat` / `zless` / `zgrep` | **圧縮されたまま**中身を読む |
| `strings` | バイナリファイルから読める文字列だけ抜き出す |
| `od` / `xxd` | バイナリを 16 進数で表示する |

```bash
$ tac sample.log | head -3          # 末尾から3行を表示する
100
99
98

$ wc -l /var/log/messages           # 行数を数える
15234 /var/log/messages

$ zless /var/log/messages-20260820.gz     # 圧縮ログを解凍せずに読む
$ zgrep ERROR /var/log/messages-*.gz      # 圧縮ログをまとめて検索する

$ strings /usr/bin/ls | head -5     # バイナリから文字列を抜き出す
```

**補足** … ログローテートで `.gz` になったファイルは、**解凍せずに `z` 系コマンドで読む**のが定石です。
ディスクを消費せず、元ファイルも壊しません。

## 使い分けの判断表

| こういうとき | 使うもの |
|:--|:--|
| 短い設定ファイルをさっと見たい | `cat` |
| 長いファイルを読みたい | `less` |
| 巨大なログを読みたい | `less +G` |
| ログの流れをリアルタイムで見たい | `tail -F` |
| ファイルの書式・ヘッダだけ確認したい | `head` |
| 直近のエラーだけ見たい | `tail -100` |
| 圧縮されたログを読みたい | `zless` / `zgrep` |
| 改行コードや制御文字を疑っている | `cat -A` |
| 編集したい | `vi` |
| 編集せずに vi の操作感で読みたい | `view` |

## 組み合わせて使う

`head` と `tail` を組み合わせると「特定の行だけ」を抜き出せます。

```bash
$ head -20 sample.log | tail -5     # 16〜20行目だけを取り出す
16
17
18
19
20

$ sed -n '16,20p' sample.log        # sed でも同じことができる
16
17
18
19
20
```

ログ調査の基本の型です。

```bash
$ tail -f /var/log/messages                     # まずリアルタイムで様子を見る
$ less +G /var/log/messages                     # 末尾から開いて、前に遡って読む
$ grep -n 'ERROR' /var/log/messages | less      # エラー行だけ抜き出して読む
$ grep -c 'ERROR' /var/log/messages             # エラーの件数だけ数える
```

**補足 … `cat file | grep` は書かない**

`grep` はファイルを直接読めるため、`cat` を経由するのは無駄です
（「Useless Use of Cat」と呼ばれます）。

```bash
$ cat sample.log | grep 50          # 動くが、cat を経由するぶん無駄がある
$ grep 50 sample.log                # こちらが正しい書き方
```

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| `cat` で巨大ファイルを開いて端末が固まった | 全行を画面に流している | `Ctrl+C` で中断し、`less` を使う |
| `more` が勝手に終了した | 末尾まで表示すると自動終了する仕様 | 戻って読みたいなら `less` |
| `less` から抜けられない | `q` が終了キー | `q` を押す（`Ctrl+C` では抜けない） |
| `tail -f` がログローテート後に止まる | 古いファイルを見続けている | `tail -F` を使う |
| `vi` で開いたファイルを壊した | 見るだけのつもりが編集モードに入った | 閲覧は `less` か `view` |
| `tail -n +95` が意図と違う | `+` は「その行から最後まで」の意味 | 末尾 N 行なら `tail -95` |
| スクリプトが `bad interpreter` で動かない | 改行コードが CRLF になっている | `cat -A` で確認し `dos2unix` |
| `.gz` のログが読めない | 圧縮されている | `zless` / `zcat` / `zgrep` |

## クラウド実務メモ

**CloudWatch Logs でも考え方は同じ**

`tail -f` に相当するのが `aws logs tail --follow` です。
Linux 側の操作を覚えておくと、クラウド側のコマンドもすぐ理解できます。

```bash
$ aws logs tail /aws/lambda/my-func --follow    # tail -f に相当する
$ aws logs tail /aws/lambda/my-func --since 1h  # 直近1時間ぶんを表示する
```

**Session Manager で入った本番サーバでは `less` を使う**

`vi` で設定ファイルを開くと、**うっかり保存して構成がずれる**リスクがあります。
確認だけなら `less`、変更するなら Ansible や Terraform を通す、という切り分けが安全です。

**コンテナ内には `less` が無いことがある**

`alpine` などの軽量イメージには `less` も `vi` も入っていないことがあります。
その場合はログを外に出して、ホスト側で読むのが確実です。

```bash
$ kubectl logs pod-name | less                  # ホスト側の less で読む
$ kubectl logs -f pod-name                      # tail -f 相当
$ kubectl exec -it pod-name -- cat /etc/nginx/nginx.conf   # Pod 内の設定を読む
```

**EBS の容量逼迫はログの `cat` から始まることがある**

巨大ログを `cat > file` でコピーするとディスクを圧迫します。
調査は `less` や `tail` で行い、必要な部分だけ抜き出します。

```bash
$ du -sh /var/log/*                 # どのログが大きいかを確認する
$ ls -lh /var/log/messages          # ファイルサイズを人が読める形式で表示する
```
