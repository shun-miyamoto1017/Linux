## シェルスクリプトとは

シェルスクリプトは、シェルへ渡すコマンドを上から順に書いたテキストファイルです。
同じ作業を繰り返すときや、手順書を自動化するときに使います。

```bash
$ file sample.sh                     # ファイルの種類を確認する
sample.sh: Bourne-Again shell script, Unicode text, UTF-8 text executable
```

| 用語 | 意味 |
|:--|:--|
| シェル | 入力されたコマンドを解釈して実行するプログラム |
| Bash | Linux で広く使われるシェルの一つ |
| スクリプト | 複数の処理を順番に記述したテキストファイル |
| インタプリタ | スクリプトを読み、書かれた命令を実行するプログラム |
| 実行権限 | ファイルをプログラムとして直接起動してよいことを示す権限 |

**補足**

拡張子 `.sh` は「シェルスクリプトだと人に分かりやすくする」ための慣習です。
ファイルを直接実行するとき、Linux が実行方法を決める根拠は実行権限と先頭行のシバンです。

---

## 実行方法の全体像

```text
sample.sh を実行したい
        │
        ├─ 現在のシェルへ変数や cd の結果を残したい
        │      └─ source ./sample.sh または . ./sample.sh
        │
        └─ 現在のシェルへ結果を残さなくてよい
               ├─ 実行権限がない ── bash ./sample.sh
               └─ 実行権限がある ── ./sample.sh
                                      └─ シバンでインタプリタを選ぶ
```

`bash`、`source`、`.` は、ファイルを引数として読み込むコマンドです。
そのため、対象ファイルに実行権限がなくても読み取り権限があれば実行できます。

一方、`./sample.sh` はファイルそのものをプログラムとして起動します。
この方法では実行権限が必要です。

---

## 確認に使うスクリプト

以降では、次の `sample.sh` を使って違いを確認します。

```bash
$ sed -n '1,6p' sample.sh            # 確認用スクリプトの内容を表示する
#!/usr/bin/env bash

MESSAGE="スクリプト内で設定"
cd /tmp
printf 'スクリプト内: %s\n' "$MESSAGE"
pwd
```

このスクリプトは、変数 `MESSAGE` を設定し、カレントディレクトリを `/tmp` へ移します。
実行後に変数と移動先が残るかを見ると、実行環境の違いが分かります。

## ひとつずつ例文で確認

### 別のシェルで実行する

**意味** … `bash ファイル名` は、新しい Bash を起動してファイルの内容を実行します。
対象ファイルの実行権限は不要ですが、Bash が内容を読むための読み取り権限は必要です。

**例文**

```bash
$ pwd                                # 実行前のカレントディレクトリを確認する
/home/shun/work

$ bash ./sample.sh                   # 新しい Bash でスクリプトを実行する
スクリプト内: スクリプト内で設定
/tmp

$ printf '[%s]\n' "$MESSAGE"        # 現在のシェルに変数が残ったか確認する
[]

$ pwd                                # 現在のシェルの移動先を確認する
/home/shun/work
```

**補足**

スクリプト内の変数設定と `cd /tmp` は、スクリプトを実行した別の Bash の中だけで有効です。
その Bash が終了すると、現在のシェルには影響が残りません。

---

### 現在のシェルで読み込む

**意味** … `source ファイル名` と `. ファイル名` は、ファイルの内容を現在のシェルで実行します。
変数、関数、`cd` の結果などが現在のシェルへ残ります。

**例文**

```bash
$ pwd                                # 読み込み前の場所を確認する
/home/shun/work

$ source ./sample.sh                 # 現在の Bash でスクリプトを読み込む
スクリプト内: スクリプト内で設定
/tmp

$ printf '[%s]\n' "$MESSAGE"        # 変数が現在のシェルに残ったか確認する
[スクリプト内で設定]

$ pwd                                # cd の結果が残ったか確認する
/tmp
```

`.` は `source` と同じ用途で使えます。

```bash
$ cd /home/shun/work                 # 確認のため元のディレクトリへ戻る
$ unset MESSAGE                      # 確認のため変数を削除する
$ . ./sample.sh                      # ドットコマンドで現在のシェルへ読み込む
スクリプト内: スクリプト内で設定
/tmp
```

**補足**

`source` は Bash で分かりやすい名前、`.` は POSIX で定められた書き方です。
他の POSIX シェルでも使うファイルでは、`.` のほうが移植しやすい書き方です。

設定ファイルの読み込みは現在のシェルを変えることが目的なので、`source` が適しています。
一方、内容を確認していないファイルを `source` すると、現在のシェルで任意のコマンドが動くため危険です。

---

### ファイルを直接実行する

**意味** … `./sample.sh` は、カレントディレクトリにあるファイルをプログラムとして直接起動します。
対象ファイルには実行権限が必要で、使用するインタプリタはシバンで決まります。

**例文**

```bash
$ ls -l sample.sh                    # 実行権限がない状態を確認する
-rw-r--r-- 1 shun shun 112 Aug 28 10:00 sample.sh

$ ./sample.sh                        # 実行権限なしで直接起動する
bash: ./sample.sh: Permission denied

$ echo $?                            # 直前の終了ステータスを確認する
126

$ chmod u+x sample.sh                # 所有者へ実行権限を追加する
$ ./sample.sh                        # 実行権限を付けて直接起動する
スクリプト内: スクリプト内で設定
/tmp
```

**補足**

`./` は「カレントディレクトリにある」というパス指定です。
通常、カレントディレクトリは `PATH` に含まれないため、`sample.sh` だけでは見つかりません。

> `PATH` の検索順と安全な追加方法は
> [シェル変数と環境変数](./シェル変数と環境変数.md) にまとめています。

## 実行権限を理解する

`ls -l` の先頭部分を見ると、読み取り・書き込み・実行の権限を確認できます。

```text
-rwxr-xr--
 │││││││││
 ││││││└┴┴─ その他のユーザ
 │││└┴┴──── グループ
 └┴┴─────── 所有者
```

| 記号 | 権限 | ファイルでの意味 |
|:-:|:--|:--|
| `r` | 読み取り | 内容を読める |
| `w` | 書き込み | 内容を変更できる |
| `x` | 実行 | プログラムとして直接起動できる |
| `-` | 権限なし | その操作は許可されていない |

### 所有者だけに実行権限を付ける

**意味** … `chmod u+x ファイル名` は、所有者にだけ実行権限を追加します。

**例文**

```bash
$ chmod u+x deploy.sh                # 所有者にだけ実行権限を追加する
$ ls -l deploy.sh                    # 変更後の権限を確認する
-rwxr--r-- 1 shun shun 840 Aug 28 10:10 deploy.sh
```

**補足**

学習環境でよく見る `chmod +x` は、現在の `umask` などを踏まえて複数区分へ実行権限を追加します。
誰に実行を許可するか明確にしたいときは、`u+x`、`g+x`、`o+x` を使い分けます。

---

### 数値で権限を設定する

**意味** … `chmod 755 ファイル名` は、所有者へ `rwx`、グループとその他へ `r-x` を設定します。

**例文**

```bash
$ chmod 755 deploy.sh                # 所有者は変更可、全員が実行可にする
$ ls -l deploy.sh                    # 数値指定の結果を確認する
-rwxr-xr-x 1 shun shun 840 Aug 28 10:10 deploy.sh
```

**補足**

共有サーバでは、必要なく `777` にしないことが重要です。
書き込み権限まで全員へ与えると、スクリプトを改ざんされる範囲が広がります。

## シバンで実行するプログラムを決める

シバンは、スクリプトの1行目に書く `#!` から始まる指定です。
ファイルを直接実行したとき、どのインタプリタへ渡すかをOSへ伝えます。

| 書き方 | 意味 | 向いている場面 |
|:--|:--|:--|
| `#!/bin/bash` | `/bin/bash` を固定して使う | 管理対象のLinuxで場所が決まっている |
| `#!/usr/bin/env bash` | `PATH` から最初の `bash` を探す | 配置場所が環境ごとに異なる可能性がある |
| `#!/bin/sh` | その環境のPOSIX系シェルを使う | Bash固有機能を使わないスクリプト |

### 固定した場所のバッシュを使う

**意味** … `#!/bin/bash` は、直接実行時のインタプリタを `/bin/bash` に固定します。

**例文**

```bash
$ head -1 deploy.sh                  # シバンを確認する
#!/bin/bash

$ /bin/bash --version | head -1      # 指定先がBashであることを確認する
GNU bash, version 5.3.0(1)-release (x86_64-pc-linux-gnu)
```

**補足**

`bash deploy.sh` と明示して実行した場合は、コマンドで指定した Bash がファイルを読みます。
シバンが使われるのは、主に `./deploy.sh` のように直接実行したときです。

---

### 検索してバッシュを使う

**意味** … `#!/usr/bin/env bash` は、現在の `PATH` から `bash` を探して起動します。

**例文**

```bash
$ command -v bash                    # PATHで最初に見つかるBashを確認する
/usr/bin/bash

$ head -1 sample.sh                  # envを使うシバンを確認する
#!/usr/bin/env bash
```

**補足**

仮想環境や複数バージョンを使い分けるときに便利です。
一方、`PATH` を変更できる環境では別の `bash` が選ばれる可能性があるため、管理サーバでは固定パスも検討します。

## 実行環境の違い

| 項目 | 別のシェルで実行 | 現在のシェルで読み込み |
|:--|:--|:--|
| 書き方 | `bash file` / `./file` | `source file` / `. file` |
| 変数の代入 | 終了すると消える | 現在のシェルに残る |
| `cd` | 終了すると元の場所のまま | 現在のシェルも移動する |
| 関数・エイリアス | 原則として現在のシェルへ残らない | 現在のシェルへ残る |
| `exit` | 実行中の別シェルが終了する | **現在のシェルが終了する可能性がある** |
| 主な用途 | バッチ処理、デプロイ、定期実行 | 設定ファイル、関数ライブラリの読み込み |

### 終了後に変数が残るか確認する

**意味** … 子シェルで行った変更は親シェルへ戻せませんが、`source` の変更は現在のシェルへ直接反映されます。

**例文**

```bash
$ bash ./sample.sh                   # 別のBashで確認用スクリプトを実行する
スクリプト内: スクリプト内で設定
/tmp
$ printf '[%s]\n' "$MESSAGE"        # 親シェルに変数が残っていないことを確認する
[]

$ printf 'CURRENT=value\n' > vars.sh # 読み込み確認用ファイルを作る
$ source ./vars.sh                   # 現在のシェルで読み込む
$ printf '[%s]\n' "$CURRENT"        # 現在のシェルに残ったことを確認する
[value]
```

**補足**

外部プログラムや子プロセスは、親プロセスの環境を直接書き換えられません。
環境変数の継承については [シェル変数と環境変数](./シェル変数と環境変数.md) を参照してください。

## 実行時によく使うオプション

| オプション | 意味 | 主な用途 |
|:--|:--|:--|
| `bash -n file` | 実行せず構文を読む | 実行前の構文確認 |
| `bash -x file` | 展開後のコマンドを表示しながら実行 | 処理経路の調査 |
| `bash -v file` | 読み込んだ行を表示しながら実行 | 入力内容の確認 |
| `bash -u file` | 未定義変数の参照をエラーにする | 変数名のタイプミス検出 |
| `bash -e file` | コマンドが失敗したら以降を実行せず終了する（`if` の条件部や `&&` の左辺など、失敗が想定される位置では止まらない） | 後続処理の誤実行を抑える |

### 実行せず構文を確認する

**意味** … `-n` はコマンドを実行せずに構文を読みます。

**例文**

```bash
$ bash -n deploy.sh                  # 実行せず構文エラーを確認する
$ echo $?                            # エラーがなければ終了ステータスは0
0

$ bash -n broken.sh                  # 閉じていない引用符があるファイルを確認する
broken.sh: line 4: unexpected EOF while looking for matching `"'
```

**補足**

`-n` が検出するのは構文エラーです。
存在しないコマンド、誤ったパス、権限不足などの実行時エラーまでは検出できません。

---

### 処理を追跡しながら実行する

**意味** … `-x` は、変数展開などを行った後のコマンドを標準エラーへ表示します。

**例文**

```bash
$ bash -x sample.sh                  # 展開後の処理を表示しながら実行する
+ MESSAGE=スクリプト内で設定
+ cd /tmp
+ printf 'スクリプト内: %s\n' スクリプト内で設定
スクリプト内: スクリプト内で設定
+ pwd
/tmp
```

**補足**

パスワードやトークンを変数に入れていると、`-x` の出力へ秘密情報が現れる可能性があります。
CIの公開ログや共有ログへそのまま残さないようにします。

> `-e`、`-u`、`pipefail` の条件と注意点は
> [シェルのオプション設定](./シェルのオプション設定.md) にまとめています。

## 使い分けの判断表

| やりたいこと | 選ぶ方法 | 理由 |
|:--|:--|:--|
| 実行権限のないスクリプトをBashで動かす | `bash ./file.sh` | ファイルをBashの入力として読むため |
| スクリプトを通常のコマンドとして動かす | `chmod u+x file.sh` の後に `./file.sh` | 実行権限とシバンを使うため |
| 設定した変数を現在のシェルへ残す | `source ./file.sh` | 現在のシェルで内容を実行するため |
| POSIXシェルでも設定を読み込む | `. ./file.sh` | `.` はPOSIXで定義された書き方のため |
| 実行前に構文だけ確認する | `bash -n ./file.sh` | コマンドを実行せずに構文を読むため |
| 処理の流れを追跡する | `bash -x ./file.sh` | 展開後のコマンドを確認できるため |

## 公式ドキュメントで確認した補足

| 確認した内容 | 公式仕様上の要点 |
|:--|:--|
| Bashへファイルを渡す | 最初の非オプション引数としてファイルを渡すと、Bashはその内容を読んで実行する |
| 直接実行 | 実行可能なシェルスクリプトは、新しい実行環境で処理される |
| シバン | 先頭の `#!` に続く部分が、直接実行時のインタプリタを指定する |
| `source` | Bashでは `.` の同義語で、現在のシェルでファイルを実行する |
| 別プロセスの変更 | 別の実行環境で行った変更は、呼び出し元のシェル環境を変更できない |
| 実行できないファイル | コマンドが見つかっても実行できない場合、Bashの終了ステータスは126になる |

`source file` のようにファイル名へ `/` を含めない場合、Bashは `PATH` を使ってファイルを探します。
カレントディレクトリのファイルを確実に読むときは、`source ./file` のようにパスを明示します。
