## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| オプションを**有効**にする | `set -o オプション名` |
| オプションを**解除**する | `set +o オプション名` |
| いまのオプション設定を一覧する | `set -o` |
| bash 独自オプションを有効にする | `shopt -s オプション名` |
| bash 独自オプションを解除する | `shopt -u オプション名` |

**シェルのオプションを設定できるのは `set` だけです。**
`declare` / `env` / `printenv` / `export` は変数まわり専用で、シェルの挙動は変えられません。

| コマンド | できること | シェルのオプション設定 |
|:--|:--|:-:|
| `set` | シェル変数・環境変数の表示 **＋ オプション設定** | **○** |
| `declare` | シェル変数・環境変数の表示、変数への属性付与 | ✗ |
| `env` | 環境変数の表示、一時的な環境変数付きコマンド実行 | ✗ |
| `printenv` | 指定の、または全ての環境変数の表示 | ✗ |
| `export` | 変数へのエクスポート属性の付与、環境変数の表示 | ✗ |

**補足 … `bash` はコマンドとして存在します**

`bash` は `/usr/bin/bash` に実体があり、実行すると**新しいシェルが起動します**。
起動時に `bash -o vi` のようにオプションを指定することも可能です。

ただしそれは**新しいシェルを起動する**動作であり、
**いま操作しているシェルのオプションは変えられません**。

```bash
$ bash -o noclobber                 # noclobber を付けた「新しいシェル」を起動する
$ set -o | grep noclobber           # 起動した子シェルの中で確認
noclobber      on

$ exit                              # 子シェルを抜けて元のシェルに戻る
$ set -o | grep noclobber           # 元のシェルの設定を確認
noclobber      off                  # 親シェルの設定は変わっていない
```

## set コマンドの三つの顔

`set` は引数によって、まったく違う 3 つの働きをします。ここが混乱の元です。

| 書き方 | 動作 |
|:--|:--|
| `set`（引数なし） | すべてのシェル変数と環境変数を表示する |
| `set -o` / `set +o`（オプション名なし） | 現在のオプション設定を一覧表示する |
| `set -o オプション名` / `set +o オプション名` | オプションを有効化・無効化する |

**例文**

```bash
$ set | head -5                     # 変数の一覧（膨大なので head で先頭5行だけ表示）
BASH=/usr/bin/bash
BASHOPTS=checkwinsize:cmdhist:...
BASH_ALIASES=()
BASH_ARGC=([0]="0")
BASH_ARGV=()

$ set -o | head -8                  # オプションの現在値を一覧（先頭8行）
allexport      off
braceexpand    on
emacs          on
errexit        off
errtrace       off
functrace      off
hashall        on
histexpand     on
```

> 変数の表示・作成については [シェル変数と環境変数](./シェル変数と環境変数.md) を参照してください。
> このノートは**オプション設定**に絞ります。

## オプションの有効化と無効化

シェルのオプション機能は、`set` コマンドで有効・無効を設定します。

```
set [-o][+o] オプション
```

**オプションを有効にするには「`-o`」を指定し、解除するには「`+o`」を指定します。**

```bash
$ set -o | grep noclobber           # まず現在の状態を確認する
noclobber      off

$ set -o noclobber                  # 有効にする
$ set -o | grep noclobber           # 変わったか確認
noclobber      on

$ set +o noclobber                  # 解除する
$ set -o | grep noclobber           # 戻ったか確認
noclobber      off
```

**補足 … なぜマイナスが有効でプラスが無効なのか**

直感と逆に見えますが、「フラグを**立てる**（`-`）／**下ろす**（`+`）」という
古い Unix の慣習に由来します。

**「マイナスは制約を加える、プラスは解き放つ」** と結びつけると忘れにくいです。
`set -x`（トレース ON）→ `set +x`（トレース OFF）で実際に手を動かすと定着します。

**補足 … 短縮形もあります**

主要なオプションには 1 文字の短縮形があり、`set -C` のように書けます。
実務では短縮形をまとめて `set -eux` のように書くことが多いです。

```bash
$ set -C                            # set -o noclobber と同じ
$ set +C                            # set +o noclobber と同じ
```

## オプション一覧

| オプション | 説明 | 短縮形 |
|:--|:--|:--|
| `allexport` | 新規作成・変更した変数を自動的に環境変数とする（エクスポートする） | `-a` |
| `emacs` | emacs エディタと同じキーバインドにする（矢印キーやマウスで操作でき、`Ctrl+D` で一文字削除できる、など） | — |
| `ignoreeof` | `Ctrl+D` を押してもログアウトしない設定にする | — |
| `noclobber` | リダイレクト演算子 `>` `>&` `<>` で既存のファイルを上書き不可に設定する | `-C` |
| `noglob` | パス名展開を無効に設定する（ワイルドカードによる展開 `*` や `?` が無効になる） | `-f` |
| `vi` | vi エディタと同じキーバインドにする（`ESC` キーでコマンドモードに移行し、入力時は `i` や `A` などで編集モードへの移行が必要、など） | — |

### allexport

**意味** … 新規作成・変更した変数を自動的に環境変数とする（エクスポートする）

**例文**

```bash
$ set -o allexport                  # 自動エクスポートを有効にする
$ FOO=bar                           # export を書かずに変数を定義
$ bash -c 'echo "[$FOO]"'           # 子シェルから見えるか確認
[bar]                               # 自動で環境変数になっている

$ set +o allexport                  # 自動エクスポートを解除
$ BAZ=qux                           # 解除後に定義した変数
$ bash -c 'echo "[$BAZ]"'           # 子シェルから見えるか確認
[]                                  # 通常のシェル変数なので引き継がれない
```

**補足** … `.env` ファイルの一括読み込みが定番の使い道です。
詳しい分解は [シェル変数と環境変数](./シェル変数と環境変数.md) にまとめています。

```bash
$ set -a; source .env; set +a       # .env の中身をすべて環境変数として読み込む
```

### emacs

**意味** … emacs エディタと同じキーバインドにする（**bash の既定値**）

**例文**

```bash
$ set -o emacs                      # emacs キーバインドにする（既定なので通常は不要）
$ set -o | grep emacs               # 現在の設定を確認する
emacs          on
```

| 操作 | キー |
|:--|:--|
| 行頭へ | `Ctrl+A` |
| 行末へ | `Ctrl+E` |
| カーソル位置の 1 文字削除 | `Ctrl+D` |
| 単語削除（後方） | `Ctrl+W` |
| 行末まで削除 | `Ctrl+K` |
| 履歴検索 | `Ctrl+R` |
| 貼り付け | `Ctrl+Y` |
| 画面クリア | `Ctrl+L` |

**補足** … emacs モードの `Ctrl+D` は「カーソル位置の 1 文字削除」ですが、
**行が空のときだけ EOF と解釈され、シェルが終了します**。
次の `ignoreeof` は、この「空行での `Ctrl+D`」を無効化するオプションです。

**補足** … これは**コマンドライン入力時のキーバインド**の話であり、
`emacs` コマンド（エディタ）とは別物です。

---

### ignoreeof

**意味** … `Ctrl+D` を押してもログアウトしない設定にする

**例文**

```bash
$ set -o ignoreeof                  # Ctrl+D での終了を無効にする
$ [Ctrl+D]                          # 空行で Ctrl+D を押してみる
Use "exit" to leave the shell.      # 終了せず、警告が出るだけ
```

**補足** … Bash マニュアルには「An interactive shell will not exit upon reading EOF.」とあります。
実装上は **`Ctrl+D` を 10 回連続で押すと結局終了**します。
回数は `IGNOREEOF` 変数で変えられます。

```bash
$ IGNOREEOF=3                       # 3回までは無視し、4回目で終了するようにする
$ echo $IGNOREEOF                   # 設定を確認する
3
```

本番の踏み台サーバや DB クライアントで、
うっかり `Ctrl+D` してセッションを落とす事故の防止に有効です。

### noclobber

**意味** … リダイレクト演算子 `>` `>&` `<>` で既存のファイルを上書き不可に設定する

**例文**

```bash
$ echo "original" > data.txt        # まず中身のあるファイルを用意する
$ set -o noclobber                  # 上書き禁止を有効にする

$ echo "overwrite" > data.txt       # 既存ファイルへの上書きを試みる
-bash: data.txt: cannot overwrite existing file     # 保護されて失敗する

$ echo "append" >> data.txt         # 追記(>>)は制限されないので成功する
$ cat data.txt                      # 中身を確認
original
append

$ echo "force" >| data.txt          # >| なら noclobber を無視して上書きできる
$ cat data.txt                      # 上書きされたことを確認
force
```

**補足** … 押さえるのは 3 点です。

1. 保護対象は **`>` `>&` `<>`** の 3 つ
2. **追記 `>>` は対象外**
3. **`>|` で意図的にバイパスできる**

**補足 … 新規作成は妨げられません**

`noclobber` が禁止するのは「**既存ファイルの上書き**」だけです。
まだ存在しないファイルへのリダイレクトは通ります。

```bash
$ set -o noclobber                  # 有効にする
$ echo "new" > newfile.txt          # 存在しないファイルなので作成できる
$ cat newfile.txt                  # 中身を確認する
new
```

手順書に `command > /etc/xxx.conf` があると、手が滑って設定ファイルを吹き飛ばす事故が起きます。
作業前に `set -o noclobber` しておくのは安価で効果の高い保険です。

### noglob

**意味** … パス名展開を無効にする（`*` や `?` による展開が効かなくなる）

**例文**

```bash
$ ls                                # 練習用のファイルを確認
a.txt  b.txt

$ echo *.txt                        # 通常はファイル名に展開される
a.txt b.txt

$ set -o noglob                     # パス名展開を無効にする
$ echo *.txt                        # 展開されず、文字列のまま出力される
*.txt

$ ls *.txt                          # ls も「*.txt」という名前のファイルを探しにいく
ls: cannot access '*.txt': No such file or directory

$ set +o noglob                     # 元に戻す
```

**補足** … `*` を含む文字列をそのまま扱いたいときに使います
（`find -name` に渡す引数、`rsync --exclude` のパターンなど）。
ただし一時的に切るより、**クォートで囲むほうが安全**です。

```bash
$ find . -name '*.log'              # クォートで囲めば noglob なしでも意図通り動く
$ rsync -av --exclude='*.tmp' src/ dst/   # 除外パターンもクォートで守る
```

### vi

**意味** … vi エディタと同じキーバインドにする

**例文**

```bash
$ set -o vi                         # vi キーバインドに切り替える
$ set -o | grep -E 'vi|emacs'       # どちらが有効か確認する
emacs          off
vi             on
```

| 操作 | キー |
|:--|:--|
| コマンドモードへ | `ESC` |
| 行頭へ | `ESC` → `0` |
| 行末へ | `ESC` → `$` |
| 編集モードへ | `i` / `a` / `A` |
| 単語削除（後方） | `ESC` → `db` |
| 行末まで削除 | `ESC` → `D` |
| 履歴検索 | `ESC` → `/` |
| 貼り付け | `ESC` → `p` |

**補足** … `emacs` と `vi` は**排他**です。片方を有効にすると、もう片方は自動的に無効になります。

恒久化するなら `~/.inputrc` に次を書きます。

```
set editing-mode vi
```

## 実務で必ず使うオプション

Ping-t / LinuC 101 の範囲外ですが、**運用スクリプトを書くなら必ず知っておくべき**ものです。
（Bash マニュアル The Set Builtin に記載）

| オプション | 短縮形 | 説明 |
|:--|:--|:--|
| `errexit` | `-e` | コマンドが非ゼロ終了したら即座にシェルを終了する |
| `nounset` | `-u` | 未定義変数を参照したらエラーにする |
| `pipefail` | — | パイプライン全体の終了ステータスを、最後に非ゼロを返したコマンドのものにする |
| `xtrace` | `-x` | 展開後のコマンドを標準エラーに出力する |
| `noexec` | `-n` | 読み込むが実行しない（**構文チェック**に使う） |

### スクリプト先頭の定番

```bash
#!/usr/bin/env bash                 # このスクリプトを bash で実行する宣言
set -euo pipefail                   # -e -u と pipefail をまとめて有効にする
```

### errexit（-e）… 失敗したら止まる

```bash
$ cat bad.sh                        # 中身を確認する
#!/bin/bash
cp /nonexistent /tmp/               # ここで失敗する
echo "コピー完了"                    # -e がないと、これが実行されてしまう

$ bash bad.sh                       # -e なしで実行する
cp: cannot stat '/nonexistent': No such file or directory
コピー完了                           # 失敗したのに「完了」と出てしまう

$ bash -e bad.sh                    # -e ありで実行する
cp: cannot stat '/nonexistent': No such file or directory
                                    # ここで止まる
```

### nounset（-u）… 未定義変数をエラーにする

タイポした変数名が空文字として素通しされるのを防ぎます。

```bash
$ DIR=""                            # 変数が空になってしまった状況を再現
$ echo rm -rf "$DIR/"               # 展開結果を確認すると…
rm -rf /                            # ルートを消しにいく形になっている

$ set -u                            # 未定義変数の参照をエラーにする
$ rm -rf "$UNDEFINED/"              # 定義していない変数を使ってみる
bash: UNDEFINED: unbound variable   # 実行される前に止まってくれる
```

**補足** … `-u` を有効にすると、意図的に未定義を許したい箇所でもエラーになります。
その場合は `${VAR:-既定値}` を使います。

```bash
$ set -u                            # 未定義をエラーにする
$ echo "${MAYBE:-default}"          # :- で「未定義なら既定値」を指定する
default                             # エラーにならない
```

### pipefail … パイプの途中の失敗を拾う

```bash
$ false | true; echo $?             # 左が失敗しても、パイプ全体は成功扱いになる
0                                   # 失敗が隠れてしまう

$ set -o pipefail                   # パイプの途中の失敗も拾うようにする
$ false | true; echo $?             # 同じコマンドをもう一度実行
1                                   # 失敗を検知できた
```

実務では `grep` や `jq` を挟んだときに効きます。

```bash
$ set -o pipefail                   # 有効にする
$ aws s3 ls s3://not-exist | wc -l  # aws が失敗しても wc は成功する
$ echo $?                           # pipefail があるので失敗を検知できる
1
```

### xtrace（-x）… 何が実行されたか表示する

```bash
$ set -x                            # トレースを有効にする
$ ls *.txt                          # 展開後のコマンドが + 行で表示される
+ ls a.txt b.txt
a.txt  b.txt
$ set +x                            # 元に戻す
+ set +x
```

### noexec（-n）… 実行せず構文だけ確認する

**本番適用前に必ず実施したい**チェックです。

```bash
$ bash -n deploy.sh                 # 実行せずに文法エラーだけをチェックする
                                    # 問題なければ何も出力されない

$ bash -n broken.sh                 # 構文エラーがある場合
broken.sh: line 12: syntax error near unexpected token `fi'
```

## そのほかのオプション

| オプション | 短縮形 | 説明 |
|:--|:--|:--|
| `verbose` | `-v` | 読み込んだ入力行をそのまま標準エラーに出力 |
| `posix` | — | POSIX 準拠モードにする |
| `monitor` | `-m` | ジョブ制御を有効にする |
| `notify` | `-b` | バックグラウンドジョブの終了を即座に通知 |
| `braceexpand` | `-B` | ブレース展開 `{a,b}` を行う（既定 ON） |
| `hashall` | `-h` | 実行したコマンドのパスを記憶する（既定 ON） |
| `histexpand` | `-H` | `!` によるヒストリ展開（対話シェルでは既定 ON） |
| `physical` | `-P` | シンボリックリンクを解決せず物理パスを使う |
| `errtrace` | `-E` | 関数内でも ERR トラップを継承する |
| `functrace` | `-T` | 関数内でも DEBUG トラップを継承する |
| `keyword` | `-k` | すべての引数を代入として扱う |
| `onecmd` | `-t` | 1 コマンド実行して終了する |
| `privileged` | `-p` | 特権モード（起動ファイルを読まない） |

```bash
$ set -o physical                   # シンボリックリンクを解決するモードにする
$ cd /var/run                       # /var/run は /run へのリンク（多くの環境で）
$ pwd                               # 実体のパスが表示される
/run

$ set +o physical                   # 元に戻す
$ cd /var/run                       # シンボリックリンクのディレクトリへ移動する
$ pwd                               # リンクのパスのまま表示される
/var/run
```

## set と shopt のちがい

bash にはオプションを設定するコマンドが **2 系統**あります。

| コマンド | 対象 | 由来 | 有効化 | 無効化 |
|:--|:--|:--|:--|:--|
| `set -o` | POSIX 由来のシェルオプション | sh 互換 | `set -o xxx` | `set +o xxx` |
| `shopt` | bash 独自の拡張オプション | bash 固有 | `shopt -s xxx` | `shopt -u xxx` |

```bash
$ set -o noclobber                  # POSIX 系のオプションは set で操作する
$ shopt -s globstar                 # bash 独自のオプションは shopt で操作する（-s = set）
$ shopt -u globstar                 # 無効化は -u（unset）

$ shopt | head -5                   # bash 独自オプションの一覧
autocd          off
assoc_expand_once off
cdable_vars     off
cdspell         off
checkhash       off
```

**符号の意味が逆転して見える**ので、試験でも実務でも混同しやすい箇所です。

| | 有効 | 無効 |
|:--|:--|:--|
| `set` | `-o` | `+o` |
| `shopt` | `-s` | `-u` |

### よく使う shopt オプション

| オプション | 説明 |
|:--|:--|
| `histappend` | 履歴ファイルを上書きせず追記する |
| `globstar` | `**` で任意の深さのディレクトリを表せる |
| `dotglob` | `*` が隠しファイルにもマッチする |
| `nullglob` | マッチ 0 件のとき、その単語を消す |
| `failglob` | マッチ 0 件のときエラーにする |
| `nocaseglob` | パス名展開で大文字小文字を区別しない |
| `extglob` | 拡張パターン `?(...)` `*(...)` を使えるようにする |
| `checkwinsize` | ウィンドウサイズ変更を検知して `LINES` / `COLUMNS` を更新する |

```bash
$ shopt -s globstar                 # ** を有効にする
$ ls **/*.conf                      # 任意の深さの .conf を一覧する

$ shopt -s nullglob                 # マッチ0件の単語を消す
$ ls *.zip                          # ファイルが無い場合、ls が引数なしで実行される
                                    # → カレントの一覧が出る（挙動が変わる点に注意）
$ shopt -u nullglob                 # 元に戻す
```

**補足** … `histexpand` のように、`set -o` と `shopt` の**両方から見える**オプションも一部あります。

## 設定を退避して元に戻す

`set +o` を**オプション名なしで**実行すると、
「いまの設定を再現するための `set` コマンドの一覧」が文字列として出力されます。

```bash
$ set +o | head -3                  # 出力の先頭3行を確認（set コマンドの列挙になっている）
set +o allexport
set -o braceexpand
set -o emacs
```

この出力をいったん変数にしまっておき、作業後に実行し直せば、元の状態に戻せます。

```bash
$ OLD_OPTS=$(set +o)                # set +o の出力を丸ごと変数に保存する
$ set -o noclobber                  # 一時的に設定を変えて作業
$ eval "$OLD_OPTS"                  # 保存しておいたコマンド列を実行して元に戻す
```

| 部分 | 意味 |
|:--|:--|
| `$( ... )` | 中のコマンドを実行し、**その出力を文字列として取り出す**（コマンド置換） |
| `OLD_OPTS=$(set +o)` | `set +o` の出力（数十行の `set` コマンド）を変数に入れる |
| `eval "$OLD_OPTS"` | **変数の中身を、コマンドとして実行する** |

`eval` は「文字列をコマンドとして実行する」コマンドです。
`echo "$OLD_OPTS"` だと文字が表示されるだけですが、`eval` を付けると実際に実行されます。

```bash
$ echo "$OLD_OPTS" | head -2        # eval を使わなければ、ただの文字列として表示される
set +o allexport
set -o braceexpand
```

> **`eval` は強力なので注意**
> 変数の中身を無条件に実行するため、**外部から受け取った値に `eval` を使ってはいけません**。
> ここでは `set +o` という自分のシェルの出力だけを対象にしているので安全です。

`shopt` にも同じ仕組みがあります。

```bash
$ OLD_SHOPT=$(shopt -p)             # shopt の現在の設定をコマンド列として保存する
$ shopt -s dotglob                  # 一時的に変更する
$ eval "$OLD_SHOPT"                 # 元に戻す
```

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| `set -o` したのに新しいターミナルで効かない | セッション限りの設定 | `~/.bashrc` に書く |
| `shopt -o` を打って混乱する | `set` と `shopt` の混同 | `set -o` と `shopt -s` を区別する |
| `set -e` なのにスクリプトが止まらない | `if` 条件内、`&&` の左辺、パイプ途中は対象外 | `pipefail` を併用し終了ステータスを明示確認 |
| `set -u` で正常な処理が止まる | 未定義を許したい箇所がある | `${VAR:-既定値}` を使う |
| `>` で設定ファイルを飛ばした | `noclobber` 未設定 | 作業前に `set -o noclobber` |
| `bash -o` で設定したのに親に効かない | 新しいシェルを起動しただけ | 親シェルで `set -o` を実行する |
| `set -x` の出力が邪魔 | トレースが有効なまま | `set +x` で戻す |

## クラウド実務メモ

**CI/CD や Systems Manager Run Command のスクリプトは `set -euo pipefail` を必須にする**

これがないと途中のコマンドが失敗しても最終ステータスが `0` になり、
「デプロイ成功」と表示されたまま壊れた状態が本番に出ます。

```bash
#!/usr/bin/env bash
set -euo pipefail                   # 失敗を確実に検知する

aws s3 sync ./dist s3://my-bucket/  # 失敗したらここで止まる
aws cloudfront create-invalidation --distribution-id ABC --paths '/*'
echo "デプロイ完了"                  # 全部成功したときだけ表示される
```

**`set -x` はログに秘匿情報を出す**

`AWS_SECRET_ACCESS_KEY` などを扱う区間は必ず `set +x` で囲みます。
CodeBuild や GitHub Actions のログは保存されるため実害が大きい箇所です。

```bash
set -x                                        # ここからトレース ON
build_app                                     # 通常の処理（ログに出てよい）

set +x                                        # トレースを一時的に OFF にする
export AWS_SECRET_ACCESS_KEY=$(get_secret)    # この行はログに出さない
set -x                                        # またトレース ON に戻す
```

`build_app` と `get_secret` はスクリプト内で定義した関数の例です。
ポイントは、**秘匿情報を扱う行だけを `set +x` と `set -x` で挟む**という書き方です。

`set -x` が有効なままだと、次のように**値そのものがログに残ります**。

```bash
$ set -x                                      # トレースを有効にする
$ export AWS_SECRET_ACCESS_KEY="wJalrXUt..."  # 秘密鍵を設定してみる
+ export AWS_SECRET_ACCESS_KEY=wJalrXUt...    # ← 値がそのままログに残ってしまう
```

**Terraform や Ansible のラッパースクリプトにも同じ原則**

`terraform apply` の前に `terraform plan` の結果を確認する処理を挟む場合、
`set -e` がないと plan が失敗しても apply に進んでしまいます。

```bash
#!/usr/bin/env bash
set -euo pipefail                   # 失敗したら止まる

terraform plan -out=tfplan          # 失敗したらここで止まる
terraform apply tfplan              # plan が成功したときだけ実行される
```

**EC2 のユーザーデータでも有効**

ユーザーデータは失敗しても静かに終わることがあります。
`set -euxo pipefail` を書いておくと、`/var/log/cloud-init-output.log` に
どこで止まったかが残ります。
