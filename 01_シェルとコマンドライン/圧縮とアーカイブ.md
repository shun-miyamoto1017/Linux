## 圧縮とアーカイブは別物

Linux ではこの 2 つが**別のコマンド**に分かれています。ここが Windows と違う点です。

| | 何をするか | コマンド |
|:--|:--|:--|
| **アーカイブ** | 複数のファイルを**1 つにまとめる**（サイズは減らない） | `tar` |
| **圧縮** | 1 つのファイルの**サイズを小さくする** | `xz` / `gzip` / `bzip2` |

```
複数ファイル ──[tar]──> 1つの .tar ──[gzip]──> .tar.gz
             まとめる              小さくする
```

`.tar.gz` という拡張子は「**tar でまとめてから gzip で圧縮した**」という意味です。
`.tgz` と短く書くこともあります。

| 拡張子 | 中身 |
|:--|:--|
| `.tar` | アーカイブのみ（圧縮なし） |
| `.tar.gz` / `.tgz` | tar + gzip |
| `.tar.bz2` / `.tbz2` | tar + bzip2 |
| `.tar.xz` / `.txz` | tar + xz |
| `.gz` / `.bz2` / `.xz` | 単一ファイルの圧縮のみ |
| `.zip` | Windows 由来。まとめる＋圧縮を 1 つで行う |

**補足** … `zip` は「まとめる」と「圧縮する」を同時に行います。
Linux で 2 つに分かれているのは、
**それぞれを別のツールとして組み合わせられる**ようにするための設計です。

## 圧縮コマンド

`xz` / `gzip` / `bzip2` は、**同じ 1 つのコマンドが圧縮と展開の両方を兼ねます**。
どちらになるかは `-d` の有無だけで決まります。

```text
bzip2 configure       … -d が無い     → 圧縮する（configure.bz2 ができる）
bzip2 -d configure.bz2 … -d が有る    → 展開する（configure に戻る）
```

**「圧縮したいのに `-d` を付けてしまう」「展開したいのに付け忘れる」のが
最もよくある取り違えです。** `-d` は decompress（展開）の `d` と覚えます。

```bash
$ gzip configure                    # -d なし → gzip 形式で圧縮する
$ bzip2 configure                   # -d なし → bzip2 形式で圧縮する
$ xz configure                      # -d なし → xz 形式で圧縮する
```

---

### xz

**意味** … xz 形式でファイルを圧縮する

xz 形式でファイルを圧縮するには `xz` コマンドを使用します。

```
xz [ オプション ] 処理対象ファイル名
```

| オプション | 説明 |
|:--|:--|
| `-d`, `--decompress` | 圧縮ファイルの展開 |
| `-k`, `--keep` | 圧縮、展開処理後に**元のファイルを削除しない** |
| `-l`, `--list` | 圧縮ファイルの情報を表示する |

**圧縮する**

```bash
$ ls                                # 圧縮前のファイルを確認
mail_backup
$ xz mail_backup                    # xz 形式で圧縮する
$ ls                                # 元ファイルは消え、.xz が作られる
mail_backup.xz
$ file mail_backup.xz               # ファイルの種類を確認する
mail_backup.xz: XZ compressed data
```

**展開する**

拡張子が「`.xz`」のファイルは xz 形式で圧縮されたファイルです。
xz 形式のファイルは、**`xz` コマンドの `-d` オプション、もしくは `unxz` コマンドで展開できます。**

```bash
$ xz -d configure.xz                # -d で展開する
$ ls                                # .xz は消え、元のファイルが戻る
configure

$ unxz configure.xz                 # unxz でも同じ結果になる
$ ls                                # 展開されたことを確認
configure
```

**オプション未指定の場合は、展開後元ファイルは削除されます。**
残したい場合は `-k` を付けます。

```bash
$ xz -d -k configure.xz             # 展開しても .xz を残す
$ ls                                # 両方が残っている
configure  configure.xz

$ xz -k configure                   # 圧縮でも同様に元を残せる
$ ls                                # 両方が残っている
configure  configure.xz
```

**情報を表示する**

`-l` は展開せずに、圧縮ファイルの情報だけを表示します。**展開はしません。**

```bash
$ xz -l configure.xz                # 圧縮率などの情報を見る
Strms  Blocks   Compressed Uncompressed  Ratio  Check   Filename
    1       1     11.4 KiB     42.1 KiB  0.271  CRC64   configure.xz
```

**そのほかのオプション**

| オプション | 意味 |
|:--|:--|
| `-c`, `--stdout` | 結果を標準出力へ出す（ファイルを書き換えない） |
| `-t`, `--test` | 圧縮ファイルが壊れていないか検査する |
| `-0` 〜 `-9` | 圧縮レベル（既定は `-6`。`-9` は高圧縮だがメモリと時間を食う） |
| `-T 数` | 使用するスレッド数（`-T0` で CPU 数に合わせる） |
| `-v` | 進捗を表示する |

```bash
$ xz -9 -T0 -v bigfile              # 高圧縮・並列・進捗表示で圧縮する
$ xz -t archive.xz                  # 壊れていないか検査する
```

**補足 … 対応する別名コマンド**

| コマンド | 同じ意味の書き方 |
|:--|:--|
| `unxz file.xz` | `xz -d file.xz` |
| `xzcat file.xz` | `xz -dc file.xz` |

### gzip

**意味** … gzip 形式でファイルを圧縮する

```bash
$ gzip access.log                   # gzip 形式で圧縮する
$ ls                                # 元ファイルは消え、.gz が作られる
access.log.gz

$ gunzip access.log.gz              # 展開する
$ ls                                # 元に戻ったことを確認
access.log
```

| オプション | 意味 |
|:--|:--|
| `-d` | 展開する（`gunzip` と同じ） |
| `-k` | 元のファイルを残す |
| `-c` | 結果を標準出力へ出す |
| `-l` | 圧縮ファイルの情報を表示する |
| `-r` | ディレクトリ内を再帰的に圧縮する |
| `-1` 〜 `-9` | 圧縮レベル（既定は `-6`） |
| `-v` | 圧縮率を表示する |

```bash
$ gzip -c access.log > backup.gz    # 元を残したまま別名で圧縮する
$ gzip -l access.log.gz             # 圧縮前後のサイズを確認する
         compressed        uncompressed  ratio uncompressed_name
              12043              84321  85.7% access.log
```

**補足** … `gzip -r dir/` は「ディレクトリをまとめて 1 つにする」のではなく、
**中のファイルを 1 つずつ個別に圧縮**します。まとめたいなら `tar` を使います。

---

### bzip2

**意味** … bzip2 形式でファイルを圧縮する

```bash
$ bzip2 mail_backup                 # bzip2 形式で圧縮する
$ ls                                # .bz2 になったことを確認
mail_backup.bz2

$ bzip2 -d mail_backup.bz2          # 展開する（bunzip2 でも同じ）
$ ls                                # 元に戻ったことを確認
mail_backup
```

| オプション | 意味 |
|:--|:--|
| `-d` | 展開する（`bunzip2` と同じ） |
| `-k` | 元のファイルを残す |
| `-c` | 結果を標準出力へ出す |
| `-t` | 壊れていないか検査する |
| `-1` 〜 `-9` | 圧縮レベル（既定は `-9`） |
| `-v` | 進捗を表示する |

### 三つの圧縮形式の比較

| | `gzip` | `bzip2` | `xz` |
|:--|:--|:--|:--|
| 拡張子 | `.gz` | `.bz2` | `.xz` |
| 展開コマンド | `gunzip` / `gzip -d` | `bunzip2` / `bzip2 -d` | `unxz` / `xz -d` |
| 圧縮率 | 低い | 中くらい | **高い** |
| 圧縮の速さ | **速い** | 遅い | 最も遅い |
| 展開の速さ | **速い** | 中くらい | 速い |
| `tar` のオプション | `-z` | `-j` | `-J` |
| よく使う場面 | ログローテート、日常 | 中間的な用途 | ソース配布、長期保管 |

**使い分けの目安**

- **日常のログ圧縮**は `gzip`。速さが正義
- **長期保管や配布**は `xz`。時間をかけてでも小さくしたい
- `bzip2` は現在では中間的な位置づけで、新規採用は減っている

**圧縮率が高い順に並べると `xz` ＞ `bzip2` ＞ `gzip`**

3 つのうち**最も圧縮率が高いのは `xz`** です。理由は採用しているアルゴリズムの違いにあります。

| 形式 | アルゴリズム | 特徴 |
|:--|:--|:--|
| `gzip` | DEFLATE | 古くからある標準。速いが圧縮率は最も低い |
| `bzip2` | Burrows-Wheeler 変換 | `gzip` より縮むが、圧縮も展開も遅い |
| `xz` | **LZMA2** | **最も縮む**。CPU とメモリを多く使うが、**展開は `bzip2` より速い** |

**`xz` が配布形式として選ばれる理由**

`xz` は `bzip2` より多くの CPU とメモリを要求しますが、

- **圧縮率が高い**ので、配布側の転送量とストレージが減る
- **展開が `bzip2` より速い**ので、受け取る側は待たされない

という組み合わせになります。圧縮は配布者が **1 回**だけ行い、
展開は利用者が **何千回も**行うため、「圧縮は遅くてよいが展開は速く」という
配布物の性質にちょうど合っています。

そのため近年はファイル配布の圧縮形式として `xz` の採用が増えており、
**Linux カーネルのソースコードも `.tar.xz` 形式で配布**されています。

**補足 … 存在しない形式に注意**

`zxy` / `bzip-ng` / `xzip2` といった名前は存在しません。
実際に使われる圧縮コマンドは、この 3 つに `zip` / `zstd` を加えた程度です。

| 名前 | 実在するか |
|:--|:--|
| `gzip` / `bzip2` / `xz` / `zip` | ○ |
| `zstd`（Facebook 製。`gzip` 並みに速く、より縮む） | ○ |
| `zxy` / `bzip-ng` / `xzip2` | **✕（存在しない）** |

迷ったら `which` や `man` で実在を確かめられます。

```bash
$ which xz                          # コマンドの実体がどこにあるか調べる
/usr/bin/xz
$ which xzip2                       # 存在しないコマンドは何も返らない
```

**共通する重要な性質**

| 性質 | 内容 |
|:--|:--|
| 元ファイルを消す | 3 つとも既定でそうなる。`-k` で残せる |
| 1 ファイルずつ | ディレクトリはまとめられない。`tar` と組み合わせる |
| `-d` で展開 | 3 つとも `-d` で展開できる |
| `-c` で標準出力 | ファイルを書き換えずパイプに流せる |

## 元ファイルを残して圧縮する

`xz` / `gzip` / `bzip2` は、**既定で元のファイルを消して圧縮ファイルに置き換えます**。

```bash
$ ls                                # 圧縮する前
configure

$ bzip2 configure                   # 圧縮する
$ ls                                # 元の configure が消えている
configure.bz2
```

元ファイルを残したい場合、方法は 3 つあります。

### 方法1 … `-k` を付ける

**意味** … keep の `k`。元のファイルを消さずに残す

```bash
$ bzip2 -k configure                # 元を残したまま圧縮する
$ ls                                # 両方ある
configure  configure.bz2
```

`gzip -k` / `xz -k` も同じです。**一番シンプルで、まずこれを覚えます。**

### 方法2 … `-c` と リダイレクト `>` を組み合わせる

**意味** … `-c` は「結果をファイルに書かず**標準出力へ出す**」オプション。
そのままでは圧縮データが画面に流れてしまうので、
リダイレクト `>` で出力先を画面からファイルへ切り替えます。

```bash
$ bzip2 -c configure > configure.bz2    # 元を残したまま、指定した名前で圧縮する
$ ls                                    # 両方ある
configure  configure.bz2
```

**この 2 つがセットで初めて意味を持ちます。**

```text
bzip2 -c configure          … 圧縮結果を「標準出力（＝画面）」へ出す
                  > configure.bz2  … その出力先を画面からファイルへ切り替える
─────────────────────────────────────────────
結果 … configure はそのまま、configure.bz2 が新しくできる
```

`-c` だけを付けて `>` を書き忘れると、**圧縮されたバイナリが端末に垂れ流されて
画面が壊れます**（`reset` コマンドで戻せます）。

**補足 … `-k` と `-c >` の使い分け**

| | `-k` | `-c` ＋ `>` |
|:--|:--|:--|
| 出力ファイル名 | **自動**（`元の名前 + 拡張子`） | **自分で決められる** |
| 別ディレクトリへ出す | できない | **できる** |
| パイプへ流す | できない | **できる** |
| 覚えやすさ | 簡単 | 少し手間 |

```bash
$ gzip -c access.log > /backup/access_$(date +%F).gz    # 別の場所へ日付つきの名前で保存する
$ gzip -c access.log | ssh backup-srv 'cat > a.gz'      # 圧縮しながら別サーバへ送る
```

### 方法3 … 先にコピーしてから圧縮する

```bash
$ cp configure configure.bak        # 先に控えを取る
$ bzip2 configure                   # 圧縮する（configure は消える）
$ ls                                # 控えと圧縮ファイルが残る
configure.bak  configure.bz2
```

素朴ですが、**ディスクに一時的に 2 倍の容量が必要**なので、
大きなファイルでは `-k` か `-c` を使います。

## 拡張子と展開コマンドの対応

**圧縮形式と展開コマンドは必ず一致させます。** 別の形式のコマンドでは展開できません。

| 拡張子 | 形式 | 展開できるコマンド |
|:--|:--|:--|
| `.gz` | gzip | `gunzip file.gz` / `gzip -d file.gz` |
| `.bz2` | bzip2 | `bunzip2 file.bz2` / `bzip2 -d file.bz2` |
| `.xz` | xz | `unxz file.xz` / `xz -d file.xz` |
| `.zip` | zip | `unzip file.zip` |
| `.tar` | tar（圧縮ではなくアーカイブ） | `tar xvf file.tar` |
| `.tar.gz` / `.tgz` | tar ＋ gzip | `tar xzvf file.tar.gz` |
| `.tar.bz2` | tar ＋ bzip2 | `tar xjvf file.tar.bz2` |
| `.tar.xz` | tar ＋ xz | `tar xJvf file.tar.xz` |

**それぞれの形式に「専用の展開コマンド」と「`-d` オプション」の 2 通りがあります。**

```text
gzip 形式  … gunzip file.gz   ＝ gzip -d file.gz
bzip2 形式 … bunzip2 file.bz2 ＝ bzip2 -d file.bz2
xz 形式    … unxz file.xz     ＝ xz -d file.xz
```

`gunzip` / `bunzip2` / `unxz` は、それぞれ `gzip -d` / `bzip2 -d` / `xz -d` を
呼び出すだけの**別名コマンド**です。**どちらを使っても結果は同じ**です。

### 形式を間違えるとどうなるか

**gzip 系のコマンドに `.bz2` を渡した場合**

```bash
$ gunzip configure.bz2              # gzip 用のコマンドに bzip2 のファイルを渡す
gzip: configure.bz2: unknown suffix -- ignored
```

「知らない拡張子なので無視した」と言われ、**何も起きません**。

**bzip2 系のコマンドに `.gz` を渡した場合**

```bash
$ bunzip2 configure.gz              # bzip2 用のコマンドに gzip のファイルを渡す
bunzip2: Can't guess original name for configure.gz -- using configure.gz.out
bunzip2: configure.gz is not a bzip2 file.
```

「bzip2 のファイルではない」とはっきり言われます。

**`tar` に圧縮ファイルだけを渡した場合**

```bash
$ tar configure.bz2                 # tar は圧縮コマンドではない
tar: Old option 'f' requires an argument.
```

`tar` は**アーカイブ（複数ファイルをまとめる）のコマンド**であって、
単体の圧縮ファイルを展開するものではありません。
`.tar.bz2` のように**アーカイブと圧縮が組み合わさっている**場合のみ、
`tar xjvf` で一度に展開できます。

**補足 … 拡張子は「印」でしかありません**

Linux は拡張子で中身を判断しません。中身の形式を確かめたいときは `file` を使います。

```bash
$ file configure.bz2                # 中身から形式を判定する
configure.bz2: bzip2 compressed data, block size = 900k

$ file configure.gz                 # gzip なら gzip と出る
configure.gz: gzip compressed data, from Unix, original size modulo 2^32 8893
```

詳しくは [ファイルの種類とタイムスタンプ](./ファイルの種類とタイムスタンプ.md) を参照。

## tar でアーカイブする

`tar` コマンドは複数のファイルをまとめて 1 つのファイル（アーカイブ）にする、
またはアーカイブを展開する際に使用するコマンドです。
**アーカイブを展開することなくアーカイブの内容を確認することもできます。**

```
tar [オプション] [ファイルまたはディレクトリ名]
```

### オプション一覧

| オプション | 説明 |
|:--|:--|
| `-c` | 新しいアーカイブを作成 |
| `-x` | アーカイブからファイルを展開 |
| **`-t`** | **アーカイブの内容を一覧表示** |
| `-f` | アーカイブファイル名を指定 |
| `-v` | 処理の詳細情報の表示 |
| `-z` | gzip を通して圧縮／展開 |
| `-j` | bzip2 を通して圧縮／展開 |
| `-J` | xz を通して圧縮／展開 |

**補足 … `-` を省略できます**

`tar` は歴史的な事情で、**先頭のハイフンを省略した書き方**が広く使われています。

```bash
$ tar cvf archive.tar dir/          # ハイフンなし（よく見る書き方）
$ tar -cvf archive.tar dir/         # ハイフンあり（どちらでも動く）
```

**補足 … ハイフンを付けるときは `f` を必ず最後に置きます**

`-f` の直後がアーカイブファイル名として読まれるためです。
**ハイフンありの `tar -cfv archive.tar dir/` は、`v` という名前のアーカイブを作ろうとして失敗します。**

```bash
$ tar -cvf archive.tar dir/         # 正しい。f の直後が archive.tar
$ tar -cfv archive.tar dir/         # 誤り。「v」というファイルを作りにいく
tar: archive.tar: Cannot stat: No such file or directory
tar: Exiting with failure status due to previous errors
```

一方、**ハイフンなしの `tar cfv archive.tar dir/` は正常に動きます**。
GNU tar は先頭のハイフンなしの塊を「古い形式のオプション指定」として解釈し、
`f` に対応する引数を並び順の先頭から拾うためです。
とはいえ書き方で挙動が変わるのは事故のもとなので、
**`f` を最後に置く**（`cvf` / `-cvf`）で統一するのが安全です。

**覚え方** … `c`（create）／`x`（extract）／`t`（list）のどれか 1 つ ＋ `v`（詳細）＋ `f`（file）
という順番で組み立てます。

### 作成する

```bash
$ ls                                # まとめる対象を確認する
dir1  dir2

$ tar cvf backup.tar dir1 dir2      # 2つのディレクトリを1つにまとめる
dir1/
dir1/file1.txt
dir1/file2.txt
dir2/
dir2/subdir2/

$ ls -lh backup.tar                 # 作られたアーカイブを確認する
-rw-rw-r--. 1 test test 10K Aug 31 23:40 backup.tar
```

**アーカイブしただけでは小さくなりません。** 圧縮は別の処理です。

### 中身を一覧する

**展開せずに中身を確認する**ときに使います。
「知らないアーカイブを展開する前に、何が入っているか確かめる」ための必須操作です。

```bash
$ tar tvf backup.tar                # 詳細つきで中身を一覧する
drwxrwxr-x test/test  0 2026-08-31 23:35 dir1/
-rw-rw-r-- test/test  4 2026-08-31 23:35 dir1/file1.txt
-rw-rw-r-- test/test  4 2026-08-31 23:35 dir1/file2.txt
drwxrwxr-x test/test  0 2026-08-31 23:36 dir2/

$ tar tf backup.tar                 # 名前だけ一覧する（v なし）
dir1/
dir1/file1.txt
dir1/file2.txt
dir2/
```

gzip 圧縮されているアーカイブなら `z` を足します。

```bash
$ tar ftvz test.tar.gz              # gzip 圧縮されたアーカイブの中身を一覧する
-rw-r--r-- root/root  1024 2026-08-31 09:35 etc/nginx/nginx.conf
```

この `ftvz` はハイフンなしの書き方なので、`f` が先頭でもアーカイブ名は並び順で拾われて動きます。
ハイフンを付けるなら `tar -tvzf test.tar.gz` のように、`f` を最後に置いてください。

**補足 … 現在の `tar` は圧縮形式を自動判別します**

GNU tar は拡張子や中身から圧縮形式を判断するため、`z` を省略しても動くことが多いです。
ただし**試験では明示的に指定する形で出題される**ため、`z` `j` `J` は覚えておきます。

```bash
$ tar tvf test.tar.gz               # z を省略しても展開できる（GNU tar の場合）
```

### 展開する

```bash
$ tar xvf backup.tar                # カレントディレクトリに展開する
dir1/
dir1/file1.txt
dir2/

$ tar xvf backup.tar -C /tmp/       # -C で展開先を指定する
$ ls /tmp                           # 指定した場所に展開されている
dir1  dir2

$ tar xvf backup.tar dir1/file1.txt # 特定のファイルだけ取り出す
dir1/file1.txt
```

| オプション | 意味 |
|:--|:--|
| `-C ディレクトリ` | 展開先を指定する |
| `--exclude=パターン` | 対象から除外する |
| `-p` | 権限をそのまま復元する（root で展開するときは既定） |
| `--strip-components=数` | 先頭の階層を指定数だけ取り除いて展開する |

```bash
$ tar czvf app.tar.gz --exclude='*.log' --exclude='node_modules' app/   # ログと依存ディレクトリを除いてまとめる
```

**補足 … 展開先が汚れないように注意します**

アーカイブによっては、トップレベルのディレクトリを持たず
**カレントディレクトリにファイルをばらまく**ものがあります。
先に `tar tf` で確認するか、空のディレクトリを作ってから展開します。

```bash
$ mkdir -p /tmp/extract && tar xvf unknown.tar -C /tmp/extract    # 空の場所に展開して中身を確かめる
```

## 圧縮しながらアーカイブする

`-z` `-j` `-J` を足すと、まとめる処理と圧縮する処理を **1 コマンドで**行えます。

| 形式 | 作成 | 一覧 | 展開 |
|:--|:--|:--|:--|
| gzip | `tar czvf a.tar.gz dir/` | `tar tzvf a.tar.gz` | `tar xzvf a.tar.gz` |
| bzip2 | `tar cjvf a.tar.bz2 dir/` | `tar tjvf a.tar.bz2` | `tar xjvf a.tar.bz2` |
| xz | `tar cJvf a.tar.xz dir/` | `tar tJvf a.tar.xz` | `tar xJvf a.tar.xz` |

```bash
$ tar czvf backup.tar.gz dir1 dir2  # gzip 圧縮つきでまとめる
dir1/
dir1/file1.txt
dir2/

$ ls -lh backup.tar backup.tar.gz   # 圧縮の効果を比べる
-rw-rw-r--. 1 test test  10K Aug 31 23:40 backup.tar
-rw-rw-r--. 1 test test 1.2K Aug 31 23:41 backup.tar.gz
```

## パイプで組み合わせる

`tar` に圧縮オプションが無かった時代の書き方で、**いまでも試験と実務の両方で出てきます。**

圧縮コマンドの `-c`（標準出力へ出す）と `-d`（展開）を組み合わせ、
パイプで `tar` に渡します。

```bash
$ gzip -cd test.tar.gz | tar ftv -  # 展開せずに中身を一覧する
-rw-r--r-- root/root  1024 2026-08-31 09:35 etc/nginx/nginx.conf
```

| 部分 | やっていること |
|:--|:--|
| `gzip -cd test.tar.gz` | `-d` で展開し、`-c` で結果を**画面ではなく標準出力**へ流す |
| `\|` | その出力を次のコマンドの入力に渡す |
| `tar ftv -` | `-f -` で「**入力を標準入力から受け取る**」という意味になる |

**`-` はファイル名の代わりに「標準入力／標準出力」を表します。**
`tar ftv -` は「パイプから流れてきたものを一覧表示する」という意味です。

```bash
$ gzip -cd test.tar.gz | tar fxv -  # パイプ経由で展開する
$ tar xzvf test.tar.gz              # z オプションを使えば1コマンドで済む
```

**補足 … いまは `z` を使えば十分です**

`gzip -cd ... | tar ...` と `tar xzvf ...` は同じ結果になります。
古い手順書や、`tar` が圧縮に対応していない環境で見かける書き方だと理解しておけば十分です。

**補足 … `tar` は `-` を省略できません**

`tar ftv` だけだと、アーカイブファイル名が指定されていないためエラーになります。

## zip と unzip

Windows とやりとりするときに使います。**既定ではインストールされていない**ことがあります。

```bash
$ zip -r archive.zip dir1           # ディレクトリをまとめて圧縮する
$ unzip archive.zip                 # 展開する
$ unzip -l archive.zip              # 展開せずに中身を一覧する
$ unzip -d /tmp/out archive.zip     # 展開先を指定する
```

| コマンド | 意味 |
|:--|:--|
| `zip -r out.zip dir/` | ディレクトリごと圧縮（`-r` が必要） |
| `unzip file.zip` | 展開 |
| `unzip -l file.zip` | 中身の一覧（`tar tf` に相当） |
| `unzip -d dir file.zip` | 展開先を指定（`tar -C` に相当） |

**補足 … 日本語のファイル名が文字化けすることがあります**

Windows で作られた zip は Shift_JIS で名前が入っているためです。
`-O` オプションで文字コードを指定します。

```bash
$ unzip -O cp932 japanese.zip       # Shift_JIS のファイル名を正しく展開する
```

## 圧縮したまま中身を見る

ログローテートで `.gz` になったファイルは、**解凍せずに読む**のが定石です。
ディスクを消費せず、元ファイルも壊しません。

| コマンド | 相当する通常コマンド |
|:--|:--|
| `zcat` | `cat` |
| `zless` | `less` |
| `zgrep` | `grep` |
| `zdiff` | `diff` |

```bash
$ zcat /var/log/messages-20260820.gz | head -5    # 先頭5行だけ見る
$ zless /var/log/messages-20260820.gz             # ページ送りで読む
$ zgrep ERROR /var/log/messages-*.gz              # 複数の圧縮ログをまとめて検索する
```

bzip2 と xz にも同じ系統のコマンドがあります。

| 形式 | 表示 | 検索 |
|:--|:--|:--|
| gzip | `zcat` / `zless` | `zgrep` |
| bzip2 | `bzcat` / `bzless` | `bzgrep` |
| xz | `xzcat` / `xzless` | `xzgrep` |

> ページャの操作は
> [ファイルの内容を見るコマンド](./ファイルの内容を見るコマンド.md) を参照してください。
