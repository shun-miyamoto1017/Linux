## 終了ステータスという前提

`&&` と `||` を理解するには、まず **終了ステータス**を知る必要があります。

コマンドは終了するときに **0〜255 の数値**を返します。

| 値 | 意味 |
|:--|:--|
| `0` | **成功** |
| `0 以外` | 失敗（数値の意味はコマンドごとに異なる） |

直前のコマンドの終了ステータスは `$?` で確認できます。

```bash
$ ls /etc                           # 存在するディレクトリを表示（成功する）
passwd  hosts  fstab
$ echo $?                           # 直前の終了ステータスを確認
0                                   # 0 = 成功

$ ls /nonexistent                   # 存在しないディレクトリを指定（失敗する）
ls: cannot access '/nonexistent': No such file or directory
$ echo $?                           # 直前の終了ステータスを確認
2                                   # 0 以外 = 失敗
```

**補足** … 「成功が 0」というのは直感と逆に見えますが、
**「エラーが 0 件だから成功」** と考えると覚えやすいです。
失敗の理由を数値で区別できるよう、`1` `2` … と番号が割り振られています。

`true` と `false` は、終了ステータスを返すだけのコマンドです。動作確認に使えます。

```bash
$ true; echo $?                     # true は必ず 0 を返す
0
$ false; echo $?                    # false は必ず 1 を返す
1
```

## ひとつずつ例文で確認

---

### セミコロン

**意味** … 区切り文字「`;`」は連結したコマンドを続けて順番に実行します。

前のコマンドが**成功しても失敗しても**、次のコマンドを実行します。

**例文**

以下は `ls` コマンドに続けて `date` コマンド（現在の日時を表示）を実行する場合の例です。

```bash
$ ls ; date                         # ls を実行してから date を実行する
file1  file2
2026年  8月 31日 日曜日 20:35:39 JST
```

**なお、「`;`」の前後にスペースがなくても構いません。**

```bash
$ ls;date                           # スペースなしでも同じ結果になる
file1  file2
2026年  8月 31日 日曜日 20:35:39 JST
```

**補足 … 前が失敗しても止まりません**

これが `&&` との決定的な違いです。

```bash
$ ls /nonexistent ; echo "次を実行"   # 前が失敗しても次は実行される
ls: cannot access '/nonexistent': No such file or directory
次を実行
```

**補足 … 改行と同じ意味です**

`;` は「1 行に複数のコマンドを書くための区切り」です。
改行して 2 行に書くのと、まったく同じ動作になります。

```bash
$ cd /var/log ; ls                  # ① 1行で書く
```

```bash
$ cd /var/log                       # ② 2行に分けて書く
$ ls                                #    ① とまったく同じ動作になる
```

3 つ以上つなげることもできます。

```bash
$ date ; uptime ; df -h             # 3つのコマンドを順番に実行する
```

### アンド二つ

**意味** … `command1` が**成功した場合のみ** `command2` を実行する制御演算子

**例文**

```bash
$ mkdir /tmp/work && cd /tmp/work   # ディレクトリ作成に成功したら移動する
$ pwd                               # 移動できたことを確認
/tmp/work

$ mkdir /root/work && cd /root/work # 権限がなく作成に失敗する
mkdir: cannot create directory '/root/work': Permission denied
                                    # cd は実行されない
$ pwd                               # 移動していないことを確認
/tmp/work
```

**補足 … 「順番に依存関係がある処理」で使います**

前が失敗したまま次に進むと壊れる場面では、必ず `&&` を使います。

```bash
$ cd /var/log && rm -rf ./*         # cd が成功したときだけ削除する

$ cd /var/log ; rm -rf ./*          # cd が失敗しても削除が走る（危険）
                                    # → 元のディレクトリの中身を消してしまう
```

**この 1 文字の違いが本番事故になります。**
「移動してから消す」「ビルドしてからデプロイする」といった処理は `&&` で書きます。

### パイプ二つ

**意味** … `command1` が**失敗した場合のみ** `command2` を実行する制御演算子

**例文**

```bash
$ ls /etc || echo "ディレクトリがありません"    # 成功するので右側は動かない
passwd  hosts  fstab

$ ls /nonexistent || echo "ディレクトリがありません"   # 失敗したので右側が動く
ls: cannot access '/nonexistent': No such file or directory
ディレクトリがありません
```

**補足 … エラー時の代替処理や通知に使います**

```bash
$ systemctl restart nginx || echo "再起動に失敗しました" >&2    # 失敗したときだけエラー出力に書く

$ command -v jq || sudo dnf install -y jq    # jq が無ければインストールする
```

`command -v コマンド名` は「そのコマンドが使えるか」を調べる書き方です。
使えれば場所を表示して成功（0）、無ければ失敗（0 以外）を返します。

**補足 … 出力を捨てて成否だけ使う**

`> /dev/null` を付けると、表示は捨てて成否だけを判定に使えます。
`/dev/null` は「書き込んだものが消えるゴミ箱」のような特殊ファイルです。

```bash
$ ls /etc > /dev/null || echo "ありません"    # 表示は捨てて、成否だけ見る
```

### アンパサンド

**意味** … コマンドを**バックグラウンド**で実行し、待たずに次へ進む

`&&`（2 個）とは別物です。**1 個だけの `&`** は「後ろで動かす」という意味になります。

**例文**

```bash
$ sleep 60 &                        # 60秒待つ処理を後ろで動かす
[1] 12345                           # [ジョブ番号] プロセスID が表示される
$                                   # すぐにプロンプトが返る

$ jobs                              # 動いているジョブを確認する
[1]+  Running                 sleep 60 &

$ fg %1                             # 前面に戻す（終わるまで待つ）
sleep 60
```

**補足** … 長い処理を流しておきたいときに使います。
ただし**ログアウトすると止まる**ため、本番では `nohup` や `systemd-run`、
あるいは `screen` / `tmux` を使うのが確実です。

```bash
$ nohup ./long_batch.sh > batch.log 2>&1 &   # ログアウトしても止まらないように実行
[1] 12346
```

## 組み合わせて使う

`&&` と `||` を並べると「成功したらこれ、失敗したらこれ」が 1 行で書けます。

```bash
$ systemctl is-active nginx > /dev/null && echo "稼働中" || echo "停止中"    # 状態で表示を分ける
稼働中
```

| 部分 | 意味 |
|:--|:--|
| `systemctl is-active nginx` | 稼働していれば成功（0）、していなければ失敗 |
| `> /dev/null` | 表示は捨てる |
| `&& echo "稼働中"` | 成功したときに実行 |
| `\|\| echo "停止中"` | 失敗したときに実行 |

**補足 … この書き方には落とし穴があります**

`A && B || C` は「A が成功したら B」ですが、**B が失敗した場合も C が実行されます**。
`if` 文のような厳密な分岐にはなりません。

```bash
$ true && false || echo "ここが実行される"    # A は成功したが B が失敗した場合
ここが実行される                     # true は成功したのに C が動いている
```

確実に分岐させたいときは `if` を使います。

```bash
$ if systemctl is-active nginx > /dev/null; then    # 確実に分岐させたいときは if
>     echo "稼働中"
> else
>     echo "停止中"
> fi
稼働中
```

### かっこでまとめる

複数のコマンドをまとめて `&&` の右側に置きたい場合は、`{ }` か `( )` で囲みます。

```bash
$ cd /tmp/work && { ls; date; }     # cd が成功したら ls と date を実行する

$ cd /tmp/work && ( ls; date )      # ( ) はサブシェルで実行される
```

| 書き方 | 実行される場所 | 特徴 |
|:--|:--|:--|
| `{ コマンド; }` | **現在のシェル** | 変数や `cd` の結果が残る。**末尾に `;` が必要** |
| `( コマンド )` | **サブシェル**（子プロセス） | 変数や `cd` の結果は残らない |

```bash
$ ( cd /tmp; pwd )                  # サブシェルで移動する
/tmp
$ pwd                               # 元のシェルは移動していない
/home/shun

$ { cd /tmp; pwd; }                 # 現在のシェルで移動する
/tmp
$ pwd                               # 移動したままになっている
/tmp
```

## パイプとの違い

`|`（パイプ）は連結の記号に見えますが、**役割がまったく違います**。

| 記号 | 何を渡すか |
|:--|:--|
| `;` `&&` `\|\|` | **何も渡さない**。実行するかどうかを制御するだけ |
| `\|` | 前のコマンドの**標準出力**を、次のコマンドの標準入力に渡す |

```bash
$ ls ; wc -l                        # ls の結果を表示してから、wc が入力待ちになる
file1  file2
                                    # ← ここで止まる（Ctrl+D で終了）

$ ls | wc -l                        # ls の出力が wc に渡され、行数が表示される
2
```

**補足** … `|` は「データを流す」、`;` `&&` `||` は「実行の順番と条件を決める」と覚えます。

**`|` そのものの詳細**（パイプにはエラーが乗らないこと、`tee` / `xargs` / `tr` / `wc`、
`PIPESTATUS` と `pipefail`）は [パイプとフィルタ](./パイプとフィルタ.md) にまとめてあります。
**`>` `<` `2>&1` などのリダイレクト**は [標準入出力とリダイレクト](./標準入出力とリダイレクト.md) を参照してください。

## まぎらわしい記号の整理

似た記号が多いので、まとめて確認します。

| 記号 | 意味 | 例 |
|:--|:--|:--|
| `;` | 順番に実行 | `ls ; date` |
| `&&` | 成功したら実行 | `cd /tmp && ls` |
| `\|\|` | 失敗したら実行 | `ls /x \|\| echo NG` |
| `&` | バックグラウンド実行 | `sleep 60 &` |
| `\|` | 出力を次に渡す（パイプ） | `ls \| wc -l` |
| `?` | **任意の 1 文字**を表すメタキャラクタ | `ls ?.txt` |
| `$` | **変数**を表すメタキャラクタ | `echo $HOME` |
| `$?` | 直前のコマンドの終了ステータス | `echo $?` |

**`?` と `$` は連結の記号ではありません。**
`?` はワイルドカード、`$` は変数を表す記号で、コマンドをつなぐ働きはありません。

```bash
$ ls ? date                         # 「?」は1文字のファイル名として扱われる
ls: cannot access '?': No such file or directory
ls: cannot access 'date': No such file or directory

$ ls $ date                         # 「$」も単なる文字として扱われる
ls: cannot access '$': No such file or directory
ls: cannot access 'date': No such file or directory
```

> `?` `*` `[ ]` などのパス名展開は [パス名展開とワイルドカード](./パス名展開とワイルドカード.md)、
> `$` `'` `"` `\` による打ち消しは [クォートとエスケープ](./クォートとエスケープ.md) にまとめています。
