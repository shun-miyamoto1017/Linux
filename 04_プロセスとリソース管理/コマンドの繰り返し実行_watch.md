## watchとは

**`watch` は、指定したコマンドを一定時間ごとに繰り返し実行して、結果を表示し続けるコマンド**です。

```text
watch [オプション] コマンド
```

**既定は 2 秒ごと**です。

```bash
$ watch date                          # date を2秒ごとに実行し続ける
```

**画面はフルスクリーンで上書きされます。** 流れていくのではなく、同じ場所が書き換わります。

```text
   通常の繰り返し（while）        watch
     結果1                          ┌──────────┐
     結果2                          │  結果3   │ ← 同じ場所が上書きされる
     結果3                          └──────────┘
     …と流れていく
```

**終了は `Ctrl+C`** です。`q` では終わりません（`top` とは違います）。

---

## 結果画面の見方

```text
Every 2.0s: date                                    vm: Sat Sep 19 23:29:03 2026

Sat Sep 19 23:29:03 UTC 2026
```

**いちばん上の 1 行がヘッダ**で、その下に**コマンドの出力そのもの**が出ます。

| 場所 | 中身 |
|:--|:--|
| **左上** | **`Every 2.0s:`** … 実行間隔 |
| **その右** | **実行しているコマンド** |
| **右上** | **ホスト名 ＋ 現在時刻** |
| 2 行目以降 | **コマンドの出力** |

```text
   Every 2.0s: date          vm: Sat Sep 19 23:29:03 2026
   └────┬───┘  └─┬─┘         └┬┘ └──────────┬─────────┘
      間隔     コマンド    ホスト名        現在時刻
```

**間隔を変えれば `Every 10.0s:` のように表示も変わる**ので、
**画面を見れば何秒ごとか分かります。**

**ヘッダが邪魔なときは `-t`（`--no-title`）で消せます。**

## よく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-n 秒`** / **`--interval 秒`** | **実行間隔を秒で指定する**（既定は 2 秒） |
| **`-d`** / **`--differences`** | **前回から変わった部分を反転表示する** |
| `-d=permanent` | 一度変わった部分をずっと反転させたままにする |
| **`-t`** / **`--no-title`** | **ヘッダを出さない** |
| **`-g`** / **`--chgexit`** | **出力が変わったら終了する** |
| `-q 回数` / `--equexit 回数` | 出力が変わらない状態が指定回数続いたら終了する |
| `-e` / `--errexit` | **コマンドが 0 以外で終了したら止まる** |
| `-b` / `--beep` | コマンドが 0 以外で終了したらビープを鳴らす |
| `-c` / `--color` | 色（ANSI エスケープ）を解釈して表示する |
| `-x` / `--exec` | `sh -c` を通さず直接実行する |
| `-p` / `--precise` | 実行時間のぶれを補正して、正確な間隔で実行する |

### 間隔を変える

```bash
$ watch -n 10 ps                      # ps を10秒ごとに実行する
```

```text
Every 10.0s: ps                                     vm: Sat Sep 19 23:33:12 2026

  PID TTY          TIME CMD
  667 pts/0   00:00:00 watch
  668 pts/0   00:00:00 watch
  669 pts/0   00:00:00 sh
  670 pts/0   00:00:00 ps
```

**`watch` と `sh` が写り込んでいる**のは、`watch` が **`sh -c` を通してコマンドを実行する**ためです（実測）。

**`-n` の後ろに秒数**です。**小数も指定できます**（`-n 0.5`）。

| 書き方 | 正しいか |
|:--|:--|
| **`watch -n 10 ps`** | **○** |
| `watch ps -n 10` | ✕ **`-n 10` が `ps` の引数として渡ってしまう**（ヘッダが `Every 2.0s: ps -n 10` になる） |
| `ps --time 10` | ✕ `ps` にそんなオプションは無い |
| `repeat 10 ps` | ✕ **`repeat` というコマンドは無い** |

**`watch` のオプションは、必ず監視したいコマンドより前**に書いてください。

### 変わったところを光らせる

**`-d` を付けると、前回の出力と違う部分が反転表示**されます。
**「どこが動いたか」を目で追える**ので、実務ではほぼ常用です。

```bash
$ watch -d -n 1 'df -h /var'          # /var の使用量が動いたところだけ光る
```

**`-d=permanent` にすると、一度でも変わった場所がずっと光ったまま**になります。
**席を外して戻ってきたときに「どこが動いたか」が残る**ので便利です。

```bash
$ watch -d=permanent -n 5 'ls -l /var/spool/mail'   # 一度でも動いた行が光り続ける
```

**注意 … `=` は省略できません。**
**`-d permanent` と空白で書くと、`permanent` がコマンドとして実行されます。**

```bash
$ watch -d permanent -n 1 date        # = を忘れると…
Every 2.0s: permanent -n 1 date       vm: Sun Sep 20 12:45:17 2026

sh: 1: permanent: not found
```

**ヘッダが `Every 2.0s: permanent -n 1 date` になっている**のが証拠です（実測）。
`-n 1` も `date` も、まとめて `permanent` の引数として渡ってしまっています。

### 変化したら止まる

**`-g`（`--chgexit`）は、出力が前回と変わった瞬間に `watch` を終了**します。
**「何かが起きるまで待つ」用途**にそのまま使えます。

```bash
$ watch -g -n 5 'systemctl is-active nginx' && echo "変化あり"   # 変わったら抜ける
```

**逆に `-q 回数` は「変わらない状態が続いたら終了」**です。
**「処理が落ち着くまで待つ」**のに使えます。

```bash
$ watch -q 3 -n 10 'ls /var/spool/batch | wc -l'   # 3回続けて同じなら終了
```

**どちらも終了ステータスは 0** です（実測）。`&&` でつないで次の処理に進めます。

**`-e`（`--errexit`）は、コマンドが 0 以外で終わったところで止まります。**

```bash
$ watch -e -n 1 false                 # 必ず失敗するコマンドを監視する
Every 1.0s: false                     vm: Sun Sep 20 12:45:31 2026

command exit with a non-zero status, press a key to exit
```

**画面の最下行にメッセージが出て、キー入力待ちで止まります**（実測）。

## クォートの落とし穴

**`watch` は既定で `sh -c` を通してコマンドを実行します。**
**パイプやリダイレクトを使うときは、全体をクォートで囲ってください。**

```bash
$ watch ps aux | grep nginx           # 危険。grep が watch の外に出てしまう
$ watch 'ps aux | grep nginx'         # 正しい。パイプごと watch に渡す
```

**囲まないと、パイプは「`watch` の出力」に対して効きます。**
`watch` の出力は画面制御が混ざっているので、**期待した結果になりません。**

**同じ理由で、リダイレクトや `;` も囲む必要があります。**

```bash
$ watch 'date; uptime'                # 2つのコマンドを続けて実行する
$ watch "ls -l /var/log | tail -5"    # 変数を展開したいときはダブルクォート
```

**補足 … 変数はいつ展開されるか**

**シングルクォートだと、`watch` が実行するたびに評価**されます。
**ダブルクォートだと、`watch` を起動した時点で 1 回だけ展開**され、以降は固定されます。

```bash
$ watch -n 1 'date +%s >> /tmp/log1'   # シングルクォート … 毎回評価される
（4回動かすと log1 には4つの違う値が入る）
$ watch -n 1 "date +%s >> /tmp/log2"   # ダブルクォートでも date は毎回動く
```

**変数の場合に差が出ます。**

```bash
$ N=$(date +%s)                        # いまの時刻を変数に入れておく
$ watch -n 1 "echo $N"                 # 起動時に展開される → ずっと同じ値
$ watch -n 1 'echo $N'                 # 毎回評価されるが、子シェルには N が無いので空になる
```

**「毎回評価したい」ならシングルクォート**、
**「起動時の値で固定したい」ならダブルクォート**、と覚えてください。

**重要 … `watch` が通すのは `sh` であって `bash` ではありません**

**Debian / Ubuntu では `/bin/sh` は `dash`** なので、**bash 固有の機能が使えません。**

```bash
$ ls -l /bin/sh                       # Ubuntu での /bin/sh の正体
lrwxrwxrwx 1 root root 4 Mar 31  2024 /bin/sh -> dash
$ sh -c 'echo "[$RANDOM]"'            # dash には $RANDOM が無い
[]
$ bash -c 'echo "[$RANDOM]"'          # bash なら値が出る
[10239]
```

**そのため `watch 'echo $RANDOM'` は、毎回空行が出るだけ**です（実測）。
**bash の機能を使いたいときは `-x` で直接 `bash -c` を呼びます。**

```bash
$ watch -n 1 -x bash -c 'echo $RANDOM'   # bash を明示すれば毎回違う値が出る
```

**`[[ ]]` や配列、`${var//a/b}` のような bash 固有の書き方も同じ**です。
**`watch` の中では使えない**と考えて、使うなら `-x bash -c` を挟んでください。

## top との使い分け

| | **`watch`** | **`top`** |
|:--|:--|:--|
| 何を見るか | **任意のコマンドの出力** | **プロセスの一覧**（専用） |
| 更新間隔 | **既定 2 秒**（`-n` で変更） | **既定 3 秒**（`d` キーで変更） |
| 終了 | **`Ctrl+C`** | **`q`** |
| 並べ替え | できない | **できる**（`P` / `M` キー） |
| 対象を絞る | コマンド側で絞る | **`u` キーでユーザ指定** |
| 変化の強調 | **`-d` でできる** | できない |

**`top` は「プロセス専用の監視画面」**、
**`watch` は「どんなコマンドでも監視画面にする道具」**です。

**`top` の詳細**は [リソース監視 プロセス単位](./リソース監視_プロセス単位.md) にまとめています。

**紛らわしいコマンド**

| コマンド | 正体 |
|:--|:--|
| **`uptime`** | **稼働時間と負荷平均**を 1 回表示する（繰り返さない） |
| **`jobs`** | **シェルのジョブ一覧**を表示する（繰り返さない） |
| **`tmux`** | **端末マルチプレクサ**。繰り返し実行とは関係ない |
| `tail -f` | **ファイルへの追記を追い続ける**（コマンドの再実行ではない） |

**「コマンドを繰り返し実行するのは `watch` だけ」**です。

## watch が使えないとき

**`watch` は `procps`（procps-ng）パッケージに入っています。**
**最小構成のコンテナなどには入っていないことがあります。**

```bash
$ dpkg -S $(which watch)              # Debian 系でどのパッケージか調べる
procps: /usr/bin/watch
```

**RHEL 系なら `rpm -qf $(which watch)` で同じことが調べられます**
（パッケージ名は `procps-ng`）。

```bash
$ watch date                          # 入っていない環境での実行例
-bash: watch: command not found
```

**そのときは `while` ループで代用**します。

```bash
$ while true; do clear; date; sleep 2; done      # watch date とほぼ同じ
```

| | **`watch`** | **`while` ループ** |
|:--|:--|:--|
| 画面の上書き | **自動** | **`clear` を自分で入れる** |
| ヘッダ | **出る** | 出ない |
| 差分の強調 | **`-d` でできる** | できない |
| どこでも動くか | パッケージが要る | **`bash` だけで動く** |

**手順書に書くときは `watch`、入っていない環境では `while`** と使い分けてください。

**補足 … ログを残したいときは `watch` を使わないでください**

`watch` は画面を上書きするので、**履歴が残りません。**
**あとで見返したいときは、追記していく形にします。**

```bash
$ while true; do date; df -h /var; sleep 60; done >> /tmp/disk.log 2>&1 &   # 追記で残す
```

## 実務での使い方

| やりたいこと | 書き方 |
|:--|:--|
| **ディスクが増えているか見る** | `watch -d -n 5 'df -h /var'` |
| **特定のプロセスが立ったか見る** | `watch -n 2 'pgrep -a nginx'` |
| **サービスの状態を追う** | `watch -n 5 'systemctl status nginx --no-pager'` |
| **接続数の変化を見る** | `watch -d -n 1 'ss -s'` |
| **ファイルが届くまで待つ** | `watch -g -n 10 'ls /var/spool/upload'` |
| **コピーの進み具合を見る** | `watch -d -n 2 'du -sh /backup'` |
| **RAID の再構築を追う** | `watch -n 30 'cat /proc/mdstat'` |

**最後の例は実務での定番**です。再構築には時間がかかるので、
**`watch` で放置しておくと進捗が分かります**
（[ソフトウェアRAIDの管理 mdadm](../06_ストレージとファイルシステム/ソフトウェアRAIDの管理_mdadm.md)）。

**注意 … 重いコマンドを短い間隔で回さないでください**

**`watch -n 1 'find / -name "*.log"'` のようなものは、監視対象のサーバを壊します。**
**間隔はコマンドの実行時間より長く**取ってください。

```text
   コマンドが 5 秒かかる  →  -n 1 だと実行が重なって負荷が積み上がる
                             -n 10 なら安全
```
