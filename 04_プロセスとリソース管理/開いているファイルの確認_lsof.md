## lsofとは

**`lsof` は「LiSt Open Files」の略で、開いているファイルを一覧するコマンド**です。
**引数を指定しない場合は、すべてのプロセスが開いているすべてのファイルを表示**します。

```bash
$ sudo lsof | head -5                # すべてのプロセスの開いているファイルを表示する
COMMAND  PID  TID TASKCMD USER  FD  TYPE DEVICE SIZE/OFF   NODE NAME
systemd    1              root cwd   DIR  253,0      255    128 /
systemd    1              root rtd   DIR  253,0      255    128 /
systemd    1              root txt   REG  253,0   102120 511529 /usr/lib/systemd/systemd
systemd    1              root mem   REG  253,0   636848  ...   /usr/lib64/libpcre2-8.so.0.11.0
```

**Linux では「すべてがファイル」**です。そのため `lsof` の守備範囲は、通常のファイルにとどまりません。

| `lsof` に写るもの | 例 |
|:--|:--|
| **通常のファイル** | `/var/log/messages` |
| **ディレクトリ** | カレントディレクトリ、ルートディレクトリ |
| **実行ファイル・共有ライブラリ** | `/usr/sbin/nginx`、`libc.so` |
| **ネットワークソケット** | **TCP / UDP の接続や待ち受け** |
| **パイプ・UNIXドメインソケット** | プロセス間通信 |
| **デバイスファイル** | `/dev/null`、端末 |

**「ポートを誰が使っているか」を `lsof` で調べられる理由**は、
**ソケットもファイルとして扱われる**からです。

**出力は非常に長くなります。** 実務では**必ず条件で絞ってから使います**。

```bash
$ sudo lsof | wc -l                  # 全体の行数を数える（数千〜数万行になる）
```

## よく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-i`** | **ネットワーク関連のファイル（ソケット）だけを表示する**。`-i :80` でポート指定 |
| **`-p PID`** | **指定した PID のプロセスが開いているファイルだけ**を表示する |
| **`-u ユーザ`** | **指定したユーザのプロセス**に絞る |
| **`-c 文字列`** | **その文字列で始まるコマンド名**のプロセスに絞る |
| **`+D ディレクトリ`** | **そのディレクトリ配下を再帰的に**探す |
| `+d ディレクトリ` | そのディレクトリ**直下だけ**を探す（再帰しない） |
| **`-t`** | **PID だけを出力する**（見出しなし。`kill` へ渡すとき） |
| **`-n`** | **IP アドレスをホスト名に変換しない**（速い） |
| **`-P`** | **ポート番号をサービス名に変換しない**（`80` を `http` にしない） |
| **`-a`** | **複数の条件を AND で結合する**（既定は OR） |
| **`+L1`** | **リンクが外された（削除済みの）ファイル**を選ぶ |
| `-N` | NFS 上のファイルに絞る |
| `-r 秒` | 指定した秒ごとに繰り返し表示する |

```bash
$ sudo lsof -i :443                  # 443番ポートに関わるものを表示する
$ sudo lsof -i TCP -s TCP:LISTEN     # 待ち受け中のTCPソケットだけを表示する
$ sudo lsof -p 1234                  # PID 1234 が開いているものを表示する
$ sudo lsof -c nginx                 # コマンド名が nginx で始まるプロセスに絞る
$ sudo lsof -u appuser -a -i         # appuser の、かつネットワーク関連だけ（AND条件）
$ sudo lsof -t -i :8080              # 8080を使っているPIDだけを出す
```

**`-a` を付けないと OR になります**

```text
lsof -u appuser -i      … appuser のファイル「または」ネットワーク関連（広い）
lsof -u appuser -a -i   … appuser の「かつ」ネットワーク関連（狙ったもの）  ← 通常こちら
```

**`-t` は `kill` と組み合わせる前提のオプション**です。

```bash
$ sudo kill $(sudo lsof -t -i :8080) # 8080を掴んでいるプロセスを終了させる
```

**実行前に必ず `lsof -i :8080` で中身を確認**します。想定外のプロセスを落とす事故を防ぐためです。

## 結果画面の見方

```bash
$ sudo lsof -i -P -n | head -6       # ネットワーク関連を名前解決なしで表示する
COMMAND   PID    USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
sshd      912    root    3u  IPv4   19283      0t0  TCP *:22 (LISTEN)
nginx    1234    root    6u  IPv4   28471      0t0  TCP *:80 (LISTEN)
nginx    1235  nginx    11u  IPv4   38102      0t0  TCP 10.0.1.5:80->10.0.2.9:51234 (ESTABLISHED)
```

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`COMMAND`** | **コマンド名**（先頭 9 文字） | 長い名前は切れる。`-c` で絞るときの手がかり |
| **`PID`** | **プロセス ID** | **これが分かれば `kill` できる** |
| `TID` | スレッド ID | スレッド単位で表示したときだけ出る |
| `TASKCMD` | タスク（スレッド）のコマンド名 | 同上 |
| **`USER`** | **プロセスの実行ユーザ** | 想定外のユーザなら要調査 |
| **`FD`** | **ファイルディスクリプタ**（後述） | **`cwd` `txt` `mem` `DEL` と数字で意味が変わる** |
| **`TYPE`** | **ファイルの種類**（後述） | `REG` `DIR` `IPv4` `unix` など |
| `DEVICE` | デバイス番号（メジャー,マイナー） | どのディスク上か |
| **`SIZE/OFF`** | **ファイルサイズ、またはオフセット** | **削除済みファイルの容量を測るときに見る** |
| `NODE` | **inode 番号**（ネットワークなら `TCP` などのプロトコル） | 同じ実体かどうかの判定に使える |
| **`NAME`** | **ファイルのパス、または接続先** | **一番知りたい情報** |

**ネットワークの場合の `NAME` の読み方**

```text
TCP *:80 (LISTEN)
    └┬┘ └───┬──┘
  全IPで待受   状態

TCP 10.0.1.5:80->10.0.2.9:51234 (ESTABLISHED)
    └────┬────┘  └──────┬─────┘  └────┬────┘
      自分側          相手側          状態
```

**`(LISTEN)` は待ち受け、`(ESTABLISHED)` は通信中**です。
状態の意味は [netstat ノート / TCP の状態でよく見るもの](../08_ネットワーク/ネットワーク状態の確認_netstat.md#tcp-の状態でよく見るもの) と同じです。

## FD列の読み方

**`FD` はファイルディスクリプタ**、つまり**プロセスが開いているものに付けられた番号**です。
**番号のほかに、特別な意味を持つ文字列**が入ります。

| 値 | 意味 |
|:--|:--|
| **`cwd`** | **カレントディレクトリ**（current working directory） |
| **`rtd`** | **ルートディレクトリ**（root directory） |
| **`txt`** | **プログラム本体の実行ファイル**（program text） |
| **`mem`** | **メモリにマップされたファイル**（共有ライブラリなど） |
| `ltx` | 共有ライブラリのテキスト部分 |
| **`DEL`** | **削除された共有ライブラリなどが、まだメモリにマップされたまま残っている状態**（`mem` / `txt` 側の話）。ログファイルのように通常の番号付き FD が指すファイルを消した場合は、`FD` は番号のままで `NAME` に `(deleted)` が付く |
| **`0` / `1` / `2`** | **標準入力 / 標準出力 / 標準エラー出力** |
| `3` 以降 | プログラムが開いた順に振られる番号 |

**番号のあとにアクセスモードが付きます。**

| 記号 | 意味 |
|:--|:--|
| **`r`** | **読み取り用に開いている** |
| **`w`** | **書き込み用に開いている** |
| **`u`** | **読み書き両用で開いている** |

```text
11u
└┬┘│
 │ └─ アクセスモード（u ＝ 読み書き両用）
 └─── ファイルディスクリプタ番号（この例では 11）
```

**`txt` と `mem` の違い**

```text
txt … そのプロセス自身の実行ファイル      （nginx なら /usr/sbin/nginx）
mem … 読み込んでいる共有ライブラリなど    （libc.so、libssl.so …）
```

**`cwd` が消えたディレクトリを指していることがあります。**
**プロセスが開いたままディレクトリを削除する**と、この状態になります。

## TYPE列の読み方

| 値 | 意味 |
|:--|:--|
| **`REG`** | **通常のファイル**（regular file） |
| **`DIR`** | **ディレクトリ** |
| **`CHR`** | **キャラクタ型デバイス**（端末、`/dev/null` など） |
| `BLK` | ブロック型デバイス（ディスク） |
| **`FIFO`** | **名前付きパイプ** |
| `PIPE` | 名前のないパイプ |
| **`IPv4`** / **`IPv6`** | **ネットワークソケット** |
| **`unix`** | **UNIX ドメインソケット**（同一ホスト内のプロセス間通信） |
| `sock` | 種類を特定できなかったソケット |
| `a_inode` | inotify などの匿名 inode |

**`unix` が多く出るのは正常**です。systemd や D-Bus がプロセス間通信に使っています。

## 調査パターン

### ポートを使っているプロセスを特定する

```bash
$ sudo lsof -i :8080 -P -n           # 8080番ポートを使っているプロセスを表示する
COMMAND   PID  USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
java     4521  app     42u  IPv6  98213      0t0  TCP *:8080 (LISTEN)
```

**「Address already in use」でサービスが起動しないとき**の定番調査です。

```text
起動できない
    ↓
lsof -i :ポート番号
    ↓
掴んでいるプロセスを特定
    ↓
止める、または設定でポートを変える
```

### 削除したのにディスクが空かない

**Linux では、削除しても「開いているプロセスがある間」は容量が解放されません。**

```bash
$ df -h /var                         # 使用率を確認する（100%近い）
$ du -sh /var/log                    # 実ファイルの合計を確認する（小さい）
```

**`df` と `du` が食い違ったら、これを疑います。**

```bash
$ sudo lsof +L1                      # 削除済みなのに開かれたままのファイルを探す
COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NLINK  NODE NAME
java     4521  app   12w   REG  253,0 5368709120     0 78213 /var/log/app.log (deleted)
```

| 列 | 見るポイント |
|:--|:--|
| **`NLINK`** | **`0` なら、ファイル名がすでに消えている** |
| **`SIZE/OFF`** | **まだ占有している容量** |
| **`NAME`** | **末尾に `(deleted)` が付く** |

**解放するには、そのプロセスを再起動するかファイルを閉じさせます。**

```bash
$ sudo systemctl restart myapp       # プロセスを再起動して解放する
```

**`kill -9` の前に、ログローテートの設定（`copytruncate` の有無）を見直す**のが本筋の対処です。

### umount できない

```bash
$ sudo umount /mnt/data              # アンマウントを試みる
umount: /mnt/data: target is busy.

$ sudo lsof +D /mnt/data             # そのディレクトリ配下を使っているプロセスを探す
```

詳しい手順は
[06_ストレージとファイルシステム / マウントとアンマウント](../06_ストレージとファイルシステム/マウントとアンマウント.md) にまとめています。

### 特定のプロセスが何を開いているか見る

```bash
$ sudo lsof -p 1234                  # PID 1234 が開いているものをすべて表示する
$ sudo lsof -p 1234 | grep REG       # 通常ファイルだけに絞る
$ sudo lsof -p 1234 | wc -l          # 開いている数を数える
```

**「Too many open files」というエラー**が出たときは、この数と上限を比べます。

```bash
$ ulimit -n                          # そのシェルでのファイルディスクリプタ上限を確認する
$ cat /proc/1234/limits | grep files # 実行中プロセスの上限を確認する
```

## fuserとの使い分け

**`fuser` も「使っているプロセス」を調べるコマンド**です。

```bash
$ sudo fuser -m /mnt/data            # そのマウントポイントを使っているPIDを表示する
$ sudo fuser -v /var/log/app.log     # 詳細（ユーザ・アクセス種別）付きで表示する
$ sudo fuser 8080/tcp                # 8080番ポートを使っているPIDを表示する
```

| | **`lsof`** | **`fuser`** |
|:--|:--|:--|
| 出力 | **コマンド名・ユーザ・パスまで詳しい** | **PID が中心で簡潔** |
| 速度 | 全体を舐めると遅い | **速い** |
| 向いている場面 | **原因を人に説明する / 詳しく調べる** | **スクリプトで PID を取る** |
| インストール | `lsof` パッケージ | `psmisc` パッケージ |

```bash
$ sudo fuser -km /mnt/data           # 使っているプロセスを強制終了してからアンマウントする
```

**`-k` は問答無用でプロセスを終了させます。** 本番環境では、**まず `lsof` で中身を確認**してから判断します。
