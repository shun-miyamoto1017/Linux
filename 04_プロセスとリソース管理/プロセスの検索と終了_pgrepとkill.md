## プロセスとPID

**プロセスとは、システム上で動作しているプログラムの最小単位**です。
1 つ 1 つのプロセスには **PID（プロセス ID）という番号**が付きます。

```bash
$ ps                                  # 自分の端末で動いているプロセスを見る
    PID TTY          TIME CMD
   1635 pts/0    00:00:00 bash
   2514 pts/0    00:00:00 ps
```

| 列 | 意味 |
|:--|:--|
| **`PID`** | **プロセス ID**。プロセスを指定するときはこの番号を使う |
| `TTY` | 紐づいている端末 |
| `TIME` | CPU を使った累積時間 |
| **`CMD`** | **プロセス名**（コマンド名） |

**プロセスを止めるコマンドは PID を要求します。**
そのため「名前から PID を調べる」作業が必ず先に来ます。ここで使うのが `pgrep` です。

## pgrep

**意味** … **実行中のプロセスから、特定の名前を持つプロセス ID を検索するコマンド**です。

```text
pgrep [オプション] 検索パターン
```

**検索パターンには拡張正規表現が指定できます。**
既定では**プロセス名の一部にマッチすれば拾います**（部分一致）。

**例文**

```bash
$ sleep 300 &                         # 確認用に1つ目のプロセスを起動する
$ sleep 300 &                         # 確認用に2つ目も起動する
$ pgrep sleep                         # 名前に sleep を含むプロセスのPIDを出す
929
930
```

**補足** … 出力は**PID だけ**です。そのままパイプやコマンド置換に流せる形になっています。

```bash
$ kill $(pgrep sleep)                 # 見つかったPIDをまとめて kill に渡す
```

### pgrep のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-l`** | **PID に加えてプロセス名も表示する** |
| **`-a`** | **PID に加えてコマンドライン全体を表示する**（引数まで見える） |
| **`-u ユーザ`** | **実効ユーザ（実際の権限）で絞り込む**。ユーザ名でも EUID でも指定できる |
| **`-U ユーザ`** | **実ユーザ（起動した本人）で絞り込む**。ユーザ名でも UID でも指定できる |
| **`-x`** | **プロセス名と完全一致**したものだけにする（部分一致をやめる） |
| `-c` | **件数だけ**を表示する |
| `-n` | 条件に合うもののうち**いちばん新しい**プロセスだけ |
| `-o` | 条件に合うもののうち**いちばん古い**プロセスだけ |
| `-f` | プロセス名ではなく**コマンドライン全体**に対してパターンを照合する |
| `-t 端末` | 指定した端末に紐づくプロセスに絞る（**`/dev/` を付けずに `pts/0` のように書く**） |

```bash
$ pgrep -l sleep                      # プロセス名も一緒に表示する
929 sleep
930 sleep

$ pgrep -a sleep                      # 引数まで含めたコマンドラインを表示する
929 sleep 300
930 sleep 300

$ pgrep -c sleep                      # 件数だけを知りたいとき
2

$ pgrep -n -l sleep                   # いちばん新しいものだけ
930 sleep

$ pgrep -u root -l sleep              # root 権限で動いているものに絞る
929 sleep
930 sleep
```

**拡張正規表現が使えます。**

```bash
$ pgrep -l '^(sle|sla)ep'             # sleep か slaep で始まるプロセス名を探す
929 sleep
930 sleep
```

**補足 … `-u` と `-U` の違い**

| オプション | 見るもの | 例 |
|:--|:--|:--|
| **`-u`**（小文字） | **実効ユーザ**（EUID）。**いまどの権限で動いているか** | SUID が付いた `passwd` は root |
| **`-U`**（大文字） | **実ユーザ**（UID）。**誰が起動したか** | `passwd` を起動した本人 |

**普段の調査で使うのは `-u`** です。「いま root 権限で動いているものはどれか」を知りたいことが多いためです。

**どちらも、ユーザ名でも数値（UID / EUID）でも指定できます。**

```bash
$ pgrep -U root | head -3             # ユーザ名で指定する
1
2
3
$ pgrep -U 0 | head -3                # UID で指定する（結果は同じ）
1
2
3
```

**`root` の UID は `0`** です。**ここは固定**なので、
`pgrep -U root` と `pgrep -U 0` は同じ意味になります。

**`pfind` というコマンドはありません。** 試験では誤答として出ます。

**補足 … SUID が付いたプログラムだと、`-u` と `-U` で結果が変わります**

**SUID（Set User ID）は「誰が実行しても、ファイルの所有者の権限で動く」仕組み**です
（[SGID 特殊パーミッション](../03_ユーザ管理とパーミッション/SGID_特殊パーミッション.md)）。
**このとき、実ユーザと実効ユーザが食い違います。**

```bash
$ ls -l myprog                        # root 所有で SUID が付いたプログラム
-rwsr-xr-x 1 root root 35336 Sep 19 23:35 myprog
$ su tu -c "/tmp/suid/myprog 120" &   # 一般ユーザ tu が実行する
$ ps axo pid,ruser,euser,command | grep '[m]yprog'   # 実ユーザと実効ユーザを並べる
  866 tu       tu       sh -c /tmp/suid/myprog 120
  867 tu       root     /tmp/suid/myprog 120
```

**867 番は「起動したのは `tu`、動いている権限は `root`」**という状態です。

```bash
$ pgrep -U root -a | grep myprog      # 実ユーザが root のもの … 867 は出ない
$ pgrep -u root -a | grep myprog      # 実効ユーザが root のもの … 867 が出る
867 /tmp/suid/myprog 120
$ pgrep -U tu -a | grep myprog        # 実ユーザが tu のもの … 866 も 867 も出る
866 sh -c /tmp/suid/myprog 120
867 /tmp/suid/myprog 120
```

**`-rwsr-xr-x` の `s` が SUID の印**です（所有者の実行権の位置）。
`passwd` や `mount` など、**一般ユーザが root 権限を必要とするコマンド**に付いています。

**「いま root 権限で動いているものを洗い出したい」なら `-u`** です。
**`-U` だと SUID のプロセスを取りこぼします**（実測）。

**補足 … 部分一致の落とし穴**

既定は部分一致なので、`pgrep ssh` は `sshd` も `ssh-agent` も拾います。
**狙ったプロセスだけを止めたいときは `-x` で完全一致にします。**

```bash
$ pgrep -x -l sle                     # 「sle」に完全一致するプロセス名は無い
                                      # 何も出ず、終了ステータスは 1 になる
```

**補足 … プロセス名は 15 文字までしか照合されません**

**`pgrep` / `pkill` が名前の照合に使うのは、`/proc/PID/stat` にある 15 文字**までです。
**それより長い名前は `-x` では絶対に一致しません。**

```bash
$ cp /bin/sleep ./averyveryverylongname12345   # 26文字の名前で動かしてみる
$ ./averyveryverylongname12345 200 &  # バックグラウンドで動かしておく
$ ps -eo pid,comm | grep avery        # comm は15文字で切られている
 2286 averyveryverylo
$ pgrep -x averyveryverylongname12345           # 一致しない
pgrep: pattern that searches for process name longer than 15 characters will result in zero matches
Try `pgrep -f' option to match against the complete command line.
$ pgrep -f averyveryverylongname12345           # -f なら当たる
2286
```

**`pkill -x` が無反応になったら、まずこの 15 文字制限を疑ってください。**
**長い名前は `-f`（コマンドライン全体に対する照合）を使います**（実測）。

### pgrep の結果画面の見方

```text
929 sleep 300
 │    │     │
 │    │     └─ コマンドライン引数（-a のときだけ出る）
 │    └─────── プロセス名（-l または -a のときだけ出る）
 └──────────── PID
```

| 表示 | どのオプションで出るか | 何が分かるか |
|:--|:--|:--|
| `929` | 既定 | **`kill` に渡す番号** |
| `929 sleep` | `-l` | **どのプログラムか**。同名の別物を掴んでいないかの確認 |
| `929 sleep 300` | `-a` | **どんな引数で起動されたか**。同じプログラムの複数インスタンスを見分けられる |

**終了ステータスも情報です。**

| 終了ステータス | 意味 |
|:-:|:--|
| **`0`** | **1 件以上見つかった** |
| **`1`** | **1 件も見つからなかった** |
| `2` | 構文エラー |
| `3` | 致命的エラー |

そのため「動いていたら再起動する」のような条件分岐が素直に書けます。

```bash
$ pgrep -x nginx > /dev/null && systemctl restart nginx   # 動いていたときだけ再起動する
```

### ps と grep の組み合わせとの違い

`ps ax | grep 名前` でも似たことができますが、**2 つの違い**があります。

```bash
$ ps ax | grep sleep                  # ps の出力を grep で絞り込む
  929 pts/0    S+     0:00 sleep 300
  930 pts/0    S+     0:00 sleep 300
  945 pts/0    R+     0:00 grep --color=auto sleep
```

| | **`pgrep`** | **`ps ax \| grep`** |
|:--|:--|:--|
| **grep 自身が混ざるか** | **混ざらない** | **混ざる**（上の 945 行） |
| 出力 | PID だけ（加工しやすい） | 行全体（`awk` で切り出しが要る） |
| 照合対象 | **プロセス名**（`-f` で全体） | **行全体**（パスや引数にも当たる） |
| 起動コスト | 1 プロセス | 2 プロセス＋パイプ |

**`grep` 自身が引っかかるのは、`grep sleep` というコマンドライン自体に `sleep` が含まれるから**です。
`ps` が一覧を作った時点で、その `grep` プロセスもすでに動いています。

**スクリプトで PID を取るなら `pgrep` を使ってください。**
`ps | grep` を使う場合は、次のどちらかで自分自身を除きます。

```bash
$ ps ax | grep '[s]leep'              # 先頭1文字を [] で囲む（クォート必須）
$ ps ax | grep sleep | grep -v grep   # grep の行を後から除く
```

## シグナルという仕組み

**シグナルとは、プロセスに送る「命令」**です。
「終了しろ」「一時停止しろ」「設定を読み直せ」といった指示を、番号または名前で送ります。

```text
   kill コマンド  ──シグナル──▶  対象のプロセス
                                    │
                    ┌───────────────┴───────────────┐
              捕まえて処理する                 捕まえられない
              （後片付けしてから終了）        （即座に強制終了）
```

**この図は「終了させる」シグナルを例にしたもの**です。
`SIGHUP`（設定の読み直し）や `SIGCONT`（再開）のように、**プロセスを終わらせないシグナルもあります**（後述）。

**重要なのは「シグナルは依頼であって、強制ではない」**という点です。
多くのシグナルはプロセス側で**受け取り方を決められます**（これを**ハンドラ**と呼びます）。
だからこそ「終了を依頼したのに終わらない」ということが起こります。

### 主なシグナル

```bash
$ kill -l                             # 使えるシグナルの一覧を表示する
 1) SIGHUP	 2) SIGINT	 3) SIGQUIT	 4) SIGILL	 5) SIGTRAP
 6) SIGABRT	 7) SIGBUS	 8) SIGFPE	 9) SIGKILL	10) SIGUSR1
11) SIGSEGV	12) SIGUSR2	13) SIGPIPE	14) SIGALRM	15) SIGTERM
16) SIGSTKFLT	17) SIGCHLD	18) SIGCONT	19) SIGSTOP	20) SIGTSTP
21) SIGTTIN	22) SIGTTOU	23) SIGURG	24) SIGXCPU	25) SIGXFSZ
（以下略。実際は 26) SIGVTALRM … 64) SIGRTMAX まで表示されます）
```

**実際の出力は 64 番まで**あります。26〜31 が `SIGVTALRM` などの残り、
**34 以降はリアルタイムシグナル**（`SIGRTMIN` 〜 `SIGRTMAX`）で、
**通常の運用で名前を指定して使うことはまずありません**。

**この中で実務と試験に出るのは 8 つ**です。

| 番号 | 名前 | 意味 | プロセス側で無視できるか |
|:-:|:--|:--|:-:|
| **1** | **`SIGHUP`** | **端末が切れた。デーモンでは「設定を読み直せ」の意味で使われる** | できる |
| **2** | **`SIGINT`** | **割り込み。`Ctrl+C` が送るもの** | できる |
| 3 | `SIGQUIT` | 終了してコアダンプを出す。`Ctrl+\` が送る | できる |
| **9** | **`SIGKILL`** | **強制終了。最後の手段** | **できない** |
| **15** | **`SIGTERM`**（既定） | **終了を依頼する。後片付けの機会を与える** | できる |
| **18** | **`SIGCONT`** | **一時停止したプロセスを再開する** | **捕捉はできるが、再開そのものは止められない** |
| **19** | **`SIGSTOP`** | **一時停止する** | **できない** |
| **20** | **`SIGTSTP`** | **一時停止。`Ctrl+Z` が送るもの** | できる |

**`SIGKILL`（9）と `SIGSTOP`（19）だけは、プロセス側で捕まえたり無視したりできません。**
カーネルが直接処理するためで、これが「9 なら必ず止まる」と言われる理由です。

## kill

**意味** … **PID を指定してシグナルを送るコマンド**です。

```text
kill [-シグナル] PID [PID...]
```

**シグナルを省略すると `SIGTERM`（15）が送られます。**
「kill＝殺す」という名前ですが、**実体は「シグナルを送る」**コマンドです。

**例文**

```bash
$ kill 929                            # SIGTERM（15）を送る。これが既定
$ kill -15 929                        # 同じ意味を番号で明示する
$ kill -TERM 929                      # 同じ意味を名前で明示する
$ kill -SIGTERM 929                   # SIG を付けた名前でも指定できる
$ kill -9 929                         # SIGKILL。強制終了
$ kill -HUP 929                       # 設定の再読み込みを依頼する
```

### kill のよく使うオプション

| 書き方 | 意味 |
|:--|:--|
| **`kill PID`** | **`SIGTERM`（15）を送る**（シグナル省略時の既定） |
| **`kill -番号 PID`** | 番号でシグナルを指定する（例 `-9`） |
| **`kill -名前 PID`** | 名前でシグナルを指定する（例 `-KILL` / `-SIGKILL`） |
| **`kill -l`** | **シグナルの一覧を表示する**（プロセスには何も送らない） |
| `kill -s シグナル PID` | `-s` で明示的にシグナルを指定する（POSIX の書き方） |
| **`kill %ジョブ番号`** | **PID ではなくジョブ番号で指定する**（[ジョブ制御](./ジョブ制御_fgとbgとjobs.md)） |
| `kill -0 PID` | **シグナルを送らずに、そのPIDが存在するかだけ確かめる** |

**補足 … いきなり `-9` を使わないでください**

`SIGKILL`（9）はプロセスに**後片付けの機会を与えません**。
そのため次の副作用が起こりえます。

| 起きること | 例 |
|:--|:--|
| 一時ファイルやロックファイルが残る | 次回起動時に「すでに起動しています」と言われる |
| 書き込み途中のデータが失われる | DB のトランザクションが中途半端に終わる |
| 子プロセスが孤児になる | 親が消え、子が systemd に引き取られて残り続ける |

**手順は `-15`（既定）→ 数秒待つ → それでも残っていたら `-9`** です。

## killall

**意味** … **プロセス名を指定して、一致するすべてのプロセスにシグナルを送るコマンド**です。

```text
killall [-シグナル] プロセス名
```

**既定では完全一致**で、`kill` と違って PID を調べる手間がありません。

**例文**

```bash
$ killall sleep                       # 名前が sleep のプロセスすべてに SIGTERM を送る
$ killall -9 sleep                    # 強制終了させる
$ killall -u test firefox             # test ユーザの firefox だけを止める
$ killall -i sleep                    # 1件ずつ確認しながら止める
```

| オプション | 意味 |
|:--|:--|
| **`-i`** / `--interactive` | **止める前に 1 件ずつ確認する** |
| **`-u ユーザ`** | 指定したユーザのプロセスだけを対象にする |
| **`-r`** | プロセス名を**正規表現**として扱う |
| **`-e`** | **プロセス名の完全一致を要求する**（15 文字を超える名前のとき） |
| `-w` | すべて終了するまで待つ |
| `-v` | 送ったかどうかを表示する |
| `-s シグナル` | 送るシグナルを指定する |

**補足 … 名前が同じだけの別物まで止まります**

`killall` は名前で対象を決めるため、**意図しないプロセスを巻き込む危険**があります。
特に `killall java` のような汎用的な名前は、他のアプリまで落とします。

**本番では `-i` を付けて 1 件ずつ確認するか、`pgrep -a` で対象を確かめてから実行してください。**

> **Solaris など一部の UNIX では `killall` が「全プロセスを終了させる」コマンドです。**
> Linux の `killall`（psmisc パッケージ）とは別物です。**他OSで安易に叩かないでください。**

## pkill

**意味** … **`pgrep` と同じ条件指定で、見つかったプロセスにシグナルを送るコマンド**です。

```text
pkill [-シグナル] [オプション] 検索パターン
```

**`pgrep` と `pkill` は対になっています。**
オプションはほぼ共通で、**探すのが `pgrep`、送るのが `pkill`** です。

**例文**

```bash
$ pgrep -a sleep                      # まず対象を目で確認する
929 sleep 300
930 sleep 300

$ pkill -e sleep                      # 確認した対象にシグナルを送る（-e で結果を表示）
sleep killed (pid 929)
sleep killed (pid 930)
```

| オプション | 意味 |
|:--|:--|
| **`-e`** | **どのプロセスに送ったかを表示する** |
| **`-u ユーザ`** / **`-U ユーザ`** | `pgrep` と同じ（実効ユーザ／実ユーザ） |
| **`-x`** | プロセス名と完全一致したものだけ |
| `-f` | コマンドライン全体に対してパターンを照合する |
| `-signal` | 送るシグナル（例 `-9`） |

**補足 … `pgrep` で確認してから `pkill` に置き換えるのが定石です**

同じオプションが使えるので、**コマンドの `pgrep` を `pkill` に書き換えるだけ**で実行に移せます。
**いきなり `pkill` を打たず、まず `pgrep -a` で対象を目視する**習慣にしてください。

## 三つの止め方の使い分け

| コマンド | 対象の指定 | 正規表現 | 向いている場面 |
|:--|:--|:-:|:--|
| **`kill`** | **PID** | — | **1 つに狙いを定めて止める**。いちばん安全 |
| **`killall`** | **プロセス名（完全一致）** | `-r` で可 | 同名プロセスを**まとめて**止める |
| **`pkill`** | **プロセス名（部分一致）＋条件** | **既定で可** | **ユーザや端末などの条件を付けて**まとめて止める |

```text
  狙い撃ちしたい  ──▶  pgrep で PID を調べる  ──▶  kill PID
  名前でまとめたい ──▶  killall プロセス名
  条件を付けたい   ──▶  pgrep -a で確認  ──▶  pkill -u ユーザ パターン
```

**`kill` は「PID しか受け付けない」のが弱点であり、同時に安全装置**でもあります。
PID を調べる過程で対象を目視することになるためです。

## 実務での手順

**「応答しないプロセスを止める」ときの順番**です。

```bash
$ pgrep -a nginx                      # ① 対象を特定する。引数まで見て別物でないか確かめる
$ kill 1234                           # ② まず SIGTERM。後片付けの機会を与える
$ sleep 5                             # ③ 数秒待つ
$ pgrep -a nginx                      # ④ 消えたか確認する
$ kill -9 1234                        # ⑤ まだ残っていたら、そのときだけ SIGKILL
```

**④ を飛ばさないでください。** `-15` で足りたのに `-9` を打つのが、
一時ファイルの残留やデータ破損のいちばん多い原因です。

**補足 … `D`（I/O待ち）状態のプロセスは `-9` でも止まりません**

`ps` の `STAT` が **`D`（割り込み不可のスリープ）** のプロセスは、
**カーネル内で I/O の完了を待っている**状態です。
シグナルはカーネルから復帰するまで配送されないため、`kill -9` を打っても消えません。

この場合に見るべきはプロセスではなく**ストレージ側**です
（[リソース監視 IOとネットワーク](./リソース監視_IOとネットワーク.md)）。

**補足 … systemd 管理下のサービスは `systemctl` を使ってください**

`kill` で直接止めると、**systemd が「異常終了」と判断して再起動をかける**ことがあります
（`Restart=always` の場合）。サービスとして動いているものは
`systemctl stop サービス名` を使います
（[systemctl サービスの操作と確認](../05_起動プロセスとカーネル/systemctl_サービスの操作と確認.md)）。
