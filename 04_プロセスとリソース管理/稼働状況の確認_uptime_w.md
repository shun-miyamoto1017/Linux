## 同じ4項目を出す3つのコマンド

**次の 4 つの情報は、`uptime` / `top` / `w` の 3 つで表示されます。**

```text
・現在時刻
・システムの稼働時間
・ログインユーザ数
・負荷平均（1分間、5分間、15分間）
```

| コマンド | どこに出るか |
|:--|:--|
| **`uptime`** | **出力そのもの**（1 行だけ） |
| **`top`** | **画面の 1 行目** |
| **`w`** | **出力の 1 行目** |

```text
$ uptime
 17:36:06 up 53 min,  2 users,  load average: 0.25, 0.26, 0.41

$ top
top - 23:33:02 up  8:40,  3 users,  load average: 0.00, 0.00, 0.00     ← 1行目が同じ形
Tasks: 143 total, ...

$ w
 11:33:37 up 19:02,  5 users,  load average: 0.37, 0.29, 0.27          ← 1行目が同じ形
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU WHAT
```

**この 4 項目は `ps` や `vmstat` には出ません。**

| コマンド | 4 項目が出るか | 補足 |
|:--|:-:|:--|
| **`uptime`** | **○** | これだけを見たいとき |
| **`top`** | **○** | 続けてプロセス一覧も見られる |
| **`w`** | **○** | 続けてログイン中のユーザ一覧も見られる |
| `ps` | ✕ | プロセスの一覧のみ |
| `vmstat` | ✕ | CPU・メモリ・I/O の統計のみ |
| `netstat` | ✕ | ネットワークの状態のみ |

**使い分けは「そのあと何を見たいか」で決まります。**

```text
負荷だけ知りたい          → uptime
重いプロセスも見たい      → top
誰が入っているか見たい    → w
```

## uptime

**`uptime` はシステムの稼働時間や負荷平均（ロードアベレージ）などを表示するコマンド**です。
**出力はたった 1 行**で、サーバの「今の混み具合」を最短で確認できます。

```text
uptime [オプション]
```

### uptime のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **（なし）** | **1 行のサマリを表示する**。ほとんどの場面はこれだけ |
| **`-p`** / `--pretty` | **稼働時間を読みやすい文章で表示**する（`up 2 weeks, 3 days, 1 hour`） |
| **`-s`** / `--since` | **システムが起動した日時**を `yyyy-mm-dd HH:MM:SS` で表示する |
| `-h` / `--help` | ヘルプを表示する |
| `-V` / `--version` | バージョンを表示する |

```bash
$ uptime                             # 稼働時間と負荷平均を1行で見る
$ uptime -p                          # 稼働時間だけを読みやすい形で見る
$ uptime -s                          # 「いつ起動したのか」を確認する
$ watch -n 5 uptime                  # 5秒ごとに更新して負荷の推移を眺める
```

### uptime の結果画面の見方

```bash
$ uptime                             # システムの稼働時間と負荷平均を表示する
 17:36:06 up 53 min,  2 users,  load average: 0.25, 0.26, 0.41
```

```text
 17:36:06 up 53 min,  2 users,  load average: 0.25, 0.26, 0.41
 └──┬───┘    └──┬──┘  └──┬──┘               └────────┬────────┘
  現在時刻    稼働時間  ログイン中          1分 / 5分 / 15分 の
                       のユーザ数           ロードアベレージ
```

| 項目 | 意味 | 見るポイント |
|:--|:--|:--|
| **現在時刻** | サーバの現在時刻 | **ログの時刻と突き合わせる基準**。ズレていたら NTP を疑う |
| **稼働時間（`up ...`）** | 最後に起動してからの経過時間 | **短いなら再起動が起きている**。障害調査の起点 |
| **`N users`** | **ログイン中のユーザ数**（同じ人の複数セッションも別に数える） | 想定より多いなら誰が入っているか `w` で確認する |
| **`load average`** | **1 分 / 5 分 / 15 分**の平均ロードアベレージ | **CPU コア数と比べて判断**する |

**`load average` の 3 つの数字は、左から 1 分・5 分・15 分の平均**です。
**値の意味と判断のしかた**は、このノートの
[ロードアベレージの読み方](#ロードアベレージの読み方) にまとめています。

## w

**`w` はログインしているユーザとそのプロセス情報を表示するコマンド**です。
**システムの稼働時間や負荷平均も表示します。**

```text
w [オプション] [ユーザ名]
```

**`w` の 1 行目は `uptime` の出力とまったく同じ**です。
そこに**「いま誰が、どこから入って、何をしているか」**の一覧が続きます。

```text
uptime … 1行目だけ
w      … 1行目 ＋ ログイン中のユーザ一覧
```

### w のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **（なし）** | **サマリ行＋全ログインユーザを表示**する |
| **`-h`** / `--no-header` | **見出し行を出さない**（スクリプトで加工するとき） |
| **`-s`** / `--short` | **短い形式**。`LOGIN@` / `JCPU` / `PCPU` を省く |
| **`-f`** / `--from` | **`FROM`（接続元）列の表示を切り替える** |
| **`-i`** / `--ip-addr` | **`FROM` をホスト名ではなく IP アドレスで表示**する |
| `-u` / `--no-current` | **`su` でユーザを切り替えている端末**について、切り替え後のユーザ名を無視して `WHAT` と CPU 時間を求める |
| `ユーザ名` | **指定したユーザの行だけ**に絞る |

```bash
$ w                                  # ログイン中のユーザをすべて表示する
$ w -i                               # 接続元をIPアドレスで表示する（名前解決を待たない）
$ w test1                            # test1 の行だけを表示する
$ w -h | wc -l                       # ログイン中のセッション数を数える
```

### w の結果画面の見方

```bash
$ w                                  # ログイン中のユーザと稼働状況を表示する
 11:33:37 up 19:02,  5 users,  load average: 0.37, 0.29, 0.27
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU WHAT
root     :0       -                Wed16   ?xdm?   1:59   0.11s /usr/bin/gnome-ses
root     pts/1    :0.0             Wed16  18:55m   0.00s  0.00s bash
test1    pts/2    192.168.1.150    11:32   57.00s  0.01s  0.01s -bash
root     pts/3    192.168.1.150    07:35    0.00s  0.03s  0.00s w
test2    pts/4    192.168.1.150    11:33   20.00s  0.00s  0.00s -bash
```

**画面は 2 つの部分に分かれます。**

| 部分 | 内容 |
|:--|:--|
| **1 行目** | **`uptime` とまったく同じサマリ**（現在時刻・稼働時間・ユーザ数・負荷平均） |
| **2 行目以降** | **ログイン中のセッションが 1 行ずつ** |

**各列の意味**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`USER`** | **ログイン名** | 同じユーザが複数行に出るのは、複数セッションを張っているから |
| **`TTY`** | **接続している端末の名前** | **`pts/N` はリモート、`ttyN` はコンソール**（後述） |
| **`FROM`** | **接続元のリモートホスト** | **`-` はローカル**。心当たりのない IP は要調査 |
| **`LOGIN@`** | **ログインした時刻** | 当日なら時刻、それ以前なら曜日で表示される |
| **`IDLE`** | **その端末が操作されていない時間** | **長いなら放置セッション**。`18:55m` は 18 時間 55 分 |
| **`JCPU`** | **その端末に紐づく全プロセスが使った CPU 時間** | 端末単位の合計 |
| **`PCPU`** | **`WHAT` に出ているプロセスが使った CPU 時間** | いま動かしているものだけ |
| **`WHAT`** | **そのユーザが実行中のコマンドライン** | **`w` 自身が写る**のは正常 |

**1行目でよくある読み間違い**

| 誤読 | 正しい読み方 |
|:--|:--|
| **`up 19:02` を「現在の時刻は19時02分」と読む** | **`19:02` は稼働時間**（19 時間 2 分）。**現在時刻は左端の `11:33:37`** |
| **`LOGIN@` を「ログインしている時間」と読む** | **`LOGIN@` はログインした時刻**。経過時間ではない |
| 負荷平均 0.37 を「高い」と読む | **CPU 数より小さければ低い**。CPU は最低でも 1 つある |

**「経過時間」と「時刻」を取り違えるのが、この 1 行の最大の落とし穴**です。

```text
現在時刻   … 11:33:37      ← 時刻（いま何時か）
稼働時間   … up 19:02      ← 経過時間（どれだけ動き続けているか）
LOGIN@     … 11:33         ← 時刻（いつ入ったか）
IDLE       … 20.00s        ← 経過時間（どれだけ放置しているか）
```

**`TTY` の読み方**

| 表記 | 意味 |
|:--|:--|
| **`pts/N`** | **疑似端末**。**SSH や端末エミュレータ経由**の接続 |
| **`ttyN`** | **物理コンソール**（`Ctrl+Alt+F2` などで切り替える画面） |
| **`:0`** | **X Window（GUI）のセッション** |

**`IDLE` の単位の読み方**

| 表記 | 意味 |
|:--|:--|
| `0.00s` | 秒 |
| `57.00s` | 57 秒 |
| `5:23` | **5 分 23 秒**（記号なしは「分:秒」） |
| **`18:55m`** | **18 時間 55 分**（末尾に `m` が付いたら「時:分」と読む） |
| `2days` | 2 日 |
| **`?xdm?`** | **GUI セッションでアイドル時間を測れない** |

**`JCPU` と `PCPU` の違い**

```text
JCPU … その端末（TTY）に紐づく すべての プロセスが使った CPU 時間の合計
PCPU … いま WHAT に表示されている 1 つの プロセスが使った CPU 時間
```

**`JCPU` はその端末に「いま」ぶら下がっているプロセスの CPU 時間の合計**です。
すでに終了したジョブは含まれないため、過去に重い処理を流していても、それが終わっていれば `JCPU` には残りません。
**`PCPU` が大きいなら、いま動かしているコマンドが CPU を食っています。**

**補足 … `w` / `who` / `last` の使い分け**

| コマンド | 分かること | 使う場面 |
|:--|:--|:--|
| **`w`** | **いま誰が、どこから、何をしているか**＋稼働時間・負荷平均 | **作業中に他人が入っていないか確認する** |
| `who` | いま誰が、どこから入っているか（実行中コマンドは出ない） | 一覧だけ欲しいとき |
| `who -b` | 最後にシステムが起動した時刻 | 再起動の確認 |
| `last` | **過去のログイン履歴**（`/var/log/wtmp`） | **いつ誰が入ったかを後から追う** |
| `lastlog` | 各ユーザの最終ログイン日時 | 使われていないアカウントの棚卸し |

```bash
$ w                                  # いまログイン中のユーザと実行中コマンドを見る
$ who                                # いまログイン中のユーザだけを見る
$ last -n 10                         # 直近10件のログイン履歴を見る
$ last reboot -n 5                   # 直近5回の再起動履歴を見る
```

**メンテナンス作業の前に `w` を打つ**のは実務の基本動作です。
**他の担当者が同じサーバで作業していないか**を確かめてから、再起動やサービス停止に進みます。

## ロードアベレージの読み方

**ロードアベレージは「実行可能状態＋割り込み不可状態のプロセスの平均数」**です（`man 1 uptime`）。

```text
実行可能状態（runnable）           … CPU を使っている、または CPU の空きを待っている
割り込み不可状態（uninterruptible）… ディスクなどの I/O 完了を待っている（ps の STAT が D）
```

**判断はコア数と比べて行います**

| 状況 | 判断 |
|:--|:--|
| **CPU コア数より小さい** | **余裕あり** |
| CPU コア数と同じくらい | ちょうど使い切っている |
| **CPU コア数より大きい** | **処理が追いついていない** |

```bash
$ nproc                              # CPU コア数を確認する
4
$ uptime                             # ロードアベレージと見比べる
 17:36:06 up 53 min,  2 users,  load average: 0.25, 0.26, 0.41
```

**ロードアベレージが高いのに CPU が暇なとき**

Linux のロードアベレージには **I/O 待ちも含まれます**。
そのため「ロードアベレージは 10 なのに、`top` の CPU 行の `id`（idle ＝ 何もしていない割合）が 90%」なら、
CPU は空いているということなので、**原因はディスク**です。

```bash
$ ps aux | awk '$8 ~ /^D/'           # I/O 待ち（STAT が D）のプロセスを抜き出す
$ iostat -x 1                        # ディスク側を確認する
```

**切り分けの続き**は
[リソース監視 システム全体 / 障害の切り分け手順](./リソース監視_システム全体.md#障害の切り分け手順) にまとめています。

**3 つの数字は時間の流れを表します**

| 並び | 期間 | 読み方 |
|:--|:--|:--|
| 1 つ目 | 直近 **1 分** | いまの瞬間の混み具合 |
| 2 つ目 | 直近 **5 分** | |
| 3 つ目 | 直近 **15 分** | ならした傾向 |

```text
1分 > 15分   … 負荷が上がってきている（悪化中）
1分 < 15分   … 山を越えて落ち着いてきている（回復中）
```

**「いま高い」だけでは判断できません。** 3 つを並べて**傾向**を読みます。

**補足 … 数値の出どころは `/proc/loadavg`**

```bash
$ cat /proc/loadavg                  # カーネルが持つ生の値を読む
0.25 0.26 0.41 1/243 5821
```

左の 3 つが `uptime` と同じ値、`1/243` は「**実行可能状態のスレッド数／存在するスレッドの総数**」、
最後の数字は最後に生成された PID です。**監視スクリプトではこちらを読むと解析が楽**です。

**補足 … ロードアベレージは CPU 数で割られていません**（`man 1 uptime`）。
**「4」という値は 1 コアなら過負荷、8 コアなら余裕**です。必ず `nproc` の結果と比べます。
