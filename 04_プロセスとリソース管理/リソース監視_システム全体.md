## どのコマンドで何が見えるか

| コマンド | CPU | メモリ | スワップ | ディスクI/O | ネットワーク | プロセス別 | 更新 |
|:--|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| **`vmstat`** | ○ | ○ | ○ | ○ | ✕ | ✕ | ○ |
| **`free`** | ✕ | **○** | **○** | ✕ | ✕ | ✕ | △（`-s`） |
| **`sar`** | ○ | ○ | ○ | ○ | ○ | ✕ | ○ |
| **`mpstat`** | **○** | ✕ | ✕ | ✕ | ✕ | ✕ | ○ |
| **`top`** | ○ | ○ | ○ | ✕ | ✕ | **○** | ○ |
| **`htop`** | ○ | ○ | ○ | △ | ✕ | **○** | ○ |
| **`ps`** | ○ | ○ | ✕ | ✕ | ✕ | **○** | ✕ |
| **`iostat`** | ○ | ✕ | ✕ | **○** | ✕ | ✕ | ○ |
| **`iotop`** | ✕ | ✕ | ✕ | **○** | ✕ | **○** | ○ |
| **`iftop`** | ✕ | ✕ | ✕ | ✕ | **○** | ✕ | ○ |
| **`iptraf`** | ✕ | ✕ | ✕ | ✕ | **○** | ✕ | ○ |
| **`uptime`** | △ | ✕ | ✕ | ✕ | ✕ | ✕ | ✕ |
| **`w`** | △ | ✕ | ✕ | ✕ | ✕ | △ | ✕ |

**`uptime` と `w` の「△」は、CPU 使用率ではなくロードアベレージ**（実行待ち＋I/O 待ちのプロセス数）
だけが分かる、という意味です。`w` の「プロセス別」も、**ログイン中のユーザが実行中のコマンドだけ**を指します。

**覚え方**

```text
vmstat … 全体を1画面で（万能。まずこれ）
free   … メモリ専用
sar    … 記録も残る、時系列の本命（別ノート）
mpstat … CPU 専門。コアごとに分けて見る
top    … プロセス別のリアルタイム
iostat … ディスク I/O
iotop  … ディスク I/O をプロセス別に
iftop  … ネットワーク帯域を相手先別に
uptime … 稼働時間とロードアベレージだけを1行で
w      … uptime の1行目＋いま誰が何をしているか
```

**`io` が付くのはディスク**、**`if` が付くのはネットワーク**（interface の if）と覚えると混同しません。

**この表のうち、ノートが分かれているもの**

| コマンド | 解説の場所 |
|:--|:--|
| `vmstat` / `free` / `top` / `htop` / `mpstat` / `pidstat` | **このノート** |
| **`sar` / `sadc` / `sa1` / `sadf`** | [sar 過去にさかのぼる監視](./sar_過去にさかのぼる監視.md) |
| `iostat` / `iotop` / `iftop` / `iptraf` | [リソース監視 IOとネットワーク](./リソース監視_IOとネットワーク.md) |
| `uptime` / `w` | [稼働状況の確認 uptime と w](./稼働状況の確認_uptime_w.md) |
| `ps` | [プロセスの確認 ps](./プロセスの確認_ps.md) |

## 測定対象から引く一覧

**「何を測りたいか」から引く表**です。コマンド名から引く上の表と対で使います。

| 測定対象 | 見たいもの | コマンド |
|:--|:--|:--|
| **CPU** | **システム全体の CPU 使用率** | **`top`**（`htop`）、`vmstat`、`iostat`、**`mpstat [-P 番号\|ALL]`**、**`sar -u [-P 番号\|ALL]`** |
| CPU | **プロセスごとの CPU 使用率** | **`top`**（`htop`）、**`ps u[ax]`** |
| CPU | **負荷平均（load average）** | **`top`**（`htop`）、`uptime`、`w` |
| **物理メモリ** | **システム全体のメモリ使用状況** | **`top`**（`htop`）、**`free`**、`vmstat`、**`sar -r`** |
| 物理メモリ | **プロセスごとのメモリ使用率** | **`top`**（`htop`）、**`ps u[ax]`** |
| **スワップ領域** | **スワップの使用状況** | **`top`**（`htop`）、`free`、`vmstat`、**`sar -S`**、**`swapon -s`** |
| スワップ領域 | **スワップイン・アウトの状況** | **`vmstat`**（`si` / `so` 列） |
| **ディスク I/O** | **読み書きの状況** | **`iostat`**、**`iotop`**、`vmstat`、**`sar -b`** |
| **ネットワーク I/O** | **通信の状況** | **`iptraf`**、**`iftop`**、**`netstat -i`** / **`-s`**、**`sar -n DEV\|EDEV`** |
| **プロセスの PID** | **プロセスの特定** | **`ps [uax]`**、**`top`**、**`lsof`** |

**太字のうち、`top` / `htop` / `iotop` / `iftop` / `iptraf` は「モニターツール」**です。

```text
モニターツール … 画面が更新され続ける。いまの状況を見張る
その他          … 実行した瞬間の値を出して終わる（引数で繰り返しにできるものもある）
```

**`top` は既定で CPU 使用率の高い順に並びます。** 「重いプロセスを探す」の第一手がこれです。

**1 つの目的に複数のコマンドがある理由**

```text
free    … メモリだけを、いま見る
sar -r  … メモリの推移を、過去にさかのぼって見る
top     … メモリもCPUも、プロセス別に、見張り続ける
```

**「いま／推移／過去」と「全体／プロセス別」の 2 軸**で選ぶと迷いません。

**計測対象として「不適切」なもの**

パフォーマンス計測では、**そのサーバの資源の使われ方に直結する値**を選びます。

| 計測対象 | 適切か | 理由 |
|:--|:-:|:--|
| CPU 使用率 | **○** | 資源の使われ方そのもの |
| 空きメモリ量 | **○** | 同上 |
| ディスク I/O | **○** | 同上 |
| ネットワーク I/O | **○** | 同上 |
| **ログインユーザ数** | **✕** | **ログインしていても操作していなければ負荷にならない** |
| **稼働中のサーバ数** | **✕** | **他サーバの台数は、このサーバの性能とは無関係** |

**パフォーマンスはサーバごとに計測します。**
「同じネットワークに何台動いているか」を数えても、**個々のサーバの状態は分かりません**。

## vmstat

**`vmstat` コマンドは、物理メモリやスワップ領域の詳細な情報や、
プロセスや CPU の統計情報などを表示します。**

```text
vmstat [オプション] [表示間隔(秒)] [回数]
```

**引数に表示間隔と回数を指定することで、これらの情報を継続的に監視できます。**

### vmstat のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **（数値2つ）** | **`vmstat 10 3` = 10秒間隔で3回表示**。回数を省くと `Ctrl+C` まで続く |
| **`-S M`** | **単位を MB にする**（既定は KB で読みにくい） |
| `-a` | `buff`/`cache` の代わりに `inact`/`active` を表示する |
| `-d` | ディスクごとの統計を表示する |
| `-s` | メモリ統計をサマリで縦に表示する |
| `-w` | 幅を広げて桁ずれを防ぐ |
| `-t` | 各行にタイムスタンプを付ける |

```bash
$ vmstat 1                           # 1秒ごとに永続表示（Ctrl+C で止める）
$ vmstat 1 5                         # 1秒ごとに5回だけ
$ vmstat -S M 1 5                    # 単位を MB にして見やすくする
$ vmstat -t 1 5                      # 時刻付きで表示する（ログに残すとき便利）
```

### vmstat の結果画面の見方

```bash
$ vmstat 10 3                        # 10秒間隔で3回表示する
procs -----------memory---------- ---swap-- -----io---- --system-- -----cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 1  0      0  31024  98692 216876    0    0     4     2  101   67  0  3 97  0  0
 1  0      0  31024  98700 216884    0    0     0     3 1011  134 48  3 49  0  0
 1  0      0  31024  98712 216884    0    0     0     4 1008  135 50  1 50  0  0
```

**出力は 6 つの欄（グループ）に分かれています。**

```text
procs   memory              swap      io          system      cpu
 │       │                   │         │           │           │
プロセス  メモリの使用状況    スワップ  ディスクI/O 割り込み等  CPU の内訳
```

**`procs` 欄 … プロセスの待ち行列**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`r`** | **実行中＋実行待ちのプロセス数**（run queue。CPU を使っている／使いたがっているものの合計） | **CPU コア数を超え続けたら CPU 不足** |
| **`b`** | **割り込み不可のスリープ状態にあるプロセス数** | **0 でない状態が続いたら I/O 待ちが発生している** |

**`b` は「I/O 待ちなどで割り込み不可のスリープ状態にあるプロセスの数」**です。
`ps` の `STAT` が `D` のプロセスがここに数えられます。

**`memory` 欄 … メモリの使用状況（単位 KB）**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`swpd`** | **使用中のスワップ領域のサイズ** | **増え続けるならメモリ不足** |
| **`free`** | **空いている物理メモリのサイズ** | 少なくても `buff`/`cache` があれば問題ないことが多い |
| **`buff`** | **バッファキャッシュのサイズ** | ディスクの**メタデータ**（inode など）用 |
| **`cache`** | **ページキャッシュのサイズ** | **ファイルの内容**用。**必要になれば解放される** |

**`buff` と `cache` の違い**

```text
バッファキャッシュ（buff）  … ブロックデバイスのメタデータを覚えておく領域
ページキャッシュ  （cache）… 読み書きしたファイルの中身を覚えておく領域
```

**どちらも「速くするために借りているだけ」**で、
**他のプロセスがメモリを必要としたら解放されます**。
そのため、**`free` が少なくても `buff` / `cache` が大きいなら余裕があります**。

**`swpd` は「使用中」であって「総量」ではありません。**
**`vmstat` ではスワップ領域の総量が表示されない**ため、
**空きスワップのサイズは `vmstat` からは分かりません**。総量は `free` や `swapon --show` で見ます。

**`free` は「空いている物理メモリ」**であって、スワップの値ではありません。

**`swap` 欄 … スワップの入出力（KB/秒）**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`si`** | **swap in**。スワップから物理メモリへ読み戻した量 | **0 でない状態が続いたら深刻** |
| **`so`** | **swap out**。物理メモリからスワップへ追い出した量 | 同上 |

**`si` / `so` が常に動いている状態を「スラッシング」**と呼び、
**応答が極端に悪化します**。`swpd` が多いだけなら許容できますが、`si`/`so` が動くのは危険信号です。

**`io` 欄 … ディスクの入出力（ブロック/秒）**

| 列 | 意味 |
|:--|:--|
| **`bi`** | **デバイスからの読み取りブロック数/秒**（blocks in） |
| **`bo`** | **デバイスへの書き込みブロック数/秒**（blocks out） |

**`bi` / `bo` は I/O 待ちの「プロセス数」ではありません。** 転送量です。
**I/O 待ちのプロセス数は `procs` 欄の `b`** で見ます。ここは混同しやすい点です。

**`system` 欄 … システムの動き（回/秒）**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`in`** | **1秒あたりの割り込み回数**（クロック割り込みを含む） | 極端に多いとハードウェアや NIC の問題 |
| **`cs`** | **1秒あたりのコンテキストスイッチ回数** | 極端に多いとプロセス数が多すぎる／ロック競合 |

**「割り込み」とは**

**ハードウェアやシステムイベントが発生したときに、実行中の処理をいったん中断して
別の処理を即座に実行するためのカーネルの仕組み**です。
キーボードの入力、NIC のパケット到着、タイマー（クロック割り込み）などが発生源になります。
カーネルがこれを制御することで、システム全体が素早く反応できます。

**`in` にはクロック割り込みも含まれます。** 何もしていないサーバでも 0 にはなりません。

**「コンテキストスイッチ」とは**

**複数のプロセスを代わるがわる処理するときに、CPU の状態（コンテキスト）を
いったん保存して、別のプロセスの状態を復元する**動作です。

```text
プロセスA を実行中
   ↓  A のレジスタ・プログラムカウンタなどを保存   ← ここが「保存」
プロセスB の状態を復元して実行                    ← ここが「復元」
   ↓
この一往復が 1 回のコンテキストスイッチ
```

**切り替えそのものにも CPU 時間がかかります。** `cs` が極端に多いと、
**本来の処理ではなく切り替えに CPU を使っている**状態になり、`sy`（カーネル側）が上がります。

**`cpu` 欄 … CPU 時間の内訳（%）。5 列の合計が 100 になります**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`us`** | **user**。ユーザプロセスが使った割合 | アプリの処理そのもの |
| **`sy`** | **system**。カーネルが使った割合 | 高いならシステムコールや I/O が多い |
| **`id`** | **idle**。**アイドル（何もしていない）時間の割合** | **低いほど忙しい** |
| **`wa`** | **iowait**。I/O 待ちの割合 | **高いならディスクがボトルネック** |
| **`st`** | **steal**。**ハイパーバイザに奪われた割合** | **クラウドで重要**。高いなら他の VM に食われている |

**上の実行例の読み方**

```text
1行目  us=0  sy=3  id=97   ← システム起動時からの平均。ほとんど何もしていなかった
2行目  us=48 sy=3  id=49   ← いまは CPU の約半分を使っている
3行目  us=50 sy=1  id=50   ← 同上
```

**`r` は 3 行とも `1`** なので、CPU を取り合っているプロセスは実質 1 つだけ（実行中のものを含む）と読めます。

### vmstat の1行目は捨てる

**最初の表示は起動時からの統計情報**であることに注意が必要です。

```text
1行目  … システム起動時からの「平均値」
2行目〜 … 指定した間隔ごとの「その区間の値」   ← 実際に見るべきはこちら
```

上の例で 1 行目の `id` が 97% なのは、
**サーバが起動してからずっと暇だった時間まで含めた平均**だからです。
2 行目以降では `id` が 49% まで落ちており、**いまは忙しい**と分かります。

**「実行時の CPU アイドル率は 97%」と読むのは誤りです。**
1 行目は現在の状態を表していません。

```bash
$ vmstat 1 5 | tail -n +4            # 見出し2行と1行目の統計を捨てて表示する
```

**この性質は `iostat` にもあります**（1 回目は起動時からの平均）。
一方 **`sar` / `mpstat` / `pidstat` は、間隔を指定した場合は 1 行目からその区間の値**です。
起動時からの平均になるのは、間隔を指定せずに実行したときだけです。

## free

**`free` コマンドはメモリやスワップ領域の使用状況を表示します。**

### free のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-h`** | **人が読みやすい単位で表示**（Gi / Mi）。**まずこれ** |
| `-m` / `-g` | MB 単位 / GB 単位で表示する |
| `-k` | KB 単位（既定） |
| **`-s 秒`** | **指定した秒数ごとに繰り返し表示**する |
| `-c 回数` | `-s` と併用して回数を指定する |
| `-t` | 合計（Total）の行を追加する |
| `-w` | `buffers` と `cache` を別の列に分ける |

```bash
$ free -h                            # 人が読める単位で表示する
$ free -h -s 5                       # 5秒ごとに繰り返し表示する
$ free -m -t                         # MB 単位で合計行つき
$ free -w -h                         # buffers と cache を分けて表示する
```

### free の結果画面の見方

```bash
$ free -h                            # メモリの使用状況を確認する
               total        used        free      shared  buff/cache   available
Mem:           7.8Gi       732Mi       6.9Gi        12Mi       475Mi       7.1Gi
Swap:             0B          0B          0B
```

**行の意味**

| 行 | 何を表すか |
|:--|:--|
| **`Mem:`** | **物理メモリ** |
| **`Swap:`** | **スワップ領域** |

**列の意味**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`total`** | **総量** | **`vmstat` には出ない**（`free` か `swapon --show` で見る） |
| **`used`** | **バッファ・ページキャッシュを含まない、実際に使われている量** | `total - free - buff/cache` |
| **`free`** | **完全に空いている量** | **少なくても慌てない**（後述） |
| `shared` | 共有メモリ（`tmpfs` など）が使っている量 | `/dev/shm` の使用量 |
| **`buff/cache`** | **バッファ・キャッシュ** | **必要になれば解放される「余裕」** |
| **`available`** | **バッファ・ページキャッシュを含めた、実質的に使用可能な量** | **本当に見るべきはこの列** |

**`free` が少ないのは異常ではありません**

Linux は**空いているメモリをキャッシュに使い切る**設計です。
「空きが少ない ＝ メモリ不足」ではありません。

```text
free       … いま完全に遊んでいるメモリ（少なくて当たり前）
available  … キャッシュを解放すれば使えるメモリ ← これが本当の空き
```

**`used` と `available` は「キャッシュを含むか」で対になっています**

| 列 | キャッシュの扱い | 何を表すか |
|:--|:--|:--|
| **`used`** | **含まない** | **実際に使われている物理メモリ** |
| **`available`** | **含む** | **これから使える物理メモリ** |

```text
total = used + free + buff/cache      … 内訳としての足し算
available ≒ free + 解放できる buff/cache … 実際に使える量
```

**`Swap` 行の `used`** も同じ読み方で、**実際に使用しているスワップ領域の量**です。

**単位は KiB（1024 バイト）です。** `total` が `514840` なら **約 502MiB**（514840 ÷ 1024）です。
ざっくり「50 万 KiB ＝ 500MB 弱」と読めば十分です。

**稼働時間が長いほど、空き物理メモリは減っていきます**

Linux は**空いている物理メモリをバッファキャッシュ・ページキャッシュとして積極的に使う**ため、
**大容量のメモリを積んでいても、動かし続けるほど `free` は小さくなります**。

```text
起動直後        … free が大きい（まだキャッシュしていない）
        ↓ ファイルを読み書きするたびにキャッシュが増える
しばらく経過    … free は小さい。ただし buff/cache が大きい   ← 正常
```

**これは異常ではありません。** 他のプロセスが必要とすれば、キャッシュは解放されます。
**`free` の少なさだけでメモリ不足と判断してはいけない**理由がこれです。

**判断の目安**

| 状況 | 判断 |
|:--|:--|
| `free` が少ないが `available` が十分 | **正常**。キャッシュが効いている良い状態 |
| **`available` が総量の 10% を切る** | **メモリ不足**。増設かチューニングを検討 |
| `Swap` の `used` が増え続ける | メモリ不足がすでに始まっている |

**`available` は単なる `free + buff/cache` ではありません。**
「解放できないキャッシュ」を除いた、より現実的な値をカーネルが計算しています。

**単位を付けないと KB になります**

```bash
$ free                               # 単位なし = KB
               total        used        free      shared  buff/cache   available
Mem:         8216192      750216     7226692       13300      486752     7465976
Swap:              0           0           0
```

スワップ領域そのものについては [06_ストレージとファイルシステム / スワップ領域](../06_ストレージとファイルシステム/スワップ領域.md) を参照してください。

## mpstat

**`mpstat` はマルチプロセッサシステムの CPU 使用状況を表示するコマンド**です。
**CPU（コア）ごとに分けて見られる**のが最大の特長です。

```text
mpstat [オプション] [表示間隔(秒)] [回数]
```

**`sysstat` パッケージに含まれます**（`sar` / `iostat` と同じ）。

```bash
$ sudo dnf install -y sysstat        # RHEL系でインストールする
$ sudo apt install -y sysstat        # Debian系でインストールする
```

### mpstat のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-P ALL`** | **すべての CPU について個別に表示する** |
| **`-P 番号`** | **指定した番号の CPU だけ**を表示する（`-P 0` など） |
| **`-u`** | **CPU 使用率を表示する**（既定） |
| **`-I ALL`** | **割り込みの統計**を表示する |
| `-A` | **すべての統計**を表示する（`-n -u -I ALL` 相当） |
| `-N ノード` | NUMA ノード単位で表示する |
| `-T` | トポロジ（CORE / SOCK / NODE）を併せて表示する |
| `-o JSON` | JSON 形式で出力する |
| **（数値2つ）** | **`mpstat 2 5` = 2秒間隔で5回表示** |

```bash
$ mpstat                             # 全CPUの平均を1回だけ表示する
$ mpstat -P ALL                      # CPUごとの使用率を表示する
$ mpstat -P ALL 2 5                  # CPUごとの使用率を2秒間隔で5回表示する
$ mpstat -P 0 1                      # CPU 0 だけを1秒ごとに表示し続ける
$ mpstat -I ALL 1 1                  # 割り込みの統計を表示する
```

**`-P` は「Processor」の P** です。`ALL` を指定すると全 CPU を並べます。
**CPU が 1 つのマシンでも使えます。**

### mpstat の結果画面の見方

```bash
$ mpstat -P ALL                      # CPUごとのCPU使用率を表示する
Linux 5.14.0-391.el9.x86_64 (localhost.localdomain)  12/22/23  _x86_64_  (2 CPU)

23:51:36  CPU  %usr %nice  %sys %iowait  %irq %soft %steal %guest %gnice  %idle
23:51:36  all  0.05  0.01  0.09    0.02  0.10  0.03   0.00   0.00   0.00  99.71
23:51:36    0  0.05  0.00  0.10    0.02  0.10  0.03   0.00   0.00   0.00  99.70
23:51:36    1  0.04  0.01  0.08    0.02  0.10  0.03   0.00   0.00   0.00  99.72
```

**ヘッダ行は `sar` や `iostat` と同じ形式**です。`(2 CPU)` が分母になります。

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`CPU`** | **対象の CPU**。**`all` は全 CPU の平均**、数値は CPU 番号 | **`all` だけ見ると偏りに気づけない** |
| **`%usr`** | **ユーザプロセスの割合** | アプリ自身の処理 |
| `%nice` | **`nice` 値を正にした（優先度を下げた）プロセス**の割合。優先度を上げたプロセスは `%usr` に入る | 通常はほぼ 0 |
| **`%sys`** | **システムプロセス（カーネル）の割合** | 高いならシステムコールや I/O が多い |
| **`%iowait`** | **I/O 待ち時間の割合** | **高いならディスクがボトルネック** |
| **`%irq`** | **ハードウェア割り込み処理の割合** | 高いなら NIC やデバイスの問題 |
| **`%soft`** | **ソフトウェア割り込み処理の割合** | **高いなら大量のパケット処理**を疑う |
| **`%steal`** | **仮想 CPU が強制的に待機させられた時間の割合** | **クラウドで最重要** |
| `%guest` | 仮想 CPU で実行されている OS に割り当てられた時間の割合 | ホスト側で見る値 |
| `%gnice` | 仮想 CPU で `nice` 値が変更されたプロセスが消費した割合 | 同上 |
| **`%idle`** | **アイドル時間の割合** | **低いほど忙しい** |

**`mpstat` が効くのは「偏り」を見つけるとき**

```text
all の %idle が 50%
    ↓ しかし
CPU 0 は %idle 0%    ← 1コアだけ振り切っている
CPU 1 は %idle 99%
```

**シングルスレッドのアプリや、割り込みが 1 コアに集中している場合**に起こります。
**全体平均だけを見ていると気づけません。**

```bash
$ mpstat -P ALL 1 5                  # 1秒ごとに5回、CPUごとの偏りを確認する
```

**`%irq` / `%soft` が特定のコアに偏る**場合は、**割り込みの割り当て**を確認します。

```bash
$ cat /proc/interrupts | head -5     # 割り込みがどのCPUで処理されているか確認する
```

### mpstat と sar -P ALL の違い

**どちらも `sysstat` に含まれ、`-P ALL` の意味も同じ**ですが、**出る列が違います**。

| | **`mpstat -P ALL`** | **`sar -P ALL`** |
|:--|:--|:--|
| **`%irq` / `%soft`** | **個別に表示される** | **既定では表示されない** |
| `%guest` / `%gnice` | 表示される | 表示されない |
| **過去にさかのぼる** | **できない** | **できる**（`-f`） |
| 用途 | **いまの CPU の偏りを詳しく見る** | **推移を追う・過去を調べる** |

```bash
$ mpstat -P ALL 1 3                  # いまの割り込みまで含めて詳しく見る
$ sar -u -P ALL 1 3                  # 同じ形式だが、割り込みの列は出ない
```

**「割り込みまで見たいなら `mpstat`」「過去を見たいなら `sar`」**と覚えます。

**`mpstat` は引数なしで実行したときだけ起動時からの平均**を表示します。
`mpstat 1 5` のように間隔を指定した場合は、1 行目からその区間の値です
（1 行目を捨てる必要があるのは `vmstat` と `iostat` だけ）。

## 障害の切り分け手順

**「サーバが重い」と言われたときの流れ**

```text
① uptime / w / top  … ロードアベレージで全体の混み具合を見る（w なら作業者も分かる）
        ↓
② vmstat 1          … CPU / メモリ / スワップ / I/O のどれが原因かを切り分ける
        ↓
   ┌────────────┬─────────────┬──────────────┬─────────────┐
   ▼            ▼             ▼              ▼             ▼
 CPU 不足     メモリ不足    ディスクI/O    ネットワーク   ホスト側
 us/sy 高い   si/so 動く    wa 高い        —              st 高い
   │            │             │              │             │
   ▼            ▼             ▼              ▼             ▼
 top で        free -h /     iostat -x →   iftop /       クラウド側の
 犯人特定      ps --sort     iotop で       iptraf        問題を疑う
              =-%mem        犯人特定
```

**判断の目安**

| 症状 | 見る値 | 原因の候補 |
|:--|:--|:--|
| **`us` が高い** | `top` の `%CPU` | アプリの処理が重い |
| **`sy` が高い** | `vmstat` の `cs`（コンテキストスイッチ） | プロセス数が多すぎる／ロック競合 |
| **`wa` が高い** | `iostat -x` の `await` `%util` | ディスクが遅い／I/O が多すぎる |
| **`si`/`so` が動く** | `free -h` の `available` | メモリ不足（スラッシング） |
| **`st` が高い** | — | **ハイパーバイザ側**。インスタンスタイプを見直す |
| **`b` が多い** | `iotop` | I/O 待ちのプロセスがいる |
| ロードアベレージだけ高い | `ps aux \| awk '$8 ~ /^D/'` | I/O 待ちのプロセスが溜まっている |

**終わってしまった障害を調べるとき**

`top` や `vmstat` は「いま」しか見られません。
**すでに収まってしまった障害**は、記録から追う以外に方法がありません。

```bash
$ sar -u -f /var/log/sa/sa07 -s 10:30:00 -e 11:30:00   # 7日の10:30〜11:30のCPUを見る
```

手順は [sar 過去にさかのぼる監視](./sar_過去にさかのぼる監視.md) にまとめています。

**ロードアベレージが高いのに CPU が暇なとき**

Linux のロードアベレージは**「実行待ち」だけでなく「I/O 待ち（`D` 状態）」も含みます**。
そのため「ロードは 10 なのに `id` が 90%」なら、**ディスクが原因**です。
