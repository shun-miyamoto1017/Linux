## iostat

**`iostat` は CPU とディスク I/O の統計を表示するコマンド**です。
`sysstat` パッケージに含まれます。

**よく使うオプション**

| オプション | 意味 |
|:--|:--|
| **`-x`** | **拡張統計**を表示する（`%util` `await` などが増える）。**実務ではほぼ必須** |
| **`-d`** | ディスクの統計だけ表示する |
| `-c` | CPU の統計だけ表示する |
| **`-h`** | 人が読みやすい形式にする |
| `-m` / `-k` | MB 単位 / KB 単位で表示する |
| `-p デバイス` | パーティション単位で表示する |
| `-t` | タイムスタンプを付ける |

```bash
$ iostat -x 1                        # 拡張統計を1秒ごとに表示する
$ iostat -xh 1 5                     # 読みやすい形式で5回だけ
$ iostat -d -p vda 1                 # vda のパーティションごとに見る
```

**結果画面の見方**

```bash
$ iostat                             # 基本の表示
Linux 6.18.44-fc-v24 (vm)   09/03/26  _x86_64_  (2 CPU)

avg-cpu:  %user   %nice %system %iowait  %steal   %idle
           3.89    0.00    1.75    0.37    0.00   93.98

Device             tps    kB_read/s    kB_wrtn/s    kB_read    kB_wrtn
vda              39.17      2455.24       192.98     928301      72964
```

**`avg-cpu` 欄** … `sar -u` と同じ 6 項目です。

**`Device` 欄（基本表示）**

| 列 | 意味 |
|:--|:--|
| **`tps`** | **1 秒あたりの転送回数**（transfers per second） |
| `kB_read/s` | 1 秒あたりの読み取り量（KB） |
| `kB_wrtn/s` | 1 秒あたりの書き込み量（KB） |
| `kB_read` | 起動からの累計読み取り量 |
| `kB_wrtn` | 起動からの累計書き込み量 |

**`-x` で増える重要な列**

| 列 | 意味 | 見るポイント |
|:--|:--|:--|
| **`r/s` / `w/s`** | 1 秒あたりの読み／書き回数 | **IOPS**。EBS の上限と比べる |
| **`rkB/s` / `wkB/s`** | 1 秒あたりの読み／書き量 | **スループット**。EBS の上限と比べる |
| **`r_await` / `w_await`** | **読み／書きの平均応答時間（ミリ秒）** | **10ms を超え続けたら遅い** |
| `aqu-sz` | 平均キュー長 | 大きいと待ち行列ができている |
| **`%util`** | **デバイスが busy だった時間の割合** | **100% に張り付いたら飽和** |

**`%util` の注意** … SSD や RAID では**100% でも余裕がある**ことがあります。
複数の要求を並列処理できるためです。**`await` と併せて判断**します。

**この 1 行目も起動時からの平均**です。`vmstat` と同じく 2 行目以降を見ます。

**引数なしで 1 回だけ実行したときは、すべて「起動してからの値」**になります。

| 列 | 引数なしで 1 回実行したときの意味 |
|:--|:--|
| **`kB_read/s` / `kB_wrtn/s`** | **起動してからの平均転送レート**（「現在の速度」ではない） |
| **`kB_read` / `kB_wrtn`** | **起動してからの累計転送量** |
| **`tps`** | **起動してからの平均転送回数** |

```text
$ iostat            … 起動してからの平均。「いま」は分からない
$ iostat 1 5        … 2行目以降が「その1秒間の値」    ← いまを見たいならこちら
```

上の例の `kB_wrtn/s` が `192.98` でも、**「いま毎秒 193KB 書いている」と読むのは誤り**です。
正しくは「**起動してから平均して毎秒 192.98KB 書き込んできた**」になります。

**単位はシステムによって変わります。** `kB_xxx` が `MB_xxx` や `Blk_xxx`（ブロック数）と
表示されることがあるため、**見出しの単位を必ず確認**します。

## iotop

**`iotop` はディスク I/O の状況を表示するコマンド**です。
**`top` に似た出力で、各プロセスごとの I/O が表示されます。**

**`iostat` との決定的な違い**

```text
iostat … 「どのディスクが」忙しいか
iotop  … 「どのプロセスが」ディスクを使っているか   ← 犯人が分かる
```

```bash
$ sudo dnf install -y iotop          # RHEL 系でインストールする
$ sudo iotop                         # 起動する（root 権限が必要）
$ sudo iotop -o                      # I/O が発生しているプロセスだけ表示する
$ sudo iotop -b -n 3                 # バッチモードで3回取得する（ログ向き）
```

**よく使うオプション**

| オプション | 意味 |
|:--|:--|
| **`-o`** | **実際に I/O しているプロセスだけ**表示する（ほとんどの場合これを付ける） |
| **`-b`** | バッチモード（ログに残す） |
| `-n 回数` | 回数を指定する |
| `-P` | スレッドではなくプロセス単位で表示する |
| `-a` | 起動してからの累積値を表示する |
| `-d 秒` | 更新間隔を変える |

**結果画面の見方**

```text
Total DISK READ :       0.00 B/s | Total DISK WRITE :       0.00 B/s
Actual DISK READ:       0.00 B/s | Actual DISK WRITE:     854.45 M/s
    TID  PRIO  USER     DISK READ  DISK WRITE   COMMAND
      1  be/4  root       0.00 B/s    0.00 B/s  systemd
      2  be/4  root       0.00 B/s    0.00 B/s  [kthreadd]
```

| 項目 | 意味 |
|:--|:--|
| **`Total DISK READ/WRITE`** | **プロセスが要求した**読み書きの合計 |
| **`Actual DISK READ/WRITE`** | **実際にディスクへ到達した**読み書きの合計 |
| `TID` | スレッド ID（`-P` を付けると PID になる） |
| **`PRIO`** | **I/O 優先度**。`be/4` は best-effort のクラス 4（標準） |
| `USER` | 実行ユーザ |
| **`DISK READ` / `DISK WRITE`** | **そのプロセスの読み／書き速度** |
| `COMMAND` | コマンド名 |

**`Total` と `Actual` がずれる理由**

書き込みは一度キャッシュに溜まり、あとでまとめてディスクへ書かれます。
そのため **`Total WRITE` が 0 でも `Actual WRITE` が大きい**（溜まっていた分が書き出されている）
という状態が普通に起こります。

**`PRIO` の見方**

| 表記 | クラス |
|:--|:--|
| `rt/N` | リアルタイム（最優先） |
| **`be/N`** | **best-effort（標準）**。N は 0〜7 で小さいほど優先 |
| `idle` | 他に I/O がないときだけ実行 |

`ionice` コマンドで変更できます。バックアップ処理を `idle` にして
本番の I/O を邪魔しないようにする、といった使い方をします。

## iftop

**`iftop` はネットワーク帯域の使用状況をリアルタイムに表示するコマンド**です。
**どの相手と、どれだけ通信しているか**が接続ごとに分かります。

```bash
$ sudo dnf install -y iftop          # RHEL 系（EPEL が必要な場合がある）
$ sudo iftop                         # 既定のインタフェースで起動する
$ sudo iftop -i eth0                 # インタフェースを指定する
$ sudo iftop -n                      # 名前解決せず IP のまま表示する（速い）
```

**よく使うオプション**

| オプション | 意味 |
|:--|:--|
| **`-i インタフェース`** | **対象のインタフェースを指定**する |
| **`-n`** | **ホスト名を解決しない**（IP のまま表示。DNS 待ちが無くなり速い） |
| `-N` | ポート番号をサービス名に変換しない |
| **`-P`** | **ポート番号も表示**する |
| `-B` | 単位をバイトにする（既定はビット） |
| `-f フィルタ` | tcpdump 形式のフィルタで絞る |
| `-t` | テキストモード（画面制御なし。ログ向き） |

**結果画面の見方**

```text
            12.5Kb      25.0Kb      37.5Kb      50.0Kb      62.5Kb
            └───────────┴───────────┴───────────┴───────────┴
192.168.11.200      => buffalo.setup          0b      0b     58b
                    <=                        0b      0b     63b
192.168.11.255      => 192.168.11.13          0b      0b      0b
                    <=                        0b      0b     47b
────────────────────────────────────────────────────────────────
TX:      cum:  289B   peak: 1.12Kb   rates:  0b   0b   58b
RX:            550B         1.23Kb           0b   0b  110b
TOTAL:         839B         2.36Kb           0b   0b  168b
```

**画面は 3 つの部分に分かれます。**

| 部分 | 内容 |
|:--|:--|
| **上部の目盛り** | 帯域のスケール（このバーの長さが通信量を表す） |
| **中央の一覧** | **接続ごとの送受信量** |
| **下部の集計** | TX（送信）/ RX（受信）/ TOTAL の合計 |

**中央の一覧の読み方**

```text
192.168.11.200      => buffalo.setup       0b   0b   58b
     │               │        │             └────┬────┘
  自ホスト側      向き     相手先        直近 2秒 / 10秒 / 40秒 の平均
                 => 送信
                 <= 受信
```

**1 つの接続が 2 行で 1 組**になっています。上が送信、下が受信です。

**右側の 3 つの数字は「直近 2 秒 / 10 秒 / 40 秒の平均転送レート」**です。
瞬間的なスパイクと継続的な通信を見分けられます。

**下部の集計**

| 行 | 意味 |
|:--|:--|
| **`TX`** | **送信**（transmit） |
| **`RX`** | **受信**（receive） |
| `TOTAL` | 合計 |
| `cum` | 起動してからの累計 |
| `peak` | 観測されたピーク値 |
| `rates` | 2 秒 / 10 秒 / 40 秒の平均 |

**転送レートの単位はビット（b）です。** バイトではありません。
`58b` は 58 ビット/秒であり、バイトで見たいなら `-B` を付けます。
なお `cum`（累計）だけは `289B` のようにバイト表記になります。

## iptraf

**`iptraf` はネットワークのトラフィックをモニターした情報を表示します。**
`iftop` より詳細で、**TCP コネクションの一覧やフラグ**まで見られます。

```bash
$ sudo dnf install -y iptraf-ng      # 現在は iptraf-ng が後継
$ sudo iptraf-ng                     # メニュー画面が起動する
```

**結果画面の見方**

```text
 TCP Connections (Source Host:Port)         Packets     Bytes   Flag  Iface
 127.0.0.1:16443                    >          178      50162   -PA-   lo
 127.0.0.1:37878                    >          166      22742   --A-   lo
──────────────────────────────────────────────────────────────────────────
 UDP (138 bytes) from 127.0.0.53:53 to 127.0.0.1:43210 on lo
──────────────────────────────────────────────────────────────────────────
 Packets captured:  2615    Drops: 0   TCP flow rate: 25.73 kbps
```

**画面は上下 2 段に分かれます。**

| 部分 | 内容 |
|:--|:--|
| **上段** | **TCP コネクションの一覧**（接続ごとに 1 行） |
| **下段** | **TCP 以外**（UDP / ICMP など）のパケットが流れる |
| **最下行** | 捕捉パケット数、ドロップ数、TCP のフロー速度 |

**上段の列**

| 列 | 意味 |
|:--|:--|
| `Source Host:Port` | 送信元の IP アドレスとポート |
| `Packets` | パケット数 |
| `Bytes` | バイト数 |
| **`Flag`** | **TCP フラグ**（後述） |
| `Iface` | インタフェース名 |

**`Flag` の読み方**

4 文字が **`S` `P` `A` `R`** の位置に対応します。

| 位置 | 記号 | 意味 |
|:--|:--|:--|
| 1 | `S` | SYN。接続の開始 |
| 2 | `P` | PSH。すぐに渡せという指示 |
| 3 | `A` | ACK。確認応答 |
| 4 | `R` | RST。強制切断 |

```text
-PA-  … PSH + ACK        → データをやり取り中
--A-  … ACK のみ         → 応答だけ
----  … フラグなし       → アイドル
S---  … SYN              → 接続を開こうとしている
---R  … RST              → 接続が強制的に切られた
```

接続を閉じるときは `F`（FIN）が表示されることもあります。
**正常な切断は `F`、異常な切断は `R`** と覚えると読み分けられます。
（フラグの並び順は iptraf-ng のバージョンによって異なる可能性があるため、実機で確認してください。）

**`R`（RST）が多いなら、接続がリセットされている**＝
ファイアウォールで弾かれている、アプリが接続を切っている、といった疑いを持ちます。

**キー操作**

| キー | 動作 |
|:--|:--|
| `Up`/`Dn`/`PgUp`/`PgDn` | スクロール |
| `M` | TCP の詳細情報を表示 |
| `W` | アクティブウィンドウを切り替え |
| `S` | TCP をソート |
| **`X`** | **終了** |

**`iftop` との使い分け**

| | **`iftop`** | **`iptraf`** |
|:--|:--|:--|
| 見えるもの | **帯域（どれだけ流れているか）** | **接続（どんな通信が起きているか）** |
| 得意な調査 | 「回線が飽和しているか」 | 「接続が切られていないか」 |

## nfsiostat と cifsiostat

**どちらも `sysstat` に含まれ、ネットワークを介したファイル共有の入出力を表示するコマンド**です。

```text
iostat                  … ローカルディスク（/dev/sda など）
nfsiostat / cifsiostat  … ネットワーク越しのファイル共有   ← iostat には出ない
```

**`iostat` は NFS / CIFS マウントの遅さを教えてくれません。**
「ファイルサーバが遅い」ときに `iostat` を見ても、ローカルディスクの数字しか出ないためです。

### NFS と CIFS

| | **NFS**（Network File System） | **CIFS**（Common Internet File System） |
|:--|:--|:--|
| 出自 | **UNIX 系 OS のファイル共有** | **SMB を拡張した Microsoft のプロトコル** |
| 主な相手 | Linux / UNIX サーバ | **Windows のファイル共有** |
| 使い方 | **サーバが公開（エクスポート）したディレクトリを、クライアントがマウントする** | 同様にマウントして使う |
| AWS の対応サービス | **Amazon EFS** | **Amazon FSx for Windows File Server** |

**どちらも「マウントしてローカルのように使う」**点は同じです。

```bash
$ mount | grep nfs                   # NFSでマウントされている場所を確認する
192.168.56.113:/tmp on /mnt/nfs type nfs4 (rw,relatime,vers=4.2,...)

$ mount | grep cifs                  # CIFSでマウントされている場所を確認する
//192.168.56.12/users on /mnt/cifs type cifs (rw,relatime,...)
```

### nfsiostat の結果画面の見方

```bash
$ nfsiostat                          # NFSマウント先ごとの入出力状況を表示する
192.168.56.113:/tmp mounted on /mnt/nfs:

           ops/s    rpc bklog
           0.667        0.000

read:      ops/s    kB/s   kB/op   retrans   avg RTT (ms)  avg exe (ms)  avg queue (ms)  errors
           0.000   0.000   0.000   0 (0.0%)         0.000         0.000           0.000  0 (0.0%)
write:     ops/s    kB/s   kB/op   retrans   avg RTT (ms)  avg exe (ms)  avg queue (ms)  errors
           0.000   0.000   0.000   0 (0.0%)         0.000         0.000           0.000  0 (0.0%)
```

**マウントポイントごとに、`read` と `write` に分けて表示されます。**

| 項目 | 意味 | 見るポイント |
|:--|:--|:--|
| **`ops/s`** | **1秒あたりの操作回数** | 上段は全体、下段は read / write ごと |
| **`rpc bklog`** | **RPC のバックログ（待ち行列）の長さ** | **0 でない状態が続くなら、要求が捌けていない** |
| **`kB/s`** | **1秒あたりの転送量** | 帯域を使っている量 |
| **`kB/op`** | **1 操作あたりの転送量** | **小さいと細かいアクセスが多い** |
| **`retrans`** | **再送の回数と割合** | **0 以外ならネットワークかサーバ側に問題** |
| **`avg RTT (ms)`** | **往復にかかった平均時間** | **サーバまでの応答の速さ** |
| **`avg exe (ms)`** | **要求を出してから完了するまでの平均時間** | **RTT より大幅に大きいなら、待ち時間が発生している** |
| `avg queue (ms)` | キューで待った平均時間 | 版によっては表示されない |
| **`errors`** | **エラーの回数と割合** | 0 以外なら要調査 |

**`avg RTT` と `avg exe` の差が、待ち時間**です。

```text
avg RTT  … 通信そのものにかかった時間
avg exe  … 要求してから終わるまでの時間（待ち時間を含む）

avg exe >> avg RTT  → 回線ではなく、クライアント側の詰まりを疑う
```

**`retrans` が出ているときは、まずネットワーク**を疑います。

### cifsiostat の結果画面の見方

```bash
$ cifsiostat                         # CIFSマウント先ごとの入出力状況を表示する
Linux 5.14.0-391.el9.x86_64 (localhost)  12/25/23  _x86_64_  (2 CPU)

Filesystem            rB/s    wB/s   rops/s   wops/s    fo/s    fc/s    fd/s
\\192.168.56.12\users  3843.99    0.00     0.00     0.00    0.04    0.04    0.00
```

| 列 | 意味 |
|:--|:--|
| **`Filesystem`** | **マウントしている共有の名前** |
| **`rB/s`** | **1秒あたりの読み取りバイト数** |
| **`wB/s`** | **1秒あたりの書き込みバイト数** |
| **`rops/s`** | **1秒あたりの読み取り操作回数** |
| **`wops/s`** | **1秒あたりの書き込み操作回数** |
| **`fo/s`** | **1秒あたりのファイルオープン回数** |
| **`fc/s`** | **1秒あたりのファイルクローズ回数** |
| `fd/s` | 1秒あたりのファイル削除回数 |

**`fo/s` / `fc/s` が高いのに `rB/s` が小さい**なら、
**小さなファイルを大量に開閉している**状態です。CIFS では特に遅くなります。

**どちらも表示間隔と回数を指定できます。**

```bash
$ nfsiostat 2 5                      # 2秒ごとに5回、NFSの入出力を表示する
$ cifsiostat 2 5                     # 2秒ごとに5回、CIFSの入出力を表示する
```

**1 行目は起動時（マウント時）からの平均**です。`iostat` と同じ性質があります。
