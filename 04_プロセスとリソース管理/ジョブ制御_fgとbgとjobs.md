## ジョブとは何か

**ジョブとは、コマンドやプログラムをグループ化して管理するための単位**です。

**ここがプロセスとの違いです。**
たとえばパイプでつないだ `ps ax | grep sshd | wc -l` は、
**プロセスとしては 3 つ**ですが、**ジョブとしては 1 つ**として数えます。

```text
  $ ps ax | grep sshd | wc -l  &
    └────────────┬────────────┘
         これで1つのジョブ

    ps(1234)  grep(1235)  wc(1236)   ← プロセスは3つ
```

**ジョブを管理しているのはシェル**です。カーネルではありません。
そのため**シェルを閉じるとジョブという概念も消えます**（プロセスは別の話。後述）。

## フォアグラウンドとバックグラウンド

コマンドは**フォアグラウンド**か**バックグラウンド**のどちらかで動きます。

| | **フォアグラウンド** | **バックグラウンド** |
|:--|:--|:--|
| 端末を占有するか | **占有する** | **占有しない** |
| キーボード入力 | **受け取れる** | 受け取れない（止まる） |
| 次のコマンドを打てるか | **打てない**（終わるまで待つ） | **打てる** |
| 起動のしかた | 普通に実行する | **末尾に `&` を付ける** |

**コマンドをシェル上で実行すると、通常はフォアグラウンドで実行されます。**
フォアグラウンドで実行している間は、**そのジョブが終わるまで別の作業ができません**。

### バックグラウンドで起動する

**コマンドラインの末尾に `&` を付けて実行します。**

```bash
$ ping -c 1000 localhost > ping.txt 2>&1 &   # 末尾の & でバックグラウンド実行する
[1] 1081
```

出力の `[1] 1081` は次の意味です。

```text
  [1] 1081
   │    │
   │    └─ PID（プロセスID）
   └────── ジョブ番号（シェルが付ける通し番号）
```

**補足 … `&` を付けたら出力先も決めてください**

バックグラウンドのジョブでも、**標準出力と標準エラー出力は端末に出続けます**。
作業中の画面に突然ログが割り込んでくるので、
**リダイレクトでファイルに逃がす**のが実務での作法です
（[標準入出力とリダイレクト](../01_シェルとコマンドライン/標準入出力とリダイレクト.md)）。

```bash
$ ./長い処理.sh > out.log 2>&1 &      # 標準出力と標準エラー出力をまとめてファイルへ
```

## ジョブ制御の全体像

**3 つの状態と、それをつなぐ 4 つの操作**だけです。

```text
                        Ctrl+Z
      ┌────────────────────────────────────┐
      │                                    ▼
  ┌──────────────────┐            ┌──────────────────┐
  │ フォアグラウンド │            │     一時停止     │
  │  （端末を占有）  │            │ （止まっている） │
  └──────────────────┘            └──────────────────┘
      ▲          ▲                     │         │
      │ fg       │ fg                  │ bg      │
      │          │                     ▼         │
      │     ┌────────────────────────────┐       │
      └─────│      バックグラウンド      │◀──────┘
  コマンド& │ （動いているが端末は空く） │
            └────────────────────────────┘

            jobs で表示できるのは、この3つの状態すべて
```

| 操作 | 何をするか |
|:--|:--|
| **`&`** | 最初からバックグラウンドで起動する |
| **`Ctrl+Z`** | **フォアグラウンドのジョブを一時停止する** |
| **`fg`** | バックグラウンドまたは一時停止中のジョブを**フォアグラウンドに戻す** |
| **`bg`** | **一時停止中のジョブをバックグラウンドで再開する** |

**`bg` の入口は「一時停止」だけ**です。
フォアグラウンドのジョブを直接バックグラウンドへ移すことはできないので、
**必ず `Ctrl+Z` で止めてから `bg`** という2手順になります。

## jobs

**意味** … **現在バックグラウンドで動作しているジョブと、一時停止中のジョブを表示するコマンド**です。

```text
jobs [オプション] [%ジョブ番号]
```

**例文**

```bash
$ ping -c 1000 localhost > ping.txt 2>&1 &   # 1つ目をバックグラウンドで起動する
$ sleep 500 &                                # 2つ目も起動する
$ jobs                                       # ジョブの一覧を見る
[1]-  Running                 ping -c 1000 localhost > ping.txt 2>&1 &
[2]+  Running                 sleep 500 &
```

### jobs のよく使うオプション

| オプション | 意味 |
|:--|:--|
| **`-l`** | **PID も一緒に表示する** |
| **`-r`** | **実行中（Running）のジョブだけ**表示する |
| **`-s`** | **一時停止中（Stopped）のジョブだけ**表示する |
| `-p` | **PID だけ**を表示する（他の情報を出さない） |
| `-n` | 前回表示したときから状態が変わったジョブだけ表示する |

```bash
$ jobs -l                             # PID 付きで表示する
[1]-  1081 Running                 ping -c 1000 localhost > ping.txt 2>&1 &
[2]+  1082 Running                 sleep 500 &

$ jobs -r                             # 実行中のものだけ
[1]-  Running                 ping -c 1000 localhost > ping.txt 2>&1 &
[2]+  Running                 sleep 500 &

$ jobs -s                             # 一時停止中のものだけ
$ echo $?                             # 何も出力されない（止まっているジョブが無い）
0
```

**いまは 2 本とも動いているので、`-r` は 2 行とも出て、`-s` は 1 行も出ません。**
**`-r` と `-s` の違いを見るには、片方を止めてから実行**します。

```bash
$ kill -STOP %1                       # ジョブ1だけを一時停止する
$ jobs -r                             # 実行中のものだけ
[2]-  Running                 sleep 500 &

$ jobs -s                             # 一時停止中のものだけ
[1]+  Stopped                 ping -c 1000 localhost > ping.txt 2>&1
```

**止まっているジョブの行には末尾の `&` が付きません**（実測）。
バックグラウンドで「動いている」わけではないためです。

```bash
$ kill -CONT %1                       # 確認が終わったら再開させておく
```

**補足** … `jobs` は**シェルの組み込みコマンド**です。
`/usr/bin/jobs` のような実行ファイルはありません。
**ジョブ情報を持っているのはシェル自身**なので、外部コマンドでは作れないためです。

### jobs の結果画面の見方

```text
[1]-  1081 Running                 ping -c 1000 localhost > ping.txt 2>&1 &
 │ │    │     │                     │
 │ │    │     │                     └─ 実行したコマンドライン
 │ │    │     └─────────────────────── 状態
 │ │    └───────────────────────────── PID（-l のときだけ）
 │ └────────────────────────────────── カレントジョブの記号
 └──────────────────────────────────── ジョブ番号
```

**① ジョブ番号** … `fg` や `bg` や `kill` で対象を指定するときに使う番号です。

**② カレントジョブの記号**

| 記号 | 意味 |
|:-:|:--|
| **`+`** | **カレントジョブ**。`fg` や `bg` を引数なしで実行したときの対象 |
| **`-`** | **2 番目のジョブ**（次にカレントになる候補） |
| （空白） | それ以外 |

**カレントジョブとは、直前にバックグラウンドで実行されたジョブ、
または直前に一時停止されたジョブ**のことです。

**この `+` は操作のたびに動きます。**

```bash
$ kill -STOP %1                       # ジョブ1を一時停止する
$ jobs                                # 状態を確認する
[1]+  Stopped                 ping -c 1000 localhost > ping.txt 2>&1
[2]-  Running                 sleep 500 &
```

**いま止めた `[1]` に `+` が移りました。**
このあと `fg` を引数なしで打つと、`[1]` が戻ってきます。

**③ 状態**

| 表示 | 意味 |
|:--|:--|
| **`Running`** | **バックグラウンドで動作中** |
| **`Stopped`** | **一時停止中** |
| `Done` | 正常に終了した（次に `jobs` を打つと一覧から消える） |
| `Exit 1` | 0 以外の終了ステータスで終わった |
| `Terminated` | シグナルで終了させられた |

## ジョブの指定方法

`fg` / `bg` / `kill` に渡す指定方法は**`%` で始めます**。

| 書き方 | 意味 |
|:--|:--|
| **`%1`** | **ジョブ番号 1** |
| **`%`** または **`%+`** | **カレントジョブ**（`+` が付いているもの） |
| **`%-`** | **2 番目のジョブ**（`-` が付いているもの） |
| `%文字列` | その文字列で**始まる**コマンドのジョブ |
| `%?文字列` | その文字列を**含む**コマンドのジョブ |

```bash
$ fg %1                               # ジョブ1をフォアグラウンドに戻す
$ fg                                  # 引数なしはカレントジョブ（%+ と同じ）
$ kill %2                             # ジョブ2を終了させる
$ fg %ping                            # ping で始まるジョブを戻す
```

**`%` を忘れると PID として解釈されます。**
`kill 1` は「ジョブ1」ではなく「**PID 1 = systemd**」への指示になるので、
**`%` は必ず付けてください**（一般ユーザなら権限エラーで済みますが、root では危険です）。

## 一時停止する

**フォアグラウンドで実行中のジョブを一時停止するには `Ctrl+Z` を押します。**

```bash
$ ping localhost > ping.txt           # フォアグラウンドで実行する（端末が占有される）
^Z                                    # Ctrl+Z を押す
[1]+  Stopped                 ping localhost > ping.txt
```

**`Ctrl+Z` が送っているのは `SIGTSTP`（20）というシグナル**です。
終了ではなく**停止**なので、メモリ上の状態はそのまま保持されます。

**似ているキー操作との違い**

| キー | 送るシグナル | 何が起きるか |
|:--|:--|:--|
| **`Ctrl+Z`** | **`SIGTSTP`（20）** | **一時停止する**（あとで再開できる） |
| **`Ctrl+C`** | **`SIGINT`（2）** | **終了する**（再開できない） |
| `Ctrl+\` | `SIGQUIT`（3） | 終了してコアダンプを出す |
| `Ctrl+D` | （シグナルではない） | 入力の終わり（EOF）を送る |
| `Ctrl+S` / `Ctrl+Q` | （シグナルではない） | 画面出力を止める／再開する |

**`Ctrl+S` で画面が固まったように見えたら `Ctrl+Q`** で戻ります。
プロセスは止まっていないので `jobs` にも変化が出ず、これを知らないと原因を探せません。

**補足 … `Ctrl+Z` は「終了」ではありません**

一時停止したジョブは**終了していません**。メモリを保持したまま残ります。
そのまま端末を閉じようとすると、シェルが警告を出します。

```text
There are stopped jobs.
```

**放置すると資源を掴んだままになる**ので、`fg` で戻して終わらせるか、
`kill %1` で明示的に終了させてください。

## fg

**意味** … **バックグラウンドで動作中、または一時停止中のジョブを、フォアグラウンド動作に切り替えるコマンド**です。

```text
fg [%ジョブ番号]
```

**引数を省略するとカレントジョブ（`+` が付いているもの）が対象**になります。

```bash
$ fg %1                               # ジョブ1をフォアグラウンドに戻す
ping -c 1000 localhost > ping.txt 2>&1
```

**戻すと同時に、そのジョブが端末を占有します。**
一時停止中だったジョブは、`fg` で戻した時点で**再開**します
（内部的に `SIGCONT`(18) が送られます）。

## bg

**意味** … **一時停止中のジョブを、バックグラウンド動作に切り替えるコマンド**です。

```text
bg [%ジョブ番号]
```

```bash
$ kill -STOP %1                       # ジョブ1を一時停止する（Ctrl+Z 相当）
$ bg %1                               # バックグラウンドで再開させる
[1]+ ping -c 1000 localhost > ping.txt 2>&1 &
$ jobs                                # 状態を確認する
[1]-  Running                 ping -c 1000 localhost > ping.txt 2>&1 &
[2]+  Running                 sleep 500 &
```

**`bg` の直後に表示される行の末尾に `&` が付いている**ことに注目してください。
「バックグラウンドで起動し直した形になった」という意味です。

**補足 … `bg` したジョブが入力を求めると止まります**

バックグラウンドのジョブがキーボード入力を読もうとすると、
**`SIGTTIN` が送られて自動的に停止**します。

```bash
$ cat < /dev/tty &                    # 入力を読むコマンドをバックグラウンドで動かす
[1] 2119
$ jobs                                # 素の jobs では理由まで出ない
[1]+  Stopped                 cat < /dev/tty
$ jobs -l                             # -l を付けると停止理由が出る
[1]+  2119 Stopped (tty input)     cat < /dev/tty
```

**停止理由の `(tty input)` が出るのは `jobs -l` のときだけ**です（実測）。
素の `jobs` は `Stopped` としか表示しないため、
**「なぜ止まったのか分からない」ときは `-l` を付けて**ください。

この場合は `fg` で戻して入力してください。**対話が必要なコマンドは `bg` に向きません。**

## ジョブとプロセスの違い

**ここが混同しやすいところ**なので、表で整理します。

| | **ジョブ** | **プロセス** |
|:--|:--|:--|
| **管理しているのは** | **シェル** | **カーネル** |
| **番号** | **ジョブ番号**（`[1]`）。シェルごとの通し番号 | **PID**。システム全体で一意 |
| 数え方 | パイプでつないだ一連は**1つ** | パイプの各コマンドが**それぞれ1つ** |
| 一覧するコマンド | **`jobs`** | **`ps`** / `pgrep` |
| 指定方法 | **`%1`** | **`1234`** |
| 見える範囲 | **そのシェルの中だけ** | **システム全体** |

**別の端末を開いて `jobs` を打っても、何も出ません。**
ジョブはそのシェルだけのものだからです。
**他の端末から操作したいときは PID を調べて `kill`** を使います。

```bash
$ jobs -l                             # ジョブ番号と PID の対応を確認する
[1]-  1081 Running                 ping -c 1000 localhost > ping.txt 2>&1 &

$ kill 1081                           # 他の端末からは PID で指定する
```

## 端末を閉じてもジョブを生き残らせる

**バックグラウンドのジョブは、端末を閉じると止まることがあります。**
端末が切れると、シェルが子プロセスに **`SIGHUP`（1）** を送るためです。

対処は 3 つあります。

| 方法 | 書き方 | 向いている場面 |
|:--|:--|:--|
| **`nohup`** | `nohup コマンド &` | **起動時に決められる**とき。手軽 |
| **`disown`** | 起動後に `disown %1` | **すでに動かしてしまった**あと |
| **`tmux` / `screen`** | セッションを作って中で実行 | **あとで画面ごと戻りたい**とき |

```bash
$ nohup ./長い処理.sh &               # SIGHUP を無視して起動する
nohup: ignoring input and appending output to 'nohup.out'

$ ./長い処理.sh &                     # うっかり普通に起動してしまった場合
[1] 2345
$ disown %1                           # シェルのジョブ表から外し、SIGHUP の対象から外す
```

**`nohup` は出力先も面倒を見ます。** リダイレクトを書かなかった場合、
標準出力を **`nohup.out`** に追記します（書き込めなければ `$HOME/nohup.out`）。

**補足 … 実務では `tmux` がいちばん確実です**

`nohup` や `disown` は**あとから画面に戻れません**。
数時間かかる作業は `tmux` のセッション内で実行しておくと、
回線が切れても `tmux attach` で続きを見られます。

## 実務での使い方

**典型的なのは「フォアグラウンドで始めた処理が思ったより長かった」場合**です。

```bash
$ tar czf backup.tar.gz /var/log      # 実行してみたら想像以上に時間がかかる
^Z                                    # ① Ctrl+Z で一時停止する
[1]+  Stopped                 tar czf backup.tar.gz /var/log

$ bg %1                               # ② バックグラウンドで再開させる
[1]+ tar czf backup.tar.gz /var/log &

$ jobs                                # ③ 端末が空いたので別の作業ができる
[1]+  Running                 tar czf backup.tar.gz /var/log &
```

**`Ctrl+Z` → `bg` は 2 手セット**で覚えてください。実務で最も使うジョブ制御です。

**もう1つの典型は `vi` からの一時離脱**です。

```bash
$ vi /etc/nginx/nginx.conf            # 設定ファイルを編集中
^Z                                    # ① Ctrl+Z で vi を止めてシェルに戻る
[1]+  Stopped                 vi /etc/nginx/nginx.conf

$ nginx -t                            # ② 別のコマンドで確認する
$ fg                                  # ③ 編集に戻る（カレントジョブなので引数不要）
```

**`vi` を終了させずに済む**ので、編集中の内容を保ったまま確認作業ができます。
