## ip コマンドと古いコマンドの対応

**`ip` コマンドは `iproute2` パッケージに含まれ、
`ifconfig` / `route` / `arp` / `netstat` を 1 つにまとめたもの**です。

```text
ip [オプション] オブジェクト [コマンド]
        │          │
   -s（統計）   address / link / route / neigh …
```

**対応表**

| やりたいこと | **新しい書き方（`ip`）** | 古い書き方 | 古い方のパッケージ |
|:--|:--|:--|:--|
| **アドレスを見る** | **`ip addr show`**（`ip a`） | `ifconfig` | `net-tools` |
| **アドレスを付ける** | **`ip addr add 10.0.0.5/24 dev eth0`** | `ifconfig eth0 10.0.0.5 netmask 255.255.255.0` | 同上 |
| **インタフェースを上げる／下げる** | **`ip link set eth0 up` / `down`** | `ifconfig eth0 up` / `down` | 同上 |
| **経路を見る** | **`ip route show`**（`ip r`） | `route -n` | 同上 |
| **経路を足す** | **`ip route add 10.1.0.0/24 via 10.0.0.1`** | `route add -net 10.1.0.0/24 gw 10.0.0.1` | 同上 |
| **既定の経路を足す** | **`ip route add default via 10.0.0.1`** | `route add default gw 10.0.0.1` | 同上 |
| **ARP テーブルを見る** | **`ip neigh show`**（`ip n`） | `arp -n` | 同上 |
| 接続の一覧を見る | **`ss`** | `netstat` | 同上 |

> **`ifconfig` / `route` / `arp` / `netstat` はどれも `net-tools` パッケージ**です。
> **最近のディストリでは既定でインストールされていない**ことがあります。
> **「`ifconfig: command not found` が出る」のは壊れているのではなく、そもそも入っていない**だけです。

**なぜ置き換わったのか**

| | `ifconfig` など | `ip` |
|:--|:--|:--|
| **1 つの NIC に複数の IP** | **エイリアス（`eth0:1`）という特殊な形**が必要 | **普通に複数付けられる** |
| **新しい機能への対応** | **更新が止まっている**（IPv6 や新機能の表示が不完全） | **カーネルの機能に追随している** |
| コマンドの数 | 用途ごとに別コマンド | **`ip` に統一** |

**試験でも実務でも `ip` が基本**ですが、**古い手順書には `ifconfig` が出てくる**ので、両方読めるようにしておきます。

## ipコマンドの組み立て方

**`ip` は「オプション → オブジェクト → コマンド → 対象」の順**で組み立てます。
**この形を覚えると、暗記する量が一気に減ります。**

```text
  ip  [オプション]  オブジェクト  [コマンド]  [対象]
       │             │            │           │
       -br -c -s -j  address      show         eth0
       -4 -6 -d      link         add          10.0.0.1/24
                     route        del
                     neigh        get
```

```bash
$ ip -br address show eth0             # 全部書いた形
$ ip -br a                             # 省略した形（同じ意味）
```

**オブジェクトは先頭から一意に識別できれば省略できます。**

| 正式 | 省略形 | 何を扱うか |
|:--|:--|:--|
| **`address`** | **`addr`** / **`a`** | **IP アドレス** |
| **`link`** | **`l`** | **インタフェースそのもの**（MAC、UP/DOWN、MTU） |
| **`route`** | **`r`** | **ルーティングテーブル** |
| **`neighbour`** | **`neigh`** / **`n`** | **ARP テーブル**（隣の機器の MAC） |
| `maddress` | `m` | マルチキャストアドレス |
| `netns` | — | ネットワーク名前空間 |

> **`show` も省略できます。**`ip a` は `ip address show` と同じです。
> **業務のメモやスクリプトでは正式名で書く**ほうが、後から読む人に親切です。

## 表示を変えるグローバルオプション

**ここが `ip` を使いこなす鍵**です。
**これらは「どのオブジェクトにも効く」オプション**で、`ip` の直後に置きます。

| オプション | 何をするか |
|:--|:--|
| **`-br`**（`-brief`） | **1 行 1 件の簡潔な表示にする** |
| **`-c`**（`-color`） | **色を付ける**（UP は緑、DOWN は赤） |
| **`-s`**（`-stats`） | **統計を出す**（送受信バイト数、エラー数）。2 回重ねるとさらに詳細 |
| **`-j`**（`-json`） | **JSON で出す**（スクリプトで扱うとき） |
| **`-d`**（`-details`） | **詳細を出す**（インタフェースの種類など） |
| **`-4`** / **`-6`** | **IPv4 だけ / IPv6 だけ**に絞る |
| `-o`（`-oneline`） | 1 件を強制的に 1 行にまとめる（`grep` しやすい） |

### -br 簡潔表示

**サーバにログインして最初に打つのはこれ**です。

```bash
$ ip -br address                       # アドレスを1行ずつ
```

```text
lo               UNKNOWN        127.0.0.1/8 
veth1@if5        UP             10.10.0.1/24 
```

```bash
$ ip -br link                          # インタフェースの状態とMACを1行ずつ
```

```text
lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP> 
veth1@if5        UP             5e:2e:5e:9e:44:94 <BROADCAST,MULTICAST,UP,LOWER_UP> 
```

**列の意味は 3 つだけ**です。

```text
  veth1@if5        UP             10.10.0.1/24
  └─ 名前          └─ 状態        └─ アドレス
```

> **`@if5` の部分は「対になっている相手のインタフェース番号」**です。
> **veth（ペアで作る仮想NIC）・VLAN・MACVLAN など、親や対向を持つ種類だけに付きます。**
> **物理 NIC（`eth0` など）には付きません。**
> **インタフェース名そのものは `@` の手前まで**で、`ip -j` の `ifname` にも `@` 以降は入りません。

| 状態 | 意味 |
|:--|:--|
| **`UP`** | **使える状態**（リンクも上がっている） |
| **`DOWN`** | **落ちている**。**理由は 2 通りある**（下記） |
| **`UNKNOWN`** | **状態を報告しない種類のインタフェース**。**up にした `lo` がこれ**。**異常ではありません** |
| **`LOWERLAYERDOWN`** | **下位のインタフェースが落ちている**（VLAN の親 NIC が down など） |

> **`lo` が `UNKNOWN` なのを見て不安になる必要はありません。**
> **ループバックは物理的なリンクを持たない**ので、状態を報告しないだけです。
> **なお `lo` が down の状態なら `DOWN` と出ます**（実測）。`UNKNOWN` は up のときの表示です。

**`DOWN` のときは第4列のフラグを見てください。**

```text
  veth1@if11  DOWN  5a:cf:...  <BROADCAST,MULTICAST>
                               ▲ UP が無い ＝ 設定で落ちている
                               → ip link set veth1 up で上がる

  veth1@if11  DOWN  5a:cf:...  <NO-CARRIER,BROADCAST,MULTICAST,UP>
                               ▲ UP はあるが NO-CARRIER
                               → 設定は上がっているが、リンクが来ていない
                               → ケーブル・対向機器・SFP を疑う。ip link set では直らない
```

**この 2 つを区別できないと、「`up` にしたのに直らない」で止まります。**

**`-br` が効くのは `address` / `link` / `neigh` の 3 つ**です。
**`route` に付けても表示は変わりません**（実測。もともと 1 行 1 件のため）。

```bash
$ ip -br neigh                         # ARP テーブルを1行ずつ
```

```text
10.10.0.99                              veth1            
10.10.0.2                               veth1            1a:67:fc:93:c9:76
```

> **`-br neigh` は状態（`REACHABLE` / `STALE` / `FAILED`）を表示しません。**（実測）
> **MAC が空欄なら解決できていない**、という読み方はできますが、
> **状態を見たいときは `-br` を付けずに `ip neigh`** を使ってください。
>
> ```text
>   ip neigh      → 10.10.0.99 dev veth1 FAILED
>   ip -br neigh  → 10.10.0.99    veth1          （FAILED が出ない）
> ```

### -c 色を付ける

```bash
$ ip -br -c address                    # 簡潔表示に色を付ける
```

**`UP` が緑、`DOWN` が赤、IP アドレスが紫**になります。
**インタフェースが 10 個以上ある機器では、これだけで見落としが減ります。**

> **オプションは重ねられます。**`ip -br -c -4 a` で
> 「IPv4 だけを、色付きで、1 行ずつ」になります。
>
> **`alias ipa='ip -br -c a'` のようにエイリアスを張っておく**と毎回楽です。
>
> **ただし `-c` は、パイプに流しても色コードを付けます。**
> **`grep` に通すと一致しなくなることがある**ので、
> **スクリプトや `grep` と組み合わせるなら `-c=auto`** にしてください。
>
> ```bash
> $ ip -br -c=auto a | grep eth0       # 端末なら色付き、パイプなら色無しになる
> ```

### -s 統計を出す

**「パケットが落ちていないか」を見るときに使います。**

```bash
$ ip -s link show veth1                # 送受信の統計を出す
```

```text
6: veth1@if5: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP mode DEFAULT group default qlen 1000
    link/ether 5e:2e:5e:9e:44:94 brd ff:ff:ff:ff:ff:ff link-netns ns2
    RX:  bytes packets errors dropped  missed   mcast           
         66700    1156      0       0       0       0 
    TX:  bytes packets errors dropped carrier collsns           
         73373    1212      0       0       0       0 
```

| 列 | 見るべきところ |
|:--|:--|
| **`errors`** | **0 でなければハードウェアかケーブルを疑う** |
| **`dropped`** | **0 でなければバッファ溢れか、受け取る相手がいないパケット** |
| `missed` | 受信が追いつかず取りこぼした数 |
| `carrier` | リンクが切れた回数（ケーブル抜けなど） |
| `collsns` | 衝突回数。いまどきの全二重では通常 0 |

**`-s` を 2 回重ねると、エラーの内訳まで出ます。**

```bash
$ ip -s -s link show veth1             # エラーの内訳まで出す
```

```text
    RX errors:  length    crc   frame    fifo overrun
                     0      0       0       0       0 
    TX errors: aborted   fifo  window heartbt transns
                     0      0       0       0       2 
```

> **`crc` が増えているならケーブルか物理層**、
> **`fifo` / `overrun` が増えているなら受信処理が追いついていない**、
> という切り分けに使います。

### -j JSON で出す

**スクリプトから使うときは、文字列を切り出すより JSON のほうが安全**です。

```bash
$ ip -j -br address                    # JSON で出す
```

```text
[{"ifname":"lo","operstate":"UNKNOWN","addr_info":[{"local":"127.0.0.1","prefixlen":8}]},{"link_index":5,"ifname":"veth1","operstate":"UP","addr_info":[{"local":"10.10.0.1","prefixlen":24}]}]
```

```bash
$ ip -j -br a | jq -r '.[] | "\(.ifname) \(.operstate)"'   # jq で整形する
$ ip -j a | jq -r '.[].addr_info[]?.local'                   # IPアドレスだけ取り出す
```

> **`awk` や `cut` で列を数える書き方は、出力が変わると壊れます。**
> **構築手順書や監視スクリプトでは `-j` ＋ `jq` に寄せる**のが安全です。

## ip address アドレスを見る

**意味** … **インタフェースに設定されている IP アドレスを表示する**

```bash
$ ip addr show                       # すべてのインタフェースを表示する
$ ip a                               # 省略形。よく使う
$ ip a show eth0                     # 特定のインタフェースだけ
$ ip -4 a                            # IPv4 だけを表示する
$ ip -br a                           # 1行1インタフェースの簡潔な表示
```

**例文**

```bash
$ ip a                               # アドレスの一覧を見る
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 9001 qdisc mq state UP group default qlen 1000
    link/ether 02:42:ac:11:00:02 brd ff:ff:ff:ff:ff:ff
    inet 10.0.1.25/24 brd 10.0.1.255 scope global dynamic eth0
       valid_lft 3210sec preferred_lft 3210sec
```

**結果画面の見方**

| 表示 | 意味 | 見るポイント |
|:--|:--|:--|
| **`2: eth0:`** | **インタフェースの番号と名前** | 名前は環境によって `ens5` `enp0s3` などになる |
| **`<... UP,LOWER_UP>`** | **状態のフラグ** | **`UP`＝管理上有効、`LOWER_UP`＝ケーブル／リンクが生きている** |
| **`mtu 9001`** | **1 回に送れる最大サイズ** | **AWS の一部インスタンスは 9001（ジャンボフレーム）** |
| **`state UP`** | インタフェースの状態 | **`DOWN` なら `ip link set <名前> up`** |
| **`link/ether 02:42:…`** | **MAC アドレス** | 物理アドレス |
| **`inet 10.0.1.25/24`** | **IPv4 アドレスとプレフィックス** | **ここが空なら IP が付いていない** |
| **`brd 10.0.1.255`** | ブロードキャストアドレス | — |
| **`scope global`** | 有効範囲 | `global`＝外部と通信可、`host`＝自分の中だけ |
| **`dynamic`** | **DHCP で取得した**ことを示す | 静的設定なら付かない |
| **`valid_lft 3210sec`** | **リース（貸出）の残り時間** | `forever` なら静的 |

**簡潔に見たいとき**

```bash
$ ip -br a                           # 名前・状態・アドレスだけを1行で出す
lo               UNKNOWN        127.0.0.1/8 ::1/128
eth0             UP             10.0.1.25/24 fe80::42:acff:fe11:2/64
```

**`-br`（brief）は一覧性が高く、サーバが何台もあるときに便利**です。

**`ifconfig` での同じ確認**

```bash
$ ifconfig                           # net-tools の古い書き方
$ ifconfig eth0                      # 特定のインタフェースだけ
```

**`ifconfig` は既定で「UP のインタフェースだけ」を表示します。**
**落ちている NIC を見落とす**ので、`ifconfig -a` で全件を出します。

## ip link インタフェースを見る

**意味** … **アドレスではなく、インタフェースそのもの（L2 レベル）の状態を表示する**

```bash
$ ip link show                       # インタフェースの一覧
$ ip link                            # 省略形
$ ip -s link show eth0               # 統計（送受信のバイト数とエラー）を含める
$ ip -br link                        # 1行にまとめて表示する
```

**例文 … エラーカウンタを見る**

```bash
$ ip -s link show eth0               # 統計付きで表示する
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 9001 qdisc mq state UP mode DEFAULT group default qlen 1000
    link/ether 02:42:ac:11:00:02 brd ff:ff:ff:ff:ff:ff
    RX: bytes  packets  errors  dropped overrun mcast
    1234567890 8901234       0        0       0     0
    TX: bytes  packets  errors  dropped carrier collsns
    9876543210 7654321       0        0       0      0
```

| 列 | 意味 | 異常の目安 |
|:--|:--|:--|
| **`errors`** | **壊れて受け取れなかった数** | **0 以外は物理層を疑う**（ケーブル、SFP、ポート） |
| **`dropped`** | **捨てられた数** | バッファ不足、フィルタ |
| **`overrun`** | 受信が追いつかなかった数 | 高負荷 |
| `carrier` | リンクの喪失回数 | ケーブル抜けの繰り返し |
| `collsns` | 衝突（コリジョン） | 現代のスイッチ環境ではまず 0 |

**`errors` と `dropped` が増え続けているなら、上位のアプリを見ても解決しません。**

**状態フラグの読み方**

| フラグ | 意味 |
|:--|:--|
| **`UP`** | **管理上「有効にした」状態**（`ip link set up` をした） |
| **`LOWER_UP`** | **物理的にリンクが確立している**（ケーブルが刺さって相手がいる） |
| **`NO-CARRIER`** | **`UP` だが、リンクが確立していない** |
| `BROADCAST` / `MULTICAST` | それぞれに対応している |

**`UP` なのに `NO-CARRIER`** は、**「有効にしたがケーブルが繋がっていない」**という意味です。

## ip route 経路を見る

**意味** … **どの宛先へ、どのインタフェースから、どのゲートウェイ経由で出るか**の一覧を表示する

```bash
$ ip route show                      # 経路の一覧
$ ip r                               # 省略形
$ ip route get 8.8.8.8               # その宛先に「実際に」どの経路が使われるかを調べる
```

**例文**

```bash
$ ip r                               # ルーティングテーブルを見る
default via 10.0.1.1 dev eth0 proto dhcp src 10.0.1.25 metric 100
10.0.1.0/24 dev eth0 proto kernel scope link src 10.0.1.25 metric 100
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown
```

**結果画面の見方**

| 表示 | 意味 |
|:--|:--|
| **`default via 10.0.1.1`** | **デフォルトゲートウェイ。**どの経路にも当てはまらない宛先はここへ送る |
| **`dev eth0`** | **そのインタフェースから出す** |
| **`10.0.1.0/24 dev eth0 scope link`** | **直接つながっているネットワーク**（ゲートウェイ不要） |
| **`proto kernel`** | カーネルが自動で作った経路 |
| **`proto dhcp`** | **DHCP から受け取った経路** |
| **`src 10.0.1.25`** | 送信元として使うアドレス |
| **`metric 100`** | **優先度。小さいほうが優先** |
| **`linkdown`** | **そのインタフェースが落ちている**ので使われない |

> **`default` の行が無ければ、外部へは一切出られません。**
> **「同じサブネットの相手には `ping` が通るのに、インターネットに出られない」**ときは、
> 真っ先にここを見ます。

**どの経路が選ばれるかを調べる**

```bash
$ ip route get 8.8.8.8               # 8.8.8.8 宛に使われる経路を調べる
8.8.8.8 via 10.0.1.1 dev eth0 src 10.0.1.25 uid 1000
    cache

$ ip route get 10.0.1.30             # 同一セグメント宛
10.0.1.30 dev eth0 src 10.0.1.25 uid 1000
    cache
```

**`ip route get` は「机上で経路を引く」コマンド**です。
NIC が複数あるときに**「この宛先はどっちから出るのか」**を確実に判定できます。

**経路の選ばれ方**

```text
① 宛先に最も「長く一致する」経路が選ばれる（ロンゲストマッチ）
      10.0.1.0/24 と default の両方に当てはまるなら、/24 のほうが優先

② 同じ長さなら metric が小さいほうが優先
```

**`route -n` での同じ確認**

```bash
$ route -n                           # net-tools の古い書き方（-n は名前を引かない）
Kernel IP routing table
Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
0.0.0.0         10.0.1.1        0.0.0.0         UG    100    0        0 eth0
10.0.1.0        0.0.0.0         255.255.255.0   U     100    0        0 eth0
```

| `route -n` の表示 | `ip r` での対応 |
|:--|:--|
| **`Destination 0.0.0.0`** | **`default`** |
| `Genmask 0.0.0.0` | プレフィックス `/0` |
| **`Flags U`** | 経路が有効（Up） |
| **`Flags UG`** | 有効 **かつ ゲートウェイ経由**（`G` があれば `via` がある） |

## ip neigh ARP テーブルを見る

**意味** … **同一セグメントの相手の IP アドレスと MAC アドレスの対応表**を表示する

**ARP**（Address Resolution Protocol）は、**IP アドレスから MAC アドレスを調べるしくみ**です。
同じネットワーク内では、**最終的に MAC アドレス宛に送る**ため、この対応が必要になります。

```bash
$ ip neigh show                      # ARP テーブルを見る
$ ip n                               # 省略形
10.0.1.1 dev eth0 lladdr 02:aa:bb:cc:dd:ee REACHABLE
10.0.1.30 dev eth0 lladdr 02:11:22:33:44:55 STALE
10.0.1.40 dev eth0  FAILED
```

| 状態 | 意味 |
|:--|:--|
| **`REACHABLE`** | **最近やりとりして、確実に届く** |
| **`STALE`** | 以前は届いたが、しばらく通信していない（**異常ではない**） |
| `DELAY` / `PROBE` | 確認中 |
| **`FAILED`** | **応答が無い。その IP の機器がいない可能性** |
| `PERMANENT` | 手動で固定した |

**`FAILED` や、そもそもエントリが無い**なら、**同一セグメントに相手がいない**か、
**相手が応答していない**ということです。

```bash
$ arp -n                             # net-tools の古い書き方
$ ip neigh flush all                 # ARP テーブルを消してやり直す（要 root）
```

**補足 … IP を変更した直後に届かないとき**

**古い MAC の対応が残っている**ことがあります。`ip neigh flush` で消せますが、
**しばらく待てば自動で更新**されます。

## その場で設定を変える

> **ここで行う変更は、すべて「再起動すると消えます」。**
> **恒久化するには次の節の設定ファイルか `nmcli` を使います。**

**アドレスを追加・削除する**

```bash
$ sudo ip addr add 10.0.1.50/24 dev eth0     # IP を追加する
$ sudo ip addr del 10.0.1.50/24 dev eth0     # IP を削除する
$ ip a show eth0                             # 結果を確認する
```

**`ip` では 1 つの NIC に複数の IP を普通に付けられます。**
`ifconfig` の `eth0:1` のようなエイリアス表記は不要です。

**インタフェースを上げ下げする**

```bash
$ sudo ip link set eth0 down         # 無効にする
$ sudo ip link set eth0 up           # 有効にする
$ sudo ip link set eth0 mtu 1500     # MTU を変える
```

> **リモートから作業しているときに `ip link set eth0 down` を実行すると、
> そこで接続が切れて戻せなくなります。** コンソールが使える状態でのみ実行します。

**経路を追加・削除する**

```bash
$ sudo ip route add 10.2.0.0/24 via 10.0.1.1        # 特定のネットワークへの経路を足す
$ sudo ip route add default via 10.0.1.1            # デフォルトゲートウェイを足す
$ sudo ip route del 10.2.0.0/24                     # 経路を消す
$ sudo ip route replace default via 10.0.1.254      # 既定の経路を置き換える
```

**`add` は既にあるとエラーになります。`replace` なら上書きできます。**

## 設定を恒久化する

**どこに書くかはディストリによって違います。** ここが RHEL 系と Debian 系で最も分かれるところです。

| 方式 | 主なディストリ | 設定の場所 |
|:--|:--|:--|
| **NetworkManager**（`nmcli`） | **RHEL 系（RHEL / CentOS / Rocky / Alma）、最近の Ubuntu デスクトップ** | `/etc/NetworkManager/system-connections/` |
| **旧 network-scripts** | RHEL 7 以前 | **`/etc/sysconfig/network-scripts/ifcfg-eth0`** |
| **netplan** | **Ubuntu 18.04 以降のサーバ** | **`/etc/netplan/*.yaml`** |
| ifupdown | Debian、古い Ubuntu | `/etc/network/interfaces` |

**RHEL 系（`nmcli`）**

```bash
$ nmcli connection show                       # 接続の一覧を見る
$ nmcli connection show eth0                  # 詳細を見る

$ sudo nmcli connection modify eth0 \
    ipv4.method manual \
    ipv4.addresses 10.0.1.50/24 \
    ipv4.gateway 10.0.1.1 \
    ipv4.dns "10.0.0.2 8.8.8.8"               # 静的に設定する

$ sudo nmcli connection up eth0               # 設定を反映する
```

**`nmcli connection up` をしないと反映されません。**

**Ubuntu サーバ（netplan）**

```bash
$ sudo vi /etc/netplan/01-netcfg.yaml         # 設定ファイルを編集する
```

```yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses: [10.0.1.50/24]
      routes:
        - to: default
          via: 10.0.1.1
      nameservers:
        addresses: [10.0.0.2, 8.8.8.8]
```

```bash
$ sudo netplan try                            # 120秒で自動的に元へ戻る安全な適用
$ sudo netplan apply                          # 確定させる
```

> **`netplan try` は、設定を間違えて接続が切れても自動で戻してくれます。**
> **リモート作業では `apply` の前に必ず `try`** を使います。

**RHEL 7 以前（ifcfg ファイル）**

```bash
$ cat /etc/sysconfig/network-scripts/ifcfg-eth0   # 設定内容を確認する
DEVICE=eth0
BOOTPROTO=none            # none/static＝静的、dhcp＝DHCP
ONBOOT=yes                # 起動時に有効にするか
IPADDR=10.0.1.50
PREFIX=24                 # NETMASK=255.255.255.0 でも可
GATEWAY=10.0.1.1
DNS1=10.0.0.2
```

| 項目 | 意味 |
|:--|:--|
| **`ONBOOT=yes`** | **起動時に有効にする。`no` だと NIC が上がらない** |
| **`BOOTPROTO`** | **`dhcp` か `none`（静的）** |
| `PREFIX` / `NETMASK` | どちらか一方を書く |
