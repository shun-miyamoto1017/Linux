## 全体像

```text
/etc/
 |- sysconfig/network                  Red Hat系の全体・(ホスト名)設定
 |- sysconfig/network-scripts/
 |    ifcfg-インタフェース名[0-9]        Red Hat系のデバイス別設定
 |- network/interfaces                 Debian系の全体・デバイス別設定
 |- hostname                           (Debian系の)ホスト名設定
 |- hosts                              ホスト名とIPアドレス対応の設定
 |- networks                           ネットワーク名とネットワークアドレス対応の設定
 |- nsswitch.conf                      名前解決の優先順位設定
 +- resolv.conf                        名前解決に使うDNSサーバの設定
```

**ディストリビューションが Red Hat 系か Debian 系かによって、
全体設定・デバイス別設定や、ホスト名を定義するファイルが異なっている点に注意**します（図の上 4 つ）。

**名前解決に関係した設定ファイル（図の下 4 つ）については、
どのディストリビューションでも共通して使えるものと思っていいでしょう。**

**これらのファイルは名前が似ているものも多く、混乱しがち**です。
**まずは各ファイルの書式など細かい点よりも、これらの役割の違いをよく理解する**ことが重要です。
**ネットワークに関連したトラブルシュートの問題などで、
これらのうちどのファイルが該当する設定を行うファイルかといった知識が必要**になります。

## RedHat系の設定ファイル

### /etc/sysconfig/network

**Red Hat 系（Enterprise Linux 6 以前）のディストリビューションでネットワークの全体設定を行うファイル**です。
**このファイルで、ネットワークや IPv6 を使用するかどうか、ホスト名・ドメイン名などが設定できます。**

```text
$ cat /etc/sysconfig/network
NETWORKING=yes
NETWORKING_IPV6=no
HOSTNAME=localhost.localdomain
DOMAINNAME=localdomain
```

| 項目 | 意味 |
|:--|:--|
| **`NETWORKING`** | **ネットワークを使用するかどうか** |
| **`NETWORKING_IPV6`** | **IPv6 アドレスの使用を有効化する**（`yes` で有効） |
| **`HOSTNAME`** | **このマシンのホスト名** |
| **`DOMAINNAME`** | **ドメイン名** |

**存在しない項目に注意**

| 名前 | 正誤 |
|:--|:-:|
| **`NETWORKING_IPV6`** | **○ これが正しい** |
| `NETWORKINGIPV6` | ✕（アンダースコアが無い） |
| `IPV6` | ✕（存在しない） |
| `ADDRESS_IPV6` | ✕（存在しない） |

> **Enterprise Linux 7 以降ではホスト名は `/etc/hostname` で管理されます。**
> **「EnterpriseLinux6 以前」という但し書きが問題文に入るのはそのため**です。

### /etc/sysconfig/network-scripts/ifcfg-eth0

**Red Hat 系でネットワークインタフェースの設定を行うファイル**です。
**`/etc/sysconfig/network-scripts` ディレクトリ内に
`ifcfg-インタフェース名[0-9]` という名前でインタフェースごとに存在**しています。

```text
  eth0 → /etc/sysconfig/network-scripts/ifcfg-eth0
  eth1 → /etc/sysconfig/network-scripts/ifcfg-eth1
```

```text
$ cat /etc/sysconfig/network-scripts/ifcfg-eth0
DEVICE=eth0
BOOTPROTO=dhcp
HWADDR=00:19:DB:E9:FB:E7
ONBOOT=yes
```

| 項目 | 意味 |
|:--|:--|
| **`DEVICE`** | **デバイス名** |
| **`BOOTPROTO`** | **`dhcp` なら DHCP で取得、`static` / `none` なら固定** |
| **`HWADDR`** | **デバイスの MAC アドレス** |
| **`ONBOOT`** | **`yes` なら起動時に自動で有効化する** |

**これはシステム全体に対する設定ではなく、`eth0` に対する設定であるという点がポイント**です。

| 選択肢 | 正誤 | 理由 |
|:--|:-:|:--|
| **`/etc/sysconfig/network-scripts/ifcfg-eth0`** | **○** | **インタフェースごとの設定ファイル** |
| `/etc/sysconfig/network` | ✕ | **全体設定のファイル**。インタフェースごとの設定は書けない |
| `/etc/network/interfaces` | ✕ | **Debian 系のファイル** |
| `/etc/network/interfaces-eth0` | ✕ | **このようなファイルは一般的に存在しない** |

## Debian系の設定ファイル

### /etc/network/interfaces

**Debian 系でネットワークの全体設定やネットワークインタフェース別の設定を行うファイル**です。
**Red Hat 系と違い、1 つのファイルにすべて書きます。**

```text
# ループバック
auto lo
iface lo inet loopback

# eth0 を DHCP で
auto eth0
iface eth0 inet dhcp

# eth1 を固定アドレスで
auto eth1
iface eth1 inet static
    address 192.168.1.10
    netmask 255.255.255.0
    gateway 192.168.1.1
```

| キーワード | 意味 |
|:--|:--|
| **`auto`** | **起動時に自動で有効化する**（Red Hat 系の `ONBOOT=yes` にあたる） |
| **`iface`** | **インタフェースの定義を始める** |
| **`inet dhcp`** | **DHCP でアドレスを取得する** |
| **`inet static`** | **固定アドレスを使う**（`address` / `netmask` / `gateway` を続けて書く） |

> **「マシンのホスト名・ドメイン名」は `/etc/network/interfaces` では設定できません。**
> **Debian 系でホスト名・ドメイン名を設定するファイルは `/etc/hostname`** です。

## ホスト名はどこで決まるか

**Debian 系ディストリビューションにおいて、自分自身のホスト名を設定するためのファイルは `/etc/hostname`** です。

```text
$ cat /etc/hostname
www4210u          ← このマシンのホスト名
```

**1 行だけ、ホスト名がそのまま書かれています。**

| ファイル | ホスト名を設定できるか |
|:--|:-:|
| **`/etc/hostname`** | **○ Debian 系はこれ**（現在は Red Hat 系でも使う） |
| **`/etc/sysconfig/network`** | **○ Red Hat 系（6 以前）の `HOSTNAME=` 項目** |
| `/etc/hosts` | **✕** |
| `/etc/host` | **✕ 一般的には存在しないファイル** |
| `/etc/resolv.conf` | **✕** |

**`/etc/hosts` との違いが最頻出の引っかけ**

**`/etc/hosts` はホスト名と IP アドレスの対応をローカルで設定することができるファイル**です。
**自分自身の IP アドレスに対応するホスト名をここに書くこともできますが、
それでは名前解決の際にそのホスト名が利用できるというだけで、
自分自身のホスト名を設定したことにはなりません。**

```text
  /etc/hostname   「私はこう名乗ります」          … 自分の名前
  /etc/hosts      「あの IP はこう呼びます」      … 他人（と自分）の名前引き
        ▲ 主語が違う
```

> **`/etc/host` というファイルは一般的には存在しません。**
> **`/etc/host.conf` であれば `/etc/nsswitch.conf` に近い役割を持った古いシステム用の設定ファイル**で、
> **今でも互換性のために残されていることがあります。**

## 名前解決に関わる3つ

**役割の違いだけをここで押さえます。**
**中身の詳しい読み方**は
[名前解決の確認 digとhost](./名前解決の確認_digとhost.md) にあります。

| ファイル | 何を設定するか |
|:--|:--|
| **`/etc/hosts`** | **ホスト名と IP アドレスの対応を、手動で 1 行ずつ書く** |
| **`/etc/nsswitch.conf`** | **どのような方法で解決を試みるかという手段、およびその優先順位** |
| **`/etc/resolv.conf`** | **名前解決に使う DNS サーバ** |

### /etc/hosts

**書式は次のとおり**です。

```text
IPアドレス  ホスト名 [ホスト名...]
```

```text
$ cat /etc/hosts
127.0.0.1       localhost.localdomain localhost
192.168.2.55    s.localdomain s
```

**IP アドレスが先、ホスト名が後**です。1 つの IP に**複数のホスト名を並べて書けます**。

| 書式 | 正誤 |
|:--|:-:|
| **`IPアドレス ホスト名 [ホスト名...]`** | **○** |
| `ホスト名 IPアドレス [IPアドレス...]` | ✕（逆） |
| `ホスト名:IPアドレス [IPアドレス...]` | ✕（コロンでは区切らない） |
| `ユーザ名 ホスト名 [ホスト名...]` | ✕（ユーザ名は関係ない） |
| `ホスト名:ユーザ名 [ユーザ名...]` | ✕（同上） |

**「LAN 内のサーバに短い別名でアクセスしたい」への答えがこのファイル**です。

**ネットワーク内全体でそのようなホスト名を利用可能にするには DNS の設定が必要**ですが、
**自分が使うクライアントマシン上でのみ有効なように設定するだけなら、
`/etc/hosts` にホスト名と IP アドレスの対応を書くだけ**で済みます。

```text
  192.168.2.55  s      と書いておけば  ping s  や  http://s/  が通る
```

### /etc/nsswitch.conf

**ホスト名と IP アドレスの変換（名前解決）を行うには、
`/etc/hosts` に記載されている内容をもとに解決する方法、
DNS サーバに問い合わせをして解決する方法などがあります。**

**このような方法のうちどれを使うのか、また複数の方法を使う場合、
どのような順番で試みるのか（優先順位）という設定を行うファイル**です。

```text
$ cat /etc/nsswitch.conf
passwd:         ldap db files
shadow:         ldap db files
group:          ldap db files
hosts:          files dns
```

**`hosts:` とある行がホスト名の名前解決の設定**です。
**この例は `files dns` なので、まずローカルファイル（`/etc/hosts` など）による解決を試み、
それに失敗した場合は DNS を使って問い合わせを行う**という設定です。
**左に指定したものほど優先順位が高くなります。**

**`passwd:` `group:` などの行もあることから分かるとおり、
このファイルはホスト名の解決方法以外にも、
ユーザ名やプロトコル名など、様々な情報を検索する優先順位を設定しているファイル**です。

> **`nsswitch` という名前は Name Service SWITCH の略**——
> **由来と一緒に覚えておくと忘れにくい**です。

### /etc/resolv.conf

**DNS とは Domain Name System の略で、
インターネットを使った分散型データベースに問い合わせを行うことで名前解決を行うシステム**です。

**通常、各クライアントは直接問い合わせる先となる DNS サーバのアドレスを知っている必要があります。**
**その DNS サーバ設定を行うファイルが `/etc/resolv.conf`** です。

```text
$ cat /etc/resolv.conf
search sakura.ne.jp
nameserver 210.188.224.11
```

| 項目 | 意味 |
|:--|:--|
| **`nameserver`** | **問い合わせ先となる DNS サーバ** |
| `search` | 補完するドメイン名（複数指定可） |
| `domain` | 自ホストのドメイン名 |

**3 つの区別が問われる**

| 問われ方 | 答え |
|:--|:--|
| **どのような方法で解決を試みるか、およびその優先順位を設定する** | **`/etc/nsswitch.conf`** |
| **名前解決に使う DNS サーバを指定する** | **`/etc/resolv.conf`** |
| **ホスト名と IP アドレスの対応を手動で設定する** | **`/etc/hosts`** |

**`/etc/hosts` も `/etc/resolv.conf` も名前解決に関係した設定ファイル**ですが、
**「どのような方法で解決を試みるかという手段、およびその優先順位を設定する」わけではない**——
という切り方で誤答を落とします。

## etc networks

**`/etc/networks` はネットワーク名とネットワークアドレス
（IP アドレスのうち、サブネットを識別するための上位部分）の対応関係を記述する設定ファイル**です。

**ここで設定したネットワーク名は、例えば `route` コマンドの表示結果などで、
ネットワークアドレスの代わりに表示されるようになります。**
**複数のサブネットが存在する時に、それぞれのネットワークにわかりやすい名前をつけたい場合**に使えます。

```text
$ cat /etc/networks
default  0.0.0.0
Eigyo    192.168.1.0
Soumu    192.168.2.0
```

| 選択肢 | 正誤 | 理由 |
|:--|:-:|:--|
| **ネットワーク名とネットワークアドレスの対応関係を記述する設定ファイル** | **○** | これが正しい |
| Red Hat 系でネットワークの基本設定を行うファイル | ✕ | **`/etc/sysconfig/network` の説明** |
| Debian 系でネットワークの基本設定を行うファイル | ✕ | **`/etc/network/interfaces` の説明** |
| ホスト名と IP アドレスの対応関係を記述する設定ファイル | ✕ | **`/etc/hosts` の説明**。`/etc/networks` は**ホスト名ではなくネットワーク名** |

> **Ping-t の解説は「多くのディストリビューションでデフォルトでは存在しません」**としていますが、
> **Ubuntu 24.04 には最初から存在し、`link-local 169.254.0.0` の 1 行が入っていました**（実機で確認）。
> **無ければ作ればよい**という結論は変わりません。

## NICを足したときの切り分け

**Linux システムではネットワークインタフェースを複数認識し、それぞれで通信を行うことが可能**です。
**この機能を応用することで、Linux OS の入ったホストをルーターとして動作させることもできます。**

**2 枚目の NIC を足したのに通信できない**——このときの手順は次のとおりです。

```text
  ① ifconfig で状態を調査する
        ▼ 認識されているか、アドレスが付いているか
  ② 設定ファイルを編集する
        Debian 系 → /etc/network/interfaces
        Red Hat 系 → /etc/sysconfig/network-scripts/ifcfg-eth1
        ▼
  ③ 再起動または ifup で反映する
```

| 対策 | 正誤 | 理由 |
|:--|:-:|:--|
| **`ifconfig` コマンドを使ってインタフェースの状態を調査する** | **○** | **認識されているか、アドレスがどう割り当てられているかを調べられる** |
| **`/etc/network/interfaces` を編集して新しいインタフェースを設定する**（Debian 系） | **○** | **Debian 系の設定ファイル** |
| `/etc/sysconfig/` 以下のファイルを編集する | ✕（Debian 系の場合） | **Red Hat 系のディレクトリ** |
| `/etc/nsswitch.conf` を編集して利用するインタフェースを切り替える | ✕ | **名前解決の優先順位を設定するファイル**。インタフェースの切り替えはできない |
| 古いネットワークインタフェースを `ifconfig down` で停止させる | ✕ | **2 つのインタフェースを同時に利用することは可能**なので、古い方を停止させる意味は特にない |

> **トラブルシュートの問題では、コマンド・ファイル等がどのような役割を持っているかを
> しっかり理解しているかどうかが問われます。**
> **各コマンド・ファイルの動作・役割について自分で説明できるくらいに理解しておけば、
> 応用問題に対してもその場で考えることで答えが導き出せる**はずです。

## NetworkManager という選択肢

**`NetworkManager` は、ネットワーク設定を動的・自動的に行うプログラム**です。
**RHEL 6 以降、Red Hat 系の標準**になりました。

| 特徴 | 内容 |
|:--|:--|
| **動的・自動** | 接続先の変化を検知し、設定を自動で切り替える |
| **GUI がある** | デスクトップ環境から設定できる。CUI は `nmcli` / `nmtui` |
| **関連ファイルを書き換える** | **`/etc/resolv.conf` などを自動で更新する** |
| 設定の保存先 | `/etc/NetworkManager/system-connections/` |

**向いている環境と、向いていない環境があります。**

```text
   ノート PC / 無線 LAN / 接続先が頻繁に変わる
        → NetworkManager が向く（自動で切り替わってくれる）

   サーバ / 設定を固定したい / 変更を管理下に置きたい
        → 自動で書き換えられると困るので、無効化することもある
```

**「サーバでは無効化する」という運用は実在します。**
停止できない仕組みではなく、**運用方針として選べる**という点を押さえてください。

```bash
$ systemctl status NetworkManager    # 動いているか確認する
$ sudo systemctl disable --now NetworkManager   # 無効化する（方針として選ぶ場合）
```

**旧来の設定方法も使えます。**

```text
   RHEL 6 〜 8   … NetworkManager が標準
                   ただし initscripts（/etc/sysconfig/network-scripts/）も引き続き使える
        ↓
   両方が存在するため、片方だけ直すと もう片方に上書きされる ことがある

   RHEL 9 以降   … 保存先の既定が keyfile
                   （/etc/NetworkManager/system-connections/）に変わった
                   ifcfg 形式は互換のため読めるが、network-scripts パッケージは提供されない
```

**これが実務で最も多い事故**です。

```text
  ✗ NetworkManager が動いている環境で ifcfg-eth0 だけを直す
       → NetworkManager が再適用したときに元へ戻る

  ○ nmcli connection modify で直す
       → NetworkManager の管理下で一貫する

  ○ NetworkManager を止めてから ifcfg-eth0 を使う
       → 旧来の方法で一貫する
```

**どちらか一方に統一してください。** 混ぜるのが一番危険です。

**サービスの起動も、`/etc/init.d/` の直接実行ではなく `systemctl` 経由が推奨**です。

> **実測できていないこと** … この検証環境には NetworkManager が入っていないため、
> `nmcli` や `systemctl status NetworkManager` の実行結果は確認していません。

## 名前が似ているファイルの整理

**`network` という単語を含むファイル・パスが多く紛らわしい**ので、役割で区別します。

| パス | 何のファイルか |
|:--|:--|
| **`/etc/sysconfig/network`** | **Red Hat 系の「全体」設定**（単数形） |
| **`/etc/sysconfig/network-scripts/ifcfg-eth0`** | **Red Hat 系の「デバイス別」設定** |
| **`/etc/network/interfaces`** | **Debian 系の設定**（`network` がディレクトリ名） |
| **`/etc/networks`** | **ネットワーク「名」の設定**（複数形） |

```text
  network      単数形で /etc/sysconfig/ の下   → Red Hat系の全体設定
  network/     ディレクトリで /etc/ の直下     → Debian系（中の interfaces）
  networks     複数形で /etc/ の直下           → ネットワーク名の対応表
        ▲ 単数・複数・ディレクトリかファイルか、で見分ける
```

**存在しないファイル名**

| 名前 | 実際は |
|:--|:--|
| **`/etc/host`** | **存在しない**（`/etc/hosts` か `/etc/host.conf`） |
| **`/etc/network/config`** | **存在しない** |
| **`/etc/network/interfaces-eth0`** | **存在しない**（Debian 系は 1 ファイルにまとめる） |
| **`/etc/dns.conf`** | **存在しない**（`/etc/resolv.conf`） |
