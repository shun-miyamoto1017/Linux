## このノートでやること

**`yum install --assumeno` のログを、上から順にどう読むかを説明します。**

ログは、だいたいこの順番で並びます。

```text
① 読み込み         Loaded plugins / Examining / Marking
② 依存解決の実況    Resolving Dependencies / --> ...
③-A 失敗したとき    Error: Package: ... の塊
③-B 成功したとき    計画の表 → Transaction Summary
④ 終わり方         Is this ok [y/d/N]: → Exiting on user command
⑤ 後片付けの案内    Your transaction was saved, ...
```

**③が A なら「足りない」、B なら「足りた」**です。まずここを見分けます。

> **「足りた」＝「持ち帰る RPM がそろった」ではありません。**
> 社内リポジトリを有効にして下見すると、Yum が足りない依存を**リポジトリから補って**計画を作るため、
> **③-B になります。**何が補われたかは、計画の表の `Installing for dependencies:` を見ます（第4章）。

## 1. 読み込みのブロック

```text
Loaded plugins: product-id, search-disabled-repos, subscription-manager
Examining /home/shun/rpm/openssh-7.4p1-23.el7_9.x86_64.rpm: openssh-7.4p1-23.el7_9.x86_64
Marking /home/shun/rpm/openssh-7.4p1-23.el7_9.x86_64.rpm to be installed
Examining /home/shun/rpm/openssh-server-7.4p1-23.el7_9.x86_64.rpm: openssh-server-7.4p1-23.el7_9.x86_64
Marking /home/shun/rpm/openssh-server-7.4p1-23.el7_9.x86_64.rpm to be installed
Resolving Dependencies
```

| 行 | 意味 |
|:--|:--|
| `Loaded plugins:` | 読み込まれたプラグインの一覧。`--noplugins` を付けるとこの行自体が減る |
| `Examining ファイル: NEVRA` | **その RPM ファイルを開いて中身を見た**。左がファイル名、右が中の NEVRA |
| `Marking ファイル to be installed` | **その RPM を計画の候補に入れた** |
| `Resolving Dependencies` | ここから依存解決が始まる |

> **`Examining` はあるのに `Marking` が無い RPM が、「黙って外された RPM」です。**
> `Examining` の直後に警告が1行出て、`Marking` されずに次の RPM へ進みます。
> **これが一番の見落としどころ**なので、第5章で機械的に拾います。

## 2. 依存解決の実況

```text
--> Running transaction check
---> Package openssh.x86_64 0:7.4p1-23.el7_9 will be installed
---> Package openssh-server.x86_64 0:7.4p1-23.el7_9 will be installed
--> Processing Dependency: openssl-libs >= 1:1.0.2k-26 for package: openssh-server-7.4p1-23.el7_9.x86_64
--> Finished Dependency Resolution
```

| 行頭 | 意味 |
|:--|:--|
| `-->` | **解決の段階**が変わった（チェック開始、依存の処理、終了） |
| `--->` | **1つのパッケージについて決まったこと**（入る／更新される／消される） |
| `--> Processing Dependency: 条件 for package: 要求元` | **「要求元」が「条件」を欲しがっている**ので、満たすものを探しに行った |
| `--> Finished Dependency Resolution` | 解決の処理が終わった。**この直後に結果が出る** |

> **`--> Processing Dependency:` が出ること自体は異常ではありません。**
> 「探しに行った」というだけで、見つかれば何も言わずに次へ進みます。
> **見つからなかったものだけが、次の `Error:` に出ます。**

> **`---> Package ... will be installed` の `0:` は Epoch です。**`0:` は「Epoch なし（0 相当）」の意味です。

## 3. 依存が足りないとき（Error: の塊）

**ここがいちばん大事です。**`--> Finished Dependency Resolution` の直後に、次の形で出ます。

```text
Error: Package: openssh-server-7.4p1-23.el7_9.x86_64 (/openssh-server-7.4p1-23.el7_9.x86_64)
           Requires: openssl-libs >= 1:1.0.2k-26
           Installed: openssl-libs-1:1.0.2k-21.el7_9.x86_64 (@anaconda)
               openssl-libs = 1:1.0.2k-21.el7_9
           Available: openssl-libs-1:1.0.2k-26.el7_9.x86_64 (internal-rhel7)
               openssl-libs = 1:1.0.2k-26.el7_9
 You could try using --skip-broken to work around the problem
 You could try running: rpm -Va --nofiles --nodigest
```

**1行ずつ読みます。**

| 行 | 読み方 |
|:--|:--|
| `Error: Package: NEVRA (出どころ)` | **この RPM が困っています。**カッコの中が出どころ。`/` で始まればあなたが渡したファイル、リポジトリ名ならリポジトリ由来 |
| `Requires: 条件` | **この RPM が欲しがっている条件。**これが「足りないもの」で、**次に探す文字列そのもの**です |
| `Installed: NEVRA (@リポジトリ)` | **いまサーバーに入っている版。**`@` 付きは「導入済み」の印 |
| （その下の字下げ行） | その版が**実際に提供している内容**。`Requires:` と見比べると、なぜ足りないかが分かる |
| `Available: NEVRA (リポジトリ名)` | **リポジトリにはこの版がある**という情報。これが出ていれば、その版を取ってくれば解決します |
| `Not found` | **提供するものがどこにも無い。**リポジトリの同期内容や権利を確認します |
| `You could try using --skip-broken ...` | Yum の定型の案内。**従ってはいけません**（問題のある RPM を黙って外すだけです） |

**上の例の読み方**

1. `openssh-server` が `openssl-libs >= 1:1.0.2k-26` を欲しがっている
2. いま入っているのは `1:1.0.2k-21`。**21 < 26 なので条件を満たさない**
3. `Available:` に `1:1.0.2k-26` がある → **これを取ってくれば解決する**
4. 取りに行く NEVRA は **`openssl-libs-1:1.0.2k-26.el7_9.x86_64`**

> **`Installed:` と `Available:` が両方出ているときが、いちばん分かりやすい形**です。
> **`Available:` が無いときは、リポジトリにも無い**ということなので、取得元の確認が必要です。

> **`Requires:` の右側は、そのままコピーして検索に使います。**
> `repoquery --whatprovides 'openssl-libs >= 1:1.0.2k-26'` のように、**必ずクォートで囲んで**渡します。
> 囲まないと `>=` の `>` がリダイレクトとして解釈され、カレントディレクトリに `=` というファイルができます。

**`Error:` の塊だけを取り出すコマンド**

```bash
$ grep -n -A6 'Error: Package:' $LOG_DIR/dryrun_01.txt   # 要求元・条件・導入済み・候補をセットで見る
$ grep 'Requires:' $LOG_DIR/dryrun_01.txt | sort -u      # 足りない条件だけを重複なしで並べる
$ grep -c 'Error: Package:' $LOG_DIR/dryrun_01.txt       # 困っている RPM の数
```

## 4. 依存が足りたとき（計画の表）

```text
================================================================================
 Package            Arch     Version                Repository          Size
================================================================================
Installing:
 openssh            x86_64   7.4p1-23.el7_9         /openssh-7.4p1-23   1.2 M
Updating:
 openssl-libs       x86_64   1:1.0.2k-26.el7_9      internal-rhel7      1.2 M
Installing for dependencies:
 libedit            x86_64   3.0-12.20121213cvs.el7 internal-rhel7       92 k

Transaction Summary
================================================================================
Install  1 Package (+1 Dependent package)
Upgrade  1 Package

Total download size: 2.4 M
Is this ok [y/d/N]:
```

**表の列は、左から パッケージ名／アーキテクチャ／`Epoch:Version-Release`／出どころ／サイズ**です。

| 見出し | 意味 | 確認すること |
|:--|:--|:--|
| `Installing:` | **新しく入る。**あなたが指定したもの | 入れてよいものか承認を確認 |
| `Updating:` | 既存パッケージの更新 | **意図した版か** |
| **`Installing for dependencies:`** | **依存の都合で Yum が足したもの** | **あなたが渡した RPM に含まれているか。**無ければ取得対象 |
| **`Updating for dependencies:`** | 同上（更新として足されたもの） | 同上 |
| `Removing:` | 削除される | **想定外なら中断** |
| **`Removing for dependencies:`** | **依存の都合で消えるもの** | **サービス停止につながる。中断して管理者に確認** |
| `Reinstalling:` / `Downgrading:` | 再導入・ダウングレード | 想定外なら中断 |
| 行中の `replacing ...` | その行のパッケージが**何を置き換えるか** | 置き換え先が想定どおりか |

**`Transaction Summary` の数字の読み方**

| 表示 | 意味 |
|:--|:--|
| `Install 1 Package (+1 Dependent package)` | **自分で指定した1個＋依存で足された1個** |
| `Upgrade`／`Remove`／`Reinstall`／`Downgrade` | それぞれの件数 |
| **`Skipped (dependency problems)`** | **依存の問題で黙って外された件数。**`skip_broken` が有効なときに出る。**0 でなければ中断** |
| `Not installed` / `Not available` | 指定したものが見つからなかった件数 |
| `Total download size` | リポジトリから落とす合計サイズ。**ローカルファイルだけなら出ないこともある** |

> **「`... for dependencies:` に出たものが、取得して持ち帰るリスト」**です。
> 出どころの列にリポジトリ名が入っていれば、それは**別システムのリポジトリから補われた**という意味で、
> **そのままでは対象サーバーには存在しません。**

**計画の表だけを取り出すコマンド**

```bash
$ grep -n -E '^(Installing|Updating|Removing|Reinstalling|Downgrading)' $LOG_DIR/dryrun_01_repo.txt   # 見出しの行番号
$ sed -n '/^Installing for dependencies:/,/^$/p' $LOG_DIR/dryrun_01_repo.txt   # 依存で足された節だけ
$ grep -n -A12 'Transaction Summary' $LOG_DIR/dryrun_01_repo.txt   # 件数のまとめ
```

## 5. 黙って外された RPM を見つける

**`Examining` されたのに `Marking` されなかった RPM**は、警告1行だけで計画から外れています。

| ログに出る文字列 | 起きていること | 既定の出力レベルで出るか |
|:--|:--|:--|
| `Cannot open: ... Skipping.` | RPM ファイルを読めなかった（壊れ・権限） | 出る |
| `... does not update installed package.` | **同じ版か新しい版が入っている**ので更新にならない | 出る |
| `Cannot add package ... Not a compatible architecture:` | アーキテクチャが合わない | 出る |
| `Cannot install package ... It is obsoleted by installed package ...` | 入っているパッケージに置き換えられている | 出る |
| `Excluding ...` | `yum.conf` の `exclude` に該当した | **出ない** |

```bash
$ grep -n -E 'Cannot open|Skipping|does not update installed package|Not a compatible architecture|obsoleted by installed package' \
    $LOG_DIR/dryrun_01.txt                   # 計画から外された RPM の警告を探す
$ grep -c 'Examining ' $LOG_DIR/dryrun_01.txt    # 読み込まれた RPM の数
$ grep -c 'Marking '   $LOG_DIR/dryrun_01.txt    # 計画に入った RPM の数
```

**期待値**：警告が**何も表示されず**、`Examining` と `Marking` の数が**一致する**

❌ 数が合わない → その差が「外された RPM」です。上の警告を手がかりに、どれが外れたか特定します。

> **`Excluding ...` は既定の出力レベル（`debuglevel=2`）では出力されません。**
> Yum のソース上、この行は debug レベルで出ます。**grep しても見つからない**ので、
> 先に `/etc/yum.conf` と `/etc/yum.repos.d/*.repo` に `exclude` が無いことを確認しておきます。
> `exclude` があった場合は、下見に **`-d 3`** を足して実行すると `Excluding` が表示されます。

## 6. 終わり方

```text
Is this ok [y/d/N]: Exiting on user command
Your transaction was saved, rerun it with:
 yum load-transaction /tmp/yum_save_tx.2026-10-14.10-30.AbCdEf.yumtx
```

| 表示 | 意味 |
|:--|:--|
| `Is this ok [y/d/N]:` | 確認の問い。`y`＝実行、`d`＝ダウンロードのみ、`N`（既定）＝中止 |
| **`Exiting on user command`** | **`--assumeno` で「いいえ」と答えたので中止した。**正常。**終了コードは 1** |
| `Your transaction was saved, rerun it with:` | 解決した計画を `/tmp` に自動保存したという案内 |

> **`Exiting on user command` は成功の印**です。終了コードが 1 でも失敗ではありません。
> **`Operation aborted.` は RHEL 8 以降の `dnf` の表示で、RHEL 7 の `yum` では出ません。**
> 版による大文字小文字の違いを避けるなら `grep -i 'exiting on user'` で探します。

> **`yum load-transaction` を実行してはいけません。実更新になります。**
> この保存は**依存解決まで進めた回だけ**作られます。`Error:` で終わった回は作られません。

> **`Nothing to do`** で終わった場合は、計画そのものが空です。
> RPM の取り違え、`el7` 以外の混入、すでに同じ版が入っている、のいずれかを疑います。

## 7. 見る順番（チェックリスト）

**上から順にこの5つを見れば、だいたい判断できます。**

- [ ] **① 外された RPM はないか** … `Examining` と `Marking` の数が一致するか（第5章）
- [ ] **② `Error:` の塊はあるか** … あれば `Requires:` が足りないもの（第3章）
- [ ] **③ 計画に `... for dependencies:` はあるか** … あればそれが取得対象（第4章）
- [ ] **④ 消えるものはないか** … `Removing` / `Removing for dependencies` / `replacing`（第4章）
- [ ] **⑤ 終わり方** … `Exiting on user command` か、`Error:` か、`Nothing to do` か（第6章）

```bash
$ grep -c 'Examining ' $LOG_DIR/dryrun_01.txt        # ①
$ grep -c 'Marking '   $LOG_DIR/dryrun_01.txt        # ①
$ grep -c 'Error: Package:' $LOG_DIR/dryrun_01.txt   # ②
$ grep -n -E '^(Installing|Updating|Removing)( for dependencies)?:' $LOG_DIR/dryrun_01.txt   # ③④
$ tail -n 5 $LOG_DIR/dryrun_01.txt                   # ⑤
```

## 8. よくある読み違い

| 読み違い | 実際は |
|:--|:--|
| **`Exiting on user command` ＝ 持ち帰る RPM がそろった** | **違います。**社内リポジトリを有効にして下見すると、Yum がリポジトリから補うのでこうなります。**`... for dependencies:` を必ず見ます** |
| 終了コード 1 ＝ 失敗 | **違います。**`--assumeno` の正常な中止でも 1 になります |
| `--> Processing Dependency:` が出た ＝ 足りない | **違います。**「探しに行った」だけです。足りないものは `Error:` に出ます |
| `Requires:` の右側を名前だけに削って検索する | **版の条件を落とすと、条件を満たさないものまで出ます。**そのまま使います |
| `Installed:` があるから大丈夫 | **版が条件を満たしているかは別です。**その下の字下げ行と `Requires:` を見比べます |
| `Nothing to do` ＝ 適用済みで問題なし | **違います。**取り違えや混入でもこうなります |
| `--skip-broken` の案内に従う | **問題のある RPM を黙って外すだけ**です。CVE 対応の抜けが隠れます |
| `Excluding` を grep したが出ないので除外は無い | **既定の出力レベルでは出ません。**設定側（`exclude`）を確認します |
