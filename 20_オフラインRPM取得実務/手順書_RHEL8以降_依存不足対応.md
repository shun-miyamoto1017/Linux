## この手順書でやること

**CVE 対応で集めた RPM について、足りない依存 RPM がなくなるまで「確認 → 追加」を繰り返します。**
**システムには何も変更を加えません**（`--assumeno` で下見するだけ）。

```text
 ┌─▶ ① 署名を確認する        rpm -K ＋ Signature 行の確認
 │   ② 目次を更新する        createrepo_c --update
 │   ③ キャッシュを消す      dnf clean all
 │   ④ 下見する              dnf --repo=localrepo upgrade --assumeno
 │   ⑤ 結果を見る
 │        ├─ OK  ─────────────▶ 「完了したら」へ
 │        └─ 依存不足
 │   ⑥ 足りない RPM を取得して置く   ← ここだけ人がやる
 └───┘（①に戻る）
```

> **いちばん大事なこと**
> **RPM を追加したら、必ず ② 目次の更新 と ③ キャッシュ削除 をしてから ④ を実行します。**
> これを飛ばすと、追加した RPM が `dnf` から見えず、**同じエラーが出続けます。**

**やり方は 2 通りあります。**

| やり方 | 内容 | 向いている場面 |
|:--|:--|:--|
| **手動版** | ①〜⑤を自分で打つ | **初めてやるとき。**何が起きているか分かる |
| **スクリプト版** | ①〜⑤を `check_deps.sh` が 1 回でやる | **慣れてから。**やり忘れが起きない |

**最初は手動版で 1 周してください。**仕組みが分かってからスクリプト版に移ると安全です。

## 準備

### 変数を設定する

```bash
$ export REPO_DIR=/opt/localrepo         # ローカルリポジトリの置き場所
$ export REPO_ID=localrepo               # リポジトリID
$ export LOG_DIR=/var/tmp/depcheck       # 結果の保存先（日をまたいでも同じ場所にする）
$ export R=01                            # 今回のラウンド番号（1回目）
$ mkdir -p "$LOG_DIR"                    # 保存先を作る
```

> **SSH を切って入り直したら、この `export` をもう一度実行してください。**
> **その場合 `R` は続きの番号にします**（例: 3 回目なら `export R=03`）。

### RPM の数と OS の一致を確認する

```bash
$ ls "$REPO_DIR"/*.rpm | wc -l                              # RPM の数
$ rpm -E 'el%{rhel}'                                        # サーバのメジャーバージョン
$ ls "$REPO_DIR"/*.rpm | grep -v "$(rpm -E 'el%{rhel}')"    # OS に合わない RPM を洗い出す
```

**期待値**

- 1 つ目: 想定どおりの数
- 2 つ目: `el8` / `el9` / `el10` のいずれか
- 3 つ目: **何も表示されない**（`noarch` などで表示されたら、ファイル名を目で確認）

### best の設定を確認する（★飛ばさない）

```bash
$ grep -nE '^best' /etc/dnf/dnf.conf                       # 設定ファイルに書かれているか
$ dnf config-manager --dump 2>/dev/null | grep -E '^best'  # 実際に効いている値
```

**`best = 1` なら True、`best = 0` なら False です。**
**この値で、依存不足のときの画面がまったく変わります。**

| `best` | 依存不足のときの表示 | 終了ステータス |
|:--|:--|:--|
| **`1`（True）** | **`Error:` ＋ `Problem:` で停止** | 1 |
| **`0`（False）** | **`Skipping packages with broken dependencies:` → `Nothing to do.` → `Complete!`** | **0** |

**⚠️ `best=0` のときは、依存が足りていないのに `Complete!` で終わります。**
**「`Nothing to do.` だから更新対象が無いだけ」と判断すると、依存不足を見落とします。**

### 登録されている鍵を確認する（作業前に 1 回）

```bash
$ rpm -q gpg-pubkey --qf '%{VERSION}\t%{SUMMARY}\n'   # 登録済みの公開鍵
```

**期待値**: 持ち主がすべて `Red Hat, Inc.`
💡 Red Hat 以外の鍵（EPEL など）がある場合、署名確認が OK でも「Red Hat 製」とは言い切れません。
　詳しくは [ローカルリポジトリの仕組み](./ローカルリポジトリの仕組み.md) の署名の節に。

## 手動版の手順

### ① 署名を確認する

```bash
$ rpm -K "$REPO_DIR"/*.rpm | grep -Ei 'NOT OK|MISSING KEYS'   # 壊れ・鍵違いを拾う
```

**期待値**: **何も表示されない**

```bash
$ for f in "$REPO_DIR"/*.rpm; do \
    printf '%-44s %s\n' "$(basename "$f")" \
      "$(rpm -qpi "$f" 2>/dev/null | sed -n 's/^Signature *: *//p')"; \
  done | grep '(none)'                                       # 署名が入っていないものを拾う
```

**期待値**: **何も表示されない**
❌ 表示された → **その RPM は署名が入っていません。**取り直してください。

> **なぜ 2 つやるのか。**
> **署名が入っていない RPM に `rpm -K` を打つと `digests OK`（終了ステータス 0）が返ります**（実測）。
> **1 つ目の確認では検出できません。**
>
> ```text
> /opt/localrepo/appx-1.0-1.noarch.rpm:    digests signatures OK     ← 署名あり
> /opt/localrepo/libbaz-1.1-1.noarch.rpm:  digests OK                ← 署名なし
> ```

### ② 目次を更新する

```bash
$ sudo createrepo_c --update "$REPO_DIR"    # 差分だけ更新するので速い
```

**期待値**: エラーなく終わる

**なぜ？** `dnf` は RPM ファイルを直接見ず、**目次（`repodata/`）だけを見て判断**します。
RPM を追加したら目次も作り直す必要があります。

### ③ キャッシュを消す

```bash
$ sudo dnf clean all          # 覚えている古い目次を捨てる
```

**期待値**: `xx files removed` と出る

**なぜ？** `dnf` は前回読んだ目次を覚えています。
消しておかないと、**古い目次のまま判断してしまうことがあります**（`metadata_expire` の既定は 48 時間）。

### ④ 下見する（結果はファイルに保存）

```bash
$ sudo dnf --repo="$REPO_ID" upgrade --assumeno \
    > "$LOG_DIR/dryrun_$R.txt" 2>&1   # 下見の結果をファイルに保存する
```

**期待値**: 何も表示されずにプロンプトが戻る（結果はファイルに入っています）

💡 **パッケージ名は付けません。**付けないと**ローカルリポジトリの全 RPM**をまとめて確認できます。
💡 **大量の出力は画面に収まらない**ので、ファイルに保存しています。

### ⑤ 結果を見る

```bash
$ tail -n 8 "$LOG_DIR/dryrun_$R.txt"      # 最後の数行を見る
```

| 最後に出ている文 | 意味 | 次にやること |
|:--|:--|:--|
| **`Operation aborted.`** | ✅ **依存OK** | 「完了したら」へ |
| **`Error:` ＋ `Problem:`** | ❌ **依存が足りない**（`best=1`） | 下のコマンドで中身を見る → ⑥へ |
| **`Skipping packages with broken dependencies:` ＋ `Nothing to do.`** | ❌ **依存が足りない**（`best=0`） | 同上 |
| **`Nothing to do.` だけ** | ⚠️ 更新対象が無い | RPM の取り違え・`el8`/`el9` の取り違え・適用済みでないか確認 |

💡 `This system is not registered ...` や `Unable to detect release version` は**無視してよい**です。

**❌ のときは、足りないものの一覧を表示します。**

```bash
$ grep 'nothing provides' "$LOG_DIR/dryrun_$R.txt" | sort -u    # 足りないものを一覧する
```

実測の表示です。

```text
  - nothing provides libbaz needed by libbar-1.1-1.noarch
```

**読み方**

```text
  - nothing provides libbaz needed by libbar-1.1-1.noarch
                     └────┘      └──────────────────┘
                   足りないもの      それを要求している RPM
```

「**`libbar-1.1` を入れるには `libbaz` が必要だが、それを持っている RPM がない**」という意味です。
**`nothing provides` と `needed by` の間が「足りないもの」**です。

```bash
$ grep -A3 'Problem' "$LOG_DIR/dryrun_$R.txt"    # nothing provides が出ないときはこちら
```

### ⑥ 足りない RPM を取得して置く

1. 足りないものを見て、**どのパッケージを取ればよいか調べる** → [付録A 足りないRPMの調べ方](#付録a-足りないrpmの調べ方)
2. Red Hat カスタマーポータルからダウンロードする
3. サーバの `$REPO_DIR` に転送する（scp / WinSCP など）
4. 数と署名を確認する
   ```bash
   $ ls "$REPO_DIR"/*.rpm | wc -l                                 # 数が増えたか
   $ rpm -K "$REPO_DIR"/*.rpm | grep -Ei 'NOT OK|MISSING KEYS'    # 壊れ・鍵違い
   ```
5. 記録表（[付録B 記録表](#付録b-記録表)）に書く
6. **ラウンド番号を 1 つ進めて、①に戻る**
   ```bash
   $ export R=02     # 次は 03、04 …
   ```

💡 **1 回で終わらないのが普通です。**追加した RPM が、さらに別の RPM を必要とすることがあります。
💡 **同じエラータの仲間（`openssl` と `openssl-libs` など）はまとめて取ると、繰り返しが減ります。**

## スクリプト版の手順

**①〜⑤を [check_deps.sh](./check_deps.sh) が 1 回でやります。**
**スクリプトの中身は [依存チェックスクリプトの読み方](./依存チェックスクリプトの読み方.md) で 1 ブロックずつ解説しています。**

### 最初に 1 回だけ

```bash
$ sudo mkdir -p /root/bin                            # 置き場所を作る
$ sudo cp check_deps.sh /root/bin/                   # スクリプトを置く
$ sudo chmod 700 /root/bin/check_deps.sh             # root だけが実行できるようにする
$ export LOG_DIR=/var/tmp/depcheck                   # 結果の保存先を固定する
```

### 繰り返す作業

```bash
$ sudo -E /root/bin/check_deps.sh        # 引数なしで実行する（-E で LOG_DIR を引き継ぐ）
```

💡 **引数は付けません。**付けないとローカルリポジトリの**すべての RPM** をまとめて確認します。
💡 **`sudo -E`** を使うのは、`LOG_DIR` などの環境変数を `sudo` 先に引き継ぐためです。

### 結果の見方

画面の最後に、次のどれかが出ます。

| 表示 | 終了ステータス | 次にやること |
|:--|:--|:--|
| **`結果: ✅ 依存OK（このまま適用できる）`** | 0 | 「完了したら」へ |
| **`結果: ❌ 依存不足あり（N 件）`** | 1 | 下の表を見て RPM を追加 → 再実行 |
| **`結果: ⚠️ 更新対象なし`** | 3 | RPM の取り違え・`el8`/`el9` の取り違え・適用済みでないか確認 |
| **`[ERROR] ...`** / **`結果: ❌ 自動解析できないエラー`** | 2 | [困ったとき](#困ったとき) を参照 |

**依存不足のときの表示例**（実測）

```text
[12:55:21] 結果: ❌ 依存不足あり（1 件）
missing_capability  hint_package
libbaz              (server does not have it: needs lookup)

[12:55:21] 次にやること: missing_hint.tsv をもとに RPM を取得 → /opt/localrepo に置く → もう一度このスクリプトを実行
```

| 列 | 意味 |
|:--|:--|
| **`missing_capability`** | **足りないもの** |
| **`hint_package`** | **取ってくるパッケージのヒント**（サーバに入っている古い版から推測したもの） |

| `hint_package` の表示 | 意味 | 次にやること |
|:--|:--|:--|
| **`openssl-libs.x86_64`** のようなパッケージ名 | 古い版が入っている | **そのパッケージの新しい版**を取る |
| **`openssl-libs.x86_64 (記号を外して特定)`** | `libcrypto.so.3(OPENSSL_3.0.9)` のような**カッコ付きの記号を外して**特定した | 同じく**そのパッケージの新しい版**を取る |
| **`(server does not have it: needs lookup)`** | サーバに入っていない | [付録A](#付録a-足りないrpmの調べ方) で調べる |

### RPM を追加したら再実行する

```bash
$ sudo -E /root/bin/check_deps.sh        # もう一度実行する
```

画面に **`前ラウンドから追加された RPM: N 件`** と出るので、**追加した数と合っているか**確認します。
💡 **ラウンド番号はスクリプトが自動で数えます**（round01, round02 …）。

### スクリプトが保存するファイル

`$LOG_DIR/roundNN/` に入ります。

| ファイル | 内容 |
|:--|:--|
| `dryrun.txt` | **ドライラン結果の全文** |
| `missing.txt` | 足りないものの一覧 |
| `missing_hint.tsv` | 足りないもの と パッケージ名のヒント |
| `missing_detail.txt` | エラー部分の抜粋（どの RPM が要求しているか） |
| `added_since_prev.txt` | 前ラウンドから追加した RPM |
| `rpm_list.txt` | そのラウンド時点の RPM 一覧 |
| `signature.txt` | `rpm -K` の結果 |
| **`signature_detail.txt`** | **1 本ずつの署名の有無と Key ID** |
| `unsigned.txt` | **署名が入っていない RPM**（あれば） |
| `gpg_keys.txt` | 登録済みの公開鍵の一覧 |
| `createrepo.log` | 目次更新のログ |
| `summary.txt` | 更新件数（OK のときだけ） |
| `not_installed.txt` | サーバ未導入のパッケージ（OK のときだけ） |

## 完了したら

## 困ったとき

| 症状・表示 | よくある原因 | 対処 |
|:--|:--|:--|
| **RPM を追加したのに同じエラーが出る** | **② 目次更新・③ キャッシュ削除を忘れている** | **② ③ をやってから ④** |
| `[ERROR] root で実行してください` | 一般ユーザーで実行した | `sudo -E` で実行する |
| `[ERROR] リポジトリID [localrepo] の .repo が見つかりません` | ローカルリポジトリの登録がまだ | [手順書 RHEL 8 以降 openssh の更新](./手順書_RHEL8以降_openssh更新.md) の手順 4 を実施 |
| `[ERROR] createrepo_c がインストールされていません` | `createrepo_c` が無い | 同手順書の 1-1 を参照 |
| `[ERROR] 壊れている、または鍵の合わない RPM があります` | 転送で壊れた／鍵が未登録 | 表示されたファイルを取り直す／`rpm --import` |
| **`[ERROR] 署名なしの RPM は出所を保証できません`** | **署名が入っていない RPM が混ざっている** | **その RPM をポータルから取り直す**（別経路で入手したものが混ざっていないか確認） |
| `[ERROR] grep -P が使えません` | grep が PCRE 非対応 | 手動版でやる（RHEL の grep は通常 `-P` に対応） |
| `filtered out by modular filtering` | モジュール対象のパッケージ（`nodejs` / `php` など） | [ローカルリポジトリの仕組み](./ローカルリポジトリの仕組み.md) の Modularity を参照して相談 |
| `conflicts with` | 既存パッケージとぶつかっている | 相手のパッケージも新しい版が必要な可能性 → 相談 |
| `Failed to download metadata for repo` | 目次が無い／`baseurl` のパス間違い | ② をやり直す、`baseurl` のスラッシュ 3 つを確認 |
| **同じ不足が 3 回以上解消しない** | 依存がぐるぐる回っている可能性 | **作業を止めて相談** |

### やってはいけないこと

| やってはいけない | なぜ |
|:--|:--|
| **`--skip-broken` を付ける** | **エラーのあるパッケージを黙って外し、`Complete!` 終了ステータス 0 で終わります。**当たっていないのに当たったと報告する事故になります |
| **`--nobest` を付ける** | **1 つ前の版で妥協します。**修正が最新版にしか入っていなければ **CVE は残ります** |
| **`rpm -Uvh --nodeps` で入れる** | 依存が壊れ、あとで別の障害になります |
| **`gpgcheck=0` にする** | 署名のない RPM が黙って入ります |

## 付録A 足りないRPMの調べ方

### まず、サーバに入っている古い版から調べる

```bash
$ rpm -q --whatprovides openssl-libs                     # 名前が書いてある場合は名前だけ指定
$ rpm -q --whatprovides 'libcrypto.so.3()(64bit)'        # ファイル名の場合は ' ' で囲む
```

| 結果 | 意味 | 取得するもの |
|:--|:--|:--|
| **パッケージ名が出た** | 古い版が入っている | **そのパッケージの新しい版** |
| **`no package provides ...`** | まだ入っていない | 下の表やポータル検索で調べる |

### カッコ付きのバージョン記号は外して調べる

**`libcrypto.so.3(OPENSSL_3.0.9)(64bit)` のようにカッコ付きの記号が付いていると、そのままでは当たりません。**
古い版はその記号を持っていないからです。**記号を外して調べ直します。**

```bash
$ rpm -q --whatprovides 'libcrypto.so.3(OPENSSL_3.0.9)(64bit)'   # そのままでは当たらない
$ rpm -q --whatprovides 'libcrypto.so.3()(64bit)'                # (OPENSSL_3.0.9) を外す
```

検証環境で実測した例です（`libtest` というテスト用パッケージで再現）。

```text
$ rpm -q --whatprovides 'libtest.so.3(TESTVER_1.0)(64bit)'
no package provides libtest.so.3(TESTVER_1.0)(64bit)        ← 当たらない

$ rpm -q --whatprovides 'libtest.so.3()(64bit)'
libtest-1.0-1.noarch                                        ← 当たった
```

**この場合の答えは「そのパッケージの新しい版を取る」**です。
`libcrypto.so.3(OPENSSL_3.0.9)` なら **`openssl-libs` の新しい版**です。

💡 **スクリプト版は、この「記号を外して再検索」を自動でやります**（`(記号を外して特定)` と表示されます）。

### よくある対応表（RHEL 8 / 9）

| 足りないもの（例） | 取得するパッケージ |
|:--|:--|
| `libcrypto.so.1.1`（RHEL 8）/ `libcrypto.so.3`（RHEL 9） | **`openssl-libs`** |
| `libssl.so.1.1` / `libssl.so.3` | **`openssl-libs`** |
| `libc.so.6` | `glibc` |
| `libsystemd.so.0` / `libudev.so.1` | `systemd-libs` |
| `libselinux.so.1` | `libselinux` |
| `libz.so.1` | `zlib` |
| `libkrb5.so.3` / `libgssapi_krb5.so.2` | `krb5-libs` |
| `libnss3.so` | `nss` |
| `libpcre2-8.so.0` | `pcre2` |

💡 **上の表は目安です。**必ず `rpm -q --whatprovides` かポータル検索で裏を取ってください。

### そのほかの調べ方

1. **同じメジャーバージョンのオンライン端末があれば**
   ```bash
   $ dnf provides 'libcrypto.so.3()(64bit)'     # そのファイルを持つパッケージを探す
   ```
2. **Red Hat カスタマーポータルのパッケージ検索**
3. **エラータ（RHSA）から探す** → CVE 番号や RHSA 番号を開くと、**含まれる RPM の一覧**が見られます

### 選ぶときのコツ

- ファイル名に **サーバと同じ `el8` / `el9` / `el10`** が入っているもの
- **`()(64bit)` 付きなら `x86_64` 版**
- **要求を満たす版**で、今回の CVE と同じ時期のもの
- **同じエラータに入っている仲間（`openssl` と `openssl-libs` など）はまとめて取る**
  - **エラータ**とは、Red Hat が出す「修正のお知らせ＋修正パッケージ一式」のことです（CVE 対応は **RHSA**）
  - **仲間どうしは同じバージョンを要求し合うことが多い**ので、まとめて取るとラウンド数が減ります
