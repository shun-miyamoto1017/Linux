## パッケージとは何か

**Linux で使用するパッケージとは、ソフトウェアの実行ファイル、設定ファイル、ライブラリ、
マニュアルなどが含まれているファイルのこと**です。
**パッケージおよびその管理ツールを使用することによって、
ソフトウェアのインストール・アンインストールなどが容易にできるようになります。**

```text
   パッケージ 1 個の中身
  ┌───────────────────────────────────────────┐
  │ /usr/sbin/httpd              実行ファイル │
  │ /etc/httpd/conf/httpd.conf   設定ファイル │
  │ /usr/lib64/httpd/modules/    ライブラリ   │
  │ /usr/share/man/man8/httpd.8  マニュアル   │
  │ ＋ メタ情報（名前・バージョン・依存関係） │
  └───────────────────────────────────────────┘
```

**手動で `make install` する場合との違い**は、**どのファイルがどこに置かれたかを
システムが台帳として持つ**ことです。だから確実にアンインストールできます。

**Red Hat Linux が開発したパッケージに RPM 形式があります。**
**もとは Red Hat Package Manager の略でしたが、Red Hat 以外にも広まったため、
現在の正式名称は再帰的な「RPM Package Manager」**です（`man 8 rpm` の NAME 行）。
**現在は Red Hat Enterprise Linux（RHEL）、CentOS、openSUSE など、
多くのディストリビューションが使用しています。**

## パッケージファイル名の読み方

**RPM 形式のパッケージファイル名は以下のような形式**です。

```text
パッケージ名-バージョン番号-リリース番号.アーキテクチャ名.rpm
```

```text
   procmail  -  3.22  -  9  .  i386  .rpm
      │          │       │      │
      │          │       │      └─ アーキテクチャ名（CPU の種類）
      │          │       └──────── リリース番号（同じバージョンでの改訂回数）
      │          └──────────────── バージョン番号（ソフト本体の版）
      └─────────────────────────── パッケージ名
```

| 部分 | 意味 | 例 |
|:--|:--|:--|
| **パッケージ名** | ソフトウェアの名前 | `procmail` `httpd` `openssl` |
| **バージョン番号** | **ソフトウェア本体の版** | `3.22` `2.4.6` |
| **リリース番号** | **同じバージョンに対する、パッケージ側の改訂回数** | `9` `9.el7` |
| **アーキテクチャ名** | 対象の CPU | `x86_64` `i386` `noarch` |

**バージョン番号とリリース番号の違いが試験で問われます。**

```text
   httpd-2.4.6-97.el7.centos.x86_64.rpm
         └─┬─┘ └──────┬──────┘
      ソフトの版    ディストリ側の改訂
                     （セキュリティ修正のバックポートなど）
```

**RHEL のセキュリティ修正は、バージョンを上げずにリリース番号だけ上げる**のが通例です
（**バックポート**と呼びます）。
そのため「バージョンが古いから脆弱」とは限りません。CVE 対応ではリリース番号まで見ます。

| アーキテクチャ名 | 意味 |
|:--|:--|
| **`x86_64`** | **64bit の Intel / AMD 系**（いまの標準） |
| `i386` / `i686` | 32bit の Intel 系（古い） |
| `aarch64` | 64bit の ARM 系（Graviton など） |
| **`noarch`** | **CPU に依存しない**（スクリプトや設定だけのパッケージ） |
| `src` | ソースパッケージ（`.src.rpm`） |

## RPMツールとYUMツールの関係

**RPM 形式のパッケージ管理ツールには 2 つあります。**

| | **RPM ツール** | **YUM ツール** |
|:--|:--|:--|
| 位置づけ | **基本的なツール** | **RPM ツールを拡張したツール群** |
| **依存関係** | **自分では解決しない**（エラーで止まる） | **自動で解決する** |
| **取得元** | **手元のファイルだけ** | **インターネットやメディア上のリポジトリ** |
| 設定ファイル | `/usr/lib/rpm/rpmrc`（既定値） | `/etc/yum.conf` |
| 主なコマンド | **`rpm`** / **`rpm2cpio`** | **`yum`** |
| Debian 系の相当 | **`dpkg`** | **`apt-get`** |

```text
      YUM ツール（yum / dnf）
          │  依存関係を調べ、必要なパッケージを集めてくる
          ▼
      RPM ツール（rpm）
          │  実際にファイルを配置し、台帳に記録する
          ▼
      ファイルシステム
```

**`yum` は内部で `rpm` を呼んでいます。**
**実務で日常的に使うのは `yum` / `dnf`** ですが、
**調査のときは `rpm -q` 系が主役**になります（リポジトリを見に行かないので速い）。

**補足 … `rpmrc` は 4 か所から読まれます**

`man 8 rpm` の FILES には、読み込み順に次の 4 つが挙げられています。

| パス | 誰のものか |
|:--|:--|
| `/usr/lib/rpm/rpmrc` | **ディストリビューション提供の既定値**。パッケージ更新で上書きされる |
| `/usr/lib/rpm/<vendor>/rpmrc` | ベンダ固有の既定値 |
| **`/etc/rpmrc`** | **システム管理者が書く場所** |
| **`~/.rpmrc`** | **ユーザごとの設定** |

**`/usr/lib/rpm/rpmrc` は編集しないでください。** 更新のたびに消えます。
**管理者が触るのは `/etc/rpmrc` か `~/.rpmrc`** です。

## rpmコマンド

**`rpm` は RPM 形式のパッケージのインストール・アンインストールなど、
基本的なパッケージ管理を行うコマンド**です。

```text
rpm [動作を決めるオプション] [併用オプション] 対象
```

**`rpm` のオプションは「何をするか」を決める 1 つと、それを補う併用オプション**に分かれます。

### インストール関連のオプション

**以下は `rpm` コマンドのインストール関連の主なオプション**です。

| オプション | 説明 |
|:--|:--|
| **`-i`**（`--install`）**パッケージファイル名** | **パッケージのインストール** |
| **`-U`**（`--upgrade`）**パッケージファイル名** | **パッケージのアップグレード（なければインストール）** |
| **`-F`**（`--freshen`）**パッケージファイル名** | **パッケージのアップグレード（なければインストールしない）** |
| **`-e`**（`--erase`）**パッケージ名** | **パッケージのアンインストール** |

**`-i` `-U` `-F` は「パッケージファイル名」、`-e` は「パッケージ名」**を取ります。
ここが試験で狙われる違いです。

### iとUとFの違い

**3 つの違いは「すでに入っているかどうか」で場合分けすると分かります。**

```text
                入っていない        入っている
   -i           インストール        エラー
   -U           インストール        アップグレード   ← いちばん万能
   -F           何もしない          アップグレード   ← 一括更新向け
```

**「元々インストールされていない場合にインストールできるのはどれか」**という問いなら、
**`-i` と `-U` の2つが正解**です。`-F` は入っていないと何もしません。

**`-F` の使いどころ**は、「入っているものだけを最新にしたい」一括更新です。

```bash
$ rpm -Fvh *.rpm                      # ディレクトリ内のrpmのうち、既に入っているものだけ更新する
```

### 併用オプション

| オプション | 説明 |
|:--|:--|
| **`-v`** | **詳細情報の表示**（verbose） |
| **`-h`**（`--hash`） | **進行状況を「#」で表示** |
| **`--test`** | **実際には実行せずにテストを実施** |
| **`--nodeps`** | **依存関係を無視** |
| `--force` | 既存ファイルの上書きを強制する |
| `--replacepkgs` | 同じパッケージを再インストールする |
| `--oldpackage` | より古いバージョンへ戻す（ダウングレード） |
| `--prefix パス` | インストール先を変更する（対応パッケージのみ） |

**補足 … `-h` は削除（`-e`）と併用できます**

`-h` は名前のとおりインストール系のオプションですが、
**`rpm --help` では `-e`（`--erase`）と同じ「Install/Upgrade/Erase options」の
グループに置かれており、削除時にも指定できます**（実測）。

```bash
$ rpm -evh hello                      # 削除でも -v -h が効く
Preparing...                          ########################################
Cleaning up / removing...
hello-1.0-1                           ########################################
```

**「`-h` はインストール専用」という説明を見かけますが、実機の動きとは違います。**
試験で「インストール時に進行状況を表示するオプション」と問われたら `-h` が答えですが、
**実機では `rpm -evh` も普通に使えます**。

**`-ivh` はセットで覚えてください。** 実務ではほぼこの形で打ちます。

```text
   rpm -ivh package.rpm
        │││
        ││└─ hash（進行状況を # で表示）
        │└── verbose（詳しく表示）
        └─── install（インストール）
```

**補足 … `--nodeps` は原則使わないでください**

依存関係を無視してインストールできますが、**動かないものが入るだけ**です。
「依存が足りない」と言われたら、**`yum` を使って解決する**のが正しい対処です。

## インストールする

**まず `--test` で確認**してから実行するのが安全です。

```bash
$ rpm -i --test hello-1.0-1.noarch.rpm     # 実際には入れずにテストする（問題なければ無出力）
$ rpm -ivh hello-1.0-1.noarch.rpm          # 進行状況を表示しながらインストールする
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
hello-1.0-1                           ########################################
```

**`--test` は何も出なければ成功**です。依存が足りなければエラーが出ます。

**引数はパッケージ「ファイル」名であって、パッケージ名ではありません。**

| 書き方 | 動くか | 理由 |
|:--|:--|:--|
| **`rpm -i procmail-3.22-9.i386.rpm`** | **○** | ファイル名を指定している |
| **`rpm -U procmail-3.22-9.i386.rpm`** | **○** | 入っていなければインストールされる |
| `rpm -i procmail` | **✕** | **パッケージ名だけでは、どのバージョンか決まらない** |
| `rpm -U procmail` | **✕** | 同上 |

**`rpm` はリポジトリを見に行きません。**
手元にある `.rpm` ファイルしか扱えないため、
**バージョン番号やアーキテクチャ名まで含んだファイル名**が必要になります。

**URL を直接指定する**こともできます。

```bash
$ rpm -ivh https://example.com/pkgs/hello-1.0-1.noarch.rpm   # URL からインストールする
```

## アンインストールする

**`-e` はパッケージ「名」を取ります。** ファイル名ではありません。

```bash
$ rpm -e hello                        # パッケージ名を指定してアンインストールする
$ rpm -q hello                        # 消えたか確認する
package hello is not installed
```

**同じパッケージが複数バージョン入っている場合**は、バージョンまで指定します。

```bash
$ rpm -e kernel-3.10.0-1160.el7.x86_64      # バージョンまで指定して削除する
```

**依存されているパッケージは削除できません。**

```text
error: Failed dependencies:
	libfoo.so.1()(64bit) is needed by (installed) bar-1.0-1.x86_64
```

**このメッセージは「bar が foo を必要としている」という意味**です。
消したければ `bar` を先に消すか、そもそも消さない判断をします。

## 問い合わせる

**`-q`（`--query`）が調査の主役**です。実務ではここを最もよく使います。

### 問い合わせのオプション

| オプション | 説明 |
|:--|:--|
| **`-q パッケージ名`** | **インストールされているか調べる** |
| **`-qa`** | **インストール済みパッケージを全て表示** |
| **`-qi パッケージ名`** | **パッケージの詳細情報を表示**（information） |
| **`-ql パッケージ名`** | **パッケージに含まれるファイルの一覧**（list） |
| **`-qf ファイル名`** | **指定したファイルがどのパッケージに属するか**（file） |
| `-qc パッケージ名` | 設定ファイルだけを一覧する（config） |
| `-qd パッケージ名` | ドキュメントだけを一覧する（doc） |
| **`-qR パッケージ名`** | **そのパッケージが必要とするもの**（requires） |
| `--whatrequires 名前` | それを必要としているパッケージを探す |
| `-q --changelog 名前` | 変更履歴を表示する |
| **`-p`** | **未インストールのパッケージファイルに対して問い合わせる** |

```bash
$ rpm -q hello                        # インストールされているか調べる
hello-1.0-1.noarch

$ rpm -ql hello                       # 含まれるファイルの一覧を見る
/usr/share/hello/greeting.txt

$ rpm -qf /usr/share/hello/greeting.txt    # このファイルはどのパッケージのものか調べる
hello-1.0-1.noarch
```

**`-qf` は障害調査で頻繁に使います。**
「この設定ファイルは何のパッケージが置いたのか」が即座に分かります。

### インストール済みか未インストールかで書き方が変わる

**ここが `-q` の最重要ポイント**です。

| 対象 | 書き方 | 引数 |
|:--|:--|:--|
| **インストール済み** | **`rpm -qi httpd`** | **パッケージ名** |
| **未インストールのファイル** | **`rpm -qip httpd-2.4.6.rpm`** | **ファイル名** |

**`-p` を付けると「ファイルに対する問い合わせ」**になります。

```bash
$ rpm -qip hello-1.0-1.noarch.rpm     # 未インストールのrpmファイルの情報を見る
Name        : hello
Version     : 1.0
Release     : 1
Architecture: noarch
Install Date: (not installed)
Group       : Unspecified
Size        : 6
License     : MIT
Signature   : (none)
Source RPM  : hello-1.0-1.src.rpm
Build Date  : Fri Sep 18 22:13:48 2026
Build Host  : vm
Summary     : Sample package for documentation
Description :
A tiny sample package used to demonstrate rpm commands.

$ rpm -qlp hello-1.0-1.noarch.rpm     # 未インストールのrpmに含まれるファイルを見る
/usr/share/hello/greeting.txt
```

**`Install Date: (not installed)`** が「まだ入っていない」ことを示しています。
**入れる前に中身を確認できる**のが `-p` の価値です。

## 検証する

**`-V`（`--verify`）はインストール時から変わったファイルを検出**します。

```bash
$ rpm -V hello2                       # インストール直後に検証する
$ echo $?                             # 何も出力されず、終了ステータスは 0
0
```

**何も出なければ「変更なし」**です。
**ファイルを書き換えてから、もう一度実行**してみます。

```bash
$ echo "key = changed" > /etc/hello2.conf            # 設定ファイルの中身を変える
$ echo "hello world" > /usr/share/hello2/greeting.txt   # もう1つの中身も変える
$ chmod 600 /usr/share/hello2/greeting.txt           # パーミッションも変える
$ rpm -V hello2                       # 差分が出るようになる
S.5......  c /etc/hello2.conf
SM5......    /usr/share/hello2/greeting.txt
```

**先頭の 9 文字**がそれぞれ検査項目を表します（実測の出力です）。

```text
   S M 5 D L U G T P    ← 並び順は必ずこの9つ
   │ │ │ │ │ │ │ │ │
   │ │ │ │ │ │ │ │ └─ P: 機能（capabilities）が違う
   │ │ │ │ │ │ │ └─── T: 更新時刻（mtime）が違う
   │ │ │ │ │ │ └───── G: 所有グループが違う
   │ │ │ │ │ └─────── U: 所有ユーザが違う
   │ │ │ │ └───────── L: シンボリックリンクの参照先が違う
   │ │ │ └─────────── D: デバイス番号（メジャー／マイナー）が違う
   │ │ └───────────── 5: ダイジェスト（旧 MD5）が違う ＝ 中身が変わった
   │ └─────────────── M: モード（パーミッションとファイル種別）が違う
   └───────────────── S: サイズが違う
```

**`.` は「その項目は変わっていない」**を表します。

**上の実測例の読み方**

| 出力 | 意味 |
|:--|:--|
| `S.5......` | **サイズ**と**中身**が変わった（`/etc/hello2.conf`） |
| `SM5......` | **サイズ**・**モード**・**中身**が変わった（`/usr/share/hello2/greeting.txt`） |

**覚え方** … `S M 5 D L U G T P` の頭を取って **「エスエム・ご・どるぐとぴー」**のように
音で覚えてしまうのが早いです。`M`（モード）が 2 文字目、`5`（中身）が 3 文字目、
という**位置**が問われます。

**9 文字の後ろに付く記号**

```text
   S.5......  c /etc/hello2.conf
   └───┬───┘  │ └── ファイル名
       │      └──── 属性マーカー（ここに付く。行頭ではない）
       └─────────── 9文字の検査結果
```

| 記号 | 意味 |
|:--|:--|
| **`.`** | **変更なし**（9 文字の中に現れる） |
| **`5`** | **中身が変わった**（最重要） |
| **`c`** | **設定ファイル**（`%config`）。**9 文字の後ろ、ファイル名の前**に付く |
| `d` | ドキュメント（`%doc`） |
| `g` | ghost ファイル（パッケージに実体を含まない） |
| `l` | ライセンスファイル（`%license`） |
| `r` | readme ファイル（`%readme`） |
| `missing` | ファイルが**存在しない**（9 文字の代わりにこの語が出る） |

**`missing` のときは 9 文字ではなく、そのまま `missing` と表示されます。**

```bash
$ rm /usr/share/hello2/greeting.txt   # ファイルを消してしまう
$ rpm -V hello2                       # もう一度検証する
S.5......  c /etc/hello2.conf
missing     /usr/share/hello2/greeting.txt
```

```bash
$ rpm -Va                             # すべてのパッケージを検証する（時間がかかる）
```

**改ざん検知や、「設定ファイルを触った覚えはないが動かない」ときの調査に使えます。**
ただし**設定ファイル（`c` 印）は変更されていて当然**なので、そこは無視して読みます。

## rpm2cpio

**`rpm2cpio` は RPM 系パッケージを cpio 形式のアーカイブに変換するコマンド**です。

**アーカイブとは、複数のファイルやディレクトリを1つにまとめたファイルのこと**です。
**cpio は、Linux で長く使われているアーカイブ形式**です。

```text
rpm2cpio パッケージファイル名
```

**標準出力に cpio アーカイブを吐く**ので、`cpio` コマンドにパイプでつなぎます。

```bash
$ mkdir -p /tmp/ext && cd /tmp/ext    # 展開先の空ディレクトリを作って移動する
$ rpm2cpio /tmp/hello-1.0-1.noarch.rpm | cpio -idv   # 展開する
./usr/share/hello/greeting.txt
1 block
$ find . -type f                      # 展開されたファイルを確認する
./usr/share/hello/greeting.txt
```

| `cpio` のオプション | 意味 |
|:--|:--|
| **`-i`** | **展開する**（extract） |
| **`-d`** | **必要なディレクトリを作る** |
| **`-v`** | **処理したファイル名を表示する** |
| `-m` | 更新時刻を保持する |

**`-idv` はセットで覚えてください。** `-d` を忘れるとディレクトリが作られず失敗します。

**使いどころ**

| 場面 | なぜ `rpm2cpio` か |
|:--|:--|
| **1つのファイルだけ取り出したい** | インストールせずに、壊した設定ファイルの原本を取り戻せる |
| **中身を先に確認したい** | `rpm -qlp` より実物を見られる |
| **RPM が使えない環境で中身が欲しい** | 展開するだけなので `rpm` の台帳を汚さない |

```bash
$ rpm2cpio httpd-2.4.6.rpm | cpio -idv ./etc/httpd/conf/httpd.conf   # 1ファイルだけ取り出す
```

**「設定ファイルを壊してしまった」ときの復旧手段**として覚えておくと効きます。

## Debian系との対応

**Debian 系 Linux では、`dpkg` がほぼ同等のコマンドにあたります。**

| やること | **RHEL 系** | **Debian 系** |
|:--|:--|:--|
| **基本ツール** | **`rpm`** | **`dpkg`** |
| 上位ツール | **`yum`** / `dnf` | **`apt-get`** / `apt` |
| インストール | `rpm -ivh pkg.rpm` | `dpkg -i pkg.deb` |
| アンインストール | `rpm -e 名前` | `dpkg -r 名前` |
| 一覧 | `rpm -qa` | `dpkg -l` |
| 含まれるファイル | `rpm -ql 名前` | `dpkg -L 名前` |
| ファイルの所属 | **`rpm -qf パス`** | **`dpkg -S パス`** |
| パッケージ形式 | `.rpm` | `.deb` |

**`-qf` と `-S` の対応を覚えておくと、どちらの系統でも調査ができます。**

## 実務での使い方

| やりたいこと | コマンド |
|:--|:--|
| **入っているバージョンを確認する** | `rpm -q openssl` |
| **このファイルはどのパッケージのものか** | **`rpm -qf /etc/nginx/nginx.conf`** |
| **パッケージが置いたファイルを全部見る** | `rpm -ql httpd` |
| **設定ファイルだけ見る** | `rpm -qc httpd` |
| **入れる前に中身を確認する** | `rpm -qlp downloaded.rpm` |
| **改ざんや変更を調べる** | `rpm -V httpd` |
| **更新履歴（CVE対応）を見る** | `rpm -q --changelog openssl \| head -30` |
| **インストール日時順に一覧する** | `rpm -qa --last \| head` |

**CVE 対応では `--changelog` が効きます。**
バージョン番号が古く見えても、**バックポートで修正済みかどうかがここで分かります**。

```bash
$ rpm -q --changelog openssl | grep -i CVE-2023-0286    # 特定のCVEが修正済みか調べる
```

**補足 … `rpm` のデータベースは `/var/lib/rpm` にあります**

インストール済みパッケージの台帳はここです。
**壊れると `rpm -q` が動かなくなる**ため、次のコマンドで再構築できます。

```bash
$ sudo rpm --rebuilddb                # RPMデータベースを再構築する
```

**補足 … このノートの実行例について**

上の実行例は、確認用に作った最小のパッケージ（`hello-1.0-1.noarch.rpm`）を
サンドボックスの `rpm` 4.18.2 で実際に操作した結果です。
**RHEL 系の実機では、`rpm` の警告行の有無など表示が多少異なる可能性があります。**
