## メディアの三分類

### 磁気テープ

UNIX 系と汎用機で長く使われてきた、**大容量バックアップの本命**です。
現在の主流は **LTO**（Linear Tape-Open）。

| 特徴 | 内容 |
|:--|:--|
| 容量単価 | **最も安い** |
| 持ち運び | 軽くて小さい。オフサイト搬送に向く |
| 書き込み | 大容量の連続書き込みが**速い** |
| 読み出し | **シーケンシャルアクセス**。任意の場所に飛べない |
| 寿命・保管 | 長期保存に向くが、**テープの摩耗・たるみで劣化**するため定期メンテナンスが要る |
| 初期費用 | **ドライブ本体が高価**。テープ単体は安い |

**「メディアは安いが装置は高い」**のがテープの経済性です。
本数が増えるほど元が取れるため、保存量が大きいほど有利になります。

### 光学メディア

CD / DVD / BD。**末尾の文字で書き換えの可否が決まります。**

| 末尾 | 意味 | 書き換え |
|:--|:--|:--|
| **R**（DVD-R, BD-R） | Recordable。**ライトワンス（追記型）** | **上書き不可** |
| **RW / RE**（DVD-RW, BD-RE） | ReWritable / REcordable erasable | **上書き可** |

```text
   R  … 一度書いたら消せない  → 改ざんできない = 監査証跡の保管に向く
   RW … 何度でも書き換えられる → 繰り返し使える
```

**上書きできないことは、用途によっては長所**です。
「後から書き換えられない」ことが要件になる証跡保管では R が選ばれます。

### ハードディスク

| 特徴 | 内容 |
|:--|:--|
| アクセス | **ランダムアクセス**。任意の場所に即座に飛べる |
| 速度 | 速い |
| 容量単価 | テープより高い |
| 寿命 | 可動部があり、**長期保管には最も向かない** |

**RAID はバックアップではありません。**
RAID は「ディスクが壊れてもサービスを止めない」ための冗長化技術で、
誤削除・ランサムウェア・論理破壊からは一切守ってくれません。

```text
   RAID     … 機器故障に備える（可用性）
   バックアップ … 人為ミス・論理破壊・災害に備える（復旧性）
        → 目的が違うので、どちらかで代用はできない
```

同様に **LVM も**、物理デバイスを論理的に束ねて柔軟に扱う技術であって、バックアップではありません。

### 比較表

| | 磁気テープ | 光学メディア | HDD |
|:--|:--|:--|:--|
| アクセス方式 | シーケンシャル | 概ねランダム | ランダム |
| 容量単価 | **安い** | 中 | 高い |
| 大容量の連続書き込み | **速い** | 遅い | 速い |
| 一部だけ取り出す | **遅い** | 速い | **速い** |
| 長期のデータ保持 | 中〜長 | **長い** | **短い** |
| 装置の初期費用 | **高い** | 安い | 安い |
| 可搬性 | **高い** | 高い | 低い |

**データ保持期間の順序**は、おおむね次のように整理されます。

```text
   光学メディア  >  磁気テープ  >  HDD
```

## シーケンシャルアクセスとは何が不便なのか

テープは**頭から順にしかたどれません。**

```text
  [BOT] ── アーカイブ1 ──EOF── アーカイブ2 ──EOF── アーカイブ3 ── [EOT]
    ↑                                            ↑
  先頭                             ここを読むには、手前を全部通過する必要がある
```

この性質から、次の使い分けが出てきます。

| やりたいこと | テープの得手不得手 |
|:--|:--|
| フルバックアップを丸ごと書く | **得意**。先頭から流し込むだけ |
| フルバックアップを丸ごと戻す | **得意**。先頭から流し出すだけ |
| ファイル1本だけ取り出す | **不得意**。目的地まで巻き送る時間がかかる |
| 差分・増分を細かく出し入れする | **不得意**。位置決めが多発する |

```text
  テープ … 「まとめてドカッと」向き
  ディスク … 「ちょこちょこ出し入れ」向き
```

## テープのデバイスファイル

SCSI 接続のテープ装置は **`st` ドライバ**が扱います。
1台目には**2つのデバイスファイル**が用意されます。

| デバイス | 名前の由来 | 操作後の動作 |
|:--|:--|:--|
| `/dev/st0` | SCSI Tape | **自動で巻き戻す**（rewind） |
| `/dev/nst0` | **n** o-rewind SCSI Tape | **巻き戻さない**（位置を保つ） |

末尾の数字は**システムが認識した順**に 0, 1, 2 … と割り当てられます。

**まぎらわしい他のデバイス**

| デバイス | 正体 |
|:--|:--|
| `/dev/sr0` | CD/DVD ドライブ |
| `/dev/sda1` | ディスクのパーティション |
| `/dev/md0` | ソフトウェア RAID（MD）デバイス |

### st と nst の違い

Red Hat のドキュメントは次のように説明しています。

> A rewind tape device rewinds the tape after every operation.
> A non-rewinding tape device leaves the tape in its current status, after completing the execution of a certain command.

```text
[ /dev/st0 を使った場合 ]
  tar cf /dev/st0 dirA   →  書く → 自動で巻き戻る
  tar cf /dev/st0 dirB   →  先頭から書く = dirA が消える  ← 事故
  
[ /dev/nst0 を使った場合 ]
  tar cf /dev/nst0 dirA  →  書く → その場に留まる
  tar cf /dev/nst0 dirB  →  続きに書かれる = 2本が並ぶ    ← 意図どおり
```

### どちらを使うべきか

```text
  1回きりの読み書きで、次も先頭から使いたい      → /dev/st0
  複数のアーカイブを順に書く / 順に読む          → /dev/nst0
  既存のデータを上書きしたくない                 → /dev/nst0
```

**実務では nst0 を使うのが基本**です。st0 は「自動で先頭に戻る」ため、
意図せず前のバックアップを潰す事故が起きやすいからです。

## mt コマンド

**`mt` はテープの位置を操作するコマンド**です。読み書きそのものは `tar` や `dd` が行い、
`mt` は「どこに頭を置くか」だけを担当します。

```text
mt [-f デバイス] 操作 [回数]
```

**回数を省略すると 1 回**として扱われます。

### この環境で確認できたこと

```bash
$ mt --version | head -1                    # mt の実装を確認する
$ dpkg -S /usr/bin/mt-gnu                   # どのパッケージのものか調べる
```

```text
mt (GNU cpio) 2.15
cpio: /usr/bin/mt-gnu
```

**Ubuntu の `mt` は GNU cpio 付属のもの**でした。
（`mt-st` パッケージを入れると、より多機能な `mt-st` が使えます）

テープ装置が無いため、実際の位置操作は**実測できていません。**

```bash
$ ls -l /dev/st0 /dev/nst0                  # テープデバイスがあるか確認する
$ mt -f /dev/nst0 status                    # 状態を取得してみる
```

```text
ls: cannot access '/dev/st0': No such file or directory
ls: cannot access '/dev/nst0': No such file or directory
mt: /dev/nst0: rmtopen failed: No such file or directory
```

**以下の操作一覧のうち、位置が実際に動く様子は実測できていません。**
ただし**どの操作名を受け付けるか**は実測できます。

### 操作の一覧

GNU cpio 版の `mt` に無効な操作名を渡すと、受け付ける一覧をそのまま出してくれます。

```bash
$ mt -f /dev/null eod                       # eod が使えるか確かめる
```

```text
mt: invalid argument 'eod' for 'operation'
Valid arguments are:
  - 'eof', 'weof'
  - 'fsf'
  - 'bsf'
  - 'fsr'
  - 'bsr'
  - 'rewind'
  - 'offline', 'rewoffl', 'eject'
  - 'status'
  - 'bsfm'
  - 'eom'
  - 'retension'
  - 'erase'
  - 'asf'
  - 'fsfm'
  - 'seek'
```

**`eod` / `seod` は GNU cpio 版の `mt` には存在しません。**
同じことをするのは **`eom`**（end of media）です。
`eod` / `seod` は `mt-st` パッケージ側の名前なので、教材の記述と手元のコマンドが食い違うことがあります。

| 操作 | 意味 | GNU cpio 版 |
|:--|:--|:--|
| `fsf n` | **前へ** n ファイル分送る。次のファイルの先頭に位置する | あり |
| `bsf n` | **後ろへ** n ファイル分戻す。前のファイルの末尾に位置する | あり |
| `fsfm n` | n ファイル進んでから1レコード戻る | あり |
| `bsfm n` | n ファイル戻ってから1レコード進む | あり |
| `fsr n` / `bsr n` | レコード単位で前後に移動する | あり |
| `asf n` | 巻き戻してから n 番目のファイルの先頭へ | あり |
| `rewind` | 先頭まで巻き戻す | あり |
| **`eom`** | **有効データの末尾へ。追記したいときに使う** | **あり** |
| `eod` / `seod` | 同上（`mt-st` での名前） | **なし** |
| `offline` / `rewoffl` / `eject` | 巻き戻してテープを排出する | あり |
| `status` | テープ装置の状態を表示する | あり |
| `erase` | テープを消去する | あり |
| `retension` | 端まで送ってから巻き戻し、テンションを整える | あり |
| `weof n` / `eof n` | 現在位置に EOF マークを n 個書く | あり |

**覚え方**

```text
   f = forward（前へ）      s = space（送る）     f = file（ファイル単位）
   b = backward（後ろへ）

   fsf … Forward Space File  → 前へ送る
   bsf … Backward Space File → 後ろへ戻す
```

### fsf と bsf

man ページの定義はこうです。

| | 定義 | 位置づけ |
|:--|:--|:--|
| `fsf` | Forward space count files. The tape is positioned on the **first block of the next file**. | 次のファイルの**先頭** |
| `bsf` | Backward space count files. The tape is positioned on the **last block of the previous file**. | 前のファイルの**末尾** |

**非対称である点に注意**してください。
`fsf 1` してから `bsf 1` しても、元の位置には戻りません。
`fsf` は「次の先頭」、`bsf` は「前の末尾」に止まるためです。

```bash
$ mt -f /dev/nst0 fsf                       # 1ファイル分 前へ送る（回数省略＝1）
$ mt -f /dev/nst0 fsf 3                     # 3ファイル分 前へ送る
$ mt -f /dev/nst0 bsf 2                     # 2ファイル分 後ろへ戻す
$ mt -f /dev/nst0 rewind                    # 先頭まで巻き戻す
$ mt -f /dev/nst0 eom                       # 有効データの末尾へ（GNU cpio 版。mt-st なら eod）
```

**`mt` に `-f` を付けないと、環境変数 `TAPE` か、コンパイル時の既定デバイスが使われます。**
意図しない装置を操作しないよう、**`-f` は常に明示**してください。

### テープ上のレイアウト

```text
  [BOT]  アーカイブ1  [EOF]  アーカイブ2  [EOF]  アーカイブ3  [EOF][EOF]  [EOT]
    ↑                                                            ↑
  Beginning Of Tape                                    EOF 2つ連続 = データの終わり

  ── fsf 1 ──▶  ここ（アーカイブ2の先頭）
  ◀── bsf 1 ──  ここ（アーカイブ1の末尾）
```

**アーカイブとアーカイブの区切りが EOF マーク**です。
`fsf` / `bsf` はこの EOF を数えて移動します。

## tar でテープに書く

テープは「大きな1本のファイル」のように見えるので、`tar` の `-f` にそのまま指定できます。

```bash
$ tar cvf /dev/nst0 /home                   # /home をテープに書く（巻き戻さない）
$ tar tvf /dev/nst0                         # テープの中身を一覧する
$ tar xvf /dev/nst0                         # テープから展開する
```

**テープに書くときは圧縮オプションを付けないのが定石**です。

```text
   理由1  LTO ドライブは装置側でハードウェア圧縮を行う（二重圧縮は無駄）
   理由2  圧縮すると、途中のビット欠損で以降が全滅しうる
```

Red Hat のドキュメントでは `tar -czf /dev/st0 ...` という例も示されていますが、
**LTO のハードウェア圧縮が効く環境では `-z` を外す**ほうが一般的です。

## 同じコマンドを2回実行するとどうなるか

**`/dev/nst0` は巻き戻らない**ので、同じ展開コマンドを繰り返すと**次のアーカイブが出てきます。**

```text
  [BOT] アーカイブ1 [EOF] アーカイブ2 [EOF] ...
          ↑
  1回目: tar xf /dev/nst0  →  アーカイブ1 を展開。頭は EOF の先へ進む
          ────────────────▶ ↑
  2回目: tar xf /dev/nst0  →  アーカイブ2 を展開（同じディレクトリに）
```

このとき、展開先で起きることは次のとおりです。

| アーカイブ2に入っているもの | 結果 |
|:--|:--|
| アーカイブ1と**同名**のファイル | **上書きされる** |
| アーカイブ1に**無い**ファイル | 追加される |
| アーカイブ1にあって2に無いファイル | そのまま残る |

**つまり「2つのアーカイブが混ざった状態」になります。**
分けて取り出したいなら、展開先を変えるか `-C` で切り替えてください。

```bash
$ tar xf /dev/nst0 -C /restore/1            # 1本目を /restore/1 へ
$ tar xf /dev/nst0 -C /restore/2            # 2本目を /restore/2 へ（頭は進んでいる）
```

**`/dev/st0` で同じことをすると、毎回巻き戻るので何度やってもアーカイブ1が出てきます。**
「2回目が出てこない」ときは、まずデバイス名の `n` を確認してください。
