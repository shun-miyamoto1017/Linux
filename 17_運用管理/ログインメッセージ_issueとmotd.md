## 三つのファイルの違い

| ファイル | 表示されるタイミング | 見える相手 |
|:--|:--|:--|
| **`/etc/issue`** | ログインプロンプトの**手前** | **まだログインしていない人**（誰でも） |
| **`/etc/issue.net`** | **ネットワーク越し**のログインプロンプトの手前 | まだログインしていない人 |
| **`/etc/motd`** | ログインに**成功した後** | **正規のユーザだけ** |

**motd** = **M**essage **O**f **T**he **D**ay（今日のお知らせ）。

---

## タイミングで覚える

```text
  [コンソールに向かう]
        │
        ▼
  ┌─────────────────────────┐
  │  /etc/issue の内容       │  ← ★ ログインしていなくても見える
  └─────────────────────────┘
  vm login: _                    ← ログインプロンプト
  Password: _
        │
        ▼  （認証成功）
  ┌─────────────────────────┐
  │  /etc/motd の内容        │  ← ★ 認証を通った人だけが見る
  └─────────────────────────┘
  $ _                            ← シェルのプロンプト
```

**この順番がそのまま「誰に見せてよい情報か」を決めます。**

```text
   /etc/issue … 攻撃者にも見える  → 機密は絶対に書かない
   /etc/motd  … 正規ユーザのみ    → 運用上の注意事項を書いてよい
```

## etc-issue ログインプロンプトの前

コンソール（仮想端末）でログインプロンプトを出しているのは **`agetty`** です。
`agetty` が `/etc/issue` を読んで表示します。

この環境の初期状態を見てみます。

```bash
$ cat -A /etc/issue                         # 制御文字も見える形で表示する
```

```text
Ubuntu 24.04.4 LTS \n \l$
$
```

`\n` と `\l` が**エスケープシーケンス**です。そのまま文字として出るのではなく、
`agetty` が実行時に値へ置き換えます。

### エスケープシーケンス

**`/etc/issue` の中でだけ意味を持つ記法**です。シェルのエスケープとは別物です。

### 実際に展開してみる

`agetty --show-issue` で、展開後の内容だけを確認できます。

```bash
$ cat /etc/issue                            # 書いた内容を確認する
```

```text
ホスト名=\n  OS=\s \r  端末=\l  時刻=\t  日付=\d
ユーザ数=\U  ドメイン=\O
```

```bash
$ agetty --show-issue                       # 展開結果だけを表示する
```

```text
ホスト名=vm  OS=Linux 6.18.44-fc-v37  端末=tty1  時刻=14:55:51  日付=Wed Sep 23  2026
ユーザ数=2 users  ドメイン=unknown_domain
```

**`\n` がホスト名に、`\s \r` がカーネル名とリリースに、`\l` が端末名に置き換わっています。**

> **注意** … `\n` は「改行」ではなく**ノード名（ホスト名）**です。
> シェルの `echo -e "\n"` とはまったく別の意味になります。ここは間違えやすいところです。
>
> **`\v` も紛らわしい**記法です。「OS のバージョン」ではなく **`uname -v` 相当のカーネルビルド情報**で、
> 実測では `#1 SMP PREEMPT_DYNAMIC @0` が出ました。
> ディストリ名を出したいときは `\S`（`/etc/os-release` の値）を使います。

### 一覧

| 記法 | 置き換わるもの | 上の実測での値 |
|:--|:--|:--|
| `\n` | **ノード名（ホスト名）** | `vm` |
| `\s` | OS の名前 | `Linux` |
| `\r` | カーネルのリリース | `6.18.44-fc-v37` |
| `\l` | 端末（tty）の名前 | `tty1` |
| `\t` | 現在時刻 | `14:55:51` |
| `\d` | 現在の日付 | `Wed Sep 23  2026` |
| `\U` | ログイン中のユーザ数 | `2 users` |
| `\O` | ドメイン名 | `unknown_domain` |
| `\m` | マシンのアーキテクチャ | `x86_64` |
| `\v` | **カーネルのビルド情報**（`uname -v` 相当） | `#1 SMP PREEMPT_DYNAMIC @0` |
| `\S` | `/etc/os-release` の値（ディストリ名など） | — |

**覚え方**

```text
   \n = node name（ノード名）… 改行ではない
   \l = line（回線 = 端末名）
   \s = system（OS 名）
   \r = release（カーネルのリリース）
```

## etc-issue-net リモートからの接続

**ネットワーク越しのログイン**で表示されるのが `/etc/issue.net` です。

```bash
$ cat /etc/issue.net                        # リモート用のバナーを確認する
```

```text
Ubuntu 24.04.4 LTS
```

`/etc/issue` と違い、**エスケープシーケンスが書かれていません。**
リモートから見せる情報は最小限にする、という配慮です。

| | `/etc/issue` | `/etc/issue.net` |
|:--|:--|:--|
| 表示する主体 | `agetty`（ローカルのコンソール） | `telnetd` など。**ssh は `Banner` 設定が必要** |
| エスケープ | 展開される | 展開のされ方が実装依存 |
| 見せる相手 | 物理的にコンソールの前にいる人 | **ネットワーク上の誰でも** |

**ssh の場合は自動では読まれません。** `sshd_config` で明示します。

```text
Banner /etc/issue.net
```

```bash
$ grep -i '^Banner' /etc/ssh/sshd_config    # バナー設定を確認する
```

> **実測できていないこと** … この環境には sshd も telnetd も入っていないため、
> リモート接続時に `/etc/issue.net` が表示される様子は確認していません。

## etc-motd ログインに成功した後

**認証を通ったユーザだけ**に表示されます。
ファイルの中身がそのまま出るだけで、**エスケープシーケンスは展開されません。**

```bash
$ cat /etc/motd                             # 内容を確認する
```

この検証環境では、`/etc/motd` は**存在しませんでした**。

```text
cat: /etc/motd: No such file or directory
```

**無くてもエラーにはなりません。** 何も表示されないだけです。

### Ubuntu の動的 motd

**Ubuntu では motd を動的に生成する仕組み**（`pam_motd`）が入っています。

```bash
$ ls /etc/update-motd.d/                    # 生成スクリプトの一覧を見る
```

```text
00-header
10-help-text
50-motd-news
```

**`/etc/update-motd.d/` のスクリプトが番号順に実行され、その出力が motd になります。**

```text
   /etc/motd              … 静的な内容（自分で書く）
   /etc/update-motd.d/*   … 実行されて動的に生成される
   /run/motd.dynamic      … 生成結果のキャッシュ
```

**ログイン時の「パッケージが N 個更新できます」という表示はこれ**です。
消したい場合はスクリプトの実行権を外します。

```bash
$ chmod -x /etc/update-motd.d/50-motd-news  # ニュース表示を止める
```

> **実測できていないこと** … このコンテナではログインセッションを張っていないため、
> `/run/motd.dynamic` は生成されていませんでした（`ls` でファイルなし）。

## 何を書いてよくて何を書いてはいけないか

**`/etc/issue` と `/etc/issue.net` は、ログインしていない相手に見えます。**

**書いてはいけないもの**

```text
  ✗ OS の詳細バージョン        → 既知の脆弱性を教えることになる
  ✗ カーネルのリリース番号      → 同上
  ✗ ホスト名・ドメイン名        → 内部構成の手がかりになる
  ✗ 管理者の氏名・連絡先        → ソーシャルエンジニアリングの材料
  ✗ 「ようこそ」               → 不正アクセスの訴追で不利に働くという議論がある
```

**既定の `Ubuntu 24.04.4 LTS \n \l` は、実はこの観点では好ましくありません。**
OS のバージョンとホスト名を、認証前の相手に教えています。
セキュリティ要件のある環境では、次のように差し替えます。

```text
Authorized access only. All activity is monitored and logged.
Disconnect immediately if you are not an authorized user.
```

**`/etc/motd` には運用情報を書いてよい**です。認証を通った人しか見ないからです。

```text
  ○ 環境名（本番 / ステージング / 検証）
  ○ 次回メンテナンス予定
  ○ 問い合わせ先（社内の窓口）
  ○ この機での作業ルール
```

## 実務での書き方

**踏み台から複数環境に入る運用の例**

`/etc/motd` に環境名を大書きします。

```text
============================================================
   ██  PRODUCTION  ██     www-prod-01
------------------------------------------------------------
   この機は本番環境です。変更前に必ず変更申請番号を確認。
   次回メンテナンス: 2026-10-05 02:00-05:00 JST
   問い合わせ: infra-team (社内チャット #infra)
============================================================
```

**検証環境は別の文字で色分け**しておくと、視覚的に間違えません。

`/etc/issue` と `/etc/issue.net` には、共通の警告文だけを置きます。

```bash
$ echo "Authorized access only. All activity is monitored and logged." > /etc/issue   # 警告文を書く
$ cp /etc/issue /etc/issue.net              # リモート用にも同じ内容を置く
```

**変更後の確認手順**

```bash
$ agetty --show-issue                       # issue の展開結果を確認する
$ cat /etc/motd                             # motd の内容を確認する
```

`/etc/motd` はログインし直さないと見えないので、**別セッションを張って確認**してください。

**Ansible で配るなら**、`/etc/motd` をテンプレートにして環境変数を埋め込むのが定番です。
環境名を変数にしておけば、同じ Playbook で全環境に正しい表示を配れます。
