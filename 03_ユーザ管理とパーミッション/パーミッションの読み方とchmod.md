## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| **権限を見る** | **`ls -l ファイル`** ／ ディレクトリ自身なら **`ls -ld ディレクトリ`** |
| **数値で設定する** | **`chmod 755 file`** |
| **権限を足す・引く** | **`chmod u+x file`** ／ **`chmod g-w file`** |
| **ちょうどこの権限にする** | **`chmod u=rwx,go=rx file`** |
| **配下もまとめて変える** | **`chmod -R 755 dir`** |

**数値の作り方**

```text
 r = 4     w = 2     x = 1        （足し算するだけ）

 rwx = 4+2+1 = 7      r-x = 4+0+1 = 5      rw- = 4+2+0 = 6

 755  =  rwx  r-x  r-x
          │    │    │
        所有  所有  その他
        ユーザ グループ
```

**外しやすい 3 点**

| 論点 | 結論 |
|:--|:--|
| **ディレクトリの `x`** | **「実行」ではなく「中に入れる・中のファイルに手が届く」**。`x` が無いと `cd` できない |
| **ディレクトリの `w`** | **中のファイルを作成・削除・改名できる。**ファイルの所有者が誰かは関係ない |
| **`chmod` を使えるのは誰か** | **そのファイルの所有ユーザ**（と root）だけ。**グループが同じでも他人のファイルは変えられない** |

## ls -l の 8 項目

**`ls -l` の 1 行には、8 つの情報が並んでいます。**
どれがどれか分かると、権限のトラブルはほぼ読むだけで切り分けられます。

```bash
$ ls -l /etc/passwd                  # ファイルの詳細を表示する
-rw-r--r--. 1 root root 1929 Jan 18 14:17 /etc/passwd
```

```text
 -rw-r--r--.   1  root  root  1929  Jan 18 14:17  /etc/passwd
 │└───┬───┘   │   │     │      │         │             │
(1)  (2)     (3) (4)   (5)    (6)       (7)           (8)
```

| # | 項目 | 内容 |
|:-:|:--|:--|
| **(1)** | **ファイルの種別** | **`-` はファイル、`d` はディレクトリ、`l` はシンボリックリンク** |
| **(2)** | **パーミッション** | **`r` `w` `x` `-` を使って 9 文字**で表す（次の節） |
| **(3)** | **ハードリンクの数** | そのファイル実体を指している名前の数 |
| **(4)** | **所有ユーザ** | このファイルを所有しているユーザ |
| **(5)** | **所有グループ** | このファイルを所有しているグループ |
| **(6)** | **ファイルサイズ** | バイト数 |
| **(7)** | **最終編集日付** | 中身を最後に変更した時刻 |
| **(8)** | **ファイル名** | — |

**例文** … `/etc/passwd` から読み取れること

```bash
$ ls -l /etc/passwd                  # 標準の権限と所有者を確認する
-rw-r--r--. 1 root root 1929 Jan 18 14:17 /etc/passwd
```

| 読み取れること | 根拠 |
|:--|:--|
| **所有ユーザも所有グループも `root`** | (4) と (5) がどちらも `root` |
| **root は読み書きできる** | 所有ユーザの欄が `rw-` |
| **root 以外は読むだけ** | 所有グループとその他の欄が `r--` |

> **`/etc/passwd` は `-rw-r--r--` で所有者が `root`、これが標準**です。
> **`sys` というユーザやグループは、必ず存在するものではありません。**

**補足 … 末尾の `.` は何か**

`-rw-r--r--.` の**末尾の `.`** は、**SELinux のセキュリティコンテキストが付いている**という印です。
RHEL 系でよく見かけます。`+` になっていれば **ACL（拡張された権限設定）** が付いています。

```bash
$ ls -l file                         # 末尾の記号を見る
-rw-r--r--. 1 root root 0 Sep 14 01:00 file     # . … SELinux のラベルあり
-rw-rw-r--+ 1 root root 0 Sep 14 01:00 file2    # + … ACL あり
```

**ファイルの種別を表す記号**は
[01_シェルとコマンドライン / ファイルとディレクトリの操作](../01_シェルとコマンドライン/ファイルとディレクトリの操作.md)
の「ファイルの種類を記号で見分ける」に一覧があります。

## パーミッションの 9 文字を読む

**パーミッションは `r` `w` `x` および `-` を使って 9 文字で表します。**
**3 文字ずつ、3 つのクラスに分かれています。**

```text
 rwx  r-x  r--
 └┬┘  └┬┘  └┬┘
所有  所有   その他
ユーザ グループ
```

| クラス | 所有ユーザ | 所有グループ | その他 |
|:--|:-:|:-:|:-:|
| **記号** | `r` `w` `x` | `r` `w` `x` | `r` `w` `x` |
| **数値** | **4 2 1** | **4 2 1** | **4 2 1** |
| **権限** | 読み／書き／実行 | 読み／書き／実行 | 読み／書き／実行 |

**`-` は、その権限が無い場合に使われます。**

**どのクラスが適用されるか**

```text
そのファイルの所有ユーザ本人             → 所有ユーザの 3 文字
所有グループに所属しているユーザ          → 所有グループの 3 文字
どちらでもないユーザ                    → その他の 3 文字
```

**上から順に 1 つだけ**が適用されます。
所有ユーザ本人なら、**グループやその他の欄がどれだけ緩くても、所有ユーザの欄しか見られません**。

```bash
$ ls -l report.txt                   # 所有ユーザは自分（shun）
-r--rw-rw- 1 shun staff 0 Sep 14 01:00 report.txt

$ echo x >> report.txt               # 書き込めない
bash: report.txt: 許可がありません
```

**グループやその他に `w` があっても、所有ユーザ本人には `r--` しか効きません。**
「自分のファイルなのに書けない」の正体はこれです。

## ファイルとディレクトリで意味が変わる

**ここが最大のつまずきどころです。**
**同じ `r` `w` `x` でも、ファイルに付けた場合とディレクトリに付けた場合で、許可される内容が違います。**

| 権限 | **ファイル**に適用した場合 | **ディレクトリ**に適用した場合 |
|:--|:--|:--|
| **読み `r`** | **ファイルの内容を参照**（`cat` / `more` など） | **ディレクトリ内の一覧を参照**（`ls` / `find` など） |
| **書き `w`** | **ファイルに書き込み**（`vi` など） | **ディレクトリ内に新規ファイルの作成／既存ファイルの名前変更や削除**（`touch` / `mv` / `rm` など） |
| **実行 `x`** | **ファイルを実行** | **ディレクトリ内のファイルへのアクセス／ディレクトリへの移動**（`cd`） |

**覚え方**

```text
ディレクトリは「ファイル名の一覧表」だと思うと分かりやすい。

 r … 一覧表を読める          → ls できる
 w … 一覧表を書き換えられる  → 作成・削除・改名できる
 x … 一覧表の先へ通れる      → cd できる、中のファイルを開ける
```

**例文** … 権限の違いで何ができるかを見る

```bash
$ ls -l                              # dir1 は全部あり、dir2 は読みだけ
合計 8
drwxrwxr-x. 3 test test 4096  6月  1 15:20 dir1
dr--r--r--. 3 test test 4096  6月  1 14:06 dir2

$ cd dir1                            # x があるので入れる
$ mkdir newdir                       # w があるので作れる
$ ls                                 # r があるので一覧が見える
file1.txt  file2.txt  newdir  subdir1

$ cd ../dir2                         # x が無いので入れない
bash: cd: ../dir2: 許可がありません
```

**補足 … `r` だけのディレクトリは「名前は見えるが中身は開けない」**

`r` があって `x` が無いディレクトリは、**`ls` で名前は出るのに、そのファイルを開けません**。

```bash
$ ls dir2                            # 名前の一覧は見える
file1.txt
$ cat dir2/file1.txt                 # 中には手が届かない
cat: dir2/file1.txt: 許可がありません
```

**補足 … `w` だけでは削除できない、が正確には逆**

**ファイルを削除できるかどうかを決めるのは、そのファイルの権限ではなく、
「そのファイルが入っているディレクトリ」の `w` 権限**です。
読み取り専用のファイルでも、**ディレクトリに `w` があれば消せてしまいます**。

これを防ぐのが**スティッキービット**です
（→ [SGID（特殊パーミッション）](./SGID_特殊パーミッション.md)）。

## chmod コマンド

**`chmod` は、ファイルやディレクトリのパーミッションを変更するコマンド**です。
名前は **ch**ange **mod**e から来ています。

```text
chmod [-R] パーミッション ファイルまたはディレクトリ
```

**パーミッションの指定には、数値か記号のどちらかを用います。**

> **`chmod` でパーミッションを変更できるのは、コマンドを実行するユーザが所有するファイルやディレクトリだけ**です
> （ただし root は除きます）。**同じグループに属しているだけでは変更できません。**

**存在しないコマンド名に注意**

| 名前 | 実在するか |
|:--|:--|
| **`chmod`** | **する。パーミッションを変更する** |
| `chown` | する。**所有ユーザ**（とグループ）を変更する |
| `chgrp` | する。**所有グループ**を変更する |
| `chmode` / `chpermit` / `chmask` / `chowner` / `chgroup` | **すべて存在しない** |

### 数値で指定する

**意味** … 3 桁（または 4 桁）の数値で、**3 つのクラスの権限をまとめて指定する**

**例文** … `file.txt` のパーミッションを 755 に変更する

```bash
$ ls -l file.txt                     # 変更前は 664
-rw-rw-r--. 1 test test 0 3月 14 23:19 file.txt

$ chmod 755 file.txt                 # 755 に設定する
$ ls -l file.txt                     # rwxr-xr-x になった
-rwxr-xr-x. 1 test test 0 3月 14 23:19 file.txt
```

**よく使う値**

| 数値 | 記号 | どんなときに使うか |
|:--|:--|:--|
| **`755`** | `rwxr-xr-x` | **実行ファイル、ディレクトリ**の標準 |
| **`644`** | `rw-r--r--` | **一般的なファイル**の標準 |
| **`700`** | `rwx------` | **自分だけが使うディレクトリ**（`~/.ssh` など） |
| **`600`** | `rw-------` | **秘密鍵・パスワードを含む設定ファイル** |
| `775` | `rwxrwxr-x` | グループで共有するディレクトリ |
| `666` | `rw-rw-rw-` | 全員が読み書き（**基本は避ける**） |
| `777` | `rwxrwxrwx` | 全員が何でもできる（**本番では使わない**） |

**補足 … 数値は「足し算」で作ります**

```text
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2     = 6
r-x = 4     + 1 = 5
r-- = 4         = 4
```

**補足 … 4 桁目は特殊パーミッションです**

`chmod 4755` のように先頭にもう 1 桁付けると、SUID（4）／SGID（2）／スティッキービット（1）を設定します。
→ [SGID（特殊パーミッション）](./SGID_特殊パーミッション.md)

### 記号で指定する

**意味** … **「誰に」「どうする」「何を」** の 3 つを記号で書く

```text
chmod  u  +  x  file
       │  │  │
      対象 操作 権限
```

**対象**

| 記号 | 意味 |
|:--|:--|
| **`u`** | **所有者**（user） |
| **`g`** | **所有グループ**（group） |
| **`o`** | **その他ユーザ**（others） |
| **`a`** | **全てのユーザ**（all）。省略時も `a` と同じ |

**操作**

| 記号 | 意味 |
|:--|:--|
| **`+`** | **権限を追加**する |
| **`-`** | **権限を削除**する |
| **`=`** | **権限を指定**する（**書いた権限だけにする。それ以外は消える**） |

**権限**

| 記号 | 意味 |
|:--|:--|
| **`r`** | 読み取り権 |
| **`w`** | 書き込み権 |
| **`x`** | 実行権 |
| **`s`** | **SUID または SGID** |
| **`t`** | **スティッキービット** |

**対象、操作、権限の順に指定します。また `,` を使用して繰り返すこともできます。**

**例文** … `dir` のパーミッションを 700 から 500 に変更する

```bash
$ chmod 500 dir                      # ① 数値で設定する
$ chmod u-w dir                      # ② 所有ユーザから w を削除する（700 → 500）
$ chmod u=rx dir                     # ③ 所有ユーザを rx だけにする（結果は同じ）
```

**3 つとも同じ結果になります。** 考え方が違うだけです。

| 書き方 | 考え方 |
|:--|:--|
| **`chmod 500 dir`** | **最終形を数値で言う** |
| **`chmod u-w dir`** | **700 から 2（＝ `w`）を引く**、と考える |
| **`chmod u=rx dir`** | **所有ユーザは `r` と `x` だけ**、と言い切る |

**例文** … 755 を記号で表す

```bash
$ chmod u=rwx,go=rx dir              # 所有ユーザは rwx、グループとその他は rx
$ chmod a=rwx,go-w dir               # 一旦全員 rwx（777）にしてから、go の w を削る
```

**どちらも 755 になります。** `,` で区切って続けて書けるのがポイントです。

**補足 … `+` と `=` の違いに注意**

```bash
$ chmod u+x file                     # いまの権限に x を足す（他は変わらない）
$ chmod u=x file                     # x だけにする（r と w は消える）
```

**`=` は「指定」なので、書かなかった権限は消えます。**

### -R で配下もまとめて変える

**意味** … **`-R` オプションを使用すると、指定したディレクトリおよびその配下にあるファイルのパーミッションを変更できます**

**例文** … `dir` とその配下を 755 にする

```bash
$ chmod -R 755 dir                   # dir 自身と、中のすべてを 755 にする
$ chmod -R u=rwx,go=rx dir           # 記号でも同じ
```

**`-R` を付けないと、指定したディレクトリ自身だけ**が変わります。

```bash
$ chmod 755 dir                      # dir だけ。中のファイルは変わらない
```

**注意 … `-R` で 755 を配るのは危険なことがあります**

**ファイルにも一律で `x`（実行権）が付いてしまう**ためです。
テキストや設定ファイルに実行権が付くのは望ましくありません。

```bash
$ chmod -R u=rwX,go=rX dir           # 大文字の X なら「ディレクトリと、元々実行権のあるファイル」だけに x を付ける
```

**大文字の `X`** は、**ディレクトリか、すでにどれかのクラスに `x` があるファイル**にだけ `x` を付けます。
`-R` と組み合わせるときの定番です。

## よく使うオプション

| オプション | 意味 | 使いどころ |
|:--|:--|:--|
| **`-R`** ／ `--recursive` | **ディレクトリ配下も再帰的に変更する** | ディレクトリごと権限を揃える |
| **`-v`** ／ `--verbose` | **変更したものをすべて表示する** | `-R` のときに何が変わったかを確認する |
| **`-c`** ／ `--changes` | **実際に変わったものだけ表示する** | `-v` よりログが短くて見やすい |
| `-f` ／ `--silent` | エラーを表示しない | スクリプトで失敗を無視したいとき |
| **`--reference=別ファイル`** | **別のファイルと同じ権限にする** | 「このファイルと同じにして」が一発で済む |
| `--preserve-root` | `/` への `-R` を拒否する | 事故防止（多くの環境で既定） |

```bash
$ chmod -c 644 *.conf                # 実際に変わったファイルだけ出す
mode of 'app.conf' changed from 0664 (rw-rw-r--) to 0644 (rw-r--r--)

$ chmod --reference=good.conf bad.conf   # good.conf と同じ権限にする
$ chmod -R -v 755 dir | tail -5      # 再帰実行の結果を確認する
```

## 結果画面の見方

**`chmod -v` の出力**

```bash
$ chmod -v 644 app.conf              # 変更内容を表示する
mode of 'app.conf' changed from 0664 (rw-rw-r--) to 0644 (rw-r--r--)
      │             │        │              │
    (1)           (2)      (3)            (4)
```

| # | 見えるもの | 意味 |
|:-:|:--|:--|
| **(1)** | 対象のファイル名 | どのファイルの話か |
| **(2)** | **`changed` / `retained`** | **`retained` なら「元から同じで、変わっていない」** |
| **(3)** | **変更前の 4 桁と記号** | 先頭の桁は特殊パーミッション |
| **(4)** | **変更後の 4 桁と記号** | ここが狙いどおりか確認する |

**`ls -l` で確認する**

```bash
$ ls -l app.conf                     # 結果を見る
-rw-r--r--. 1 app app 512 Sep 14 01:00 app.conf
 ││└┬┘└┬┘└┬┘
 ││ │  │  └─ その他        … r--（読むだけ）
 ││ │  └──── 所有グループ   … r--（読むだけ）
 ││ └─────── 所有ユーザ     … rw-（読み書き）
 │└────────── 種別          … -（通常ファイル）
 └─────────── 先頭の文字が d ならディレクトリ
```

**数値で確認したいとき**

```bash
$ stat -c '%a %n' app.conf           # 数値だけを表示する
644 app.conf

$ stat -c '%A %a %U %G %n' app.conf  # 記号・数値・所有者・グループをまとめて
-rw-r--r-- 644 app app app.conf
```

**`stat` は「見たい項目だけ取り出せる」**ので、スクリプトでの確認に向きます。

## 間違えやすい書き方

| 書き方 | どこが誤りか |
|:--|:--|
| **`chmod -R +755 dir`** | **`+755` は「現在の権限に 755 を足す」という意味**。書式としては通るが、**755 に設定はされない** |
| `chmod 755 dir`（配下も変えたい場合） | **`-R` が無い**ので `dir` 自身しか変わらない |
| `chmod u=rwx,go=rx dir`（配下も変えたい場合） | 同上。**記号でも `-R` は必要** |
| **`chmode` / `chpermit`** | **存在しないコマンド** |
| `chmod 755` のつもりで `chmod 0755` | **これは正しい**（4 桁目の `0` は「特殊パーミッションなし」） |
| 他人のファイルに `chmod` | **所有ユーザ（と root）しか変更できない** |

**`+755` が誤りである理由**

```text
chmod +755 file   →  「全クラスに 755 という権限を追加する」の意味になる
                     すでにある権限は消えないので、755 ちょうどにはならない

chmod 755 file    →  「755 に設定する」
```

**「設定」したいときは数値をそのまま書く**か、記号なら **`=`** を使います。

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| **`Permission denied` で `cd` できない** | ディレクトリに **`x` が無い** | `ls -ld` で確認し、`chmod u+x` |
| `ls` はできるのにファイルを開けない | ディレクトリに `r` はあるが **`x` が無い** | `chmod u+x ディレクトリ` |
| 自分のファイルなのに書き込めない | **所有ユーザの欄**が `r--` になっている | 適用されるのは 1 クラスだけ。`chmod u+w` |
| 他人のファイルの権限を変えられない | `chmod` は**所有ユーザと root だけ** | 所有者に頼むか、`sudo` |
| `chmod -R 755` したらテキストも実行可能になった | **`-R` は一律に適用される** | **`chmod -R u=rwX,go=rX`**（大文字 `X`） |
| `chmod u=x` したら読めなくなった | **`=` は「指定」。書かない権限は消える** | 足すだけなら `+` を使う |
| `chmod +755` で 755 にならない | **`+` は追加の意味** | 数値をそのまま `chmod 755` |
| 権限は合っているのに拒否される | **SELinux** か **ACL** の可能性がある（`.` や `+` が付いている） | `ls -l` の末尾記号を見る。`getfacl` / `ls -Z` |
| `-rw-r--r--.` の `.` が気になる | **SELinux のラベル**が付いている印 | 権限そのものとは別物 |

## クラウド実務メモ

**SSH の秘密鍵は `600` でないと使えない**

権限が緩いと **SSH が鍵を読み込まず、接続できません**。EC2 でいちばん多いつまずきです。

```bash
$ chmod 600 ~/.ssh/my-key.pem        # 所有ユーザだけが読み書きできる状態にする
$ chmod 700 ~/.ssh                   # ディレクトリ自体も自分だけに
$ ssh -i ~/.ssh/my-key.pem ec2-user@203.0.113.10   # これで接続できる
```

```text
Permissions 0644 for 'my-key.pem' are too open.   ← 権限が緩すぎるときのエラー
```

**Windows からコピーした鍵は、ほぼ必ず権限が緩くなっています。**

**`authorized_keys` は `600`、`~/.ssh` は `700`**

ここが緩いと、**サーバ側が公開鍵を無視して**パスワード認証に落ちます。

```bash
$ ls -ld ~/.ssh                      # 700 であることを確認する
drwx------. 2 ec2-user ec2-user 29 Sep 14 01:00 /home/ec2-user/.ssh
$ ls -l ~/.ssh/authorized_keys       # 600 であることを確認する
-rw-------. 1 ec2-user ec2-user 389 Sep 14 01:00 /home/ec2-user/.ssh/authorized_keys
```

**`chmod -R 777` は原因調査を止める最悪手**

「権限で失敗する → とりあえず 777」は、**原因が分からなくなるうえにセキュリティ事故になります**。
`ls -ld` で 1 階層ずつたどれば、どこで止まっているかは必ず分かります。

```bash
$ namei -l /data/app/config.yml      # パスの各階層の権限をまとめて表示する
f: /data/app/config.yml
 drwxr-xr-x root root /
 drwxr-x--- root root data          ← ここで止まっている
```

**`namei -l` は「どの階層で権限が足りないか」を一発で見せてくれます。**

**コンテナイメージでの注意**

`COPY` したファイルの権限は**ビルド環境のものが引き継がれます**。
Windows やネットワークドライブでビルドすると、意図しない権限になることがあります。

```dockerfile
COPY --chmod=755 entrypoint.sh /usr/local/bin/
```

**`--chmod` を付けて明示**するのが確実です。

**IaC では権限も宣言する**

```hcl
resource "local_file" "conf" {
  filename        = "/etc/app/app.conf"
  content         = "..."
  file_permission = "0644"        # 明示しないと環境の umask に左右される
}
```

Ansible なら `mode: '0644'` を必ず書きます。**書かないと `umask` 依存**になります
（→ [所有権とumask](./所有権とumask.md)）。
