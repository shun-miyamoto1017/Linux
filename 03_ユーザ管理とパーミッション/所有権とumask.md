## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| **所有ユーザを変える** | **`chown staff file.txt`** |
| **所有グループだけを変える** | **`chgrp staffgroup file.txt`** ／ **`chown :staffgroup file.txt`** |
| **両方いっぺんに変える** | **`chown staff:staffgroup file.txt`** |
| **配下もまとめて変える** | **`chown -R staff:staffgroup dir`** |
| **既定パーミッションを見る** | **`umask`**（引数なし） |
| **既定パーミッションを変える** | **`umask 027`** |

**3 つのコマンドの役割**

```text
chmod … 権限（rwx）を変える
chown … 所有ユーザ（と、ついでに所有グループ）を変える
chgrp … 所有グループ「だけ」を変える
umask … これから作るものの既定値を決める
```

**外しやすい 3 点**

| 論点 | 結論 |
|:--|:--|
| **`chgrp` にコロンは付けない** | **`chgrp -R :group dir` は書式の誤り。**コロンは `chown` の書式 |
| **umask は「引き算」ではない** | **`6(rw) - 3(wx)` は `4(r)`。**`3` にはならず、**マイナスにもならない** |
| **ファイルとディレクトリで初期値が違う** | **ファイルは 666、ディレクトリは 777**。だから同じ umask でも結果が違う |

## 所有ユーザと所有グループ

**ファイルやディレクトリには、必ず「所有ユーザ」と「所有グループ」が 1 つずつ設定されています。**

```bash
$ ls -l file.txt                     # 所有者を確認する
-rw-rw-r--. 1 test staff 0 3月 14 21:55 file.txt
                  │    │
              所有ユーザ 所有グループ
```

**なぜ 2 つあるのか**

パーミッションが **所有ユーザ／所有グループ／その他** の 3 クラスに分かれているためです。
**「誰が所有ユーザか」「どのグループが所有グループか」で、どのクラスの権限が適用されるかが決まります。**

```text
 file.txt   所有ユーザ test   所有グループ staff   権限 rw-rw-r--

  test がアクセス           → rw-   （所有ユーザの欄）
  staff に所属するユーザ     → rw-   （所有グループの欄）
  それ以外                  → r--   （その他の欄）
```

**所有者を変えるということは、「誰にどのクラスが当たるか」を変える**ということです。

## chown コマンド

**`chown` は、指定したファイルまたはディレクトリの所有ユーザやグループを変更するコマンド**です。
名前は **ch**ange **own**er から来ています。

```text
chown [-R] ユーザ名              ファイルまたはディレクトリ
chown [-R] ユーザ名:グループ名    ファイルまたはディレクトリ
chown [-R] :グループ名           ファイルまたはディレクトリ
```

> **所有ユーザを変更できるのは root ユーザのみ**です。
> 一般ユーザは、自分のファイルであっても**他人に譲渡できません**（誰のものか分からなくなるのを防ぐため）。

**例文** … `file.txt` の所有ユーザを `test` から `staff` に変更する

```bash
$ ls -l                              # 変更前
-rw-rw-r--. 1 test test 0 3月 13 05:36 file.txt

$ sudo chown staff file.txt          # 所有ユーザを staff にする
$ ls -l                              # 所有ユーザだけが変わった
-rw-rw-r--. 1 staff test 0 3月 13 05:36 file.txt
```

**例文** … 所有ユーザと所有グループを同時に変更する

```bash
$ sudo chown staff:staffgroup file.txt   # ユーザ名:グループ名 の形で書く
$ ls -l                                  # 両方が変わったことを確認する
-rw-rw-r--. 1 staff staffgroup 0 3月 14 21:18 file.txt
```

**補足 … `:` の部分は `.` としても同じです**

```bash
$ sudo chown staff:staffgroup file.txt   # コロン
$ sudo chown staff.staffgroup file.txt   # ドット。結果は同じ
```

**ドットはユーザ名に `.` が使える環境で紛らわしいため、実務ではコロンを使います。**

**例文** … 所有グループだけを変更する（ユーザ名を省く）

```bash
$ chown :staffgroup file.txt         # 先頭にコロンを置くとグループだけ変わる
$ chown .staffgroup file.txt         # ドットでも同じ
```

**ユーザが所属しているグループであれば、一般ユーザでも変更できます。**
自分のファイルを、自分が入っているグループに移すだけなら `sudo` は要りません。

**例文** … `-R` で配下もまとめて変更する

```bash
$ sudo chown -R staff:staffgroup dir     # dir と配下すべてを変更する
$ ls -lR dir                             # 結果を確認する
```

**`-R` を付けないと、指定したディレクトリ自身だけ**が変わります。中のファイルは元のままです。

## chgrp コマンド

**`chgrp` は、指定したファイルまたはディレクトリの所有グループ「のみ」を変更するコマンド**です。
名前は **ch**ange **gr**ou**p** から来ています。

```text
chgrp [-R] グループ名 ファイルまたはディレクトリ
```

> **`chgrp` にコロンは付けません。** グループ名をそのまま書きます。

**例文** … `file.txt` の所有グループを `test` から `staffgroup` に変更する

```bash
$ ls -l                              # 変更前
-rw-rw-r--. 1 test test 0 3月 14 21:55 file.txt

$ chgrp staffgroup file.txt          # 所有グループを変更する
$ ls -l                              # グループだけが変わった
-rw-rw-r--. 1 test staffgroup 0 3月 14 21:55 file.txt
```

**例文** … `-R` で配下もまとめて変更する

```bash
$ sudo chgrp -R staffgroup dir       # dir と配下すべてのグループを変更する
```

**`chgrp` では所有ユーザを変更できません。** そこが `chown` との違いです。

---

## chown と chgrp の使い分け

| | **`chown`** | **`chgrp`** |
|:--|:--|:--|
| **所有ユーザ** | **変更できる**（root のみ） | **変更できない** |
| **所有グループ** | **変更できる** | **変更できる** |
| **グループの書き方** | **`:グループ名`**（または `.グループ名`） | **`グループ名`**（**コロンなし**） |
| **両方まとめて** | **`chown ユーザ:グループ`** | できない |
| `-R` | **ある** | **ある** |

**「所有グループだけを変えたい」ときは、どちらでも書けます。**

```bash
$ chown :staffgroup file.txt         # chown で、ユーザ名を省く
$ chgrp staffgroup file.txt          # chgrp で、そのまま書く
```

**同じ結果**になります。**`chgrp` は「グループ専用の chown」**と覚えると迷いません。

**書式の対応表**

| やりたいこと | `chown` の書き方 | `chgrp` の書き方 |
|:--|:--|:--|
| ユーザだけ | `chown staff file` | **できない** |
| **グループだけ** | **`chown :staffgroup file`** | **`chgrp staffgroup file`** |
| 両方 | `chown staff:staffgroup file` | **できない** |
| グループだけ・再帰 | **`chown -R :staffgroup dir`** | **`chgrp -R staffgroup dir`** |

## umask とは

**新規に作成されるファイルやディレクトリのデフォルトのパーミッションは、
システムのパーミッション初期値を基本とし、それを `umask` 値
（初期値から削除する権限の設定）で調整して決定されます。**

**システムのパーミッション初期値**

| 作られるもの | 初期値 | 記号 |
|:--|:--|:--|
| **新規ファイル** | **666** | `rw-rw-rw-` |
| **新規ディレクトリ** | **777** | `rwxrwxrwx` |

> **ファイルの初期値に `x` が入っていない**のがポイントです。
> 新しく作ったテキストに実行権が付いていたら危ないので、**ファイルには最初から `x` を与えません**。

**「削除する権限」を指定する、という発想**

```text
                ファイル            ディレクトリ
 初期値          666                 777
 umask 値      − 022               − 022
 ─────────────────────────────────────────
 実際の権限      644                 755
```

**umask は「残す権限」ではなく「削る権限」**です。ここが直感と逆なので間違えやすいところです。

### umask 値の計算

**例** … ディレクトリを `750`（所有ユーザは全部、グループは読み・実行、その他は禁止）にしたい

```text
 所有ユーザは、 読み・書き・実行可能   → 削除される権限はないので      左の桁が「0」
 所有グループは、読み・実行可能        → 書き込み(2)が削除されるので    中央の桁が「2」
 その他のユーザは、全て不可           → 読み(4)+書き(2)+実行(1)なので  右の桁が「7」
```

**適切な umask 値は `027`** です。先頭に `0` をつけて **`0027`** と表記されることもあります。

```bash
$ umask 027                          # umask を設定する
$ umask                              # 確認する
0027

$ touch file                         # ファイルを作る
$ mkdir dir                          # ディレクトリを作る
$ ls -l                              # それぞれの権限を見る
合計 4
drwxr-x---. 2 staff staff 4096 4月 29 12:32 dir      ← 750
-rw-r-----. 1 staff staff    0 4月 29 12:32 file     ← 640
```

**重要 … 引き算ではありません**

**umask の計算は「数値の引き算」ではなく、「その権限を消す」という操作**です。
**桁ごとに、消す権限のビットを落とします。**

**例** … `umask 0037` のときのファイルのパーミッション

```text
 所有ユーザの権限は    6 (rw) − 0       = 6 (rw)
 所有グループの権限は  6 (rw) − 3 (wx)  = 4 (r)    ※ 3 にはなりません。読み取り権限が残ります
 その他のユーザの権限は 6 (rw) − 7 (rwx) = 0       ※ −1 にはなりません
```

| | ファイル | 所有ユーザ | 所有グループ | その他 | ディレクトリ | 所有ユーザ | 所有グループ | その他 |
|:--|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| **umask が 0 の場合** | **666** | `rw-` | `rw-` | `rw-` | **777** | `rwx` | `rwx` | `rwx` |
| **umask 値** | **037** | `---` | `-wx` | `rwx` | **037** | `---` | `-wx` | `rwx` |
| **デフォルトの権限** | **640** | `rw-` | `r--` | `---` | **740** | `rwx` | `r--` | `---` |

**`6 - 3 = 3` と計算してしまうのが典型的な誤り**です。
`3` は `-wx`（書き・実行）を意味します。**ファイルの初期値 `6` には `x` がそもそも無い**ので、
消えるのは `w` だけで、**`r` が残って `4` になります**。

**覚え方**

```text
数を引くのではなく、「その権限のスイッチを OFF にする」と考える。

  初期値  rw-      （r=ON, w=ON, x=OFF）
  umask   -wx      （w と x を OFF にする）
  ───────────────
  結果    r--      （r だけ残る）
```

### umask コマンド

**`umask` は、ファイルやディレクトリを新規作成した際の、
デフォルトのパーミッションを調整するコマンド**です。

```text
umask [umask値]
```

| 書き方 | 動作 |
|:--|:--|
| **`umask`**（引数なし） | **現在の umask 値を表示する** |
| **`umask 027`** | **そのシェル上でのみ** umask 値を変更する |
| **`umask -S`** | **記号で表示する**（残る権限のほうを表示） |

```bash
$ umask                              # 現在の値を数値で見る
0022

$ umask -S                           # 記号で見る（こちらは「残る権限」）
u=rwx,g=rx,o=rx

$ umask 077                          # 自分だけがアクセスできる設定にする
$ touch secret.txt                   # ファイルを作る
$ ls -l secret.txt                   # 600 になっている
-rw-------. 1 shun shun 0 Sep 14 01:00 secret.txt
```

> **`umask 027` のように変更しても、効くのは「そのシェルの中だけ」**です。
> 端末を閉じたり、別の端末を開いたりすると元に戻ります。

**似ているが違うコマンド**

| コマンド | 何をするか |
|:--|:--|
| **`umask`** | **これから作るもの**の既定パーミッションを調整する |
| **`chmod`** | **すでにあるもの**のパーミッションを変更する |
| `chgrp` | すでにあるものの**所有グループ**を変更する |
| `chown` | すでにあるものの**所有ユーザ・グループ**を変更する |
| `chmask` / `chowner` / `chgroup` | **存在しないコマンド** |

**「新規作成のデフォルトを変えたい」なら `umask`、「今あるものを変えたい」なら `chmod`** です。

### umask を恒久的に変える

**シェルの設定ファイルに書きます。**

| 書く場所 | 効く範囲 |
|:--|:--|
| **`~/.bashrc`** | **そのユーザだけ** |
| **`/etc/profile`** ／ `/etc/bashrc` | **システム全体**（ログインシェル経由） |
| `/etc/login.defs` の `UMASK` | ログイン時の既定値（ディストリによる） |

```bash
$ echo 'umask 027' >> ~/.bashrc      # 自分だけに適用する
$ source ~/.bashrc                   # いまのシェルにも反映する
$ umask                              # 確認する
0027
```

**補足 … サービス（systemd）には `~/.bashrc` は効きません**

systemd が起動するプロセスは**ログインシェルを経由しない**ため、`~/.bashrc` を読みません。
ユニットファイルで明示します。

```ini
[Service]
UMask=0027
```

## 結果画面の見方

**`umask` の出力**

```bash
$ umask                              # 数値で表示する
0027
│└┬┘
│ └─ 3 桁の umask 値（所有ユーザ・所有グループ・その他）
└─── 特殊パーミッション用の桁。通常は 0
```

| 出力 | 意味 | そのとき作られるもの |
|:--|:--|:--|
| **`0000`** | 何も削らない | ファイル **666** ／ ディレクトリ **777** |
| **`0022`** | **グループとその他から `w` を削る**（多くのディストリの既定） | ファイル **644** ／ ディレクトリ **755** |
| **`0027`** | さらに**その他から全部削る** | ファイル **640** ／ ディレクトリ **750** |
| **`0077`** | **自分以外から全部削る** | ファイル **600** ／ ディレクトリ **700** |

**`umask -S` の出力は「残る権限」**

```bash
$ umask                              # 数値は「削る権限」
0027
$ umask -S                           # 記号は「残る権限」。意味が反転している
u=rwx,g=rx,o=
```

**同じ設定を、数値は「削る側」、記号は「残る側」から表示しています。**
ここを取り違えると混乱するので、**どちらを見ているかを意識**します。

**`ls -l` で結果を確かめる**

```bash
$ umask 027                          # 設定する
$ touch f && mkdir d                 # ファイルとディレクトリを作る
$ ls -l                              # 両方の結果を見る
drwxr-x---. 2 shun shun 4096 Sep 14 01:00 d      ← 777 − 027 = 750
-rw-r-----. 1 shun shun    0 Sep 14 01:00 f      ← 666 − 027 = 640
```

**ファイルとディレクトリで結果が違う**のは、**初期値が 666 と 777 で違う**からです。

## 間違えやすい書き方

| 書き方 | どこが誤りか |
|:--|:--|
| **`chgrp -R :staffgroup dir`** | **`chgrp` にコロンは不要。**書式が誤り |
| **`chgrp test staffgroup file.txt`** | **引数はグループ名ひとつだけ。**「変更前」を書く必要はない |
| **`chown staffgroup file.txt`**（グループを変えたいとき） | **所有ユーザが `staffgroup` に変わってしまう**。グループなら `:staffgroup` |
| **`chown staff staffgroup file.txt`** | **区切りがコロンかドットでないと通らない** |
| `chown staffgroup:staff file.txt` | **ユーザとグループが逆**。`ユーザ名:グループ名` の順 |
| `chown :staffgroup dir`（配下も変えたいとき） | **`-R` が無い**ので `dir` 自身だけ |
| **`umask 755`** と書く | **umask は「削る権限」**。755 を残したいなら **`umask 022`** |
| `umask` で `6-3=3` と計算する | **桁ごとの引き算ではない**。`6(rw) - 3(wx)` は `4(r)` |
| 一般ユーザが `chown` で他人に譲渡 | **所有ユーザの変更は root のみ** |

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| `chgrp: 無効なグループです` | **コロンを付けた**（`:group`） | `chgrp group` と書く。コロンは `chown` の書式 |
| `chown: 許可されていない操作です` | **所有ユーザの変更は root のみ** | `sudo` を付ける |
| `chown -R` したのに一部が変わらない | シンボリックリンクの先は既定で追わない | `-h` でリンク自身、`-L` でリンク先をたどる |
| `umask` を変えたのに戻ってしまう | **そのシェルの中だけ**の設定 | `~/.bashrc` / `/etc/profile` に書く |
| systemd のサービスで umask が効かない | **ログインシェルを経由しない** | ユニットの `[Service]` に `UMask=` を書く |
| ファイルだけ実行権が付かない | **ファイルの初期値は 666**（`x` が無い） | 実行権は `chmod +x` で明示的に付ける |
| `umask -S` の値が数値と合わない気がする | **数値は「削る権限」、記号は「残る権限」** | 意味が反転していると覚える |
| デプロイしたファイルの所有者がおかしい | **`sudo` で作ると root のものになる** | `chown -R appuser:appgroup` で揃える |
| グループを変えたのに権限が変わらない | **所有グループの欄の権限が元から緩い／厳しい** | `ls -l` で 3 クラスそれぞれを確認する |

## クラウド実務メモ

**デプロイ後の所有者揃えはほぼ必須**

`sudo` で展開したファイルは **root の所有**になります。アプリのユーザで動かすなら揃えます。

```bash
$ sudo tar xzf app.tar.gz -C /opt/app        # root で展開される
$ sudo chown -R appuser:appgroup /opt/app    # アプリのユーザに揃える
$ sudo find /opt/app -type d -exec chmod 750 {} \;   # ディレクトリは 750
$ sudo find /opt/app -type f -exec chmod 640 {} \;   # ファイルは 640
```

**`find` で種類ごとに分ける**のが定番です。`chmod -R 750` だと**ファイルにも実行権が付きます**。

**ログの権限は umask で決まる**

アプリが自分で作るログファイルの権限は、**そのプロセスの umask** で決まります。
`umask 022` のままだと **644（他人も読める）** になります。

```ini
[Service]
User=appuser
UMask=0027                     # ログは 640 になる
```

**個人情報や認証情報を含むログでは、ここを明示**します。

**EC2 のユーザーデータは root・umask 022**

ユーザーデータは **root 権限で実行**され、作られるファイルは root のものになります。

```bash
#!/bin/bash
umask 027                                    # 先に umask を絞る
install -o appuser -g appgroup -m 640 /dev/null /var/log/app.log
```

**`install` コマンドは「作成と同時に所有者と権限を指定」できる**ので、
`touch` → `chown` → `chmod` の 3 手を 1 手にできます。

**コンテナでは `USER` と所有者を合わせる**

```dockerfile
RUN useradd -r -u 1001 appuser
COPY --chown=appuser:appuser app/ /opt/app/
USER appuser
```

**`COPY --chown`** を使わないと、**root 所有のファイルを非 root ユーザで読む**ことになり、
書き込みが必要な場所で失敗します。

**S3 や EFS には Linux の所有権がそのままは効かない**

- **S3** … オブジェクトに `rwx` の概念はありません。**IAM とバケットポリシー**で制御します
- **EFS** … **Linux の所有権とパーミッションがそのまま効きます**。UID / GID を**インスタンス間で揃える**必要があります

```bash
$ id appuser                         # 各インスタンスで UID/GID が同じか確認する
uid=1001(appuser) gid=1001(appgroup) groups=1001(appgroup)
```

**UID がずれていると、同じ EFS を見ても別ユーザ扱い**になります。
