## スワップ領域とは

**スワップ領域とは、物理メモリ（実メモリ、RAM）に収まらなかった情報を一時的に格納する為の、
通常ハードディスク上に作成する領域です。**

```text
【メモリに余裕があるとき】
  プロセス ─→ 物理メモリ（速い）

【メモリが足りなくなったとき】
  プロセス ─→ 物理メモリ（速い）
                 │ 当面使わないデータを追い出す
                 ▼
              スワップ領域（ディスク上・遅い）
```

**物理メモリよりも動作は遅くなります。** ディスクはメモリより桁違いに遅いためです。
それでも用意する理由は、**「遅くなる」ほうが「プロセスが強制終了される」よりましだから**です。

| スワップが無い場合 | スワップがある場合 |
|:--|:--|
| メモリを使い切ると **OOM Killer** がプロセスを強制終了する | **遅くなりながらも動き続ける**ので、気づいて対処する時間ができる |

**補足 … スワップは「ファイルシステム」ではありません**

`mkfs` で作れないのはこのためです。ファイルやディレクトリを置く場所ではなく、
**メモリのページをそのまま退避させる専用の領域**なので、構造がまったく違います。

**補足 … スワップの実体は2種類あります**

| 種類 | 作り方 | 特徴 |
|:--|:--|:--|
| **スワップパーティション** | `fdisk` などでパーティションを切ってから `mkswap` | わずかに速い。従来からの標準 |
| **スワップファイル** | 普通のファイルを作ってから `mkswap` | **後から柔軟に増減できる**。クラウドで主流 |

**`mkswap` はどちらにも使えます。**
引数に**デバイスファイルか、スワップファイルとするファイルを指定**すると、スワップ領域が作成されます。

### 似ているが別物の2つ

**スワップ領域と混同されやすいものが 2 つ（`tmpfs` と予約ブロック）あります。** まとめて整理しておきます。

| | **スワップ領域** | **tmpfs** | **予約ブロック** |
|:--|:--|:--|:--|
| **一言でいうと** | **大容量の記憶装置上に作られる仮想的なメモリ領域** | **メモリ上に作られる揮発性の特殊ファイルシステム** | **ファイルシステム内に予約された root 専用の領域** |
| 実体はどこにあるか | **ディスク上** | **メモリ上** | **ディスク上（ファイルシステムの中）** |
| 何のためにあるか | **メモリの空き容量が尽きた場合に備える** | **メモリの速さを活かして一時データを置く** | **ディスク容量が尽きても root が作業できるようにする** |
| どのファイルシステムの話か | ファイルシステムではない | 専用の特殊ファイルシステム | **ext2 / ext3 などの機能** |

```text
  スワップ領域 … ディスクの一部を「メモリのように」使う   ─┐
                                                              ├─ 向きが逆
  tmpfs        … メモリの一部を「ディスクのように」使う   ─┘
```

**「スワップ領域とは何か」を選ぶ問題では、次の 3 つが誤答として並びます。**

| 誤った説明 | 実際は何の説明か |
|:--|:--|
| メモリ上に作られる、揮発性の特殊ファイルシステムである | **tmpfs** の説明 |
| ファイルシステム内に予約された root ユーザ専用の領域である | **ext2 / ext3 の予約ブロック**の説明 |
| **ハードディスクの容量**が尽きた場合に備える予備領域である | 同上。**スワップが備えるのは「メモリ」の枯渇**であって、ディスクの枯渇ではない |

**正しい説明は「大容量の記憶装置上に作られる仮想的なメモリ領域である」**です。

> **予約ブロック**とは、**万が一ディスク容量が尽きた場合にも `root` が作業できるように、
> いくらかのブロック（容量）を予約しておく**というものです。既定では全体の 5% 程度が予約されます。
> `tune2fs -m 割合 デバイス` で変更できます。**スワップ領域とは関係がありません。**

## 作成・有効化・無効化の3ステップ

### mkswap 作成する

**意味** … 指定した領域を**スワップ領域として初期化**する

```text
mkswap [オプション] デバイス名またはファイル名
```

```bash
$ sudo mkswap /dev/sda2              # パーティションをスワップ領域にする
Setting up swapspace version 1, size = 64 MiB (67104768 bytes)
no label, UUID=de5dcc83-7052-4a98-92e3-26d9bca16662
```

**UUID が振られる**点に注目してください。`/etc/fstab` にはこの UUID を書けます。

| オプション | 意味 |
|:--|:--|
| `-L ラベル` | ラベルを付ける |
| `-c` | 不良ブロックを検査してから作成する |
| `-f` | 領域が大きすぎるといった警告を無視して強制的に作成する |

**注意 … `mkswap` は中身を消します**

`mkfs` と同じく、指定した領域の内容を破棄します。**デバイス名を必ず `lsblk` で確認**してから実行します。

### swapon 有効化する

**意味** … 作成したスワップ領域を**システムが使える状態にする**

**`mkswap` で作成しただけではスワップ領域は有効になっていません。
作成した領域を引数に与え、`swapon` を実行するとそのスワップ領域が有効になります。**

```bash
$ sudo swapon /dev/sda2              # スワップ領域を有効にする
$ swapon --show                      # 有効になったことを確認する
NAME       TYPE      SIZE USED PRIO
/dev/sda2  partition  64M   0B   -2
```

| オプション | 意味 |
|:--|:--|
| **`-a`** | **`/etc/fstab` に記載されているスワップ領域をすべて有効にする** |
| `-s` | 使用状況を表示する（`--show` の古い書き方） |
| `--show` | 使用状況を表で表示する |
| `-p 優先度` | 優先度を指定する（数値が大きいほど先に使われる） |
| `-v` | 詳細を表示する |

```bash
$ sudo swapon -a                     # fstab のスワップ設定をまとめて有効にする
```

**`swapon` はスワップ領域を「作る」機能は持っていません。** 有効化するだけです。

### swapoff 無効化する

**意味** … 有効になっているスワップ領域を**使うのをやめる**

**既に有効になっているスワップ領域を引数に与えると、その領域を無効にします。**

```bash
$ sudo swapoff /dev/sda2             # スワップ領域を無効にする
$ swapon --show                      # 何も表示されない（無効になった）
```

| オプション | 意味 |
|:--|:--|
| `-a` | 有効なスワップ領域をすべて無効にする |
| `-v` | 詳細を表示する |

**`swapoff` もスワップ領域を「作る」機能は持っていません。**

**注意 … `swapoff` は時間がかかることがあります**

スワップに退避されていたデータを**すべて物理メモリへ戻してから**無効化するためです。
物理メモリに空きがないと**失敗します**。

```bash
$ sudo swapoff /dev/sda2             # メモリに空きが無いと失敗する
swapoff: /dev/sda2: swapoff failed: Cannot allocate memory
```

## 紛らわしいコマンドの整理

Ping-t で必ず並べて出てくる 5 つです。**スワップ領域を作れるのは `mkswap` だけ**です。

| コマンド | 何をするか | スワップ領域を作れるか |
|:--|:--|:-:|
| **`mkswap`** | **スワップ領域を作成する** | **○** |
| `swapon` | スワップ領域を**有効化**する | ✕ |
| `swapoff` | スワップ領域を**無効化**する | ✕ |
| `mkfs` | 各種**ファイルシステム**を作成する | ✕ |
| `fdisk` | **パーティションを作成・編集**する | ✕ |

**`mkfs` で作れない理由**

**`mkfs` は各種ファイルシステムを作ることができるコマンドですが、
スワップは特別な領域で、厳密にはファイルシステムではないため、`mkfs` で作ることはできません。**

**`fdisk` で作れない理由**

**`fdisk` はスワップ用のパーティションを作成する際に使用します。
スワップ領域の作成までは行えません。**

`fdisk` がやるのは「ディスクをここからここまでで区切る」ことと、
そのパーティションに「タイプ 82（Linux swap）」という**印を付ける**ことまでです。
**印を付けただけでは中身は空**なので、`mkswap` で整える必要があります。

```text
fdisk でタイプ 82 を付ける … 「ここはスワップ用の区画です」という札を立てただけ
mkswap を実行する          … 実際にスワップ領域として使える形に整える
swapon を実行する          … システムに「使っていいよ」と登録する
```

## 起動時に自動で有効化する

**スワップ領域がシステム起動時に自動で有効化されるには、
`/etc/fstab` ファイルに記載されていることが必要です。**

**`/etc/fstab` ファイルは、利用するファイルシステムのマウント設定を事前に行っておくための
設定ファイルですが、スワップ領域の設定についてもここに記載します。**

**システム起動時に、スワップ領域に関する行には有効化処理が行われ、
その他の行に対してはマウント処理が行われます。**

### 書き方

```text
UUID=de5dcc83-...   swap   swap   defaults   0   0
      (1)           (2)    (3)      (4)     (5) (6)
```

| # | 項目 | スワップ行での書き方 |
|:-:|:--|:--|
| (1) | デバイス名 | **どのパーティション（またはファイル）がスワップ用であるか**。`UUID=` / `LABEL=` / `/dev/sda2` / スワップファイルのパス |
| (2) | マウントポイント | **`swap`** と書く（マウントしないのでマウントポイントは無い） |
| (3) | ファイルシステムの種類 | **`swap`** と書く。**この行がスワップ設定であることの目印** |
| (4) | マウントオプション | 通常は `defaults` |
| (5) | dump フラグ | `0` |
| (6) | fsck フラグ | **`0`**（ファイルシステムではないのでチェック対象外） |

**`/etc/fstab` 内で「ファイルシステムの種類」の項目に `swap` と記載されている行が、
スワップ領域に関する設定です。**

```bash
$ cat /etc/fstab                     # スワップの行を確認する
UUID=3b80b96c-...  /       xfs   defaults  0 0
UUID=de5dcc83-...  swap    swap  defaults  0 0    ← この行がスワップ設定
```

### 反映を確認する

`/etc/fstab` に書いたら、**再起動する前に**動くことを確かめます。

```bash
$ sudo swapon -a                     # fstab の記述どおりに有効化してみる
$ swapon --show                      # 有効になったか確認する
NAME       TYPE      SIZE USED PRIO
/dev/sda2  partition  64M   0B   -2
```

`/etc/fstab` の書き間違いは**起動失敗に直結**します。
[fstabの書き方](./fstabの書き方.md) の
「起動時に自動マウントする条件」の注意点も同じく当てはまります。

## 使用状況を確認する

**スワップの使用状況は `df` では確認できません。** ここがよく問われます。

`df` は**ファイルシステムの空き容量**を表示するコマンドで、
スワップはファイルシステムではないため対象外です。

```bash
$ df -h | grep -i swap               # 何も出てこない
```

**確認に使う 3 つ**

| 方法 | 出てくるもの |
|:--|:--|
| **`free -h`** | **物理メモリとスワップの使用量をまとめて** |
| **`swapon --show`**（`swapon -s`） | **どの領域が有効か、優先度は何か** |
| `cat /proc/swaps` | 上と同じ情報の生データ |

**`free -h`**

```bash
$ free -h                            # メモリとスワップの状況を見る
               total        used        free      shared  buff/cache   available
Mem:           7.8Gi       664Mi       6.8Gi       5.0Mi       595Mi       7.2Gi
Swap:           63Mi          0B        63Mi
```

`Swap:` の行を見ます。`used` が増え続けているなら、**物理メモリが足りていない**サインです。

**`swapon --show`**

```bash
$ swapon --show                      # 有効なスワップ領域を一覧する
NAME             TYPE SIZE USED PRIO
/tmp/sw/swapfile file  64M   0B   -2
```

| 列 | 意味 |
|:--|:--|
| `NAME` | デバイスまたはファイルのパス |
| `TYPE` | `partition` か `file` か |
| `SIZE` / `USED` | 全体と使用中のサイズ |
| **`PRIO`** | **優先度**。値が大きいものから先に使われる |

**`swapon -s` は出力の形が違う**

同じ「使用状況の確認」でも、**`--show` と `-s` では表示形式が変わります**。

```bash
$ swapon -s                          # 旧形式でスワップの利用状況を表示する
Filename                Type       Size       Used  Priority
/dev/sda3               partition  1048568    0     -1
```

| | **`swapon --show`** | **`swapon -s`** |
|:--|:--|:--|
| 列の名前 | `NAME` / `TYPE` / `SIZE` / `USED` / `PRIO` | **`Filename` / `Type` / `Size` / `Used` / `Priority`** |
| サイズの単位 | **人が読める単位**（`64M` など） | **KB**（`1048568` = 約 1GB） |
| 中身 | 同じ情報 | 同じ情報 |

**`swapon -s` の出力内容は `cat /proc/swaps` と同じ**です。
**`-s` を付けずに `swapon` だけを実行すると「有効化」になり、利用状況は表示されません。**

| 表示される項目 | 意味 |
|:--|:--|
| **`Filename`** | スワップに使っているデバイスまたはファイルのパス |
| **`Type`** | **`partition`（パーティション）か `file`（スワップファイル）か** |
| **`Size`** | **スワップ領域の総量**（KB） |
| **`Used`** | **使用中のスワップ領域のサイズ**（KB） |
| **`Priority`** | 優先度。**値が大きいものから先に使われる** |

**`cat /proc/swaps`**

```bash
$ cat /proc/swaps                    # カーネルが持つ生の情報を読む
Filename                Type    Size    Used    Priority
/tmp/sw/swapfile        file    65532   0       -2
```

サイズの単位が **KB** である点だけ注意します。

**補足 … 見るべきは「使用量」より「増え方」**

スワップが少し使われていること自体は異常ではありません。
Linux は**当面使わないページを先にスワップへ逃がしておく**ことがあるためです。

| 状況 | 判断 |
|:--|:--|
| `used` が少量で変化しない | 正常 |
| **`used` が増え続ける** | **物理メモリ不足**。増設かチューニングを検討 |
| `si` / `so`（`vmstat` の列）が常に動いている | **スワップの読み書きが多発**＝深刻。応答が悪化する |

```bash
$ vmstat 1 5                         # 1秒ごとに5回、スワップ入出力を観測する
```

`si`（swap in）と `so`（swap out）が常時ゼロでないなら、性能問題として扱います。

## スワップファイルで増やす

パーティションを切り直さずにスワップを増やせるので、**運用中のサーバで使える**方法です。

```bash
$ sudo fallocate -l 2G /swapfile     # ① 2GB のファイルを確保する
$ sudo chmod 600 /swapfile           # ② 所有者だけが読み書きできるようにする
$ sudo mkswap /swapfile              # ③ スワップ領域として初期化する
$ sudo swapon /swapfile              # ④ 有効化する
$ swapon --show                      # ⑤ 確認する
NAME       TYPE SIZE USED PRIO
/swapfile  file   2G   0B   -2
```

**② の `chmod 600` は必須です。** 権限が緩いと `swapon` が警告を出します。
スワップにはメモリの中身がそのまま入るため、**他のユーザから読めてはいけません**。

**⑥ `/etc/fstab` に登録する（忘れると再起動で消えます）**

```bash
$ echo '/swapfile swap swap defaults 0 0' | sudo tee -a /etc/fstab   # fstab へ追記する
```

**補足 … `fallocate` が使えない場合**

XFS など一部の環境では `fallocate` で作ったファイルが `swapon` に拒否されることがあります。
その場合は `dd` で作ります。

```bash
$ sudo dd if=/dev/zero of=/swapfile bs=1M count=2048 status=progress   # 2GB を実際に書く
```

`dd` については [dd コマンド](./ddコマンド.md) を参照してください。

### ddで作る場合の3コマンド

**空きパーティションが無い環境では、`dd` でファイルを作る手順がそのまま問われます。**
**軸になるコマンドは `dd` → `mkswap` → `swapon` の 3 つ**です（間に `chmod 600` を挟みます）。

```bash
$ sudo dd if=/dev/zero of=/tmp/swapfile bs=1024 count=1048576   # ① 1GiB の空ファイルを作る
$ sudo chmod 600 /tmp/swapfile                                   # ② 権限を600にする
$ sudo mkswap /tmp/swapfile                                      # ③ スワップ領域として初期化する
$ sudo swapon /tmp/swapfile                                      # ④ 有効化する
```

**`if` と `of` を逆に書かない**

**ここが誤答として必ず用意されます。**

| 指定 | 意味 |
|:--|:--|
| **`if=`** | **入力ファイル（デバイス）を指定する** |
| **`of=`** | **出力ファイル（デバイス）を指定する** |

```text
  ○ dd if=/dev/zero of=/tmp/swapfile    /dev/zero から読んで、swapfile へ書く
  ✕ dd of=/dev/zero if=/tmp/swapfile    swapfile から読んで、/dev/zero へ捨てる（何も作られない）
```

**`/dev/zero` は 16 進数のデータ `0x00` を延々と生成する特殊ファイル**で、
**特定サイズの、内容が何もないファイルを作る**ときに使います。

**`bs` と `count` の掛け算がサイズ**

```text
  bs=1024 × count=1048576 = 1,073,741,824 バイト ≒ 1GB
```

**`mkfs` では作れません**（理由は前述の「`mkfs` で作れない理由」のとおりです）。
`mkfs /tmp/swapfile` という書き方は誤りです。

### スワップファイルを作るところまでの流れを追う

**実行例**（`mkswap` と `swapon` が何を言ってくるかに注目します）

```bash
$ sudo mkswap /tmp/swapfile                    # スワップ領域として初期化する
スワップ空間バージョン1を設定します、サイズ = 1048572 KiB
ラベルはありません, UUID=40698c53-a3b2-4d6c-b44c-6a6ee65dbb4e
$ sudo swapon /tmp/swapfile                    # 有効化する（権限が緩いと警告が出る）
swapon: /tmp/swapfile: 安全でない権限 0644 を持ちます。 0600 がお勧めです。
```

| 出力 | 読み方 |
|:--|:--|
| **`スワップ空間バージョン1を設定します`** | **`mkswap` が署名を書き込んだ**。ここではまだ有効になっていない |
| **`UUID=…`** | **`mkswap` が UUID を振る**。`/etc/fstab` にこの UUID で書ける |
| **`安全でない権限 0644 を持ちます`** | **`chmod 600` を忘れている**。**メモリの中身が他ユーザから読めてしまう** |

**確認する**

```bash
$ swapon -s                                    # 有効なスワップの一覧を見る
Filename        Type       Size     Used  Priority
/dev/dm-1       partition  839676   1804  -1
/tmp/swapfile   file       1048572  0     -2
$ free                                          # 合計が増えていることを確認する
```

**`Type` 欄が `file` になっていれば、スワップファイルとして有効化されています。**

**後始末**

```bash
$ sudo swapoff /tmp/swapfile                   # 無効化する
$ sudo rm /tmp/swapfile                        # ファイルを削除してディスクを空ける
```

**スワップ領域のファイルはディスク領域を占有し続けます。**
**不要になったら `swapoff` で無効化し、削除しておきます。**

### なぜ緊急時にスワップを足すのか

**メモリ利用率が非常に高い状態で運用を続けると、
カーネルがメモリ不足と認識したときに OOM Killer（Out Of Memory Killer ＝
メモリ不足時の自動プロセス停止機能）が発動し、プロセスの強制終了処理が実行されます。**

**OOM Killer は独自の基準でプロセスを強制終了する**ため、
**意図しない重要なプロセスが強制終了される可能性があります。**

```text
  ① 物理メモリが不足する
        ▼
  ② スワップが使われ始める（vmstat の si / so が動き出す）
        ▼
  ③ スワップも不足する
        ▼
  ④ OOM Killer がプロセスを強制終了してメモリを確保する
```

**`vmstat 1` で継続的に見ていると、この流れがそのまま観察できます。**

| `vmstat` の欄 | 見るもの |
|:--|:--|
| **`swpd`** | **スワップの使用量**。増え始めたら物理メモリが足りていない |
| **`si` / `so`** | **スワップイン／スワップアウト**。**0 以外が続いたら危険信号** |
| `free` | 物理メモリの空き |

`vmstat` の読み方は [リソース監視 システム全体](../04_プロセスとリソース管理/リソース監視_システム全体.md) にあります。

**強制終了されたかどうかはログで確認できます。**

```bash
$ sudo journalctl | grep -i "Out of memory"    # OOM Killer の発動を探す
kernel: Out of memory: Kill process 12976 (bash) score 879 or sacrifice child
kernel: Killed process 12977 (yes) total-vm:107896kB, anon-rss:32kB, file-rss:0kB
```

| 語 | 意味 |
|:--|:--|
| **`Kill process <PID> (<名前>)`** | **どのプロセスを選んだか** |
| **`score`** | **OOM Killer が付けた「殺しやすさ」の点数。大きいほど選ばれやすい** |
| `sacrifice child` | 子プロセスを代わりに終了させる選択肢があったこと |

**恒久的な対策は 2 つ**あります。

| 対策 | 内容 | 注意 |
|:--|:--|:--|
| **優先度を下げる** | 重要なプロセスの OOM Killer の停止優先度を低く設定する | **プロセス番号が変わると都度設定が必要になる** |
| **メモリを増やす** | 物理メモリ・スワップを十分に用意する | 根本的だが、すぐには増やせないことがある |

**突然のメモリ利用率の増加に対して取れる緊急対策としては、スワップ領域を増やすのが現実的**です。
**スワップはディスク上なのでアクセスは非常に遅いですが、
更新頻度の低いメモリ領域をスワップに移すことで物理メモリの空きを確保し、
システムの継続運用を可能にできます。**
