## マウントとは何か

Linux では、ディスクやパーティションを**そのままでは使えません**。
「このディスクを、このディレクトリとして見せる」という接続作業が必要で、これを**マウント**と呼びます。

```text
/dev/sdb1（ディスクの実体）
        │
        │  mount /dev/sdb1 /data
        ▼
    /data（ディレクトリとして見えるようになる）
```

- **デバイスファイル**（`/dev/sdb1` など）… ディスクの実体を指す入り口
- **マウントポイント**（`/data` など）… そのディスクを見せるディレクトリ

Windows のように「D ドライブ」が勝手に生えるのではなく、
**ディレクトリツリーの好きな場所に接ぎ木する**のが Linux の考え方です。

**補足 … マウントポイントは事前に存在している必要があります**

```bash
$ sudo mkdir -p /data                # マウント先のディレクトリを先に作る
$ sudo mount /dev/sdb1 /data         # そこへマウントする
```

**補足 … マウントすると、元々そこにあったファイルは見えなくなります**

消えるわけではありません。**上にかぶさって隠れる**だけで、アンマウントすれば戻ります。
中身の入ったディレクトリをマウントポイントにすると混乱するので、空のディレクトリを使います。

## mount コマンド

```text
mount [オプション] [マウントするデバイス名] [マウントポイント]
```

### デバイスとマウントポイントを指定する

**意味** … `/etc/fstab` に設定が無い場合は、**デバイス名とマウントポイントの両方**を書く

**例文** … `/dev/sr0` として認識されている CD-ROM を `/mnt/cdrom` にマウントする

```bash
$ sudo mount /dev/sr0 /mnt/cdrom     # デバイス名 → マウントポイントの順で書く
```

**順番は「デバイス名 → マウントポイント」です。** 逆に書くと失敗します。

```bash
$ sudo mount /mnt/cdrom /dev/sr0     # 逆順は誤り
```

**補足 … ファイルシステムの種類は省略できます**

`-t` を指定しない場合、`mount` が**中身を見て自動で判別**します。
標準的な CD-ROM のファイルシステムは `iso9660` ですが、書かなくても認識されます。

```bash
$ sudo mount /dev/sr0 /mnt/cdrom             # -t なし。自動判別される
$ sudo mount -t iso9660 /dev/sr0 /mnt/cdrom  # 明示しても同じ結果
```

**種類を間違えて指定すると失敗します。** CD-ROM に `-t ext4` を指定するのは誤りです。

**補足 … `/etc/fstab` に設定があるならマウントポイントだけでよい**

`/etc/fstab` に書いてあれば、**デバイス名を省略**できます。

```bash
$ sudo mount /mnt/cdrom              # fstab の設定を見てマウントする
```

設定が無いのにマウントポイントだけを書くと、こう怒られます。

```bash
$ sudo mount /tmp/mt/mnt             # fstab にエントリが無い場合
mount: /tmp/mt/mnt: can't find in /etc/fstab.
```

### 引数なしで実行すると一覧が出る

**意味** … `mount` を引数なしで実行すると、**現在マウントされているファイルシステムの一覧**が表示される

**一般ユーザによるマウントは通常禁止されていますが、一覧の表示は誰でもできます。**

```bash
$ mount                              # 一般ユーザでも実行できる
/dev/mapper/vg_server1-lv_root on / type ext4 (rw)
proc on /proc type proc (rw)
sysfs on /sys type sysfs (rw)
devpts on /dev/pts type devpts (rw,gid=5,mode=620)
tmpfs on /dev/shm type tmpfs (rw)
/dev/sda1 on /boot type ext4 (rw)
/dev/sr0 on /mnt/cdrom type iso9660 (ro)
```

**読み方**

```text
/dev/sda1     on  /boot     type ext4   (rw)
    │              │             │        │
 デバイス      マウント先    種類     マウントオプション
```

**補足 … 情報の出どころは `/etc/mtab` です**

`/etc/mtab` には現在マウントされているファイルシステムの情報が格納されています。
ただし**最近のディストリビューションでは、`/etc/mtab` は `/proc/self/mounts` へのシンボリックリンク**です。

```bash
$ ls -l /etc/mtab                    # 実体を確認する
lrwxrwxrwx 1 root root 19 May  8 16:23 /etc/mtab -> ../proc/self/mounts
```

つまり中身はカーネルが持っている情報で、**編集できるファイルではありません**。
`/proc/mounts` や `/proc/self/mounts` も同じく**読み取り専用**です。
マウント状態を変えたいときは、これらを書き換えるのではなく `mount` / `umount` を使います。

### mount の主なオプション

| オプション | 意味 |
|:--|:--|
| `-a` | **`/etc/fstab` に記載されているファイルシステムをすべてマウント**する（`noauto` が指定されているものは除く） |
| `-o` | 続けてマウントオプションを指定する |
| `-t` | 続けてファイルシステムの種類を指定する（指定しない場合は自動で種類を推測） |
| `-r` | 読み取り専用でマウントする（`-o ro` と同じ） |
| `-w` | 読み書き可能でマウントする（既定） |
| `-v` | 詳細を表示する |
| `--bind` | 既にあるディレクトリを別の場所にも見せる |

```bash
$ sudo mount -a                      # fstab の設定をまとめてマウントする
$ sudo mount -o ro /dev/sdb1 /data   # 読み取り専用でマウントする
$ sudo mount -t xfs /dev/sdb2 /data  # ファイルシステムの種類を明示する
$ sudo mount -o remount,rw /         # マウントしたまま読み書き可能に切り替える
```

**補足 … `-o remount` は障害対応の定番です**

ルートファイルシステムが読み取り専用で上がってしまったとき、
再起動せずに書き込み可能へ戻すのに使います。

### -t と -o を組み合わせる

**意味** … 種類（`-t`）とマウントオプション（`-o`）は**役割が別**なので、両方まとめて指定できる

**例文** … ext3 ファイルシステムの `/dev/sda1` を `/export` に**読み取り専用で**マウントする

```bash
$ sudo mount -t ext3 -o ro /dev/sda1 /export   # 種類は ext3、読み取り専用で繋ぐ
```

**それぞれの役割**

```text
mount  -t ext3   -o ro   /dev/sda1   /export
        └──┬──┘  └─┬─┘  └───┬───┘  └──┬──┘
      種類の指定  オプション  デバイス名  マウントポイント
                （ro＝読み取り専用）
```

| 部分 | 何を指定しているか |
|:--|:--|
| `-t ext3` | **ファイルシステムの種類**を指定する |
| `-o ro` | **マウントオプション**を指定する。`ro` は読み取り専用 |
| `/dev/sda1` | **マウントするデバイス名** |
| `/export` | **マウントポイント** |

**結果を確認する**

```bash
$ findmnt /export                    # 実際に効いているオプションを確認する
TARGET   SOURCE     FSTYPE OPTIONS
/export  /dev/sda1  ext3   ro,relatime

$ sudo touch /export/x               # 読み取り専用なので書き込めない
touch: cannot touch '/export/x': Read-only file system
```

**間違えやすい書き方**

| 書き方 | どこが誤りか |
|:--|:--|
| `mount -t ro -o ext3 /dev/sda1 /export` | **`-t` と `-o` の中身が逆**。`ro` は種類ではなくオプション |
| `mount -t ext3 -o ro /export /dev/sda1` | **デバイス名とマウントポイントが逆** |
| `mount -a ext3 /dev/sda1 /export` | **`-a` は fstab をまとめてマウントする**オプション。種類の指定には使えない |

**覚え方**

```text
-t … type      … 何のファイルシステムか
-o … options   … どう扱うか（ro / rw / noexec …）
```

**補足 … `-r` は `-o ro` の短縮形です**

```bash
$ sudo mount -r /dev/sda1 /export            # -r だけでも読み取り専用になる
$ sudo mount -o ro /dev/sda1 /export         # こちらと同じ意味
```

複数のオプションを付けたいときは `-o` にカンマ区切りでまとめます。

```bash
$ sudo mount -t ext3 -o ro,noexec,nosuid /dev/sda1 /export   # 3つまとめて指定する
```

**補足 … 障害調査では読み取り専用マウントが基本です**

壊れかけたディスクや、証跡を保全したいディスクは
**必ず `-o ro` でマウント**します。書き込みが起きると、
復旧の可能性も証跡としての価値も失われます。

## fstab の設定は別ノートにある

**`mount` コマンドでつないだ状態は、再起動すると消えます。**
恒久的にマウントしたいときは **`/etc/fstab`** に設定を書きます。

| 知りたいこと | 見るところ |
|:--|:--|
| **6 つの設定項目**（デバイス名／マウントポイント／種類／オプション／dump／fsck） | [fstabの書き方](./fstabの書き方.md) |
| **デバイス名を `UUID=` で書く理由**と、`blkid` / `lsblk` での調べ方 | 同上 |
| **マウントオプションの一覧**（`defaults` の中身、`auto` / `noauto`、`user` / `users`） | 同上 |
| **起動時に自動マウントする条件**と、書き間違いからの守り方 | 同上 |

**このノートで押さえておくのは、`mount` コマンドとの関係だけ**です。

```bash
$ sudo mount /dev/sdb1 /data         # fstab に書いていないときは両方を指定する
$ sudo mount /data                   # fstab に書いてあれば、マウントポイントだけでよい
$ sudo mount -a                      # fstab に書かれたものを一括でマウントする
```

## umount コマンド

```text
umount [オプション] [マウントされているデバイス名、またはマウントポイント]
```

**コマンド名は `unmount` ではなく `umount`（n が無い）** です。ここもよくある打ち間違いです。

### 指定するのはどちらか片方だけ

**`umount` コマンドは「デバイス名」または「マウントポイント」のどちらかを指定すればよい**、
というのが最重要ポイントです。

```bash
$ sudo mount -t xfs /dev/sdb2 /data  # まずマウントしておく

$ sudo umount /dev/sdb2              # デバイス名で指定 … ○
$ sudo umount /data                  # マウントポイントで指定 … ○
```

**両方を書くと余計なエラーが出ます**

```bash
$ sudo umount /dev/sdb2 /data        # 両方書いた場合
umount: /data: not mounted.
```

`umount` は**引数を「アンマウント対象のリスト」として順に処理**します。
そのため最初の `/dev/sdb2` でアンマウントが成功し、続く `/data` は
**もうマウントされていない**のでエラーになります。
結果としてアンマウント自体はされますが、**書式としては誤り**です。

```text
umount /dev/sdb2 /data
        └──┬──┘ └─┬─┘
        1つ目を処理  2つ目を処理 → すでに外れているのでエラー
```

### umount の主なオプション

| オプション | 意味 |
|:--|:--|
| **`-a`** | **`/etc/mtab` ファイルに記載されているファイルシステムをすべてアンマウント** |
| **`-t 種類`** | **指定した種類のファイルシステムのみをアンマウント** |
| `-f` | 強制的にアンマウントする |
| `-l` | 遅延アンマウント（参照が無くなった時点で外す） |
| `-R` | 再帰的にアンマウントする |
| `-v` | 詳細を表示する |

**`-a` と `-t` を組み合わせる**

```bash
$ sudo umount -at xfs                # 現在マウントされている xfs をすべてアンマウントする
```

`-at xfs` は `-a -t xfs` の短縮形です。
`/etc/mtab` に記述されている **xfs 形式のファイルシステムだけ**が対象になります。

**注意 … `-a` は業務では使いません**

`umount -a` は**マウントされているものを手当たり次第に外そうとします**。
`/` や `/boot` まで対象に入るため、稼働中のサーバで実行してはいけません。
試験では正解の選択肢になりますが、実務では**対象を明示して 1 つずつ外す**のが鉄則です。

**注意 … `-f` と `-l` は最後の手段です**

```bash
$ sudo umount -f /data               # 強制的にアンマウントする
$ sudo umount -l /data               # 遅延アンマウント
```

技術的には可能ですが、**推奨されない方法**です。
他のユーザやプロセスの作業を強制的に中断することになり、**データの損失を招く恐れ**があります。
`-l` は「見た目上すぐ外れる」ので一見安全そうですが、
書き込み中のプロセスが残っていればデータは壊れます。

## アンマウントできないとき

**ユーザやプロセスが、ファイルシステムにあるファイルを操作中の場合や、
ファイルシステム内で操作をしている場合、そのファイルシステムはアンマウントできません。**

このような場合には `device is busy` や `target is busy` などのエラーメッセージが表示されます。
**具体的なメッセージはシステムや状況によって異なります。**

```bash
$ sudo umount /mnt/testpoint         # アンマウントを試みる
umount: /mnt/testpoint: target is busy.
```

### 正しい対処の順番

**ファイルシステムのアンマウントを行うためには、事前に、関連するプロセスを安全に終了させたり、
関連ファイルを操作中のユーザに通知して操作を終了してもらう必要が生じることがあります。**

```text
① 誰が使っているかを特定する    … fuser -m / lsof
        ↓
② そのユーザに連絡して終了してもらう（または安全にプロセスを止める）
        ↓
③ もう一度アンマウントする
```

**強制アンマウントは正解ではありません。** 順番を飛ばさないことが大切です。

### ① 使用中のプロセスを特定する

**`fuser` コマンドは、ファイルやファイルシステムを使用しているプロセスを特定することができるコマンド**です。

```bash
$ sudo fuser -m /mnt/testpoint       # そのファイルシステムを使っているプロセスを表示する
/mnt/testpoint:       3046
```

`-m` は「指定したファイルが属する**ファイルシステム全体**を対象にする」オプションです。

**より詳しく見たいときは `lsof`**

```bash
$ sudo lsof +D /mnt/testpoint        # そのディレクトリ配下を開いているプロセスを一覧する
COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
tail    3046 root    3r   REG    7,0        0   12 /mnt/testpoint/file1.txt
```

`lsof` はコマンド名・PID・ユーザ・開いているファイル名まで出るので、
**「誰に声をかければいいか」が分かります**。実務ではこちらのほうが役立ちます。

| コマンド | 分かること | 使いどころ |
|:--|:--|:--|
| `fuser -m マウントポイント` | PID だけ | まず犯人の数を知りたいとき |
| `fuser -mv マウントポイント` | PID ＋ ユーザ ＋ コマンド名 | もう少し情報が欲しいとき |
| `lsof +D ディレクトリ` | 開いているファイルまで | **誰に何を止めてもらうか決めるとき** |

### ② 操作を終了してもらう

```bash
$ sudo kill 3046                     # プロセスに終了を要求する
$ jobs                               # 終了したことを確認する
[1]+  Terminated              tail -f /mnt/testpoint/file1.txt &
```

**`kill` は「強制終了」ではありません。** 既定では TERM シグナルを送り、
プロセスに**片付けをしてから終わるよう「お願い」**します。
どうしても止まらないときだけ `kill -9`（KILL）を使いますが、
これは片付けをさせずに殺すため、書きかけのデータは失われます。

**自分のプロセスでない場合は、まず利用者に連絡します。** これが今回の問題の正解です。

### ③ アンマウントする

```bash
$ sudo umount /mnt/testpoint         # 今度は成功する（何も表示されない）
```

**エラーメッセージが表示されなければ成功**です。`umount` は成功時に何も言いません。

### やってはいけない対処

| 誤った対処 | なぜ誤りか |
|:--|:--|
| **`umount` の専用オプションで強制的にアンマウントする** | 技術的には可能だが**推奨されない**。他のユーザやプロセスの作業を強制的に中断することになり、**データの損失を招く恐れ**がある |
| **`/proc/self/mounts` と `/proc/mounts` を書き換える** | これらは**情報を確認するための読み取り専用ファイルであり編集できない**。仮に書き換えられても実際のマウント状態は変わらない |
| **管理者権限に変更して安全にアンマウントする** | **管理者権限を利用するだけでは安全にアンマウントできない**。使用中のファイルシステムをアンマウントするには、関連するプロセスを安全に終了させたり他のユーザに通知するなど、**さらに具体的な対処が必要** |

**自分がマウントポイントの中にいるだけでも busy になります**

意外な原因のトップがこれです。

```bash
$ cd /data                           # マウントポイントの中へ移動する
$ sudo umount /data                  # 自分のカレントディレクトリなので外せない
umount: /data: target is busy.

$ cd /                               # 外へ出る
$ sudo umount /data                  # 今度は成功する
```

## sync ディスクバッファを書き出す

**アンマウントとセットで問われるのが `sync`** です。

### なぜバッファがあるのか

**ディスクアクセスはメモリに比べると遅いため、書き込み命令があった場合には
いったんメモリ上に内容を保存し（ディスクバッファ）、
書き込み内容が溜まったらディスクバッファからディスクへ書き込みを行う、
という二段階の転送が行われています。**

```text
  アプリケーション
        │ write()
        ▼
  ディスクバッファ（メモリ上・速い）   ← ここでいったん受け止める
        │ まとめて書き出す
        ▼
  ディスク（遅い）
```

**これによりパフォーマンスを向上させています。**

**ところが、ディスクバッファ上にデータが保持されている状態で突然電源が落ちると、
そのデータが失われ、ファイルシステムに不整合が発生してしまうことがあります。**

### sync コマンド

**`sync` は、ディスクバッファの内容をすべて確実にディスクに書き込むコマンド**です。

```bash
$ sync                               # メモリ上のディスクバッファをディスクへ書き出す
```

**引数も出力もありません。** 書き終わるまで戻ってこないのが `sync` の仕事です。

| コマンド | ディスクバッファを書き出すか |
|:--|:--|
| **`sync`** | **○** |
| `mount` | ✕（マウントするだけ） |
| `umount` | **内部で `sync` を実行している** |
| `fsck` | ✕（整合性をチェックするだけ） |
| `fuser` | ✕（使用中のプロセスを調べるだけ） |

### umount の前に sync は要らない

**`umount` コマンドや `shutdown` コマンドは内部で `sync` を実行しているので、
それら操作を行う前に敢えて `sync` を行う必要はありません。**

**ただ、大昔にはそのような仕組みがなかったことがあり、
その時の名残で習慣的に `umount` などの前に `sync` を実行することもあります。**

**それでも `sync` を打つ場面**

| 場面 | 理由 |
|:--|:--|
| **USB メモリを物理的に抜く直前** | アンマウントを忘れたまま抜くと消える |
| **`dd` でイメージを書いた直後** | 書き込みが完了したか確認したい（[dd コマンド](./ddコマンド.md)） |
| **電源断の試験をする直前** | 意図的にバッファを空にしてから落とす |
| **仮想マシンのスナップショットを取る直前** | ゲスト側のバッファをディスクに落としておく |

**補足 … `sync` は「書き出し命令を出して待つ」だけ**

**ディスク自身が持つキャッシュまでは保証しません。**
より厳密に保証したい場合は、アプリケーション側で `fsync()` を使うか、
`dd` なら `conv=fsync` を付けます。

## 現在のマウント状況を調べる

**現在マウントされているファイルシステムを確認できる方法は 4 つあります。**
どれを使っても、見えるのは**同じ情報**です。

| 方法 | 種類 | 特徴 |
|:--|:--|:--|
| **`mount`（引数なし）** | コマンド | 一覧を表示。昔からの定番 |
| **`cat /etc/mtab`** | ファイル | 現在マウントされているファイルシステムの情報 |
| **`cat /proc/self/mounts`** | ファイル | 同上（カーネルが提供） |
| **`cat /proc/mounts`** | ファイル | 同上（カーネルが提供） |

**`cat /etc/fstab` は違います。** `/etc/fstab` は
**「マウントの設定ファイル」**であって、**いま何がマウントされているか**を示すものではありません。

```text
/etc/fstab            … これからどうマウントするか（設定・希望）
/etc/mtab             … いま実際に何がマウントされているか（現状）
/proc/self/mounts     … 同上
/proc/mounts          … 同上
```

「設定を書いたのにマウントされていない」という状況がありうるので、
**この 2 つは必ず区別**します。

### 4つの見え方

**`mount`（引数なし）**

```bash
$ mount                              # 読みやすい形で一覧表示する
/dev/mapper/VolGroup-lv_root on / type ext4 (rw)
proc on /proc type proc (rw)
sysfs on /sys type sysfs (rw)
devpts on /dev/pts type devpts (rw,gid=5,mode=620)
tmpfs on /dev/shm type tmpfs (rw,rootcontext="system_u:object_r:tmpfs_t:s0")
/dev/sda1 on /boot type ext4 (rw)
none on /proc/sys/fs/binfmt_misc type binfmt_misc (rw)
sunrpc on /var/lib/nfs/rpc_pipefs type rpc_pipefs (rw)
```

**`cat /etc/mtab`**

```bash
$ cat /etc/mtab                      # fstab と同じ6列の形式で並ぶ
/dev/mapper/vg_cent67-lv_root / ext4 rw 0 0
proc /proc proc rw 0 0
sysfs /sys sysfs rw 0 0
devpts /dev/pts devpts rw,gid=5,mode=620 0 0
（略）
```

**`cat /proc/self/mounts`**

```bash
$ cat /proc/self/mounts              # カーネルが持っている情報を直接読む
rootfs / rootfs rw 0 0
proc /proc proc rw,relatime 0 0
sysfs /sys sysfs rw,seclabel,relatime 0 0
（略）
```

**`cat /proc/mounts`**

```bash
$ cat /proc/mounts                   # /proc/self/mounts とほぼ同じ内容
rootfs / rootfs rw 0 0
proc /proc proc rw,relatime 0 0
sysfs /sys sysfs rw,seclabel,relatime 0 0
（略）
```

**書式の違い**

```text
mount コマンド … デバイス on マウント先 type 種類 (オプション)
ファイル       … デバイス マウント先 種類 オプション 0 0   ← fstab と同じ6列
```

**ファイル側は `/etc/fstab` と同じ 6 列**なので、そのまま比較しやすいのが利点です。

**補足 … `/proc/self/mounts` と `/proc/mounts` の違い**

**この 2 つの内容は、マウント名前空間（mount namespace）の違いにより、
ユーザによって異なる場合があります。**
コンテナやユーザごとに別のマウント空間を持てる仕組みで、
**`/proc/self/` は「いま実行しているプロセスから見た世界」**を返します。
通常のサーバ運用では同じ内容だと考えて構いません。

**補足 … `/etc/mtab` の実体はシンボリックリンク**

最近のディストリビューションでは、`/etc/mtab` は
`/proc/self/mounts` へのシンボリックリンクになっています。

```bash
$ ls -l /etc/mtab                    # 実体を確認する
lrwxrwxrwx 1 root root 19 May  8 16:23 /etc/mtab -> ../proc/self/mounts
```

昔は `mount` コマンドが `/etc/mtab` を自分で書き換えていましたが、
**カーネルが持つ情報のほうが正確**なため、いまはそちらへ委ねる形になっています。
そのため、**この 4 つはすべて同じ情報源を見ている**ことになります。

### 実務で使い分けるなら

| コマンド | 特徴 |
|:--|:--|
| `mount`（引数なし） | 一覧を表示。昔からの定番 |
| **`findmnt`** | **ツリー表示で見やすい**。現在の標準的なコマンド |
| `df -h` | **空き容量**とセットで見たいとき |
| `lsblk -f` | **デバイス側**から見たいとき（種類・UUID・マウント先） |
| `cat /proc/mounts` | カーネルが持っている生の情報。**スクリプトで解析するとき** |

```bash
$ findmnt /data                      # 特定のマウントポイントを調べる
TARGET SOURCE     FSTYPE OPTIONS
/data  /dev/loop0 ext4   rw,relatime

$ findmnt --verify                   # /etc/fstab の記述に誤りが無いか検査する
$ df -h /data                        # 空き容量を確認する
$ lsblk -f                           # デバイス側から俯瞰する
```

**障害調査の入口は `df -h` → `findmnt` → `lsblk -f` の順**が効率的です。
「容量が足りない」のか「そもそもマウントされていない」のかを、この順で切り分けられます。
