## デバイスファイルとは

**システムに接続されている物理的なデバイスにアクセスする方法として、
`/dev` 内の仮想ファイル（デバイスファイル）があります。**

**様々なデバイスにデバイスファイルとしてアクセスが可能で、
ハードディスクについてもデバイスファイルが用意されます。**

```text
  物理的なハードディスク
        ▲
        │ カーネルのドライバが仲立ちする
        ▼
  /dev/sda   ← デバイスファイル（仮想ファイル）
        ▲
        │ ユーザはこれを「ファイルのように」扱う
        ▼
  mkfs / mount / dd / hdparm …
```

**「ハードディスクは Linux 上ではどのようなインタフェースで操作できるか」
という問いの答えは `/dev` 内の仮想ファイルとして操作できる**です。

| 選択肢 | 正誤 | 理由 |
|:--|:-:|:--|
| **`/dev` 内の仮想ファイルとして操作できる** | **○** | **デバイスファイルがこれ** |
| `/proc` 内の仮想ファイルとして操作できる | ✕ | **`/proc` の一部は接続されているデバイスの情報を持つが、あくまで情報を表示するためのインタフェース**。「操作」はできない |
| `/sys` 内の仮想ファイルとして操作できる | ✕ | **`/sys` は `/proc` と近い役割**でカーネルとユーザ間のインタフェースになるが、**デバイスを直接操作するためのものではない** |
| カーネルが管理しており、通常の方法でアクセスできるインタフェースは存在しない | ✕ | **デバイスファイルが用意されている** |

```text
  /dev    デバイスを 操作 する      … ブロックデバイス / キャラクタデバイス
  /proc   プロセスとカーネルの 情報   … 読むだけ
  /sys    デバイスとドライバの 情報   … 読むだけ（一部は書けるが操作用ではない）
```

`/proc` と `/sys` の役割は
[FHSとディレクトリ構成](./FHSとディレクトリ構成.md) にもあります。

## 記憶装置のデバイスファイル一覧

**記憶装置のデバイスファイルは、接続の形態や位置によって名前が決まります。**

| デバイスファイル | 説明 |
|:--|:--|
| **`/dev/sda`** | **SCSI / SATA HDD の 1 番目** |
| **`/dev/sdb`** | **SCSI / SATA HDD の 2 番目** |
| **`/dev/sdc`** | **SCSI / SATA HDD の 3 番目** |
| **`/dev/sdd`** | **SCSI / SATA HDD の 4 番目** |
| **`/dev/hda`** | **IDE の Primary Master** |
| **`/dev/hdb`** | **IDE の Primary Slave** |
| **`/dev/hdc`** | **IDE の Secondary Master** |
| **`/dev/hdd`** | **IDE の Secondary Slave** |
| **`/dev/sr0`** | **SCSI / SATA CD-ROM の 1 番目** |
| **`/dev/sr1`** | **SCSI / SATA CD-ROM の 2 番目** |
| **`/dev/st0`** | **SCSI テープの 1 番目** |
| **`/dev/st1`** | **SCSI テープの 2 番目** |

**IDE 接続のハードディスクは `hd` で始まるデバイスファイル、
SCSI / SATA 接続のハードディスクは `sd` で始まるデバイスファイル**です。

**IDE の 4 つの位置**

**IDE は 1 本のケーブルで 2 台のデバイスを接続**し、
**片方をマスター、もう片方をスレーブ**と呼んでいました。
**ケーブルが 2 本（Primary / Secondary）あるので、合計 4 台**です。

```text
  Primary ケーブル   ┬─ Master  → /dev/hda
                     └─ Slave   → /dev/hdb
  Secondary ケーブル ┬─ Master  → /dev/hdc
                     └─ Slave   → /dev/hdd
```

**`a` → `b` → `c` → `d` の順に、
Primary Master → Primary Slave → Secondary Master → Secondary Slave** と並びます。

**存在しないデバイスファイル**

| 見かける名前 | 実際は |
|:--|:--|
| **`/dev/cdrom0`** | **通常存在しない**。ディストリビューションによっては **`/dev/sr0` へのシンボリックリンクとして `/dev/cdrom`** が作られる |
| **`/dev/scd`** | **通常存在しない**。ディストリビューションによっては **`/dev/sr0` へのシンボリックリンクとして `/dev/scd0`** が作られる |
| `/dev/raid1` / `/dev/rd1` | **存在しない**。RAID デバイスは `/dev/md0` |

## 名前から接続を読む

**「このデバイスファイルは物理的にどう接続されているか」**という問われ方をします。
**表を逆から引くだけ**です。

| デバイスファイル | どう接続されているか |
|:--|:--|
| **`/dev/sda`** | **SATA のポート 1 番** |
| **`/dev/sdb`** | **SATA のポート 2 番** |
| **`/dev/sdc`** | **SATA のポート 3 番** |
| **`/dev/hda`** | **IDE でプライマリマスター** |
| **`/dev/hdb`** | **IDE でプライマリスレーブ** |
| **`/dev/hdc`** | **IDE でセカンダリマスター** |
| **`/dev/hdd`** | **IDE でセカンダリスレーブ** |

**解き方の手順**

```text
  ① 先頭2文字を見る
       sd → SCSI / SATA    →  3文字目のアルファベットが「何台目」
       hd → IDE            →  3文字目のアルファベットが「どの位置」
  ② 3文字目を a=1 / b=2 / c=3 / d=4 に読み替える
  ③ IDE なら Primary/Secondary × Master/Slave の表に当てる
```

**CD-ROM が混ざっても迷わない**

**「HDD 2 本で RAID1 を構成し、CD-ROM ドライブが 1 台内蔵されたサーバ。
CD-ROM のデバイスファイル名は」**という問いでは、
**HDD の本数は関係ありません。**

```text
  HDD 2本      → /dev/sda, /dev/sdb    （sd 系で数える）
  CD-ROM 1台   → /dev/sr0              （sr 系で 別に 数える）
```

**`sd` と `sr` は別の系列で数える**ので、
**HDD が何本あっても CD-ROM の 1 台目は `/dev/sr0`** です。

> **SCSI CD-ROM のドライバ名は `sr`** です。
> **この名前は Linux カーネルのソースコード（`drivers/scsi/sr.c`）で定義されています。**
> **複数台の SCSI CD-ROM には順に `sr0`、`sr1`… のデバイスファイルが割り当てられます。**

## ディスクとパーティションの区別

**`/dev/sda` のように数字のついていないデバイスファイルは、
接続されている「ハードディスクそのもの」を表します。**

**実際にマウントする際などに使うデバイスファイルは `/dev/sda1` 等と数字がついたものですが、
こちらはハードディスクではなく「そのハードディスク上のパーティション」を指すデバイスファイル**です。

```bash
$ ls -l /dev | grep sd                 # SATA ハードディスクを一覧する
brw-rw---- 1 root disk 8, 0 5月 19 05:26 sda
brw-rw---- 1 root disk 8, 1 5月 19 05:26 sda1
brw-rw---- 1 root disk 8, 2 5月 19 05:26 sda2
```

**この出力の正しい読み方**

| 読み方 | 正誤 | 理由 |
|:--|:-:|:--|
| **`sda` はハードディスク、`sda1` と `sda2` はパーティションである** | **○** | **数字の有無が境目** |
| `sda`、`sda1`、`sda2` は同じハードディスク上の異なるパーティションである | ✕ | **`sda` はパーティションではなくハードディスク全体** |
| `sda`、`sda1`、`sda2` はそれぞれ異なるハードディスクである | ✕ | **異なるディスクなら `sdb`、`sdc` のように3文字目が変わる** |
| `sda` は `sda1` の別名である | ✕ | **同じものを指しているわけではない** |
| `sda1` と `sda2` はハードディスク、`sda` はそれらをまとめた RAID アレイである | ✕ | **RAID アレイのデバイス名は `/dev/md0`** |

**読み解きの例**

```text
  /dev/sdb3  →  SATA 接続で 2 番目 のハードディスクの 3 番目 のパーティション
                 │        │              │
                 sd       b              3
                 SCSI/SATA 2台目        パーティション3
```

**これらを混同するとエラーのもとになるので、区別する必要があります。**

```bash
$ sudo mkfs -t ext4 /dev/sda           # ディスク全体を潰してしまう（パーティションテーブルごと消える）
$ sudo mkfs -t ext4 /dev/sda1          # 正しくはパーティションを指定する
```

**`lsblk` で親子関係を見る**のがいちばん分かりやすい方法です。

```bash
$ lsblk                                # ディスクとパーティションの階層が見える
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0  100G  0 disk
├─sda1   8:1    0    1G  0 part /boot
└─sda2   8:2    0   99G  0 part /
```

## 接続規格の系譜

```text
  IDE（ATA / PATA）  ── 古い。パラレル転送。マスター/スレーブ
        │
        ▼
  SATA（シリアルATA）── 現在の主流。シリアル転送。マスター/スレーブ という概念は 無い
        │
        ▼
  NVMe              ── SSD 向け。PCI Express バスを使う

  SCSI              ── サーバ向けの別系統。iSCSI としてネットワーク越しにも使う
```

### IDE と ATA

**IDE（ATA）はハードディスクや光学ドライブを接続するための規格**です。
**長い歴史があり、時代に応じて多くの転送モード・規格が作られました。**

| 特徴 | 内容 |
|:--|:--|
| **転送方式** | **パラレル転送**（あとから PATA とも呼ばれる） |
| **1 本のケーブルに** | **2 台**（マスターとスレーブ） |
| **デバイスファイル** | **`hd` で始まる** |
| **最大速度** | **もっとも高速なモードでも規格上 133.3MB/s 程度** |

**転送モードは PIO モード、DMA モード、Ultra DMA モードの 3 つに大別できます。**

| モード | 誰が転送するか | 特徴 |
|:--|:--|:--|
| **PIO モード** | **CPU が直接** IDE 接続したデバイスからメモリへデータを転送する | **もっとも原始的**。**他の処理にも使う CPU に負担をかけてしまう点が欠点** |
| **DMA モード** | **DMA コントローラと呼ばれる CPU とは別の物理的なチップ**が転送を処理する | **PIO モードと異なり CPU を使わないため、比較的高速で負担がかかりません** |
| **Ultra DMA モード** | 同上 | **DMA を拡張したもので、さらに高速な転送をサポート** |

**「PIO モードでは CPU を使うが、DMA モードでは専用のコントローラを使う」**——これが正しい説明です。

| 説明 | 正誤 |
|:--|:-:|
| **PIO モードでは CPU を使うが、DMA モードでは専用のコントローラを使う** | **○** |
| PIO モードでは専用のコントローラを使うが、DMA モードでは CPU を使う | ✕（**逆**） |
| PIO モードでは光学ドライブが扱えないが、DMA モードでは扱える | ✕（**どちらでも扱える**） |
| PIO モードでは光学ドライブが扱えるが、DMA モードでは扱えない | ✕（同上） |

転送モードの設定は
[hdparmによるディスクパラメータ](./hdparmによるディスクパラメータ.md) にあります。

### SATA

**SATA とは、コンピュータにハードディスクなどの記憶装置や DVD などの光学ドライブを
接続するためのインタフェース規格**です。

**かつての IDE（ATA）接続に取って代わる接続方法で、
シリアル転送を行うためにケーブル・端子が小さくて済み、また高速な転送が可能**です。

| 説明 | 正誤 | 理由 |
|:--|:-:|:--|
| **ハードディスクの接続に利用できる規格である** | **○** | **主にハードディスク、光学ディスクの接続に使われる** |
| **ATA よりも高速な転送が行える** | **○** | **下の速度比較のとおり** |
| DVD ドライブの接続には利用できない規格である | ✕ | **CD / DVD / Blu-ray Disc ドライブの接続にも利用可能** |
| マスター・スレーブの概念が存在する | ✕ | **これは SATA より古い規格である ATA(PATA) についての説明** |

**速度の比較**

| 規格 | 最大速度 |
|:--|:--|
| **ATA**（もっとも高速なモードでも） | **133.3MB/s 程度** |
| **SATA**（もっともバージョンの古い規格でも） | **150MB/s** |
| **SATA II** | **300MB/s** |
| **SATA III** | **600MB/s** |

**Linux システムにおいては、SATA で接続したハードディスクは
`/dev/sda` など `sd` で始まる名前のデバイスファイルを通じて操作することができます。**

### AHCI

**AHCI（Advanced Host Controller Interface）は、
IDE に比べてはるかに高速なシリアル ATA（SATA）を活かせるインターフェース仕様として登場した規格**で、
**インテルが策定しています。**

**IDE との互換性を重視した SATA の規格 SATA1.0 では速度より互換性が重視され、性能は犠牲となりましたが、
SATA2.0 で AHCI は規格化され、SATA 本来の機能・性能を満たすことができるようになりました。**

```text
  SATA1.0   IDE との互換性を優先  → 性能が出ない
       ▼
  SATA2.0   AHCI が規格化        → SATA 本来の性能が出る
       ▼
  （SSD の時代）NVMe             → SATA/AHCI では足りず、PCIe へ
```

**似た略語の整理**

| 略語 | 何か |
|:--|:--|
| **AHCI** | **SATA の仕様を定義し、ストレージとメモリ間のデータ交換などについてインテルが策定した規格** |
| **NVMe** | **PCI Express バスから SSD に接続するための規格** |
| **PCIe** | **拡張カードを繋ぐバスの規格そのもの**（NVMe はこの上に乗る） |
| **SSD** | **記憶装置そのもの**（規格ではない） |
| **UEFI** | **旧来のファームウエアである BIOS に代わる新しいファームウエア**（ストレージ規格ではない） |

**AHCI と NVMe はどちらも「SSD の繋ぎ方」**ですが、
**AHCI は SATA 用、NVMe は PCIe 用**です。詳しくは [SSDとNVMe](./SSDとNVMe.md) にあります。

### SCSI

**SCSI（Small Computer System Interface）とは、
PC やサーバに直接接続されたハードディスクなどの周辺機器を制御し、
データ転送を行うための規格の一つ**です。

| 用語 | 意味 |
|:--|:--|
| **イニシエータ** | **ホスト側**（コマンドを出す側） |
| **ターゲット** | **デバイス側**（コマンドを受ける側） |
| **LUN**（Logical Unit Number） | **記憶装置を識別するための論理的な単位** |
| **WWID / WWN** | **SAN において記憶装置を一意に識別するためのもの** |

**この SCSI の機能を TCP/IP ネットワーク上で利用できるようにしたものが iSCSI**です。
詳しくは [iSCSIの設定と管理](./iSCSIの設定と管理.md) にあります。

## シリアルATAがSCSIとして見える理由

**Linux はシリアル ATA 接続のデバイスを SCSI 接続と認識し、デバイスドライバも SCSI 用のものを使用します。**

**だから SATA のディスクなのに `sd`（SCSI Disk）という名前になります。**

```text
  物理的には  SATA で繋がっている
        ▼
  Linux は    SCSI として扱う（libata が SCSI 層に橋渡しする）
        ▼
  名前は      /dev/sda … sd = SCSI Disk
```

**この仕組みのおかげで、規格ごとに名前を覚え分けなくて済みます。**

| 物理的な接続 | Linux から見た名前 |
|:--|:--|
| **SATA HDD** | **`/dev/sda`**（SCSI 扱い） |
| **SCSI HDD** | **`/dev/sda`**（そのまま） |
| **USB メモリ** | **`/dev/sdb`** など（USB マスストレージも SCSI 扱い） |
| **SAS HDD** | **`/dev/sda`** など |
| **IDE HDD**（古い環境） | **`/dev/hda`** |
| **NVMe SSD** | **`/dev/nvme0n1`**（SCSI 扱いではない） |

> **近年のカーネルでは IDE 接続のディスクも `libata` 経由で `/dev/sda` として見える**ことがあります。
> **試験で問われるのは「`hd` は IDE、`sd` は SCSI / SATA」という古典的な対応**なので、
> **実機と食い違っても慌てない**でください。
