## 書式は3つのブロック

```text
find  [検索起点ディレクトリ]  [検索式]  [アクション]
        どこから探すか          何を探すか   見つけたらどうするか
```

**3 つとも省略できます。** 省略したときの既定はこうです。

| ブロック | 省略したときの既定 |
|:--|:--|
| **検索起点** | **カレントディレクトリ** |
| 検索式 | すべてにマッチ |
| **アクション** | **`-print`**（パスを改行区切りで表示） |

```bash
$ find                                 # カレントディレクトリ以下をすべて表示する
$ find .                               # 上と同じ意味
$ find ./                              # 上と同じ意味
$ find $PWD                            # 上と同じだが、絶対パスで表示される
```

**補足** … **`$PWD` を起点にすると出力が絶対パスになります。**
スクリプトで結果を他所へ渡すときは、**相対パスだと実行ディレクトリに依存する**ので絶対パスが安全です。

**検索式は「テスト」、アクションは「動作」**です。
`-name` や `-type` は**真偽を判定する条件**、`-print` や `-exec` は**実際に何かをする**もの、と分けて覚えます。

---

### 順番を入れ替えると動かない

**3 つとも省略できますが、「書く順番」は入れ替えられません。**
**検索起点は必ず検索式より前**です。

```bash
$ find -uid 0 .                        # 起点をうしろに書いてしまった
find: paths must precede expression: `.'
find: possible unquoted pattern after predicate `-uid'?
```

**`paths must precede expression`（パスは式より先に書け）**という、そのままのメッセージが出ます。

| 書き方 | 成立するか | 理由 |
|:--|:-:|:--|
| **`find /var/log -user root -print`** | **○** | **起点 → 検索式 → アクション**の順 |
| **`find /var/log -uid 0`** | **○** | アクションは省略できる（既定は `-print`） |
| `find -user root` | **△** | 動くが**カレントディレクトリが起点**になる。特定のディレクトリを指定したい問いでは誤り |
| `find -uid 0 /var/log` | **✕** | **起点が検索式より後ろ**にある |
| `find /var/log httpd.conf -name` | **✕** | 検索式の**値だけ先に書いている** |
| `find -name httpd.conf /etc` | **✕** | 起点が最後にある |

### 検索式をクォートで囲まない

**検索式そのものを引用符で囲むと、1 つの長い述語名として扱われて失敗します。**

```bash
$ find . '-user root'                  # 検索式ごとクォートしてしまった
find: unknown predicate `-user root'
```

**`unknown predicate`（そんな述語は知らない）**と言われます。
**`-user` と `root` の間の空白まで名前に含まれてしまう**ためです。

| 書き方 | 成立するか |
|:--|:-:|
| **`find /var/log -user root`** | **○** |
| **`find . -name "*.log"`** | **○**（**値だけ**を囲むのは正しい） |
| `find /var/log '-user root'` | **✕**（**検索式ごと**囲んでいる） |

**引用符は通常、正規表現やワイルドカードを含む「値」を指定する際に使います。**
**`-name "*.log"` のように、シェルに展開させたくない値だけを囲む**のが正しい使い方です
（詳しくは [名前で探す](#名前で探す)）。

## 検索式でしぼり込む

### 名前で探す

**意味** … **`-name` はファイル名で検索します。** ワイルドカードが使えます。

**例文**

```bash
$ find /var/log -name "*.log"          # 拡張子が .log のものを探す
$ find . -name "dir*"                  # dir で始まる名前を探す
$ find . -iname "A.TXT"                # 大文字小文字を区別せずに探す
./a.txt
```

**補足** … **ワイルドカードは必ずクォートします。**
クォートしないと**シェルが先に展開してしまい**、`find` に届く前に別物になります。

| 書き方 | 意味 |
|:--|:--|
| **`-name "*.f"`** | **0 文字以上の文字列 ＋ `.f`**。`abc.f` も `.f` もマッチする |
| `-iname` | 大文字小文字を区別しない |
| `-path "*/sub/*"` | **パス全体**に対してマッチさせる |
| `-regex` | 正規表現で指定する |

---

### 種類で探す

**意味** … **`-type` はファイルの種類で検索します。**

| 指定 | 種類 |
|:--|:--|
| **`f`** | **通常ファイル** |
| **`d`** | **ディレクトリ** |
| **`l`** | **シンボリックリンク** |
| `b` | ブロックデバイス |
| `c` | キャラクタデバイス |
| `p` | 名前付きパイプ |
| `s` | ソケット |

**例文**

```bash
$ find . -type f                       # 通常ファイルだけを探す
$ find . -type d                       # ディレクトリだけを探す
$ find . -maxdepth 1 -type l           # シンボリックリンクだけを探す
./link.txt
```

**補足** … **「全てのファイル」と言われたら `-type f`** です。
指定しないと**ディレクトリも結果に混ざる**ので、`-exec` と組み合わせたときに意図しない動作になります。

### 時刻で探す

| 検索式 | 何を見るか |
|:--|:--|
| **`-mtime 日数`** | **最終更新日**（内容が変わった日） |
| **`-atime 日数`** | **最終アクセス日**（読まれた日） |
| `-ctime 日数` | ステータス変更日（権限や所有者が変わった日） |
| `-mmin 分` / `-amin 分` | 分単位で指定する |
| `-newer ファイル` | 指定したファイルより新しいもの |

**数字の前の符号が肝心です。**

```text
  -mtime 3    ちょうど 3 日前（72〜96時間前）
  -mtime +3   3 日より前（古い）      ← 「+ は 古い」
  -mtime -3   3 日以内（新しい）      ← 「- は 新しい」
```

**例文**

```bash
$ find . -maxdepth 1 -type f -mtime +2   # 2日より古いファイルを探す
./old.txt
$ find . -maxdepth 1 -type f -mtime -1   # 24時間以内に更新されたファイルを探す
./c.log
./a.txt
```

**補足** … **`+` と `-` を取り違えると、消す対象が正反対になります。**
`-delete` と組み合わせる前は、**必ず `-print` で対象を確認**します。

`atime` / `mtime` / `ctime` の違いは
[ファイルの種類とタイムスタンプ](../01_シェルとコマンドライン/ファイルの種類とタイムスタンプ.md) にあります。

---

### サイズで探す

**意味** … **`-size` はファイルサイズで検索します。** 単位を後ろに付けます。

| 単位 | 意味 |
|:--|:--|
| `c` | バイト |
| `k` | **キビバイト**（1,024 バイト） |
| `M` | **メビバイト**（1,024 × 1,024 バイト） |
| `G` | **ギビバイト**（1,024 × 1,024 × 1,024 バイト） |
| （無し） | **512 バイトブロック** |

**例文**

```bash
$ find . -maxdepth 1 -type f -size +5k   # 5KBより大きいファイルを探す
./big.bin
$ find . -maxdepth 1 -type f -size -5k   # 5KBより小さいファイルを探す
./c.log
./a.txt
$ find . -maxdepth 1 -type f -size 10k   # ちょうど10KBのファイルを探す
./big.bin
```

**補足** … **単位を書き忘れると 512 バイト単位**になります。
`-size +100` は「100MB より大きい」ではなく「51200 バイトより大きい」です。

```bash
$ find /var -type f -size +100M          # 100MBより大きいファイルを探す（容量逼迫の犯人探し）
```

### 所有者と権限で探す

| 検索式 | 何を見るか |
|:--|:--|
| **`-user ユーザ名`** | **所有者のユーザ名またはユーザID** |
| **`-uid ユーザID`** | **所有者のユーザID** |
| `-group グループ名` | 所有グループ |
| `-gid グループID` | 所有グループのID |
| `-nouser` / `-nogroup` | **所有者が存在しない**（ユーザ削除後の置き去り） |
| **`-perm アクセス権`** | **アクセス権で検索** |

**`-user` はユーザ名でもユーザIDでも受け取れます。**

**root は、ユーザID が `0`、ユーザ名が `root` のユーザ**なので、
**`-uid 0` / `-user 0` / `-user root` のいずれを使っても同じ結果**になります。

```bash
$ find . -uid 0                        # ユーザIDで指定する
.
./r1
./r2
$ find . -user 0                       # -user に数値を渡してもよい（結果は同じ）
.
./r1
./r2
$ find . -user root                    # ユーザ名で指定する（結果は同じ）
.
./r1
./r2
```

| 書き方 | 意味 |
|:--|:--|
| **`-uid 0`** | **ユーザIDで指定**（数値しか受け取らない） |
| **`-user 0`** | **`-user` は数値も受け取る**ので、これも root になる |
| **`-user root`** | **ユーザ名で指定** |

**「`-user` は数値も受け取る」**——ここが「すべて選べ」の設問で効いてきます。
**逆に `-uid` にユーザ名は渡せません。**

**`/var/log` 配下で所有者が root のものを探す、という問いの正解は 3 つ**です。

```bash
$ find /var/log -uid 0                 # ① ユーザIDで
$ find /var/log -user 0                # ② -user に数値を渡して
$ find /var/log -user root -print      # ③ ユーザ名で（-print は省略してもよい）
```

**`-perm` は 3 つの書き方で意味が変わります。**

| 書き方 | 意味 |
|:--|:--|
| **`-perm 644`** | **ぴったり 644 のもの** |
| **`-perm -644`** | **644 のビットを「すべて含む」もの**（それ以上の権限があってもよい） |
| **`-perm /111`** | **指定したビットの「いずれか」を持つもの** |

**例文**

```bash
$ find . -maxdepth 1 -type f -perm 644   # ぴったり644のものを探す
./a.txt
$ find . -maxdepth 1 -type f -perm -044  # 「その他」に読み権限があるものを探す
./c.log
./a.txt
$ find . -maxdepth 1 -type f -perm /111  # 実行ビットがどれか立っているものを探す
./c.log
```

**補足** … **セキュリティの棚卸しで使う定番**です。

```bash
$ sudo find / -type f -perm -4000 2>/dev/null   # SUID が付いたファイルを洗い出す
```

SUID については
[SGID 特殊パーミッション](../03_ユーザ管理とパーミッション/SGID_特殊パーミッション.md) を参照してください。

### 階層の深さを絞る

| 検索式 | 意味 |
|:--|:--|
| **`-maxdepth 階層数`** | **指定した階層まで**検索する |
| **`-mindepth 階層数`** | **指定した階層から下**を検索する |

**`-maxdepth` は「何階層目まで」、`-mindepth` は「何階層以降を」検索するのかを指定します。**

**3 階層のディレクトリで、数字を変えながら実際に動かした結果**です。

```bash
$ ls -R .                                # 3階層のディレクトリを用意した
.:
dir1

./dir1:
dir2

./dir1/dir2:
dir3

./dir1/dir2/dir3:
```

```bash
$ find . -maxdepth 1 -type d             # 1階層目まで
.
./dir1
$ find . -maxdepth 2 -type d             # 2階層目まで
.
./dir1
./dir1/dir2
$ find . -maxdepth 3 -type d             # 3階層目まで
.
./dir1
./dir1/dir2
./dir1/dir2/dir3
```

```bash
$ find . -mindepth 1 -type d             # 1階層目以降（起点の . が消える）
./dir1
./dir1/dir2
./dir1/dir2/dir3
$ find . -mindepth 2 -type d             # 2階層目以降
./dir1/dir2
./dir1/dir2/dir3
$ find . -mindepth 3 -type d             # 3階層目以降
./dir1/dir2/dir3
```

**読み取れること**

| 観察 | 意味 |
|:--|:--|
| **`-maxdepth` は数字を増やすほど結果が増える** | **上から掘る深さの上限** |
| **`-mindepth` は数字を増やすほど結果が減る** | **浅いものを捨てる下限** |
| **`-maxdepth 1` には起点の `.` が含まれる** | **起点そのものが「深さ 0」**として扱われる |
| **`-mindepth 1` で起点の `.` が消える** | **深さ 0 を除外している**から |

```text
  深さ 0    .                    ← 起点そのもの
  深さ 1    ./dir1
  深さ 2    ./dir1/dir2
  深さ 3    ./dir1/dir2/dir3
```

**「起点は深さ 0」**と覚えておくと、`-mindepth 1` の意味がすぐ分かります。

**例文**

```bash
$ find . -maxdepth 1 -type f             # 直下のファイルだけを見る（掘らない）
$ find . -mindepth 2 -type f             # 2階層目より下だけを見る
./sub/b.txt
```

**補足** … **`-maxdepth 1` は `ls` に近い動き**になります。
**大きなディレクトリを調べるときは、まず `-maxdepth 1` で当たりを付ける**と速く済みます。

> **`-depth` という指定も存在します。**
> これは階層数を取るものではなく、**「ディレクトリの中身を先に処理してからディレクトリ自身を処理する」**という
> 探索順序の指定です（GNU findutils 4.9.0 の `--help` で確認）。
> **階層を絞りたいときに使うのは `-maxdepth` / `-mindepth`** で、`-depth` ではありません。

## アクションで何かをする

### print と print0

| アクション | 何をするか |
|:--|:--|
| **`-print`** | **検索結果を改行で区切って表示する**（既定の動作） |
| **`-print0`** | **検索結果を NUL 文字（`\0`）で区切って表示する** |

**例文**

```bash
$ find . -maxdepth 1 -name "dir*" -print | od -c | head -3   # 区切りが改行(\n)であることを見る
0000000   .   /   d   i   r       3  \n   .   /   d   i   r       2  \n
0000020   .   /   d   i   r       1  \n
```

```bash
$ find . -maxdepth 1 -name "dir*" -print0 | od -c | head -3  # 区切りがNUL(\0)であることを見る
0000000   .   /   d   i   r       3  \0   .   /   d   i   r       2  \0
0000020   .   /   d   i   r       1  \0
```

**補足** … **`-print` は既定の動作**なので、
**`-print` も `-print0` も書かなければ `-print` を指定したときと同じ結果**になります。
**`-print0` を書く意味は、次の節で出てくる「空白問題」への対策**です。

> **NUL 文字（`\0`、16 進数で `00`）は制御コードのひとつ**で、
> **C 言語やさまざまなデータ形式で文字列の終端を意味します。**
> **ファイル名に含めることができない唯一の文字**なので、区切りとして安全に使えます。

### exec でコマンドを実行する

**意味** … **`-exec コマンド {} \;` で、検索結果のファイルに対してコマンドを実行します。**

```text
  find . -type f -exec wc -w {} \;
                      │    │   └─ コマンドの終わりを表す
                      │    └───── 検索結果のファイルに置き換わる
                      └────────── 実行するコマンド
```

**例文**

```bash
$ find . -type f -exec wc -w {} \;     # 見つかった各ファイルの単語数を表示する
0 ./c.log
5 ./sub/b.txt
3 ./a.txt
```

**`{}` と `\;` の意味**

| 記号 | 意味 |
|:--|:--|
| **`{}`** | **検索結果のファイルに置き換えられる** |
| **`;`** | **`-exec` で実行するコマンドの終了を意味する** |
| **`\`** | **`;` はメタキャラクタなので、シェルに解釈されないようエスケープする** |

**エスケープを忘れるとどうなるか**

```bash
$ find . -maxdepth 1 -name a.txt -exec echo {} ;   # \ を忘れた場合
find: missing argument to `-exec'
```

**シェルが `;` をコマンドの区切りとして先に食べてしまう**ため、
`find` からは `-exec echo {}` までしか見えず、**引数が足りない**と怒られます。
**`\;` のほかに `';'` や `";"` と書いても構いません。**

クォートとエスケープについては
[クォートとエスケープ](../01_シェルとコマンドライン/クォートとエスケープ.md) を参照してください。

**`-exec` は複数書ける**

```bash
$ find . -maxdepth 1 -name c.log -exec echo FIRST {} \; -exec echo SECOND {} \;   # 左から順に実行される
FIRST ./c.log
SECOND ./c.log
```

**左から順に実行されます。**

---

### セミコロンとプラスの違い

**`-exec` の終わり方には 2 種類あります。**

| 書き方 | 実行のされ方 |
|:--|:--|
| **`-exec コマンド {} \;`** | **1 ファイルにつき 1 回**コマンドを実行する |
| **`-exec コマンド {} +`** | **見つかった分をまとめて**、できるだけ少ない回数で実行する |

**例文**

```bash
$ find . -type f -exec echo BATCH {} +   # まとめて1回で渡される
BATCH ./c.log ./sub/b.txt ./a.txt
```

```bash
$ find . -type f -exec sh -c 'echo "回:$#"' _ {} +   # 引数の個数を数える
回:3
```

**1 回の実行で 3 つの引数が渡された**ことが分かります。
`\;` なら 3 回に分かれて実行されます。

| | **`\;`** | **`+`** |
|:--|:--|:--|
| 実行回数 | **ファイルの数だけ** | **できるだけ少なく** |
| 速さ | 遅い | **速い** |
| 使える場面 | `{}` を途中に何度でも置ける | **`{}` はコマンドの末尾に 1 回だけ** |

**補足** … **ファイル数が多いときは `+` が圧倒的に速い**です。
**1 万ファイルなら、`\;` は 1 万回プロセスを起動**します。

---

### そのほかのアクション

| アクション | 何をするか |
|:--|:--|
| **`-delete`** | **見つかったものを削除する** |
| `-ls` | `ls -l` に近い詳細な形式で表示する |
| `-ok コマンド \;` | **1 件ごとに確認しながら**実行する |
| `-printf 書式` | 書式を指定して表示する |
| `-prune` | そのディレクトリの下に降りない |
| `-quit` | 最初の 1 件で終了する |

```bash
$ find . -maxdepth 1 -name del.tmp -delete   # 確認なしで削除される
```

**`-delete` は確認を求めません。**
**必ず先に `-print` で対象を確かめてから**実行します。

```bash
$ find /tmp -type f -mtime +30 -print         # ① まず対象を確認する
$ find /tmp -type f -mtime +30 -delete        # ② 確認できたら削除する
```

**補足** … **`-ok` は 1 件ずつ `y/n` を聞いてくれます。**
**手作業で慎重に消すときはこちらが安全**です。

## 検索結果を他のコマンドに渡す

### 空白を含む名前でこわれる

**`find` の検索結果は改行コード LF（`\n`）で区切って出力されます。**
**ところが `xargs` は、標準入力から受け取った文字列を「改行またはスペース」で区切って処理します。**

**その結果、`dir 1` というディレクトリ名を `dir` と `1` という別々のものとして扱ってしまいます。**

```bash
$ find . -maxdepth 1 -name "dir*" -print | xargs ls -d   # 空白で名前が割れる
ls: cannot access './dir': No such file or directory
ls: cannot access '3': No such file or directory
ls: cannot access './dir': No such file or directory
ls: cannot access '2': No such file or directory
```

**`./dir 3` が `./dir` と `3` に割れている**のが見て取れます。

---

### print0 と xargs -0 の組

**`find` の `-print0` と `xargs` の `-0`（`--null`）をセットで使うと解決します。**

```text
  find … -print0   検索結果を NUL 文字で区切って出力する
              │
              ▼
  xargs -0 …       区切りを NUL 文字とみなして受け取る
              │
              ▼
  空白が含まれていても、誤って区切られない
```

```bash
$ find . -maxdepth 1 -name "dir*" -print0 | xargs -0 ls -d   # 空白入りでも壊れない
./dir 1
./dir 2
./dir 3
```

**どちらか片方だけでは意味がありません。**
**`-print0` を出しても `xargs` 側が `-0` を知らなければ、NUL をただの文字として扱ってしまいます。**

**`find | xargs` を書くときは `-print0` と `-0` を必ずセットにする**——これが定石です。

---

### exec と xargs の使い分け

| | **`-exec`** | **`xargs`** |
|:--|:--|:--|
| プロセス | `find` だけ | `find` と `xargs` の 2 つ |
| **空白入りの名前** | **そのままで安全** | **`-print0` と `-0` が必要** |
| 速さ | `\;` は遅い／`+` なら速い | 速い |
| **できること** | **`{}` を好きな位置に置ける** | **並列実行（`-P`）など xargs 側の機能が使える** |

**空白対策だけなら `-exec` のほうが手堅い**です。

```bash
$ find . -type f -name "*.log" -exec gzip {} \;      # xargs を使わずに済ませる
```

`xargs` の詳細は
[パイプとフィルタ](../01_シェルとコマンドライン/パイプとフィルタ.md) にあります。

## 結果画面の見方

**`-ls` を付けると詳細が出ます。**

```bash
$ find . -maxdepth 1 -name a.txt -ls   # 詳細な形式で表示する
   786962      4 -rw-r--r--   1 root     root           17 Sep 15 01:35 ./a.txt
```

| 欄 | 意味 | どこを見るか |
|:--|:--|:--|
| **`786962`** | **i ノード番号** | **同じ番号なら同じ実体**（ハードリンクの確認） |
| `4` | 占有ブロック数（1KB 単位） | 実サイズより大きいことがある |
| **`-rw-r--r--`** | **ファイル種別とパーミッション** | 先頭 1 文字が種別、残り 9 文字が権限 |
| `1` | ハードリンクの数 | 2 以上なら他からもリンクされている |
| **`root root`** | **所有ユーザと所有グループ** | 権限まわりの調査で見る |
| `17` | サイズ（バイト） | |
| `Sep 15 01:35` | 最終更新日時 | `-mtime` の判定はここ |
| **`./a.txt`** | **パス** | 起点からの相対パス |

**`ls -l` との違い**

| | **`find -ls`** | **`ls -l`** |
|:--|:--|:--|
| 先頭の欄 | **i ノード番号とブロック数が付く** | 付かない |
| 対象 | **検索条件に合ったものだけ** | ディレクトリの中身すべて |
| 再帰 | **既定で深く潜る** | `-R` が要る |

## よく使う検索式とアクション

**検索式（テスト）**

| 検索式 | 説明 |
|:--|:--|
| **`-name ファイル名`** | **ファイル名で検索** |
| `-iname ファイル名` | 大文字小文字を区別せずに検索 |
| **`-atime 日数`** | **最終アクセス日で検索** |
| **`-mtime 日数`** | **最終更新日で検索** |
| `-ctime 日数` | ステータス変更日で検索 |
| **`-perm アクセス権`** | **アクセス権で検索** |
| **`-size サイズ`** | **ファイルサイズで検索** |
| **`-type ファイルの種類`** | **ファイルの種類で検索**（`f` ファイル／`d` ディレクトリ／`l` シンボリックリンク） |
| **`-uid ユーザID`** | **ファイルの所有者のユーザIDで検索** |
| **`-user ユーザ名またはユーザID`** | **ファイルの所有者のユーザ名またはユーザIDで検索** |
| **`-maxdepth 階層数`** | **指定した階層まで検索** |
| **`-mindepth 階層数`** | **指定した階層から下を検索** |
| `-empty` | 中身が空のファイル・ディレクトリ |
| `-newer ファイル` | 指定ファイルより新しいもの |

**アクション**

| アクション | 説明 |
|:--|:--|
| **`-print`** | **検索結果を改行で区切って表示（デフォルト）** |
| **`-print0`** | **検索結果を NUL 文字で区切って表示** |
| **`-exec コマンド名 {} \;`** | **検索結果のファイルに対してコマンドを実行** |
| `-exec コマンド名 {} +` | まとめて実行する |
| `-ok コマンド名 {} \;` | 確認しながら実行 |
| `-delete` | 削除する |
| `-ls` | 詳細形式で表示 |

**演算子で組み合わせる**

| 演算子 | 意味 |
|:--|:--|
| （並べるだけ） | **かつ**（`-a` が省略されている） |
| `-o` | または |
| `!` / `-not` | 否定 |
| `( )` | グループ化（**シェル対策に `\( \)` と書く**） |

```bash
$ find . -type f \( -name "*.log" -o -name "*.txt" \)   # .log または .txt を探す
$ find . -type f ! -name "*.log"                         # .log 以外を探す
```

## まぎらわしいコマンドの整理

**「指定したディレクトリ以下からファイルやディレクトリを検索するコマンドは」
という問いで、選択肢に並ぶのは名前が似た別物**です。

| コマンド | 実際は何をするか |
|:--|:--|
| **`find`** | **指定したディレクトリ以下からファイルやディレクトリを検索する**（これが正解） |
| **`file`** | **ファイルやディレクトリの種別を表示する**。検索はしない |
| **`cpio`** | **cpio 形式で複数のファイルを 1 つのアーカイブにまとめる／展開する** |
| **`tar`** | **複数のファイルやディレクトリを 1 つにまとめる** |
| **`lookfor`** | **存在しないコマンド** |

```bash
$ file /etc/hosts /etc                 # 「何であるか」を判定するだけ
/etc/hosts: ASCII text
/etc:       directory
$ find /etc -name hosts                # 「どこにあるか」を探す
/etc/hosts
```

**`file` は種別の判定、`find` は場所の検索**——ここが入れ替えられて出題されます。

**`cpio` は `find` と組み合わせて使う**ので、この 2 つは一緒に覚えると混同しません。

```bash
$ find /data -name "*.log" | cpio -o > logs.cpio   # find で選んで cpio でまとめる
```

`tar` / `cpio` そのものは
[圧縮とアーカイブ](../01_シェルとコマンドライン/圧縮とアーカイブ.md)、
`file` は
[ファイルの種類とタイムスタンプ](../01_シェルとコマンドライン/ファイルの種類とタイムスタンプ.md) にあります。

## まぎらわしい指定の整理

**存在しないもの**

| 見かける指定 | 実際は |
|:--|:--|
| **`-null0`** | **存在しない**（NUL 区切りは **`-print0`**） |
| `-null` | **`find` には無い**（`xargs` 側の `--null` と混同しやすい） |
| `-print0` を `xargs` に `-0` 無しで渡す | **区切りが解釈されず、かえって壊れる** |

**存在するが、意味を取り違えやすいもの**

| 指定 | 正しい意味 |
|:--|:--|
| **`-depth`** | **階層数の指定ではない。** ディレクトリの中身を先に処理する**探索順序**の指定 |
| `-maxdepth` / `-mindepth` | **こちらが階層の深さ**を指定するもの |
| `-perm 644` / `-perm -644` | **ぴったり**か、**そのビットを含む**か |
| `-size +100` | 単位が無いので **512 バイト単位**。`+100M` とは別物 |

> **Ping-t の解説では `-depth` を「存在しない」と説明していることがあります**が、
> **GNU findutils 4.9.0 の `find --help` には `-depth` が Normal options として載っています**（実機で確認）。
> ただし**「検索結果を NUL 文字で区切る」用途には使えない**ので、
> **その設問の選択肢としては誤り**である、という結論は変わりません。
