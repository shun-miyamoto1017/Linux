## オートマウントとは何か

**オートマウントは、アクセスがあったときに自動でマウントし、
一定時間使われなければ自動でアンマウントする仕組み**です。

```text
  【/etc/fstab の場合】
    起動時にマウントする
      → NFS サーバが落ちていると、起動が止まる
      → 使っていなくても繋ぎっぱなし

  【autofs の場合】
    普段は繋がっていない
      → ディレクトリにアクセスした瞬間にマウントされる
      → しばらく使わなければ自動で外れる
```

**利点は 3 つ**です。

| 利点 | 内容 |
|:--|:--|
| **起動が止まらない** | サーバが落ちていても、アクセスするまで何も起きない |
| **資源を無駄にしない** | 使わない共有を繋ぎっぱなしにしない |
| **リムーバブルメディアに向く** | CD-ROM や USB のように、あったり無かったりするもの |

**オートマウントを利用するためにはあらかじめ、
どのディレクトリにどのデバイスをどのようなファイルシステムとしてマウントするのか、
設定しておく必要があります。**

**この仕組みは `automount` デーモンというプログラムにより実現されます。**
**CD/DVD などのメディアに対して利用するほか、
ネットワーク経由でマウントするディレクトリ（NFS）などに対して利用しても便利**です。

### 似ているが別物の3つ

**試験では「オートマウントとは何か」を、似た機能と入れ替えた選択肢で問われます。**

| 説明 | 何の話か |
|:--|:-:|
| **特定デバイスを必要な時だけ自動でマウントし、利用できるようにする機能** | **オートマウント（`automount`）** |
| ハードウェアが接続された際、自動的に対応するデバイスファイルを作る機能 | **`udev`** |
| 重要なファイルシステムをシステムの起動時に自動マウントする機能 | **`mount -a`**（起動時） |
| `/etc/fstab` に設定しておくことで `mount` / `umount` を便利にする機能 | **`/etc/fstab`** |

**`udev` との違い**

```text
  udev        デバイスを認識し、デバイスファイル（/dev/sr0 など）を作る
                  ↓
  automount   必要な時に、そのデバイスファイル上のファイルシステムをマウントする
```

**「デバイスファイルを作る」のが `udev`、「マウントする」のが `automount`**です。
**`automount` デーモンはデバイスファイルの作成には関与しません。**

**起動時の自動マウントとの違い**

**確かにシステムの起動時にルートファイルシステムなど重要なものは自動的にマウントされますが、
この動作に `automount` デーモンは関係がなく、この動作をオートマウントとは呼びません。**

**この機能は、システム起動時に `mount -a` コマンド
（`/etc/fstab` に記載されていて `noauto` オプションがついていないすべてのファイルシステムをマウントする）
を実行することで実現されています。**

**`/etc/fstab` との違い**

**確かに `/etc/fstab` をあらかじめ設定しておくことで、
デバイスとマウント先のどちらか片方を指定するだけで `mount` コマンドが使え、
都度マウントオプションを指定しなくても済むという点で便利なのですが、
この動作にも `automount` デーモンは関係がなく、オートマウントとは呼びません。**

| 仕組み | いつマウントされるか | 使わなくなったら |
|:--|:--|:--|
| **`/etc/fstab`（`noauto` なし）** | **起動時に一括** | **繋ぎっぱなし** |
| **`/etc/fstab`（`noauto` あり）** | **人が `mount` したとき** | 人が `umount` するまで |
| **autofs** | **アクセスがあった瞬間** | **一定時間で自動的に外れる** |

## 設定ファイルは2階建て

**メインの設定ファイルは `/etc/auto.master` です。これはマスターマップと呼ばれます。**
**その中でさらに、マップファイルという設定ファイルを指定します。**

```text
  /etc/auto.master      ← マスターマップ（メイン設定ファイル）
        │  マップファイルを指定する
        ▼
  /etc/auto.direct      ← マップファイル
  /etc/auto.cdrom       ← マップファイル
        │  実際に何をどこへ繋ぐかを書く
        ▼
     マウントされる
```

**2 階建てになっているのは、用途ごとにマップファイルを分けられるようにするため**です。

---

### マスターマップの3フィールド

```text
/-      /etc/auto.direct                    ← 直接マップ
/auto   /etc/auto.cdrom   --timeout 60      ← 間接マップ
```

**左のフィールドから順に、マウントポイント、マップファイル、オプションを指定します。**
**オプションは任意です。**

| # | フィールド | 内容 |
|:-:|:--|:--|
| **(1)** | **マウントポイント** | **`/-` なら直接マップ**。実際のパスなら間接マップの起点 |
| **(2)** | **マップファイル** | どのファイルに詳細を書いてあるか |
| (3) | オプション | `--timeout 60` など。**任意** |

**`/etc/auto.master` の 2 番目は「マップファイルの指定」であって、マウント先ではありません。**
ここは誤答として必ず出てきます。

---

### マップファイルの書式

```text
マウント名  [マウントオプション]  ロケーション（マウントするリソースやデバイス）
```

**`/etc/auto.direct` の中身の例**

```text
/mnt/NFS    NFS1:/share
```

**`/etc/auto.cdrom` の中身の例**

```text
cdrom   -fstype=iso9660   :/dev/cdrom
```

| # | フィールド | 内容 |
|:-:|:--|:--|
| **(1)** | **マウント名** | **直接マップなら絶対パス**、間接マップなら**名前だけ** |
| (2) | マウントオプション | `-fstype=iso9660` `-ro` など。**任意** |
| **(3)** | **ロケーション** | **マウントするリソースやデバイスの場所**。`ホスト:/パス` または `:/dev/xxx` |

**ロケーションの書き方**

| 書き方 | 意味 |
|:--|:--|
| **`NFS1:/share`** | **NFS サーバ `NFS1` の `/share`** |
| **`:/dev/cdrom`** | **ローカルデバイス**（ホスト名が無いのでコロンから始まる） |

**ローカルデバイスでも先頭にコロンが要る**のが独特です。

## 直接マップと間接マップ

**マウントポイントの指定方法は、「直接マップ」「間接マップ」の二つの方式があります。**

| | **直接マップ** | **間接マップ** |
|:--|:--|:--|
| **マスターマップの1番目** | **`/-`** | **`/auto` のような実際のパス** |
| **マップファイルのマウント名** | **絶対パス** | **名前だけ** |
| **実際のマウント先** | **マウント名がそのまま** | **マウントポイント ＋ マウント名** |
| 向いている用途 | 決まった 1 か所に繋ぐ | 同じ親の下に何個も並べる |

---

### 直接マップ

**マスターマップにおいて、直接マップでのマウントポイントは、常に「`/-`」という表記で記載されます。**

```text
auto.master:
/-      /etc/auto.direct

auto.direct:
/mnt/NFS    NFS1:/share
```

**直接マップの場合、マップファイルに書かれた 1 番左のマウント名が絶対パスとなり、
マウントポイントとなります。**

```text
  /mnt/NFS  ← マップファイルのマウント名がそのままマウント先
```

**この例では、`/mnt/NFS` にアクセスすると `NFS1:/share` がマウントされます。**

**`/-` は「相対パス」ではありません。**
**「マウント先はマップファイル側に絶対パスで書いてある」という目印**です。

---

### 間接マップ

**間接マップでは、個別のマップファイルに対し、示されたマウントポイントがマウントの起点を提供し、
自動マウント先の親ディレクトリとなります。**

```text
auto.master:
/auto   /etc/auto.cdrom   --timeout 60

auto.cdrom:
cdrom   -fstype=iso9660   :/dev/cdrom
```

**`/auto` と指定しているので、`/auto` が自動マウントの起点になります。**

**間接マップの場合、実際にマウントされるパスは、
`/etc/auto.master` で指定するマウントポイントと、
マップファイルで指定するマウント名を合わせたものになります。**

```text
  /auto      ＋   cdrom      =   /auto/cdrom
   │              │
   │              └─ マップファイルのマウント名
   └─ マスターマップのマウントポイント
```

**この例では `/auto/cdrom` が自動マウント先**となります。

---

### どこにマウントされるかの求め方

**手順を決めておけば、どの設定が来ても同じやり方で解けます。**

```text
  ① マスターマップの1番目を見る
        /- なら  →  直接マップ  →  マップファイルのマウント名がそのまま答え
        /auto なら →  間接マップ  →  ② へ
  ② マップファイルのマウント名を見る
  ③ ①のマウントポイント ＋ ②のマウント名  =  答え
```

**例題の形で確かめる**

| マスターマップ | マップファイル | マウント先 |
|:--|:--|:--|
| `/-  /etc/auto.direct` | `/mnt/NFS  NFS1:/share` | **`/mnt/NFS`** |
| `/auto  /etc/auto.cdrom` | `cdrom  -fstype=iso9660  :/dev/cdrom` | **`/auto/cdrom`** |
| `/data  /etc/auto.nfs` | `share1  NFS1:/export1` | **`/data/share1`** |

**よくある誤答の型**

| 誤答 | それは何か |
|:--|:--|
| **`/etc/auto.direct`** | **マスターマップの 2 番目**。マップファイルの指定であって、マウント先ではない |
| **`/-`** | **直接マップであることを示す記号**。マウント先ではない |
| **`NFS1:/share`** | **マップファイルの 2 つ目のフィールド**。マウントするリソースの場所 |
| **`/auto`**（間接マップのとき） | **起点であって、そのものがマウント先になるわけではない** |
| **`/cdrom`** | **マップファイルのマウント名**。ルート直下にマウントされることはない |

## よく使うオプション

**マスターマップのオプション**

| オプション | 意味 |
|:--|:--|
| **`--timeout 秒`** | **この秒数アクセスが無ければ自動でアンマウントする** |
| `--ghost` | マウントされていなくてもディレクトリを見せる（`browse` と同じ） |

**マップファイルのマウントオプション**

| オプション | 意味 |
|:--|:--|
| **`-fstype=種類`** | **ファイルシステムの種類**（`iso9660` / `nfs` / `ext4` など） |
| `-ro` / `-rw` | 読み取り専用／読み書き |
| `-soft` / `-hard` | NFS の応答が無いときの挙動 |
| `-nosuid` / `-nodev` | セキュリティ関連 |

```text
cdrom   -fstype=iso9660,ro   :/dev/cdrom
```

**カンマ区切りで複数指定**できます。`/etc/fstab` のオプションと同じ書き方です。

## 結果画面の見方

**設定を確認する**

```bash
$ grep -v '^#' /etc/auto.master | grep -v '^$'   # 有効な設定行だけを見る
/-      /etc/auto.direct
/auto   /etc/auto.cdrom   --timeout 60
$ cat /etc/auto.cdrom                             # マップファイルの中身を見る
cdrom   -fstype=iso9660   :/dev/cdrom
```

**マウントされているか確認する**

```bash
$ mount | grep autofs                             # autofs が管理しているポイントを見る
/etc/auto.direct on /mnt/NFS type autofs (rw,relatime,fd=7,...)
/etc/auto.cdrom on /auto type autofs (rw,relatime,fd=13,...)
```

| 見るところ | 意味 |
|:--|:--|
| **`type autofs`** | **まだ実体は繋がっていない。autofs が見張っている状態** |
| **左側がマップファイル名** | どの設定で見張っているか |
| **右側がマウントポイント** | **直接マップなら最終的なパス、間接マップなら起点** |

**アクセスすると実体が繋がります。**

```bash
$ ls /auto/cdrom                                  # アクセスした瞬間にマウントされる
$ mount | grep cdrom                              # 実体が繋がったことを確認する
/dev/sr0 on /auto/cdrom type iso9660 (ro,relatime,...)
```

**`type autofs` から `type iso9660` に変わった**のが、実際にマウントされた印です。

## 起動と確認

```bash
$ sudo systemctl start autofs                     # デーモンを起動する
$ sudo systemctl enable autofs                    # 起動時に自動で立ち上げる
$ systemctl status autofs                         # 動いているか確認する
$ sudo systemctl reload autofs                    # 設定を変えたら読み直させる
```

**設定を変えたら `reload` が要ります。** ファイルを書いただけでは反映されません。

**`/etc/auto.master` を編集した場合には、設定を反映させるためにデーモンの再起動が必要**です。

| 環境 | 書き方 |
|:--|:--|
| **systemd 系**（現在の主流） | **`systemctl reload autofs`** |
| **SysVinit 系**（試験で問われるのはこちら） | **`/etc/init.d/autofs reload`** |

```bash
$ sudo /etc/init.d/autofs reload                  # SysVinit 系での読み直し
```

**反映されないと思ったときに疑うのはここ**です。

| やってみたこと | 反映されるか |
|:--|:-:|
| **`/etc/init.d/autofs reload` を実行する** | **○** |
| `auto.master` コマンドを実行する | ✕（**そんなコマンドは存在しない**） |
| `newautofs` コマンドを実行する | ✕（**存在しない**） |
| 何もしない | ✕（**ファイルを書いただけでは反映されない**） |
| `/etc/fstab` にマウント情報を書く | ✕（**autofs とは別の仕組み**。オートマウントにならない） |

ユニットの操作は
[systemctl サービスの操作と確認](../05_起動プロセスとカーネル/systemctl_サービスの操作と確認.md) を参照してください。

## まぎらわしい指定の整理

**存在しないファイル**

| 見かける名前 | 実際は |
|:--|:--|
| **`/etc/auto.conf`** | **存在しない** |
| **`/etc/mount.conf`** | **存在しない** |
| `/etc/udev/udev.conf` | **存在するが udev のメイン設定ファイル**。オートマウントとは関係ない |
| **`/etc/auto.master`** | **これが正しい** |

**役割を取り違えない**

```text
  /etc/auto.master   マスターマップ      … どのマップファイルを使うか
  /etc/auto.direct   マップファイル      … 何をどこへ繋ぐか（直接マップ）
  /etc/auto.cdrom    マップファイル      … 同上（間接マップ）
  /etc/fstab         起動時のマウント設定 … autofs とは別の仕組み
  /etc/mtab          現在のマウント状況   … 設定ファイルではない
```

`/etc/fstab` と `/etc/mtab` の違いは [fstabの書き方](./fstabの書き方.md) にあります。
