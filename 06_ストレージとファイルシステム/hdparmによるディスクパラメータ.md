## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| **現在の設定をすべて見る** | **`hdparm /dev/hda`**（オプションなし） |
| **型番など詳細を見る** | **`hdparm -i /dev/hda`** |
| **ドライブから直接、新しい情報も得る** | **`hdparm -I /dev/sda`** |
| **DMA を有効にする** | **`hdparm -d1 /dev/hda`** |
| **32bit I/O を有効にする** | **`hdparm -c1 /dev/hda`** |
| **ライトキャッシュを有効にする** | **`hdparm -W 1 /dev/hda`** |
| **読み込み速度を測る** | **`hdparm -t /dev/hda`** / **`hdparm -T /dev/hda`** |

**押さえる 3 点**

| 論点 | 結論 |
|:--|:--|
| **数字の `0` と `1`** | **`0` がオフ、`1` がオン**。`-d0` は DMA オフ、`-d1` は DMA オン |
| **`-c` と `-d` は別物** | **`-c` は 32bit I/O、`-d` は DMA**。DMA を聞かれて `-c` を選ぶのが典型的な誤答 |
| **小文字 `-i` と大文字 `-I`** | **`-i` は IDE ベースの古いフォーマット、`-I` はドライブから直接**。SSD には `-I` |

**覚え方**

```text
  -c  32bit I/O    … Cpu との I/O 幅（c は 32bit の「c」と割り切る）
  -d  DMA          … Dma の d
  -W  Write cache  … Write の W（大文字）
  -t  実測          … 実際に読んで測る
  -T  キャッシュ    … キャッシュだけ測る
  -i  情報（古い）   -I  情報（直接）
```

## hdparm とは

**ハードディスクに関するパラメータを取得・設定するコマンドとして、`hdparm` があります。**

```text
hdparm [オプション] ハードディスクデバイス
```

**ハードディスクの転送モードの設定・確認、速度のベンチマークなどを行うことができるコマンド**です。

```bash
$ sudo hdparm /dev/hda                 # 現在のパラメータを一覧する
```

**まぎらわしいコマンドの整理**

| 見かける名前 | 実際は |
|:--|:--|
| **`hdparm`** | **これが正しい**（ハードディスクのパラメータ） |
| **`hdparam`** | **存在しない**。`param` ではなく **`parm`**（`a` が 1 つ少ない） |
| `fdisk` | **パーティションを操作する**コマンド。転送モードは扱わない |
| `mdadm` | **RAID を操作する**コマンド |
| `mdstat` | **存在しない**（`/proc/mdstat` というファイルはある） |
| `tune2fs` | **ext 系ファイルシステムの設定**。ディスクの転送モードとは無関係 |

**`hdparm` はディスク装置のパラメータ、`tune2fs` はファイルシステムのパラメータ**
——層が 1 つ違います。

```text
  hdparm    物理ディスク そのもの の設定     … 転送モード、キャッシュ
  tune2fs   その上の ファイルシステム の設定  … 予約ブロック、ラベル、ジャーナル
```

`tune2fs` は [ext系ファイルシステムの内部構造](./ext系ファイルシステムの内部構造.md) にあります。

## オプション一覧

| オプション | 説明 |
|:--|:--|
| **`-i`** | **詳細情報を表示する（IDE ベース）** |
| **`-I`** | **ドライブから直接詳細情報を得る** |
| **`-c0`** | **32bit I/O をオフ** |
| **`-c1`** | **32bit I/O をオン** |
| **`-d0`** | **DMA モードをオフ** |
| **`-d1`** | **DMA モードをオン** |
| **`-t`** | **BufferCache オフで読込速度を計測** |
| **`-T`** | **BufferCache のみで読込速度を計測** |
| **`-W0`** | **ライトキャッシュのオフ** |
| **`-W1`** | **ライトキャッシュのオン** |

**`hdparm v9.65` の `--help` を実機で確認した抜粋**

```text
 -c   Get/set IDE 32-bit IO setting
 -d   Get/set using_dma flag
 -i   Display drive identification
 -I   Detailed/current information directly from drive
 -t   Perform device read timings
 -T   Perform cache read timings
 -W   Get/set drive write-caching flag (0/1)
```

**`Get/set` と書かれているものは、値を付けなければ現在値の表示**になります。

```bash
$ sudo hdparm -d /dev/hda              # 現在の DMA 設定を見る（値を付けない）
/dev/hda:
 using_dma    =  1 (on)
$ sudo hdparm -d1 /dev/hda             # DMA を有効にする（値を付ける）
```

## 情報を見る

### 小文字のiと大文字のI

**`-i` オプションを利用すると、ハードディスクの「型番」（を含む様々な情報）を調べることができます。**

```bash
$ sudo hdparm -i /dev/sda              # 型番などの詳細情報を表示する
/dev/sda:
 Model=Hitachi HDS721680PLA380 , FwRev=P210ABEA, SerialNo=PVF804ZET8SU2N
 Config={ HardSect NotMFM HdSw>15uSec Fixed DTR>10Mbs } ...（略）
```

| 出力の欄 | 意味 |
|:--|:--|
| **`Model`** | **型番** |
| `FwRev` | ファームウェアのリビジョン |
| `SerialNo` | シリアル番号 |

**SSD では `-I`（大文字）を使う**

**SSD は SATA の規格を使ったものが主流で、`hdparm` で情報が取得できますが、
比較的新しい技術であるため、古いフォーマットの `-i` オプションでは全ての情報は取得できません。**
**この場合、`-I` オプションで直接機器から情報を得ることにより、新しい情報も表示できます。**

```bash
$ sudo hdparm -I /dev/sda | grep -i trim    # SSD の TRIM 対応を確認する
   *    Data Set Management TRIM supported (limit 8 blocks)
   *    Deterministic read ZEROs after TRIM
```

**「SSD など、最新の機器の情報を、直接ドライブから取得したい」と問われたら `-I`** です。

| オプション | どこから情報を取るか | 新しい機器に対応するか |
|:--|:--|:-:|
| **`-i`** | **カーネルが起動時に取得したもの**（IDE ベースの古いフォーマット） | **一部しか取れない** |
| **`-I`** | **ドライブから直接** | **取れる** |

```text
  -i   小文字 …  古い（IDE 時代のフォーマット）
  -I   大文字 …  Immediate・直接 と覚える
```

### オプションなしで実行する

**`hdparm` に対してハードディスクデバイスのみを指定し、何もオプションを指定しなかった場合には、
そのハードディスクに対する現在の設定パラメータの一覧が表示されます。**

```bash
$ sudo hdparm /dev/hda                 # 設定パラメータの一覧を表示する
/dev/hda:
     multcount    = 128 (on)
     I/O support  =  1 (32-bit)
     unmaskirq    =  0 (off)
     using_dma    =  1 (on)
     keepsettings =  0 (off)
     nowerr       =  0 (off)
     readonly     =  0 (off)
     readahead    = 256 (on)
     geometry     = 3939/255/63, sectors = 63283200, start = 0
```

| 欄 | 意味 |
|:--|:--|
| **`I/O support`** | **32bit I/O の設定**（`-c` で変える） |
| **`using_dma`** | **DMA モードの設定**（`-d` で変える） |
| `multcount` | 1 回の割り込みで転送するセクタ数 |
| `readahead` | 先読みするセクタ数 |
| **`geometry`** | **シリンダ/ヘッド/セクタと総セクタ数** |

**「設定されている転送モード」を知りたいときは、オプションなしで実行**します。

## 転送モードを変える

### DMAモード

**`-d0` を指定し DMA モードを無効にすると、ディスクへの転送は PIO モードで行われます。**
**PIO モードは CPU が直接 IDE 接続したデバイスからメモリへデータを転送するモードで、
他の処理にも使う CPU に負担をかけてしまう点が欠点です。**

**一方 `-d1` を指定すると データ転送が DMA モードで行われます。**
**DMA モードでは DMA コントローラと呼ばれる CPU とは別の物理的なチップが転送を処理します。**
**PIO モードと異なり CPU を使わないため、比較的高速で負担がかかりません。**

```bash
$ sudo hdparm -d1 /dev/hda             # DMA を有効にする（高速・CPU 負担が小さい）
$ sudo hdparm -d0 /dev/hda             # DMA を無効にする（PIO モードになる）
```

| やりたいこと | オプション |
|:--|:--|
| **DMA を有効にする** | **`-d1`** |
| **DMA を無効にする** | **`-d0`** |

**`-c0` / `-c1` は 32bit I/O を無効／有効にするオプションです。DMA の設定には影響がないので、誤りです。**

```text
  DMA の設定    → -d0 / -d1
  32bit I/O の設定 → -c0 / -c1
        ↑ ここを混ぜた選択肢が必ず出る
```

PIO と DMA の違いそのものは
[接続規格とデバイスファイル](./接続規格とデバイスファイル.md) にもあります。

### 32bit I/O

**32bit I/O を有効（`-c1`）にすることで、無効時（`-c0`）よりも転送速度の向上が見込めます。**
**ただし物理デバイスが対応していない場合は、無効（`-c0`）に設定します。**

```bash
$ sudo hdparm -c1 /dev/hda             # 32bit I/O を有効にする
$ sudo hdparm -c0 /dev/hda             # 32bit I/O を無効にする
```

| 問われ方 | 答え |
|:--|:--|
| **32bit I/O が有効になるように設定したい** | **`hdparm -c1 /dev/hda`** |
| **32bit I/O が無効になるように設定したい** | **`hdparm -c0 /dev/hda`** |
| **DMA を有効にしたい** | **`hdparm -d1 /dev/hda`** |
| **DMA を無効にしたい** | **`hdparm -d0 /dev/hda`** |

**`tune2fs` を選ばせる誤答**

| 誤答の選択肢 | なぜ違うか |
|:--|:--|
| `tune2fs --trans-bit 32 /dev/hda` | **存在しないオプション**。`tune2fs` はファイルシステム用 |
| `tune2fs --dma-mode32 /dev/hda` | **存在しないオプション** |
| `tune2fs -b 32 /dev/hda` | **`tune2fs` に `-b` は無い**（`mke2fs -b` はブロックサイズ） |

**転送モードはディスク装置の話なので `hdparm`**——`tune2fs` が出てきたら即座に切れます。

## ライトキャッシュ

| オプション | 意味 |
|:--|:--|
| **`-W1`** | **ライトキャッシュのオン** |
| **`-W0`** | **ライトキャッシュのオフ** |

```bash
$ sudo hdparm -W 1 /dev/hda            # ライトキャッシュを有効にする
$ sudo hdparm -W 0 /dev/hda            # ライトキャッシュを無効にする
```

**`-W 1` と `-W1` はどちらでも通ります。**

**有効と無効のトレードオフ**

| 設定 | 何が起きるか |
|:--|:--|
| **`-W1`（有効）** | **実際の書き込みを待たずに、CPU へは書き込み完了が返ることになるので、書き込み速度的には向上が見込めますが、CPU が把握する書き込み状態と実際の書き込み状態の差異が発生するため、データが失われる危険性が内在します** |
| **`-W0`（無効）** | **ディスクへの書き込みはキャッシュを経由せず、CPU からの書き込み命令時に行われるため、書き込み速度や条件によりディスク I/O 待ちが発生しやすくなりますが、突発的な電源 OFF 等の場合でも、CPU が把握する状態との不整合は発生しにくくなります** |

```text
  -W1   速い が 危ない    … 電源断でキャッシュ上のデータが消える
  -W0   遅い が 安全      … 書き込み命令のたびにディスクへ届く
```

**問われ方ごとの答え**

| 問われ方 | 答え |
|:--|:--|
| **書き込み速度向上のため、ライトキャッシュを有効にしたい** | **`hdparm -W 1 /dev/hda`** |
| **突発の電源断起因のライトキャッシュ喪失でデータ不整合を起こさないために、ライトキャッシュをオフにしたい** | **`-W0`** |

**「速度」と言われたら `-W1`、「電源断」「不整合」と言われたら `-W0`** です。

**実務では UPS とセットで考える**

```text
  UPS がある            → -W1 で速度を取る（電源断がそもそも起きにくい）
  UPS が無い・重要データ  → -W0 で安全を取る
  RAID コントローラにバッテリがある → コントローラ側のキャッシュに任せる
```

## 読み込み速度を測る

| オプション | 何を測るか |
|:--|:--|
| **`-t`** | **BufferCache オフで読込速度を計測** |
| **`-T`** | **BufferCache のみで読込速度を計測** |

**バッファキャッシュとは Linux のメモリ上に置かれるデータで、
ハードディスクから読み出されたデータをキャッシュしておき、
再度同じデータが必要になった場合のアクセスを高速化するためのものです。**

**`-t` ではこのキャッシュ機構を無効にし、実際のディスクアクセス速度を計測できます。**
**`-T` ではディスクアクセスなしに、このバッファキャッシュの性能のみを評価できます。**

```bash
$ sudo hdparm -t /dev/sda              # 実際のディスク読み込み速度
/dev/sda:
 Timing buffered disk reads: 1024 MB in  3.00 seconds = 341.33 MB/sec
$ sudo hdparm -T /dev/sda              # メモリ（キャッシュ）の読み込み速度
/dev/sda:
 Timing cached reads:   20000 MB in  2.00 seconds = 10000.00 MB/sec
```

```text
  -t   ディスクを 実際に 読む     … 数百 MB/s（ディスクの実力）
  -T   メモリ だけ を読む        … 数千〜数万 MB/s（メモリの実力）
        ↑ 桁が違うので、出力を見ればどちらか分かる
```

**「ハードディスクおよびバッファキャッシュからの読み込み速度を測りたい」
と問われたら `-t` と `-T` の 2 つ**が正解です。

| 選択肢 | 正誤 |
|:--|:-:|
| **`-t`** | **○** |
| **`-T`** | **○** |
| `-i` | ✕（**詳細情報の表示**） |
| `-j` | ✕（**存在しない**） |
| `--bench` | ✕（**存在しない**） |

**測るときのコツ**

```bash
$ sudo hdparm -tT --direct /dev/sda    # 3回ほど繰り返して平均を見る
```

**1 回だけの値は当てにならない**ので、**3 回は回して安定した値を見る**のが実務のやり方です。

**`Model` が型番**です。**受け入れ検査や資産管理台帳に載せるのはここ**です。

## 組み合わせて情報を揃える

**「型番、設定されている転送モード、作成されているパーティションの数」を知りたい**
——この 3 つは**1 コマンドでは揃いません。**

| 欲しい情報 | コマンド |
|:--|:--|
| **型番** | **`hdparm -i /dev/hda`** |
| **設定されている転送モード** | **`hdparm /dev/hda`**（オプションなし） |
| **作成されているパーティションの数** | **`fdisk -l /dev/hda`** |

**正解は 3 つ**です。

| 選択肢 | 正誤 | 理由 |
|:--|:-:|:--|
| **`hdparm -i /dev/hda`** | **○** | **型番が分かる** |
| **`hdparm /dev/hda`** | **○** | **転送モードなど現在のパラメータが分かる** |
| **`fdisk -l /dev/hda`** | **○** | **パーティションの一覧が分かる** |
| `fdisk /dev/hda` | ✕ | **対話モードに入ってしまう**。一覧を出すなら `-l` |
| `fdisk -v /dev/hda` | ✕ | **`-v` はバージョン表示** |
| `hdparm -j /dev/hda` | ✕ | **`-j` というオプションは無い** |

**`fdisk -l` と `fdisk` の違い**

```text
  fdisk -l /dev/hda    一覧を出して すぐ終わる     … 安全
  fdisk /dev/hda       対話モードに入る           … w を打たなければ無害だが、事故のもと
```

`fdisk` の操作は [ディスクを追加する手順](./ディスクを追加する手順.md) にあります。

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| **DMA を有効にしたいのに `-c1` を打った** | **`-c` は 32bit I/O** | **`-d1`** を使う |
| **`hdparam` が `command not found`** | **綴りが違う** | **`hdparm`**（`a` が 1 つ少ない） |
| **SSD の情報が途中までしか出ない** | **`-i` は古いフォーマット** | **`-I`（大文字）**を使う |
| **設定が再起動で戻る** | **`hdparm` の設定は揮発する** | **`/etc/hdparm.conf`** に書くか、起動時スクリプトで実行する |
| **`-t` の値が毎回違う** | **1 回では安定しない** | **3 回以上測って平均を見る** |
| **`-T` の値が異常に大きい** | **メモリを測っているから** | **ディスクの実力は `-t`** |
| **`tune2fs` で転送モードを変えようとした** | **層が違う** | **`hdparm`** を使う |
| **仮想マシンで `-d1` が効かない** | **仮想ディスクには物理的な DMA 設定が無い** | **クラウド・仮想環境では触らない** |

**設定を永続化する**

```bash
$ sudo vi /etc/hdparm.conf             # 起動時に適用したい設定を書く
```

```text
/dev/sda {
    write_cache = off
}
```

**`hdparm` コマンドで打った設定はメモリ上のもの**で、**再起動すると消えます。**

## クラウド実務メモ

**① クラウドの仮想ディスクでは転送モードを触らない**

**EBS / Persistent Disk / Managed Disk は仮想化されたブロックデバイス**です。
**物理的な DMA や 32bit I/O という概念がそもそもありません。**

| オプション | クラウドで意味があるか |
|:--|:--|
| **`-d0` / `-d1`**（DMA） | **意味がない**。ハイパーバイザが面倒を見る |
| **`-c0` / `-c1`**（32bit I/O） | **意味がない** |
| **`-W0` / `-W1`**（ライトキャッシュ） | **効かないことが多い**。EBS は独自にキャッシュを持つ |
| **`-t` / `-T`**（速度計測） | **意味がある**。ボリュームタイプの実効性能を測れる |
| **`-I`**（詳細情報） | **意味がある**。ただし出る情報は限られる |

**クラウドで `hdparm` を使うのは、ほぼ `-t` による実測だけ**です。

**② EBS の実効性能を測る**

```bash
$ sudo hdparm -t --direct /dev/nvme1n1   # 3回繰り返して平均を取る
```

**ただし `hdparm -t` はシーケンシャル読み込みしか測りません。**
**IOPS（ランダム性能）を測るなら `fio`** を使います。

```bash
$ sudo fio --name=randread --rw=randread --bs=4k --size=1G \   # 4KB ランダム読み込みを測る
    --numjobs=4 --runtime=60 --group_reporting --filename=/data/testfile
```

| 測りたいもの | ツール |
|:--|:--|
| **シーケンシャル読み込み** | **`hdparm -t`**（手軽） |
| **IOPS / ランダム性能 / 書き込み** | **`fio`**（本格的） |
| 瞬間の I/O 状況 | `iostat -x 1` |

**gp3 の IOPS 設定が効いているかは `fio` でないと分かりません。**

**③ バーストクレジットの枯渇を疑う**

**gp2 や旧世代の EBS はバーストクレジットを使い切ると急に遅くなります。**

```bash
$ aws cloudwatch get-metric-statistics --namespace AWS/EBS \   # バーストクレジット残量を見る
    --metric-name BurstBalance --dimensions Name=VolumeId,Value=vol-xxxx \
    --start-time 2026-09-16T00:00:00Z --end-time 2026-09-16T12:00:00Z \
    --period 300 --statistics Average
```

**「朝は速いのに昼過ぎから遅い」はバーストクレジット枯渇の典型**です。
**`hdparm` でいくら測っても原因は出てきません。**

**④ 遅いという申告の切り分け順**

```text
  ① iostat -x 1 で await と %util を見る        ← まず現状
  ② hdparm -t で素の読み込み速度を測る
  ③ CloudWatch で BurstBalance / VolumeQueueLength を見る
  ④ ボリュームタイプと IOPS 設定を確認する
  ⑤ オンプレなら hdparm の設定と SMART を見る   ← ここで初めて装置を疑う
```

**クラウドでは①〜④でほぼ片が付きます。**
**`hdparm` で設定を触る出番は、オンプレの物理サーバだけ**だと考えて構いません。

**⑤ 物理サーバの受け入れ検査には使える**

```bash
$ sudo hdparm -I /dev/sda | head -20   # 型番・シリアル・容量を台帳に転記する
$ sudo hdparm -tT --direct /dev/sda    # 実効速度を記録する
$ sudo smartctl -a /dev/sda            # 初期の SMART 値を記録する
```

**この 3 つを納品時に取っておくと、半年後に「遅くなった」と言われたときの比較対象になります。**
