## まずこれだけ

| レベル | 最低台数 | 利用可能容量 | 目的 |
|:--|:-:|:--|:--|
| **RAID0** | **2台** | **全ディスクの合計** | **速度と容量**（冗長性なし） |
| **RAID1** | **2台** | **1 台分** | **安全性**（何台使っても 1 台分） |
| **RAID5** | **3台** | **合計から 1 台分を引いた分** | **容量と冗長性の両立** |

**押さえる 3 点**

| 論点 | 結論 |
|:--|:--|
| **RAID0 は冗長化するか** | **しない**。まとめるだけ。1 台壊れれば全滅 |
| **RAID1 の容量** | **何台使っても 1 台分**。4 台でも 1 台分 |
| **RAID5 のパリティ** | **専用ディスクは無い**。各ディスクに**分散**して書かれる |

**別名で覚える**

```text
  RAID0  ストライピング（striping）  … データを 分散 して書く
  RAID1  ミラーリング（mirroring）    … 同じデータを 鏡写し にする
  RAID5  パリティ（parity）付き分散   … 復旧用の符号を 分散 して持つ
```

## RAIDとは何か

**RAID とは複数のディスクをまとめて利用することでアクセスの高速化やデータの冗長化を行う技術**で、
**Redundant Arrays of Independent Disks（独立ディスク群の冗長配置）の頭文字**を取った名前です。

**RAID には RAID レベルと呼ばれるいくつかの種類があり、
RAID レベルによって複数のディスクの使い方や実現される内容が異なります。**

```text
  複数のディスク            まとめ方（RAID レベル）        得られるもの
  ┌───┐┌───┐┌───┐
  │ A ││ B ││ C │  ──▶  RAID0  直列化して1台に  ──▶  速度と容量
  └───┘└───┘└───┘  ──▶  RAID1  並列化して1台に  ──▶  安全性
                      ──▶  RAID5  パリティを分散  ──▶  容量と安全性の両立
```

**「冗長化」とは、同じデータやパリティを保持することで信頼性を高めること**です。
**この言葉が説明文に入っているかどうかが、RAID0 とそれ以外を分ける目印**になります。

## RAID0 ストライピング

**RAID0 はストライピングとも言い、2 台以上のディスクを直列化して 1 台のディスクとします。**
**個々のディスクの領域をすべてまとめ、巨大なディスクにするというイメージ**です。

```text
  データ  A1 A2 A3 A4 A5 A6
            ↓
  ┌─ disk1 ─┐ ┌─ disk2 ─┐
  │ A1  A3  │ │ A2  A4  │      ← 交互に振り分けて書く
  │ A5      │ │ A6      │
  └─────────┘ └─────────┘
```

**RAID0 を利用すると、容量は基本的に全てのディスクの容量を合わせた容量となります。**
**また複数のディスクを同時に利用する事で、高速に読み書きが行えるようになります。**

**ただし、データの冗長化は一切行われていない**ため、
**RAID0 を構成している複数台のディスクのうちどれかに問題が発生しただけで
RAID0 全体が利用できなくなる可能性があります。**

**したがって RAID0 は安全性を高める目的ではなく、
大きく高速なディスク領域を確保する目的で利用します。**

| 説明 | 正誤 |
|:--|:-:|
| **ストライピングとも呼ばれる** | **○** |
| **2 台以上のディスクを使って構成する** | **○**（1 台では分散できない） |
| **シーケンシャルアクセスのパフォーマンスに優れる** | **○** |
| **複数台のディスクを利用しデータを冗長化する** | **✕**（**まとめるだけ。冗長化はしない**） |

> **シーケンシャルアクセスとは、大きなファイルを読み書きする場合など、
> ディスクを一方向に続けて利用するようなアクセス**のことです。
> **RAID0 では複数のディスクにデータが分散しているため、それぞれのディスクで同時に読み書きを行うことができ、
> ディスク台数が増えれば増えるほどシーケンシャルアクセスのスピードが高速になります。**

## RAID1 ミラーリング

**RAID1 はミラーリングとも言い、2 台以上のディスクを並列化して 1 台のディスクとします。**
**個々のディスクにはすべて同一のデータが書き込まれます。**

```text
  データ  A1 A2 A3
            ↓  同じものを全部に書く
  ┌─ disk1 ─┐ ┌─ disk2 ─┐
  │ A1 A2 A3│ │ A1 A2 A3│      ← 完全に同じ内容
  └─────────┘ └─────────┘
```

**したがってディスクを 2 台利用した場合には二重に、3 台利用した場合は三重に、
というようにデータが多重にディスクに保持されることになり、非常に冗長性が高い構成**です。

**RAID1 を構成しているディスクのうち何台かが故障したとしても、
1 台でも正常に動作するディスクが残っていれば RAID1 領域は安全に利用可能**です。
**そして故障したディスクを随時新しいディスクに交換していくことで、無用にシステムを止めずに済みます。**

**このように RAID1 は冗長化を行い、重要なデータの信頼性・安全性を高める目的で利用します。**

| 説明 | 正誤 |
|:--|:-:|
| **ミラーリングとも呼ばれる** | **○** |
| **データを多重化することで信頼性を高める** | **○** |
| **2 台以上のディスクを使って構成する** | **○** |
| **パリティを利用することでデータを冗長化する** | **✕**（**これは RAID5 の説明**。RAID1 はパリティを使わない） |

**「多重化」と「パリティ」を取り違えない**

```text
  RAID1  同じデータをそのまま 何枚も 持つ        … 多重化
  RAID5  元に戻せる 符号（パリティ）を持つ        … パリティ
```

## RAID5 パリティ分散

**RAID5 は 3 台以上のディスクで構成し、
パリティ領域と呼ばれるデータ復旧用の冗長なデータを各ディスクに分散して保持します。**

```text
  ┌─ disk1 ─┐ ┌─ disk2 ─┐ ┌─ disk3 ─┐
  │ A1      │ │ A2      │ │ Ap      │   ← Ap は A1,A2 のパリティ
  │ B1      │ │ Bp      │ │ B2      │   ← パリティの置き場所がずれていく
  │ Cp      │ │ C1      │ │ C2      │
  └─────────┘ └─────────┘ └─────────┘
       ↑ パリティが1台に固まらず、分散している
```

**基本的には RAID0 と同様に直列化されるので、ディスク台数を増やせば増やすほど RAID5 全体の容量は増えます。**
**具体的には、RAID5 では構成ディスクの全容量から 1 台分だけ減らした容量が利用可能**です。

**またパリティが存在するので、RAID0 とは異なり冗長性も確保されています。**
**構成しているディスクに障害が発生した場合は、
他のディスクのパリティ領域を利用することで復旧することができます。**

**このように RAID5 は全体の容量を増やしつつ冗長性も確保する目的で利用します。**

| 説明 | 正誤 | 理由 |
|:--|:-:|:--|
| **構成ディスク台数を増やすほど、利用できる容量が増加する** | **○** | **パリティは 1 台分だけ。残りはすべて使える** |
| **構成ディスクのうち 1 台をパリティ専用に使う** | **✕** | **1 台「分」の容量を使うが、専用ディスクがあるわけではない**。各ディスクに分散する |
| **構成ディスクのうち 1 台でも正常ならばデータが復旧できる** | **✕** | **これは RAID1 の説明**。RAID5 が耐えられるのは **1 台の障害まで** |
| **2 台以上のディスクで構成する** | **✕** | **3 台以上**が必要 |

**なぜ RAID5 は 3 台からなのか**

**仮にディスク 2 台で RAID5 を構成した場合を考えると、実際に利用できる容量は 1 台分**となります。
**しかし 2 台を利用し 1 台分の容量で良いならば、
そもそもパリティなど利用せず RAID1 としてミラーリングすれば良いわけです。**
**したがって RAID5 として意味があるのは 3 台から**です。

> **RAID3 や RAID4 というものもあり、これらはディスク 1 台をパリティ専用に使います**
> （その点を除いては RAID5 とほぼ同じ）。
> **「パリティ専用ディスク」という説明は RAID3 / RAID4 のもの**で、**RAID5 ではありません。**

## 3つを並べて比べる

| | **RAID0** | **RAID1** | **RAID5** |
|:--|:--|:--|:--|
| **別名** | **ストライピング** | **ミラーリング** | — |
| **最低台数** | **2台** | **2台** | **3台** |
| **利用可能容量** | **全ディスクの合計** | **1 台分** | **合計から 1 台分を引いた分** |
| **冗長化** | **しない** | **する（多重化）** | **する（パリティ）** |
| **耐えられる障害** | **0 台** | **1 台でも残れば可** | **1 台まで** |
| **読み込み速度** | **速い** | やや速い | 速い |
| **書き込み速度** | **速い** | 遅め（全台に書く） | **遅め**（パリティ計算が要る） |
| **目的** | **大きく高速な領域** | **重要データの安全性** | **容量と冗長性の両立** |

**選び分けの考え方**

```text
  消えても作り直せるもの（キャッシュ、一時領域、中間ファイル）
      → RAID0      速さと容量を取る

  消えたら困るもの（OS 領域、DB のログ、設定）
      → RAID1      容量効率を犠牲にして安全を取る

  量があって、かつ消えたら困るもの（ファイルサーバ、アーカイブ）
      → RAID5      両取りする
```

## 容量の計算

**試験では「◯GB のディスク N 台で RAID◯ を構成した。利用可能な容量は」という形で必ず出ます。**

| レベル | 計算式 |
|:--|:--|
| **RAID0** | **容量 × 台数** |
| **RAID1** | **容量 × 1**（台数は関係ない） |
| **RAID5** | **容量 × (台数 − 1)** |

**500GB のディスク 4 台で計算してみる**

| レベル | 計算 | 答え |
|:--|:--|:--|
| **RAID0** | **500GB × 4 = 2,000GB** | **2TB** |
| **RAID1** | **500GB × 1** | **500GB** |
| **RAID5** | **500GB × (4 − 1) = 1,500GB** | **1.5TB** |

**RAID1 は「何台使っても 1 台分」**

**RAID1 では何台のディスクを使って構成しても、1 台分の容量しか利用できません。**
**これは RAID1 は各ディスクに同じデータを保持する、という仕組みを考えれば明らかです。**

```text
  RAID1 で 4 台 → 4 枚とも中身が同じ → 見えるのは 1 枚分
```

**ここで「4 台だから 2TB」と答えてしまうのが典型的な誤答**です。

**RAID5 は台数を増やすほど得をする**

```text
  3 台 → 500 × 2 = 1TB    （効率 67%）
  4 台 → 500 × 3 = 1.5TB  （効率 75%）
  5 台 → 500 × 4 = 2TB    （効率 80%）
      ↑ パリティは常に 1 台分なので、台数が増えるほど効率が上がる
```

**ただし台数が増えるほど「2 台同時に壊れる確率」も上がります。**
**大量のディスクを束ねるときは、パリティを 2 台分持つ RAID6 を検討**します。

## 何台まで壊れて平気か

| レベル | 耐えられる障害 | 2 台壊れたら |
|:--|:--|:--|
| **RAID0** | **0 台**（1 台壊れれば全滅） | — |
| **RAID1**（2台構成） | **1 台** | **全滅** |
| **RAID1**（4台構成） | **3 台**（1 台残れば読める） | **平気** |
| **RAID5** | **1 台** | **全滅** |
| RAID6 | 2 台 | 平気 |

**RAID5 で 2 台同時はアウト**

**RAID5 はパリティという数学的に元データを復旧することができる符号を使ってデータを冗長化していますが、
これにより復旧できるのはディスク 1 台の障害まで**です。
**2 台以上に同時に障害が発生した場合は、RAID5 のパリティでは復旧ができません。**

**「1 台でも正常ならばデータが復旧できる」のは RAID1 の説明**です。
**RAID1 は同じデータをすべてのディスクに書き込み保持しているので、1 台でも無事ならば問題ありません。**

```text
  RAID5 も RAID1 もデータを冗長化しているが、
  RAID1 では 容量効率を犠牲にして RAID5 より一層の安全性を確保している
```

**再構築中がいちばん危ない**

**1 台壊れた RAID5 を交換して再構築している間は、残り全台をフルに読みます。**
**このタイミングで 2 台目が壊れると全滅**です。
**再構築中は「冗長性がゼロの RAID0 と同じ」**だと考えて扱います。

## 組み合わせたレベル

**RAID0 と RAID1 を組み合わせたものもあります。**

| 呼び方 | 構成 | 最低台数 | 特徴 |
|:--|:--|:-:|:--|
| **RAID10（1+0）** | **ミラーしてからストライプ** | **4台** | **速くて強い**。容量は半分 |
| RAID01（0+1） | ストライプしてからミラー | 4台 | RAID10 より障害に弱い |
| RAID6 | パリティを 2 台分持つ | 4台 | **2 台まで耐える**。書き込みはさらに遅い |
| linear（JBOD） | 単に連結するだけ | 2台 | 速度も冗長性も無い |

**`mdadm` の `--level=` が受け取る値**（mdadm 4.3 の `--help` で確認）

```text
  raid level: 0,1,4,5,6,10,linear,multipath and synonyms
```

**実務では RAID10 か RAID6 の二択**になることが多いです。

```text
  DB のデータ領域（書き込みが多い）        → RAID10
  ファイルサーバ・アーカイブ（読みが多い）  → RAID6
```

## 説明の入れ替えに気をつける

**この分野の設問は「説明のうち誤っているものはどれか」という形が中心です。**
**レベル同士の説明を入れ替えたものが必ず紛れ込みます。**

| 説明 | 本当はどのレベルか |
|:--|:--|
| **ストライピングとも呼ばれる** | **RAID0** |
| **ミラーリングとも呼ばれる** | **RAID1** |
| **データを多重化することで信頼性を高める** | **RAID1** |
| **パリティを利用することでデータを冗長化する** | **RAID5** |
| **1 台でも正常ならばデータが復旧できる** | **RAID1** |
| **構成ディスクのうち 1 台をパリティ専用に使う** | **RAID3 / RAID4**（RAID5 ではない） |
| **台数を増やすほど利用できる容量が増加する** | **RAID0 と RAID5**（RAID1 は増えない） |
| **冗長化を一切行わない** | **RAID0** |

**キーワードで引ける表**

```text
  「ストライピング」「直列化」「冗長化しない」      → RAID0
  「ミラーリング」「並列化」「多重化」「同一データ」 → RAID1
  「パリティ」「分散して保持」「3 台以上」          → RAID5
  「パリティ専用ディスク」                         → RAID3 / RAID4
```

## つまずきポイント

| 誤解 | 正しくは |
|:--|:--|
| **RAID1 を 4 台にしたら容量が増えると思った** | **何台でも 1 台分**。増えるのは冗長性だけ |
| **RAID5 はパリティ用のディスクが 1 台あると思った** | **各ディスクに分散**する。専用ディスクは RAID3 / RAID4 |
| **RAID5 なら 2 台壊れても復旧できると思った** | **1 台まで**。2 台は RAID6 |
| **RAID0 も冗長化の一種だと思った** | **冗長化しない**。1 台壊れれば全滅 |
| **RAID を組んだからバックアップは不要だと思った** | **RAID は可用性の仕組み**。誤削除もランサムウェアも防げない |
| **RAID5 を 2 台で組もうとした** | **3 台以上**。2 台なら RAID1 を使う |
| **容量の違うディスクを混ぜた** | **いちばん小さいディスクに合わせられる**。差分は無駄になる |

**RAID はバックアップではない**

```text
  RAID が守れるもの     ディスクの 物理故障
  RAID が守れないもの   誤削除 / 誤上書き / ランサムウェア / 筐体ごとの障害 / 論理破損
```

**「RAID を組んでいるので大丈夫です」は設計レビューで必ず突っ込まれます。**
**バックアップは別に要る**、が結論です。

## クラウド実務メモ

**① クラウドでは RAID を自分で組まないことが多い**

**EBS / Persistent Disk / Managed Disk は、サービス側で既に冗長化**されています。

| レイヤ | 誰が冗長化するか |
|:--|:--|
| **物理ディスク** | **クラウド事業者**（利用者からは見えない） |
| **ボリューム** | **EBS は AZ 内で自動的に複製**される |
| **AZ 障害** | **利用者の責任**。マルチ AZ 構成やスナップショットで対処する |

**「EBS が 1 本壊れる」という心配はほぼ不要**です。
**心配するのは AZ 障害とリージョン障害**で、そこは RAID では解決しません。

**② それでもソフトウェア RAID を組む 2 つの場面**

| 場面 | 何を組むか | 理由 |
|:--|:--|:--|
| **IOPS / スループットが 1 本の上限に足りない** | **RAID0** | **複数ボリュームを束ねて上限を超える** |
| **インスタンスストア（NVMe）を使う** | **RAID0**（速度）／**RAID1**（保護） | **インスタンスストアは停止で消える**ので、用途次第 |

```bash
$ sudo mdadm -C /dev/md0 -l 0 -n 2 /dev/nvme1n1 /dev/nvme2n1   # 2本束ねて帯域を稼ぐ
```

**EBS を RAID0 で束ねるときの注意**

**スナップショットが「束ね全体で整合した 1 点」にならない**ので、
**取得前にファイルシステムを凍結する**（`fsfreeze`）か、
**そもそもスナップショットに頼らない設計**にします。

**③ gp3 なら RAID0 より先にパラメータを見る**

**gp3 は IOPS とスループットを容量と切り離して指定できます。**
**RAID0 で束ねる前に、まず 1 本の性能を引き上げられないか確認**します。

```text
  gp3 の上限に達している？  → いいえ → gp3 のパラメータを上げる（構成が単純なまま）
                            → はい   → 複数本を RAID0 で束ねる
```

**構成が単純なほど、深夜に起きたときに直せます。**

**④ オンプレ移行の棚卸しでは「RAID レベル」を必ず控える**

**移行元が RAID5 の 4 台構成（実効 1.5TB）なら、移行先で要るのは 1.5TB**です。
**生の容量 2TB で見積もると過剰**になります。

```bash
$ cat /proc/mdstat                     # 移行元でレベルと台数を控える
$ sudo mdadm -D /dev/md0               # 実効容量も確認する
```

読み方は [ソフトウェアRAIDの管理_mdadm](./ソフトウェアRAIDの管理_mdadm.md) にあります。
