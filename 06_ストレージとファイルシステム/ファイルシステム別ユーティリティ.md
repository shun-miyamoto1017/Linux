## なぜ種類ごとに分かれているのか

**ファイルシステムの作成、設定、チェック、情報表示を行うコマンドは、ファイルシステム毎に用意されています。**
**これはファイルシステムによって内部の形式が異なるため、それぞれの形式を扱う別のプログラムが必要であるためです。**

```text
  ext4 の内部構造          XFS の内部構造
   ├ スーパーブロック        ├ スーパーブロック（別形式）
   ├ i ノードテーブル        ├ B+ ツリー
   └ ブロックグループ        └ アロケーショングループ
          │                        │
          ▼                        ▼
      e2fsck                   xfs_repair
   （ext の構造しか読めない）  （XFS の構造しか読めない）
```

**同じ「チェック」でも、中でやっていることがまったく違う**ので、別のプログラムになります。

**`mkfs` と `fsck` はその違いを隠す「窓口」**です。

```text
  mkfs -t xfs /dev/sdb1   →  内部で mkfs.xfs を呼ぶ
  fsck -t ext4 /dev/sdb1  →  内部で fsck.ext4（= e2fsck）を呼ぶ
```

**窓口のコマンドが、種類別のコマンドを呼ぶ**のであって、**逆ではありません。**
「`mkfs` は他のファイルシステム作成コマンドから内部的に利用される」という説明は**逆**です。

## 作成するコマンド

| ファイルシステム | 作成コマンド |
|:--|:--|
| **ext2 / ext3 / ext4** | **`mke2fs`、`mkfs.ext2`、`mkfs.ext3`、`mkfs.ext4`** |
| **xfs** | **`mkfs.xfs`** |
| **iso9660** | **`mkisofs`** |

**ファイルシステムによって複数のコマンドがある場合（例えば `mke2fs` と `mkfs.ext2`）がありますが、
名前が異なっていても同一のもの（ハードリンクやシンボリックリンク）です。**

```bash
$ ls -l /sbin/mkfs.ext4 /sbin/mke2fs           # 実体が同じかどうかを見る
```

**ext2 を作れるコマンド**

| コマンド | ext2 を作れるか |
|:--|:--|
| **`mke2fs`** | **○**（既定が ext2） |
| **`mkfs`** | **○**（`-t` を省略すると ext2） |
| **`mkfs.ext2`** | **○** |
| **`mkfs.ext3`** | **✕** |

**`mkfs.ext3` として実行された場合は、`-t` や `-j` が付いていなくても ext3 として作成されます。**
**名前そのものが「ext3 を作れ」という指示**になるためです。

**ext4 を作れるコマンド**

| コマンド | ext4 を作れるか |
|:--|:--|
| **`mkfs.ext4`** | **○** |
| **`mke2fs -t ext4`** | **○** |
| **`mkfs -t ext4`** | **○** |
| `mkfs.ext2` / `mkfs.ext3` | **✕**（それぞれ ext2 / ext3 になる） |

詳しい使い方は [ディスクを追加する手順](./ディスクを追加する手順.md) にあります。

## チェックするコマンド

| ファイルシステム | チェックコマンド |
|:--|:--|
| **ext2 / ext3 / ext4** | **`e2fsck`、`fsck.ext2`、`fsck.ext3`、`fsck.ext4`** |
| **xfs** | **`xfs_check`、`fsck.xfs`** |

**`e2fsck` がチェックできるのは ext2 / ext3 / ext4 だけ**です。
**XFS はチェックできません。**

**`e2fsck` の主なオプション**

| オプション | 説明 |
|:--|:--|
| **`-b`** | **指定のスーパーブロックを使い復元を行う** |
| **`-c`** | **不良ブロックのチェックを行う** |
| **`-p`** | **確認を出さずに、安全に直せる範囲を自動修復する**（preen モード。不良ブロック専用ではない） |

```bash
$ sudo e2fsck -b 32768 /dev/sdb1              # 予備のスーパーブロックを使って復元する
$ sudo e2fsck -c /dev/sdb1                     # 不良ブロックを調べる
$ sudo e2fsck -p /dev/sdb1                     # 安全に直せるものだけ自動で直す
```

**`-b` は「先頭のスーパーブロックが壊れたとき」の最後の手段**です。
**ext 系はスーパーブロックの複製を複数持っている**ので、そちらから復元できます。

```bash
$ sudo dumpe2fs /dev/sdb1 | grep -i superblock  # 予備スーパーブロックの位置を調べる
```

> **`xfs_check` について（実機で確認した注意）**
> **Ping-t の解説では XFS のチェックコマンドとして `xfs_check` が挙げられています。**
> ただし **`xfsprogs 6.6.0` には `xfs_check` が含まれていません**。
> **新しい版では `xfs_repair -n`（修復せずに検査だけ）に統合**されています。
> **試験では `xfs_check` が正解**ですが、**実機で見つからなくても異常ではありません。**

```bash
$ sudo xfs_repair -n /dev/sdb1                 # XFS を検査だけする（修復しない）
Phase 1 - find and verify superblock...
Phase 2 - using internal log
Phase 3 - for each AG...
```

修復そのものは [fsckとファイルシステムの修復](./fsckとファイルシステムの修復.md) にあります。

## 設定と情報表示のコマンド

**以下の表のコマンドはすべて、作成済みのファイルシステム（デバイス）を引数に取って動作します。**

| コマンド | 何をするか |
|:--|:--|
| **`tune2fs`** | **ext2 / ext3 / ext4 の設定を行う** |
| **`e2label`** | **ext2 / ext3 / ext4 のラベルを操作** |
| **`dumpe2fs`** | **ext2 / ext3 / ext4 の詳細を表示する** |
| **`debugfs`** | **ext2 / ext3 / ext4 の対話的デバッグを行う** |
| **`xfs_admin`** | **xfs の設定を行う** |
| **`xfs_info`** | **xfs の情報を表示する** |

**対応関係で覚える**

```text
   ext系            XFS
  ────────         ────────
  mke2fs     ←→    mkfs.xfs
  e2fsck     ←→    xfs_check
  tune2fs    ←→    xfs_admin
  dumpe2fs   ←→    xfs_info
  debugfs    ←→    xfs_db
```

**左右で名前がまったく似ていない**のが、この分野の厄介なところです。
**「役割の対応」で覚える**しかありません。

### ext系のユーティリティ

**`tune2fs` … 設定を後から変える**

| オプション | 説明 |
|:--|:--|
| **`-c 回数`** | **自動 fsck が行われるまでのマウント回数を設定** |
| **`-i 間隔`** | **自動 fsck が行われるまでの時間を設定** |
| **`-j`** | **ext2 を ext3 に変換**（ジャーナリング機能を付与） |
| **`-l`** | **スーパーブロックの内容を出力** |
| **`-m 割合`** | **root 用予備領域の割合を設定** |
| **`-L ラベル`** | **指定した名前でラベルをつける** |

```bash
$ sudo tune2fs -c 30 -i 1m /dev/sda2          # 30回マウント または 1ヶ月 で自動fsck
```

**`-c` は count（回数）、`-i` は interval（間隔）**と英単語に関連づけると忘れません。
**`-i` に続く `1m` の `m` は月（month）**です。ほかに `d`（日）、`w`（週）が使えます。

**`-L` と `-l` は大文字小文字で意味が変わります。**

| 指定 | 意味 |
|:--|:--|
| **`-L ラベル`** | **ラベルを設定する** |
| **`-l`** | **スーパーブロックの内容を表示する** |

**`e2label` … ラベル専用のコマンド**

```text
e2label デバイス ラベル
```

```bash
$ sudo e2label /dev/sda1 DATA                  # ラベルを設定する
$ sudo e2label /dev/sda1                       # 引数を省くと現在のラベルを表示する
DATA
```

**ラベルを設定する方法は 3 つ**あります。

| 方法 | 書き方 | いつ使うか |
|:--|:--|:--|
| **作成時に付ける** | **`mke2fs -L ROOT /dev/sdb1`** | 新規作成のとき |
| **作成後に変える** | **`tune2fs -L DATA /dev/sda1`** | あとから変えるとき |
| **専用コマンドで変える** | **`e2label /dev/sda1 DATA`** | 同上 |

**`e2label` はコマンド名に `2` と入っていますが、ext2 / ext3 / ext4 のどれに対しても利用できます。**
**`tune2fs` も同様**です。

**`dumpe2fs` … 詳細を表示する**

```bash
$ sudo dumpe2fs -h /dev/sdb1                   # スーパーブロックの情報だけを表示する
```

`-h` を付けないとブロックグループの情報まで大量に出ます。

### XFSのユーティリティ

**`xfs_admin` … 設定を行う**

| オプション | 説明 |
|:--|:--|
| **`-l`** | **ラベルを表示する** |
| **`-L ラベル`** | **ラベルを設定する** |
| **`-u`** | **UUID を表示する** |
| `-U UUID` | UUID を設定する |

```bash
$ sudo xfs_admin -l -u x.img                   # ラベルと UUID を表示する
label = ""
UUID = bd617821-1f2b-48e3-a291-58c9e7745cde
$ sudo xfs_admin -L MYXFS x.img                # ラベルを設定する
writing all SBs
new label = "MYXFS"
```

**`xfs_admin` は原則アンマウント状態で使います。**
ext 系の `tune2fs` がマウント中でも多くの設定を変えられるのとは違う点です。

**`xfs_info` … 情報を表示する**

```bash
$ sudo xfs_info /data                          # マウントポイントを指定して情報を見る
meta-data=x.img                  isize=512    agcount=4, agsize=25600 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=1        finobt=1, sparse=1, rmapbt=1
data     =                       bsize=4096   blocks=102400, imaxpct=25
         =                       sunit=0      swidth=0 blks
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=16384, version=2
```

**`xfs_info` は通常マウントポイントを指定**します。ここも `dumpe2fs` との違いです。

## バックアップと復元

| ファイルシステム | バックアップ | 復元 |
|:--|:--|:--|
| ext2 / ext3 / ext4 | `dump` | `restore` |
| **XFS** | **`xfsdump`** | **`xfsrestore`** |

**`xfsdump` は XFS ファイルシステムのバックアップを行うコマンド**です。
**`xfsrestore` はバックアップから XFS ファイルシステムの復元を行うコマンド**です。

```bash
$ sudo xfsdump -f /backup/data.dump /data      # /data をファイルへバックアップする
$ sudo xfsrestore -f /backup/data.dump /data   # バックアップから復元する
```

**名前にアンダースコアが入らない**のが特徴です。

```text
  ○ xfsdump     xfsrestore        ← バックアップ系はくっつく
  ○ xfs_admin   xfs_info   xfs_db ← 管理系はアンダースコアが入る
```

**この使い分けを知らないと、`xfs_dump` や `xfs_restore` と書いて間違えます。**

## debugfs 対話的に調べる

**`debugfs` は ext2 / ext3 / ext4 ファイルシステムの対話的デバッグを行うコマンド**です。

**起動すると専用の `debugfs` シェル画面となり、
その中で使えるさまざまなコマンドを使ってファイルシステムを調査・編集することができます。**

```bash
$ sudo debugfs /dev/sdb1                       # 対話モードで開く
debugfs 1.47.0 (5-Feb-2023)
debugfs:  ls -l /
debugfs:  stat <12>
debugfs:  quit
```

```bash
$ sudo debugfs -R "ls -l /" /dev/sdb1          # -R で1コマンドだけ実行する
```

**押さえる 3 点**

| 論点 | 結論 |
|:--|:--|
| **何をするコマンドか** | **専用のシェルを起動し、対話的に調査や編集を行う** |
| **対象は** | **ext2 / ext3 / ext4 のみ**。**名前に `e2` が入っていないが、xfs は扱えない** |
| **いつ使うか** | **`e2fsck` や `tune2fs` で解決できない**ときの最後の手段 |

**きめ細かで高度な操作が行える反面、操作には ext2 / ext3 / ext4 ファイルシステムに対する
十分な知識が必要**です。
**`e2fsck` や `tune2fs` などの便利なコマンドで解決できる場合は、まずそちらの利用を検討するべき**です。

**まぎらわしい説明の整理**

| 説明 | それは何の説明か |
|:--|:--|
| ファイルシステムの不整合を調査し、自動的に修復する | **`e2fsck -p`** の説明 |
| オプションを指定することでファイルシステムの設定を行う | **`tune2fs`** の説明 |
| ext2 / ext3 / ext4 だけでなく xfs も扱える | **誤り**。ext 専用 |
| **専用のシェルを起動し、対話的に調査や編集を行う** | **これが `debugfs`** |

## 光学メディアのイメージを作る

**CD や DVD といったメディア用のファイルシステムは、`mkisofs` という専用のコマンドで作成できます。**
**`mkisofs` の使い方は `mkfs` 系のコマンドとは異なっています。**

```text
mkisofs [オプション] ディレクトリ
```

| オプション | 説明 |
|:--|:--|
| **`-o ファイル`** | **続けてイメージファイル出力先を指定する** |
| **`-J`** | **Windows 系拡張である Joliet フォーマットで作成** |
| **`-R`** | **UNIX 系拡張である RockRidge フォーマットで作成** |
| **`-udf`** | **DVD で用いられる UDF フォーマットで作成** |

```bash
$ mkisofs -R -o backup.iso /data               # RockRidge 形式でイメージを作る
$ mkisofs -J -o win.iso /data                  # Joliet 形式（Windows 向け）で作る
$ mkisofs -R -J -o both.iso /data              # 両方の拡張を入れる（実務ではこれが多い）
```

**4 つの形式の違い**

| 形式 | 何のための拡張か |
|:--|:--|
| **ISO 9660** | **大本の規格**。ファイル名の長さや文字に厳しい制限がある |
| **RockRidge** | **ISO 9660 形式のファイル名制限などを緩和するため、独自の拡張を施した CD 系メディア用のフォーマット。UNIX 系 OS で利用される** |
| **Joliet** | 同じく ISO 9660 の拡張だが、**主に Windows 系 OS で利用される**。形式の詳細も異なる |
| **UDF** | **DVD で用いられる**形式 |

**`-R` と `-J` は「どちらの OS 向けの拡張か」で選びます。**
**両方付ければ、どちらの OS でも長いファイル名が読めます。**

**`-RR` というオプションは存在しません。**

**引数はディレクトリ**

```text
  mkfs 系   … デバイス を引数に取る（/dev/sdb1）
  mkisofs   … ディレクトリ を引数に取る（/data）
```

**「そのディレクトリの中身を、指定の形式のイメージファイルにする」**という動きです。
`mkfs` のように「既にある領域をフォーマットする」のとは考え方が違います。

USB から起動できるようにする `isohybrid` は
[その他のブートローダ](../05_起動プロセスとカーネル/その他のブートローダ.md) にあります。

## 結果画面の見方

**`xfs_info` の出力**

```text
meta-data=x.img                  isize=512    agcount=4, agsize=25600 blks
data     =                       bsize=4096   blocks=102400, imaxpct=25
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=16384, version=2
```

| 行 | 何が分かるか | どこを見るか |
|:--|:--|:--|
| **`meta-data`** | **i ノードのサイズとアロケーショングループの数** | **`agcount`** … 並列性に効く |
| **`data`** | **ブロックサイズと総ブロック数** | **`bsize` × `blocks` が容量** |
| `naming` | ディレクトリの形式 | `ftype=1` なら型情報を持つ |
| **`log`** | **ジャーナルの置き場所と大きさ** | **`internal log` は同じデバイス内** |

**`xfs_admin -l -u` の出力**

```text
label = "MYXFS"
UUID = bd617821-1f2b-48e3-a291-58c9e7745cde
```

**`/etc/fstab` に `LABEL=MYXFS` や `UUID=...` と書ける**値がここで分かります。

## 存在しないコマンドの整理

| 見かける名前 | 実際は |
|:--|:--|
| **`mkxfs`** | **存在しない**。`mke2fs` にあたる名前の XFS 版は無い。正しくは **`mkfs.xfs`** |
| **`xfs_dump`** | **存在しない**。正しくは **`xfsdump`** |
| **`xfs_restore`** | **存在しない**。正しくは **`xfsrestore`** |
| **`xfsadmin`** | **存在しない**。正しくは **`xfs_admin`**（アンダースコアが要る） |
| **`xfs_backup`** | **存在しない** |
| **`e3label`** | **存在しない**。`e2label` が ext2 / ext3 / ext4 すべてに使える |
| **`fslabel`** | **存在しない** |
| **`mkfsck`** | **存在しない** |
| `mkfs` でチェック | **`mkfs` は作成**。チェックは `fsck` |

**覚え方**

```text
  アンダースコアが入る    xfs_admin  xfs_info  xfs_db  xfs_repair
  アンダースコアが入らない xfsdump    xfsrestore
  そもそも存在しない      mkxfs      xfs_dump   xfsadmin
```
