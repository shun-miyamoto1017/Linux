## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| **パスの通った実行ファイルの場所を知る** | **`which コマンド名`** |
| **シェルがどう解釈しているかを知る**（通常 / 組み込み / エイリアス） | **`type コマンド名`** |
| **実行ファイル・マニュアル・ソースをまとめて知る** | **`whereis コマンド名`** |
| **あらゆるファイルを名前で高速に探す** | **`locate パターン`** |
| **`locate` のデータベースを更新する** | **`updatedb`** |
| **条件を付けて今この瞬間のファイルを探す** | **`find 起点 検索式`** |

**押さえる 3 点**

| 論点 | 結論 |
|:--|:--|
| **`PATH` に依存するのは** | **`which` と `type` の 2 つだけ**。`whereis` / `locate` / `find` は `PATH` に関わらず探せる |
| **`type` だけができること** | **シェルの組み込みコマンドかエイリアスかを見分ける** |
| **`locate` が見つけてくれない理由** | **データベースが古い**。`updatedb` で更新する |

## 5つのコマンドを一枚で見る

| コマンド | 何を探すか | どこから探すか | 速さ |
|:--|:--|:--|:--|
| **`which`** | **実行ファイルだけ** | **環境変数 `PATH` のディレクトリ** | 速い |
| **`type`** | **シェルがどう解釈するか**（通常 / 組み込み / エイリアス / 関数） | **シェル自身の情報 ＋ `PATH`** | 速い |
| **`whereis`** | **実行ファイル・マニュアル・ソース** | **Linux の標準的なディレクトリ**（決め打ち） | 速い |
| **`locate`** | **あらゆるファイル・ディレクトリ** | **あらかじめ作られた検索用データベース** | **とても速い** |
| **`find`** | **あらゆるファイル・ディレクトリ** | **実際にディスクをたどる** | **遅い** |

```text
  which     PATH の中だけ                 … 「いま打ったら何が動くか」
  type      シェルの解釈                   … 「本当は何が動くのか」
  whereis   標準ディレクトリ決め打ち       … 「マニュアルはどこ？」
  locate    データベース                   … 「名前は覚えてるけど場所を忘れた」
  find      ディスクを実際に歩く           … 「条件を付けて確実に」
```

## PATHに頼るものと頼らないもの

**シェルはパスの指定無しで入力されたコマンド（プログラム）を、
環境変数 `PATH` に設定されているディレクトリの中から検索して実行します。**
**これらのディレクトリは「パスが通っている」という言い方をします。**

```bash
$ echo $PATH                                   # どこを探しに行くのかを確認する
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

**ホームディレクトリで `/bin/ls` とせず `ls` だけでコマンドを実行できるのは、
環境変数 `PATH` に `/bin` へのパスが通っているためです。**

**ここが試験の分かれ目**です。

| コマンド | `PATH` に依存するか |
|:--|:-:|
| **`which`** | **する**（`PATH` のディレクトリしか見ない） |
| **`type`** | **する**（通常のコマンドは `PATH` を参照して絶対パスを出す） |
| **`whereis`** | **しない**（標準的なディレクトリを決め打ちで探す） |
| **`locate`** | **しない**（データベースを引く） |
| **`find`** | **しない**（指定した起点以下を実際に歩く） |
| `ls` | — （**そもそも検索コマンドではない**。指定ディレクトリの一覧を出すだけ） |

**「環境変数 `PATH` の値に関わらず、実行ファイルの場所を検索できるコマンドは」
という問いの答えは `locate` / `whereis` / `find` の 3 つ**です。

**「環境変数 `PATH` に基づいて実行ファイルの場所を表示するコマンドは」
という問いの答えは `which` / `type` の 2 つ**です。

**問題文の「〜に基づいて」と「〜に関わらず」で答えが正反対になります。**
**ここを読み飛ばすと必ず落とします。**

**管理者用コマンドが見つからない理由**

**通常、管理者用のコマンド（`/sbin` / `/usr/sbin` / `/usr/local/sbin` にあるコマンドなど）の
格納場所は、一般ユーザの環境変数 `PATH` には含まれていません。**
**そのため、`which` や `type` を使って一般ユーザが管理者用のコマンドの場所を確認することはできません。**

```bash
$ which fdisk                                  # 一般ユーザだと見つからないことがある
/usr/bin/which: no fdisk in (/usr/local/bin:/usr/bin:/home/shun/.local/bin)
$ whereis fdisk                                # whereis なら PATH に関係なく見つかる
fdisk: /usr/sbin/fdisk /usr/share/man/man8/fdisk.8.gz
```

**`command not found` と言われたら、まず `whereis` で当たる**のが実務の手順です。

## which パスの通った実行ファイルを探す

**`which` コマンドは指定したコマンドが格納されている場所を検索し、そのパスを表示します。**
**検索するディレクトリは環境変数 `PATH` で設定されている（パスが通っている）ディレクトリです。**
**デフォルトでは、最初にコマンドが見つかったディレクトリのパスを表示します。**

```text
which [オプション] コマンド名
```

```bash
$ which cp                                     # cp の実体がどこにあるかを見る
/usr/bin/cp
```

| オプション | 意味 |
|:--|:--|
| **`-a`** | **最初の 1 つで止めず、`PATH` 上で見つかるものをすべて表示する** |

```bash
$ which -a python3                             # 同名のコマンドが複数あるかを調べる
/usr/bin/python3
/bin/python3
```

**`-a` は「意図しない方が先に動いている」ときの調査に使います。**
**`PATH` の並び順で先に見つかった方が実行される**ためです。

**`which` が探すのは実行ファイルだけ**です。マニュアルもソースも探しません。

## type シェルがどう解釈するかを見る

**`type` コマンドは、指定したコマンドが通常のコマンドか、シェルの組み込みコマンドか、
エイリアスか、などの情報を表示します。**
**通常のコマンドの場合、そのコマンドのファイルが格納されている場所の絶対パスを表示します。**

**`type` の実行により、指定したコマンドに対してシェルがどのように解釈し
何を実行するのかがわかります。**

```text
type [オプション] コマンド名
```

### 3つの答え方

```bash
$ type cp                                      # 通常のコマンド
cp is /usr/bin/cp
$ type echo                                    # シェルの組み込みコマンド
echo is a shell builtin
$ type ll                                      # エイリアス
ll is aliased to `ls -l'
```

| 表示 | 意味 |
|:--|:--|
| **`〜 is /usr/bin/〜`** | **通常のコマンド**（ディスク上の実行ファイル） |
| **`〜 is a shell builtin`** | **シェルの組み込みコマンド**（`echo` / `cd` / `pwd` など） |
| **`〜 is aliased to '…'`** | **エイリアス** |
| `〜 is a function` | シェル関数 |

**便利なオプション**

| オプション | 意味 |
|:--|:--|
| **`-t`** | **種類だけを 1 語で返す**（`file` / `builtin` / `alias` / `function`） |
| **`-a`** | **同じ名前で見つかるものをすべて表示する** |

```bash
$ type -t cp                                   # 種類だけを取り出す（スクリプト向け）
file
$ type -t echo                                 # 組み込みかどうかを判定する
builtin
$ type -a echo                                 # 組み込みと実行ファイルの両方が存在する
echo is a shell builtin
echo is /usr/bin/echo
echo is /bin/echo
```

**`echo` のように「組み込みと実行ファイルの両方がある」コマンドでは、
組み込みの方が優先されます。**
**`man echo` の内容と実際の挙動がずれるのはこれが理由**です。

### which との違い

| | **`which`** | **`type`** |
|:--|:--|:--|
| 正体 | **外部コマンド**（`/usr/bin/which`） | **シェルの組み込みコマンド** |
| **エイリアスを見分けられるか** | **できない** | **できる** |
| **組み込みコマンドを見分けられるか** | **できない** | **できる** |
| シェル関数を見分けられるか | できない | できる |
| 探す範囲 | **`PATH` の実行ファイルだけ** | シェルの解釈 ＋ `PATH` |

```bash
$ alias ls='ls --color=auto'                   # エイリアスを定義しておく
$ which ls                                     # which はエイリアスに気づかない
/usr/bin/ls
$ type ls                                      # type はエイリアスだと教えてくれる
ls is aliased to `ls --color=auto'
```

**「`ls` の挙動がおかしい」と言われたら `type ls`**、が一次調査の型です。
**`which` では原因にたどり着けません。**

## whereis 実行ファイルとマニュアルとソースを探す

**`whereis` コマンドは、指定したコマンド、またそのマニュアル、ソースコードが
格納されている場所を検索し、絶対パスで表示します。**

**Linux でコマンドの格納される標準的なディレクトリの中から検索する**ため、
**環境変数 `PATH` に左右されません。**

```text
whereis [オプション] コマンド名
```

```bash
$ whereis cp                                   # 実行ファイルとマニュアルの場所を見る
cp: /bin/cp /usr/share/man/man1p/cp.1p.gz /usr/share/man/man1/cp.1.gz
```

**左からコマンド（バイナリ形式の実行ファイル）、マニュアル、ソースコードの場所**が並びます。

> **実機では man が入っていないと実行ファイルだけが出ます**（サンドボックスで確認）。
> ```text
> $ whereis cp
> cp: /usr/bin/cp
> ```
> **`man-db` や `*-doc` パッケージが入っていない最小構成では、マニュアルの行が出ません。**
> **試験の出力例のように 3 種類が並ぶのは、ドキュメントまで入っている環境**です。

| 出力の例 | 何の場所か |
|:--|:--|
| **`/bin/cp`** | **実行ファイル** |
| **`/usr/share/man/man1/cp.1.gz`** | **マニュアル**（`/usr/share/man` 配下） |
| `/usr/src/…` | ソースコード（あれば） |

| オプション | 意味 |
|:--|:--|
| **`-b`** | **実行ファイルだけを探す** |
| **`-m`** | **マニュアルだけを探す** |
| **`-s`** | **ソースだけを探す** |
| `-l` | 探しに行くディレクトリの一覧を表示する |

```bash
$ whereis -b cp                                # 実行ファイルだけに絞る
cp: /usr/bin/cp
$ whereis -l | head -4                         # どこを探しているのかを確認する
bin: /usr/bin
bin: /usr/sbin
bin: /usr/lib/x86_64-linux-gnu
bin: /usr/lib
```

**`-b` / `-m` / `-s` は「binary / manual / source」の頭文字**です。

## locate データベースから高速に探す

**`locate` コマンドは、あらかじめ作成された検索用データベースに沿って、
検索パターンに合致したファイルやディレクトリを高速に検索するコマンド**です。

**Windows での「インデックスを付けて検索を速くする」という機能と同様**です。

```text
locate [オプション] パターン
```

```bash
$ locate whereis                               # 名前に whereis を含むものを探す
/usr/bin/whereis
/usr/share/bash-completion/completions/whereis
```

| オプション | 意味 |
|:--|:--|
| **`-i`** | **大文字小文字を区別しない** |
| **`-c`** | **件数だけを表示する** |
| **`-b`** | **パス全体ではなくファイル名の部分だけで探す** |
| `-l 件数` | 指定した件数で打ち切る |
| `-r` | パターンを正規表現として解釈する |

```bash
$ locate -c whereis                            # 何件ヒットするかだけ見る
2
$ locate -i WHEREIS | head -2                  # 大文字で書いても見つかる
/usr/bin/whereis
/usr/share/bash-completion/completions/whereis
```

### updatedb で更新する

**`updatedb` コマンドで、`locate` コマンドが利用する検索用のデータベースを更新します。**

```bash
$ sudo updatedb                                # データベースを作り直す
```

**データベースが更新された後に作成や変更されたファイルは `locate` コマンドで検索できません。**
**検索用のデータベースは `updatedb` コマンドで定期的に更新する必要があります。**

**`updatedb` コマンドの設定ファイルは `/etc/updatedb.conf`** です。

```bash
$ cat /etc/updatedb.conf                       # 何を対象から外しているかを見る
PRUNE_BIND_MOUNTS="yes"
PRUNEPATHS="/tmp /var/spool /media /var/lib/os-prober …"
PRUNEFS="NFS afs autofs … proc sysfs tmpfs …"
```

| 設定 | 意味 |
|:--|:--|
| **`PRUNEPATHS`** | **この**パス**を対象から外す** |
| **`PRUNEFS`** | **この**ファイルシステムの種類**を対象から外す** |
| `PRUNENAMES` | この名前のディレクトリを対象から外す（`.git` など） |
| `PRUNE_BIND_MOUNTS` | バインドマウントを二重に登録しない |

**多くのディストリビューションでは、`cron` や systemd のタイマーで
1 日 1 回 `updatedb` が自動実行されます。**

```bash
$ systemctl list-timers | grep -i updatedb     # 自動実行の設定を確認する
```

### 探せないファイルがある理由

**「あるはずのファイルが `locate` で出てこない」には 2 つの理由**があります。

| 理由 | 確かめ方 | 対処 |
|:--|:--|:--|
| **データベースが古い**（作った直後のファイル） | `find` なら見つかる | **`sudo updatedb`** を実行する |
| **除外対象のパスにある**（`/tmp` など） | `/etc/updatedb.conf` の `PRUNEPATHS` を見る | **`find` を使う**。または設定から外す |

```bash
$ touch /home/shun/newfile.txt                 # 新しいファイルを作る
$ locate newfile.txt                           # まだデータベースに無い（何も出ない）
$ sudo updatedb                                # データベースを更新する
$ locate newfile.txt                           # 今度は見つかる
/home/shun/newfile.txt
```

**`locate` は「速いが、今この瞬間の状態とは限らない」**——ここが `find` との本質的な違いです。

## find 条件を付けて実際に探す

**`find` コマンドは指定したディレクトリ以下からファイルやディレクトリを検索するコマンド**です。
**検索条件としてファイル名やディレクトリ名以外にも、
アクセス権やファイルのサイズなど、さまざまな検索条件を指定できます。**

**`locate` や `whereis` に比べ時間はかかりますが、
コマンド名を含む実行ファイルを検索することが可能**です。

```bash
$ find /usr -name "*whereis*"                  # /usr 以下を実際に歩いて探す
/usr/bin/whereis
/usr/share/man/man1/whereis.1.gz
/usr/share/bash-completion/completions/whereis
```

**3 つのコマンドで同じものを探した比較**

```text
  locate whereis        データベースを引く          … 一瞬。ただし古いかもしれない
  whereis whereis       標準ディレクトリを決め打ち   … 実行ファイルとマニュアルだけ
  find /usr -name "*whereis*"  ディスクを歩く        … 遅いが確実で、条件も付けられる
```

検索式とアクションの詳細は
[findによるファイル検索](./findによるファイル検索.md) にあります。

## 使い分けの決め方

```text
  ① いま打ったコマンドが何を実行しているのか知りたい
        → type      （エイリアスや組み込みも分かる）

  ② 実行ファイルのパスだけ欲しい
        → which     （PATH の中だけ。スクリプトで使いやすい）

  ③ マニュアルやソースの場所も知りたい／PATH に無いコマンドを探したい
        → whereis

  ④ 名前は分かるが場所を忘れた（実行ファイルとは限らない）
        → locate    （出てこなければ sudo updatedb）

  ⑤ 条件を付けて確実に探したい／作りたてのファイルを探したい
        → find
```

**問われ方 → 答えの早見表**

| 問われ方 | 答え |
|:--|:--|
| **指定したコマンド、またそのマニュアル、ソースコードの場所を絶対パスで表示する** | **`whereis`** |
| **指定したコマンドをシェルがどのように解釈するかを表示する** | **`type`** |
| **環境変数 `PATH` に基づいて実行ファイルの場所を表示する**（2つ） | **`which` / `type`** |
| **環境変数 `PATH` の値に関わらず実行ファイルの場所を検索できる**（3つ） | **`locate` / `whereis` / `find`** |
| **`locate` が利用する検索用データベースを更新する** | **`updatedb`** |
| **あらかじめ作成されたデータベースから高速に検索する** | **`locate`** |
| コマンドの場所のパスを表示する（2つ） | **`which` / `whereis`** |

## 手を動かして確かめる

**① 3つのコマンドで同じものを探す**

```bash
$ locate whereis                               # データベースから引く
/usr/bin/whereis
/usr/share/bash-completion/completions/whereis
$ whereis whereis                              # 標準ディレクトリから探す
whereis: /usr/bin/whereis
$ find /usr -name "*whereis*"                  # 実際にディスクを歩く
/usr/bin/whereis
/usr/share/man/man1/whereis.1.gz
/usr/share/bash-completion/completions/whereis
```

**同じ「whereis を探す」でも、拾ってくるものが違う**のが分かります。

**② type で3種類を見分ける**

```bash
$ type cp                                      # 通常のコマンド
cp is /usr/bin/cp
$ type echo                                    # シェルの組み込み
echo is a shell builtin
$ alias ll='ls -l'                             # エイリアスを作る
$ type ll                                      # エイリアスだと分かる
ll is aliased to `ls -l'
$ type -t cp; type -t echo; type -t ll         # 種類だけを取り出す
file
builtin
alias
```

**③ locate が古いことを実際に確かめる**

```bash
$ touch ~/loctest/zz_newfile_12345.txt         # 新しいファイルを作る
$ locate zz_newfile_12345                      # まだ見つからない（何も出ない）
$ sudo updatedb                                # データベースを更新する
$ locate zz_newfile_12345                      # 今度は見つかる
/home/claude/loctest/zz_newfile_12345.txt
```

**④ PRUNEPATHS の効果を確かめる**

```bash
$ touch /tmp/zz_pruned_999.txt                 # 除外対象の /tmp に作る
$ sudo updatedb                                # 更新しても
$ locate zz_pruned_999                         # 見つからない（/tmp は PRUNEPATHS）
$ find /tmp -name "zz_pruned_999*"             # find なら見つかる
/tmp/zz_pruned_999.txt
```

**`/etc/updatedb.conf` の `PRUNEPATHS` に `/tmp` が入っている**ためです。
**「`locate` に出ない ＝ 存在しない」ではない**ことが、これで確認できます。

**⑤ which と type でエイリアスの見え方が違うことを確かめる**

```bash
$ alias ls='ls --color=auto'                   # エイリアスを定義する
$ which ls                                     # which は実行ファイルしか見ない
/usr/bin/ls
$ type ls                                      # type はエイリアスを教えてくれる
ls is aliased to `ls --color=auto'
```

## 存在しないコマンドの整理

| 見かける名前 | 実際は |
|:--|:--|
| **`where`** | **存在しない**。正しくは **`whereis`** |
| **`whichis`** | **存在しない**。`which` と `whereis` を混ぜた引っかけ |
| **`locatedb`** | **存在しない**。データベースの更新は **`updatedb`** |
| **`update`** | **存在しない**（`locate` 用としては）。正しくは **`updatedb`** |
| **`updb`** / **`dbup`** / **`dbupdate`** | **すべて存在しない** |
| `grep` でコマンドの場所 | **`grep` はファイルの中身を検索する**。場所は探さない |
| `ls` でコマンドの場所 | **`ls` は指定ディレクトリの一覧を出すだけ** |

**覚え方**

```text
  which    ← PATH の中を「どっち（which）が動くか」
  whereis  ← 「どこにある（where is）？」実行ファイル・マニュアル・ソース
  type     ← 「種類（type）は何？」通常 / 組み込み / エイリアス
  locate   ← 「位置を突き止める（locate）」データベース経由
  updatedb ← 「db を update する」そのままの名前
```

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| **`which` で管理コマンドが見つからない** | **一般ユーザの `PATH` に `/sbin` が無い** | **`whereis`** を使う。または `sudo` 経由で実行する |
| **`locate` に新しいファイルが出ない** | **データベースが古い** | **`sudo updatedb`** を実行する |
| **`locate` に `/tmp` のファイルが出ない** | **`PRUNEPATHS` で除外されている** | **`find`** を使う |
| **`ls` の挙動がおかしい** | **エイリアスが定義されている** | **`type ls`** で確認する。`\ls` か `command ls` で素の動作にする |
| **`which` と実際に動くものが違う** | **エイリアスかシェル関数がある** | **`type -a`** で全部見る |
| **`man echo` と実際の動きが違う** | **組み込みの `echo` が優先されている** | **`help echo`** を見る。`type -a echo` で確認する |
| **`whereis` でマニュアルが出ない** | そのコマンドに man が入っていない | パッケージによっては別途インストールが要る |
| **`updatedb` が `permission denied`** | 一般ユーザでは書けない | **`sudo`** を付ける |

## クラウド実務メモ

**① コンテナでは `which` が入っていないことがある**

**`distroless` や `alpine` の最小イメージには `which` が無い**ことがあります。
**`type` はシェルの組み込みなので、シェルさえあれば必ず使えます。**

```bash
$ type -t python3                              # which が無くても種類は分かる
file
$ command -v python3                           # POSIX 標準。which の代わりになる
/usr/local/bin/python3
```

**スクリプトで「そのコマンドがあるか」を判定するなら `command -v` が最も移植性が高い**です。

```bash
#!/bin/bash
if ! command -v jq >/dev/null 2>&1; then       # jq が無ければ終了する
  echo "jq が必要です" >&2
  exit 1
fi
```

**② 踏み台や AMI の PATH 汚染を疑う**

**「同じ playbook なのにこのサーバだけ失敗する」の典型は、`PATH` の並び順**です。

```bash
$ which -a terraform                           # 複数入っていないかを見る
/usr/local/bin/terraform
/home/ec2-user/bin/terraform
$ terraform version                            # 実際に動いている方を確認する
```

**`/usr/local/bin` が先に来るか `~/bin` が先に来るかで結果が変わります。**
**Ansible の `ansible.builtin.command` は非ログインシェルで動く**ため、
**手で打ったときと `PATH` が違う**——ここが事故の温床です。

**③ `locate` は本番サーバに入れないことが多い**

**`updatedb` はディスク全体を舐める**ので、
**I/O が効くサーバ（DB、ログ集約）では負荷源になります。**

| 環境 | 方針 |
|:--|:--|
| **開発・検証** | `locate` を入れて構わない。調査が速い |
| **本番（I/O が効く）** | **入れないか、`PRUNEPATHS` にデータ領域を追加する** |
| **コンテナ** | **そもそも入れない**。イメージが太る |

```bash
# /etc/updatedb.conf にデータ領域を足しておく
PRUNEPATHS="/tmp /var/spool /media /data /var/lib/docker"
```

**④ 監査では `find` を使う**

**「今この瞬間の状態」が要る監査やインシデント対応では `locate` を使いません。**
**データベースが古ければ、攻撃者が置いたファイルは出てこない**ためです。

```bash
$ sudo find / -xdev -newermt '-1 hours' -type f 2>/dev/null   # 直近1時間に作られたファイル
```

**`-xdev` を付けて別ファイルシステムへ降りないようにする**のがコツです。
