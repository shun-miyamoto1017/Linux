## 全体の流れは5段階

```text
  ① 物理的に接続する
        ▼
     /dev/sdc として認識される（この時点では中身は空）
        ▼
  ② fdisk /dev/sdc            ← パーティションを切る
        ▼
     /dev/sdc1 ができる
        ▼
  ③ mkfs -t ext4 /dev/sdc1    ← ファイルシステムを作る
        ▼
     読み書きできる構造ができる（でもまだ触れない）
        ▼
  ④ mount /dev/sdc1 /data     ← ディレクトリに繋ぐ
        ▼
     /data として読み書きできる
        ▼
  ⑤ /etc/fstab に登録          ← 再起動後も自動でマウントされる
```

**どこで止まっているかの見分け方**

| 症状 | どこまで進んでいるか | 次にやること |
|:--|:--|:--|
| `lsblk` にディスク自体が出ない | **①が未完了** | 接続・アタッチを確認する |
| `lsblk` に出るがパーティションが無い | **②が未完了** | `fdisk` でパーティションを切る |
| `blkid` で `TYPE=` が出ない | **③が未完了** | `mkfs` でファイルシステムを作る |
| `df` に出ない | **④が未完了** | `mount` する |
| **再起動したら消えた** | **⑤が未完了** | **`/etc/fstab` に書く** |

**この表の順に上から確認していけば、必ずどこかで引っかかります。**

## 1 パーティションを作る

**パーティションは、ハードディスクの記録領域を複数に分けた、それぞれの領域**です。
**MBR 形式では `fdisk` を使います。**

```bash
$ lsblk                                # ① ディスクが認識されているか確認する
$ sudo fdisk /dev/sdc                  # ② 対話モードでパーティションを編集する
```

### fdisk の主なコマンド

**`fdisk` は対話モードで動きます。** 1 文字のコマンドを打って操作します。

| コマンド | 何をするか |
|:--|:--|
| **`m`** | **ヘルプを表示する**（迷ったらこれ） |
| **`p`** | **現在のパーティションテーブルを表示する** |
| **`n`** | **新しいパーティションを作成する** |
| **`d`** | **パーティションを削除する** |
| **`t`** | **パーティションのタイプ（システムID）を変更する** |
| `l` | 指定できるタイプの一覧を表示する |
| **`w`** | **変更を書き込んで終了する** |
| **`q`** | **保存せずに終了する** |

**`w` を打つまでディスクには何も書かれません。**
**間違えたら `q` で抜ければ無傷**です。ここが `fdisk` の安全弁になっています。

```text
  n  →  パーティションを作る
  t  →  タイプを変える（スワップなら 82、Linux なら 83）
  p  →  確認する
  w  →  ここで初めて書き込まれる
```

**よく使うタイプ番号**

| 番号 | 意味 |
|:--|:--|
| **`83`** | **Linux**（既定） |
| **`82`** | **Linux swap** |
| `8e` | Linux LVM |
| `fd` | Linux raid 自動検出 |

**スワップ用に切るときは `t` で `82` を付けます。**
ただし**タイプを付けただけでは中身は空**なので、`mkswap` が別に必要です
（[スワップ領域](./スワップ領域.md) 参照）。

```bash
$ sudo fdisk -l /dev/sdc               # 対話に入らず一覧だけ見る
$ sudo partprobe /dev/sdc              # カーネルにパーティションテーブルを読み直させる
```

**補足** … `w` の後もカーネルが古い情報を持っていることがあります。
**`/dev/sdc1` が現れないときは `partprobe`**（または再起動）で読み直させます。

### GPT では parted か gdisk を使う

**`fdisk` は MBR 形式のためのコマンド**です。
**2TB を超えるディスクや UEFI 環境では GPT 形式**を使うため、別のコマンドになります。

| 形式 | 使うコマンド | 扱えるサイズ |
|:--|:--|:--|
| **MBR** | **`fdisk`** | **2TB まで** |
| **GPT** | **`parted`** / **`gdisk`** | 2TB 超も可 |

```bash
$ sudo parted /dev/sdc mklabel gpt                    # GPT のラベルを作る
$ sudo parted /dev/sdc mkpart primary ext4 0% 100%    # ディスク全体を1つのパーティションにする
$ sudo parted /dev/sdc print                          # 確認する
```

**補足** … **近年の `fdisk` は GPT も扱えるようになっています**が、
**試験では「MBR は `fdisk`、GPT は `parted` / `gdisk`」**という対応で押さえます。

MBR と GPT の違いは [BIOSとUEFI](../05_起動プロセスとカーネル/BIOSとUEFI.md) にあります。

## 2 ファイルシステムを作る

**`mkfs` コマンドでファイルシステムを作成できます。**

```text
mkfs [オプション] デバイス名
```

パーティションを切っただけでは使えません。**「フォーマットする」作業がこれ**にあたります。

```text
ディスク ──[パーティション作成]──> パーティション ──[mkfs]──> ファイルシステム ──[mount]──> 使える
           fdisk / parted                        mkfs                        mount
```

### 主なオプション

| オプション | 説明 |
|:--|:--|
| **`-t ファイルシステムの種類`** | **ファイルシステムの種類を指定** |
| **`-c`** | **ファイルシステムを作成する前に不良ブロックを検査** |
| `-v` | 詳細を表示する |

**`-t` オプションで、ext2 / ext3 / ext4 のみならず xfs、jfs などのファイルシステムを指定できます。**

```bash
$ sudo mkfs -t ext4 /dev/sdb1        # ext4 で作成する
$ sudo mkfs -t xfs /dev/sdb1         # XFS で作成する
$ sudo mkfs -t ext4 -c /dev/sdb1     # 不良ブロックを検査してから作成する
```

**補足 … `-c` は種類別ツールへ渡されるオプションです**

公式の man ページを確認すると、`mkfs` フロントエンド自身のオプションとして
記載されているのは `-t` と `-V`（詳細表示）`-h`（ヘルプ）だけです。
`-c` は **`mkfs` が呼び出す種類別のコマンド（`mke2fs` など）に渡されるオプション**です。

そのため、**`-c` が使えるかどうかはファイルシステムの種類によります**。
ext 系では使えますが、`mkfs.xfs` には `-c` の不良ブロック検査はありません。

**注意 … `-c` は時間がかかります**

不良ブロック検査はディスク全体を読むため、**大容量ディスクでは数時間かかる**ことがあります。
クラウドの仮想ディスクは物理的な不良ブロックを意識しなくてよいので、通常は使いません。

### -t を省略すると ext2 になる

**`-t` オプションを使用しない場合は、デフォルトで ext2 ファイルシステムが作成されます。**

エラーにはなりません。**黙って ext2 が作られる**のが要注意ポイントです。

```bash
$ sudo mkfs /dev/hda1                # -t を付けずに実行する
mke2fs 1.47.0 (5-Feb-2023)
Creating filesystem with 5120 4k blocks and 5120 inodes
（略）

$ sudo blkid /dev/hda1               # 何ができたか確認する
/dev/hda1: UUID="76cfc3ed-..." BLOCK_SIZE="4096" TYPE="ext2"    ← ext2 になっている
```

man ページにも「If not specified, the default filesystem type (currently ext2) is used.」
（指定しない場合、既定のファイルシステムタイプ（現在は ext2）が使われる）と明記されています。

**なぜ問題なのか**

**ext2 は古いファイルシステムであり、ジャーナリング機能（更新履歴をジャーナル（ログ）に
記録しておく機能）がないなどの理由で現在は積極的に利用されることはありません。**

意図せず ext2 で作ってしまうと、
**障害時の復旧に時間がかかり、データ破損のリスクも高い**状態で運用することになります。

**`mkfs` を使うときは、必ず `-t` を付ける**と覚えてください。

### mke2fs ext系専用のコマンド

**`mke2fs` コマンドで ext2 / ext3 / ext4 ファイルシステムを作成できます。**

```text
mke2fs [オプション] デバイス名
```

| オプション | 説明 |
|:--|:--|
| **`-j`** | **ext3 ファイルシステムを作成**（journal の `j`） |
| **`-t ファイルシステムの種類`** | **ファイルシステムの種類を指定**（ext2 / ext3 / ext4） |
| **`-c`** | **ファイルシステムを作成する前に不良ブロックを検査** |
| **`-L ラベル`** | **続けてボリュームラベル名を指定**（**大文字の `L`**） |
| **`-b ブロックサイズ`** | **続けてブロックサイズを byte 単位で指定** |
| **`-m 割合`** | **続けて root 用予備領域の割合を指定**（既定は 5%） |
| **`-n`** | **実際には実行せず確認のみ** |
| `-q` | 静かに実行する（進捗を出さない） |

**`-n` … 作る前に結果を見る**

**`-n` を付けると、実際にはファイルシステムを作らずに、
どのように作成されるのか（i ノード数やブロック総数）だけを表示します。**

```bash
$ sudo mke2fs -n /dev/sdb1                  # 実行せず、作られる内容だけを確認する
mke2fs 1.47.0 (5-Feb-2023)
Filesystem label=
OS type: Linux
Block size=1024 (log=0)
Fragment size=1024 (log=0)
131072 inodes, 524288 blocks
```

**本番のディスクに対して「本当にこれでよいか」を確かめてから実行**できます。
**i ノード数が足りるかどうかを事前に見る**のが実務での使い方です。

**`-m` … root 用予備領域の割合**

**root ユーザ用の予備領域とは、通常の領域とは別に確保された root ユーザのみが使える予備領域**で、
**予約ブロック**とも言います。
**このように分けておくことで、通常の領域を使い切ってしまった場合にも、
root ユーザは専用の領域を使ってメンテナンス作業が可能になります。**

```bash
$ sudo mke2fs -j -m 1 /dev/sdb1             # 予備領域を既定の5%から1%に減らして作る
```

**データ用の大きなディスクでは 1% 程度に減らす**のが定石です。
**1TB のディスクで 5% なら 50GB が使えないまま**になるためです。

**`-L` は大文字**

```text
  ○ mkfs -t ext2 -L ROOT /dev/sdb1     大文字の L がラベル
  ✕ mkfs -t ext2 -l ROOT /dev/sdb1     小文字の l は別の意味
  ✕ mke2fs -l ROOT /dev/sdb1           同上
```

**`mke2fs` のオプションは `mkfs -t ext2` のように `mkfs` コマンドを経由しても
まったく同じものが使えます。**

```bash
$ sudo mkfs -t ext2 -L ROOT /dev/sdb1       # ext2 を作り、ROOT というラベルを付ける
```

**作成済みのファイルシステムのラベルを変えたいとき**は
`tune2fs -L` か `e2label` を使います
（[ファイルシステム別ユーティリティ](./ファイルシステム別ユーティリティ.md)）。

**`mke2fs` もオプションなしなら ext2 になります**

```bash
$ sudo mke2fs /dev/hda1              # 種類を指定しない → ext2
$ sudo blkid /dev/hda1               # 何ができたか確認する
/dev/hda1: UUID="712fdb08-..." BLOCK_SIZE="4096" TYPE="ext2"
```

**`-j` を付けると ext3 になります**

```bash
$ sudo mke2fs -j /dev/hda1           # ジャーナル付き＝ext3 を作る
$ sudo blkid /dev/hda1               # ext3 になっている
/dev/hda1: UUID="9b06dbea-..." SEC_TYPE="ext2" BLOCK_SIZE="4096" TYPE="ext3"
```

**`-j` は「ext3 を作る」という意味**です。`ext2` に**ジャーナルを足したものが ext3**
という関係がそのままオプション名になっています。

### ext2 を作る3つの書き方

`/dev/hda1` に ext2 を作る、という同じ目的でも複数の書き方が成立します。

| 書き方 | 成立するか | 理由 |
|:--|:-:|:--|
| **`mkfs -t ext2 /dev/hda1`** | **○** | `-t` で明示している |
| **`mke2fs /dev/hda1`** | **○** | `mke2fs` はオプションなしで ext2 |
| **`mkfs /dev/hda1`** | **○** | `mkfs` は `-t` 省略時の既定が ext2 |
| `mke2fs -j /dev/hda1` | ✕ | **`-j` は ext3 を作る**オプション |
| `mkfs -c ext2 /dev/hda1` | ✕ | **`-c` は種類を指定するオプションではない** |

**`mkfs -c ext2 /dev/hda1` がなぜ誤りなのか**

`-c` は**不良ブロックの検査**を指示するオプションで、**種類を受け取りません**。
そのため後ろに続く `ext2` が**デバイス名**として、`/dev/hda1` が**ブロック数**として
解釈されてしまいます。

```bash
$ sudo mkfs -c ext2 /dev/hda1        # -c は種類指定ではない
mke2fs 1.47.0 (5-Feb-2023)
mkfs.ext2: invalid blocks '/dev/hda1' on device 'ext2'
                          └─ ブロック数扱い    └─ デバイス名扱い
```

**種類を指定するのは `-t`**、**不良ブロック検査は `-c`** と覚え分けます。

### ext3 を作る2つの書き方

**`-j` と `-t ext3` はどちらも ext3 になります。** 実機で確かめた結果です。

```bash
$ mke2fs -q -j v.img        && blkid v.img     # -j で作る
v.img: UUID="4a73..." SEC_TYPE="ext2" BLOCK_SIZE="4096" TYPE="ext3"
$ mke2fs -q -t ext3 w.img   && blkid w.img     # -t ext3 で作る
w.img: UUID="c5fc..." SEC_TYPE="ext2" BLOCK_SIZE="4096" TYPE="ext3"
```

`/dev/sda3` に ext3 を作る、という同じ目的で成立する書き方は次のとおりです。

| 書き方 | 成立するか | 理由 |
|:--|:-:|:--|
| **`mke2fs -j /dev/sda3`** | **○** | **`-j` はジャーナリング機能を付与し、ext3 を作成するオプション** |
| **`mke2fs -t ext3 /dev/sda3`** | **○** | **`-t` は作成するファイルシステムの種類を指定するオプション** |
| `mke2fs /dev/sda3` | ✕ | **`-j` が無いので ext3 ではなく ext2 を作ってしまう** |
| `mke2fs -L ext3 /dev/sda3` | ✕ | **`-L` はボリュームラベルの指定**。`ext3` という名前のラベルが付くだけで、形式は ext2 のまま |
| `mkfs ext3 /dev/sda3` | ✕ | **書式が誤り**。`mkfs -t ext3 /dev/sda3` と書く必要がある |

**`-L ext3` の罠を実機で確かめる**

```bash
$ mke2fs -q -L ext3 x.img && blkid x.img       # ラベルだけ ext3 になる
x.img: LABEL="ext3" UUID="a68d..." BLOCK_SIZE="4096" TYPE="ext2"
                                                     └─ 形式は ext2 のまま
```

**`LABEL="ext3"` と `TYPE="ext2"` が同時に出る**のが動かぬ証拠です。
**ラベルは単なる名札**で、ファイルシステムの形式には一切影響しません。

**同じく、ext2 を作るのに `-b` を付けても種類は変わりません。**

```bash
$ sudo mke2fs -b 1024 /dev/sda3                # ブロックサイズ 1024 の ext2 を作る
```

| 書き方 | できるもの |
|:--|:--|
| **`mke2fs -b 1024 /dev/sda3`** | **ext2**（`-b` はブロックサイズの指定なので種類は既定のまま） |
| `mke2fs -j /dev/sda3` | **ext3**（`-j` は種類を変える） |
| `mke2fs -n /dev/sda3` | **何もできない**（`-n` は確認のみで実行しない） |

**「種類を変えるオプション」は `-j` と `-t` の 2 つだけ**、と整理しておくと迷いません。

ブロックサイズや i ノードが何を意味するのかは
[ext系ファイルシステムの内部構造](./ext系ファイルシステムの内部構造.md) にあります。

### mkfs と mke2fs の関係

**`mkfs` コマンドは `mke2fs` コマンドなどのフロントエンドとして統一的に使えます。**

```text
mkfs -t ext4 /dev/sdb1
   │
   └─ 内部で mkfs.ext4（＝ mke2fs -t ext4）を呼び出す

mkfs -t xfs /dev/sdb1
   │
   └─ 内部で mkfs.xfs を呼び出す
```

| | `mkfs` | `mke2fs` |
|:--|:--|:--|
| 作れる種類 | **`-t` で ext 系 / xfs / jfs など何でも** | **ext2 / ext3 / ext4 のみ** |
| 位置づけ | 各種コマンドの**フロントエンド** | ext 系**専用の本体** |
| `-t` 省略時 | **ext2** | **ext2** |

**`fdisk` で作ったパーティションにファイルシステムを作れるのは、この 2 つ**です。
`make2fs` / `mk2fs` / `mkfdisk` といったコマンドは**存在しません**。

**パーティションを作っただけでは使えません**（冒頭の「全体の流れ」の図のとおり、`mkfs` を経てはじめて使えます）。

```text
fdisk でパーティションを作る … ディスクを区切っただけ。まだファイルを置けない
        ↓
mkfs / mke2fs でファイルシステムを作る ← ここで「ファイル単位のデータ管理」ができるようになる
        ↓
mount でマウントする … 実際に読み書きできるようになる
```

### 公式は種類別コマンドを推奨している

man ページの冒頭に、こう書かれています。

> This mkfs frontend is deprecated in favour of filesystem specific mkfs.\<type\> utils.
> （この `mkfs` フロントエンドは非推奨であり、ファイルシステム固有の `mkfs.<種類>` を使うべきである）

**`mkfs -t ext4` は、実際には `mkfs.ext4` を呼び出しているだけ**です。

```bash
$ ls /sbin/mkfs*                     # 種類別のコマンドが並んでいる
/sbin/mkfs  /sbin/mkfs.bfs  /sbin/mkfs.cramfs  /sbin/mkfs.ext2
/sbin/mkfs.ext3  /sbin/mkfs.ext4  /sbin/mkfs.minix
```

| 書き方 | 評価 |
|:--|:--|
| `mkfs -t ext4 /dev/sdb1` | 動く。**試験ではこちらが問われる** |
| **`mkfs.ext4 /dev/sdb1`** | **公式推奨。実務ではこちら** |

**種類別コマンドのほうが良い理由**

- そのファイルシステム固有のオプションが `--help` にきちんと出る
- `-t` の書き忘れによる ext2 事故が起きない
- インストールされていない種類は**そもそもコマンドが無い**ので、実行前に気づける

```bash
$ mkfs.xfs                           # 入っていなければコマンドが見つからない
-bash: mkfs.xfs: command not found
$ sudo dnf install -y xfsprogs       # XFS のツールを入れる
```

**作成後は必ず確認します**

```bash
$ sudo blkid /dev/sdb1               # 種類と UUID を確認する
/dev/sdb1: UUID="b9301c5a-..." BLOCK_SIZE="4096" TYPE="ext4"

$ lsblk -f                           # ツリーで俯瞰する
$ sudo file -s /dev/sdb1             # 中身から判定する（未フォーマットなら "data"）
```

**注意 … `mkfs` は中身を消します**

`mkfs` は**そのパーティションの内容をすべて破棄**します。
`dd` と同じく確認を求めてこないので、**デバイス名を必ず `lsblk` で確認**してから実行します。
詳しくは [dd コマンド](./ddコマンド.md) の「dd は危険なコマンド」も参照してください。

## 3 マウントする

**ファイルシステムを作っただけでは、まだ読み書きできません。**
**ディレクトリツリーに繋いで初めて使えるようになります。**

```bash
$ sudo mkdir -p /data                  # ① マウント先のディレクトリを作る
$ sudo mount /dev/sdc1 /data           # ② デバイス、マウント先の順に指定する
$ df -h /data                          # ③ マウントされたことを確認する
```

**`mount` は「デバイス」「マウント先」の順**です。逆に書くと通りません。
詳細は [マウントとアンマウント](./マウントとアンマウント.md) にあります。

## 4 fstab に登録して恒久化する

**`mount` コマンドでのマウントは再起動で消えます。**
**恒久的に使うには `/etc/fstab` に書きます。**

```bash
$ sudo blkid /dev/sdc1                 # ① UUID を調べる
/dev/sdc1: UUID="b7be915b-083c-4dd0-872f-adc6c47a1f76" TYPE="ext4"
$ sudo vi /etc/fstab                   # ② 1行追記する
```

```text
UUID=b7be915b-083c-4dd0-872f-adc6c47a1f76  /data  ext4  defaults  0 2
```

```bash
$ sudo umount /data                    # ③ いったん外して
$ sudo mount -a                        # ④ fstab の記述だけでマウントできるか試す
$ df -h /data                          # ⑤ 付いていれば書き方は正しい
```

**④ の `mount -a` を再起動前に必ず実行**します。
**書き間違えたまま再起動すると、起動しなくなることがあります。**

書式とオプションは [fstabの書き方](./fstabの書き方.md) にあります。
