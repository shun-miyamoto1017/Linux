## まずこれだけ

| コマンド | 何をするか | 編集できるか |
|:--|:--|:-:|
| `cat` | ファイルの中身を**すべて**一気に表示する | ✗ |
| `less` | ファイルの中身を**1 画面ずつ**表示する（前にも戻れる） | ✗ |
| `more` | ファイルの中身を**1 画面ずつ**表示する（`less` の古い版） | ✗ |
| `head` | ファイルの**先頭**だけ表示する（既定 10 行） | ✗ |
| `tail` | ファイルの**末尾**だけ表示する（既定 10 行） | ✗ |
| `vi` | テキストエディタを起動する | ✓ |
| `emacs` | テキストエディタを起動する | ✓ |

**「見るだけ」と「編集できる」の線引きが、この項目の要点です。**

## ファイルの中身を見るコマンド

以下の例では、100 行のログファイルを使います。

```bash
$ seq 1 100 > sample.log            # 1〜100 の数字を1行ずつ書いたファイルを作る
$ wc -l sample.log                  # 行数を数えて確認する
100 sample.log
```

---

### cat

**意味** … ファイルの内容を**すべて**表示する

**例文**

```bash
$ cat sample.log                    # 100行が一気に流れる（画面に収まらない）
1
2
...
100

$ cat -n sample.log | head -3       # -n で行番号を付ける（先頭3行だけ表示）
     1  1
     2  2
     3  3

$ cat file1.txt file2.txt > all.txt # 複数ファイルを連結して1つにまとめる
```

**補足** … `cat` は **conCATenate（連結する）** の略です。
本来は「複数ファイルをつなげる」コマンドで、
1 ファイルだけ指定したときに「中身を表示する」ように見えているだけです。

**大きなファイルに `cat` を使ってはいけません。** 全部を画面に流すため、
数十万行のログだと端末が固まったようになり、先頭は流れ去って読めません。

```bash
$ cat /var/log/messages             # 巨大なログだと画面が流れ続けて読めない
$ less /var/log/messages            # こちらを使う
```

---

### less

**意味** … ファイルの内容を**ページ（1 画面）ごとに**表示する

**例文**

```bash
$ less sample.log                   # 1画面ずつ表示する（q で終了）
1
2
...
（画面の高さぶんだけ表示されて止まる）
```

画面内では次のキーが使えます。

| キー | 動作 |
|:--|:--|
| `スペース` / `f` | 次のページへ |
| `b` | **前のページへ戻る** |
| `↓` / `↑` | 1 行ずつ移動 |
| `g` | 先頭へ |
| `G` | 末尾へ |
| `/文字列` | 下方向へ検索 |
| `?文字列` | 上方向へ検索 |
| `n` / `N` | 次の / 前の検索結果へ |
| `q` | 終了 |

**補足** … `less` は**ファイル全体を読み込まずに表示を始める**ため、
数 GB のログでも一瞬で開きます。実務ではこれが決定的な差になります。

```bash
$ less +G /var/log/messages         # +G で末尾から開く（最新のログをすぐ見る）
$ less +F /var/log/messages         # +F で tail -f と同じ追従モードになる（Ctrl+C で解除）
$ less -N sample.log                # -N で行番号を表示する
```

パイプでつないで使うこともできます。長い出力を読むときの定番です。

```bash
$ ps aux | less                     # プロセス一覧をページ送りで読む
$ journalctl -u nginx | less        # systemd のログをページ送りで読む
```

### more

**意味** … ファイルの内容を**ページ（1 画面）ごとに**表示する（`less` より古いコマンド）

**例文**

```bash
$ more sample.log                   # 1画面ずつ表示する
1
2
...
--More--(23%)                       # 画面下に進捗率が出る
```

| キー | 動作 |
|:--|:--|
| `スペース` | 次のページへ |
| `Enter` | 1 行だけ進む |
| `/文字列` | 検索 |
| `q` | 終了 |

**補足** … `more` は**末尾まで表示すると自動的に終了**します。
`less` は `q` を押すまで終わりません。この違いは実際に触るとすぐ分かります。

もともと `more` には「戻れない」という制約があり、
それを改良したのが `less` です。**「less is more」（less のほうが more より高機能）**
という言葉遊びが名前の由来として知られています。

現在の Linux（util-linux 版）の `more` は `b` で 1 画面戻れますが、
検索や移動の機能は `less` に及びません。**実務では `less` を使えば十分**です。

---

### head

**意味** … ファイルの**先頭**を表示する（既定は 10 行）

**例文**

```bash
$ head sample.log                   # 先頭10行を表示する（既定）
1
2
...
10

$ head -3 sample.log                # 行数を指定して先頭3行だけ表示する
1
2
3

$ head -c 20 sample.log             # -c ならバイト数で指定する
```

**補足** … ログの形式や CSV のヘッダを確認したいときに使います。

```bash
$ head -1 data.csv                  # CSV のヘッダ行だけ確認する
id,name,created_at
```

---

### tail

**意味** … ファイルの**末尾**を表示する（既定は 10 行）

**例文**

```bash
$ tail sample.log                   # 末尾10行を表示する（既定）
91
...
100

$ tail -3 sample.log                # 末尾3行だけ表示する
98
99
100

$ tail -n +95 sample.log            # 95行目から最後まで表示する（+ に注意）
95
...
100
```

**補足** … 実務で最もよく使うのは **`-f`（follow）** です。
ファイルに追記された内容をリアルタイムで表示し続けます。障害調査の必需品です。

```bash
$ tail -f /var/log/messages         # 追記されるログを流し続ける（Ctrl+C で終了）

$ tail -F /var/log/messages         # -F ならログローテートされても追従し続ける
```

`head` と組み合わせると「特定の行だけ」を抜き出せます。

```bash
$ head -20 sample.log | tail -5     # 16〜20行目だけを取り出す
16
17
18
19
20
```

## ページャとエディタのちがい

`less` や `more` のように「中身を見るためだけ」のコマンドを **ページャ（pager）** と呼びます。
`vi` や `emacs` は **エディタ（editor）** で、見るだけでなく**書き換えられます**。

| | ページャ（`less` / `more`） | エディタ（`vi` / `emacs`） |
|:--|:--|:--|
| 中身を見る | ○ | ○ |
| **中身を書き換える** | **✗** | **○** |
| 起動の速さ | 速い（全部読まない） | ファイルを読み込む |
| 誤操作のリスク | 低い（壊せない） | 高い（保存すると変わる） |

**補足** … **本番環境で「見るだけ」のときは、あえてページャを使う**のが安全側の作法です。
`vi` で開いてしまうと、うっかり文字を入力して `:wq` で保存する事故が起こりえます。

```bash
$ less /etc/nginx/nginx.conf        # 見るだけなら壊しようがない
$ vi /etc/nginx/nginx.conf          # 編集する意図があるときだけ開く
```

どうしても `vi` の操作感で読みたい場合は、**読み取り専用で開く** `view` があります。

```bash
$ view /etc/nginx/nginx.conf        # vi と同じ操作だが書き込みできない
$ vi -R /etc/nginx/nginx.conf       # -R でも同じ（read-only モード）
```

### ページごとに表示するコマンド

> 証跡 10

**問題**

ファイルの内容をページ（1 画面）ごとに表示するが、編集はできないコマンドは次のうちどれか。（全て選択）

（1）`emacs` （2）`less` （3）`vi` （4）`more` （5）`cat`

---

**正解** … （2）`less` と（4）`more`

---

**解説**

ファイルの内容をページ（1 画面）ごとに表示するコマンドは `less` と `more` です。

したがって正解は
- `less`
- `more`
です。

**実行例**

```bash
$ seq 1 100 > sample.log            # 確認用に100行のファイルを作る

$ less sample.log                   # 1画面ずつ表示され、q を押すまで終わらない
1
2
...
（画面の高さぶんで停止。スペースで次のページ、b で前のページ）

$ more sample.log                   # 1画面ずつ表示され、末尾まで行くと自動終了する
1
2
...
--More--(23%)
```

**補足** … 設問には条件が **2 つ**あります。両方を満たすものを選びます。

| 条件 | `cat` | `less` | `more` | `vi` | `emacs` |
|:--|:-:|:-:|:-:|:-:|:-:|
| ページ（1 画面）ごとに表示する | ✗ | ○ | ○ | ○ | ○ |
| **編集はできない** | ○ | ○ | ○ | ✗ | ✗ |
| **両方を満たす** | ✗ | **○** | **○** | ✗ | ✗ |

`cat` は「編集できない」は満たしますが「ページごと」を満たしません。
`vi` と `emacs` は「ページごと」は満たしますが「編集できない」を満たしません。
**片方だけ満たす選択肢を落とす**のがこの問題の解き方です。

---

**誤答選択肢の解説**

#### cat

**ファイルの内容を 1 ページずつではなく、すべて表示するコマンドですので、誤りです。**

```bash
$ cat sample.log                    # 100行が一気に流れて止まらない
1
2
...
100
$                                   # そのままプロンプトに戻る（ページ送りがない）

$ less sample.log                   # less なら画面の高さで止まる
1
...
（ここで停止し、キー入力を待つ）
```

**補足** … `cat` を「ページごとに見たい」場合は、パイプで `less` に渡します。
実務ではこの形もよく使いますが、**ファイルを直接 `less` で開くほうが速い**です。

```bash
$ cat sample.log | less             # 動くが、cat を経由するぶん無駄がある
$ less sample.log                   # こちらが正しい書き方
```

---

#### vi

**テキストエディタの `vi` を起動するコマンドです。テキストエディタはファイルの編集を行うことができますので、誤りです。**
なお、**`vi` は Linux で標準的に使用されるテキストエディタ**です。

```bash
$ vi sample.log                     # エディタが起動する（画面ごとの閲覧もできる）
                                    # i を押すと入力モードになり、中身を書き換えられる
                                    # :q! で保存せず終了、:wq で保存して終了
```

**補足** … `vi` は**踏み台サーバやコンテナ内で唯一入っていることが多いエディタ**なので、
最低限の操作は覚えておく必要があります。ただし**設問の条件（編集はできない）を満たしません**。

「`vi` の操作感で、かつ編集させたくない」場合は `view` を使います。

```bash
$ view sample.log                   # 読み取り専用で開く（保存しようとすると警告が出る）
```

---

#### emacs

**テキストエディタの `emacs` を起動するコマンドです。テキストエディタはファイルの編集を行うことができますので、誤りです。**
なお、**`emacs` も `vi` と並んで愛用者の多いテキストエディタ**です。

```bash
$ emacs sample.log                  # エディタが起動する（環境によっては未インストール）
                                    # Ctrl+X Ctrl+S で保存、Ctrl+X Ctrl+C で終了

$ which emacs                       # インストールされているか確認する
/usr/bin/emacs
```

**補足** … `emacs` は多くのディストリで**既定ではインストールされていません**。
一方 `vi`（`vim-minimal`）はほぼ確実に入っています。
この差が、実務で `vi` を覚える理由になっています。

なお `set -o emacs` というシェルオプションもありますが、
これは**行編集のキーバインドの話**であり、`emacs` コマンドとは別物です
（[シェル環境のカスタマイズ](./シェル環境のカスタマイズ.md) を参照）。

## 公式ドキュメントで確認した補足

### `less` は「編集できない」が、エディタを呼び出せる

`less` 自体に編集機能はありません。ただし **`v` キーを押すと、
`VISUAL` または `EDITOR` 環境変数で指定されたエディタが起動**します（`less(1)` に記載）。

```bash
$ echo $EDITOR                      # どのエディタが起動するか確認する
vi

$ less sample.log                   # less で開いてから v を押すと vi が起動する
```

設問の「編集はできない」という分類は**コマンド自体の機能**の話であり、正しい理解です。
ただし実務では「`less` で開いたつもりが `v` を押してエディタに入っていた」ということが起こりえます。

### `more` と `less` の主な違い

| 項目 | `more` | `less` |
|:--|:--|:--|
| 前のページへ戻る | 限定的（util-linux 版は `b` で可） | ○（`b` / `↑` / `g`） |
| 末尾まで表示したとき | **自動的に終了する** | `q` を押すまで終わらない |
| ファイルの読み込み | 先に読む | **必要なぶんだけ読む**（巨大ファイルでも速い） |
| 検索の機能 | 単純 | 前方・後方検索、ハイライト |
| 標準搭載 | POSIX で規定 | ほぼすべてのディストリに同梱 |

### `less` の設定は `LESS` 環境変数で行う

毎回オプションを打たずに済ませたい場合は、`LESS` に既定オプションを入れます。

```bash
$ export LESS='-R -N -i'            # -R:色をそのまま表示 -N:行番号 -i:検索で大小無視
$ less sample.log                   # 上のオプションが自動で適用される
```

`man` コマンドの表示にも `less` が使われているため、この設定は man ページにも効きます。

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| `cat` で巨大ファイルを開いて端末が固まった | 全行を画面に流している | `Ctrl+C` で中断し、`less` を使う |
| `more` が勝手に終了した | 末尾まで表示すると自動終了する仕様 | 戻って読みたいなら `less` |
| `less` から抜けられない | `q` が終了キー | `q` を押す（`Ctrl+C` では抜けない） |
| `tail -f` がログローテート後に止まる | ファイルの実体が入れ替わっている | `tail -F` を使う |
| `vi` で開いたファイルを壊した | 見るだけのつもりが編集モードに入った | 閲覧は `less` か `view` |
| `tail -n +95` が意図と違う | `+` は「その行から最後まで」の意味 | 末尾 N 行なら `tail -95` |

## クラウド実務メモ

**ログ調査の基本の型**

```bash
$ tail -f /var/log/messages                     # まずリアルタイムで様子を見る
$ less +G /var/log/messages                     # 末尾から開いて、前に遡って読む
$ grep -n 'ERROR' /var/log/messages | less      # エラー行だけ抜き出して読む
```

**CloudWatch Logs でも考え方は同じ**

`tail -f` に相当するのが `aws logs tail --follow` です。
Linux 側の操作を覚えておくと、クラウド側のコマンドもすぐ理解できます。

```bash
$ aws logs tail /aws/lambda/my-func --follow    # tail -f に相当する
```

**Session Manager で入った本番サーバでは `less` を使う**

`vi` で設定ファイルを開くと、**うっかり保存して構成がずれる**リスクがあります。
確認だけなら `less`、変更するなら Ansible や Terraform を通す、という切り分けが安全です。

**コンテナ内には `less` が無いことがある**

`alpine` などの軽量イメージには `less` も `vi` も入っていないことがあります。
その場合は `cat` と `head` / `tail` で凌ぐか、ログを外に出して読みます。

```bash
$ kubectl logs pod-name | less                  # ホスト側の less で読むのが確実
$ kubectl exec -it pod-name -- cat /etc/nginx/nginx.conf
```
