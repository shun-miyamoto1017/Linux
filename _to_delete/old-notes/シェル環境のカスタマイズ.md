## まずこれだけ

| やりたいこと | コマンド |
|:--|:--|
| シェルのオプションを**有効**にする | `set -o オプション名` |
| シェルのオプションを**解除**する | `set +o オプション名` |
| いまのオプション設定を一覧する | `set -o` |
| シェル変数と環境変数をすべて見る | `set`（引数なし） |
| 環境変数だけ見る | `env` / `printenv` |
| 特定の環境変数だけ見る | `printenv 変数名` |
| **環境変数を作る／シェル変数を環境変数にする** | **`export` または `declare -x`** |
| コマンド履歴を保存ファイルに残さない | `HISTFILESIZE=0` |

**役割の切り分けが試験のポイントです。**

| したいこと | 使うコマンド |
|:--|:--|
| シェルのオプションを**設定**する | `set` だけ |
| 環境変数を**作る／昇格させる** | `export` と `declare -x` だけ |
| 変数を**見る**だけ | `set` / `declare` / `env` / `printenv` |

## シェル変数と環境変数のちがい

ここが曖昧だと `set` と `env`、`export` の違いが理解できません。

**環境変数は、変数を設定したシェル上と、そこから起動されるシェルやアプリケーション、コマンドで
有効な変数です。これは設定が子プロセスに引き継がれる事を意味します。**

| 種類 | 説明 | 子プロセスに引き継がれるか |
|:--|:--|:-:|
| **シェル変数** | 変数を設定したシェル上でのみ有効な変数 | ✗ |
| **環境変数** | `export` 属性が付いたシェル変数 | ✓ |

**例文**

```bash
$ MYVAR=hello                       # シェル変数として定義する
$ echo $MYVAR                       # いまのシェルでは値が見える
hello

$ bash -c 'echo "[$MYVAR]"'         # 子シェルを起動して同じ変数を見る
[]                                  # 引き継がれていないので空

$ export MYVAR                      # エクスポート属性を付けて環境変数に昇格
$ bash -c 'echo "[$MYVAR]"'         # もう一度、子シェルから見る
[hello]                             # 今度は引き継がれている
```

**補足** … プロセスが起動するとき、親は「環境（environment）」という文字列の配列を子に渡します。
ここに載せるかどうかを決めるのが `export` です。
シェル変数は「シェルというプログラムのローカル変数」、環境変数は「OS がプロセス間で受け渡す値」
と考えると腑に落ちます。

なお `bash -c 'コマンド'` は「新しいシェルを起動して、そこで 1 回だけコマンドを実行する」書き方です。
子プロセスに引き継がれるかどうかを確かめるのに便利なので、この後もよく使います。

## 代表的な環境変数

あらかじめ用意されている代表的な環境変数には以下のようなものがあります。

| 環境変数 | 説明 |
|:--|:--|
| `HISTFILE` | コマンド履歴保存ファイルのパス |
| `HISTSIZE` | 現在のシェルでのコマンド履歴の保存数 |
| `HISTFILESIZE` | コマンド履歴保存ファイルへの履歴保存数 |
| `HOSTNAME` | ホスト名 |
| `HOME` | ログインしているユーザのホームディレクトリ |
| `LANG` | ロケール（言語設定） |
| `PATH` | コマンドやプログラムを検索するディレクトリのリスト |
| `PWD` | カレントディレクトリのパス |
| `USER` | ログインしているユーザ |

**例文**

```bash
$ echo $HOME                        # ホームディレクトリの場所
/home/shun

$ echo $PWD                         # いまいるディレクトリ（pwd コマンドと同じ内容）
/home/shun/work

$ echo $USER                        # ログインユーザ名
shun

$ echo $PATH                        # コマンドを探しにいくディレクトリの並び（: 区切り）
/usr/local/bin:/usr/bin:/bin

$ echo $HISTFILE                    # 履歴が保存されるファイルの場所
/home/shun/.bash_history
```

**補足** … このうち `HISTFILE` `HISTSIZE` `HISTFILESIZE` は、
**厳密には bash が用意する「シェル変数」で、既定では export されていません**。
実際に確認すると `env` には出てきません。

```bash
$ set | grep '^HISTSIZE'            # set はシェル変数も表示するので見つかる
HISTSIZE=1000

$ env | grep '^HISTSIZE'            # env は環境変数だけなので見つからない
                                    # （何も出力されない）
```

試験では「環境変数」としてまとめて出題されますが、実務で
「子プロセスに引き継がれるか」を判断するときはこの違いが効いてきます。

## セットコマンドの三つの顔

`set` は引数によって、まったく違う 3 つの働きをします。ここが混乱の元です。

| 書き方 | 動作 |
|:--|:--|
| `set`（引数なし） | すべてのシェル変数と環境変数を表示する |
| `set -o` / `set +o`（オプション名なし） | 現在のオプション設定を一覧表示する |
| `set -o オプション名` / `set +o オプション名` | オプションを有効化・無効化する |

**例文**

```bash
$ set | head -5                     # 変数の一覧（膨大なので head で先頭5行だけ表示）
BASH=/usr/bin/bash
BASHOPTS=checkwinsize:cmdhist:...
BASH_ALIASES=()
...

$ set -o | head -8                  # オプションの現在値を一覧（先頭8行）
allexport      off
braceexpand    on
emacs          on
errexit        off
errtrace       off
functrace      off
hashall        on
histexpand     on
```

## オプションの有効化と無効化

シェルのオプション機能は、`set` コマンドで有効・無効を設定します。

```
set [-o][+o] オプション
```

**オプションを有効にするには `-o` を指定し、解除するには `+o` を指定します。**

```bash
$ set -o noclobber                  # noclobber を有効にする
$ set +o noclobber                  # noclobber を解除する
```

**補足** … 直感と逆に見えますが、「フラグを**立てる**（`-`）／**下ろす**（`+`）」という
古い Unix の慣習に由来します。
**「マイナスは制約を加える、プラスは解き放つ」** と結びつけると忘れにくいです。

### オプション一覧

| オプション | 説明 |
|:--|:--|
| `allexport` | 新規作成・変更した変数を自動的に環境変数とする（エクスポートする） |
| `emacs` | emacs エディタと同じキーバインドにする（矢印キーやマウスで操作でき、`Ctrl+D` で一文字削除できる、など） |
| `ignoreeof` | `Ctrl+D` を押してもログアウトしない設定にする |
| `noclobber` | リダイレクト演算子 `>` `>&` `<>` で既存のファイルを上書き不可に設定する |
| `noglob` | パス名展開を無効に設定する（ワイルドカードによる展開 `*` や `?` が無効になる） |
| `vi` | vi エディタと同じキーバインドにする（`ESC` キーでコマンドモードに移行し、入力時は `i` や `A` などで編集モードへの移行が必要、など） |

> オプションの詳細は LinuC 102 の範囲です。ここでは
> **「`set` コマンドでシェルのオプションを設定できる」**という事を覚えておきましょう。

### allexport

**意味** … 新規作成・変更した変数を自動的に環境変数とする（エクスポートする）

**例文**

```bash
$ set -o allexport                  # 自動エクスポートを有効にする
$ FOO=bar                           # export を書かずに変数を定義
$ bash -c 'echo "[$FOO]"'           # 子シェルから見えるか確認
[bar]                               # 自動で環境変数になっている

$ set +o allexport                  # 自動エクスポートを解除
$ BAZ=qux                           # 解除後に定義した変数
$ bash -c 'echo "[$BAZ]"'           # 子シェルから見えるか確認
[]                                  # 通常のシェル変数なので引き継がれない
```

**補足 … 設定ファイルの一括読み込みでよく使われます**

実務では次の 1 行をよく見かけます。まずこれが何をしているかを分解します。

```bash
$ set -a; source .env; set +a       # ← この1行を以下で分解して説明する
```

**手順1 … `.env` ファイルとは**

`変数名=値` を 1 行ずつ書いただけのテキストファイルです。
接続先やパスワードなどの設定値を、プログラム本体とは別に切り出しておくために使います。

```bash
$ cat .env                          # .env の中身を表示して確認する
DB_HOST=10.0.1.20
DB_PORT=5432
APP_ENV=production
```

**手順2 … `source` とは**

`source ファイル名` は、**そのファイルに書かれた行を、いま自分がいるシェルで実行する**コマンドです。
`.env` を `source` すると、中の 3 行がそのまま打ち込まれたのと同じ状態になります。

```bash
$ source .env                       # .env の3行をいまのシェルで実行する
$ echo $DB_HOST                     # 変数として読み込まれたか確認
10.0.1.20
```

**手順3 … `source` だけでは足りない理由**

`source` しただけでは**シェル変数**にしかならないため、
`docker` や `terraform` といった別のコマンド（＝子プロセス）には渡りません。

```bash
$ source .env                       # 読み込む
$ bash -c 'echo "[$DB_HOST]"'       # 子シェルから見えるか確認
[]                                  # 引き継がれていない
```

かといって `.env` の全行に `export` を書き足すのは面倒です。

**手順4 … そこで `allexport` で挟む**

`source` の前後を `set -a` と `set +a` で挟むと、
読み込んだ変数がすべて自動で環境変数になります。

```bash
$ set -a                            # ここから定義する変数は自動で環境変数になる
$ source .env                       # .env を読み込む（3つとも環境変数になる）
$ set +a                            # 自動エクスポートを解除して元に戻す

$ bash -c 'echo "[$DB_HOST]"'       # 子シェルから見えるか確認
[10.0.1.20]                         # 引き継がれた
```

**手順5 … 1 行にまとめる**

この 3 つを `;`（セミコロン）でつないだものが、冒頭の 1 行です。
**`;` は「コマンドを順番に実行する」という区切り記号**で、3 回に分けて打つのと同じ意味です。

```bash
$ set -a; source .env; set +a       # 上の3行をセミコロンでつないだだけ
```

| 部分 | やっていること |
|:--|:--|
| `set -a` | これ以降に定義する変数を自動で環境変数にする |
| `source .env` | `.env` の中身をいまのシェルで実行して、変数を定義する |
| `set +a` | 自動エクスポートをやめて、元の状態に戻す |

**注意点が 2 つあります。**

1. **`set +a` を書き忘れない**。忘れると、それ以降に作る変数がすべて環境変数になってしまいます。
2. **`.env` に書いたパスワードが、そこから起動するすべてのコマンドに見えます**。
   実務では Secrets Manager や Parameter Store から取得する方式のほうが、監査面で望ましい選択です。

> **`source` と `.` は同じもの**
> `source .env` は `. .env` とも書けます（こちらが POSIX 準拠の書き方）。
> どちらも「いまのシェルでファイルを読み込む」という意味です。
>
> 一方 `bash .env` と書くと**別のシェルが起動してそこで実行される**ため、
> 変数が手元のシェルに残りません。ここは間違えやすいポイントです。
>
> ```bash
> $ bash .env              # 子シェルで実行され、終わると同時に消える
> $ echo $DB_HOST          # 手元のシェルに残っているか確認
>                          # 空。何も残らない
> ```

### emacs

**意味** … emacs エディタと同じキーバインドにする（**bash の既定値**）

**例文**

```bash
$ set -o emacs                      # emacs キーバインドにする（既定なので通常は不要）
```

| 操作 | キー |
|:--|:--|
| 行頭へ | `Ctrl+A` |
| 行末へ | `Ctrl+E` |
| カーソル位置の 1 文字削除 | `Ctrl+D` |
| 単語削除（後方） | `Ctrl+W` |
| 行末まで削除 | `Ctrl+K` |
| 履歴検索 | `Ctrl+R` |
| 貼り付け | `Ctrl+Y` |

**補足** … emacs モードの `Ctrl+D` は「カーソル位置の 1 文字削除」ですが、
**行が空のときだけ EOF と解釈され、シェルが終了します**。
次の `ignoreeof` は、この「空行での `Ctrl+D`」を無効化するオプションです。

### ignoreeof

**意味** … `Ctrl+D` を押してもログアウトしない設定にする

**例文**

```bash
$ set -o ignoreeof                  # Ctrl+D での終了を無効にする
$ [Ctrl+D]                          # 空行で Ctrl+D を押してみる
Use "exit" to leave the shell.      # 終了せず、警告が出るだけ
```

**補足** … Bash マニュアルには「An interactive shell will not exit upon reading EOF.」とあります。
実装上は **`Ctrl+D` を 10 回連続で押すと結局終了**します。回数は `IGNOREEOF` 変数で変えられます。

```bash
$ IGNOREEOF=3                       # 3回までは無視し、4回目で終了するようにする
```

本番の踏み台サーバで、うっかり `Ctrl+D` してセッションを落とす事故の防止に有効です。

### noclobber

**意味** … リダイレクト演算子 `>` `>&` `<>` で既存のファイルを上書き不可に設定する

**例文**

```bash
$ echo "original" > data.txt        # まず中身のあるファイルを用意する
$ set -o noclobber                  # 上書き禁止を有効にする

$ echo "overwrite" > data.txt       # 既存ファイルへの上書きを試みる
-bash: data.txt: cannot overwrite existing file     # 保護されて失敗する

$ echo "append" >> data.txt         # 追記(>>)は制限されないので成功する
$ cat data.txt                      # 中身を確認
original
append

$ echo "force" >| data.txt          # >| なら noclobber を無視して上書きできる
$ cat data.txt                      # 上書きされたことを確認
force
```

**補足** … 押さえるのは 3 点です。

1. 保護対象は **`>` `>&` `<>`** の 3 つ
2. **追記 `>>` は対象外**
3. **`>|` で意図的にバイパスできる**

手順書に `command > /etc/xxx.conf` があると、手が滑って設定ファイルを吹き飛ばす事故が起きます。
作業前に `set -o noclobber` しておくのは安価で効果の高い保険です。

### noglob

**意味** … パス名展開を無効にする（`*` や `?` による展開が効かなくなる）

**例文**

```bash
$ ls                                # 練習用のファイルを確認
a.txt  b.txt

$ echo *.txt                        # 通常はファイル名に展開される
a.txt b.txt

$ set -o noglob                     # パス名展開を無効にする
$ echo *.txt                        # 展開されず、文字列のまま出力される
*.txt

$ ls *.txt                          # ls も「*.txt」という名前のファイルを探しにいく
ls: cannot access '*.txt': No such file or directory

$ set +o noglob                     # 元に戻す
```

**補足** … `*` を含む文字列をそのまま扱いたいときに使います
（`find -name` に渡す引数、`rsync --exclude` のパターンなど）。
ただし一時的に切るより、**クォートで囲むほうが安全**です。

```bash
$ find . -name '*.log'              # クォートで囲めば noglob なしでも意図通り動く
```

### vi

**意味** … vi エディタと同じキーバインドにする

**例文**

```bash
$ set -o vi                         # vi キーバインドに切り替える
```

| 操作 | キー |
|:--|:--|
| コマンドモードへ | `ESC` |
| 行頭へ | `ESC` → `0` |
| 行末へ | `ESC` → `$` |
| 編集モードへ | `i` / `a` / `A` |
| 行末まで削除 | `ESC` → `D` |
| 履歴検索 | `ESC` → `/` |

**補足** … 恒久化するなら `~/.inputrc` に次を書きます。

```
set editing-mode vi
```

## 変数を表示するコマンド

| コマンド | 説明 |
|:--|:--|
| `set` | 全てのシェル変数と環境変数を表示 |
| `declare` | 全てのシェル変数と環境変数を表示 |
| `env` | 全ての環境変数を表示 |
| `printenv` | 指定の、または全ての環境変数を表示 |

**例文**

```bash
$ env | head -3                     # 環境変数の一覧（先頭3行だけ表示）
SHELL=/bin/bash
PWD=/home/shun
LANG=ja_JP.UTF-8

$ printenv HOME                     # 変数を1つだけ取れるのは printenv
/home/shun

$ declare -p PATH                   # 属性つきで1変数だけ表示（-x が環境変数の印）
declare -x PATH="/usr/local/bin:/usr/bin:/bin"

$ export                            # 環境変数の一覧（declare -x 形式で出る）
declare -x HOME="/home/shun"
declare -x LANG="ja_JP.UTF-8"
```

**補足** … `set` と `declare` はシェル変数も含めて表示するので、
**「`export` していない変数が見えるかどうか」で使い分けられます**。

```bash
$ MYVAR=hello                       # export していないシェル変数を用意

$ set | grep '^MYVAR'               # set は シェル変数も表示するので見つかる
MYVAR=hello

$ env | grep '^MYVAR'               # env は環境変数だけなので見つからない
                                    # （何も出力されない）
```

## コマンド履歴のしくみ

`bash` シェルには、過去に入力したコマンドの履歴を記録する機能があります。
**コマンドの履歴はログアウト時にコマンド履歴保存ファイルに保存され、
次回ログイン時に参照できるようになっています。**

コマンドの履歴は `history` コマンドで確認することが出来ます。

**例文**

```bash
$ history                           # メモリ上に保持されている履歴を番号つきで表示
    1  ls -l
    2  cd /var/log
    3  tail -f messages
    4  history

$ echo $HISTFILE                    # 履歴の保存先ファイルを確認
/home/shun/.bash_history

$ cat $HISTFILE | tail -3           # ファイル側の履歴（末尾3行）を見る
ls -l
cd /var/log
tail -f messages
```

**2 段構えになっている点が重要です。**

| 変数 | どこの話か | 効く範囲 |
|:--|:--|:--|
| `HISTSIZE` | **メモリ上**の履歴リスト | 現在のシェルで `history` に何件表示されるか |
| `HISTFILESIZE` | **ファイル**（`$HISTFILE`）の履歴 | ログアウト時に何件書き出されるか |

```
コマンド入力
   ↓
メモリ上の履歴リスト   ← HISTSIZE が上限
   ↓ ログアウト時に書き出し
~/.bash_history        ← HISTFILESIZE が上限
```

> **履歴の「呼び出し方」はこちら**
> `!3` や `!ca` で過去のコマンドを再実行する**操作側の話**は
> [コマンドラインでの作業](./コマンドラインでの作業.md) にまとめています。
> このノートは**設定側**（何件残すか、どこに保存するか）を扱います。

### シェルのオプションを設定するコマンド

> 証跡 2

**問題**

シェルのオプションを設定できるコマンドはどれか。

（1）`set` （2）`bash` （3）`env` （4）`export`

---

**正解** … （1）`set`

---

**解説**

シェルのオプション機能は、`set` コマンドで有効・無効を設定します。
`set` コマンドは、**引数を指定しない場合は全てのシェル変数と環境変数を表示します。**
以下の書式のように**引数を指定した場合は、シェルのオプションを変更できます。**

```
set [-o][+o] オプション
```

オプションを有効にするには「`-o`」を指定し、解除するには「`+o`」を指定します。

**実行例**

```bash
$ set -o | grep noclobber           # まず現在の状態を確認する
noclobber      off

$ set -o noclobber                  # 有効にする
$ set -o | grep noclobber           # 変わったか確認
noclobber      on

$ set +o noclobber                  # 解除する
$ set -o | grep noclobber           # 戻ったか確認
noclobber      off
```

---

**誤答選択肢の解説**

その他の選択肢について、`export` と `env` は、
**環境変数を表示するコマンドであり `set` とともによく出題されます。
しかし、この 2 つには `set` のようにシェルのオプションを設定する機能はないため、誤りです。**

| コマンド | 説明 |
|:--|:--|
| `set` | 全てのシェル変数と環境変数を表示 |
| `declare` | 全てのシェル変数と環境変数を表示 |
| `env` | 全ての環境変数を表示 |
| `printenv` | 指定の、または全ての環境変数を表示 |

また、**`bash` は Linux の標準シェルの名称であり、このようなコマンドはないため、誤りです。**

---

#### bash

**なぜ誤りか** … `bash` はシェルそのものの名称です。
シェルのオプションを設定するためのコマンドではないため、誤りです。

```bash
$ bash -o noclobber                 # noclobber を付けた「新しいシェル」を起動する
$ set -o | grep noclobber           # 起動した子シェルの中で確認
noclobber      on

$ exit                              # 子シェルを抜けて元のシェルに戻る
$ set -o | grep noclobber           # 元のシェルの設定を確認
noclobber      off                  # 親シェルの設定は変わっていない
```

**補足（正確を期すための注記）** … `bash` は `/usr/bin/bash` に実体があり、
コマンドとして実行することはできます（新しいシェルが起動します）。
起動時に `bash -o vi` のようにオプションを指定することも可能です。
ただしそれは**新しいシェルを起動する**動作であり、
**いま操作しているシェルのオプションは変えられません**。
「シェルのオプションを設定するコマンド」としては誤り、という理解が正確です。

```bash
$ which bash                        # bash の実体がある場所を確認
/usr/bin/bash

$ echo $SHELL                       # ログインシェルの種類を確認
/bin/bash
```

---

#### env

**なぜ誤りか** … `env` は全ての環境変数を表示するコマンドです。
シェル変数もシェルのオプションも扱えないため、誤りです。

```bash
$ env | head -3                     # 環境変数の一覧（先頭3行）
SHELL=/bin/bash
PWD=/home/shun
LANG=ja_JP.UTF-8

$ MYVAR=hello                       # export していないシェル変数を作る
$ env | grep MYVAR                  # env で探してみる
                                    # 出てこない（環境変数ではないため）
```

**補足** … `env` にはもう 1 つ、
**一時的に環境変数を設定してコマンドを実行する**という使い方があります。

```bash
$ env LANG=C date                   # この date の実行中だけ LANG を C にする
Tue Aug 25 15:00:00 JST 2026

$ echo $LANG                        # 元のシェルの値を確認
ja_JP.UTF-8                         # 変わっていない
```

---

#### export

**なぜ誤りか** … `export` は変数にエクスポート属性を付けて環境変数にするコマンドです。
引数なしなら環境変数を一覧表示しますが、シェルのオプションは設定できないため、誤りです。

```bash
$ export | head -3                  # 環境変数の一覧（先頭3行）
declare -x HOME="/home/shun"
declare -x LANG="ja_JP.UTF-8"
declare -x PATH="/usr/local/bin:/usr/bin:/bin"

$ export -o noclobber               # set と同じ書き方を試してみる
bash: export: -o: invalid option    # そもそもオプション指定を受け付けない
```

**補足** … `export` は次の「環境変数を作成するコマンド」の問題では**正解になります**。
「何をするコマンドか」を正しく覚えていれば、両方の問題に対応できます。

### 環境変数を作成するコマンド

> 証跡 3・証跡 4（同一問題）

**問題**

シェルから起動したアプリケーションやコマンドでも有効な環境変数を作成したり、
シェル変数を環境変数に変更したりできるコマンドは次のうちどれか。（2 つ選択）

（1）`printenv` （2）`env` （3）`declare -x` （4）`export` （5）`set`

---

**正解** … （4）`export` と（3）`declare -x`

---

**解説**

環境変数は、変数を設定したシェル上と、そこから起動されるシェルやアプリケーション、
コマンドで有効な変数です。これは設定が子プロセスに引き継がれる事を意味します。

環境変数は `export` や `declare -x` を以下のように実行すると作成できます。
（`declare` コマンドは「オプション無し」で全てのシェル変数と環境変数を表示、
「`-x`」で環境変数を宣言できます。）

```
export 環境変数=値
declare -x 環境変数=値
```

また、`export` や `declare -x` により
シェル変数（変数を設定したシェル上でのみ有効な変数）を環境変数に変更できます。

```
export シェル変数名
declare -x シェル変数名
```

**実行例（Ping-t の解説に掲載されている例）**

例）シェル変数 `LPIC` を設定した後に `export` で環境変数にする

```bash
$ LPIC=study_linux                  # まずシェル変数として定義する
$ export LPIC                       # エクスポート属性を付けて環境変数にする
```

**追加の実行例（子プロセスに引き継がれることの確認）**

```bash
$ LPIC=study_linux                  # シェル変数として定義
$ bash -c 'echo "[$LPIC]"'          # 子シェルから見えるか確認
[]                                  # 引き継がれていない

$ export LPIC                       # 環境変数に昇格させる
$ bash -c 'echo "[$LPIC]"'          # もう一度、子シェルから確認
[study_linux]                       # 引き継がれた

$ declare -x LINUC=study_linuc      # 定義と環境変数化を同時に行う書き方
$ bash -c 'echo "[$LINUC]"'         # 子シェルから確認
[study_linuc]

$ declare -p LPIC LINUC             # 属性を確認（-x が付いていれば環境変数）
declare -x LPIC="study_linux"
declare -x LINUC="study_linuc"
```

**補足** … `export` と `declare -x` は同じ働きをします。
`declare` には他にも属性を付けるオプションがあり、`-x` はそのうちの 1 つ、という位置づけです。

| オプション | 意味 | 例 |
|:--|:--|:--|
| `-x` | 環境変数にする（`export` と同義） | `declare -x LPIC=study_linux` |
| `-r` | 読み取り専用にする | `declare -r VERSION=1.0` |
| `-i` | 整数として扱う | `declare -i COUNT=5` |
| `-a` | 配列 | `declare -a LIST` |
| `-A` | 連想配列 | `declare -A MAP` |
| `-p` | 属性と値を表示 | `declare -p HOME` |

```bash
$ declare -r VERSION=1.0            # 読み取り専用の変数を作る
$ VERSION=2.0                       # 書き換えを試みる
bash: VERSION: readonly variable    # 拒否される

$ declare -i COUNT=5                # 整数属性を付けた変数を作る
$ COUNT=COUNT+3                     # 整数属性があると式として計算される
$ echo $COUNT                       # 計算結果を確認
8
```

---

**誤答選択肢の解説**

その他の選択肢については以下のとおりです。

- `set`
- `env`
- `printenv`

**これらは変数を確認できるコマンドです。**

| コマンド | 説明 |
|:--|:--|
| `set` | 全てのシェル変数と環境変数を表示 |
| `declare` | 全てのシェル変数と環境変数を表示 |
| `env` | 全ての環境変数を表示 |
| `printenv` | 指定の、または全ての環境変数を表示 |

---

#### set

**なぜ誤りか** … 全てのシェル変数と環境変数を「表示」するコマンドです。
シェルのオプションは設定できますが、**変数を環境変数に昇格させることはできない**ため、誤りです。

```bash
$ MYVAR=hello                       # シェル変数を作る
$ set | grep '^MYVAR'               # set で表示できることを確認
MYVAR=hello

$ bash -c 'echo "[$MYVAR]"'         # 子シェルから見えるか確認
[]                                  # set しただけでは引き継がれない
```

**補足** … ただし `set -o allexport` を有効にしておけば、
**それ以降に定義した変数**は自動的に環境変数になります。
「変数を指定して昇格させる」わけではないので、この問題の答えにはなりません。

```bash
$ set -o allexport                  # 自動エクスポートを有効にする
$ NEWVAR=world                      # 以降に定義した変数は自動で環境変数になる
$ bash -c 'echo "[$NEWVAR]"'        # 子シェルから確認
[world]
$ set +o allexport                  # 元に戻す
```

---

#### env

**なぜ誤りか** … 全ての環境変数を「表示」するコマンドです。
既存のシェル変数を環境変数に変更することはできないため、誤りです。

```bash
$ MYVAR=hello                       # シェル変数を作る

$ env MYVAR bash -c 'echo ok'       # 変数名だけ渡してもコマンド名と解釈される
env: 'MYVAR': No such file or directory

$ env MYVAR=hello bash -c 'echo "[$MYVAR]"'
[hello]                             # 「値まで書けば」そのコマンドの間だけ有効になる
```

**補足** … `env VAR=値 コマンド` は「そのコマンドの実行中だけ」環境変数を設定します。
呼び出し元のシェルには影響しないため、「環境変数を作成する」とは意味が違います。

---

#### printenv

**なぜ誤りか** … 指定の、または全ての環境変数を「表示」するだけのコマンドです。
設定する機能がないため、誤りです。

```bash
$ printenv | head -3                # 環境変数の一覧（先頭3行）
SHELL=/bin/bash
PWD=/home/shun
LANG=ja_JP.UTF-8

$ printenv HOME                     # env との違いは「1つだけ取れる」こと
/home/shun

$ printenv MYVAR                    # 未定義の変数を指定してみる
$ echo $?                           # 直前のコマンドの終了ステータスを見る
1                                   # 1 = 失敗（定義されていない）
```

**補足** … `printenv VAR` は終了ステータスで
「その環境変数が定義されているか」を判定できるため、スクリプトのチェック処理で使えます。

```bash
$ printenv AWS_PROFILE > /dev/null || echo "AWS_PROFILE が未設定です"
AWS_PROFILE が未設定です
```

この 1 行は 3 つの部品でできています。

| 部分 | 意味 |
|:--|:--|
| `printenv AWS_PROFILE` | 変数があれば値を表示して成功（終了ステータス 0）、無ければ失敗（1） |
| `> /dev/null` | 表示された値を捨てる。**成否だけ知りたいので出力は要らない** |
| `\|\| echo "..."` | **直前が失敗したときだけ**右側を実行する |

`/dev/null` は「書き込んだものが消えるゴミ箱」のような特殊ファイルです。
`||` は「左が失敗したら右」、`&&` は「左が成功したら右」を意味します。

```bash
$ export AWS_PROFILE=prod           # 変数を設定してから同じ行を試す
$ printenv AWS_PROFILE > /dev/null || echo "AWS_PROFILE が未設定です"
                                    # 成功したので右側は実行されず、何も出ない

$ printenv AWS_PROFILE && echo "設定済みです"   # && なら成功したときに右側が動く
prod
設定済みです
```

### コマンド履歴を残さない設定

> 証跡 6

**問題**

コマンド履歴保存ファイルに記録が残らないように以下のとおり作業を行った。
空欄に当てはまるものはどれか。

```bash
$ [    ]=0                          # ← この空欄に入る変数名を答える
```

（1）`HISTSAVE` （2）`HISTORY` （3）`HISTFILESIZE` （4）`COMMAND` （5）`HISTSIZE`

---

**正解** … （3）`HISTFILESIZE`

---

**解説**

`bash` シェルには、過去に入力したコマンドの履歴を記録する機能があります。
コマンドの履歴はログアウト時にコマンド履歴保存ファイルに保存され、
次回ログイン時に参照できるようになっています。
コマンドの履歴は `history` コマンドで確認することが出来ます。

**環境変数 `HISTFILESIZE` を `0` にすると、
コマンド履歴保存ファイルにコマンド履歴が保存されなくなります。**

**実行例（Ping-t の解説に掲載されている例）**

```bash
$ history                           # メモリ上の履歴を表示
    1  history
    2  ls -l $HISTFILE
    3  history
$ cat $HISTFILE                     # ファイル側の履歴を表示（まだ空）
$ exit                              # ログアウト（ここでファイルに書き出される）
（ログアウト後、再ログイン）
$ history                           # 再ログイン後の履歴を表示
    1  history                      ┐
    2  ls -l $HISTFILE              │ 前回ログイン時点の
    3  history                      │ 履歴が残っている
    4  cat $HISTFILE                │
    5  exit                         │
    6  history                      ┘
$ cat $HISTFILE                     # ファイル側も確認
history                             ┐
ls -l $HISTFILE                     │ ログアウト前の履歴が
history                             │ 残っている
cat $HISTFILE                       │
exit                                ┘
$ HISTFILESIZE=0                    # ← ここで 0 を設定する
$ history                           # メモリ上の履歴は消えていないことに注目
    1  history
    2  ls -l $HISTFILE
    3  history
    4  cat $HISTFILE
    5  exit
    6  history
    7  cat $HISTFILE
    8  HISTFILESIZE=0
    9  history
$ exit                              # ログアウト
（ログアウト後、再ログイン）
$ history                           # 再ログイン後の履歴を表示
    1  history                      # 履歴が残っていない
```

**補足** … 「メモリ上の履歴」と「ファイル上の履歴」は別物、という点がこの問題の核心です。
`HISTFILESIZE=0` を設定した直後も `history` には 9 件表示されています。
**メモリ上の履歴は消えず、ログアウト時にファイルへ書き出す件数が 0 になる**ためです。

**確認のしかた**

```bash
$ HISTFILESIZE=0                    # 0 を設定する
$ ls -l $HISTFILE                   # 履歴ファイルのサイズを確認
-rw------- 1 shun shun 0 Aug 25 15:00 /home/shun/.bash_history
                                    # ↑ サイズが 0 バイトに切り詰められている
```

---

**誤答選択肢の解説**

その他の選択肢については以下のとおりです。

#### HISTSIZE

**現在のシェルでのコマンド履歴保存数を格納する環境変数のため、誤りです。**

```bash
$ echo $HISTSIZE                    # 現在の設定値を確認
1000

$ HISTSIZE=3                        # メモリ上の履歴を3件に制限してみる
$ history                           # 表示される件数を確認
   10  HISTSIZE=3
   11  history                      # 直近の数件しか残らない

$ cat $HISTFILE | wc -l             # ファイル側の行数を数える
500                                 # ファイル側は制限されていない
```

**補足** … 名前が似ているので、**「FILE が付くほうがファイル」**と覚えます。

| 変数 | 制御する対象 | `=0` にすると |
|:--|:--|:--|
| `HISTSIZE` | メモリ上の履歴リスト | `history` に何も表示されなくなる |
| `HISTFILESIZE` | 履歴保存ファイル | ファイルが 0 バイトに切り詰められる |

「作業中も履歴を見たくない」なら `HISTSIZE=0`、
「ファイルに残したくない」なら `HISTFILESIZE=0` です。
設問は「**コマンド履歴保存ファイル**に記録が残らないように」なので `HISTFILESIZE` が正解です。

---

#### COMMAND

**デフォルトでは存在しない環境変数のため、誤りです。**

```bash
$ echo "[$COMMAND]"                 # 中身があるか確認（[ ] で囲むと空でも分かる）
[]                                  # 空

$ printenv COMMAND                  # 環境変数として存在するか確認
$ echo $?                           # 終了ステータスを見る
1                                   # 1 = 定義されていない
```

**補足** … 似た名前で実在するものに `PROMPT_COMMAND` と `BASH_COMMAND` があります。
これらが記憶に残っていると `COMMAND` を選びたくなるので注意します。

| 変数 | 意味 |
|:--|:--|
| `PROMPT_COMMAND` | プロンプト表示の直前に実行されるコマンド |
| `BASH_COMMAND` | いま実行中のコマンド（トラップ処理などで使う） |

```bash
$ PROMPT_COMMAND='history -a'       # コマンドを打つたびに履歴をファイルへ追記する
```

---

#### HISTORY

**デフォルトでは存在しない環境変数のため、誤りです。**

```bash
$ echo "[$HISTORY]"                 # 中身があるか確認
[]                                  # 空

$ history                           # 「history」は変数ではなくコマンドとして存在する
    1  ls -l
    2  history
```

**補足** … `history` は**コマンド**として実在します。変数ではありません。
「履歴といえば history」という連想で選びやすい、ひっかけの選択肢です。

| よく使う `history` の操作 | 意味 |
|:--|:--|
| `history` | 履歴を表示 |
| `history -c` | メモリ上の履歴をすべて消す |
| `history -d 番号` | 指定した 1 件を消す |
| `history -a` | メモリ上の履歴をファイルへ追記 |
| `history -r` | ファイルの履歴をメモリへ読み込む |

---

#### HISTSAVE

**デフォルトでは存在しない環境変数のため、誤りです。**

```bash
$ echo "[$HISTSAVE]"                # 中身があるか確認
[]                                  # 空
```

**補足** … 「save（保存）」という語感から正解に見えますが、bash にこの変数はありません。
実在する `HIST` 系の変数は次のとおりです。**この 5 つ以外は疑ってかかる**のが確実です。

| 実在する変数 | 意味 |
|:--|:--|
| `HISTFILE` | 履歴保存ファイルのパス |
| `HISTSIZE` | メモリ上の履歴の保存数 |
| `HISTFILESIZE` | 履歴保存ファイルへの保存数 |
| `HISTCONTROL` | 重複行やスペース始まりの行を記録しない設定 |
| `HISTTIMEFORMAT` | 履歴に日時を付けるフォーマット |

```bash
$ set | grep '^HIST'                # HIST で始まる変数だけを抜き出して確認
HISTCONTROL=ignoredups
HISTFILE=/home/shun/.bash_history
HISTFILESIZE=2000
HISTSIZE=1000
```

## 公式ドキュメントで確認した補足

Bash マニュアル The Set Builtin に記載のうち、**運用スクリプトで必須**のものです。

### 実務で必ず使うオプション

| オプション | 短縮形 | 説明 |
|:--|:--|:--|
| `errexit` | `-e` | コマンドが非ゼロ終了したら即座にシェルを終了する |
| `nounset` | `-u` | 未定義変数を参照したらエラーにする |
| `pipefail` | — | パイプライン全体の終了ステータスを、最後に非ゼロを返したコマンドのものにする |
| `xtrace` | `-x` | 展開後のコマンドを標準エラーに出力する |
| `noexec` | `-n` | 読み込むが実行しない（構文チェック用） |

**スクリプト先頭の定番**

```bash
#!/usr/bin/env bash                 # このスクリプトを bash で実行する宣言
set -euo pipefail                   # -e -u と pipefail をまとめて有効にする
```

**なぜ必要か（例文）**

```bash
$ DIR=""                            # 変数が空になってしまった状況を再現
$ rm -rf "$DIR/"                    # 展開すると rm -rf / になり、全消しの危険がある
```

```bash
$ set -u                            # 未定義変数の参照をエラーにする
$ rm -rf "$UNDEFINED/"              # 定義していない変数を使ってみる
bash: UNDEFINED: unbound variable   # 実行される前に止まってくれる
```

```bash
$ false | true; echo $?             # 左が失敗しても、パイプ全体は成功扱いになる
0                                   # 失敗が隠れてしまう

$ set -o pipefail                   # パイプの途中の失敗も拾うようにする
$ false | true; echo $?             # 同じコマンドをもう一度実行
1                                   # 失敗を検知できた
```

**本番適用前の構文チェック**

```bash
$ bash -n deploy.sh                 # 実行せずに文法エラーだけをチェックする
$ bash -x deploy.sh                 # 1行ずつ展開結果を表示しながら実行する
```

### その他のオプション

| オプション | 短縮形 | 説明 |
|:--|:--|:--|
| `verbose` | `-v` | 読み込んだ入力行をそのまま標準エラーに出力 |
| `posix` | — | POSIX 準拠モードにする |
| `monitor` | `-m` | ジョブ制御を有効にする |
| `notify` | `-b` | バックグラウンドジョブの終了を即座に通知 |
| `braceexpand` | `-B` | ブレース展開 `{a,b}` を行う（既定 ON） |
| `hashall` | `-h` | 実行したコマンドのパスを記憶する（既定 ON） |
| `histexpand` | `-H` | `!` によるヒストリ展開（対話シェルでは既定 ON） |
| `physical` | `-P` | シンボリックリンクを解決せず物理パスを使う |

### `set` と `shopt` の使い分け

bash にはオプションを設定するコマンドが **2 系統**あります。

| コマンド | 対象 | 有効化 | 無効化 |
|:--|:--|:--|:--|
| `set -o` | POSIX 由来のシェルオプション | `set -o xxx` | `set +o xxx` |
| `shopt` | bash 独自の拡張オプション | `shopt -s xxx` | `shopt -u xxx` |

```bash
$ set -o noclobber                  # POSIX 系のオプションは set で操作する
$ shopt -s globstar                 # bash 独自のオプションは shopt で操作する（-s = set）
$ shopt -u globstar                 # 無効化は -u（unset）
```

**符号の意味が逆転して見える**ので、試験でも実務でも混同しやすい箇所です。

### 設定を退避して元に戻す

`set +o` を**オプション名なしで**実行すると、
「いまの設定を再現するための `set` コマンドの一覧」が文字列として出力されます。

```bash
$ set +o | head -3                  # 出力の先頭3行を確認（set コマンドの列挙になっている）
set +o allexport
set -o braceexpand
set -o emacs
```

この出力をいったん変数にしまっておき、作業後に実行し直せば、元の状態に戻せます。

```bash
$ OLD_OPTS=$(set +o)                # set +o の出力を丸ごと変数に保存する
$ set -o noclobber                  # 一時的に設定を変えて作業する
$ eval "$OLD_OPTS"                  # 保存しておいたコマンド列を実行して元に戻す
```

| 部分 | 意味 |
|:--|:--|
| `$( ... )` | 中のコマンドを実行し、**その出力を文字列として取り出す**（コマンド置換） |
| `OLD_OPTS=$(set +o)` | `set +o` の出力（数十行の `set` コマンド）を変数に入れる |
| `eval "$OLD_OPTS"` | **変数の中身を、コマンドとして実行する** |

`eval` は「文字列をコマンドとして実行する」コマンドです。
`echo "$OLD_OPTS"` だと文字が表示されるだけですが、`eval` を付けると実際に実行されます。

```bash
$ echo "$OLD_OPTS" | head -2        # eval を使わなければ、ただの文字列として表示される
set +o allexport
set -o braceexpand
```

> **`eval` は強力なので注意**
> 変数の中身を無条件に実行するため、**外部から受け取った値に `eval` を使ってはいけません**。
> ここでは `set +o` という自分のシェルの出力だけを対象にしているので安全です。

### 履歴を制御するその他の変数

| 変数 | 意味 |
|:--|:--|
| `HISTCONTROL=ignoredups` | 直前と同じコマンドを記録しない |
| `HISTCONTROL=ignorespace` | 先頭がスペースのコマンドを記録しない |
| `HISTCONTROL=ignoreboth` | 上の両方 |
| `HISTIGNORE='ls:history:exit'` | 指定パターンのコマンドを記録しない |
| `HISTTIMEFORMAT='%F %T '` | 履歴に日時を表示する |

```bash
$ HISTTIMEFORMAT='%F %T '           # 履歴に「年月日 時分秒」を付ける
$ history | tail -2                 # 直近2件を表示して確認
   45  2026-08-25 15:00:12 ls -l
   46  2026-08-25 15:00:20 history
```

## 設定を恒久化する場所

`set` や `export`、`HISTFILESIZE` はそのセッション限りなので、恒久化するには設定ファイルに書きます。

| ファイル | 読まれるタイミング | 主な用途 |
|:--|:--|:--|
| `/etc/profile` | ログインシェル起動時（全ユーザ） | システム全体の環境変数 |
| `/etc/profile.d/*.sh` | 同上 | パッケージごとの設定を分割 |
| `/etc/bashrc`（RHEL 系）<br>`/etc/bash.bashrc`（Debian 系） | 対話シェル起動時（全ユーザ） | システム全体のエイリアス・関数 |
| `~/.bash_profile` | ログインシェル起動時（個人） | `PATH` などの環境変数 |
| `~/.bashrc` | 対話シェル起動時（個人） | エイリアス、`set -o`、プロンプト |
| `~/.bash_logout` | ログアウト時 | 後始末 |

**使い分けの原則** … 環境変数は `~/.bash_profile`、エイリアスやシェルオプションは `~/.bashrc`。

環境変数は一度 `export` すれば子プロセスに継承されるので、ログイン時に 1 回で十分です。
一方、エイリアスやシェルオプションは継承されないため、
新しい対話シェルが立つたびに読み込む必要があります。

```bash
# ~/.bashrc の例
set -o noclobber                    # > による上書き事故を防ぐ
set -o ignoreeof                    # Ctrl+D での誤ログアウトを防ぐ
shopt -s histappend                 # 履歴を上書きせず追記する
HISTSIZE=10000                      # メモリ上の履歴を1万件まで保持
HISTFILESIZE=20000                  # ファイルには2万件まで残す
HISTTIMEFORMAT='%F %T '             # 履歴に日時を残す（監査で効く）
alias ll='ls -alF'                  # よく使うオプション付き ls の短縮形
alias grep='grep --color=auto'      # 検索結果に色を付ける
```

## つまずきポイント

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| `set -o` したのに新しいターミナルで効かない | セッション限りの設定 | `~/.bashrc` に書く |
| `~/.bashrc` の設定が `ssh host 'cmd'` で効かない | 非対話シェルでは読まれない | `~/.bash_profile` か `env` で明示 |
| `set -e` なのにスクリプトが止まらない | `if` 条件内、`&&` の左辺、パイプ途中は対象外 | `pipefail` を併用し終了ステータスを明示確認 |
| `shopt -o` を打って混乱する | `set` と `shopt` の混同 | `set -o` と `shopt -s` を区別する |
| `env` に自分の変数が出てこない | `export` していないシェル変数 | `export VAR` するか `set` で確認 |
| `>` で設定ファイルを飛ばした | `noclobber` 未設定 | 作業前に `set -o noclobber` |
| 履歴が保存されない | `HISTFILESIZE` が 0 になっている | `set \| grep HIST` で確認 |
| 複数端末で履歴が上書きされる | 後から閉じた端末の履歴で上書きされる | `shopt -s histappend` |

## クラウド実務メモ

**CI/CD や Systems Manager Run Command のスクリプトは `set -euo pipefail` を必須にする**

これがないと途中のコマンドが失敗しても最終ステータスが `0` になり、
「デプロイ成功」と表示されたまま壊れた状態が本番に出ます。

**`set -x` はログに秘匿情報を出す**

`AWS_SECRET_ACCESS_KEY` などを扱う区間は必ず `set +x` で囲みます。
CodeBuild や GitHub Actions のログは保存されるため実害が大きい箇所です。

```bash
set -x                                        # ここからトレース ON
build_app                                     # 通常の処理（ログに出てよい）

set +x                                        # トレースを一時的に OFF にする
export AWS_SECRET_ACCESS_KEY=$(get_secret)    # この行はログに出さない
set -x                                        # またトレース ON に戻す
```

`build_app` と `get_secret` はスクリプト内で定義した関数の例です。
ポイントは、**秘匿情報を扱う行だけを `set +x` と `set -x` で挟む**という書き方です。

`set -x` が有効なままだと、次のように**値そのものがログに残ります**。

```bash
$ set -x                                      # トレースを有効にする
$ export AWS_SECRET_ACCESS_KEY="wJalrXUt..."  # 秘密鍵を設定してみる
+ export AWS_SECRET_ACCESS_KEY=wJalrXUt...    # ← 値がそのままログに残ってしまう
```

**踏み台サーバでは逆に「履歴を残す」設定が求められる**

`HISTFILESIZE=0` は履歴を消す設定ですが、金融案件などの監査要件では
**「いつ誰が何を打ったか」の証跡を残すこと**が求められます。
運用設計としては次を `/etc/profile.d/` に置くのが定番です。

```bash
# /etc/profile.d/history.sh
HISTSIZE=10000                                # メモリ上の履歴を1万件まで保持
HISTFILESIZE=20000                            # ファイルには2万件まで残す
HISTTIMEFORMAT='%F %T '                       # 履歴に日付と時刻を付ける
readonly HISTFILE HISTSIZE HISTFILESIZE HISTTIMEFORMAT   # 利用者が書き換えられないようにする
export HISTSIZE HISTFILESIZE HISTTIMEFORMAT   # 子プロセスにも引き継ぐ
shopt -s histappend                           # 履歴を上書きせず追記する
PROMPT_COMMAND='history -a'                   # コマンドごとに履歴をファイルへ即時追記
```

各行が何をしているかは次のとおりです。

| 行 | 意味 |
|:--|:--|
| `HISTSIZE=10000` | メモリ上の履歴を 1 万件まで保持する |
| `HISTFILESIZE=20000` | 履歴ファイルに 2 万件まで残す |
| `HISTTIMEFORMAT='%F %T '` | 履歴に「日付 時刻」を付ける（`%F`＝年月日、`%T`＝時分秒） |
| `readonly ...` | **利用者が値を書き換えられないようにする** |
| `export ...` | 子プロセスにも引き継ぐ |
| `shopt -s histappend` | 履歴ファイルを**上書きせず追記**する（複数端末で消し合わない） |
| `PROMPT_COMMAND='history -a'` | **コマンドを打つたびに履歴をファイルへ即時追記**する |

`PROMPT_COMMAND` は「プロンプトを表示する直前に実行されるコマンド」を入れる変数です。
ここに `history -a`（メモリ上の履歴をファイルへ追記）を入れておくと、
**ログアウトを待たずに証跡が残ります**。
異常終了やセッション切断で履歴が失われるのを防ぐ、実務上の定番設定です。

`readonly` を付けると、利用者が `HISTFILESIZE=0` を実行しても弾かれます。

```bash
$ HISTFILESIZE=0                    # 履歴を消そうとしてみる
bash: HISTFILESIZE: readonly variable          # 読み取り専用なので拒否される
```

ただしこれは万能ではありません（別のシェルを起動する、`unset` を試みるなどの回避手段があります）。
本格的な証跡管理は、OS の設定に頼らず
**Session Manager のログ記録（S3 / CloudWatch Logs）**で担保するのが現代の設計です。

**EC2 のユーザーデータは非対話・非ログインシェルで動く**

`~/.bashrc` も `~/.bash_profile` も読まれません。`PATH` は明示的に設定します。

**環境変数で AWS の向き先が変わる**

`AWS_PROFILE` `AWS_REGION` `AWS_DEFAULT_REGION` は環境変数なので、
`export` した瞬間から子プロセス（`aws` コマンド、`terraform`）すべてに効きます。
本番と検証を取り違える事故の主要因なので、作業前に必ず確認します。

```bash
$ printenv AWS_PROFILE AWS_REGION   # いまどのプロファイル・リージョンを向いているか確認
$ aws sts get-caller-identity       # 実際にどの AWS アカウントに繋がるかを確認
```
